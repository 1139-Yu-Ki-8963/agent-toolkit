# 機能設計書・詳細設計書・単体テスト設計書の決まり

## 概要

`docs/skills/` のうち reverse の単位（`reverse-*`・`reverse-shared`）の各機能を対象にする。
各機能に、納品物と同じ章構成の3文書（基本設計書・詳細設計書・単体テスト設計書）を
`docs/design/skills/<機能名>/` に置くことを定める。SKILL.mdは機能の宣言と手順を持つ。
要件との対応・方式設計・テスト観点は3文書として残す。setup の単位はこの規約の対象外。

## 違反時の手順

文書が欠落している場合、`docs/design/skills/<機能名>/`に基本設計書.md・詳細設計書.md・単体テスト設計書.mdを、規則が定める節と表の形で作る。単体テスト設計書は`check-unit-test-design-doc-sections.sh --check-file`が許可を返すまで直す。§2の行に前提・操作・期待結果が無い場合、現場コードを走らせたときの値で埋める。§2の観点キーが§1に無い場合、§1へ観点を足すか§2の値を直す。自己テストの件数が実物とずれる場合、「自己テスト」の表の件数列を`--self-test`の実測に合わせて直す。対応表に機能が無い場合、`docs/design/requirements/要件と機能の対応表.md`の逆引き表へ追記する。

§5終了コード・差し戻し・保留の一覧の表に「保留のとき」列が無い場合、既存の各行の末尾へ列を足す。判定が保留の記録を実際に飛ばす検査には振る舞いを、それ以外の行には「対象外」を書く。

§2の「自己テストのケース名」列が自己テストの出力と一致しない場合、対応するスクリプトへ`--self-test`を実行し、出力に無い§2の値を実物の`ケースN: 説明`へ直す。出力にあって§2に無いケースは、§1へ観点（`<対象>-<観点要約>`の意味語キー）を足し、§2へ行を足す。前提・操作・期待結果は自己テストの設定値と期待値から書き起こす。現場コードでしか確かめられないケースは区分を「レビュー」とし、この列を`（レビュー）`にする。

## 設計判断

### check-skill-design-docs.sh

**必要性**: `docs/skills/`のreverse単位の機能は増え続ける。機能ごとに3文書の実在・節構成・対応表との整合・テストケース数の実物一致という複数段の判定を要する。人が目視で確かめるのは非現実的であり、CIから繰り返し呼ばれる検査として固定する必要がある。

**代替案を採用しなかった理由**:
- Bash ツール直叩き: 機能を追加するたびに節見出し・表のヘッダ・ケース数の一致を手で確認すると、確認の省略・見落としを繰り返す
- 既存 `validate-skill-definitions.sh` への直接実装: あちらは SKILL.md 自体の宣言（鍵・requires・tests の実在）を検査する。設計文書という別の成果物の形を検査する判定を混ぜると責務が肥大化するため、規約自身のフォルダに置く checker として分離した
- setupの単位も対象に含める: setupは対象システムの環境構築を担い、reverseとは要件・完了条件の性質が異なる。1つの検査に混ぜると、setup側の変更でreverse側の検査が誤って揺れる
- 既存 Makefile ターゲット拡張・package.json scripts 追加: このリポジトリはどちらも持たず、新規導入は本検査専用の依存を増やすだけになる

**保守責任者**: 人手（ユーザー）。節の構成や単体テスト設計書の表の形を変更する場合は、本ファイルの規則の表と`check-skill-design-docs.sh`を同時に更新する。setupの単位を対象に含める場合は、規約名・対象範囲の記述も同時に見直す。

**廃棄条件**: `docs/skills/`によるreverse単位の機能定義の運用を廃止した時、または3文書の検査を構造化データから機械的に導出できるようになった時。

**2026-09-06の変更**: 「自己テストの件数が実物と一致する」規則は件数という集計値しか見ていなかった。改善指示書17件の対応で自己テストにケースを足しても、§2のケースを足さなくても、件数さえ揃えば合格していた。実測では複数の機能で§2の追加が0件のまま合格していた。該当はreverse-listing-unitsとreverse-writing-foundation-guidesである。reverse-writing-basic-designとreverse-sharedも同様である。§2の各行に「自己テストのケース名」列（10列目）を足し、自己テストの出力と双方向で名前を突き合わせる規則を追加した。集計値の一致では検出できない「件数だけ合わせて中身を書かない」という抜け道を、名前の集合比較で塞ぐ。
