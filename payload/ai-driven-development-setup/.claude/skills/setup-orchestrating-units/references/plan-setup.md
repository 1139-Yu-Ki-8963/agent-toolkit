# plan-setup.sh の判定方法

`scripts/plan-setup.sh` が実行順を導く2つの根拠と、その近似の粗さを記す。

## 2つの辺

1. `requires`: 機能 X の `requires` に機能 Y があれば、Y を X より先に置く
2. 入出力の重なり: 機能 Y の `outputs` のいずれかと、機能 X の `inputs` のいずれかが「重なる」なら、Y を X より先に置く

## 重なりの判定（近似）

入力・出力はいずれもパターン文字列（例: `docs/rules/*/parent.yml`）で宣言する。重なりの判定は、パターンの最初の `*` より前の固定部分（接頭辞）だけを比べ、片方がもう片方の接頭辞になっていれば「重なる」とみなす。

例えば `docs/rules/*/parent.yml` と `docs/rules/*/*/rule.md` は、どちらも接頭辞が `docs/rules/` であるため重なる。

この判定は粗い近似である。同じ接頭辞を持つが実際には無関係なパターン同士も重なると判定してしまう。逆に、接頭辞が異なるが実際には同じファイル集合を指すパターン（同じ場所を別の書き方で指す等）は重ならないと判定してしまう。宣言する側が、意図しない実行順を避けたい場合は、パターンの接頭辞を意図的に分ける、または `requires` で明示するとよい。

## 外部入力

どの機能の `outputs` とも重ならない `inputs` は「外部入力」として計画の表に載せる。統括はこれを依存関係の欠落としては扱わず、読む側の判断に委ねる。`--target` を渡した場合は、そのパスの下に該当パターンに一致するファイルが実在するかどうかを添えるが、実在しなくても計画自体は終了コード0で返す。

## 既知の限界

- 接頭辞比較のみのため、パターンの `*` より後ろの構造（拡張子・階層数の違い等）は見ない
- 同一の機能内で `inputs` と `outputs` が重なっていても自己辺は作らない（i != j の対だけを見る）
- 循環が検出された場合、報告する循環は残存ノードの中から名前の辞書順で最小のものを起点に1つ見つけた例であり、複数の循環がある場合にすべてを列挙しない
