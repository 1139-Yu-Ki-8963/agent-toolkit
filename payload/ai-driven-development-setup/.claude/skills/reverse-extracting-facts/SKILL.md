## いつ使うか

一覧を作る機能が全種別で合格した後、種別ごとに使う。単位ごとに、設計書へ転記する事実をコードから取り出して固定する。

## いつ使わないか

一覧が無い、または一覧化が合格していない種別のとき（一覧を作る機能をやり直す）。取り出しの規則（道標の節4の当該種別の表）が無い種別のとき（道標を描く機能で規則を書く）。

## 前提

- 設計書の置き場（`design-root.sh` で読む）に `docs/design/lists/<種別>.json`（一覧の元データ）があること
- 設計書の置き場の `docs/design/common/道標.md` の節4に、当該種別の「事実の項目 | どの構文・記述から取るか」の表（取り出しの規則）があること
- この機能は取り出しの規則を解釈するだけで、言語やフレームワークごとの分岐を持たない。取り出し方は道標が持つ

## 手順

1. 次を実行し、範囲の承認（可否・道標の同一性）を確かめる。

   ```bash
   bash ../reverse-shared/scripts/check-entry.sh <出力の置き場> <対象リポジトリのルート> --design-root <設計書の置き場>
   ```

   終了コードが0でなければ止まる。止まったときは道標を描く機能の範囲の承認をやり直す
2. 種別ごとに次を実行する。

   ```bash
   bash scripts/extract-facts.sh <対象リポジトリのルート> --run <出力の置き場> --kind <種別> --design-root <設計書の置き場>
   ```

   取り出しの規則が「正規表現」の項目は道標の指定どおりに `grep -E` で行単位に走査して捕捉値を集める。「AIの読み取り」の項目は値を空のまま「未」へ載せる。単位ごとの事実ファイルを `facts/<種別>/<単位のフォルダ名>.json` に書き、`facts/<種別>/集計.json` に単位数・機械で埋まった項目数・未の項目数・規則の無い項目を書く
3. 終了コードを見る。0なら次へ。1なら一覧の属するファイルが対象に実在しないことを意味する。一覧を作る機能の当該領域の調査（検出条件）へ差し戻す（差し戻し: 検出条件-見直し）。2なら道標・一覧の不在などの使い方の誤りであり、前提を整えてからやり直す。差し戻しの回数に上限は設けない。同じ不合格が2回続いたら取り出しの規則の書き方を変えるなど方法を変え、方法が尽きたら人に戻さず、確認事項に登録してその項目を未に残し先へ進む
4. `未` に載った項目（「AIの読み取り」の項目と、機械で0件だった項目）を、AIが単位の属するファイルを読んで埋める。同じ手順でもう一度別の一時領域へ読み、`bash scripts/compare-facts.sh <一時領域> <正の出力先> --kind <種別>` で比べる。違えば3回目を読み、2回一致した値を採る。それでも決まらなければ確認事項に登録し、値は空のまま「未」に残す
5. `bash ../reverse-shared/scripts/units-status.sh <出力の置き場> set <種別> <識別子> 事実 済` を、未が空になった単位ごとに記録する。手順2の実行時点で未が空の単位は自動で記録済みである
6. 種別ごとの集計（単位数・機械で埋まった項目数・未の項目数）を報告する

`--verify` を付けて `extract-facts.sh` を実行すると、既存の出力ともう一度取り出した結果を比べ、違えば終了コード1で返す（差し戻し: 工程内-やり直し）。機械の取り出しは決定的であるべきという完了条件を確かめる手段として使う。差し戻しの回数に上限は設けない。同じ不一致が2回続いたら取り出しの規則を見直すなど方法を変え、人に戻さない

## 完了条件

- 一覧の全単位に事実ファイルがある
- 事実ファイルが形の定義（reverse-shared/references/fact-shapes.json）に合う
- 同じコードから2回取り出して一致する（`--verify` または手動の2回読みで確認）
- `tests/` の全件が通る

## 設計判断

### extract-facts.sh

**必要性**: 事実の取り出しは「同じコードから2回取り出して一致する」という完了条件を担う工程であり、AIの読みだけでは決定性を保証できない。道標の取り出しの規則を機械で実行して行単位に捕捉することで、再現可能な値と根拠を単位ごとに固定できる。取り出しの規則の解釈（正規表現・捕捉番号・範囲・パイプのエスケープ）とAIの読み取り項目の分離は複数段の分岐を持ち、Bashツールの直叩きでは毎回再現できない。

**代替案を採用しなかった理由**:
- 言語ごとの取り出しスクリプトを機能が持つ: 知らないリポジトリに既製の取り出し方を当てることになり、対象ごとに合わない。取り出し方は道標が対象を読んで組む
- AIが毎回読んで取り出す: 再現性が無く、2回一致の完了条件を機械で確かめられない

**保守責任者**: 人手（ユーザー）。取り出しの規則の書式（項目・区切り・既定値）を変えるときは、道標の様式（reverse-drawing-map）と本スクリプトと自己テストを同時に直す。

**廃棄条件**: 取り出しの規則の形を別の仕組み（構文解析器など）に置き換えた時。

### compare-facts.sh

**必要性**: `--verify` および2回読みの一致確認は、事実ファイルの「値」の集合を単位ごと項目ごとに突き合わせる処理を要する。手作業での目視比較は項目数が多いと見落とすため、機械で差分を列挙する。

**代替案を採用しなかった理由**:
- `diff` によるファイル全体の比較: 値の並び順の違いを不一致と誤判定する（値は集合として比べるべきで順序は意味を持たない）
- AIが目視で2つのJSONを見比べる: 項目数・単位数が増えると見落としが生じ、完了条件の確認として機械的でない

**保守責任者**: 人手（ユーザー）。事実ファイルの形（事実.<項目>.値）を変えるときは、extract-facts.shと本スクリプトと自己テストを同時に直す。

**廃棄条件**: 事実の一致確認を別の仕組みに変えた時。
