本書は画面だけが持つ文書であり、単一画面内の操作の流れを扱う。画面をまたぐ結合テストはプロジェクト全体の `docs/design/common/種別横断結合テスト設計書.md` が担う。

本書は画面の操作要素に対する意味のあるシナリオを定義し、`画面結合テスト設計書.md` のケースキーおよび往復検証観点キーと対応付ける。シナリオはポータル表示用の一覧表と機械実行用YAMLの両方を持ち、内容を一致させる。

## 機械実行用YAML

一覧表とシナリオ別仕様に記載した全シナリオを、次の形で重複なく記載する。`key`、`name`、`start_state`、`roundtrip_viewpoint_key`、`screen_test_case_key` は一覧表と一致させる。`operations` の順序・action・target・value・expected はシナリオ別仕様と一致させる。

```yaml
scenarios:
  - key: <検索条件入力-結果反映>
    name: <検索条件を入力して結果へ反映する>
    start_state: <初期表示済み>
    roundtrip_viewpoint_key: <操作後-画面反映>
    screen_test_case_key: <検索実行-結果表示>
    preconditions:
      - <対象画面が初期表示済みである>
      - <必要なテストデータが存在する>
    operations:
      - action: fill
        target: <検索条件入力欄>
        value: <検索語>
        expected: <入力値が表示される>
      - action: click
        target: <検索ボタン>
        expected: <検索結果が表示される>
    end_conditions:
      - <検索結果が表示され、読み込み中表示が残っていない>
```

## 記入規則

- `action` は `click`、`fill`、`select`、`check`、`uncheck`、`press`、`navigate` のいずれかを使う
- 1シナリオに複数の操作を記載し、操作の順序を保持する
- 各操作は、操作直後に観測する `expected` を持つ
- 一覧表、シナリオ別仕様、YAMLのキー・操作数・操作順・期待結果を一致させる
- `対応往復検証観点キー` と `roundtrip_viewpoint_key` は、画面結合テスト設計書の往復検証観点キーに一致させる
- `対応画面テストケースキー` と `screen_test_case_key` は、画面結合テスト設計書のケースキーに一致させる
- 意味の異なる操作の流れを1シナリオへ詰め込まず、開始状態または目的が異なる場合は別の意味キーに分ける
