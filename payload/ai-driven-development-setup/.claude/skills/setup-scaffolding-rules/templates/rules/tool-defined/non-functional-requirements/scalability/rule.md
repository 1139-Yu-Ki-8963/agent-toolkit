# 利用が増えたときの決まり

## 概要

利用の量が増えたときに、どこまで・どうやって対応するかの要件。

量の増加は、ある一点を越えるまで症状を出さないため、増えてから考えると間に合わない。基本設計書の方式設計で、この要件を満たす方式を確定する。方式をどの文書のどの節へ書くかは、設計書の書き方の決まりが定める。

## 規則

| 規則 | 内容 | 検査 |
|---|---|---|
| 増加の見込みを数値で置く | 利用者数・データ件数・処理件数が、いつまでにどこまで増えるかの見込みを数値で置く | 静的解析: 要件定義書または基本設計書に増加の見込みの記述があるかを走査する |
| 増やす方向を決める | 台数を増やして対応するのか、1台を大きくして対応するのかを先に決める | 静的解析: 基本設計書に拡張の方向を述べた記述があるかを走査する |
| 処理の側に状態を残さない | 台数を増やして対応する場合、処理を行う側に利用者ごとの状態を保持しない | 静的解析: 処理を行う層に利用者ごとの状態を保持する記述が無いかを走査する |
| 件数に比例する処理を作らない | 全件を読み込んでから絞り込む処理を作らず、絞り込みをデータの側で行う | 静的解析: 全件の取得の後に絞り込みを行う記述が無いかを走査する |
| 上限に達したときの振る舞いを決める | 処理の量が上限に達した場合に、待たせるのか断るのかを決める | 静的解析: 受け付けの入口に流量の制限が設定されているかを走査する ／ レビュー: 上限に達したときに待たせるのか断るのか、決めた振る舞いの中身を確認する |

## 違反時の手順

書き込みが止められた場合、全件を取得してから絞り込んでいる箇所を、絞り込みの条件をデータの側へ渡す形へ書き直す。増加の見込み・拡張の方向・流量の制限が見当たらないと知らされた場合は、要件定義書または基本設計書へ該当する記述を書き足す。処理の層に利用者ごとの状態を保持していると知らされた場合は、その状態を処理の外側（データの保管先や共有の記憶）へ移す。
