# 基本設計の完了状態の観点

出典: 規約「設計書の書き方の決まり」の基本設計書の完了状態。「不明点が
存在しない」は既定の有無で判定する（既定を置ければ確認事項、置けなければ
保留）。

各単位・各共通設計文書を、次の6観点で判定する。1つでも否があれば不合格。
すべて合であれば合格。既定を置けない不明点があるときだけ保留にする。

| 観点 | 合の基準 | 否のときの差し戻し先 |
|---|---|---|
| 外部仕様の確定 | 画面・帳票・外部インタフェースの仕様に曖昧さが無い | 基本設計-不合格 |
| 業務ルールと例外系の確定 | 取消・二重送信・リトライ・タイムアウトなどの扱いに矛盾が無い | 基本設計-不合格 |
| 非機能の方式の確定 | 性能・可用性・セキュリティ・監査・運用・災害対策の方式が決まっている | 基本設計-不合格（共通設計文書に起因するなら共通設計-再承認） |
| データの整合性・トランザクション境界・排他の確定 | 整合性・境界・排他の方針が決まっている | 基本設計-不合格 |
| 不明点の不在 | 未確定の事項に既定が置けている（既定が無ければ保留） | 保留 |
| 単体テスト設計書の実在 | 同じフォルダに単体テスト設計書がある（機能を除く） | 基本設計-不合格 |

## 判定の手順

1. `scripts/check-basic-phase.sh` の機械検査を先に読む。1件でも不合格があれば
   その単位・文書は基本設計-不合格として扱い、観点表は読まない
2. 機械検査を通った単位・文書だけを、文書のレビュー担当（AI）が上記6観点で読む
3. 各観点を合・否で判定し、`scripts/record-acceptance.sh` で記録する
4. 既定を置けない不明点だけを保留にする。保留は所定の確認事項として工程
   2-12で提示し、前倒しで人に聞かない
