# 版付けと公開の決まり

## 概要

版の付け方・公開の手順・公開の後の切り戻しの取り決め。

公開は利用者へ届いた時点で取り消せなくなるため、届く前に止める機会を手順の中へ置く。何をいつ公開したかを、公開した本人以外が後から追える状態を保つ。

## 規則

| 規則 | 内容 | 検査 |
|---|---|---|
| 版の付け方を決める | 版の番号の付け方を決め、番号の増え方から変更の大きさが読めるようにする。既定の形式は `<主>.<副>.<修正>` の3つの数字を点で区切る形式とする | 静的解析: `<主>.<副>.<修正>` の形式に一致するかを走査する。値はこのプロジェクトの規則の表で上書きできる |
| 変更の履歴を版ごとに残す | 各版で何が変わったかを、利用者の視点で残す | 静的解析: 変更の履歴のファイルが実在し、最新の版の項目を持つかを走査する ／ レビュー: 記述が利用者の視点で書かれているかを確認する |
| 公開の手順を自動で実行する | 公開の操作を手順として自動化し、手作業の並びに依存させない | 静的解析: 継続的な配布の設定ファイルが実在し、公開の手順が登録されているかを走査する |
| 検査を通った成果物だけを公開する | テストと静的解析を通過した成果物だけを公開の対象にする | 静的解析: 配布の設定に、公開の前段としてテストの実行が登録されているかを走査する ／ テスト: テストを意図的に失敗させ、公開が実際に止まることを確かめる |
| 公開の記録を残す | 何を・いつ・誰が公開したかを記録へ残す | 静的解析: 公開の記録が版管理または配布の仕組みへ残る設定になっているかを走査する ／ テスト: 公開を1回実行し、記録が実際に残ることを確かめる |

## 違反時の手順

公開・版付けの操作が止められた場合、変更履歴のファイル（CHANGELOG.md 等）を作成または更新し、これから公開する版の項目を利用者の視点で書き足してから同じコマンドを再実行する。
