# 顧客向け文書の文体の決まり

## 概要

顧客へ提示する文書の地の文をである調で書く取り決め。2026-09-05、配る規約と配布物のひな形の間にあった文体の食い違い（改善指示書 第1回 1-16）を人が裁定し、である調へ統一すると決定した。

私たちの作業のための文書（設計判断の記録・配布するスキルの定義・レビューを担う定義・規約定義のテンプレート等）は敬体で書いてもよい。この使い分けは、同じフォルダに置く定義ファイル（basenameと配置条件の組）で機械的に管理し、対象の除外をスクリプト本体へ直書きしない。

## 規則

| 規則 | 内容 | 検査 |
|---|---|---|
| 顧客向け文書の地の文をである調にする | 顧客へ提示する設計書・帳票・生成物の地の文はである調（である・だ）で書く。コメント・表の行・見出し・コード柵は判定の対象外とする。私たちの作業のための文書（設計判断の記録・配布するスキルの定義・レビューを担う定義等）は定義ファイルの一覧に登録して除外する | 静的解析: check-document-style-register.sh が地の文の文末を走査し、除外定義に無いファイルの敬体（です・ます・でしょう・ましょう・ください）の文末を検出する |

## 違反時の手順

書き込みが止められた場合、敬体で書いた地の文をである調へ書き直す。設計判断の記録・配布するスキルの定義・レビューを担う定義など、私たちの作業のための文書は敬体のままでよい。除外の対象を増やす場合は、同じフォルダの document-style-exclusions.json へ basename と配置条件を追記する。
