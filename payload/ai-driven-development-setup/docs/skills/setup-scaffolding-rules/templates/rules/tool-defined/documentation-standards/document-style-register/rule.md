# 顧客向け文書の文体の決まり

## 概要

顧客へ提示する文書の地の文を敬体で書く取り決め。

私たちの作業のための文書（設計判断の記録・配布するスキルの定義・レビューを担う定義・規約定義のテンプレート等）は常体で書いてよい。この使い分けは、同じフォルダに置く定義ファイル（basenameと配置条件の組）で機械的に管理し、対象の除外をスクリプト本体へ直書きしない。

## 規則

| 規則 | 内容 | 検査 |
|---|---|---|
| 顧客向け文書の地の文を敬体にする | 顧客へ提示する設計書・帳票・生成物の地の文は敬体（です・ます）で書く。コメント・表の行・見出し・コード柵は判定の対象外とする。私たちの作業のための文書（設計判断の記録・配布するスキルの定義・レビューを担う定義等）は定義ファイルの一覧に登録して除外する | 静的解析: check-document-style-register.sh が地の文の文末を走査し、除外定義に無いファイルの常体（である・だ）の文末を検出する |

## このプロジェクトの規則

| 規則 | 内容 | 検査 |
|---|---|---|
| 未解析 | この規約に対応する実装の慣行は、まだ観測していない。リバース解析を実行して対象コードを分析すると、その結果からこの節へ規則が起こされる。解析を待たずに規則を決めたい場合は、この節へ直接書き足してよい | 不可: 観測の有無は解析の実行結果に依存し、静的解析で判定できない |

## 違反時の手順

書き込みが止められた場合、常体で書いた地の文を敬体へ書き直す。設計判断の記録・配布するスキルの定義・レビューを担う定義など、私たちの作業のための文書は常体のままでよい。除外の対象を増やす場合は、同じフォルダの document-style-exclusions.json へ basename と配置条件を追記する。
