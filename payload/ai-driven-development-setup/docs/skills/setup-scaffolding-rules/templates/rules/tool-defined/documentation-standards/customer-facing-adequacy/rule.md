# 顧客へ提示する文書の決まり

## 概要

顧客へ提示する設計書・生成物に、作る側の内部事情・指示・第三者呼称を残さない取り決め。

対象は `<project_root>` 配下の生成物（基本設計書・詳細設計書・生成HTML）に限る。テンプレートと本検査が読む定義ファイル自身は対象外とする。

## 規則

| 規則 | 内容 | 検査 |
|---|---|---|
| 作る側の指示を顧客向け文書へ残さない | 「〜を移す」「〜へ記入する」などの作業指示文をそのまま本文へ残さない | 静的解析: check-customer-facing-adequacy.sh の第1カテゴリ（指示文の残存）が該当語を検出し FAIL とする |
| 読み手を第三者として呼ばない | 読み手を「利用者」「対象プロジェクト」等の第三者として突き放す呼び方をしない | 静的解析: check-customer-facing-adequacy.sh の第2カテゴリ（第三者呼称）が該当語を検出し FAIL とする |
| 作る側の事情を顧客向け文書へ書かない | 「対象コード」「移送」など、作る側だけに意味がある事情語を書かない | 静的解析: check-customer-facing-adequacy.sh の第3カテゴリ（作る側の事情語）が該当語を検出し FAIL とする |
| 顧客が対応できない確認先を指定しない | 顧客が連絡・照会できない内部の確認先を指定しない | 静的解析: check-customer-facing-adequacy.sh の第4カテゴリ（確認先の妥当性）が該当語を検出し FAIL とする |
| 実装言語の用語と略語を説明する | プログラミング言語や実装の慣用語・略語を、説明なしに使わない | 静的解析: check-customer-facing-adequacy.sh の第5カテゴリ（実装言語の用語と略語）が該当語を検出し REVIEW とする（機械化できない範囲は人手のレビューで判定する） |
| 指示語だけに頼らず内容を自己完結させる | 「上記」「前述」などの指示語だけに頼らず、参照先を明示して文を自己完結させる | 静的解析: check-customer-facing-adequacy.sh の第6カテゴリ（指示語の自己完結）が該当語を検出し REVIEW とする（機械化できない範囲は人手のレビューで判定する） |

## このプロジェクトの規則

| 規則 | 内容 | 検査 |

| 未解析 | この規約に対応する実装の慣行は、まだ観測していない。リバース解析を実行して対象コードを分析すると、その結果からこの節へ規則が起こされる。解析を待たずに規則を決めたい場合は、この節へ直接書き足してよい | 不可: 観測の有無は解析の実行結果に依存し、静的解析で判定できない |

## 違反時の手順

書き込みが止められた場合、該当箇所を読み手（顧客）が理解できる言葉へ書き直す。REVIEW と判定された箇所は、人手のレビューで文脈に照らして適切かどうかを確認する。
