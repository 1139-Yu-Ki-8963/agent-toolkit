# 状態の移り変わりの決まり

## 概要

業務の対象が取りうる状態と、状態のあいだで許される移り変わりの取り決め。

許されない移り変わりは、起きてから戻す手段が無い場合が多い。状態と移り変わりの一覧を先に確定し、実装がそれ以外の移り変わりを作らない状態にする。

状態と移り変わりの一覧そのものは状態遷移図の成果物が持つ。本書は状態をどう決め、どう保つかを定め、一覧は持たない。

## 規則

| 規則 | 内容 | 検査 |
|---|---|---|
| 状態を列挙する | 対象が取りうる状態をすべて列挙し、名前を1つに決める | 静的解析: 基本設計書に状態の一覧が実在するかを走査する ／ レビュー: 列挙が対象の実際の状態を網羅し、同じ状態に複数の名前が付いていないかを確認する |
| 許す移り変わりを表で書く | どの状態からどの状態へ移れるかを表で書き、書いていない移り変わりを許さない | 静的解析: 基本設計書に状態の移り変わりの表が実在するかを走査する ／ テスト: 表に書いていない移り変わりを実行した場合に拒否されることを確かめる |
| 移り変わりの引き金を書く | 各移り変わりについて、何が起きたときに移るかを書く | 静的解析: 移り変わりの表に引き金の欄が埋まっているかを走査する |
| 状態を文字列の直接の比較で扱わない | 状態を名前の付いた定数として定義し、文字列の直接の比較で判定しない | 静的解析: 状態の判定に文字列の直接の比較が無いかを走査する |
| 移り変わりを1箇所で行う | 状態を変える処理を1箇所へ集め、複数の場所から直接書き換えない | 静的解析: 状態の項目への代入が複数の場所に現れていないかを走査する |
| 終わりの状態を決める | それ以上移らない状態を明示し、その状態からの変更を禁じる | 静的解析: 状態の一覧に終わりの状態の区分が存在するかを走査する ／ テスト: 終わりの状態から別の状態へ変更しようとした場合に拒否されることを確かめる |

## 違反時の手順

書き込みが止められた場合、状態を表す文字列リテラルを名前の付いた定数へ置き換え、比較をその定数との比較に書き直してから改めて書き込む。比較の相手が状態ではなく、たまたま status や state を含む識別子だった場合は、定数化せずそのまま書き込んでよい。
