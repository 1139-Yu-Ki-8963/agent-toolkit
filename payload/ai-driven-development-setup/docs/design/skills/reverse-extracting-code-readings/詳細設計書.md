## §2 処理の定義

**この節の位置づけ: 現行実装**

1. `check-entry.sh` で範囲の承認（可否・調査と検出条件の定義書の同一性）を確かめる。
2. 種別ごとに `extract-code-readings.sh` を実行し、正規表現の項目は `grep -E` で捕捉、AIの読み取りの項目は値を空のまま「未」へ載せる。
3. 終了コードを見て、1なら一覧を作る機能の当該領域の調査へ差し戻し、2なら前提を整えてやり直す。
4. 「未」に載った項目をAIが読んで埋め、別の一時領域へもう一度読んで `compare-code-readings.sh` で比べる。一致しなければ3回目を読み、2回一致した値を採る。
5. `units-status.sh` で未が空になった単位ごとに「読み取り結果 済」を記録する。
6. 種別ごとの集計を報告する。

## §3 ロジック

**この節の位置づけ: 現行実装**

### extract-code-readings.sh

読み取り結果の取り出しは「同じコードから2回取り出して一致する」という完了条件を担う工程であり、AIの読みだけでは決定性を保証できない。調査と検出条件の定義書の取り出しの規則を機械で実行して行単位に捕捉することで、再現可能な値と根拠を単位ごとに固定できる。extract-code-readings.shは現状、list-units-of.shの出力を識別子・表示名・場所・属するファイルの位置で読む。フォルダ名は識別子から`unit-dir-name.sh`を直接呼んで得ており、list-units-of.shの5列目（フォルダ名）を読むよう変える対象である。

`--verify`の分岐は、比較の一致判定を返す前に再取り出しの戻り値を見る。戻り値が1（規則を解釈できない項目・属するファイルの不在）なら、比較が一致していても標準エラーへ理由を出し終了コード1で返す。戻り値が2以外で比較が不一致のときは従来どおり終了コード1で返す。両方が正常（戻り値0）かつ比較が一致したときだけ終了コード0で返す（改善指示書 第1回 1-8）。

取り出しの規則の「範囲」は `場所`・`単位`・`両方`・`属するファイル`・`単位の定義` の5値を取る。`normalize_scope()` は前方一致で判定するため、「単位の定義」は「単位」より先に照合し「単位」へ丸められないようにする。範囲が `単位の定義` のとき、切り出しの終端は一覧の次の単位の直前の行（他の値と同じ従来の終端）ではなく、定義を開く文の行以降で最初に開く括弧（丸`()`・角`[]`・波`{}`の3種をまとめて1つの残高で数える）が閉じる行までとする。行の末尾に1個以上並ぶ`\r`を除いてから扱う（CRLFのファイルでも空行を空行として判定し、先読みの空行飛ばしが正しく働くようにするため）。残高は文字ごとに数え、開き文字（`(`・`[`・`{`）で+1、閉じ文字（`)`・`]`・`}`）で-1とする。閉じ文字で残高が0に戻った直後、空白を除く次の文字が`;`または`,`のとき、またはそこで行が終わるときはその行を終端とし残りの文字は数えない（`,`は呼び出し式や配列要素の区切りであり本体が続かないため。`CREATE TABLE t (id INT);`は1行、`); CREATE TABLE zombi (`は`;`の位置で終端になり同じ行に続く次の定義の開きを取り込まない、`wrap(fn, "orders-real"),`は`,`の位置で終端になり次行の除外オブジェクトを取り込まない）。次の文字が`;`・`,`以外（`{`・`:`など）なら数え続け、行末で残高が0に戻っていれば、残高を0に戻した閉じ文字が丸括弧`)`のときに限り、探索範囲内の次の空白でない行の、空白を除く最初の文字が波括弧`{`かどうかで先読みする。波括弧なら終端にせず数え続け、そうでなければその行を終端とする（`function Foo(props) {`は対応する`}`の行が終端、波括弧を次行に置く様式（`function foo($x)`の次行が`{`）は先読みにより`{`のある行へ進み、対応する`}`の行が終端になる）。閉じ文字が波括弧`}`または角括弧`]`のときは、次の行の先頭が波括弧`{`であっても先読みをせずその行を終端とする（オブジェクトを並べる様式（`},`の次行が`{`）で、閉じた単位の内容に隣のオブジェクトが混入することを防ぐ）。丸`()`・角`[]`は先読みが判定する次の行の先頭文字としても対象から除く（`CREATE TABLE a (…)`の次行が`(SELECT …);`のような別の文の開始を誤って取り込まないため）。探索は一覧の次の単位の直前の行までに限る（この境界を超えて次の単位の閉じ括弧を誤って終端に採ることを防ぐ）。一覧から意図して除外した定義（廃止されたもの）が直前の単位と次の単位の間に残っている場合でも、この終端決定で除外された定義の内容を隣の単位が取り込まない。最初の開き括弧が現れる前に探索範囲が尽きるか、範囲内で残高が0に戻らなければ、従来の終端（一覧の次の単位の直前の行）に落ちる。`場所`・`単位`・`両方`・`属するファイル`の終端の決め方は変えない（第1回改善指示書1-28）。起票にあった、行頭側の見た目（字下げを取り除いた先頭の文字）で終端の行を判定する案は、開始行以降の括弧の対応を数える本設計と食い違うため採らなかった。既知の限界は6つある。(1)本体を括弧で囲まない定義（Pythonの`def`、Rubyの`end`など）は、閉じても行末で残高が0のまま終わるため開始行だけを取る。`def f(x):`は`(x)`の対応が閉じた直後の文字が`:`で`;`でも行末でもないため数え続けるが、行末時点で残高が0のため、次の行（インデントされた本体の1行目）は先頭が波括弧ではなく先読みで救えず、開始行自身が終端になる。ただし次の行が`{`で始まる場合は続行する（例: `def f(x):`の次行が`(a, b) = (x, y)`のような丸括弧始まりの行なら先読みは救わず開始行だけになるが、次行が`{`で始まる混在様式なら続行する）。(2)デコレータや注釈の行（`@Injectable()`など）から始まる定義は、デコレータの括弧が閉じる行までになり、本体は取れない。戻り値の型が`[]`で終わる署名（TypeScriptの`function f(): string[]`など）の次行に`{`を置く様式は、署名行自体で丸括弧`()`に続く角括弧`[]`の対応が閉じて残高が0に戻った直後は行末であり、次の行の先頭が波括弧にならないため先読みでは救えず開始行だけになる。(3)署名と`{`の間にコメント行があるときも同様に開始行だけになる（先読みは空行だけを飛ばし、コメント行は飛ばさない。言語ごとのコメント記法を判定しないため）。検出条件は開始行が定義の文（`class`・`function`・`CREATE TABLE`など）の行になるように書く。(4)文字列やコメントの中の括弧も数えるため、閉じ括弧があれば定義の途中で終端になり（欠落）、開き括弧があれば閉じずに従来の終端まで伸びる（取り込み）。(5)切り出しは行単位のため、次の定義が一覧に無いときは終端の行の残り全体を取り込む。一覧に載る次の単位が同じ行から始まるときは、探索範囲（一覧の次の単位の直前の行まで）がその手前で切れるため、範囲内で残高が0に戻らず終端が決まらず従来の終端に落ちる（行粒度）。(6)メソッド連鎖（`.get(…)`を次の行に続ける書き方）は最初の呼び出しの括弧が閉じた行で終端になり、続く連鎖を取れない。開始行を連鎖の全体を含む文にする検出条件を書く。`check-survey-definition.sh` は取り出しの規則の「範囲」列の値を検査しないため、5値以外の値が書かれていても止めない。

言語ごとの取り出しスクリプトを機能が持つ案は、知らないリポジトリに既製の取り出し方を当てることになり対象ごとに合わないため採らない。AIが毎回読んで取り出す案は再現性が無く、2回一致の完了条件を機械で確かめられないため採らない。

出力先は単位ごとに`${out}/${kind}/${dirname}.json`（フォルダ名は list-units-of.sh の5列目）で組み立てるため、フォルダ名が空・書き込み先として使えない値、または正規化して同じ値になる（大文字小文字だけ・NFC/NFDの合成分解だけ・`ß`と`ss`のような大文字小文字の畳み込みだけの違いを含む）と、単位を取り違えたまま黙って上書き・欠落する、または出力先の外へ書く。単位を処理する前に`classify_dirname()`でフォルダ名を1件ずつ検査する。空の判定は、半角空白・全角空白U+3000・タブ・改行・ゼロ幅空白U+200B・BOM U+FEFFを除いて空かどうかで行う（list-units-of.shの表示名の空白判定と同じ集合）。空でなければ、`/`を含む・`.`または`..`・`\`を含む・制御文字0x00-0x1F/0x7Fを含む・先頭が`.`のいずれかを不正な名前とする。どちらでもない値は、UnicodeのNFCへ揃えたうえで大文字小文字を畳み込んだ値（`perl -CSDA -MUnicode::Normalize -Mfeature=fc,unicode_strings`の`fc()`で得る。perl 5.16以降が前提。`fc`は完全な大文字小文字の畳み込みを行い、`lc`が別扱いにする`ß`と`ss`も同じ値に畳み込む）を鍵にして重複を判定する。空なら標準エラーへ`[FAIL] フォルダ名-空: <種別>: 識別子=<識別子>`、不正なら`[FAIL] フォルダ名-不正: <種別>: フォルダ名=<名前> 識別子=<識別子>`、重複なら`[FAIL] フォルダ名-重複: <種別>: フォルダ名=<正規化前の名前の列挙> 識別子=<識別子の列挙>`を出し終了コード2で止める（検査キー`フォルダ名-空`・`フォルダ名-不正`・`フォルダ名-重複`）。いずれの検査も出力先へのフォルダ作成・書き込み（`mkdir -p ${out}/${kind}`）より前に行う。処理の最後には、単位数の報告と出力フォルダの実ファイル数（集計.json自身を除く）を突き合わせ、食い違えば`[FAIL] 出力-件数不一致: <種別>: 単位数=<N> 実ファイル数=<M>`を出し終了コード2で止める（検査キー`出力-件数不一致`。フォルダ名の空・不正・重複以外の理由で実ファイルが欠ける事態、および単位を減らした後も同じ出力先へ出し続け前回実行の古いファイルが残って余る事態の両方を見落とさないための保険）。再実行の照合（`--verify`）は入出力とも同じ壊れ方を再現するため、この種の再現性のある壊れ方は検出できない。このフォルダ名の一意性検査を先に置く理由はそこにある（第1回改善指示書1-30・反証）。既知の限界: フォルダ名の重複検査は識別子の値だけを見るため、ある単位のフォルダ名が集計ファイルの名前（`集計`）、または正規化して`集計`に一致する名前と一致する場合までは検知しない。この場合は実ファイル数の突合が`集計.json`を除いた数で食い違い、`出力-件数不一致`として検出される。

`classify_dirname()`はperl（`Unicode::Normalize`・`fc`。`fc`はperl 5.16以降の機能）を前提とする。前提が満たせない環境で呼ぶと判定できないまま空・想定外の出力を返し、フォルダ名-空/フォルダ名-不正/フォルダ名-重複の検査を素通りしたまま単位を処理してしまう（fail-open。`../escaped`のような不正な名前が出力先の外へ書かれる。第1回改善指示書1-30・第2版反証）。単位を1件でも処理する前に`check_dirname_classifier_prerequisite()`（`perl -CSDA -MUnicode::Normalize -Mfeature=fc,unicode_strings -e 'print fc(NFC("A"))'`が`a`を返すかどうか）で前提を確かめ、満たせなければ`[FAIL] 前提-perl不在: <種別>: perl 5.16以降・Unicode::Normalize・fcのいずれかが使えないためフォルダ名の検査ができません`を出し終了コード2で止め、何も書かない（検査キー`前提-perl不在`）。`perl -MUnicode::Normalize -e 1`だけの確認では`Unicode::Normalize`の読み込み可否しか確かめられず、`fc`（perl 5.16以降の機能）が無い環境でも前提検査を誤って通過してしまう（第1回改善指示書1-30・第3版反証）。前提不成立の理由がperl本体の不在なのか、Unicode::Normalizeの不在なのか、fc（perl 5.16未満）の不在なのかを`check_dirname_classifier_prerequisite()`は区別しないため、メッセージも3つのいずれかが原因でありうることを示す（第1回改善指示書1-30・第4版反証所見1）。加えて`classify_dirname()`の戻り値を1行の判定へ変換する`classify_dirname_row()`は、戻り値が`EMPTY`・`OK\t<正規化した名前>`のいずれでもないとき（前提の確認漏れ・`classify_dirname()`自体が想定外の値を返す異常）はOKとして扱わずINVALIDへ倒す（fail-closed。前提確認の抜け漏れに対する保険）。

本スクリプトは macOS 標準の`/bin/bash`（3.2系）で動くことを前提とする。bash 3.2には、`case`文を`$( )`（コマンド置換）の直下に置くと、`case`のパターンに続く`)`を`$( )`の終端と誤認して構文エラーになる既知のパーサ不具合がある。このため`classify_dirname()`の判定は`case`文を持つ独立した関数（`classify_dirname_row()`）へ切り出し、`$( )`の中では関数呼び出しだけを行う（`case`を直接`$( )`の中に書かない）。自己テスト自身の判定文にも同種の記述があったため、`grep -q`を使う形に直した（第1回改善指示書1-30・第2版反証）。

保守責任者は人手（ユーザー）。取り出しの規則の書式を変えるときは、調査と検出条件の定義書の様式と本スクリプトと自己テストを同時に直す。

廃棄条件は取り出しの規則の形を別の仕組み（構文解析器など）に置き換えた時。

### compare-code-readings.sh

`--verify` および2回読みの一致確認は、読み取り結果ファイルの値の集合を単位ごと項目ごとに突き合わせる処理を要する。手作業での目視比較は項目数が多いと見落とすため、機械で差分を列挙する。

`diff` によるファイル全体の比較は値の並び順の違いを不一致と誤判定するため採らない。AIが目視で2つのJSONを見比べる案は項目数・単位数が増えると見落としが生じるため採らない。

保守責任者は人手（ユーザー）。読み取り結果ファイルの形を変えるときは、extract-code-readings.shと本スクリプトと自己テストを同時に直す。

廃棄条件は読み取り結果の一致確認を別の仕組みに変えた時。
