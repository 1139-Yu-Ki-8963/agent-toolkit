# コードの読み取り結果を取り出す（reverse-extracting-code-readings）の基本設計書

調査と検出条件の定義書の取り出しの規則を実行し、対象リポジトリのコードから単位ごとのコードの読み取り結果を取り出す。機械で埋まった項目とAIが埋める項目（未）を分けて固定する。

## §1 外部仕様

**この節の位置づけ: 現行実装**

### 要件との対応

| 要件の柱 | 要件の項目 | この機能が満たす内容 |
|---|---|---|
| 柱2 基盤一式の作成を支える | 出力: 種別ごとの設計書と、業務の言葉の決まりを含む規約 | 設計書へ転記する読み取り結果を種別・単位ごとに取り出し固定する |
| 柱2 基盤一式の作成を支える | 完了条件: 設計書だけからコードを再生成し、元のコードとの照合が通る | 同じコードから2回取り出して一致することを検証し、読み取り結果の再現性を確かめる |
| 支援ツール全体の制約 | 全機能がテストと合格基準を持つ。柱の合否は配下の機能の結果で決まる | 完了条件を明文化し、tests/ の自己テストで確かめる |

## §2 業務仕様

**この節の位置づけ: 現行実装**

### 手順

1. `check-entry.sh` で範囲の承認（可否・調査と検出条件の定義書の同一性）を確かめる。
2. 種別ごとに `extract-code-readings.sh` を実行し、正規表現の項目は `grep -E` で捕捉、AIの読み取りの項目は値を空のまま「未」へ載せる。
3. 終了コードを見て、1なら一覧を作る機能の当該領域の調査へ差し戻し、2なら前提を整えてやり直す。
4. 「未」に載った項目をAIが読んで埋め、別の一時領域へもう一度読んで `compare-code-readings.sh` で比べる。一致しなければ3回目を読み、2回一致した値を採る。
5. `units-status.sh` で未が空になった単位ごとに「読み取り結果 済」を記録する。`extract-code-readings.sh`に`--no-units-status`を付けるとこの書き込みを行わない（`--out`で出力先を退避しても実行フォルダの状態のファイルを書き換えないようにするため）。`--verify`は`--no-units-status`の指定に関わらず常にこの書き込みを行わない（照合は読むだけの操作であるべきため。第1回改善指示書1-38）。
6. 種別ごとの集計を報告する。

### 判定の規則

| 検査 | スクリプト | 検査キー |
|---|---|---|
| 取り出しの決定性 | scripts/extract-code-readings.sh --verify | 工程内-やり直し |
| 属するファイルの実在 | scripts/extract-code-readings.sh | 検出条件-見直し |
| 2回取り出しの一致 | scripts/compare-code-readings.sh | 値-不一致・単位-不在 |
| フォルダ名が空 | scripts/extract-code-readings.sh | フォルダ名-空 |
| フォルダ名が不正 | scripts/extract-code-readings.sh | フォルダ名-不正 |
| フォルダ名が重複 | scripts/extract-code-readings.sh | フォルダ名-重複 |
| 単位数と出力ファイル数の不一致 | scripts/extract-code-readings.sh | 出力-件数不一致 |
| フォルダ名検査の前提が不成立 | scripts/extract-code-readings.sh | 前提-perl不在 |

## §3 方式設計

**この節の位置づけ: 現行実装**

機械とAIの分担は、機械検査（`検査`節の各スクリプト）が形式・実在・網羅を確かめ、AIが業務の言葉への翻訳・判断を担う二段構成である。

実行方式はシェルスクリプトと`grep`・正規表現による走査であり、対象コードの言語に依存しない。

### extract-code-readings.sh

読み取り結果の取り出しは「同じコードから2回取り出して一致する」という完了条件を担う工程であり、AIの読みだけでは決定性を保証できない。調査と検出条件の定義書の取り出しの規則を機械で実行して行単位に捕捉することで、再現可能な値と根拠を単位ごとに固定できる。extract-code-readings.shは現状、list-units-of.shの出力を識別子・表示名・場所・属するファイルの位置で読む。フォルダ名は識別子から`unit-dir-name.sh`を直接呼んで得ており、list-units-of.shの5列目（フォルダ名）を読むよう変える対象である。

取り出しの規則の「範囲」は `場所`・`単位`・`両方`・`属するファイル`・`単位の定義` の5値を取る。範囲が `単位の定義` のとき、切り出しの終端は一覧の次の単位の直前の行ではなく、定義を開く文の行以降で最初に開く括弧（丸・角・波の3種をまとめて1つの残高で数える）が閉じる行までとする。行の末尾に1個以上並ぶ`\r`を除いてから扱う（CRLFのファイルでも空行を空行として判定するため）。残高が0に戻った直後、空白を除く次の文字が`;`または`,`のときはその行を終端とする（`,`は呼び出し式や配列要素の区切りであり本体が続かないため）。`;`・`,`のいずれでもなく行が終わるときは、残高を0に戻した閉じ括弧が丸括弧`)`のときに限り、探索範囲内の次の空白でない行の、空白を除く最初の文字が波括弧`{`かどうかで先読みする（関数の署名の後に本体の`{`が続く様式に限る）。波括弧なら終端にせず数え続け、そうでなければその行を終端とする。閉じ括弧が波括弧`}`または角括弧`]`のときは、次の行が波括弧`{`で始まっていても先読みせずその行を終端とする（オブジェクトを並べる様式で隣のオブジェクトを取り込まないため）。次の文字が`;`・`,`のいずれでも行末でもなければそのまま数え続ける。探索は一覧の次の単位の直前の行までに限る。一覧から意図して除外した定義（廃止されたもの）が残っていても、この終端決定で除外された定義の内容を隣の単位が取り込まない。最初の開き括弧が現れる前に探索範囲が尽きるか、範囲内で残高が0に戻らなければ、従来の終端（一覧の次の単位の直前の行）に落ちる。既知の限界は6つある。(1)本体を括弧で囲まない定義（Pythonの`def`・Rubyの`end`など）は開始行だけになる。ただし次の行が`{`で始まる場合は続行する。(2)デコレータや注釈の行から始まる定義は、デコレータの括弧が閉じる行までになり、本体は取れない。戻り値の型が`[]`で終わる署名（TypeScriptの`function f(): string[]`など）の次行に`{`を置く様式は、署名行自体の角括弧`[]`の対応が閉じて残高が0に戻った直後が行末となり先読みでは救えず開始行だけになる。(3)署名と`{`の間にコメント行があるときも同様に開始行だけになる（先読みは空行だけを飛ばし、コメント行は飛ばさない）。(4)文字列やコメントの中の括弧も数えるため終端が早まる（欠落）ことも従来の終端まで伸びる（取り込み）こともある。(5)切り出しは行単位のため、次の定義が一覧に無いときは終端の行の残り全体を取り込み、一覧に載る次の単位が同じ行から始まるときは探索範囲がその手前で切れ終端が決まらず従来の終端に落ちる（行粒度）。(6)メソッド連鎖（`.get(…)`を次の行に続ける書き方）は最初の呼び出しの括弧が閉じた行で終端になり、続く連鎖を取れない。開始行を連鎖の全体を含む文にする検出条件を書く（第1回改善指示書1-28）。

言語ごとの取り出しスクリプトを機能が持つ案は、知らないリポジトリに既製の取り出し方を当てることになり対象ごとに合わないため採らない。AIが毎回読んで取り出す案は再現性が無く、2回一致の完了条件を機械で確かめられないため採らない。

本スクリプトは macOS 標準の`/bin/bash`（3.2系）で動くことを前提とする。フォルダ名の重複判定はperl（`Unicode::Normalize`・`fc`。perl 5.16以降）を前提とし、前提が満たせない環境では何も書かずに検査キー`前提-perl不在`で終了コード2にする（詳細は詳細設計書 §3 ロジック）。

保守責任者は人手（ユーザー）。取り出しの規則の書式を変えるときは、調査と検出条件の定義書の様式と本スクリプトと自己テストを同時に直す。

廃棄条件は取り出しの規則の形を別の仕組み（構文解析器など）に置き換えた時。

### compare-code-readings.sh

`--verify` および2回読みの一致確認は、読み取り結果ファイルの値の集合を単位ごと項目ごとに突き合わせる処理を要する。手作業での目視比較は項目数が多いと見落とすため、機械で差分を列挙する。

`diff` によるファイル全体の比較は値の並び順の違いを不一致と誤判定するため採らない。AIが目視で2つのJSONを見比べる案は項目数・単位数が増えると見落としが生じるため採らない。

保守責任者は人手（ユーザー）。読み取り結果ファイルの形を変えるときは、extract-code-readings.shと本スクリプトと自己テストを同時に直す。

廃棄条件は読み取り結果の一致確認を別の仕組みに変えた時。

## §5 エラーと例外

**この節の位置づけ: 現行実装**

### --verify の終了コード

`extract-code-readings.sh --verify`は、比較が一致した場合でも判定する。再取り出しの戻り値が1（規則を解釈できない項目・属するファイルの不在）なら、標準エラーへ理由を出し終了コード1で返す。`--verify`の有無にかかわらず、規則を解釈できない状態は同じ終了コードで呼び出し元へ伝わる（改善指示書 第1回 1-8）。

### 終了コード・差し戻しの一覧

| 検査 | スクリプト | 検査キー |
|---|---|---|
| 取り出しの決定性 | scripts/extract-code-readings.sh --verify | 工程内-やり直し |
| 属するファイルの実在 | scripts/extract-code-readings.sh | 検出条件-見直し |
| 2回取り出しの一致 | scripts/compare-code-readings.sh | 値-不一致・単位-不在 |
| フォルダ名が空 | scripts/extract-code-readings.sh | フォルダ名-空 |
| フォルダ名が不正 | scripts/extract-code-readings.sh | フォルダ名-不正 |
| フォルダ名が重複 | scripts/extract-code-readings.sh | フォルダ名-重複 |
| 単位数と出力ファイル数の不一致 | scripts/extract-code-readings.sh | 出力-件数不一致 |
| フォルダ名検査の前提が不成立 | scripts/extract-code-readings.sh | 前提-perl不在 |

### 完了条件

- 一覧の全単位に読み取り結果ファイルがある。
- 読み取り結果ファイルが形の定義（reverse-shared/references/code-reading-items.json）に合う。
- 同じコードから2回取り出して一致する（`--verify` または手動の2回読みで確認）。
- `tests/` の全件が通る。
