# 調査と検出条件の定義書を書く（reverse-writing-survey-definition）の単体テスト設計書

**この文書の位置づけ**（別の言語で作り直す場合は、まず「仕様」から読む）

- 仕様: §1 テスト観点、§2 テストケース一覧、§3 入力条件、§4 期待結果、§5 異常系、§6 境界値、§7 網羅基準、§8 前提条件と終了条件
- 現行実装: 該当なし

## 本書が検証するもの

reverse-writing-survey-definitionが現場の実コードに対して書く調査と検出条件の定義書、および要件定義書・共通設計文書・承認の仕組みの品質を対象とする。検証は実際の現場コードで行い、検証者が現場コードを数え上げ本文と突き合わせる。

## テスト対象

| スクリプト | 自己テストの実行 | ケース数 |
|---|---|---|
| scripts/check-survey-definition.sh | bash scripts/check-survey-definition.sh --self-test | 28 |
| scripts/check-design-docs.sh | bash scripts/check-design-docs.sh --self-test | 13 |

## テストの粒度と自動化の方針

| 項目 | 方針 |
|---|---|
| テストの粒度 | 現場コード1件を対象に、調査と検出条件の定義書・要件定義書・共通設計文書・承認の仕組みそれぞれの観点を検証者が突き合わせる。 |
| 自動化 | 現場コードの数え上げと本文の突き合わせは検証者が手で行う。check-survey-definition.sh・check-design-docs.shの自己テストは実装の入出力・分岐・終了コードの回帰確認として別途`--self-test`で自動実行する（節「自己テスト」参照）。 |

## 本書が扱わない範囲

| 対象外の事項 | 対象外とする理由 | 代わりに確認する資料または試験 |
|---|---|---|
| 複数機能をまたぐ結合 | 単位ごとの文書は結合テストを扱わないため | docs/design/skills/reverse-orchestrating-flow/ |
| 候補数の許容2割が定義書の節6以外にも適用されるか | 工程2-1の完了条件としてしか定義が無く未検証のため | 工程2-1の完了条件の定義箇所 |
| 要件の柱の項目単位の網羅 | 「要件-機能が入口を覆う」は業務の入口の網羅だけを照合し、要件の柱ごとの項目網羅までは照合していないため | 要件定義書の各柱の項目一覧 |

## §1 テスト観点

**この節の位置づけ: 現行実装**

| キー | 観点 | 区分 | 由来 |
|---|---|---|---|
| 定義書-帰属の網羅 | ルート直下のフォルダ・ファイルが、調査と検出条件の定義書の節2・節3の記述に漏れなく含まれる | 正常 | ai-work/todo/現場コードで検証するテストケースの案.md 第一フェーズ |
| 定義書-試作の除外 | 対象領域を1つに絞ったとき、絞り外のフォルダが理由付きで除外「その他」に分類される | 正常 | 同上 |
| 定義書-候補数の実在 | 領域内の接続窓口の候補数が、検証者の実測と2割以内で一致する | 正常 | 同上 |
| 定義書-検出条件の例 | 検出条件の例のパスが実在し、正規表現に一致し、一覧化で拾われる | 正常 | 同上 |
| 定義書-取り出しの規則の形 | 読み取り結果の項目の記述が「正規表現・捕捉・範囲」または「AIの読み取り」のどちらかの形で書かれ、地の文が無い | 正常 | 同上 |
| 定義書-対象外の理由 | 対象に存在しない種別が、理由「対象に存在しない」で対象外になる | 正常 | 同上 |
| 定義書-非UTF-8 | 非UTF-8のファイルが変換して読め、文字コードが節0に記録される | 境界 | 同上 |
| 要件-機能が入口を覆う | 各機能の対応する単位の候補を合わせると、業務の入口を全て含む | 正常 | 同上 |
| 共通設計-6文書の合格 | 共通方式の実装がある場合、共通設計の6文書の合格の記録があり未確定は確認事項に既定付きで登録される | 正常 | 同上 |
| 承認-同一性 | 承認後に調査と検出条件の定義書を変えると、同一性の検査が不合格になり後工程が止まる | 異常 | 同上 |

## §3 入力条件

**この節の位置づけ: 現行実装**

| 種類 | 内容 | 該当するケースのキー |
|---|---|---|
| ルート直下にフォルダとファイルがある現場コード | ルートディレクトリに複数のフォルダ・ファイルが並ぶ実在の対象 | 定義書-帰属の網羅-検証 |
| 領域を1つに絞った現場コード | 試作の対象領域が1つだけに限定された対象 | 定義書-試作の除外-検証 |
| 接続窓口を検証者が数えた現場コード | 領域内の接続窓口を検証者が実測して件数を得た対象 | 定義書-候補数の実在-検証 |
| 検出条件を書いた種別がある現場コード | いずれかの種別に検出条件の例のパスが書かれた定義書 | 定義書-検出条件の例-検証 |
| 節4の読み取り結果の項目の表がある定義書 | 読み取り結果の項目を列挙した表を持つ定義書 | 定義書-取り出しの規則の形-検証 |
| 対象に帳票が無い現場コード | 帳票に相当する種別が実在しない対象 | 定義書-対象外の理由-検証 |
| EUC-JPのファイルがある現場コード | 文字コードがEUC-JPのソースファイルを含む対象 | 定義書-非UTF-8-検証 |
| 業務の入口を検証者が数えた現場コード | 経路の登録とメニューの定義の合計件数を検証者が実測した対象 | 要件-機能が入口を覆う-検証 |
| 共通方式の実装がある現場コード | 認証・ログ等の共通方式が実装された対象 | 共通設計-6文書の合格-検証 |
| 承認後に定義書を変えた状態 | 承認済みの調査と検出条件の定義書へ承認後に変更を加えた状態 | 承認-同一性-検証 |

## §4 期待結果

**この節の位置づけ: 現行実装**

| 種類 | 内容 | 該当するケースのキー |
|---|---|---|

| 除外の理由付き分類 | 絞り外のフォルダが理由付きで除外に分類される | 定義書-試作の除外-検証 |

| 検出条件の例の実在一致 | 例のパスが実在し正規表現に一致し一覧化で拾われる | 定義書-検出条件の例-検証 |
| 読み取り結果の様式一致 | 読み取り結果の項目が既定の2形式のいずれかで書かれ地の文が無い | 定義書-取り出しの規則の形-検証 |
| 対象外理由の記載 | 対象に存在しない種別の理由が「対象に存在しない」になっている | 定義書-対象外の理由-検証 |
| 非UTF-8の変換読み取り | 文字コードが節0に記録され本文が読める形で現れる | 定義書-非UTF-8-検証 |
| 業務入口の網羅 | 各機能の対応する単位の候補が業務の入口を全て含む | 要件-機能が入口を覆う-検証 |
| 共通設計6文書の合格記録 | 6文書の合格の記録があり終了コード0 | 共通設計-6文書の合格-検証 |
| 承認後変更の不合格 | 同一性の検査が不合格になり後工程が止まる | 承認-同一性-検証 |
