# 確認事項一覧を作る（reverse-building-confirmation-items）の詳細設計書

## §1 構成要素

| スクリプト | 役割 |
|---|---|
| build-confirmation-items.sh | 確認事項一覧を組み立てる。`--verify`で既存の出力を設計書と突き合わせる検証も担う |

## §2 処理の定義

1. `<実行フォルダ>`と`--design-root <設計書の置き場>`を受け取る（`--design-root`省略時は`design-root.sh`で読む）
2. `confirmations/確認事項の記録.md`の8列表を読み、キーごとに行を保持する（見出し行・区切り行は除く）
3. 設計書の置き場配下の全`*.md`を走査し、「## 要確認事項一覧」節（前方一致で判定）を持つファイルごとに列見出しを読み、キー・事項・確認先・既定を抽出する。セル内の`\|`は分割前に退避し分割後に復元する
4. 記録に無いキーを、埋め方の規則（基本設計書§2）で8列に組み立てて追加する
5. 出力の全行の既定・反映先が空でないことを確かめる。空があれば`[FAIL] 行-空欄`で終了コード1
6. `--verify <確認事項一覧.md>`が指定された場合は、設計書から抽出したキーがすべて指定ファイルの「キー」列に現れるかだけを確かめる。欠けがあれば`[FAIL] キー-出力欠落`で件数を示し終了コード1
7. 通常実行では組み立てた表を`confirmations/確認事項一覧.md`へ書き、終了コード0
8. 確認事項一覧を書いた後、`confirmations/確認事項の提示の記録.md`を書く。持つのは提示した日（実行日）・確認事項の件数（表の行数）・未回答の件数（状態が「未回答」の行数）・提示した相手（既定は「開発チーム」）である。`--verify`のときは書かない

## §3 ロジック

### build-confirmation-items.sh

**必要性**: 基本設計書§3を参照。

**代替案を採用しなかった理由**: 基本設計書§3を参照。

**保守責任者**: 人手（ユーザー）。列見出しの組み合わせ・埋め方の規則を変えるときは、本スクリプトと自己テストと基本設計書§2を同時に直す。

**廃棄条件**: 基本設計書§3を参照。

### 列見出しの動的な読み分け

「## 要確認事項一覧」節の最初の表の行（見出し行）を1回だけ読み、列名（「キー」「確認事項」「事項」「確認先」「既定」）ごとの列番号を記憶してから、以降の行をその列番号で読む。列名を先頭から順に固定する方式は取らない（設計書ごとに列の並びと数が異なるため）。

### 単位の重複表記

同じキーが複数の設計書に現れる場合、最初に見つかった単位を採用し、2件目以降は件数だけを「ほかN件」として単位欄に添える。

### エスケープ済みパイプの扱い

表の1行を列へ分割する処理は共通のawk関数`split_row`に一本化する。分割前にセル内の`\|`を`@@ESCPIPE@@`へ置換し、`|`で分割した後に各列で元の`|`へ戻す。確認事項の記録・要確認事項一覧の抽出のすべてがこの関数を使うため、表記の扱いが機能全体で揃う。

### bash 3.2 互換の配列展開

`local -a arr=()`で宣言した配列が要素数0のとき、bash 3.2は`set -u`下で`"${arr[@]}"`の展開をunbound variableとして扱う。bash 4以降は空文字列として扱い問題にならない。本スクリプトは配列を連結・反復する箇所すべてで`[ "${#arr[@]}" -gt 0 ]`により要素数を先に確認してから展開する。エントリポイントは`if [ "${BASH_SOURCE[0]:-$0}" = "$0" ]; then main "$@"; fi`の形にする。sourceしたときは関数定義だけが読み込まれ実行されない。自己テストはこれを利用する。`/bin/bash`が3.2系のときだけ関数をsourceして`run_build`を直接呼び、記録ファイル不在・新規0件（全配列が空）でも実際にunbound variableにならないことを確かめる。

### 提示の記録が回答を持たない理由

回答は開発チームが確認事項一覧の回答欄へ直接書く。提示の記録が回答を写すと、同じ値が2か所に増え、どちらが新しいかを判定できなくなる。記録は提示した時点の事実（提示した日・確認事項の件数・未回答の件数・提示した相手）だけを持ち、回答の所在は確認事項一覧の1か所に保つ。

## §4 入出力の値

| 入力 | 形 | 出所 |
|---|---|---|
| 確認事項の記録 | Markdown（8列） | `<実行フォルダ>/confirmations/確認事項の記録.md` |
| 要確認事項一覧 | Markdown（節） | 設計書の置き場配下の各Markdown |

| 出力 | 形 | 置き場 |
|---|---|---|
| 確認事項一覧 | Markdown | `<実行フォルダ>/confirmations/確認事項一覧.md` |

## §5 エラー処理

| 検査 | スクリプト | 検査キー |
|---|---|---|
| 使い方の誤り | build-confirmation-items.sh | 判定不能-使い方の誤り |
| 既定・反映先の空欄 | build-confirmation-items.sh | 行-空欄 |
| 設計書のキーの出力欠落 | build-confirmation-items.sh --verify | キー-出力欠落 |

### 失敗したときの出力の扱い

既定・反映先の空欄で終了コード1になったときは、確認事項一覧も提示の記録もどちらも書かない。前回の実行が残した両ファイルはそのまま残るため、終了コード1のときの `confirmations/` の中身は最新の入力を表さない。名指しされたキーを埋めて実行し直すまで、両ファイルの値を当てにしない。
