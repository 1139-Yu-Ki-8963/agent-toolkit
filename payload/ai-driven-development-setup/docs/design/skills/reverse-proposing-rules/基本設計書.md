# 規約提案を出す（reverse-proposing-rules）の基本設計書

全設計文書とコードを読み、規約の提案（用語の追加候補を含む）を出典と提案先付きで確認事項の記録に登録する。AIが様式を埋め、検査スクリプトが形を固定する。

## §1 外部仕様

**この節の位置づけ: 現行実装**

### 要件との対応

| 要件の柱 | 要件の項目 | この機能が満たす内容 |
|---|---|---|
| 柱2 基盤一式の作成を支える | 出力: 業務の言葉の決まりを含む規約 | 対象コードから観測した慣行を、規約の分類（rule-taxonomy.json）へ提案として結び付ける |
| 柱2 基盤一式の作成を支える | 入力: 確認事項への回答と、規約提案の採否 | 提案の採否を工程2-12で聞けるよう、出典・提案先付きで規約提案.mdへ書く |

### 入力

| 入力 | 形 | 出所 |
|---|---|---|
| 全設計文書 | Markdown | `docs/design/` 配下 |
| コード | 対象コード一式 | 対象リポジトリ |
| 提案先の規約の一覧 | JSON | `../reverse-shared/references/rule-taxonomy.json`（`setup-scaffolding-rules`の写し） |
| 確認事項の記録 | Markdown（8列） | `confirmations/確認事項の記録.md` |

### 出力

| 出力 | 形 | 置き場 |
|---|---|---|
| 規約提案 | Markdown（観測・判断・観測なしの3節） | `confirmations/規約提案.md` |

### 実行の口

Skill("reverse-proposing-rules")として呼ぶ、または`scripts/`配下のスクリプトを直接実行する。

## §2 業務仕様

**この節の位置づけ: 現行実装**

### 手順

1. 設計書の置き場を読む
2. 設計文書とコードを読み、規約提案の候補を集める
3. `templates/規約提案.md`を複製し、「## 観測」「## 判断」「## 観測なし」を埋める
4. 提案先の規約を`rule-taxonomy.json`の`parent`/`key`の組で書く
5. `check-rule-proposals.sh`を実行する。最初に「## 観測」「## 判断」「## 観測なし」の3節の見出しが揃っているかを確かめ、1つでも無ければ（空ファイルを含む）節-欠落で終了する
6. 不合格の行を直し手順3へ戻る
7. 提案の採否・用語の承認は確認事項の記録へ行として書く

### 判定の規則

| 検査 | スクリプト | 検査キー |
|---|---|---|
| 3節の見出しの実在 | check-rule-proposals.sh | 節-欠落 |
| 出典の実在 | check-rule-proposals.sh | 出典-不在 |
| 提案先の実在 | check-rule-proposals.sh | 提案先-不在 |
| 観測なしの理由 | check-rule-proposals.sh | 観測なし-理由欠落 |

## §3 方式設計

**この節の位置づけ: 現行実装**

機械とAIの分担は、AIが設計文書・コードから観測と提案を書き、機械（`check-rule-proposals.sh`）が出典・提案先の実在・観測なしの理由の3点を検査する二段構成である。提案先の実在確認は`reverse-shared/references/rule-taxonomy.json`（`setup-scaffolding-rules`の写し）に対して行う。これはreverse単位がsetup単位のフォルダへ直接依存しない設計（skill-naming規約の単位分離）を保つためである。

### check-rule-proposals.sh

**必要性**: 規約提案は出典の無い思いつきや、実在しない規約への提案では採否を判断できない。AIが様式を埋める性質上、出典・提案先・理由の欠落を機械で検知する必要がある。

**代替案を採用しなかった理由**:
- 検査を持たずAIの自己申告に任せる: 出典の無い提案・存在しない規約への提案が確認事項の記録まで混入する
- 提案先の存在確認を省く: 採否を聞く工程2-12で初めて「そんな規約は無い」と気づき、手戻りになる

**保守責任者**: 人手（ユーザー）。様式の節構成を変えるときは、本スクリプトと`templates/規約提案.md`と自己テストを同時に直す。

**廃棄条件**: 規約提案の様式を構造化データに変えた時。

## §5 エラーと例外

**この節の位置づけ: 現行実装**

### 終了コード・差し戻し・保留の一覧

| 検査 | スクリプト | 検査キー | 保留のとき |
|---|---|---|---|
| 使い方の誤り・規約提案.md不在・規約定義不在 | check-rule-proposals.sh | 判定不能（終了コード2） | 対象外 |
| 3節の見出しの実在（空ファイルを含む） | check-rule-proposals.sh | 節-欠落 | 対象外 |
| 出典の実在 | check-rule-proposals.sh | 出典-不在 | 対象外 |
| 提案先の実在 | check-rule-proposals.sh | 提案先-不在 | 対象外 |
| 観測なしの理由 | check-rule-proposals.sh | 観測なし-理由欠落 | 対象外 |

### 完了条件（満たさない場合は差し戻しまたは保留とする）

- `confirmations/規約提案.md`があり3節を持つ（無ければ節-欠落）
- 「## 判断」の各行に出典と提案先の規約がある
- 提案先の規約が`rule-taxonomy.json`に実在する
- 「## 観測なし」の各行に理由がある
- `check-rule-proposals.sh`が終了コード0
