# 一覧を作る（reverse-listing-units）の基本設計書

道標の検出条件を実行して対象リポジトリを走査し、種別ごとの単位の一覧と元データを作り、候補数と実測の差を報告する。

## §1 外部仕様

**この節の位置づけ: 現行実装**

### 要件との対応

| 要件の柱 | 要件の項目 | この機能が満たす内容 |
|---|---|---|
| 柱1 調査を支える | 出力: 規模・構成と、画面・API・テーブルなど種別ごとの件数 | 検出条件を実行して種別ごとの単位を実測し、一覧と元データを書く |
| 柱1 調査を支える | 完了条件: 件数が実測と一致する | 一覧の集計.jsonで候補数と実測の差を判定する |
| 支援ツール全体の制約 | 全機能がテストと合格基準を持つ | 一覧の集計.jsonの判定がすべて合格であることを完了条件にする |

### 入力

| 入力 | 形 | 出所 |
|---|---|---|
| 道標 | Markdown（節「単位の見つけ方」の検出条件） | 対象の docs/design/common/道標.md |
| 対象範囲の承認 | Markdown | 出力の置き場の confirmations/ |

### 出力

| 出力 | 形 | 置き場 |
|---|---|---|
| 種別ごとの単位の元データ | JSON | docs/design/lists/<種別>.json |
| 種別ごとの単位の一覧 | Markdown | docs/design/lists/<種別>.md |
| 一覧の集計（実測・候補数・差・判定） | JSON | docs/design/lists/一覧の集計.json |

### 実行の口

Skill("reverse-listing-units")として呼ぶ、または`scripts/`配下の各スクリプトを直接実行する。

## §2 業務仕様

**この節の位置づけ: 現行実装**

### 手順

1. check-entry.shで範囲の承認（可否・道標の同一性）を確かめる
2. scripts/list-units.shを実行し、検出条件ごとに走査して元データと一覧と集計を書く
3. 終了コードを見る。1なら集計の判定に従い道標を描く機能へ差し戻す
4. 到達範囲が「AIの読み取り」の種別は、AIが読んで一覧を書き、2回の読みが一致することを確かめる

### 判定の規則

| 検査 | スクリプト | 検査キー |
|---|---|---|
| 範囲の承認の確認 | ../reverse-shared/scripts/check-entry.sh | 可否・道標の同一性 |
| 検出条件の実行と候補数の突き合わせ | scripts/list-units.sh | 候補数の差・例の不在・検出条件の形式・除外の一致・補完・文字コード変換・識別子の捕捉不能 |

## §3 方式設計

**この節の位置づけ: 現行実装**

機械とAIの分担は、機械検査（`検査`節の各スクリプト）が形式・実在・網羅を確かめ、AIが業務の言葉への翻訳・判断を担う二段構成である。

実行方式はシェルスクリプトと`grep`・正規表現による走査であり、対象コードの言語に依存しない。

### list-units.sh

**必要性**: 一覧化は「件数が実測と一致する」という要件の完了条件を担う工程であり、AIの読みだけでは実測にならない。道標の検出条件を機械で実行して数えることで、第一フェーズが組んだ見つけ方の当否を件数で確かめられる。走査・一致・分割・識別子の解釈は複数段の分岐を持ち、Bashツールの直叩きでは毎回再現できない。

**代替案を採用しなかった理由**:
- 言語ごとの走査スクリプトを機能が持つ: 知らないリポジトリに既製の見つけ方を当てることになり、対象ごとに合わない。見つけ方は第一フェーズが対象を読んで組む
- AIが読んで数える: 再現性が無く、実測にならない

**保守責任者**: 人手（ユーザー）。検出条件の形（項目・書き方）を変えるときは、道標の様式と本スクリプトと自己テストを同時に直す。

**廃棄条件**: 検出条件の形を別の仕組み（構文解析器など）に置き換えた時。

## §5 エラーと例外

**この節の位置づけ: 現行実装**

### 終了コード・差し戻し・保留の一覧

| 検査 | スクリプト | 検査キー |
|---|---|---|
| 範囲の承認の確認 | ../reverse-shared/scripts/check-entry.sh | 可否・道標の同一性 |
| 検出条件の実行と候補数の突き合わせ | scripts/list-units.sh | 候補数の差・例の不在・検出条件の形式・除外の一致・補完・文字コード変換・識別子の捕捉不能 |

### 完了条件（満たさない場合は差し戻しまたは保留とする）

- 到達範囲が「機械」の全種別についてJSONとMarkdownがあり、一覧の集計.jsonの判定がすべて「合格」
- 「AIの読み取り」の種別は2回の読みが一致し、同じ形の出力がある
- 到達範囲が「対象外」の種別は集計に理由付きで「対象外」がある
- tests/の全件が通る
