# 一覧を作る（reverse-listing-units）の詳細設計書

## §1 構成要素

**この節の位置づけ: 現行実装**

| スクリプト | 役割 |
|---|---|
| scripts/list-units.sh | 自己テストと機械検査を持つスクリプト |

## §2 処理の定義

**この節の位置づけ: 現行実装**

1. check-entry.shで範囲の承認（可否・道標の同一性）を確かめる
2. scripts/list-units.shを実行し、検出条件ごとに走査して元データと一覧と集計を書く
3. 終了コードを見る。1なら集計の判定に従い道標を描く機能へ差し戻す
4. 到達範囲が「AIの読み取り」の種別は、AIが読んで一覧を書き、2回の読みが一致することを確かめる

## §3 ロジック

**この節の位置づけ: 現行実装**

### list-units.sh

**必要性**: 一覧化は「件数が実測と一致する」という要件の完了条件を担う工程であり、AIの読みだけでは実測にならない。道標の検出条件を機械で実行して数えることで、第一フェーズが組んだ見つけ方の当否を件数で確かめられる。走査・一致・分割・識別子の解釈は複数段の分岐を持ち、Bashツールの直叩きでは毎回再現できない。

**代替案を採用しなかった理由**:
- 言語ごとの走査スクリプトを機能が持つ: 知らないリポジトリに既製の見つけ方を当てることになり、対象ごとに合わない。見つけ方は第一フェーズが対象を読んで組む
- AIが読んで数える: 再現性が無く、実測にならない

**保守責任者**: 人手（ユーザー）。検出条件の形（項目・書き方）を変えるときは、道標の様式と本スクリプトと自己テストを同時に直す。

**廃棄条件**: 検出条件の形を別の仕組み（構文解析器など）に置き換えた時。

## §4 入出力の値

**この節の位置づけ: 現行実装**

| 入力 | 形 | 出所 |
|---|---|---|
| 道標 | Markdown（節「単位の見つけ方」の検出条件） | 対象の docs/design/common/道標.md |
| 対象範囲の承認 | Markdown | 出力の置き場の confirmations/ |

| 出力 | 形 | 置き場 |
|---|---|---|
| 種別ごとの単位の元データ | JSON | docs/design/lists/<種別>.json |
| 種別ごとの単位の一覧 | Markdown | docs/design/lists/<種別>.md |
| 一覧の集計（実測・候補数・差・判定） | JSON | docs/design/lists/一覧の集計.json |
