# 一覧を作る（reverse-listing-units）の単体テスト設計書

**この文書の位置づけ**（別の言語で作り直す場合は、まず「仕様」から読む）

- 仕様: §1 テスト観点、§2 テストケース一覧、§3 入力条件、§4 期待結果、§5 異常系、§6 境界値、§7 網羅基準、§8 前提条件と終了条件

## 本書が検証するもの

reverse-listing-unitsが現場の実コードに対して作る一覧・対応表の品質を対象とする。検証は実際の現場コードで行い、検証者が現場コードを数え上げ本文と突き合わせる。

## §1 テスト観点

**この節の位置づけ: 現行実装**

| キー | 観点 | 区分 | 由来 |
|---|---|---|---|
| 一覧-件数一致 | 種別ごとの一覧の件数が、候補数の記載と2割以内で一致し判定が「合格」になる | 正常 | ai-work/todo/現場コードで検証するテストケースの案.md 第二フェーズ（一覧を作る） |
| 一覧-識別子 | 一覧の識別子が経路や名前で、捕捉不能が0件になる | 正常 | 同上 |
| 一覧-同一ファイル複数 | 1ファイルに複数単位が含まれるとき、それぞれ別の識別子で行が分かれる | 正常 | 同上 |
| 一覧-除外を拾わない | 除外フォルダに一覧化の記法と同じ記法があっても拾わない | 正常 | 同上 |
| 一覧-削除された表 | 除外の一致（DROP文の捕捉）を持つ検出条件が、削除された表を一覧から除く | 正常 | 同上 |
| 一覧-AIの読み取りの種別 | AIの読み取りの種別を2回読んでも一覧が一致し、同じ形のJSON・mdになる | 正常 | 同上 |
| 一覧-機能との対応 | 全単位がいずれかの機能に属し、機能の総数すべてに単位が対応する。不足があれば確認事項に載る | 正常 | 同上 |
| 一覧-一覧までで止まる | 出力の範囲が「一覧まで」のとき、一覧の後の出力が無い | 正常 | 同上 |
| 差し戻し-検出条件 | 実測が候補数と2割を超えて食い違うとき判定が「不合格」になり、定義書の当該領域の検出条件を直して再承認を経てから再実行し合格する | 異常 | ai-work/todo/現場コードで検証するテストケースの案.md モード・差し戻し・前提の確認 |

## §3 入力条件

**この節の位置づけ: 現行実装**

| 種類 | 内容 | 該当するケースのキー |
|---|---|---|
| 候補数の記載がある現場コード | 定義書に種別ごとの候補数を持つ現場コード | 一覧-件数一致-検証 |

| 除外フォルダに同記法のファイルがある現場コード | 除外対象のフォルダに一覧化対象と同じ記法のファイルを含む現場コード | 一覧-除外を拾わない-検証 |
| CREATEとDROPが対になる表がある現場コード | 削除されたテーブル定義と除外の一致の検出条件を持つ現場コード | 一覧-削除された表-検証 |

| 出力の範囲「一覧まで」を選んだ状態 | 統括で出力の範囲を一覧までに限定した実行状態 | 一覧-一覧までで止まる-検証 |
| 候補数と実測が2割を超えて食い違う現場コード | 定義書の候補数が実測と大きく乖離する現場コード | 差し戻し-検出条件-検証 |
