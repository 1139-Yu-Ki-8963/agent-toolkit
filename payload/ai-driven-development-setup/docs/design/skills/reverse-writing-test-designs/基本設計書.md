# テスト設計書を書く（reverse-writing-test-designs）の基本設計書

テスト設計書の出力が「出力する」のとき、基本設計書・詳細設計書・単体テスト設計書・要件定義書の受入条件を読み、種別内結合テスト設計書と種別横断結合テスト設計書を書く。

## §1 外部仕様

**この節の位置づけ: 現行実装**

### 要件との対応

| 要件の柱 | 要件の項目 | この機能が満たす内容 |
|---|---|---|
| 柱2 基盤一式の作成を支える | 出力: 種別ごとの設計書（テスト設計書の出力が出力するときだけ） | 単位が1つ以上ある種別ごとに種別内結合テスト設計書を書き、全体で種別横断結合テスト設計書を書く |
| 柱2 基盤一式の作成を支える | 完了条件: 未回答の確認事項が無い | 受入条件が無い機能を確認事項に登録する |

### 入力

| 入力 | 形 | 出所 |
|---|---|---|
| 要件定義書 | Markdown | `docs/design/requirements/要件定義書.md` |
| 基本設計書・詳細設計書・単体テスト設計書 | Markdown | `docs/design/<種別>/` |
| 一覧の元データ | JSON | `docs/design/lists/<種別>.json` |

### 出力

| 出力 | 形 | 置き場 |
|---|---|---|
| 種別内結合テスト設計書 | Markdown | `docs/design/<種別フォルダ>/<種別名>結合テスト設計書.md` |
| 種別横断結合テスト設計書 | Markdown | `docs/design/common/種別横断結合テスト設計書.md` |

### 実行の口

Skill("reverse-writing-test-designs")として呼ぶ、または`scripts/`配下のスクリプトを直接実行する。

## §2 業務仕様

**この節の位置づけ: 現行実装**

### 手順

1. テスト設計書の出力を読む。「出力しない」なら何も作らず終える
2. 設計書の置き場を読む
3. 種別ごとに単位を列挙し、単位が1つ以上ある種別だけ`templates/種別内結合テスト設計書.md`を複製して埋める
4. `templates/種別横断結合テスト設計書.md`を複製して埋める。§1は要件定義書の受入条件から観点を起こし、§4に受入条件との対応を書く
5. `check-test-designs.sh`を実行する
6. 不合格の項目を手順3または4からやり直す

### 判定の規則

| 検査 | スクリプト | 検査キー |
|---|---|---|
| 出力要否の判定 | check-test-designs.sh | テスト設計書の出力-不明 |
| 文書の実在 | check-test-designs.sh | 文書-不在 |
| 節の実在 | check-test-designs.sh | 節-欠落 |
| 位置づけの実在 | check-test-designs.sh | 位置づけ-欠落 |
| 未記入の不在 | check-test-designs.sh | 未記入-残存 |
| file:lineの不在 | check-test-designs.sh | 位置-禁止 |
| 観点とケースの整合 | check-test-designs.sh | 観点キー-不一致／観点-ケース未対応 |
| 受入条件の対応 | check-test-designs.sh | 受入条件-未対応 |

## §3 方式設計

**この節の位置づけ: 現行実装**

機械とAIの分担は、機械検査（`check-test-designs.sh`）が形式・実在・整合を確かめ、AIが単位間のつながり・種別をまたぐ流れ・受入条件との対応の翻訳を担う二段構成である。

実行方式はシェルスクリプトと`grep`・`awk`による走査であり、対象コードの言語に依存しない。単位の一覧・実行フォルダの設定はreverse-shared配下の共有部品を介して読み、本機能では再実装しない。

### check-test-designs.sh

**必要性**: 種別内結合テスト設計書は単位が1つ以上ある種別すべてに要り、種別横断結合テスト設計書は観点とケースと受入条件の対応が要る。対象ごとに単位の有無・種別の数・受入条件の件数が違うため、機械で節の欠落・観点キーの不整合・未記入・file:lineを一括で確かめる必要がある。

**代替案を採用しなかった理由**:
- 手順書の注意書きだけにする: 種別の数が対象ごとに違うため、種別内結合テスト設計書の作り忘れが後工程まで見つからない
- 単体テスト設計書の検査を流用する: あちらは単位ごとの様式の専用であり、種別をまたぐ流れ・受入条件との対応という別の様式を検査する責務を持たない

**保守責任者**: 人手（ユーザー）。7種別の一覧・節の名前を変えるときは、`templates/`配下の2様式と本スクリプトと自己テストを同時に直す。

**廃棄条件**: テスト設計書の様式を構造化データに変えた時。

### 完了条件（満たさない場合は差し戻しまたは保留とする）

- テスト設計書の出力が「出力しない」なら何も作らずに終える
- 単位が1つ以上ある種別すべてに種別内結合テスト設計書がある
- 種別横断結合テスト設計書があり、§1の全観点に§2のケースが対応し、§4が受入条件を1行以上持つ
- `check-test-designs.sh`が終了コード0
- `tests/`の全件が通る
