# 作業ディレクトリと出力の配置

AI駆動開発の基盤一式を作る作業で使うディレクトリは 3 つである。それぞれの役割と、中の置き場と、どの段が何をどこへ出すかを定める。この文書が置き場の定義であり、出力配置の定義（output-layout）と各機能の宣言（inputs・outputs）はこの文書に合わせる。

## 用語

| 用語 | 意味 |
|---|---|
| 納品物 | 先方リポジトリへ置く物。設計書・規約・各 AI ツールの設定・開発フロー・運用の skill・任意のポータル |
| 成果物 | 支援ツールが出力するが納品しない物。先方リポジトリに含めない出力の置き場に置く確認事項一覧・完了報告・事実・再生成・照合・記録 |

## 3 つのディレクトリ

| ディレクトリ | 役割 | 版管理 | 書く側 |
|---|---|---|---|
| 支援ツールのリポジトリ（`ai-driven-development-setup`） | 機能の定義と配布物を持つ。作業中は読むだけ | 支援ツール側のリポジトリ | 支援ツールの開発者だけ |
| 先方リポジトリ | 納品物と、開発チームが運用で使う記録を持つ | 先方のリポジトリ | 支援ツールの機能（配置・生成）と開発チーム |
| 先方リポジトリに含めない出力の置き場（`ai-output/`） | 成果物（確認事項・完了報告と、事実の抽出・再生成・照合・一時ファイル）を持つ。先方リポジトリには入れない | 入れない | 支援ツールの機能。確認事項の回答欄だけ開発チーム |

## 支援ツールのリポジトリの中

| 置き場 | 何を置くか |
|---|---|
| `docs/design/` | 要件と設計の文書（本文書を含む） |
| `docs/rules/<親>/<子>/` | このリポジトリ自身の規約と検査 |
| `docs/skills/<単位>-<作業>-<対象>/` | 機能の定義。SKILL.md・scripts・templates・tests・samples |
| `docs/skills/<単位>-shared/` | 単位で共有する部品 |
| `.claude/` | 定義から派生した skill と規約。直接編集しない |
| `delivery-payload/<単位>/` | 定義から作る配布物。直接編集しない |
| `ai-work/todo/` | この体系を作り直す作業の計画と、項ごとの作業指示書 |
| `ai-work/records/` | 完了した作業指示書と完了の記録 |

## 先方リポジトリの中

先方リポジトリの直下に足すものは 4 種に限る。`docs/` には AI が読む定義だけを置き、記録と確認事項は置かない。

| 置き場 | 何を置くか | 性質 |
|---|---|---|
| `docs/rules/<親>/<子>/` | 規約の定義と検査 | AI が読む定義（納品物） |
| `docs/design/requirements/` | 要件定義書（規約の 6 内容を節に持つ 1 文書） | AI が読む定義（納品物） |
| `docs/design/common/` | 道標、共通設計文書 6 つ（業務仕様書・方式設計書・データ設計書・エラー設計書・共通外部仕様書・基盤設計書）、共通処理の詳細設計書、結合テスト仕様書、技術スタック、環境構築手順書 | AI が読む定義（納品物） |
| `docs/design/lists/` | 種別ごとの一覧（Markdown と JSON を同じ場所に）・納品物一覧・テスト観点表・テストケース一覧 | AI が読む定義（納品物） |
| `docs/design/<種別>/<単位>/` | 基本設計書・単体テスト設計書・詳細設計書 | AI が読む定義（納品物） |
| `docs/skills/<名前>/` | 運用の skill の定義 | AI が読む定義（納品物） |
| `ai-work/todo/` | AI が読む計画と作業指示書 | 運用の記録 |
| `ai-work/records/` | 開発フローの完了記録・基本設計の合格記録 | 運用の記録 |
| `project-portal/` | 人が見る HTML | 任意の納品物 |
| `.claude/`・`.cursor/`・`.codex/`・`CLAUDE.md`・`AGENTS.md` | 各 AI ツールの設定 | 定義からの派生（納品物） |

種別は screens・apis・tables・batches・reports・externals・features の 7 つで、`docs/design/<種別>/` のフォルダ名に使う。


## 設計書の置き場の2つの使い方

reverse の工程は、設計書（道標・要件定義書・共通設計文書・一覧・単位の設計書・合格の記録）の書き込み先を「設計書の置き場」で決める。統括の実行の開始スクリプト（`start-run.sh`）が run.json の「設計書の置き場」キーに値を書く。reverse の各機能は `bash docs/skills/reverse-shared/scripts/design-root.sh <実行フォルダ>` でこの値を読む。

| 使い方 | 「設計書の置き場」の値 | docs/design・ai-work の展開先 |
|---|---|---|
| 先方リポジトリへ展開する | `--deploy-to` で指定した先方リポジトリのルート | 先方リポジトリの `docs/design/`・`ai-work/records/` |
| 作業場所だけに置く（既定） | `<実行フォルダ>/design`（`--deploy-to` 未指定時に自動作成） | `<実行フォルダ>/design/docs/design/`・`<実行フォルダ>/design/ai-work/records/` |

先方リポジトリのルート（対象コードを読む場所）と設計書の置き場は独立した値であり、作業場所だけに置く使い方では対象コードのルートは読むためだけに使われ、設計書は書き込まない。

## 先方リポジトリに含めない出力の置き場の中

`ai-output/<先方の名前>/<実行の識別子>/` の下に置く。実行の識別子は日時とコミットハッシュから作る。

| 置き場 | 何を置くか | 誰が読むか |
|---|---|---|
| `confirmations/` | 確認事項の記録・確認事項一覧・承認用の要約・対象範囲の承認の記録 | 開発チームが回答欄を書く。運用の機能が回答を先方リポジトリの設計書へ書き戻す |
| `reports/` | 完了報告・納品物一覧の写し・検証の判定の要約 | 支援側と開発チーム |
| `facts/` | 原本コードから取り出した事実 | 支援ツールの機能 |
| `rebuilt/` | 設計書だけから再生成したコード | 支援ツールの機能 |
| `compare/` | 原本と再生成の照合結果 | 支援ツールの機能 |
| `logs/` | 実行の記録 | 支援ツールの機能 |

## 各段の出力先

| 段 | 出力先 |
|---|---|
| 第一フェーズ（道標・要件定義書・共通設計文書） | 先方 `docs/design/common/道標.md`・`docs/design/requirements/要件定義書.md`・`docs/design/common/` の 6 文書、置き場 `confirmations/承認用の要約.md`・`confirmations/対象範囲の承認.md` |
| 一覧 | 先方 `docs/design/lists/` |
| 共通の基本設計・単位の基本設計・単体テスト設計書 | 先方 `docs/design/common/`・`docs/design/<種別>/<単位>/` |
| 基本設計の完了判定 | 先方 `ai-work/records/basic-design-acceptance/<種別>-<単位>.json`。共通設計文書は `common-<文書名>.json` |
| 共通処理と単位の詳細設計 | 先方 `docs/design/common/`・`docs/design/<種別>/<単位>/` |
| テスト文書 | いまのリバースでは作らない。開発チームが作る場合の置き場。テスト観点表・テストケース一覧は先方 `docs/design/lists/`、結合テスト仕様書は先方 `docs/design/common/`。操作シナリオ仕様書は繰り返し再検証（verify 単位）を選んだ場合だけ先方 `docs/design/screens/<単位>/` に md と YAML の対で置く |
| 確認事項一覧 | 置き場 `confirmations/確認事項一覧.md` |
| 事実の抽出・再生成・照合 | 置き場 `facts/`・`rebuilt/`・`compare/` |
| 完了報告 | 置き場 `reports/`。納品物一覧は先方 `docs/design/lists/納品物一覧.md` にも置く |
| 規約の配置と派生（納品の段だけ。reverse の工程では使わない） | 先方 `docs/rules/`・`.claude/`・`.cursor/`・`.codex/`・`AGENTS.md` |
| 運用の skill の配置 | 先方 `docs/skills/`（派生で `.claude/skills/`） |

## 決めた理由

- `docs/` を定義だけにするのは、定義と生成物・記録の区別を保つためである。記録が混ざると、何が納品物かが読めなくなる
- 確認事項を先方リポジトリに置かないのは、回答の途中の状態を納品物に混ぜないためである。回答は書き戻した結果だけが先方リポジトリに残る
- `ai-work/` と `ai-output/` の名前は、AI が読み書きする物であることが名前から分かるように付けた
- 旧の置き場（`docs/manifests`・`docs/scope-and-progress`・`docs/tasks`）は使わない。配る規約「どこに何を置くかの決まり」の運営文書の行は `ai-work/todo/`・`ai-work/records/` へ改める
