§1概要

transcribing-images は画像を忠実に書き起こし、再照合後に actionable・findings・expectedChange・verification の構造化 handoff をセッション管理へ返す。調査・実装・テスト・公開は行わない。

対象外: 画像の加工・派生画像生成は dev-flow-preparing-manual-mockup、画像への注釈付けはプロジェクト側 annotating-screenshots が担当する。本スキルはテキスト化のみを担う。

§2出力

本スキルを実行すると、次の成果物が生成される。

書き起こし本文
原文ママ原則・構造保持のマークアップ規則に従って画像内容を再現した Markdown テキスト。ユーザーに提示される（保存は既定で行わない）。
要確認リスト
数値・固有名詞・URL・コードの再照合で確信度が低いと判断された箇所の一覧。該当がなければ「なし」と明記される。
次アクション提案
書き起こし内容の種類（改善要望メモ／仕様・設計メモ／単なる資料）に応じ、実行手段となるスキル名を明記した提案文。
構造化 handoff
actionable・findings（id/source/observation）・expectedChange・verification を持ち、実装せずセッション管理へ返す契約。セッション管理が2段階確認後に scopeConfirmation を加えて共通handoffへ統合する。

§3用語

用語意味
原文ママ原則要約・言い換え・補完をせず、誤字も含め原文どおりに転記する方針。誤字には [原文ママ] を付す
構造保持見出し階層・箇条書き・表・強調を Markdown で再現し、レイアウトが意味を持つ場合は配置を注記すること
判読不能 / 判読注意文字が読み取れない箇所は [判読不能]、推測を伴う場合は [判読注意: <読み>] と明示すること
要確認リスト検証工程（Phase 3）で確信度が低いと判断された箇所を書き起こし末尾にまとめたもの

§4動作フロー

Phase 1: 入力収集と分類
  画像を全件 Read → 種類分類（文書/UI/手書き/図表/写真）
  複数枚 → AskUserQuestion で対象・順序確認（1枚なら即進む）

Phase 2: 書き起こし
  原文ママ原則 + 構造保持でMarkdown化
  判読不能/判読注意/図の記録タグを付与

Phase 3: 検証
  数値・固有名詞・URL・コードを画像と再照合
  確信度の低い箇所を要確認リストにまとめる

Phase 4: 提示と次アクション提案
  書き起こし全文を提示（保存は要求時のみ）
  種類別に実行スキル名を明記した次アクションを提案

§5書き起こしのマークアップ規則

記法用途
[原文ママ]原文の誤字・不自然な表現をそのまま転記した箇所に付す
[判読不能]文字が読み取れない箇所
[判読注意: <読み>]推測を伴う判読箇所。推測した読みを併記する
[図: <1行説明>]図・写真部分の存在を記録する
禁止事項: 要約・言い換え・補完は一切行わない。誤字脱字も直さず原文のまま転記する。

§6検証と要確認リスト

書き起こし後、数値・固有名詞・URL・コードは誤読リスクが最も高い要素として画像と再照合する。確信度の低い箇所は要約せずそのまま書き起こし末尾の「要確認リスト」にまとめ、該当がない場合も「なし」と明記する。

§7構造化 handoff と次アクション提案

本スキルは文字起こしと構造化 handoff をセッション管理へ返すまでで完結する。後続の調査・計画・レビューはセッション管理が利用可能な専門スキルを優先し、存在しない場合は標準 reviewer・通常応答へ縮退する。

内容の種類提案する流れ
改善要望・指摘のメモ構造化 handoff を返し、調査・計画・レビューへ進むか確認する
仕様・設計のメモ構造化 handoff を返し、設計またはモック化へ進むか確認する
単なる資料保存先の指定、または他の対応事項の確認
責務境界: 本スキルは後続処理を実行せず、存在しないスキルを必須条件にしない。ルーティングと 2 段階の範囲確認はセッション管理が担う。

§8環境と設定

項目内容
入力元~/.claude/uploads/<session>/ 配下の画像、およびユーザー添付の画像
保存の既定動作提示のみ。ユーザーが明示的に保存を求めた場合のみ、指定先へ Write する
外部依存なし（Claude Code 標準ツールのみで完結）

§9予想を裏切る挙動

  • 通常の文書作成と逆に、誤字・不自然な表現ほど「直さず原文のまま」転記するのが正しい挙動
  • 1 枚のみの入力では AskUserQuestion による確認を省略し即座に書き起こしへ進む（確認は複数枚時のみ）
  • 後続の専門スキルがない環境でも文字起こしは完了し、セッション管理が標準 reviewer・通常応答へ縮退する
