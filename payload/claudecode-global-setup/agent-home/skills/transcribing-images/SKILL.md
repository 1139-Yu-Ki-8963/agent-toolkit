# transcribing-images — 画像書き起こし

添付・アップロードされた画像の内容を、要約せず構造を保ったまま忠実に書き起こす。書き起こし後は数値・固有名詞を画像と再照合し、内容の種類に応じた次アクションを提案するところまでを 1 スキルの責務とする。

## 使用タイミング

- 「書き起こして」「文字起こし」「transcribe」と言われた時
- 画像添付とともに内容のテキスト化を求められた時
- 対象外: 画像の加工・派生画像生成（→ `dev-flow-preparing-manual-mockup`）、画像への注釈付け（→ プロジェクト側 `annotating-screenshots`）

## Phase 1: 入力収集と分類

1. `~/.claude/uploads/<session>/` 配下とユーザー添付の画像を全件 Read する
2. 種類を分類する: 文書スクショ / UI スクショ / 手書きメモ / 図表 / 写真
3. 複数枚ある場合は書き起こし対象と順序を AskUserQuestion で確認する。1 枚のみの場合は確認せず Phase 2 へ進む

**完了**: 対象画像が全件 Read 済みで、種類分類と（複数枚時のみ）対象・順序が確定している。

## Phase 2: 書き起こし

- **原文ママ原則**: 要約・言い換え・補完をしない。誤字も原文のまま転記し `[原文ママ]` を付す
- **構造保持**: 見出し階層・箇条書き・表・強調を Markdown で再現する。レイアウトが意味を持つ場合（2 カラム・吹き出し等）は配置を注記する
- 判読不能箇所は `[判読不能]`、推測を伴う判読は `[判読注意: <読み>]` とマークする
- 図・写真部分は `[図: <1 行説明>]` として存在を記録する

**完了**: 対象画像の全内容が上記マークアップ規則に従って書き起こされている。

## Phase 3: 検証

1. 数値・固有名詞・URL・コードを画像と再照合する（誤読リスクが最も高い要素）
2. 確信度の低い箇所を「要確認リスト」として書き起こし末尾にまとめる

**完了**: 数値・固有名詞・URL・コードの再照合が完了し、要確認リストが作成されている（該当なしの場合は「なし」と明記）。

## Phase 4: 提示と次アクション提案

1. 書き起こし全文を提示し、保存先を確認する（既定: 提示のみ。ユーザーが保存を求めたら指定先へ Write）
2. 内容の種類に応じた次アクションを提案する:
   - 改善要望・指摘のメモ → 「この内容をセッション管理へ渡し、調査・計画・レビューへ進めますか？」
   - 仕様・設計のメモ → 「この内容をセッション管理へ渡し、設計またはモック化を検討しますか？」
   - 単なる資料 → 「保存先の指定、または他に対応すべきことはありますか？」
3. 改善要望・指摘を含む場合は、次の構造化 handoff をセッション管理へ返す。実装先へ直接渡さない。

```yaml
actionable: true
findings:
  - id: "画像内で一意な意味語キー"
    source: "画像ファイルまたは添付識別子"
    observation: "画像から忠実に読み取れた指摘"
expectedChange: []
verification: []
```

- `actionable`: 実装・調査候補が 1 件以上なら true
- `findings`: 各要素に `id`・`source`・`observation` を必須とする
- `expectedChange`: 指摘から期待される変更。推測を含む場合はその旨を明記する
- `verification`: 変更後に指摘が解消したと判定する方法

本 Skill は文字起こしと handoff 作成までを担当し、調査・実装・テスト・公開は行わない。ここまでで本 Skill は完結する。セッション管理者が 2 段階の範囲確認を行い、確認結果を `scopeConfirmation.investigationAndImplementation` と `scopeConfirmation.goalScope` に記録して共通引き継ぎ契約へ統合する。後続処理は、そのランタイムで利用可能な専門 Skill を優先し、存在しなければ利用可能な標準 reviewer・通常応答へ縮退して同じ目的と証拠を満たす。存在しない Skill を必須条件にしない。

**完了**: 書き起こし全文と構造化 handoff がセッション管理へ返され、種類に応じた次アクション提案がユーザーに示されている。

## 完了条件

| Phase | 完了条件 |
|---|---|
| Phase 1 | 対象画像が全件 Read 済みで、分類と（複数枚時のみ）対象・順序が確定している |
| Phase 2 | 全内容がマークアップ規則（原文ママ・構造保持・判読不能表記）に従って書き起こされている |
| Phase 3 | 数値・固有名詞・URL・コードの再照合が完了し、要確認リストが作成されている |
| Phase 4 | 書き起こし全文・構造化 handoff・次アクション提案が提示され、セッション管理へ返されている |
| **Goal** | 書き起こし全文・要確認リスト・構造化 handoff・次アクション提案が揃っている |

## ツールリファレンス

| ツール | 用途 |
|---|---|
| Read | 添付・アップロード画像の読み取り |
| Bash | `~/.claude/uploads/<session>/` の存在確認・一覧取得 |
| AskUserQuestion | 複数枚時の書き起こし対象・順序の確認 |
| Write | ユーザーが保存を明示的に求めた場合のみ、指定先への書き出し |

## 重要な注意事項

1. 要約・言い換え・補完は一切しない。誤字脱字も原文のまま転記する
2. 保存は既定で行わない。提示のみで完了とし、ユーザーが明示的に保存を求めた場合のみ Write する
3. 判読不能・推測読みは必ず `[判読不能]` / `[判読注意: <読み>]` で明示し、断定しない
4. 数値・固有名詞・URL・コードは書き起こし後に必ず画像へ再照合する
5. actionable findings があっても本 Skill 自身は実装しない。必ずセッション管理へ返す
6. 後続 Skill の存在を仮定しない。ルーティングと縮退判断はセッション管理の責務とする

## 予想を裏切る挙動

- 通常の文書作成と逆に、誤字・不自然な表現ほど「直さず原文のまま」転記するのが正しい挙動
- 1 枚のみの入力では AskUserQuestion による確認を省略し即座に書き起こしへ進む（確認は複数枚時のみ）
- 後続の専門 Skill がない環境でも文字起こし自体は完了でき、セッション管理が標準 reviewer・通常応答へ縮退する
