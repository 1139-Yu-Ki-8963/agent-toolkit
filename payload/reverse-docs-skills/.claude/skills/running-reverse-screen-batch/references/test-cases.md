# running-reverse-screen-batch テストケース

観点キーは連番禁止。内容を要約した意味語で付ける（番号からは情報を得られないため）。

| 観点キー | 前提 | 操作 | 期待結果 | 機械検証 |
|---|---|---|---|---|
| per-item分離-前半後半の盲検分離 | 前半で原本コードを読む | 後半のper-item promptを実行する | 前半の情報が後半のコンテキストに混入しない | 手動 |
| docs-only経路-後半を起動しない | verification_mode=docs-onlyである | 前半完了後の分岐を確認する | STATIC_COMPLETEで終端し後半を起動しない | 手動 |
| マーカー冪等性-終了コード非依存の判定 | claude -pの終了コードを確認する | Phase 4の完了判定を行う | 終了コードを信用せずマーカー実在のgrepで判定する | 手動 |
| limit待機-精度向上反復に数えない | 出力にlimit文言が検出される | 失敗切り分け手順を実行する | 基盤事象として待機後に再開し反復回数に数えない | 手動 |
| 開通競合-conflict-skipの区別 | unlocking-reverse-target-screensがCONFLICT-SKIPPEDを返す | 周回ループを継続する | failedとは別区分としfail_limit_kに加算しない | 手動 |
| 時限到達-ソフト停止 | deadlineを超過している | 次画面着手前の判定を行う | 新規着手せず実行中の呼び出しは中断しない | 手動 |
| 並列レーン-画面重複配分の禁止 | 統括が画面リストをレーン数で分割する | レーン運用を開始する | 各レーンのscreen_idsに重複が無いようにする | 手動 |
| 環境スロット解放-後半完了直後 | 対象画面が後半完了に到達する | 環境スロット解放を行う | 軽量teardownでポートとプロセスのみ解放しbaseline_tagは保持する | 手動 |
| single-pass経路-1回で確定 | verification_mode=single-passである | 判定結果を確認する | PASSでもFAILでも1回でfailedリストへ確定させ再キューしない | 手動 |
| 単発ドライラン-先頭画面の二重実行禁止 | Phase 2で先頭1画面を本番1回目として実行する | Phase 3の無人ループを起動する | 同じ画面をPhase 3で再実行しない | 手動 |

## 機械検証との対応

- 機械検証が「手動」の行は、guide.html の検証状況へ手動確認を記録する
- self-test に対応ケースを追加したら、この表の機械検証列を同じコミットで更新する
