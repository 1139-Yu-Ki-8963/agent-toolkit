意味用語候補生成スキル
generating-glossary-for-reverse-docs

コードと既存文書から意味用語の候補を取り出し、未承認の提案としてリポジトリ外へ渡す互換スキルの確定仕様。正式な用語集には一切触れない。

対応 OSWindows WSL2 環境
検証状況scripts/test-generating-glossary-proposal-contract.sh が外部パス・リポジトリ内への出力拒否・シンボリックリンク拒否・提案の検証・直接 HTML 経路と自動承認文言の不在を確認する

§1概要

コードと既存文書には、そのシステムでしか通じない言葉が散らばっている。本スキルはそれらを走査して意味用語の候補を取り出し、観測した事実・推定・根拠を分けた形で提案としてまとめる。

スキル名に用語集の生成を含むが、生まれるのは未承認の提案だけである。この名前は以前の呼び出し元との互換のために残しているものであり、正式な用語集を作る権限を意味しない。正式な用語集・用語辞書 HTML には一切触れない。

本スキルがやること
コードと既存文書の走査・観測事実と推定の分離・未承認の提案と診断の出力
本スキルがやらないこと
正式な用語集の更新・提案の承認・用語辞書 HTML の生成（いずれも managing-semantic-glossary の担当）

起動引数

引数内容
target_repo_path走査対象の実在する絶対パス
proposal_output_ref提案の書き出し先。対象リポジトリの外を指す明示的な絶対パスに限る
target_glossary_key対象となる用語集の識別キー
base_content_version提案の基準となる用語集の版
source_revision走査した時点のコードの版

出力先が未指定・相対パス・対象リポジトリ自身またはその配下・シンボリックリンク・既存ファイルのいずれかに該当する場合、本スキルは書き込まずに停止する。

§2出力

1 回の実行につき、次の 2 点が対象リポジトリの外に生まれる。

未承認の提案
正式な提案スキーマに準拠した YAML。承認者の欄は空のまま出力される
診断
欠落した書き起こし元・走査できなかった層・未解決の候補・それぞれの件数を持つ JSON。提案ファイルの隣に置かれる

§3用語

未承認の提案
人の審査を待つ状態の候補。承認済みの用語として扱ってはならない

§4動作フロー（Phase 1〜4）

Phase内容
Phase 1 出力先の検証write-glossary-proposal-output.py が出力先を検証する。未指定・相対パス・対象リポジトリ内・シンボリックリンク・既存ファイル・親ディレクトリの差し替えを、いずれも書き込まずに拒否する
Phase 2 抽出コードと既存文書を走査し、観測した事実と推定を分けて候補を取り出す
Phase 3 提案の組み立て承認の状態を未承認に固定したまま、正式な提案スキーマの形へ組み立てる
Phase 4 機械検証と停止validate-verified-glossary-proposal-bundle.py で検証する。検証を通れば人の審査へ引き渡す状態で停止し、通らなければ 3 回まで修正を試みる

§5守り（禁止事項と機械検証）

禁止事項

  • 対象リポジトリの中へ提案を書き出さない
  • 無人実行であっても提案を自動で承認しない。確からしさが高くても承認済みの状態へ進めない
  • 正式な用語集・用語辞書 HTML を本スキルから更新しない
  • 走査で確認できなかった語を推測で候補に加えない

機械検証

scripts/test-generating-glossary-proposal-contract.sh が、出力先が対象リポジトリの外であること・リポジトリ内への出力が拒否されること・シンボリックリンクが拒否されること・提案が検証を通ること・直接 HTML を生成する経路と自動承認を示す文言が存在しないことを確認する。
