意味用語候補生成互換Skill
generating-glossary-for-reverse-docs

旧名を維持しながら、リバース解析結果を未承認proposalとして外部へ渡します。

§1 概要

コードと既存文書から観測事実、推定、根拠を分離し、正式proposal schemaのdetected候補を作ります。正式glossaryとportalには触れません。

§2 出力

人が審査できる未承認候補と走査診断だけを生成します。

detected proposal
正式proposal schemaに準拠した外部YAML。承認者は空です。
diagnostics
欠落した採録源、未走査層、未解決候補、件数を持つJSON sidecarです。

§3 必須入力

引数制約
target_repo_path解析対象の実在絶対path
proposal_output_ref対象repo外の明示絶対YAML path
用語集情報target glossary key、base version、source revision

§4 安全な出力

scripts/write-glossary-proposal-output.pyが検証と新規作成を同じdirectory descriptorで行います。未指定、相対path、対象repo自身・配下、symlink・hardlink、既存出力、親directory差し替えをfail closedで拒否します。

§5 ワークフロー

  1. 外部出力pathを検証する。
  2. 観測事実と推定を分離して抽出する。
  3. approval statusをdetectedに固定してproposalを組み立てる。
  4. 正式validatorで検証し、NEEDS_REVIEWで停止する。

§6 承認境界

headlessでも自動承認しません。confidenceが高くてもapprovedやmergedへ遷移せず、人の審査へ渡します。

§7 Portal公開

このSkillはpage-dataや用語辞書HTMLを生成しません。承認済みglossary YAMLだけをmanaging-semantic-glossaryのportal publishへ渡す別経路を使います。

§8 停止条件

STOPPED
必須入力欠落、外部path違反、同じfindingの反復。
NEEDS_REVIEW
schema検証済みdetected proposalを人へ引き渡した状態。

§9 検証

scripts/test-generating-glossary-proposal-contract.shが外部path、repo内拒否、symlink拒否、detected proposal検証、直接HTML経路と自動承認文言の不在を確認します。

検証状況: 2026-08-02 指定14列に変換可能な観測・推定分離とproposal-only境界のcontract testを実行。

§10 予想を裏切る挙動

Skill名にglossary生成を含みますが、生成物は未承認proposalです。旧呼び出し元の互換性を保つための名前であり、正式用語集の生成権限を意味しません。
