# generating-batch-basic-design-for-reverse-docs テストケース

観点キーは連番禁止。内容を要約した意味語で付ける（番号からは情報を得られないため）。

| 観点キー | 前提 | 操作 | 期待結果 | 機械検証の方法 |
|---|---|---|---|---|
| 業務語彙-実装用語ゼロ | バッチ基本設計書が生成済みである | Phase 5 検査1を実行する | 実装用語（フレームワーク用語・型構文・原本の拡張子・内部の成果物名）の検出が0件であること | 検査1（`grep -nE 'interface [A-Z]|: *(string|number|boolean)\b|\bstyled-components\b|\bFastAPI\b|\bExpress\b|@app\.(get|post|put|delete)|\.(py|pl|pm|cgi|rb|go|java)\b|batch-manifest|unitId|unitKey|detectionMethod' <バッチ基本設計書.md>` の検出0件） |
| 根拠-file:line不使用 | 本文がある | Phase 5 検査1を実行する | 原本の拡張子を含むファイルパス形式の記述が本文に存在しないこと | 検査1（同一grepコマンドの拡張子パターンで検出0件） |
| 注記-記入規則コメント残存なし | テンプレートを展開した設計書がある | Phase 5 検査2を実行する | テンプレートの記入規則を書いたHTMLコメント（`<!-- -->`）が本文に残っていないこと | 検査2 |
| frontmatter-status-authored | Phase 3 Step4が完了している | Phase 5 検査3を実行する | frontmatterの`status`が`authored`になっていること | 検査3 |
| 章-完備 | テンプレートが章見出しを持つ | Phase 5 検査4を実行する | テンプレートが持つ全ての章見出しが出力に存在すること | 検査4 |
| バッチテスト-由来の記録 | バッチ結合テスト設計書が生成済みである | Phase 5 由来の記録検査を実行する | §1テスト観点と§5異常系の全行に、由来する基本設計書の章が記録されていること | 由来の記録検査 |
| バッチテスト-情報源の限定 | バッチ結合テスト設計書が生成済みである | Phase 5 情報源の検査を実行する | 本文に、基本設計書に現れない語（原本のファイル名・関数名・変数名）が含まれていないこと | 情報源の検査 |
| 識別子-空でERROR中断 | `unitId`と`unitKey`の双方が空のユニットがある | Phase 3 Step1で出力先を決定する | `status=ERROR`となり、hintに「出力先の識別子が確定しない」が入る | 手動（合成フィクスチャを要する） |
| 処理詳細-記述なし | バッチ基本設計書が生成済みである | 本文の処理の流れ・コミットの単位・排他の制御の記載有無を確認する | 処理の流れ・コミットの単位・排他の制御が書かれていないこと（バッチ詳細設計書の担当範囲であるため） | 手動（章立て確定前のため機械検査項目化は未実施） |
| 未確定事項-要確認事項への回送 | コードから確定できない事項がある | Phase 2 Step3およびPhase 3 Step3を実行する | 推測で埋めず、要確認事項一覧へ記録される | 手動（対象コードベースを要する） |

## 機械検証との対応

- 機械検証が「手動」の行は、guide.html の検証状況へ手動確認を記録する
- self-test に対応ケースを追加したら、この表の機械検証列を同じコミットで更新する
