マトリクス・対応表生成スキル
generating-cross-views-for-reverse-docs

既存のマニフェスト群を突き合わせ、5 つの横断ページを機械生成する交差ビュー生成スキルの確定仕様。

対応 OSWindows WSL2 環境
検証状況生成エンジン（build-matrix-pages.sh）が必須トップレベルキーの検査を内部で兼ねる。5 ページ横断での単独実機検証は未実施。スキル専用のテストスクリプトは持たない
依存共有スクリプト generation-engine/scripts/ 配下の extract-screen-metadata.sh・extract-api-metadata.sh・build-matrix-data.sh・build-permission-function-data.sh・extract-ai-assets.sh・build-matrix-pages.sh ／ 任意 build-portal.sh

§1概要

画面・API・テーブル・機能の一覧は、それぞれ単独では「何があるか」しか答えない。誰がどの画面を使えるのか、どの API がどのテーブルを触るのかといった問いに答えるには、複数の一覧を突き合わせる必要がある。本スキルは既存のマニフェスト群を交差させ、横断で引ける 5 つのページを機械生成する。

生成できるのは、元になるマニフェストが揃っているページだけである。必要な一覧が未生成なら該当ページは作らず、作れなかった事実を報告する。欠けた情報を推測で埋めることはしない。

本スキルがやること
既存マニフェストの突き合わせ・交差データの導出・5 ページの機械生成
本スキルがやらないこと
元になる画面・API・テーブル・機能の各一覧の作成（それぞれの一覧生成スキルの担当） ／ 権限設計の良否判定

起動引数

引数内容
target_repo_pathメタデータ抽出の対象となるリポジトリルート
output_dir5 ページの書き出し先ディレクトリ。既存マニフェストの所在でもある
portal_output_dir任意。渡された場合のみポータルへ反映する
sites_path任意。AI 設定資産の抽出に使う
site_key任意。AI 設定資産の抽出に使う

元になるマニフェストが揃っていないページは生成されない。5 ページのうち一部だけが生まれることは正常な結果である。

§2出力

元になるマニフェストが揃っている分だけ、次の 5 点が生まれる。

権限画面マトリクス.html
どの権限がどの画面に到達できるかの交差表
権限機能マトリクス.html
どの権限がどの機能を実行できるかの交差表
CRUD図.html
どの処理がどのテーブルに対して作成・参照・更新・削除のどれを行うかの対応表
画面-API-テーブル対応表.html
画面・API・テーブル・機能の間の参照関係をたどるための対応表
AI設定資産.html
対象リポジトリが持つ AI エージェント向け設定資産の一覧

§3用語

交差ビュー
複数の一覧を突き合わせて、単独の一覧では答えられない関係を示すページ
マニフェスト
各一覧生成スキルが出力した JSON。本スキルはこれを入力として読む

§4動作フロー（Phase 1〜4）

Phase内容
Phase 1 入力の確認output_dir 配下の各マニフェストの実在を確認し、生成できるページを確定する
Phase 2 メタデータ抽出（機械実行）extract-screen-metadata.sh・extract-api-metadata.sh・extract-ai-assets.sh が交差に必要なメタデータを取り出す
Phase 3 交差データの導出（機械実行）build-matrix-data.sh・build-permission-function-data.sh が交差表のデータを組み立てる
Phase 4 生成build-matrix-pages.sh が 5 ページを出力する。このスクリプトは出力前に必須トップレベルキーの検査を兼ねる。portal_output_dir が渡されていれば build-portal.sh でポータルへ反映する

§5守り（禁止事項と機械検証）

禁止事項

  • 交差データの JSON や生成後の HTML を手作業で編集しない。直すのは導出スクリプトの側
  • 元のマニフェストに無い関係を推測で補完しない
  • マニフェストが欠けているページを、部分的な情報で無理に生成しない

機械検証

Phase 4 の build-matrix-pages.sh が必須トップレベルキーの検査を内部で行い、検査を通らないデータからはページを出力しない。
