§1概要

そのバッチが何のために存在し業務上どんな目的を担うかは、バッチ基本設計書が書く。しかし、処理の流れ・コミットの単位・排他の制御・リトライ・件数と実行時間の目安という実装の手順には、業務的な意味とは別に答える必要がある。

本スキルは原本コードの処理定義から詳細設計書を書く。基本設計スキルが担う意味は抽出しない。読み手は実装の詳細を確認する担当者である。

本スキルがやること
バッチ 1 本ごとの処理の流れ・コミットの単位・排他の制御・リトライ・件数と実行時間の目安を、根拠付きで記入したバッチ詳細設計書の生成
本スキルがやらないこと
起動の契機・実行の周期・入力と出力・業務上の目的・異常時の復旧の方針の記述（バッチ基本設計書の担当）／バッチ一覧の生成（generating-batch-list-for-reverse-docsの担当）

起動引数

引数必須内容
batch_manifest_path必須バッチ一覧の拡張マニフェストの絶対パス
source_dir必須原本コードのルート
output_dir必須出力先のルート
template_root必須テンプレート群のルート
unit_keys任意対象を絞るキーの配列
common_docs_root任意共通文書のルート

unit_kind は batch 固定であり、引数には取らない。

§2出力

バッチ 1 本につき、次の 1 点が生まれる。

バッチ詳細設計書.md（<output_dir>/バッチ/batch-<バッチ識別子>/詳細設計/バッチ詳細設計書.md）
処理の流れ・コミットの単位・排他の制御・リトライ・件数と実行時間の目安を、原本の file:line 形式の根拠付きで記入した文書。根拠を付けられない項目は要確認事項一覧へ回される。

§3用語

根拠
原本のファイルと行を file:line の形で示す記録方法。詳細設計では本文に書いてよい。実装用語の混入は差し戻しの理由にならない。
拡張マニフェスト記載事項の一致
マニフェストの schedule・targetTables・downstreamJobs・execMethod のうち値を持つフィールドが、本文に反映されていることの確認。
要確認事項
コードから確定できない事項を推測で埋めず、確認事項として記録したもの。キーは連番を禁じ、内容を要約した意味語で付ける。

§4動作フロー（Phase 1〜4）

Phaseやること完了条件
Phase 1
起動引数の検収と対象の確定		 必須4引数の実在確認、マニフェストの検収（unitKind が batch・units が1件以上）、対象ユニットの確定を行う 4引数が実在し、マニフェストが検収済みで、対象ユニットが確定している
Phase 2
原本読解		 マニフェストの sourceFile が指すファイルを読み、処理の流れ・コミットの単位・排他の制御・リトライ・件数と実行時間の目安を file:line 形式の根拠付きで抽出する。マニフェストの schedule・targetTables・downstreamJobs・execMethod との整合を確認する 対象ユニット全件について、根拠付きの記入材料が揃っている
Phase 3
執筆		 テンプレートを展開・配置し、各章へ記入する。空欄のまま残った項目を要確認事項一覧へ列挙し、frontmatter の status を draft から authored へ更新する 全対象ユニットの設計書が記入済みである
Phase 4
機械検査		 拡張マニフェスト記載事項の一致・注記の残存検査・frontmatter の検査・章の完備検査の4検査を実行する。不合格が1件でもあれば Phase 3 へ戻る（上限3回） 4検査すべてが合格している

§5守り（禁止事項と機械検証）

禁止事項

  • 起動の契機・実行の周期・入力と出力・業務上の目的・異常時の復旧の方針を書かない（バッチ基本設計書の担当）
  • 原本に無い値を書かない。推測で埋めない
  • 子スキルへ委任しない。原本読解と執筆（Phase 1〜3）は一貫性を保つため単一のメインエージェントが通しで担う
  • 根拠を付けられない項目を空欄のまま放置せず、要確認事項一覧へ回す

機械検証

Phase 4 で次の4検査を実行する。検査1はマニフェストの schedule・targetTables・downstreamJobs・execMethod のうち値を持つフィールドが、生成した本文に反映されていることを確認する。検査2はテンプレートの記入規則を書いた HTML コメントが残っていないことを確認する。検査3は frontmatter の status が authored になっていることを確認する。検査4はテンプレートが持つ全ての章見出しが出力に存在することを確認する。1つでも不合格なら Phase 3 へ戻り、上限3回で収束しなければ status=ERROR とする。本スキルは実装用語の混入を検査対象としない。
