§1概要

正式用語集を直接編集せず、検査、影響分析、候補レビューを実行する。結果は管理Skillが消費できる変更要求へ整える。

既定はdry-run。 保守Skillは最終承認者にも適用主体にもならない。

独立CRUD runnerや保守CLIではなく、AIがRead/Grep/Bash/Write/Editで調査と変更要求作成を行う手順である。scriptsは実行入口ではなく契約検証用テストである。

§2出力

人が採否と移行可否を判断するための次の情報が生まれる。

品質検査レポート
重複、類義、禁止語、命名、参照切れを位置と根拠付きで示す。
影響サマリー
直接・派生・意味・互換・運用影響と未走査領域を分ける。
変更要求
変更前後、理由、根拠、承認候補、移行案を管理Skillへ渡せる形にする。

§3操作

群操作
変更準備add / update / deprecate / retire
品質監査detect-duplicates / synonyms / forbidden-terms / naming-violations
利用監査detect-unused-terms / analyze-impact
候補・全体review-proposal / validate-registry

deleteモードは持たない。review-proposal、add、update、deprecate、retireでは--registry <file-or-dir>が必須。省略時はreview_requiredとして、変更要求を管理Skillへ渡さない。

§4検査順序

正式CLI → report schema → schema → key → label正規化 → alias/禁止語 → representation → 類義候補 → 参照整合

exit 0でもreview_requiredがあれば適用可能と判定しない。SGS/SGK/SGR/SGL/SGP/SGV/SGDのcode familyとseverityを保持する。類義語はdefinition、kind、scope、relation、representationも比較し、自動統合しない。

§5影響分析

分類例
直接key、API field、DB列
派生portal、生成文書、将来のAI索引
意味計算規則、状態遷移
互換外部API、event、DB契約
運用FAQ、手順書、教育資料

§6未使用判定

code、database、api、ui、document、event、messageを別々に走査する。機械走査できない法令、契約、教育、運用はhuman_check_requiredを付ける。

全チャネル0件でも、それだけでは削除条件にならない。

§7候補レビュー

proposal.extracted_facts[]とproposal.inferences[]を分け、既存類似語、根拠、confidence、影響、不足情報を示す。採用・差し戻し・却下・保留は人が裁定する。外部identity provider照合は未実装で、actor/role/decisionを外部本人確認済みとは扱わない。同一actorが兼任してもrole別承認を要求し、change案のapproved_byへbusiness_approver:<actor>とtechnical_approver:<actor>の2件を記録する。

§8禁止事項

  • 正式glossaryの直接編集
  • 公開済み用語の物理削除
  • 類義語の自動統合
  • 未使用0件からの自動削除
  • 解析候補の直接昇格

§9検証

正式test command
scripts/test-maintaining-semantic-glossary.sh。deterministic CLIと手順契約を区分して検証する。
区分付き記録
互換ファイル名verification/ai-forward-test.jsonへrepo相対fixture、source SHA-256前後、CLI観測、期待判定、サンプルhashを保存する。evidenceModeはcli_replay、cli_and_contract、contract_onlyを区別する。
再実行手順
repo rootから正式test commandを実行する。wrapperはscripts/verify-ai-forward-test.pyでschema検証し、実行可能CLIを再実行してfixture hashを照合する。絶対pathや機密値は記録しない。
責務境界
registry省略・dry-run変更要求・ai_index停止のうち実行入口がない部分は契約照合であり、AI実行を再現した証拠ではない。正式glossaryを直接変更しない。

§10管理Skillへの引渡し

保守Skill: 検査・影響・変更要求 → 管理Skill: validator・二者承認・適用・portal公開

errorまたはreview_requiredが残る時は適用を推奨せず、不足情報と次の判断者を返す。
