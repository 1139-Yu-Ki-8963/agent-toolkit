# generating-requirement-definitions-for-reverse-docs テストケース

観点キーは連番禁止。内容を要約した意味語で付ける（番号からは情報を得られないため）。

| 観点キー | 前提 | 操作 | 期待結果 | 機械検証の方法 |
|---|---|---|---|---|
| 業務語彙-内部識別子ゼロ | 対象文書が生成済みである | Phase 4 検査1を実行する | 型構文・フレームワーク用語・原本の拡張子・内部識別子（`unitId`・`unitKey`・`detectionMethod`・`sourceFile`・`unitNameGuess`・`manifest.ext.json`）の検出が0件であること | 検査1（`grep -nE 'interface [A-Z]|: *(string|number|boolean)\b|\.(py|pl|pm|cgi|rb|go|java|tsx|jsx)\b|unitId|unitKey|detectionMethod|sourceFile|unitNameGuess|manifest\.ext\.json' <対象文書.md>` の検出0件） |
| 注記-記入規則コメント残存なし | テンプレートを展開した文書がある | Phase 4 検査2を実行する | テンプレートの記入規則を書いたHTMLコメント（`<!-- -->`）が本文に残っていないこと | 検査2 |
| frontmatter-status整合 | Step 3-4のstatus確定が完了している | Phase 4 検査3を実行する | `status`が`draft`または`traced`のいずれかで、Step 3-4の判定結果と一致していること | 検査3 |
| 章-完備 | テンプレートが§1〜§3の章見出しを持つ | Phase 4 検査4を実行する | テンプレートが持つ全ての章見出しが出力に存在すること | 検査4 |
| 要確認-行数下限 | ユニット単位の4文書（機能・帳票・バッチ・外部連携要件）が生成済みである | Phase 4 検査5を実行する | §3の行数が対象ユニット数以上であること | 検査5 |
| 要確認-必須3キー残存 | ビジネス概要が生成済みである | Phase 4 検査5を実行する | 事業概要・システム役割・対象利用者の3キーが§3に残存していること | 検査5 |
| 配置-出力先実在 | 対象文書が生成済みである | Phase 4 検査6を実行する | `<output_dir>/<commonRoot>/<ファイル名>`が実在すること | 検査6 |
| 個別基本設計書-未生成時の空欄維持 | 帳票・バッチ・外部連携要件のいずれかのユニットで個別基本設計書が未生成である | Phase 2 Step2-2、Phase 3 Step3-2を実行する | 該当ユニットの当該観測列が空欄のまま残り、§3に「個別基本設計書が未生成」の行が追加されること | 手動（合成フィクスチャを要する） |
| status-traced昇格条件 | 対象文書の全ユニットでマニフェストと個別基本設計書がともに実在する | Phase 3 Step3-4を実行する | `status`が`draft`から`traced`へ更新されること | 検査3（`traced`が§2の空欄ゼロと対応していることを確認） |
| status-draft維持条件 | 対象文書のいずれかのユニットで個別基本設計書が未生成である | Phase 3 Step3-4を実行する | `status`が`draft`のまま維持されること | 検査3 |
| 入力なし-対象外記録 | ある種別のマニフェストも該当なし記録も実在しない | Phase 2 Step2-1を実行する | 当該文書がスキップ対象として記録され、推測で生成されないこと | 手動（合成フィクスチャを要する） |
| ビジネス概要-対象外記録 | ある種別のマニフェストも該当なし記録も実在しない | Phase 2 Step2-3、Phase 3 Step3-2を実行する | §2の値列へ「対象外（入力なし）」が記入され、§3へ当該種別の行が追加されること | 手動（合成フィクスチャを要する） |
| 機能-個別基本設計書は不使用 | 機能要件一覧を生成する | Phase 2・Phase 3を実行する | 機能一覧マニフェストの単独入力だけで§2の全列が記入され、個別基本設計書を読まないこと | 手動（対象マニフェストを要する） |
| 件数取得-画面はscreensキー | screen-manifest.jsonが実在する（最上位キーがscreens） | Phase 2 Step2-3を実行する | `.screens`の要素数を件数として取得し`.units`を参照しないこと（screen-manifest.jsonは`.units`を持たない） | 手動（`jq '.units' screen-manifest.json`がnullになることで検証可） |
| 件数取得-画面以外はunitsキー | 機能・API・テーブル・バッチ・帳票・外部連携のいずれかのmanifestが実在する（最上位キーがunits） | Phase 2 Step2-3を実行する | `.units`の要素数を件数として取得すること | 手動 |

## 機械検証との対応

- 機械検証が「手動」の行は、ガイドHTMLの検証状況へ手動確認を記録する
- 本スキルは現時点でガイドHTML（references/guide.html）を持たない
- self-test に対応ケースを追加したら、この表の機械検証列を同じコミットで更新する
