# unlocking-reverse-target-screens テストケース

観点キーは連番禁止。内容を要約した意味語で付ける（番号からは情報を得られないため）。

| 観点キー | 前提 | 操作 | 期待結果 | 機械検証 |
|---|---|---|---|---|
| 前提ゲート-最初の1枚目は確認省略 | 開通済み画面が1件も無い | 前提ゲートを実行する | リファレンス画面確認を省略しdevサーバー確認のみで通過する | 手動 |
| 前提ゲート-未確定キー残存で停止 | manifest.ymlに未確定トークンが残る | 前提ゲートを実行する | status=ERRORとし穴埋めを実行者が推測しない | 手動 |
| 埋め込みビュー-ルート不在時の読み替え | 対象画面がトップレベルルートを持たない | Phase 1を実行する | 親画面経由のURLと操作手順に読み替える | 手動 |
| 大型複合画面-最小集合限定 | オペレーション数が20件を超える | Phase 1を実行する | 初期表示に必要な最小集合だけを開通対象とする | 手動 |
| 権限チェーン-呼び出し無しはスキップ | 対象画面が権限チェック関数を呼ばない | Phase 2着手前の確認を行う | 登録作業をスキップし判定根拠を記録する | 手動 |
| 権限チェーン-同一分類キーの横断登録 | 分類キーが複数系統に分散消費される | Phase 2の登録を行う | 洗い出した全系統へ一括登録する | 手動 |
| 検証ループ-フォールバック形状不一致の診断 | 汎用空応答フォールバックがある構成でクラッシュする | Phase 4の失敗診断を行う | フォールバック形状と消費側の直読みフィールドを突合する | 手動 |
| 開通競合-重複割当の検知 | 作業コピーまたはブランチが他プロセス使用中 | 前提ゲート着手前に確認する | status=CONFLICT-SKIPPEDで即座に終了する | 手動 |
| dynamic-only-完了条件 | 実測URLからscenariosを補完した | scenarios完全性ゲートを実行する | 通過した場合だけstatus=UNLOCKEDを返す | 手動 |
| standalone-基準確立の決定的確認 | syncing-reverse-envがPASSを返した | 基準タグ確立を確認する | 決定的コマンド出力で確認し自己申告で済ませない | 手動 |
| ポート上限-BLOCKEDへの分類 | syncing-reverse-envがスロット上限到達のERRORを返す | Phase 5の結果を判定する | status=BLOCKEDとしhintに3点の確認事項を記す | 手動 |
| 並列実行-レジストリ記帳のみ直列化 | 複数実行者が同時に開通作業を行う | Phase 5の記帳を行う | 記帳のみ排他し他の作業は並列のままとする | 手動 |

## 機械検証との対応

- 機械検証が「手動」の行は、unlocking-reverse-target-screens-guide.html の検証状況へ手動確認を記録する
- self-test に対応ケースを追加したら、この表の機械検証列を同じコミットで更新する
