# generating-external-detail-design-for-reverse-docs テストケース

観点キーは連番禁止。内容を要約した意味語で付ける（番号からは情報を得られないため）。

| 観点キー | 前提 | 操作 | 期待結果 | 機械検証の方法 |
|---|---|---|---|---|
| マニフェスト整合-記載事項一致 | 外部連携詳細設計書が生成済みである | Phase 4 検査1を実行する | マニフェストの`direction`・`protocol`・`authMethod`のうち値を持つフィールドが本文に反映され、不一致が0件であること | 検査1 |
| 注記-記入規則コメント残存なし | テンプレートを展開した設計書がある | Phase 4 検査2を実行する | テンプレートの記入規則を書いたHTMLコメント（`<!-- -->`）が本文に残っていないこと | 検査2 |
| frontmatter-status-authored | Phase 3 Step4が完了している | Phase 4 検査3を実行する | frontmatterの`status`が`authored`になっていること | 検査3 |
| 章-完備検査 | 外部連携詳細設計書が生成済みである | Phase 4 検査4を実行する | テンプレートが持つ全ての章見出しが出力に存在すること | 検査4 |
| 識別子-空でERROR中断 | `unitId`と`unitKey`の双方が空のユニットがある | Phase 3 Step1で出力先を決定する | `status=ERROR`となり、hintに「出力先の識別子が確定しない」が入る | 手動（合成フィクスチャを要する） |
| 実装位置-非記録 | 原本コードから項目が抽出済みである | Phase 2 Step2を実行する | 対象コードのファイルパス・行番号がなく、確定できない項目は要確認事項一覧へ回ること | 手動（対象コードベースを要する） |
| 実装用語-混入許容 | 外部連携詳細設計書が生成済みである | 本文の実装用語の混入有無を確認する | 実装用語の混入を理由に差し戻さないこと（外部連携基本設計書とは逆の方針） | 手動（Phase 4 に実装用語検査が存在しないことの確認） |
| 担当範囲-基本設計の記述なし | 外部連携詳細設計書が生成済みである | 本文の連携の方式・連携の契機・責任の分界点・正常時と異常時の応答・再送の可否の記載有無を確認する | 連携の方式・連携の契機・責任の分界点・正常時と異常時の応答・再送の可否が書かれていないこと（外部連携基本設計書の担当範囲であるため） | 手動（章立て確定前のため機械検査項目化は未実施） |

## 機械検証との対応

- 機械検証が「手動」の行は、guide.html の検証状況へ手動確認を記録する
- self-test に対応ケースを追加したら、この表の機械検証列を同じコミットで更新する
