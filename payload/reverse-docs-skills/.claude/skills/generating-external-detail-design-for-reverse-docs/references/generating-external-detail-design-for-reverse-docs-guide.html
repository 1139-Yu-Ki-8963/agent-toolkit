§1概要

その外部連携が何のために存在し、誰と連携するかは、外部連携基本設計書が書く。しかし、その連携がどんな電文をどう変換し、どうタイムアウトし、どうリトライするかという実装の詳細には、業務的な意味とは別に答える必要がある。

本スキルは原本コードを読み、電文の項目の定義・変換の処理・タイムアウト・リトライ・冪等性の担保を各項目に file:line 形式の根拠を付けて記述する。詳細設計は実装用語を使ってよい。

本スキルがやること
外部連携 1 本ごとの電文の項目の定義・変換の処理・タイムアウト・リトライ・冪等性の担保を、原本コードの根拠付きで記入した外部連携詳細設計書の生成
本スキルがやらないこと
連携の方式・連携の契機・責任の分界点・正常時と異常時の応答・再送の可否の記述（外部連携基本設計書の担当）／ 外部連携一覧の生成（generating-external-list-for-reverse-docsの担当）

起動引数

引数必須内容
external_manifest_path必須外部連携一覧の拡張マニフェストの絶対パス
source_dir必須原本コードのルート
output_dir必須出力先のルート
template_root必須テンプレート群のルート
unit_keys任意対象を絞るキーの配列
common_docs_root任意共通文書のルート

unit_kind は external 固定であり、引数には取らない。

§2出力

外部連携 1 本につき、次の 1 点が生まれる。

外部連携詳細設計書.md（<output_dir>/外部連携/external-<外部連携識別子>/詳細設計/外部連携詳細設計書.md）
その外部連携の電文の項目の定義・変換の処理・タイムアウト・リトライ・冪等性の担保を、原本コードの file:line 根拠付きで記入した文書。コードから確定できなかった事項は要確認事項一覧へまとめて記載される。

§3用語

file:line根拠
原本コードのファイルと行を file:line の形で本文に示す記述の方針。詳細設計は業務語彙の制約を受けず、実装用語を使ってよい。
要確認事項
コードから確定できない事項を推測で埋めず、確認事項として記録したもの。キーは連番を禁じ、内容を要約した意味語で付ける。
マニフェストとの整合確認
拡張マニフェストの direction・protocol・authMethod と、原本から読み取った内容が食い違わないかを確認すること。食い違いは要確認事項一覧へ記録する。

§4動作フロー

Phaseやること完了条件
Phase 1
起動引数の検収と対象の確定		 必須4引数の実在確認、マニフェストの検収（unitKind が external・units が1件以上）、対象ユニットの確定を行う 4引数が実在し、マニフェストが検収済みで、対象ユニットが確定している
Phase 2
原本読解		 マニフェストの sourceFile が指すファイルを読み、電文の項目の定義・変換の処理・タイムアウト・リトライ・冪等性の担保を file:line 根拠付きで抽出する。マニフェストとの整合を確認する 対象ユニット全件について、根拠付きの記入材料が揃っている
Phase 3
執筆		 テンプレートを展開・配置し、各章へ記入する。空欄のまま残った項目を要確認事項一覧へ列挙し、frontmatter の status を draft から authored へ更新する 全対象ユニットの設計書が記入済みである
Phase 4
機械検査		 拡張マニフェスト記載事項の一致検査・注記の残存検査・frontmatter の検査・章の完備検査の4検査を実行する。不合格が1件でもあれば Phase 3 へ戻る（上限3回） 4検査すべてが合格している

§5守り（禁止事項と機械検証）

禁止事項

  • 連携の方式・連携の契機・責任の分界点・正常時と異常時の応答・再送の可否を書かない（外部連携基本設計書の担当）
  • コードから確定できない事項を推測で埋めない
  • マニフェストとの食い違いを無視せず、要確認事項一覧へ記録する
  • 子スキルへ委任しない。原本読解と執筆（Phase 1〜3）は一貫性を保つため単一のメインエージェントが通しで担う

機械検証

Phase 4 で次の4検査を実行する。検査1はマニフェストの direction・protocol・authMethod のうち値を持つフィールドが生成した本文に反映されていることを確認する。検査2はテンプレートの記入規則を書いた HTML コメントが残っていないことを確認する。検査3は frontmatter の status が authored になっていることを確認する。検査4はテンプレートが持つ全ての章見出しが出力に存在することを確認する。本スキルは実装用語の混入を検査対象としない。1つでも不合格なら Phase 3 へ戻り、上限3回で収束しなければ status=ERROR とする。
