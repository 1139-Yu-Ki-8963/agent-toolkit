§1概要

glossary、proposal、changeを別文書として扱う。リバース解析は候補だけを生成し、正式用語へ直接書き込まない。

既定はdry-run。 二者承認と明示的な適用指示がそろうまで定義YAMLを変更しない。

独立CRUD runnerや管理CLIではなく、AIがRead/Grep/Bash/Write/Editで変更要求と承認済みYAML差分を扱う手順である。scriptsは実行入口ではなく契約検証用テストである。

§2出力

操作に応じて、次の監査可能な状態が生まれる。

検証済み変更結果
差分、根拠、影響、承認、validator findingを結び付けた結果。
変更履歴
誰が何をなぜ判断したかをcontent versionとともに追跡できる記録。
portal投影
承認済み用語だけから決定的に生成した人向けデータ。

§3入力とモード

モード役割定義変更
lookup / validate検索・検証なし
review-proposal候補の採否材料を確定proposal/changeのみ
add / update承認済み意味定義を変更二者承認時のみ
deprecate / retire移行と履歴保持二者承認時のみ
publish承認済み定義を派生派生物のみ

review-proposal、add、update、deprecate、retireでは--registry <file-or-dir>が必須。省略時はreview_requiredとして適用を止める。

§4処理フロー

入力確定 → validator → report schema検証 → 影響確認 → 二者承認 → 適用（任意） → portal投影
exit / status扱い
0 / validerror 0件。review_requiredが1件以上なら適用停止、warningだけなら継続可
1 / invalid入力・対象を変更せず停止
2 / unavailabledependency、parse、内部、走査不能として入力・対象を変更せず停止

§5二者承認

役割判断
business approverdefinitionとscopeの業務上の正しさ
technical approverrepresentation、互換性、移行影響

AIは推奨できるが、AIだけをbusiness approverにしない。外部identity provider照合は未実装で、actor/role/decision記録と人のレビューまでを扱う。同一actorが兼任してもrole別承認を要求し、changeのapproved_byへbusiness_approver:<actor>とtechnical_approver:<actor>の2件を記録する。

§6ライフサイクル

proposal → active → deprecated → retired / rejected（proposal側だけ）

公開済み用語は物理削除せず、retired後もkey解決と履歴を保持する。

§7公開境界

portal
v0.1で許可する唯一のpublish target。source YAMLは変更しない。
ai_index
将来のpublish拡張。現行版ではreview_required / not_implementedで成果物なしに停止する。

§8停止条件

  • validator exit 1または2、statusがinvalidまたはunavailable
  • counts.errorまたはcounts.review_requiredが1件以上
  • 二者承認の欠落、stale version、未裁定衝突
  • portal以外のpublish target

SGS/SGK/SGR/SGL/SGP/SGV/SGDのcode familyとseverityを保持し、report countsをfindingsから再集計する。

§9検証

正式test command
scripts/test-managing-semantic-glossary.sh。deterministic CLIと手順契約を区分して検証する。
区分付き記録
互換ファイル名verification/ai-forward-test.jsonへrepo相対fixture、source SHA-256前後、CLI観測、期待判定、成果物hashを保存する。evidenceModeはcli_replay、cli_and_contract、contract_onlyを区別する。
再実行手順
repo rootから正式test commandを実行する。wrapperはscripts/verify-ai-forward-test.pyでschema検証し、実行可能CLIを再実行する。portal projectorは一時領域へ再実行し、verification/portal-page-data.jsonとのbyte一致を確認する。絶対pathや機密値は記録しない。
責務境界
registry省略・dry-run・ai_index停止のうち実行入口がない部分は契約照合であり、AI実行を再現した証拠ではない。CLI exit 0をregistry省略時の適用許可へ読み替えない。
