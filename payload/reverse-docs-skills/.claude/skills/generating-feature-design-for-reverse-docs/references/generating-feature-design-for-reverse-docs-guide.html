generating-feature-design-for-reverse-docs

機能一覧マニフェストと配下ユニットの拡張マニフェストから、機能単位の集約設計書を執筆するスキルの確定仕様。機能一覧の生成スキルは一覧HTMLのみを担い、設計書の雛形展開・生成・記入をしないと明記しており、本スキルがその先を引き受ける。

§1概要

このスキルは、機能単位の集約設計書を書く。機能一覧の生成スキルは一覧 HTML だけを担い、設計書の雛形展開・生成・記入をしないと明記している。本スキルがその先を引き受け、機能設計書のテンプレートを展開して記入する。情報源は機能一覧マニフェストと配下ユニットのマニフェスト、そして構成要素の個別設計書の 3 つに限り、原本コードは読まない。

§2出力

機能 1 つにつき、以下の 3 点が生まれる。

機能 1 つぶんの全体像
その機能を構成する画面・API・実行ファイルが一覧になり、それぞれの個別設計書へのパスが並ぶ。読んだ人は、業務としてひとまとまりの操作が、どの実装要素の組み合わせで成り立っているかを把握できる。
構成要素をまたぐ事項だけを集めた記述
業務フロー、業務ルール、状態のライフサイクル、そして複数の構成要素が共有する処理と記憶域が記される。どの個別設計書にも収まらない情報がここに集まる。
確定できなかったことの一覧
個別設計書が存在しない構成要素や、マニフェストと突合できなかった参照が、推測で埋められずに列挙される。

§3用語

集約設計書
構成要素の個別設計書から値を再掲せず、パスで参照する設計書。構成要素をまたいで初めて意味を持つ事項だけを正として持つ。
共通処理
複数の構成要素が呼ぶ内部ヘルパー。機能側に 1 箇所だけ記述する。
共有状態
複数の構成要素が同じ記憶域を介して受け渡す情報。機能側に 1 箇所だけ記述する。

§4集約設計書としての書き分け

機能設計書は集約設計書である。構成要素（API・画面・実行ファイル）の個別仕様は各構成要素の設計書を正とし、本書は値を再掲せずパスで参照する。1 つの機能に複数のエンドポイントが同居する構成を前提とし、本書が担う固有の役割は次の 2 つで、いずれも機能側に 1 箇所だけ記述する。

対象記述先規約
共通処理§7.1 機能内の呼び出し一覧複数の構成要素が同じ内部ヘルパーを呼ぶ場合、そのヘルパーを機能設計書に 1 回だけ記述する。各構成要素の個別設計書には重複して書かず、参照に留める
共有状態§6.2 共有ストア・共有領域複数の構成要素が同じ記憶域（セッションテーブル・共有ストア・一時領域）を介して連携する場合、その受け渡しを機能設計書に 1 回だけ記述する

同じ内容を機能設計書と個別設計書の両方へ書くことを禁止する。2 つ目の実体を作ると、片方だけが更新される穴が生まれる。

§5動作フロー

Phase名前完了条件
Phase 1起動引数の検収と対象確定3 引数が実在し、マニフェストが検収済みで、配下ユニットと対象機能が確定している
Phase 2集約材料の収集対象機能全件について、構成要素一覧と集約対象が揃っている
Phase 3執筆全対象機能の設計書が記入済みである
Phase 4検証4 検査すべてが合格している
── 動作フロー ─────────────────────────────

Phase 1  起動引数の検収と対象確定
   │  3引数の実在確認 → マニフェスト検収 → 配下ユニット確定 → 対象機能確定
   ▼
Phase 2  集約材料の収集
   │  構成要素の突合 → 共通処理/共有状態の集約対象を特定 → 不足分を要確認事項へ
   ▼
Phase 3  執筆
   │  テンプレート展開 → §1〜§10記入 → 空欄を§11要確認事項へ
   ▼
Phase 4  検証
   │  検査1 章の完備 / 検査2 全章の充足 / 検査3 参照実在 / 検査4 プレースホルダの残存
   │  不合格ならPhase 3へ差し戻し（上限3回）
   ▼
完了  機能ごとに構成要素の参照と、機能側に1箇所だけ集約した共通処理・共有状態を持つ設計書

§6検証

Phase 4 で実行する 4 つの機械検査。1 つでも不合格なら Phase 3 へ差し戻し、上限 3 回で収束しなければ status=ERROR とする。

検査内容
検査1 章の完備生成した各設計書に §1 から §11 が存在し、あわせて付録 A・B も存在する。§ の章は grep -c '^## §' が 11 を返すことで確認し、付録は grep -c '^## 関連資料\|^## 章マップ' が 2 を返すことで確認する
検査2 全章の充足§1 から §11 の各章について、表の本文行が 1 行以上あるか、または当該章に対応する項目が §11 要確認事項へ回っているかのいずれかを満たす。どちらも満たさない空章があれば不合格とする
検査3 参照実在§2.1 に記載した個別設計書のパスが実在する。design_docs_root が渡されていない場合は本検査を skip し、その旨を返却の hint に記録する
検査4 プレースホルダの残存FEATUREKEY・FEATUREID・CATEGORY・SOURCEREF が本文に残っていない

§7制約と既知の限界

  • 原本コードを読まないため、個別設計書の質が本書の質の上限になる
  • 構成要素の個別設計書が 1 枚も無い場合でも中断せず、要確認事項だけを持つ設計書を生成する
  • 往復検証の対象外である。機能には対応する原本ファイルが存在せず、突合の相手がない
  • 検査3 の参照実在は design_docs_root が渡されない場合に skip する
