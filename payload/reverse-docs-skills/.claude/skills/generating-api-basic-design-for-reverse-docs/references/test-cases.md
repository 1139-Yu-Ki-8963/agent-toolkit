# generating-api-basic-design-for-reverse-docs テストケース

観点キーは連番禁止。内容を要約した意味語で付ける（番号からは情報を得られないため）。

| 観点キー | 前提 | 操作 | 期待結果 | 機械検証の方法 |
|---|---|---|---|---|
| 業務語彙-実装用語ゼロ | 設計書が生成済みである | Phase 5 検査1を実行する | 実装用語（フレームワーク用語・型構文・原本の拡張子・内部の成果物名）の検出が0件であること | `bash generation-engine/scripts/tests/test-api-basic-design-evidence-ledger.sh` |
| 根拠列-基本設計書から分離 | API基本設計書テンプレートがある | 15個のデータ表のヘッダを走査する | `根拠` という列が0件であること | 同self-testの「API基本設計書の根拠列」 |
| 実装位置-非記録 | output-layoutと納品物一覧がある | 根拠台帳の配置キーとkindが存在しないことを照合する | 根拠台帳が納品物として宣言されず、設計書に対象コードのファイルパス・行番号がないこと | 同self-testの「実装位置の非記録」 |
| 根拠-file:line不使用 | 設計書の本文がある | Phase 5 検査1を実行する | 原本の拡張子（.py/.pl/.pm/.cgi）を含むファイルパス形式の記述が本文に存在しないこと | 検査1（同一grepコマンドの拡張子パターンで検出0件） |
| 注記-記入規則コメント残存なし | テンプレートを展開した設計書がある | Phase 5 検査2を実行する | テンプレートの記入規則を書いたHTMLコメント（`<!-- -->`）が本文に残っていないこと | 検査2 |
| frontmatter-status-authored | Phase 3 Step5が完了している | Phase 5 検査3を実行する | 基本設計書のfrontmatterが`status: authored`であり、`updated`に`<YYYY-MM-DD>`が残っていないこと | 検査3 |
| 識別子-空でERROR中断 | `unitId`と`unitKey`の双方が空のユニットがある | Phase 3 Step1で出力先を決定する | `status=ERROR`となり、hintに「出力先の識別子が確定しない」が入る | 手動（合成フィクスチャを要する） |
| 対象-0件で生成せず完了 | 対象ユニットが0件である | Phase 1 Step4で対象ユニットを確定する | 設計書を生成せず、生成物0件のまま完了する | 手動（合成フィクスチャを要する） |

| 担当範囲-詳細設計の記述なし | 設計書が生成済みである | 本文の要求・応答の項目定義および処理手順の記載有無を確認する | 要求と応答の項目定義・処理手順が書かれていないこと（API詳細設計書の担当範囲であるため） | 手動（章立て確定前のため機械検査項目化は未実施） |

根拠台帳の即時適用はAPI基本設計書に限る。APIテスト設計書は基本設計書を情報源とし、コードを根拠にしないため台帳の対象外とする。API詳細設計書、単体テスト設計書および機能設計書は将来の移行方針とし、本項目では既存テンプレートとスキルの契約を変更しない。

## 機械検証との対応

- 機械検証が「手動」の行は、guide.html の検証状況へ手動確認を記録する
- self-test に対応ケースを追加したら、この表の機械検証列を同じコミットで更新する
