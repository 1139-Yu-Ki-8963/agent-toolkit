テストケース一覧生成スキル
generating-test-case-list-for-reverse-docs

画面ごとの単体・結合・操作シナリオの 3 種のテスト仕様書を横断集約し、整合検証を通過したデータだけから テストケース一覧.html を生成する派生一覧スキルの確定仕様。

対応 OSWindows WSL2 環境
検証状況一覧生成エンジン（build-unit-list.sh）は画面一覧生成で実プロジェクト動作確認済み。3 種の横断集約と専用検証（aggregate-test-cases.sh・validate-test-case-manifest.sh）の単独実機検証は未実施。スキル専用のテストスクリプトは持たない
依存共有スクリプト shared/scripts/aggregate-test-cases.sh・shared/scripts/validate-test-case-manifest.sh・shared/scripts/unit-list/build-unit-list.sh ／ 任意 shared/scripts/build-portal.sh

§1概要

テストケースは画面ごとの仕様書に分かれて書かれるうえ、単体・結合・操作シナリオの 3 種に分かれている。システム全体で何件のケースがあり、どの画面が手薄かは、この状態では分からない。本スキルは 3 種を横断で集約し、1 つの表として引けるテストケース一覧.html を作成する。

出力はタブを持たない単一の表である。3 種を切り替えて見るのではなく、種別を列として持つ 1 枚の表にまとめることで、種別をまたいだ比較を可能にする。

本スキルがやること
3 種のテスト仕様書の横断集約・整合検証・テストケース一覧.html の生成
本スキルがやらないこと
画面ごとのテスト仕様書の執筆（画面詳細設計書の生成工程の担当） ／ 観点の網羅性の評価（generating-test-viewpoint-list-for-reverse-docs の担当）

起動引数

引数内容
output_dir画面ごとのテスト仕様書の所在であり、テストケース一覧.html の書き出し先でもあるディレクトリ
portal_output_dir任意。渡された場合のみポータルへ反映する

画面ごとのテスト仕様書が 1 件も存在しない場合、本スキルは生成せず SKIP を返す。

§2出力

対象リポジトリ 1 つにつき、次の 1 点が生まれる。

テストケース一覧.html
単体・結合・操作シナリオの 3 種を横断集約した単一の表。タブを持たない。output_dir 配下の 一覧/テストケース一覧/ に置かれる

§3用語

単体
画面内の部品や関数の単位で確認するテスト。操作手順は持たない
結合
複数の要素をつないだ状態で確認するテスト。操作手順を持つ
操作シナリオ
利用者の一連の操作をたどるテスト。シナリオ名で仕様書の該当節と突き合わせる

§4動作フロー（Phase 1〜4）

Phase内容
Phase 1 集約対象の確認output_dir 配下に画面ごとのテスト仕様書が存在するかを確認する。0 件なら生成せず SKIP を返す
Phase 2 横断集約（機械実行）aggregate-test-cases.sh が 3 種の仕様書を走査し、マニフェストの JSON を組み立てる。確定行が 0 件の種別も、集約対象として走査した記録を残す
Phase 3 整合検証（機械実行）validate-test-case-manifest.sh を実行する。全項目 PASS が次へ進む条件。FAIL は 3 回まで修正を試み、超過したら Phase 2 へ差し戻す
Phase 4 生成build-unit-list.sh がテストケース一覧.html を出力する。portal_output_dir が渡されていれば build-portal.sh でポータルへ反映する

§5守り（禁止事項と機械検証）

禁止事項

  • マニフェストや生成後の HTML を手作業で編集しない。直すのは集約スクリプトの側
  • テスト仕様書に書かれていないケースを補完しない
  • 確定行が 0 件の種別を、集約の記録から脱落させない
  • build-unit-list.sh を経由せず HTML を組み立てない

機械検証

Phase 3 の validate-test-case-manifest.sh が全項目 PASS しない限り HTML は生成されない。3 回の修正で PASS しない場合は Phase 2 へ差し戻し、原因が集約側にあることを明示して止まる。
