本書は、画面・API・テーブル・バッチ・帳票・外部連携の詳細設計書に共通する記述方法を定める。
各詳細設計書は業務仕様と実装契約を読者へ伝える。実装位置ではなく、文書内の契約を安定した参照先とする。

## §1 型の記述

- 型は対象言語で使う型名を記載する。対象言語の型へ一意に定まらない場合は、文字列・数値・真偽値・日付時刻・列挙・配列・構造体の分類を併記する。
- 配列と構造体は、要素または構成項目の型まで記載する。
- 列挙は取り得る値を列挙し、未定義値を受け入れるかを明記する。

## §2 有効な範囲の記述

- 値を参照できる範囲は「有効な範囲」の列に記載する。
- 範囲は、処理内・関数内・構成要素内・要求内・セッション内・永続のいずれかで表す。対象技術の用語を使う場合は、この区分との対応を併記する。
- 同名の値が複数の範囲に存在する場合は、どの範囲の値を扱うかを区別する。

## §3 NULL 許容の記述

- NULL を許容するかを「許容」「不許容」のいずれかで記載する。
- NULL、未指定、空文字、空配列、0 は区別し、それぞれの意味が異なる場合は扱いを記載する。
- 条件によって NULL を許容する場合は、その条件と NULL のときの処理を記載する。

## §4 初期値・既定値の記述

- 作成時に設定する値は「初期値」、入力を省略したときに採用する値は「既定値」として区別する。
- 初期値または既定値を持たない場合は「なし」と記載する。
- 動的に決まる場合は、決定条件または算出規則を記載する。

## §5 桁と精度の記述

- 文字列は最大文字数、整数は最大桁数を記載する。
- 小数は全体桁数と小数部桁数を記載し、丸め・切り捨て・切り上げの方式を併記する。
- 日付時刻は書式と精度を記載する。タイムゾーンを扱う場合は、その基準も記載する。
- 制限が無い場合は「制限なし」、実装から確定できない場合は「未確定」と記載し、推測で補わない。

## §6 疑似コードの記述

- 疑似コードは処理順序、分岐、繰り返し、終了条件を業務語彙で表す。
- 実装言語の構文や実装コードの転記を避け、詳細設計書だけで処理の意図を読める粒度にする。
- 疑似コードと関連する表には、対象コードのファイルパスや行番号を記録しない。
- 「参照先」には、文書内の節番号または関数単位の契約への参照だけを記載する。対象コードの位置や、別途追従が必要な根拠台帳への参照は記載しない。

## §7 適合確認

詳細設計書を確定する前に、次を確認する。

1. 型または型の分類が記載されている。
2. 有効な範囲が記載されている。
3. NULL 許容と初期値または既定値が区別されている。
4. 文字数・桁数・精度のうち、対象に必要な制約が記載されている。
5. 疑似コードと関連する表に、対象コードのファイルパスや行番号が無い。
6. 参照先が文書内の節番号または関数単位の契約に限定されている。
