## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | API詳細設計書 | API単体テスト設計書（本書） |
| 内部結合 | 1つのAPIの中で関数・メソッドが結合した状態（外部の振る舞い） | API基本設計書 | API結合テスト設計書 |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## テストの粒度と自動化の方針

| 項目 | 方針 |
|---|---|
| テストの粒度 | 1つの関数またはメソッドを1単位として、入出力・分岐・副作用・例外を確認する。 |

## 本書が扱わない範囲

| 対象外の事項 | 対象外とする理由 | 代わりに確認する資料または試験 |
|---|---|---|
| APIの応答コードを含む外部契約 | 関数単位より上のAPI単位であるため | API結合テスト設計書 |
| 複数の機能・APIの連携 | 単位ごとの文書は結合テストを扱わないため | docs/test-cases/結合テスト仕様書.md |

## §1 テスト観点

**この節の位置づけ: 仕様**

§1は正常・異常・境界を含む全観点の一覧です。
§5と§6は、§1のうち異常と境界の観点を列ごとに詳しく述べる部分集合です。
§5と§6では新しい観点キーを作らず、§1と同じ観点キーを使います。
実行する全ケースは§2だけに記載し、§1の全観点へ1件以上のケースを対応させます。
実行するテストの件数は§2のデータ行数だけで数えます。

観点は詳細設計書のメソッド設計・ロジック設計・エラー処理から起こす。API では、それぞれ API実装記録 §4.2（関数単位の契約）、API詳細設計書 §5（ロジック）、API詳細設計書 §7（エラー）を対応する情報源として扱う。
