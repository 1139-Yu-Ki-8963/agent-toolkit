# 使うツールとコマンドの決まり

## 概要

開発で使うツールとコマンドを、どこから・どの権限で・何を確かめてから実行するかの取り決め。

コマンドは実行した瞬間に効果が出るため、実行の前にしか判断の機会がない場合がある。使うツールを決めておくことで、同じ作業が実行者ごとに違う手順にならない状態を保つ。

## 規則

| 規則 | 内容 | 根拠 | 検査 |
|---|---|---|---|
| 使うツールを宣言で定める | 依存の導入・テストの実行・整形・静的解析に使うツールを、リポジトリの設定ファイルで宣言する | 手元だけに入れたツールは、他の作業者と継続的な統合の環境で動かない | 静的解析: 依存の宣言ファイルに、使用するツールが登録されているかを走査する |
| 版を固定する | ツールと依存の版を固定のファイルで留め、実行のたびに版が変わらないようにする | 版が動くと、同じ入力から違う結果が出る | 静的解析: 依存の版を固定するファイルが実在し、版管理へ登録されているかを走査する ／ テスト: 依存の導入を複数回実行し、導入される版が毎回変わらないことを確かめる |
| コマンドは宣言した入口から呼ぶ | 繰り返し使うコマンドを設定ファイルの実行定義へ登録し、長い引数の直打ちを避ける | 直打ちのコマンドは実行者ごとに引数が違い、結果の違いを追えない | 静的解析: 設定ファイルの実行定義に、テスト・整形・静的解析の入口が登録されているかを走査する |
| 秘密の値をコマンドの引数に置かない | 認証の鍵と合言葉は環境変数または秘密情報の保管先から読み、コマンドの引数と履歴に残さない | 引数はシェルの履歴とプロセスの一覧から読み取れる | 静的解析: リポジトリ内のスクリプトと設定に、認証の鍵らしい文字列が直接書かれていないかを走査する ／ テスト: 実際にコマンドを実行し、プロセスの引数一覧やシェル履歴に秘密の値がそのまま現れないことを確かめる |

## 違反時の手順

コマンドの実行が止められた場合、認証の鍵・合言葉らしき値を環境変数または秘密情報の保管先へ移し、コマンドの引数を `$VAR` のような参照に書き換えてから再実行する。値がプレースホルダ等で実際には秘密ではない誤検知の場合は、引数を環境変数参照の形に揃えるだけで解消する。
