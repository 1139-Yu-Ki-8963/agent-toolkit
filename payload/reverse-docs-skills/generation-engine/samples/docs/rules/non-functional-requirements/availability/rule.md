# 稼働を続けることと復旧の決まり

## 概要

稼働を続ける度合いと、障害が起きたときに復旧するまでの要件。

止まらないようにする方策と、止まった後に戻す方策は別のものであり、両方を決める。基本設計書の方式設計で、この要件を満たす方式を確定する。方式をどの文書のどの節へ書くかは、設計書の書き方の決まりが定める。

## 規則

| 規則 | 内容 | 検査 |
|---|---|---|
| 稼働の目標を数値で決める | 稼働を続ける割合と、計画して止める時間帯を、数値と時刻で決める | 静的解析: 要件定義書または基本設計書に稼働の目標値の記述があるかを走査する |
| 復旧の目標を2つ決める | 復旧までの時間と、失ってよいデータの時間幅の2つを決める | 静的解析: 要件定義書または基本設計書に復旧の時間と失ってよいデータの時間幅の記述があるかを走査する |
| 外部への依存に失敗時の扱いを持たせる | 外部との通信へ、待ち時間の上限・やり直しの回数・失敗した場合の振る舞いを決める | 静的解析: 外部への通信の呼び出しに待ち時間の上限が指定されているかを走査する ／ レビュー: やり直しの回数と失敗した場合の振る舞いが具体的に決められているかを確認する |
| 復旧の手順を書いて試す | 障害からの復旧の手順を書き、実際に試して動くことを確かめる | 静的解析: 復旧の手順書が実在するかを走査する ／ テスト: 手順に従って復旧を実行し、目標の時間内に戻ることを確かめる |

## このプロジェクトの規則

| 未解析 | この規約に対応する実装の慣行は、まだ観測していない。リバース解析を実行して対象コードを分析すると、その結果からこの節へ規則が起こされる。解析を待たずに規則を決めたい場合は、この節へ直接書き足してよい | 未解析: リバース解析が未実行であり、対象コードの観測結果がない | 不可: 観測の有無は解析の実行結果に依存し、静的解析で判定できない |

## 違反時の手順

書き込みが止められた場合、外部への通信の呼び出しへ待ち時間の上限を指定する。上限を独自の語で表す仕組みを使っている場合は、"timeout" という語が呼び出しの近くに現れるように、その仕組みの呼び出しを添えてから改めて書き込む。
