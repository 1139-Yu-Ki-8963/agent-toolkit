# 記録と監視の決まり

## 概要

記録の出し方・監視の対象・異常を知らせる仕組みと、操作の追跡に関する要件。

障害が起きてから記録を足しても、起きた時点の記録は存在しない。基本設計書の方式設計で、記録と監視の方式を確定する。方式をどの文書のどの節へ書くかは、設計書の書き方の決まりが定める。

## 規則

| 規則 | 内容 | 根拠 | 検査 |
|---|---|---|---|
| 記録の形式を1つに揃える | 出力する記録の形式を1つに決め、機械で読める形にする | 形式のばらばらな記録は、横断して絞り込むことができない | 静的解析: 記録の出力に、共通の出力口を経ない直接の書き出しが無いかを走査する ／ テスト: 実際に出力した記録が機械で解析できる形式になっているかを確かめる |
| 記録に追跡の鍵を含める | 1つの要求に属する記録を後からつなげるための鍵を、すべての記録へ含める | 鍵が無いと、同時に動いた複数の要求の記録が混ざって読めない | 静的解析: 記録の出力の共通処理に追跡の鍵の付与があるかを走査する |
| 秘密の値と個人の情報を記録しない | 認証の鍵・合言葉・個人を特定する情報を、記録へ出さない | 記録は保管先が広く、消す手数が本体のデータより大きい | 静的解析: 記録の出力に秘密の値らしい変数が渡されていないかを走査する ／ レビュー: 変数名からは検出できない個人の情報が記録に混入していないかを確認する |
| 記録の水準を使い分ける | 異常・警告・情報・詳細の水準を使い分け、常時の出力を必要な範囲に絞る | すべてを同じ水準で出すと、異常が量に埋もれる | 静的解析: 記録の出力に水準の指定があるかを走査する ／ レビュー: 水準が異常・警告・情報・詳細で適切に使い分けられ、常時の出力が必要な範囲に絞られているかを確認する |
| 監視する指標を先に決める | 何を見て正常と判断するかの指標を、稼働の前に決める | 稼働してから決めると、決めるまでの期間の値が残らない | 静的解析: 監視の設定ファイルが実在し、指標が登録されているかを走査する |
| 知らせる条件と宛先を決める | どの値がどうなったら誰へ知らせるかを決める | 宛先の無い通知は、誰も見ないまま溜まる | 静的解析: 監視の設定に通知の条件と宛先が登録されているかを走査する |
| 操作の記録を残す | 権限の変更・データの削除・設定の変更について、誰が・いつ・何に対して・何をしたかを残す | 不正や誤操作が起きたとき、原因と範囲を後から特定できない | 静的解析: 権限の変更・削除・設定の変更を行う処理に記録の出力があるかを走査する ／ レビュー: 出力される記録に、誰が・いつ・何に対して・何をしたかの4項目が含まれているかを確認する |

## 違反時の手順

書き込みが止められた場合、記録の出力に渡している値から秘密の値らしい変数を外し、必要ならその値を伏せ字やハッシュ値に置き換えてから改めて書き込む。エラーの説明文など、秘密の値を実際には渡していないのに語だけが同じ行に現れている場合は、記録先の変数名を秘密の語彙と紛らわしくない名前に変える。
