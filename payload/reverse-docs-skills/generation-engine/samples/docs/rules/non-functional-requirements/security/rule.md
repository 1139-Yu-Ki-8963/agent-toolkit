# 認証と入力と秘密の値の決まり

## 概要

認証・権限・入力の検証・秘密の値の扱いに関する要件。

この分野の誤りは、動作としては正常に見えるため、試して気付くことができない。基本設計書の方式設計で、この要件を満たす方式を確定する。方式をどの文書のどの節へ書くかは、設計書の書き方の決まりが定める。

## 規則

| 規則 | 内容 | 根拠 | 検査 |
|---|---|---|---|
| 問い合わせを文字列の結合で組み立てない | データベースへの問い合わせを利用者の入力の結合で作らず、値を分離して渡す仕組みを使う | 結合した問い合わせは、入力の内容が命令として解釈される | 静的解析: 問い合わせの組み立てに文字列の結合が使われていないかを走査する |
| 利用者の入力を素のまま出力しない | 画面へ出す値を、出力先の形式に応じて無害化してから書き出す | 無害化しない出力は、入力に含めた記述が画面上で実行される | 静的解析: 無害化を経ない出力の呼び出しが無いかを走査する |
| 権限の確認を処理の側で行う | 表示の出し分けだけに頼らず、処理を実行する側でも権限を確かめる | 表示の出し分けは、直接呼び出せば迂回できる | 静的解析: 処理の入口に権限の確認が置かれているかを走査する |
| 秘密の値をコードへ書かない | 認証の鍵・合言葉・接続の情報を、コードと設定ファイルへ直接書かない | 一度版管理へ入った値は履歴に残り、消しても復元できる | 静的解析: コードと設定に認証の鍵らしい文字列が含まれていないかを走査する |
| 入力の検証を境界で行う | 外から入る値を、受け取る境界で形式と範囲を検証する | 境界を越えた後の検証は、検証の漏れた経路を作る | 静的解析: 外部からの入力を受ける入口に検証の記述があるかを走査する ／ レビュー: その検証が形式と範囲の両方を確認しているかを確認する |
| 依存の脆弱性を決めた間隔で確かめる | 使っている依存に既知の脆弱性が無いかを、週に1回の間隔で検査する。間隔はこのプロジェクトの規則の表で上書きできる | 依存の脆弱性は、自分のコードを変えなくても増える | 静的解析: 継続的な統合の設定に依存の脆弱性の検査が、週に1回の間隔で登録されているかを走査する。間隔はこのプロジェクトの規則の表で上書きできる |

## 違反時の手順

書き込みが止められた場合、書こうとした鍵・合言葉・接続情報らしい値を、環境変数や秘密情報の管理の仕組みからの読み出しに置き換える。テスト用のダミー値のように正当な理由でリテラルが必要な場合は、値の形式が実物と混同されない書き方（プレースホルダーであると分かる記述）に変える。
