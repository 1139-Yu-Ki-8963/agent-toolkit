# データ設計書

本書はデータ設計方針を整理した設計書です。データモデル・APIスキーマ・状態管理・データフロー・キャッシュ戦略・状態遷移の方針を扱います。

## 本書に書かないもの

| 書かない内容 | 正の置き場 |
|---|---|
| 個別テーブルのカラム定義 | 各テーブル定義書（未整備の場合は本書に記載せず「実在しない」で明記） |
| 個別 API のリクエスト/レスポンス詳細 | 各 API 詳細設計書（未整備の場合は本書に記載せず「実在しない」で明記） |
| 画面固有のデータ取得ロジック | 各画面詳細設計書 |
| UI 表示上の状態（loading/empty/error） | `./共通設計書.md`（§1） |

---

## §1 データモデル概要

> 区分: 仕様

| エンティティ | 概要 |
|---|---|
| 注文（Order） | 会員が確定した購入単位。明細行（OrderItem）を子に持つ |
| 会員（Member） | EC サイトの購入者アカウント |
| 商品（Product） | 販売対象。SKU 単位で在庫と紐づく |
| 在庫（Inventory） | SKU ごとの引当可能数量 |
| 請求（Invoice） | 注文確定後に発行される請求単位 |
| 支払い（Payment） | 決済代行サービス経由の決済記録 |
| 出荷（Shipment） | 注文に対する配送手配単位 |
| 返品（Return） | 出荷済み注文に対する返品申請 |
| クーポン（Coupon） | 割引条件を持つ販促コード |
| レビュー（Review） | 会員が商品に投稿する評価コメント |
| 問い合わせ（Inquiry） | 会員からのサポート問い合わせ |
| キャンペーン（Campaign） | 期間限定の販促施策 |

## §2 API スキーマ

> 区分: 仕様

| 項目 | 内容 |
|---|---|
| エンドポイント体系 | `/api/<リソース名複数形>/:id` 形式の RESTful パターン（例: `/api/orders/:id`, `/api/members/:id`） |
| リクエスト/レスポンス設計方針 | 共通エンベロープ形式。正常時 `{ "data": {...}, "meta": { "requestId": "..." } }`、異常時 `{ "error": { "code": ..., "message": "..." }, "meta": {...} }` |

## §5 キャッシュ戦略

> 区分: 仕様

| 項目 | 内容 |
|---|---|
| キャッシュ方式 | React Query のインメモリキャッシュ（`staleTime` を各クエリごとに個別設定） |
| 無効化戦略 | mutation 成功時に対応するクエリキーを `invalidateQueries` で無効化 |
