## §1 画面概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 画面名 | 注文一覧 |
| 目的 | 受注担当者が注文を検索・絞り込みし、詳細確認やCSV出力につなげる |
| ルート | /orders |
| 遷移元 | なし（起点画面） |
| 遷移先 | 注文詳細（行クリック時） |

### 1.2 業務上の位置づけ

受注業務フローの起点となる画面であり、受注担当者は本画面から日々の注文状況を把握し、個別の詳細確認や経理向けのCSV出力へ進む。

**この節の位置づけ: 仕様**

| モード | 切替条件 | UI の変化 |

| ロール | CSV出力ボタン | 検索フォーム |

| 経理担当者 | 表示 | 表示 |
| 受注担当者 | 非表示 | 表示 |

### 5.1 URL パラメータ

| パラメータ名 | 型 | 必須 | 用途 |

| status | 文字列 | △ | ステータス絞り込み条件を URL 経由で復元する |

| dateTo | 文字列（日付） | △ | 注文期間の終了日を URL 経由で復元する |

### 5.2 セッション・ストレージ参照

| キー名 | 種別 | 用途 |
|---|---|---|
| order-list-last-search | session | 直前の検索条件を一覧再訪時に復元する |

### 5.3 メイン画面の状態変数

| 変数名 | 型 | 初期値 | 役割 |
|---|---|---|---|
| searchKeyword | 文字列 | 空文字 | 受注番号・顧客名の検索キーワードを保持する |
| statusFilter | 文字列 | 空文字（全件） | 絞り込み対象のステータス区分を保持する |
| orders | 注文レコードの配列 | 空配列 | 検索結果の注文一覧を保持する |
| isLoading | 真偽値 | 偽 | 検索実行中かどうかを保持する |
| currentPage | 数値 | 1 | 表示中のページ番号を保持する |

### 5.4 サブコンポーネントの状態変数

| コンポーネント | 変数名 | 型 | 役割 |
|---|---|---|---|
| OrderSearchForm | dateRange | 開始日・終了日を持つ組 | 期間絞り込みの入力値を保持する |

### 5.5 派生値（計算値）

| 派生値名 | 算出ロジック概要 | 依存する状態変数 |
|---|---|---|
| totalCount | orders の件数を集計する | orders |
| hasCancelledRow | orders の中にキャンセル状態が含まれるか判定する | orders |

### 5.7 共有ストア参照

| ストア / コンテキスト | 参照キー | 用途 |
|---|---|---|
| AuthContext | userRole | 経理権限の有無を判定しCSV出力ボタンの表示可否を決める |

### 5.8 検索条件更新関数

updateSearchCondition(条件差分) — 引数に渡した項目のみ現在の検索条件へマージし、ページ番号を1に戻したうえで再検索を行う。

### 5.9 初期値・デフォルト値一覧

| 変数名 | 初期値 | 参照先 |
|---|---|---|
| currentPage | 1 | 一覧は常に1ページ目から開始する業務要件のため |
| statusFilter | 空文字（全件） | 初期表示では全ステータスを対象とする業務要件のため |

## §6 データフロー

**この節の位置づけ: 現行実装。本節は現在の実装の作りをそのまま記録した節です。作り直す前に、この節に書いた作りをどう扱うかを決める必要がある**

### 6.1 初期表示シーケンス

1. URL パラメータ取得
2. ストア初期化（AuthContext から利用者権限を取得）
3. API 呼び出し（§9 参照）
4. データ変換（§6.5 参照）
5. 画面状態を ready に更新

#### 6.1.1 起動時初期化（URL パラメータ → ストア書き戻し）

status・dateFrom・dateTo の各 URL パラメータを searchKeyword 以外の検索条件ストアへ書き戻す。

### 6.2 依存連鎖

statusFilter が変化すると orders の再取得が発生する。

### 6.3 ユーザー操作確定時の処理フロー

1. バリデーション（§14 参照）
2. 確認ダイアログ表示（確認を要する操作がないため不要）
3. API 呼び出し
4. 成功時: 一覧を更新
5. 失敗時: エラー表示（§14 参照）

### 6.4 データ更新トリガーの分類

| トリガー | 種別 | 処理概要 |
|---|---|---|
| 検索実行ボタン押下 | ユーザー操作 | 現在の検索条件で注文一覧を再取得する |
| CSV出力ボタン押下 | ユーザー操作 | 現在の検索条件でCSV生成APIを呼び出す |

### 6.5 データ変換（API レスポンス → 画面表示用データ）

| 変換名 | 入力型 | 出力型 | 変換概要 |
|---|---|---|---|
| formatOrderRow | 注文APIレスポンス | 一覧表示用の注文行 | 金額を3桁区切り文字列へ、ステータスコードを表示ラベルへ変換する |

### 6.6 画面状態の遷移

| 状態 | 遷移条件 | UI の表示 |
|---|---|---|
| loading | 初期表示・再取得中 | ローディング表示 |
| empty | データ 0 件 | 空状態メッセージ |
| error | API エラー | エラーメッセージ（§14 参照） |
| ready | データ取得成功 | メインコンテンツ |

## §7 ロジック

**この節の位置づけ: 仕様**

### 7.1 分岐

| キー | 条件 | 真の場合 | 偽の場合 |
|---|---|---|---|
| CSV出力ボタン活性化分岐 | 利用者が経理権限を持ち検索結果が1件以上か（§4.1・§4.4・§5.5 totalCount） | CSV出力ボタンを活性化する | CSV出力ボタンを非表示にする |
| 期間範囲妥当性分岐 | 開始日が終了日より後になっていないか（§14.1） | 検索を実行する | 期間指定不正エラーを表示する（§14.2） |
| 行表示分岐 | 対象注文のステータスがキャンセルか（§5.5 hasCancelledRow・§12.2.5） | muted-row パターンで表示する | 通常の行表示にする |

### 7.2 繰り返し

| キー | 対象 | 継続条件 | 打ち切りの条件 |
|---|---|---|---|
| 一覧行描画 | 検索結果 orders（§5.3）の各要素 | 1ページあたりの表示件数（DEFAULT_PAGE_SIZE、§13.1）に達するまで、または要素が残っている間 | 表示上限（20件、§16.1）に達したとき、または要素をすべて描画し終えたとき |
| ステータス絞り込み選択肢描画 | ORDER_STATUS_OPTIONS（§13.2）の各選択肢 | 選択肢が残っている間 | 選択肢をすべて描画し終えたとき |

### 7.3 判定表

| キー | 入力の組み合わせ | 結果 |
|---|---|---|
| 検索結果表示判定 | 画面状態＝empty | 空状態メッセージ表示 |
| 検索結果表示判定 | 画面状態＝ready かつ orders 件数＞0 | 一覧テーブル表示 |
| CSV出力可否判定 | 利用者権限＝経理担当者 かつ totalCount ≧ 1 | CSV出力ボタン活性化 |
| CSV出力可否判定 | 利用者権限＝受注担当者 | CSV出力ボタン非表示 |

## §8 疑似コード

**この節の位置づけ: 現行実装。本節は現在の実装の作りをそのまま記録した節です。作り直す前に、この節に書いた作りをどう扱うかを決める必要がある**

検索実行ボタンを押したとき、入力された検索条件で検索条件更新関数を呼び出す。呼び出し後、ページ番号を1に戻して注文検索APIを呼び出す。取得に成功した場合は一覧を更新する。失敗した場合はエラーを表示する。

CSV出力ボタンを押したとき、現在の検索条件で注文CSV出力APIを呼び出す。利用者が経理権限を持たない場合はこの操作自体を提示しない。

一覧の行をクリックしたとき、選択した注文の受注番号を伴って注文詳細画面へ遷移する。
