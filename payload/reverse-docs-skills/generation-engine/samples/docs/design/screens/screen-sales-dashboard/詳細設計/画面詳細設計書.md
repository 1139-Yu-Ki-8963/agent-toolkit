# 売上ダッシュボード 画面詳細設計書

## §1 画面概要

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 画面名 | 売上ダッシュボード |
| 目的 | 指定期間の売上実績を集計・可視化する |
| ルート | /dashboard/sales |
| 遷移元 | 管理メニュー |
| 遷移先 | 注文一覧（カテゴリ別内訳のドリルダウン操作時） |

### 1.2 業務上の位置づけ

経営層・店舗運営担当者が日々の売上状況を確認し、期間別・カテゴリ別の傾向を把握するための起点画面です。

---

## §2 機能一覧

### 2.1 機能一覧表

| キー | 機能名 | 概要 | 優先度 |
|---|---|---|---|
| 期間-指定集計 | 期間指定集計 | 開始日・終了日・集計単位を指定して売上を集計する | 必須 |
| 集計-手動再実行 | 手動再集計 | 直近の注文データを反映して集計結果を再取得する | 必須 |
| カテゴリ別-内訳表示 | カテゴリ別売上内訳表示 | 商品カテゴリごとの売上構成比をグラフで表示する | 必須 |

### 2.2 機能間の関係

期間指定集計の完了後にのみ手動再集計ボタンが活性化する。期間未指定の状態では再集計を実行できません。

## §5 状態管理

> 非該当項目: §5.2 セッション・ストレージ（画面固有の永続化なし）; §5.6 画面専用ストア（画面固有の永続化なし）; §5.7 共有ストア（他画面と共有するストア参照は使用しない）

### 5.1 URL パラメータ
| パラメータ名 | 型 | 必須 | 用途 |
|---|---|---|---|
| from | string | ○ | 集計対象期間の開始日を示す |
| to | string | ○ | 集計対象期間の終了日を示す |
| granularity | string | △ | 推移グラフの集計単位（daily/weekly/monthly）を示します。省略時はdaily |

### 5.3 メイン画面の状態変数

| 変数名 | 型 | 初期値 | 役割 |
|---|---|---|---|
| periodRange | object | URLパラメータのfrom/toから初期化 | 集計対象期間の開始日・終了日を保持する |
| granularity | string | "daily" | 推移グラフの集計単位を保持する |
| isRecalculating | boolean | false | 再集計処理の実行中状態を保持する |
| summaryData | object または null | null | 集計結果（合計売上・注文件数・平均客単価）を保持する |

### 5.4 サブコンポーネントの状態変数

| コンポーネント | 変数名 | 型 | 役割 |
|---|---|---|---|
| CategoryBreakdownTable | sortColumn | string | カテゴリ内訳テーブルの並び替え対象列を保持する |

### 5.5 派生値（計算値）

| 派生値名 | 算出ロジック概要 | 依存する状態変数 |
|---|---|---|
| averageOrderValue | 合計売上金額を注文件数で除算して算出する | summaryData |
| isPeriodValid | 開始日が終了日より前であるかを判定する | periodRange |

### 5.8 検索条件更新関数

updatePeriodRange(from, to) — 期間適用ボタン押下時に呼び出され、periodRangeとURLパラメータの両方を更新する。

### 5.9 初期値・デフォルト値一覧

| 変数名 | 初期値 | 参照先 |
|---|---|---|
| granularity | daily | 直近の動向を最も細かい粒度で把握できるようにするため |
| isRecalculating | false | 画面表示直後は再集計操作が発生していないため |

## §6 データフロー

### 6.1 初期表示シーケンス

1. URL パラメータ（期間・集計単位）取得
2. periodRange・granularityの状態を初期化
3. 売上集計取得APIを呼び出す（§9参照）
4. 集計結果を画面表示用データへ変換（§6.5参照）
5. 画面状態をreadyに更新

#### 6.1.1 起動時初期化（URL パラメータ → ストア書き戻し）

URLパラメータのfrom/to/granularityを、periodRange状態変数とgranularity状態変数へそのまま書き戻す。

### 6.2 依存連鎖

periodRangeまたはgranularityの変化は、売上集計取得APIの再呼び出しを連鎖的に引き起こす。

### 6.3 ユーザー操作確定時の処理フロー

1. バリデーション（§14参照）
2. 確認ダイアログ表示（確認を要する操作がないため不要）
3. 売上集計取得APIまたは手動再集計APIを呼び出す
4. 成功時: サマリ・グラフ・内訳の表示を更新
5. 失敗時: エラー表示（§14参照）

### 6.4 データ更新トリガーの分類

| トリガー | 種別 | 処理概要 |
|---|---|---|
| 期間適用ボタン押下 | ユーザー操作 | 新しい期間で売上集計取得APIを呼び出す |
| 再集計ボタン押下 | ユーザー操作 | 手動再集計APIを呼び出し最新の集計結果を取得する |

### 6.5 データ変換（API レスポンス → 画面表示用データ）

| 変換名 | 入力型 | 出力型 | 変換概要 |
|---|---|---|---|
| toSalesSummaryView | SalesSummaryResponse | SalesSummaryView | APIレスポンスの集計値を表示用のサマリ・グラフ・内訳データへマッピングする |

### 6.6 画面状態の遷移

| 状態 | 遷移条件 | UI の表示 |
|---|---|---|
| loading | 初期表示・再取得中 | ローディング表示 |
| empty | データ0件 | 空状態メッセージ（対象期間に売上データがない旨） |
| error | APIエラー | エラーメッセージ（§14参照） |
| ready | データ取得成功 | メインコンテンツ（サマリ・グラフ・内訳） |

## §7 ロジック

### 7.1 分岐

| キー | 条件 | 真の場合 | 偽の場合 |
|---|---|---|---|
| 期間妥当性分岐 | 開始日が終了日より前か（§4.2・§5.5 isPeriodValid） | 期間適用ボタンを活性化し売上集計取得APIを呼び出す | 期間適用ボタンを無効化し即座にエラー表示する（§14.2） |
| 再集計ボタン活性化分岐 | 期間指定が完了し再集計処理が実行中でないか（§3.7） | 再集計ボタンを活性化する | 再集計ボタンを非活性のままにする |
| 推移データ点上限分岐 | 集計単位が monthly か（§12.1.5・§16.1） | 表示するデータ点を最大12点に絞り込む | 集計単位に応じたデータ点をそのまま表示する |

### 7.2 繰り返し

| キー | 対象 | 継続条件 | 打ち切りの条件 |
|---|---|---|---|
| 売上推移グラフ描画 | trend（§9.2 レスポンス）の各データ点 | 集計単位が monthly の場合は最大12点に達するまで、または要素が残っている間 | 上限（12件、§16.1）に達したとき、または全データ点を描画し終えたとき |
| カテゴリ別内訳描画 | categoryBreakdown（§9.2 レスポンス）の各要素 | 要素が残っている間 | 要素をすべて描画し終えたとき（§13.3 の表示形式に従う） |

### 7.3 判定表

| キー | 入力の組み合わせ | 結果 |
|---|---|---|
| 期間適用可否判定 | 開始日 ＜ 終了日 | 期間適用ボタン活性化・売上集計取得API呼び出し |
| 期間適用可否判定 | 開始日 ≧ 終了日 | 期間適用ボタン無効化・エラー表示 |
| 再集計可否判定 | 期間指定完了 かつ 再集計処理未実行中 | 再集計ボタン活性化 |
| グラフ表示判定 | 集計単位＝monthly かつ データ点＞12件 | 直近12か月分に絞り込み表示 |

## §8 疑似コード

期間適用ボタンを押したとき、開始日が終了日より前かを確認する。妥当であれば期間の状態を更新し売上集計取得APIを呼び出す。妥当でなければ期間適用ボタンを無効化しエラーを表示する。

再集計ボタンを押したとき、手動再集計APIを呼び出す。呼び出しに成功した場合はサマリ・グラフ・内訳の表示を更新する。失敗した場合はエラーを表示する。

集計単位選択欄を変更したとき、集計単位の状態を更新し推移グラフを再描画する。集計単位が月次の場合は表示するデータ点を最大12点に絞り込む。
