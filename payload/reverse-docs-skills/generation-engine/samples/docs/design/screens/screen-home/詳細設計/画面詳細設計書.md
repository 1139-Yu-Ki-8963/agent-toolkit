# ホーム画面 画面詳細設計書

## §1 画面概要

> 区分: 仕様

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 画面名 | ホーム画面 |
| 目的 | ログイン後の利用者に業務全体の状況を提示し、各業務画面への入り口を提供する |
| ルート | / |
| 遷移元 | ログイン画面 |
| 遷移先 | サイドメニューで選択した各業務画面 |

### 1.2 業務上の位置づけ

ダッシュボードとしてログイン直後に必ず経由する画面であり、利用者は本画面から通知の確認や各業務画面への遷移を行う。

---

## §2 機能一覧

> 区分: 仕様

### 2.1 機能一覧表

| キー | 機能名 | 概要 | 優先度 |
|---|---|---|---|
| 表示-ダッシュボード集計 | ダッシュボード集計表示 | ログインユーザーに関連する業務集計値をカード形式で表示する | 必須 |
| ナビゲーション-サイドメニュー | サイドメニュー遷移 | サイドナビの項目クリックで各業務画面へ遷移する | 必須 |
| 通知-確認 | 通知確認 | 通知パネルを開き未読通知を一覧表示し既読にする | 必須 |

### 2.2 機能間の関係

通知確認によって既読化された件数は、サイドメニューに付随する通知バッジの表示件数に即時反映される。

## §3 画面構造

> 区分: 仕様

> 非該当項目: §3.4 メニューバー設定（サイドナビ形式のため専用メニューバーを持たない）; §3.5 設定オブジェクト構造（設定オブジェクトを持たない画面のため）

### 画面キャプチャ

> 元コードの画面キャプチャーは、このサンプルには含まれません。

### 部品構成（コンポーネント構造）

```
┌─ HomePage ──────────────────────────┐
│ ┌─ TopHeader ─────────────────────┐ │
│ │ UserMenu / NotificationBell     │ │
│ └──────────────────────────────────┘ │
│ ┌─ SideNav ─────┐ ┌─ MainArea ────┐ │
│ │ NavMenuItem    │ │ SummaryCard   │ │
│ └────────────────┘ └───────────────┘ │
└────────────────────────────────────────┘
```

### 3.1 コンポーネント配置

```
HomePage
├─ TopHeader
│   ├─ UserMenu
│   └─ NotificationBell
├─ SideNav
│   └─ NavMenuItem（繰り返し）
└─ MainArea
    └─ SummaryCard（繰り返し）
```

### 3.2 DOM 配置順序

1. TopHeader — 利用者情報と通知の表示
2. SideNav — 各業務画面への遷移メニュー
3. MainArea — ダッシュボード集計カードの表示

### 3.3 レイアウト制約

|---|---|
| レイアウト方式 | Flex（横並び：サイドナビ＋メインエリア） |
| 最小幅 | 960px |
| 最大幅 | 1440px |

### 3.6 スタイル適用パターン

| 領域 | 適用パターン | 参照先 |
|---|---|---|
| NavMenuItem（非活性項目） | disabled-nav-item | `DESIGN.md > colors.disabledNav` |
| NotificationBell（未読バッジ） | badge-count | `DESIGN.md > colors.badgeCount` |

### 3.7 ボタン一覧

| ボタン名 | 種別 | 位置 | 活性条件 |
|---|---|---|---|
| 通知ベル | 補助 | TopHeader 内 | 常時 |
| サイドメニュー項目 | 主要 | SideNav 内 | 対応する権限を利用者が持つとき |

## §4 業務ルール（条件付き：業務モード・権限制御がある画面のみ）

> 区分: 仕様

### 4.1 業務モードと切替条件

| モード | 切替条件 | UI の変化 |
|---|---|---|
| 通常表示 | 既定 | 権限に応じたメニュー項目のみ表示 |
| 管理者表示 | 利用者が管理者権限を持つ場合 | 管理系メニュー項目を追加表示 |

### 4.2 業務判断ポイント

利用者の権限区分（一般・管理者）によってサイドメニューに表示する項目が分岐する。

### 4.3 業務フロー内の前後画面との関係

ログイン画面から遷移してくる起点画面であり、以降のあらゆる業務画面への分岐点となる。

### 4.4 権限別の UI 制御

| ロール | 管理系メニュー | 通常業務メニュー |
|---|---|---|
| 管理者 | 表示 | 表示 |
| 一般利用者 | 非表示 | 表示 |

### 5.9 初期値・デフォルト値一覧

| 変数名 | 初期値 | 参照先 |

## §6 データフロー

> 区分: 今の作り（作り直す際: 決めておく）

### 6.1 初期表示シーケンス

1. ストア初期化（AuthContext から利用者権限・利用者名を取得）
2. API 呼び出し（§9 参照）
3. データ変換（§6.5 参照）
4. 画面状態を ready に更新

#### 6.1.1 起動時初期化（AuthContext → メニュー表示）

AuthContext から取得した userRole を用いて表示するサイドメニュー項目を決定する。

### 6.2 依存連鎖

unreadCount が変化すると NotificationBell のバッジ表示が更新される。

### 6.3 ユーザー操作確定時の処理フロー

1. バリデーション（入力項目がないため不要）
2. 確認ダイアログ表示（確認を要する操作がないため不要）
3. API 呼び出し
4. 成功時: 通知一覧・未読件数を更新
5. 失敗時: エラー表示（§14 参照）

### 6.4 データ更新トリガーの分類

| トリガー | 種別 | 処理概要 |
|---|---|---|
| 通知ベルクリック | ユーザー操作 | 通知一覧APIを呼び出し通知パネルを開く |
| 通知項目クリック | ユーザー操作 | 該当通知を既読化しunreadCountを更新する |

### 6.5 データ変換（API レスポンス → 画面表示用データ）

| 変換名 | 入力型 | 出力型 | 変換概要 |
|---|---|---|---|
| formatSummaryCard | ダッシュボード集計APIレスポンス | カード表示用データ | 集計値をラベル付きカード表示用の構造へ変換する |

### 6.6 画面状態の遷移

| 状態 | 遷移条件 | UI の表示 |
|---|---|---|
| loading | 初期表示中 | ローディング表示 |
| error | API エラー | エラーメッセージ（§14 参照） |
| ready | データ取得成功 | メインコンテンツ |

## §7 ロジック

> 区分: 仕様

### 7.1 分岐

| キー | 条件 | 真の場合 | 偽の場合 |
|---|---|---|---|
| 通知バッジ表示分岐 | unreadCount が1以上か（§5.5 hasUnread） | 通知ベルにバッジを表示する | バッジを表示しない |
| 管理系メニュー表示分岐 | 利用者権限が管理者か（§4.1・§5.5 visibleMenuItems） | 管理系メニュー項目を追加表示する | 通常のメニュー項目のみ表示する |
| 画面表示分岐 | 画面状態が error か（§6.6） | エラーメッセージを表示する（§14 参照） | 通常のダッシュボードコンテンツを表示する |

### 7.2 繰り返し

| キー | 対象 | 継続条件 | 打ち切りの条件 |
|---|---|---|---|
| サイドメニュー項目描画 | visibleMenuItems（§5.5）の各項目 | 絞り込み後の項目が残っている間 | 項目をすべて描画し終えたとき |
| 集計カード描画 | summaryCards（§5.3）の各要素 | カードが残っている間 | カードをすべて描画し終えたとき |
| 通知一覧描画 | notifications（§5.4）の各要素 | 通知パネルが開いており通知が残っている間 | 表示上限件数（MAX_NOTIFICATION_DISPLAY、§13.1）に達したとき |

### 7.3 判定表

| キー | 入力の組み合わせ | 結果 |
|---|---|---|
| 画面表示判定 | 画面状態＝loading | ローディング表示 |
| 画面表示判定 | 画面状態＝error | エラーメッセージ表示（§14 参照） |
| 画面表示判定 | 画面状態＝ready | メインコンテンツ表示 |
| メニュー表示判定 | 利用者権限＝管理者 | 管理系メニュー項目を含めて表示 |
| メニュー表示判定 | 利用者権限＝一般利用者 | 通常メニュー項目のみ表示 |

## §8 疑似コード

> 区分: 今の作り（作り直す際: 決めておく）

通知ベルをクリックしたとき、通知一覧APIを呼び出す。取得に成功した場合は未読件数を更新し通知パネルを開く。取得に失敗した場合はエラーメッセージを表示する。

通知項目をクリックしたとき、選択した通知を既読化する。既読化に成功した場合は未読件数を1減らす。

サイドメニュー項目をクリックしたとき、利用者が対応する権限を持つ場合は対象の業務画面へ遷移する。権限を持たない場合、その項目自体を表示しない。

## §12 領域別仕様

> 区分: 仕様

### 12.1 サイドナビエリア（SideNav）

#### 12.1.1 概要

各業務画面への遷移メニューを表示する領域。利用者権限に応じて表示項目が絞り込まれる。

#### 12.1.2 配置

TopHeader の下、MainArea の左側に配置される。

#### 12.1.3 項目定義

| 項目名 | 型 | 必須 | 書式 | 状態別編集可否 |
|---|---|---|---|---|
| メニュー項目名 | 文字列 | ○ | 日本語ラベル | ready: 可（クリック可） / loading: 不可 |

#### 12.1.4 イベント・挙動

| イベント | 挙動 |
|---|---|
| onMenuItemClick | 対象画面へ遷移する |

#### 12.1.5 領域固有の制約

権限を持たない項目は非表示とし、グレー表示での提示は行わない。

### 12.2 通知パネル（NotificationBell）

#### 12.2.1 概要

未読通知を含む通知一覧を表示し、クリックで既読化する領域。

#### 12.2.2 配置

TopHeader 内、利用者メニューの隣に配置される。

#### 12.2.3 項目定義

| 項目名 | 型 | 必須 | 書式 | 状態別編集可否 |
|---|---|---|---|---|
| 未読件数 | 数値 | ○ | バッジ表示 | ready: 不可 / loading: 不可 |

#### 12.2.4 イベント・挙動

| イベント | 挙動 |
|---|---|
| onNotificationClick | 通知を既読化する |

#### 12.2.5 領域固有の制約

未読件数が0件の場合はバッジ自体を表示しない。
