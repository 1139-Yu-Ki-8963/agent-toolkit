# 会員編集 画面詳細設計書

## §1 画面概要

> 区分: 仕様

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 画面名 | 会員編集 |
| 目的 | 会員の登録情報を修正し、会員状態（有効・休会・退会）を切り替える |
| ルート | /members/:id/edit |
| 遷移元 | 会員一覧 |
| 遷移先 | 会員詳細（保存操作完了時）、会員一覧（削除完了時または戻る操作時） |

### 1.2 業務上の位置づけ

会員管理業務における会員情報の維持・更新工程の中核画面であり、会員からの申告内容の反映と会員状態の切り替えを一元的に担う。

---

## §2 機能一覧

> 区分: 仕様

### 2.1 機能一覧表

| キー | 機能名 | 概要 | 優先度 |
|---|---|---|---|
| 会員情報-編集保存 | 会員情報編集 | 氏名・連絡先・住所・会員区分を編集して保存する | 必須 |
| 会員状態-変更 | 会員状態変更 | 会員状態を有効・休会・退会の間で切り替える | 必須 |
| 会員-削除退会 | 会員削除 | 退会確定済みの会員情報を削除する | 必須 |
| 編集内容-下書き保持 | 編集内容の自動下書き保持 | 保存前の入力内容をブラウザに保持し、再訪時に復元する | 任意 |

### 2.2 機能間の関係

会員削除は会員状態が退会である場合にのみ活性化する。会員状態変更（退会への変更）が先行条件となる直列の依存関係を持ちます。

## §4 業務ルール（条件付き：業務モード・権限制御がある画面のみ）

> 区分: 仕様

### 4.1 業務モードと切替条件

| モード | 切替条件 | UI の変化 |
|---|---|---|
| 通常編集モード | 会員状態が有効または休会 | 全入力欄が編集可能 |
| 退会済み閲覧モード | 会員状態が退会 | 連絡先入力欄が読み取り専用になり、削除ボタンが活性化する |

### 4.2 業務判断ポイント

会員状態を退会へ変更する操作は、出荷待ち注文の有無によって確認ダイアログの文言が分岐する。出荷待ち注文がある場合は注文キャンセルを促す警告を追加表示する。

### 4.3 業務フロー内の前後画面との関係

会員一覧から選択された会員番号を受け取り、保存完了後は更新済みの会員情報を伴って会員詳細へ引き継ぐ。

### 4.4 権限別の UI 制御

| ロール | 保存 | 削除 |
|---|---|---|
| 会員管理担当者 | 表示 | 非表示 |
| 会員管理責任者 | 表示 | 表示 |

## §6 データフロー

> 区分: 今の作り（作り直す際: 決めておく）

> 非該当項目: §6.1.1 URL 状態同期（会員番号は取得APIの引数としてのみ使用する）; §6.2 依存連鎖（独立したデータ取得のみ）

### 6.1 初期表示シーケンス

1. URL パラメータ（会員番号）取得
2. ローカルストレージの下書き有無を確認
3. 会員情報取得APIを呼び出す（§9参照）
4. 取得結果を編集フォーム用データへ変換（§6.5参照）
5. 画面状態をreadyに更新

### 6.3 ユーザー操作確定時の処理フロー

1. バリデーション（§14参照）
2. 確認ダイアログ表示（会員状態を退会に変更する場合、または削除操作の場合）
3. 保存APIまたは削除APIを呼び出す
4. 成功時: 会員詳細または会員一覧へ遷移
5. 失敗時: エラー表示（§14参照）

### 6.4 データ更新トリガーの分類

| トリガー | 種別 | 処理概要 |
|---|---|---|
| 保存ボタン押下 | ユーザー操作 | 入力内容を会員更新APIへ送信する |
| 削除ボタン押下 | ユーザー操作 | 会員削除APIを呼び出す |
| 下書き自動保存 | 自動 | 入力欄の変更を検知しローカルストレージへ書き込む |

### 6.5 データ変換（API レスポンス → 画面表示用データ）

| 変換名 | 入力型 | 出力型 | 変換概要 |
|---|---|---|---|
| toMemberFormValues | MemberResponse | MemberFormValues | APIレスポンスの会員情報を編集フォーム用の項目値へマッピングする |

### 6.6 画面状態の遷移

| 状態 | 遷移条件 | UI の表示 |
|---|---|---|
| loading | 初期表示・再取得中 | ローディング表示 |
| empty | データ0件 | 空状態メッセージ（該当会員が存在しない旨） |
| error | APIエラー | エラーメッセージ（§14参照） |
| ready | データ取得成功 | メインコンテンツ（編集フォーム） |

## §7 ロジック

> 区分: 仕様

### 7.1 分岐

| キー | 条件 | 真の場合 | 偽の場合 |
|---|---|---|---|
| 削除ボタン活性化分岐 | 会員状態が退会かつ出荷待ち注文が0件か（§5.5 isDeleteEnabled） | 削除ボタンを活性化する | 削除ボタンを非活性のままにする |
| 保存ボタン活性化分岐 | 必須項目が入力済みかつバリデーションエラーが0件か（§5.5 isSaveEnabled） | 保存ボタンを活性化する | 保存ボタンを非活性のままにする |
| 会員状態変更確認分岐 | 会員状態を退会へ変更する操作か（§4.2・§6.3） | 出荷待ち注文の有無に応じた確認ダイアログを表示する | 確認ダイアログを表示せず通常の保存を行う |

### 7.2 繰り返し

| キー | 対象 | 継続条件 | 打ち切りの条件 |
|---|---|---|---|
| 連絡先入力欄の検証 | 連絡先情報入力欄（メールアドレス・電話番号・住所、§12.1.3）の各項目 | 項目が残っている間 | 全項目のチェックが終わったとき（§14.1） |
| 会員区分・状態選択肢の描画 | MEMBER_TYPE_OPTIONS / MEMBER_STATUS_OPTIONS（§13.2）の各選択肢 | 選択肢が残っている間 | 選択肢をすべて描画し終えたとき |

### 7.3 判定表

| キー | 入力の組み合わせ | 結果 |
|---|---|---|
| 削除可否判定 | 会員状態＝退会 かつ 出荷待ち注文＝0件 | 削除ボタン活性化 |
| 削除可否判定 | 会員状態＝退会 かつ 出荷待ち注文＞0件 | 削除ボタン非活性 |
| 編集モード判定 | 会員状態＝有効または休会 | 全入力欄編集可能（通常編集モード） |
| 編集モード判定 | 会員状態＝退会 | 連絡先入力欄が読み取り専用（退会済み閲覧モード） |

## §8 疑似コード

> 区分: 今の作り（作り直す際: 決めておく）

保存ボタンを押したとき、入力内容を検証する。検証に問題がなければ会員情報更新APIを呼び出す。呼び出しに成功した場合は会員詳細へ遷移する。失敗した場合はエラーを表示する。

削除ボタンを押したとき、削除確認ダイアログを表示する。ダイアログで承認された場合は会員削除APIを呼び出す。承認されなかった場合は削除操作を取り消す。

会員状態を退会へ変更する操作をしたとき、変更内容を一時保持する。確認ダイアログでの承認を得た場合は保存APIを呼び出す。承認前に取り消した場合は一時保持した値を破棄し元の状態に戻す。

| イベント | 発火要素 | 処理概要 |
|---|---|---|
| onSave | 保存ボタン | バリデーション後、会員情報更新APIを呼び出す |
| onDeleteRequest | 削除ボタン | 削除確認ダイアログを表示する |
| onFieldChange | 各入力欄 | 状態変数を更新し、下書き自動保存をトリガーする |

### 11.2 サブコンポーネントイベント

| コンポーネント | イベント | 処理概要 |
|---|---|---|
| DeleteConfirmDialog | onConfirm | 会員削除APIを呼び出す |
| DeleteConfirmDialog | onCancel | ダイアログを閉じ、削除操作を取り消す |

### 11.3 複数ステップ処理の詳細

会員状態を退会へ変更する操作は、(1) 状態変更の一時保持、(2) 確認ダイアログでの承認、(3) 保存APIの呼び出し、の3ステップを踏む。承認前にキャンセルした場合は一時保持した値を破棄し元の状態に戻す。

### 11.4 キーボード操作

| キー | 発火条件 | 挙動 |
|---|---|---|
| Tab | フォーカス可能要素 | 氏名 → 連絡先 → 会員区分 → 会員状態 → 保存 → 削除 → 戻る の順で移動する |
| Enter | 入力欄フォーカス時 | フォームを送信せず次項目へフォーカスを移す |
