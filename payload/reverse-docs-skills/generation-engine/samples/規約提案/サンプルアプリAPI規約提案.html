01

認証とエラー処理

認証トークンの渡し方とエラー応答の扱いを検討する章である。

認証トークンのヘッダー方式

提案あり
  • src/api/client.ts:42 でBearerトークンをAuthorizationヘッダーに設定している。
  • src/api/legacy-client.ts:18 でも同じ形式を使っている。

規約提案文(案)

認証トークンは常にAuthorizationヘッダーへ`Bearer <token>`形式で渡す。

出典: src/api/client.ts:42、src/api/legacy-client.ts:18

HTTPステータスコードとエラー種別の対応

提案あり
  • src/api/error-handler.ts:12 で400番台を業務エラー、500番台を通信基盤のエラーとして分岐している。
  • src/api/error-handler.ts:35 で404を「対象が存在しない」の意味に限定して使っている。

規約提案文(案)

400番台は業務エラー、500番台は通信基盤のエラーとして扱い、404は対象不存在の意味に限定する。

出典: src/api/error-handler.ts:12、src/api/error-handler.ts:35

エラー応答の形式

対象外

エラー応答の形式は共通基盤ライブラリが強制しており、個別アプリでの規約提案の対象にならない。

02

命名とページング

一覧系APIのページング方式とフィールド命名を検討する章である。

一覧のページング方式

提案あり
  • src/api/list-items.ts:30 で`cursor`と`limit`パラメータを受け取っている。
  • src/api/list-orders.ts:25 でも同じ`cursor`パラメータ名を使っている。

規約提案文(案)

一覧系APIのページングは`cursor`と`limit`のクエリパラメータで統一する。オフセット方式は使わない。

出典: src/api/list-items.ts:30、src/api/list-orders.ts:25

外部APIへのリクエストタイムアウト設定

提案あり
  • src/api/external-client.ts:20 で`timeout: 5000`を明示している。
  • src/api/payment-client.ts:15 でも同様に`timeout`を明示している。

規約提案文(案)

外部APIへのリクエストには必ずtimeoutを明示する。既定値に頼らない。

出典: src/api/external-client.ts:20、src/api/payment-client.ts:15

レスポンスフィールドの命名規則

→共通規約を参照

レスポンスフィールドのcamelCase命名は全社共通のコーディング規約が既に定めており、共通規約を参照する。
