# AI設定資産の管理規約

<!-- ツールが定める運用規約。本文入りで納品する。対象リポジトリ側での編集はずれ検知の対象になり、再納品で上書きされる。 -->

## 概要

スキル・規約・フックの作成と変更の手順、および配置先の取り決め。

`docs/` が定義であり、`.claude/` と `.cursor/` と `.codex/` はそこから生成される派生である。変更は必ず定義側から行う。

## 規則

| 規則 | 内容 | 根拠 |
|---|---|---|
| 定義は docs に置く | AI エージェントが読む規約・手順・用語の定義は `docs/` 配下にだけ置く。ツール別のフォルダに定義の実体を作らない | 同じ内容の 2 つ目の実体を作ると、片側だけが更新される穴が生まれる |
| 派生は生成物として扱う | `.claude/` と `.cursor/` と `.codex/` の内容は `docs/` から生成する。直接編集しない | 直接編集すると定義との対応が壊れ、次の生成で失われる |
| 変更は定義側から行う | 規約を直すときは `docs/` の該当ファイルを直し、適用の操作で各ツールの形式へ反映する | 反映の向きを一方向に固定することで、どちらが正しいかの判断が不要になる |
| ずれは台帳で検知する | 各派生物の内容ハッシュを台帳へ記録し、突合で手作業の編集を検知する。判定に更新時刻は使わない | 更新時刻は git の操作や別のツールでも動くため、変更の有無の判定に使えない |
| 本書は再納品で上書きされる | この文書はツール側が定める運用規約であり、対象リポジトリ側での編集はずれ検知の対象になる | 保守の仕組みが依拠する前提そのものであり、プロジェクトごとに変えられると仕組みが成立しない |

## この文書が空雛形でない理由

大半の規約は、現場の担当者が根拠を得てから記入する空雛形として納品する。本書は例外である。定義と派生の関係はツールの動作そのものが決めており、プロジェクトごとに変えられる余地がない。
