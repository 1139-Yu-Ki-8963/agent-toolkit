# AIエージェント行動規約 検査できない理由

最初に検討したのは、エージェントの実行ログから「判断と反映が分離されているか」を機械的に検出することだった。上位エージェントの発話と下位エージェントへの委任呼び出しの前後関係をログから抽出し、委任直前に方針決定を示すキーワードが出現するかを調べる案を試した。

この方法には壁があった。方針決定を示す発話は定型文で書かれるとは限らず、キーワード一致では「決めたつもりで書いていない発話」と「決めていないのに決めたと書いた発話」の両方を取り違える。委任先の選択が適切だったかという判断は、対象タスクの複雑さや過去の失敗履歴といった、ログ単体には現れない文脈に依存する。同じ発話パターンでも、タスクの性質が違えば適切さの評価が反転する。

そのため、この規約の遵守確認は機械検査に頼らず、人による事後レビューに委ねる。作業完了後に、委任履歴と成果物を突き合わせて、判断と反映が実際に分離されていたかを人が判定する。誤った委任の兆候（同じ担当への重複依頼、検証なしの報告転送）が繰り返し見つかった場合は、規約の記述自体を見直す。
