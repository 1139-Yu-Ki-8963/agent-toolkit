# 納品物フォルダ体系

## 担当の定義

各納品物の担当は `delivery-reverse-manifest.yml` に一意に登録する。テンプレートのみの納品物は `shared/templates/template-only/` に置き、値・例・架空ID・規範・推奨値を含めない。

本ファイルはリバース設計の納品物目録である。成果物と生成スキルの対応を管理する。

機械可読な定義は `delivery-folder-catalog.json` とする。
`deliverable` は同ファイルの`deliverable_source`が指すmanifest全出力を展開した集合である。
その他は
`control_artifacts`・`assets`・`evidence` に明示分類する。portalには
`deliverable` かつ `publish_status=implemented` の具体HTMLだけを掲載する。

画像からの文字起こし。リバース対象ユニットの成果物置き場（`<output_dir>` 配下）の全体構成と、各ファイルを生成するスキルの対応を示す。

実装状態・担当・停止条件は`delivery-reverse-manifest.yml`に定義する。根拠不足の納品物は空構造だけを出力する。

## 検証記録（verification/）

検証記録は納品物ではないため `docs/` の外に配置する。`docs/` と同階層の `verification/` フォルダに格納する。

```
verification/
└── screen-<画面ID>/
    ├── facts/
    │   └── <run_id>/
    │       ├── facts.yml
    │       ├── facts.lock
    │       └── recount-report.txt
    ├── 単体-<対象ファイルbasename>/
    │   └── <timestamp>/
    │       └── (単体検証記録)
    └── <timestamp>/
        ├── 修正指示書.md
        ├── 最終報告.md
        └── (テストログ・差分レポート等)
```

docs 内に検証記録は一切存在しない。facts・単体検証記録・修正指示書・最終報告・テストログはすべて verification/ 配下に配置する。
