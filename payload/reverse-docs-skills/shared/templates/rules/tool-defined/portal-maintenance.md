## 概要

ポータルと一覧の HTML を保守するときの取り決め。

これらの HTML は定義から生成される派生物である。人が直接編集する対象ではない。

## 規則

| 規則 | 内容 | 根拠 |
|---|---|---|
| HTML を直接編集しない | `project-portal/` 配下の HTML と一覧ページは生成物である。表示を見て気付いた誤りも HTML 側では直さない | 直接編集すると次の生成で失われ、直したはずの内容が消える |
| 直すときは定義を直す | 表示が誤っている場合、生成元の定義（設計書・マニフェスト・カタログ）を直してから再生成する | 表示は定義の写像であり、写像だけを直しても元は誤ったまま残る |
| ずれは台帳で検知する | 生成時に各 HTML の内容ハッシュを台帳へ記録し、突合で手作業の編集を検知する。判定に更新時刻は使わない | 更新時刻は git の操作や別のツールでも動くため、変更の有無の判定に使えない |
| 本書は再納品で上書きされる | この文書はツール側が定める運用規約であり、対象リポジトリ側での編集はずれ検知の対象になる | 保守の仕組みが依拠する前提そのものであり、プロジェクトごとに変えられると仕組みが成立しない |

## この文書が空雛形でない理由

大半の規約は、現場の担当者が根拠を得てから記入する空雛形として納品する。本書は例外である。ポータルが生成物であることはツールの動作そのものが決めており、プロジェクトごとに変えられる余地がない。
