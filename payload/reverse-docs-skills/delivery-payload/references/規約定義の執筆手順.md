# 規約定義の執筆手順

本ファイルは `docs/rules/<親>/<子>/rule.md` の「このプロジェクトの規則」の節へ、対象リポジトリの実態に即した規則を記入するときの手順を定める文書である。定義そのものの形式（front matter の鍵・節構成）は `規約定義と派生生成の設計.md` の「3. rule.md の形式」を参照する。

## 記入対象

記入の対象は次の 2 種類である。

- `delivery-payload/templates/rules/rule-template.md` から生成した雛形
- `scaffold-rule-definitions.sh` が生成した `status: draft` の rule.md

## 記入手順

1. `# <title>` の下に、この規約が扱う対象を対象リポジトリの実態に即して具体的に書く。
2. `## 概要` に、対象リポジトリの実態を調査してから規約の要約を記入する。
3. `## 規則` の表に、規則行を追加する。各規則行には、対象リポジトリの実装から観測した根拠を添える。実装に現れない規則を発明しない。
4. `enforcement` を `advisory` にした場合は `## 違反時の手順` を記入する。`none` のままにする場合は、この節ごと削除する。
5. `checkable` を `true` にした場合は `## 設計判断` 節を追加し、検査を機械化する必要性・代替案を採らなかった理由・保守責任者・廃棄条件の 4 項目を書く。`false` のままにする場合は、この節を置かない。
6. 記入が終わったら front matter の `status` を `draft` から `approved` に変え、`origin` を `manual` に変える。

## 関連

- `規約定義と派生生成の設計.md` — rule.md の形式（front matter の鍵・節構成）の定義
- `delivery-payload/templates/rules/rule-template.md` — 空雛形のテンプレート
- `generation-engine/scripts/rules/scaffold-rule-definitions.sh` — 雛形を機械生成するスクリプト
