# 章役割キー→§→節キーワードの対応表

章役割キー→§→節キーワードの対応表。本リポジトリの delivery-payload/references/ 配下で正本を持ち、rebuilding-screen-unit-from-docs / rebuilding-code-from-docs へ chapter_map_path として配布する。

## 章の役割キー → 節キーワード対応表（正本）

章の特定は設計書の前付け（frontmatter）の chapter_map（役割キー）で行う。`generation-engine/scripts/audit-consistency.sh` は chapter_map から役割キー→§番号を解決し、以下の節キーワードで二次解決する。本表が節キーワード対応の正本であり、SKILL.md・ng-classification.md・report-format.md・guide.html はここへのポインタとする。

| 役割キー | 節キーワード（既定 §） |

| 機能一覧 | 機能一覧表（既定 §2） |

| 状態管理 | メイン画面の状態変数（既定 §5.3）・サブコンポーネントの状態変数（既定 §5.4） |

## 機能設計書の章の役割キー → 節キーワード対応表

機能設計書（unit_kind=feature）は集約設計書であり、画面詳細設計書とは章構成が異なるため、対応表を分けて持つ。§番号は既定であり、設計書の前付けの chapter_map で解決する。役割キーは画面詳細設計書側の表と重複しないよう接頭辞を付け、ファイル全体で一意にしている。

| 役割キー | 節キーワード（既定 §） |

| 機能概要 | 基本情報（既定 §1.1） |
| 機能範囲 | 構成要素一覧（既定 §2.1）・参照テーブル一覧（既定 §2.2） |

| 業務ルール | 業務判断ポイント（既定 §4.1）・状態と遷移の制約（既定 §4.2） |
| 機能データ | 業務対象の定義（既定 §5.1）・構成要素とテーブルの対応（既定 §5.2） |
| 状態受け渡し | 受け渡しパラメータ（既定 §6.1） |
| 呼び出し仕様 | 機能内の呼び出し一覧（既定 §7.1） |

| 機能非機能要件 | 件数と量の制限（既定 §9.1） |

## API詳細設計書の章の役割キー → 節キーワード対応表

API詳細設計書（unit_kind=api）は 1 エンドポイント 1 枚の実装契約であり、画面詳細設計書とも機能設計書とも章構成が異なるため、対応表を分けて持つ。§番号は既定であり、設計書の前付けの chapter_map で解決する。役割キーは他の表と重複しないよう接頭辞を付け、ファイル全体で一意にしている。
