# 名前の付け方の決まり

## 概要

変数・関数・ファイル・ディレクトリの名前の付け方の取り決め。

名前は最も読まれる説明であり、読み手が中身を見る前に意味を取る唯一の手がかりである。表記の形式と、意味の付け方の両方を扱う。

## 規則

| 規則 | 内容 | 根拠 | 検査 |
|---|---|---|---|
| 不透明な省略を使わない | 読み手が展開できない省略を使わない。分野で定着した省略だけを許可の一覧で認める | 省略の展開は、書いた本人の頭の中にしかない | 静的解析: 識別子に許可の一覧へ無い短い省略が含まれていないかを走査する |
| 通し番号を識別子にしない | 連番だけの名前を付けない | 番号は並び順しか表さず、対象が何であるかを示さない | 静的解析: 識別子が数字だけの語尾で区別されていないかを走査する |
| 動くものは動詞から始める | 処理を行う関数と実行するファイルの名前を動詞から始め、値と設定は名詞にする | 名前の品詞から、呼ぶものか読むものかが判別できる | 静的解析: 関数の名前が動詞から始まっているかを走査する |
| 表記の形式を対象ごとに固定する | 変数・関数・型・定数・ファイル・ディレクトリのそれぞれで、大文字と小文字の使い分けを1つに固定する | 形式が混在すると、名前の形から対象の種類を読めなくなる | 静的解析: 識別子の表記が対象の種類ごとに単一の形式へ揃っているかを走査する |
| 名前から中身が読み取れるようにする | 名前だけを見た人が、それが何であるかを推し量れる名前を付ける。中身を表さない名前を使わない | 名前は最初に目に入るものであり、そこで中身が読み取れないと、必要なものへ辿り着けない | 判定不能: 名前が中身を表しているかは意味の判断を含み、書き込みの内容からは判定できない ／ レビュー: 名前だけを見て、その対象が持つ規則や役割を 1 つでも言い当てられるかを確認する |

## 違反時の手順

書き込みが止められた場合、連番だけで区別している識別子を、対象が何であるかを表す名前へ置き換える。基底名が偶然一致する無関係な技術用語の同居（utf8 と utf16 等）による誤検知だった場合は、そのまま書き込んで差し支えない。
