# コードの書き方と分割の決まり

## 概要

コードの書き方・分割の大きさ・整形の取り決め。

読む回数は書く回数より多いため、書きやすさより読みやすさを優先する。機械で矯正できる部分は整形の道具へ任せ、人の判断が要る部分だけを規約として書く。

## 規則

| 規則 | 内容 | 検査 |
|---|---|---|
| 整形は道具へ任せる | 字下げ・引用符・行の折り返しは整形の道具で矯正し、人の判断の対象から外す | 静的解析: 整形の設定ファイルが実在し、統合の検査に整形の確認が登録されているかを走査する |
| 関数を1つの責務に絞る | 1つの関数が複数の理由で変更される構造にしない。長くなった関数は分割する。既定の上限は50行とする | 静的解析: 50 行を超えていないかを走査する。値はこのプロジェクトの規則の表で上書きできる |
| 入れ子を深くしない | 条件の分岐と繰り返しの入れ子を浅く保ち、早期の脱出で平らにする。既定の上限は4段とする | 静的解析: 4 段を超えていないかを走査する。値はこのプロジェクトの規則の表で上書きできる |
| 型の検査を骨抜きにしない | 何でも受け付ける型と、型の指定の省略で検査を無効にしない | 静的解析: 何でも受け付ける型の使用箇所を走査する |
| 試したままのコードを残さない | 出力のための一時的な記述と、注釈で消した試行のコードを残さない | 静的解析: 出力のための一時的な呼び出しと、注釈で消したコードの塊を走査する |
| 数値と文字列に名前を付ける | 意味を持つ数値と文字列を直接書かず、名前の付いた定数にする | 静的解析: 意味を持つ数値の直接の記述を走査する |

## 違反時の手順

書き込みが止められた場合、`any` / `Any` の型注釈と `@ts-ignore` / `@ts-nocheck` / `# type: ignore` を、対象を表す具体的な型へ置き換える。型を今すぐ絞り込めないやむを得ない事情がある場合も、検査を無効化するのではなく、理由をコメントに残したうえで暫定の型を書く。
