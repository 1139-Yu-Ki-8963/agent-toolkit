# 進捗確認スクリプトの使い方

## この文書は何か

`docs/scripts/report-progress.sh` の使い方をまとめた文書である。

`docs/tasks/指摘改善一覧.md` の状態集計・codexの稼働状況・main統合状況・公開状態を、実行のたびに実測して出す道具である。

この文書はスクリプト自体の使い方を扱う。
いつ・どの頻度で報告を出すかという運用手順は `docs/session-prompts/定期報告フォーマット.md` を参照する。

## 正本

`docs/scripts/report-progress.sh`

対応する規約は `.claude/rules/always/tasks/issue-ledger-format/rule.md` である。
状態の語彙（未着手・対応中・完了・対象外・未確認）と、1見出しにつき状態行を1つに保つ原則を定める。

## なぜこのスクリプトが要るか

指摘の状態集計を `grep -c` のようなコマンドで直接数えると、1つの見出しに複数の状態行が残っている場合に二重に数えてしまう。

実際に2026-08-19、見出し87件に対して単純な `grep -c` が105件の状態行を検出し、見出し数と合わない集計をユーザーへ誤って報告する事故が起きた。

`report-progress.sh` は、各見出しについて次の見出しの直前に現れた最後の状態行だけを1件として数える。
同じ見出しの中に古い状態行が残っていても、二重には数えない。

## 3つの使い方

### 状態集計だけを出す

```bash
bash docs/scripts/report-progress.sh
```

`docs/tasks/指摘改善一覧.md` の状態集計だけを出す。
最も軽く、頻繁に呼んでも実行時間が短い。

出力例:

```
### 指摘の全体（見出し単位・重複なし）
総数: 97件
  完了: 77件
  未着手: 16件
  未確認: 2件
  対応中: 2件
```

### 全体像を出す

```bash
bash docs/scripts/report-progress.sh --full
```

状態集計に加えて、次の3つも一度に出す。

- codex作業者の稼働状況（worktreeごとの直近コミット・未コミット行数）
- 直近でmainへ統合したコミットの一覧
- agent-toolkitの公開状態（origin/mainとの一致有無）

出力例:

```
## 定期報告（11:34時点）

### 指摘の全体（見出し単位・重複なし）
総数: 97件
  完了: 77件
  未着手: 16件
  未確認: 2件
  対応中: 2件

### codex作業者（最大3件同時）
  improve-1-202: 55b001ca 【バグ修正】出力先誤指定を検知（1-202） / 未コミット行数=0

### 直近でmainへ統合した件
50ddf67f 【ドキュメント】1-202の実装状況と残課題を記帳（1-202）
659edcd5 【ドキュメント】完了扱いの誤りを再検証で訂正（1-54, 1-183, 1-196, 1-29, 1-31, 1-35, 1-41, 1-46）
f7088e79 【ドキュメント】新規の改善課題10件を一覧へ加える（1-229〜1-233, 1-234, 1-235, 1-237, 1-238, 1-239）

### 公開状態
  未公開または未確認: local=xxxxxxx / origin/main=yyyyyyy
```

このモードは `git fetch` や複数の `git log` を含むため、状態集計だけを出すモードより時間がかかる。

### スクリプト自身の検査

```bash
bash docs/scripts/report-progress.sh --self-test
```

集計ロジックが壊れていないかを検査する。
合成した見出しデータで、単純な集計・複数状態行の二重カウント防止・実リポジトリの見出し数と集計総数の一致の3点を確かめる。

`--self-test` は終了コードで結果を返す。
0なら全件成功、それ以外は失敗を含む。

```
実行 4 件 / 成功 4 件 / 失敗 0 件
```

台帳の状態値が規約の5つ（未着手・対応中・完了・対象外・未確認）以外を含む場合、`[INFO]` として一覧を出す。
この行は失敗として数えない。
規約外の値が見つかった場合、対応する見出しを開いて手作業で是正する。

## 判定できない場合の扱い

`--self-test` は `mktemp` で一時領域を使う。
サンドボックス制約などで一時領域へ書き込めない場合、`[UNKNOWN]` を出して終了コード2で終わる。

このときの終了コード2は「検査に失敗した」という意味ではなく、「検査そのものを実行できなかった」という意味である。
`dangerouslyDisableSandbox: true` を付けて再実行すると、通常どおり判定できる。

この扱いは `.claude/rules/always/verification/indeterminate-result/rule.md` の考え方に沿う。

## 定期報告フォーマット.md との役割分担

| 文書 | 扱う内容 |
|---|---|
| この文書 | `report-progress.sh` のコマンドライン引数・出力・終了コードの意味 |
