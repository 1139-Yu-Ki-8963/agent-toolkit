# 定期報告フォーマット

## この文書は何か

`docs/tasks/指摘改善一覧.md` の指摘をcodexで並行して解消しているあいだ、進行を管理する側（このセッション）がユーザーへ定期的に出す状態報告の型である。会話の記憶ではなく、実行のたびにコマンドで数え直した値だけを埋める。

## 使い方

`ScheduleWakeup` の発火や `task-notification` の到着で状態確認をする際、以下のテンプレートの空欄を「値の出し方」のコマンドで埋めて、そのままユーザーへ提示する。値を覚えている数字で埋めない。埋めるたびに実行し直す。

複数課題を同時にcodex execへ投入する前は .claude/rules/always/session/parallel-issue-dispatch/rule.md の規約1（投入前の重なり確認）に従うこと。

## テンプレート

```
## 定期報告（<HH:MM時点>）

### 指摘の全体（見出し単位・重複なし）
- 総数: <N>件
- 完了: <N>件
- 未着手: <N>件
- 対応中: <N>件
- 対象外: <N>件
- 未確認: <N>件

### codex作業者（最大3件同時）
| worktree | 課題キー | 状態 | 直近ログ更新 |
|---|---|---|---|
| <worktree名> | <1-NN> | 稼働中/停止/完了 | <mtime> |

### レビュー担当
- レビュー用worktree: <パス or なし>
- 直近レビュー結果: <あれば要約、無ければ「未実施」>

### 直近でmainへ統合した件
- <課題キー>（<コミットハッシュ>）

### 公開状態
- agent-toolkit origin/main: <最新同期コミット or 「未確認」>

### 次の一手
- <具体的な次のアクション1つ>
```

## 値の出し方

### 指摘の全体（総数・状態別件数）

```bash
bash docs/scripts/report-progress.sh --full
```

上記1コマンドで、指摘の状態集計・codex稼働状況・main統合状況・公開状態のすべてを一度に取得できる。集計ロジックの正本は `docs/scripts/report-progress.sh` であり、規約は `.claude/rules/always/tasks/issue-ledger-format/rule.md` を参照する。

### codex作業者の稼働状況

```bash
pgrep -f "codex exec" | wc -l   # 稼働中プロセス数（3件上限の遵守確認）
ps aux | grep "codex exec -C" | grep -v grep   # 対象worktreeの特定
```

各対象worktreeについて:

```bash
git -C <worktree> log -1 --oneline   # コミット済みなら完了の可能性
git -C <worktree> status --porcelain | wc -l   # 未コミット差分の有無
stat -f '%Sm' <ログファイル>   # ログの最終更新時刻（停止しているかの判定）
```

ログのmtimeが現在時刻から大きく離れている場合、停止（gh認証待ち等のプリフライト停止を含む）を疑い、`tail -80 <ログファイル>` で原因を確認する。

### レビュー担当の状況

```bash
git worktree list | grep review-batch1   # レビュー用worktreeの有無
git -C <レビューworktree> log -3 --oneline   # 直近のレビュー結果コミット
```

### 直近のmain統合

```bash
git -C /Users/MacPro/Projects/reverse-docs-skills log -5 --oneline
```

### 公開状態

```bash
cd ~/github-public/agent-toolkit
git fetch origin main
git rev-parse HEAD
git rev-parse origin/main
```

両者のハッシュが一致していれば公開済み。キャッシュに頼らず `git fetch` で都度確認する（過去に「公開したつもり」で実際は未pushだった実例があるため）。

## 報告の頻度についての注意

- `ScheduleWakeup` の `delaySeconds` は状態が変わりそうな間隔で設定する。設定した間隔より短い周期で確認を繰り返すことを禁止する
- リマインダー通知（ツール未使用の指摘等）は状態確認のトリガーにしない。トリガーは「実際のwakeup発火」「task-notification」「ユーザーからの新規メッセージ」の3つに限る
- 同じ値を確認するコマンドを同一ターン内で2回以上実行しない

## この形が向くとき

- codex execで複数件を並行実行しており、ユーザーへ進行の見える化が必要なとき
- 3件同時上限のような制約の遵守状況を都度示す必要があるとき

## この形が向かないとき

- 単発の修正で並行実行が無いとき（この場合は完了報告のみで足りる）
