# 宣言データ不在を値の不正と誤報する問題を直す指示書

**状態**: 着手できる
**優先度**: 高
**前提**: なし
**元の指摘**: なし

## この指示書は何か

規約の定義ファイル（`delivery-payload/references/rule-taxonomy.json`）が無い環境で、
`validate-rule-definitions.sh` が「値が不正」と報告していた。
不在は値の不正ではない。存在しないものの中身を判定することはできない。
存在確認を先に置き、不在のときは宣言の検査だけを飛ばすようにする。

## なぜ必要か

2026-08-23 22:42 のコミット `82ad38f` が、この定義ファイルへ
`crossCuttingChecks` の検査を追加した。この検査は存在確認を持たず、
ファイルが無い場合も `jq` の失敗を「必須項目または値域が不正」と報告していた。

その結果、第1層の機械検証で失敗が 0 本から 2 本へ増えた。

    朝    対象 180 本 / 成功 178 本 / 失敗 0 本 / 判定不能 2 本
    夜    対象 182 本 / 成功 177 本 / 失敗 2 本 / 判定不能 2 本

失敗した 2 本は次である。

    generation-engine/scripts/rules/build-derived-rules.sh --self-test
    generation-engine/scripts/rules/scaffold-rule-definitions.sh --self-test

いずれも、配備先へ配ったスクリプトを配備先の構成で実行する検査を持つ。
配備先は対象プロジェクトであり `delivery-payload/` を持たない。
配ったスクリプトは `<配備先>/docs/delivery-payload/references/rule-taxonomy.json`
を探すが、そこには何も無い。

放置すると、配る対象が納品先で必ず不合格を返す。
納品先の利用者は、自分の規約に問題があると読み違える。

## やること

1. `validate_checker_declarations` の冒頭へ、定義ファイルの存在確認を置く
2. 不在のときは `[UNKNOWN]` を出し、宣言の検査だけを飛ばして戻る
3. 他の検査（front matter の鍵・値域など）は続ける
4. 存在するときの振る舞いは変えない

## 完了の判定

1. `bash generation-engine/scripts/rules/scaffold-rule-definitions.sh --self-test` が終了コード 0 を返す
2. `bash generation-engine/scripts/rules/build-derived-rules.sh --self-test` が終了コード 0 を返す
3. `bash generation-engine/scripts/rules/validate-rule-definitions.sh` が終了コード 0 を返す
4. `bash generation-engine/scripts/rules/validate-rule-judgment-coverage.sh` が終了コード 0 を返す
5. 宣言を 1 件削ると終了コード 1 を返す（22:42 に足した検査が生きている）

## 触らない範囲

- `82ad38f` が足した `crossCuttingChecks` の検査そのもの。実在の問題を見つけるために足したものであり、消すと元の問題が戻る
- 定義ファイルが存在するときの判定
- `delivery-payload/references/rule-taxonomy.json` の中身

## 決めていないこと

| 何を決めたか | 選んだもの | 選んだ理由 | 覆すと何が変わるか |
