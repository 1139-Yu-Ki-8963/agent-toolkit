# セッションプロンプトを2つへまとめる指示書

## 1. この指示書は何か

`docs/session-prompts/` に6件・995行の文書が溜まっている。同じことが複数の文書に書かれており、どれを読めばよいかが決まっていない。作業者が読むものと、進行を管理する者が読むものの2つへまとめ直す。

## 2. なぜ必要か

現在の6件は次のとおりである。

| 文書 | 行数 | 誰が読むか |
|---|---|---|
| `PM引き継ぎの現状.md` | 183 | 管理者 |
| `定期報告フォーマット.md` | 109 | 管理者 |
| `指示書を完遂するループ.md` | 178 | 作業者 |
| `負荷を見ながらタスクを消化する.md` | 199 | 管理者 |
| `進捗を管理して割り振るPM.md` | 194 | 管理者 |
| `進捗確認スクリプトの使い方.md` | 132 | 両方 |

**管理者向けが4件に分かれており、内容が重なっている。**進め方・報告の型・引き継ぎ・負荷の見方が別々の文書に散っているため、新しく管理者になった者はどれから読めばよいか分からない。

読み手で分ける規約（`.claude/rules/always/docs/audience-split/rule.md`）は、外部向けと内部向けを分けることを定めている。この考え方を、内部の文書のうち「誰が読むか」の軸へ広げる。

## 3. やること

`docs/session-prompts/` を次の2件へまとめる。

    作業者のプロンプト.md    指示書を受け取って完遂する者が読む
    進行担当のプロンプト.md   作業を割り振り、取り込み、公開する者が読む

### 作業者のプロンプトへ入れるもの

- 指示書の読み方（冒頭4行・必須8節・完了の判定）
- 状態の語の使い分け（冒頭は2種類、記録の表は5種類）
- 実行していないのに「完了」と書かないこと
- コミット欄に実在するハッシュを書くこと
- 指示書を `done/` へ移さないこと
- 判断で止まらないこと（既定に従い、記録して次へ進む）
- コミットの作法（日本語の接頭辞・作者の指定・課題キーの記載）
- コミット前に実行する検査

出典は `指示書を完遂するループ.md` と、指示書形式規約（`.claude/rules/always/tasks/instruction-format/rule.md`）である。

### 進行担当のプロンプトへ入れるもの

- 測る3つの数（資源・再起動の記録・負荷）と、数から決めること
- 衝突を避ける見方（ファイル名の重なりだけでは判断できない理由）
- 作業を渡すときに書くこと・書かないと詰まるもの
- 報告の裏取り（5手順と、実際に起きた食い違いの一覧）
- 取り込みと公開の順序
- 待ち方（条件で起きる形にする）
- 作業場所の片付け
- 気をつけること（本体で動く・止めても動き続ける・判定不能と不合格の違い）
- 進捗の確かめ方（`docs/scripts/` の各スクリプトの使い方）
- 定期報告の型

出典は `負荷を見ながらタスクを消化する.md`・`進捗を管理して割り振るPM.md`・`定期報告フォーマット.md`・`進捗確認スクリプトの使い方.md`・`PM引き継ぎの現状.md` である。

### まとめ方の決まり

1. **同じことを2度書かない。**両方に要る内容（進捗の確かめ方など）は、進行担当の側へ置き、作業者の側からは参照だけする
2. **実際に起きたことを残す。**「〜回起きた」という実測は、なぜその決まりがあるかを示すため削らない
3. **手順はそのまま実行できる形で書く。**コマンドは省略せず、変数は実体で書く
4. **元の6件は削除する。**まとめ直した2件へ内容が移ったことを確かめてから削除する

## 4. 完了の判定

1. `docs/session-prompts/作業者のプロンプト.md` が実在する
2. `docs/session-prompts/進行担当のプロンプト.md` が実在する
3. `docs/session-prompts/` の `.md` が2件だけになる
4. 2件の合計行数が、元の6件の合計（995行）より少ない
5. 元の6件にあったスクリプトへの言及が2件のいずれかに残っている
6. 鮮度の検査が終了コード0を返す
7. 形の検査が不合格0件を返す

## 5. 触らない範囲

- `docs/tasks/` 配下の指示書
- `.claude/rules/` 配下の規約
- `generation-engine/` 配下の生成物と検査

## 6. 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| 2件の名前 | `作業者のプロンプト.md` と `進行担当のプロンプト.md` | 既にこの名前の文書がある場合は末尾に用途を足す |
| 元の6件をいつ削除するか | まとめ直した2件をコミットしたあと、同じコミットで削除する | 内容の移し忘れが見つかった場合は削除を後回しにする |
| 重なる内容をどちらへ置くか | 進行担当の側へ置き、作業者の側からは参照する | 作業者が単独で読んで実行できなくなる場合は作業者の側へ複製する |
| 引き継ぎの現状をどう扱うか | いつでも通用する部分だけを進行担当の側へ移す。その時点の状況は移さない | なし |

## 7. 他の指示書との関係

依存も重複もない。`docs/session-prompts/` だけを対象とする。

## 8. この指示書の位置づけ

文書の整理であり、コードの変更を伴わない。読み手で分ける規約の考え方を、内部の文書へ広げる作業として切り出した。
