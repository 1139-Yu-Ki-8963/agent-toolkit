## この指示書は何か

判定スクリプトが 7 件、第 1 層の集約に載っておらず一度も走っていない。集約が拾う形へ直すか、拾えない理由を記録する。

## なぜ必要か

第 1 層の機械検証（`generation-engine/scripts/verification/run-layer-machine-checks.sh`）は、自己テストを持つスクリプトを動的に集めて一括で走らせる。集約が拾わないスクリプトは**一度も走らない。合格も不合格も返さない。**

配線漏れを見つける検査（`generation-engine/scripts/tests/check-verification-wiring.sh`）は、この 7 件を警告として報告するが、**終了コード 0 を返して通す。** 警告は誰も止めないため、載っていない状態が続く。

### 集約対象件数の参照元

集約対象件数は変動するため、本書における現在値は次のコマンドの標準出力だけを参照する。

```bash
set -o pipefail
bash generation-engine/scripts/verification/run-layer-machine-checks.sh --list | grep -c .
```

2026-08-19 にこの作業用ディレクトリで実行した結果は **162 件**だった。
この値は日付付きの実行記録であり、完了判定の閾値や現在値の参照元にはしない。
以後の確認では、このコマンドを都度実行する。

**検査が存在するのに走っていない状態は、検査が無い状態と変わらない。** 放置すると、その検査が守るはずのものが壊れても誰も気付かない。

## やること

1. **7 件それぞれを実際に実行し、引数なしで検査として成立するかを確かめる。** 名前が `test-` で始まるものは、実行そのものが検査になる形かもしれない

2. 集約が拾う条件を読む。`run-layer-machine-checks.sh` の収集部分（`list_targets` 相当）を読み、何を拾い何を拾わないかを把握する

3. 7 件それぞれについて次のどちらかを行う

| 分け方 | どうするか |
|---|---|
| 集約が拾える形に直せる | `--self-test` を受け付ける形にするか、収集の条件へ加える |
| 直せない | 拾えない理由を、そのスクリプトの冒頭コメントへ書く |

4. **収集の条件を変える場合は、変更前後に「集約対象件数の参照元」のコマンドを実行し、変更後の値が変更前を上回ることを確かめる**

### 載らない理由と所要時間の実測

委任元が 3 本を調べた（2026-08-19・コミット `b50d09ba` 時点）。

#### 載らない理由

集約は `--self-test` を**引数として処理している形跡**（`case` 文の `--self-test)` 分岐、または `if` 文の `= "--self-test"` 比較）を持つものだけを拾う。調べた 3 本はいずれもこの分岐を 0 件しか持たない。

```
check-photo-findings-29.sh            0 件
test-python-facts-flow.sh             0 件
test-screen-unit-root-layout.sh       0 件
```

**引数を取らず、実行そのものが検査になる形である。**

#### 引数なしで走らせた結果

```
test-python-facts-flow.sh        所要 31 秒 / 終了コード 1 / self-test FAIL: 1件
test-screen-unit-root-layout.sh  所要 44 秒 / 終了コード 1
```

**2 本とも落ちている。集約に載っていないため、この不合格を誰も見ていなかった。**

**どちらも 120 秒以内で終わる。** 集約へ載せても打ち切られない。

#### この事実が示すこと

載せる作業には**2 段ある。**

1. 集約が拾う形にする（載せる）
2. 載せた結果として現れる不合格を直す

**1 だけを行うと、集約の失敗が 3 本から増える。** それ自体は正しい。**見えていなかったものが見えるようになるだけである。** ただし、載せた直後に集約が赤くなることを承知しておく必要がある。

不合格を直すのは本指示書の範囲外とする。**載せることと直すことは別の作業であり、混ぜると「載せたら赤くなったので載せるのをやめる」という判断が起きやすい。**

### 載せ方の選択

集約は `--self-test` を引数として処理するものを拾う。**引数を取らない検査を載せる方法は 2 つある。**

| 方法 | 中身 | 向いている場合 |
|---|---|---|
| 各スクリプトへ `--self-test` の受け口を足す | 引数を受けても同じ動作をする分岐を足す | スクリプトを触ってよい場合。**既定はこちら**（決めていないことの表のとおり） |
| 集約の収集条件を広げる | 名前が `test-` で始まるものも拾う | 7 本すべてが同じ形をしており、条件 1 つで拾える場合 |

**収集条件を広げる場合は、意図せず別のものまで拾わないかを確かめる。** 集約の所要時間が伸びる。

**同じ原因である可能性が高い、ではなく、同じスクリプトを呼んでいる。** `prefill-design-from-facts.sh` の原因（転記先の見出し `### 15.3 依存` がテンプレートに無い）を直せば、この 1 本の不合格も同時に直る。**別々に調べる必要はない。**

所要時間の 402 秒は、内部で 11 本の自己テストを直列に呼ぶ構造による。**縮める作業は不合格が直ってから行う。**

### 着手の順序

1. **すぐ載せられる 2 本**を載せる。集約が赤くならず、載せる仕組みが動くことを確かめられる
2. **落ちている 2 本**を載せる。集約の失敗が 2 本増えるが正しい
3. **道具が無い 2 本**は、終了コードを判定不能へ揃えてから載せる
4. **未測の 1 本**は所要時間を測ってから判断する
5. **`check-photo-findings-29.sh` は最後にする。** 所要時間が 402 秒で上限を超え、かつ落ちている。落ちる原因が別の指示書（`第1層の機械検証で落ちる2本を直す指示書`）と同じ可能性があるため、そちらが片付いてから確かめる

**1 から順に進める。** まとめて載せると、載せる仕組みの問題と各検査の問題が混ざって切り分けられない。

## 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| 集約の収集の条件を広げるか、各スクリプトを直すか | 各スクリプトを直す。収集の条件を広げると、意図せず別のものまで拾い、集約の所要時間が伸びる | 7 件すべてが同じ形をしており、条件を 1 つ足すだけで拾える場合 |

## 他の指示書との関係

`自己テストの所要時間が規約の件数に追いつかれる問題を片付ける指示書`（`docs/tasks/done/` にある）が、上限で打ち切られる問題を扱った。本指示書は、上限ではなく収集の条件から外れる問題を扱う。**どちらも「検査が存在するのに走っていない」という同じ結果を招く。**

## この指示書の位置づけ
