## この指示書は何か

配線漏れの検査が、警告から外す目印として通し番号を含む固定の文字列を探している。番号からは何の条件か読み取れない。内容が読める文字列へ改める。

## なぜ必要か

`check-verification-wiring.sh` の `has_exempt_comment` は、対象ファイルの本文を `grep -qF` で調べる。

本文に `改善課題 1-138 の横断検収条件の対象外` が含まれていれば警告から外す。

この文字列には次の 2 つの問題がある。

1. **番号が何を指すのか、文字列からは読み取れない。** 除外の理由が所要時間なのか、環境の準備なのか、対象の性質なのかを、書いた人以外は判別できない
2. **内容要約キー規約は、連番を識別子に使うことを禁じている。** 同規約は意味語による命名を求める

2026-08-19、走っていない検査を集約へ載せる作業で、3 件のスクリプトへこの文字列を書いた。理由はそれぞれ異なる（所要時間の超過が 1 件、環境の準備の不足が 2 件）が、目印の文字列は同じである。理由は各スクリプトの冒頭コメントに書いたが、**目印そのものは理由を持たない。**

放置すると、目印を持つファイルが増えるほど、何のための除外かが読み取れなくなる。

## やること

1. `check-verification-wiring.sh` の `has_exempt_comment` が探す文字列を、内容が読める文字列へ変える
2. 現在この文字列を持つファイルをすべて洗い出し、新しい文字列へ置き換える
3. 自己テストの除外条件のケースが、新しい文字列で通ることを確かめる

## 完了の判定

1. 旧い文字列 `改善課題 1-138 の横断検収条件の対象外` を持つファイルが 0 件になる
2. 配線漏れの検査の自己テストが終了コード 0 で終わる
3. 配線漏れの検査の警告の件数が、置き換えの前後で変わらない

#### 置換前再現コマンド

履歴の初点 `2ee8749` はすでに新しい目印を持つため、作業場所内の一時複製で目印だけを旧文字列へ戻して比較した。

```bash
set -euo pipefail
tmp_dir="$(mktemp -d "$PWD/.marker-before.XXXXXX")" || exit 1
trap 'find "$tmp_dir" -depth -delete' EXIT
cp -R generation-engine "$tmp_dir/"
rg -l0 --fixed-strings '集約の対象外' "$tmp_dir/generation-engine/scripts" \
  | xargs -0 perl -pi -e \
    's/集約の対象外/改善課題 1-138 の横断検収条件の対象外/g'
old_marker_count="$(rg -o --fixed-strings \
  '改善課題 1-138 の横断検収条件の対象外' \
  "$tmp_dir/generation-engine/scripts" | wc -l | tr -d ' ')"
if rg -q --fixed-strings '集約の対象外' "$tmp_dir/generation-engine/scripts"; then
  exit 1
fi
test "$old_marker_count" -gt 0
before_count="$(bash "$tmp_dir/generation-engine/scripts/tests/check-verification-wiring.sh" \
  "$tmp_dir" 2>&1 | LC_ALL=C grep -c 'WARN')"
after_count="$(bash generation-engine/scripts/tests/check-verification-wiring.sh \
  "$PWD" 2>&1 | LC_ALL=C grep -c 'WARN')"
printf 'old-markers=%s new-markers=0 before=%s after=%s\n' \
  "$old_marker_count" "$before_count" "$after_count"
test "$before_count" -eq "$after_count"
```
