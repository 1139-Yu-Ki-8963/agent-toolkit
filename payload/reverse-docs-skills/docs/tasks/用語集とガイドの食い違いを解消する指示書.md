# 用語集とガイドの食い違いを解消する指示書

**状態**: 着手できる
**優先度**: 中
**前提**: なし
**元の指摘**: なし

## この指示書は何か

用語集（`docs/guides/用語集.md`）とスキルのガイド（`.claude/skills/*/references/guide.html`）の用語が食い違っている。用語集を唯一の情報源とする建て付けが機能していないため、食い違いを解消する。

## なぜ必要か

`generation-engine/scripts/check-glossary-sync.sh` は、用語集とガイドの用語パネルの食い違いを見る検査である。実測（2026-08-19・コミット `3fbc799c` 時点）:

```
bash generation-engine/scripts/check-glossary-sync.sh .
SUMMARY unregistered=114 unregistered_occurrences=159 mismatch=6 unused=5
終了コード: 1
```

内訳は次のとおりである。

| 種別 | 件数 | 意味 |
|---|---|---|
| 未登録 | 114 語（出現 159 か所） | ガイドで使われているが用語集に無い |
| 食い違い | 6 件 | 用語集とガイドで説明が異なる |
| 使われていない | 5 語 | 用語集にあるがガイドで使われていない |

未登録の語には「パラメタライズドテスト」「派生アダプター」「空雛形」「縮退」「退役」などが含まれる。

**用語集を唯一の情報源とする建て付けが機能していない。** 114 語が未登録では、用語集を読んでもガイドの語が分からない。ガイドを読む人（納品先のエンジニアと作業を担うエージェント）は、その場で意味を推測することになる。

この検査は既に存在し、落ち続けている。**見つけているのに直っていない状態が続いている。**

## やること

1. **未登録の 114 語を一覧で出す。** `--list-unregistered` の引数がある

```
bash generation-engine/scripts/check-glossary-sync.sh . --list-unregistered
```

2. 一覧を読み、語ごとに次のどちらかに分ける

| 分け方 | 見分け | どうするか |
|---|---|---|
| 用語集へ載せる | ガイドを読む人が意味を取れない語 | 用語集へ説明つきで追加する |
| ガイドから消す | このリポジトリでしか通じない語・別の語で言い換えられる語 | ガイドの側を平易な語へ書き換える |

**「独自の言葉遣いをなくす」という別の取り組みと重なる語がある。** 重なる場合はガイドから消す側を選ぶ。

3. **食い違い 6 件**は、用語集とガイドのどちらが正しいかを判断し、片方へ揃える。用語集を情報源とする建て付けなので、原則は用語集へ揃える

4. **使われていない 5 語**は、用語集から消すか、使う場所を作る。消す場合は、他の文書で使われていないことを確かめてから消す

#### 分けるときの目安

この一覧には、**今日スキルの説明から禁じた語と同じものが多く含まれる。**

| 語の例 | 扱い |
|---|---|
| マニフェスト・ユニット種別・交差ビュー・孤児参照・原本を見ない検証 | このリポジトリでしか通じない。**ガイドから消して平易な語へ書き換える** |
| `facts.yml`・`page-data.json`・`env-config.json`・`nodes`・`edges`・`prerequisites` | ファイル名・設定の鍵の名前そのもの。**用語集へ載せる対象ではない。** 検査が拾わない形にできるかを先に確かめる |
| エンドポイント・コンポーネント・CSS トークン | 業界で通じる語だが初見の読み手には説明が要る。**用語集へ載せる** |
| 確定・根拠・転記・共通処理 | 一般の日本語。**用語集へ載せる必要があるかを 1 語ずつ判断する** |

**ファイル名と設定の鍵の名前が多く含まれる。** これらを用語集へ載せると、用語集が設定の一覧になって読まれなくなる。検査がこれらを拾わない形にできるなら、そちらを先に検討する。ただし**検査の判定を緩めて通してはならない。** 拾わない形にする場合も、拾わない理由を検査の冒頭コメントへ書く。

`facts.yml` のように英字とドットを含むものは、語ではなくファイル名である。**語とファイル名を分ける規則を検査へ入れられるかを確かめてから、1 語ずつの判断に入る。** 先に規則で減らせれば、判断する語数が大きく減る。

## 完了の判定

1. `bash generation-engine/scripts/check-glossary-sync.sh .` が終了コード 0 を返す
2. `bash generation-engine/scripts/check-glossary-sync.sh . 2>&1 \| LC_ALL=C grep -q 'unregistered=0'` が終了コード 0 を返す
3. `bash generation-engine/scripts/check-internal-jargon.sh` が終了コード 0 を返す（ガイドから消した語が、独自の言葉遣いの検査を落とさないこと）
4. `bash generation-engine/scripts/skill-guide/apply-guide-style.sh --self-test` が終了コード 0 を返す（ガイドの体裁を壊していないこと）

## 触らない範囲

- `generation-engine/scripts/check-glossary-sync.sh` そのもの。検査の判定を緩めて通してはならない
- `docs/tasks/` 配下
- `delivery-payload/` 配下

## 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| 未登録の語を載せるか消すか | ガイドを読む人が意味を取れない語は載せる。このリポジトリでしか通じない語は消す。迷ったら消す側にする。用語集が膨らむほど読まれなくなる | その語が納品先で必ず使われる技術用語である場合 |
| 一度に全件やるか分けるか | 分けてよい。1 語でも減れば前へ進む | — |
| 食い違いの解消の向き | 用語集へ揃える。用語集を情報源とする建て付けのため | ガイドの説明のほうが明らかに正確で、用語集が古い場合。その場合は用語集を直す |

## 他の指示書との関係

`独自の言葉遣いをなくす指示書`（`docs/tasks/done/` にある）が、ガイドとスキル定義から独自の語を減らした。本指示書はその続きで、**用語集との対応が取れていない語**を扱う。片付いた指示書が対象にしなかった範囲である。

## この指示書の位置づけ

検査は既にあり、落ち続けている。**検知と是正を分け、是正のほうを 1 件として切った。** 114 語を 1 語ずつ判断する作業であり、件数が多いため見積もりが要る。
