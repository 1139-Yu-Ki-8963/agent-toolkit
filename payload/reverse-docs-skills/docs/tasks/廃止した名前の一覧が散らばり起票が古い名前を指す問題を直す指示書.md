# 廃止した名前の一覧が散らばり起票が古い名前を指す問題を直す指示書

**状態**: 着手できる
**優先度**: 高
**前提**: なし
**元の指摘**: なし

## この指示書は何か

廃止した資料の名前が、複数の検査にそれぞれ直接書かれている。新しく指示書を書く担当は、その名前が既に廃止されていることを知る手段を持たない。名前の一覧を1箇所へ集め、指示書の本文もその一覧と突き合わせる検査を作る。

## なぜ必要か

実測（2026-08-24）。「要確認事項の記録先を根拠を記録する資料へ向け直せ」という指示書を起票した。ところが改善課題1-246（コミット `bd5d289`「【修正】納品物からコード行番号ベースの根拠記録を除く 1-246」）が既にその資料を廃止していた。次の4語は、対象配下に0件であることを検査が要求する状態になっていた。

```
根拠資料
根拠を記録する資料
設計単位根拠台帳
共通文書根拠台帳
```

起票した既定どおりに進めれば、その指示書の完了の判定3（節構成の検査）を直ちに壊すところだった。担当が実測で気づいて方針を変えたため、実害は出ていない。**気づけたのは偶然であり、仕組みが止めたわけではない。**

同じ4語が2つの検査にそれぞれ直接書かれている。

```
generation-engine/scripts/tests/check-design-doc-section-consistency.sh
generation-engine/scripts/tests/test-api-design-decisions.sh
```

前者は `evidence_ref_count` という変数で0件を要求する。1-246 の以前は逆に26件を要求していた（期待値が26から0へ反転している）。

廃止した名前が増えるたびに、書かれている箇所をすべて探して直すことになる。探し漏らせば、片方の検査だけが古い一覧で判定する。加えて、起票する担当はどちらの検査も読まないため、廃止を知る経路がない。

## やること

1. **廃止した資料・節の名前の一覧を1つのファイルへ集める。** 置き場はこのリポジトリ固有の場所とする（`delivery-payload/references/` は配布物であり、このリポジトリの起票の運用は配布対象ではない）。各語について、廃止した改善課題の番号とコミットのハッシュ、置き換え先（あれば）を持たせる
2. **既存2つの検査を、その一覧を読む形へ変える。** 4語のハードコードを無くす
3. **`docs/tasks/` 配下の指示書の本文を走査し、一覧の語が含まれていたら不合格にする検査を作る。** 判定の式に縦棒（`|`）が入るため、式をスクリプトへ切り出す（片付けの判定器が縦棒を列の区切りと読み違え、判定行そのものを壊すため）
4. 新しい検査は `--self-test` を実引数として処理すること。第1層の集約（`generation-engine/scripts/verification/run-layer-machine-checks.sh`）が `--self-test` を持つ `.sh` を動的に集めるため、この形にすると自動的に検査対象へ載る
5. **一時ファイルを作る場合は置き場を明示すること**（`mktemp "${TMPDIR:-/tmp}/<名前>.XXXXXX"`）。引数なしの `mktemp` は既定の置き場へ書こうとして失敗する環境がある
6. `diff` や `comm` の引数へプロセス置換（`<(...)`）を渡さないこと。`/dev/fd/N` を開けない環境がある
7. 新しい検査の設計判断（必要性・代替案を採用しなかった理由・保守責任者・廃棄条件）を `docs/rules/portal/page-conventions/rule.md`（正本）へ追記し、`build-derived-rules.sh --apply` で派生物を再生成すること。`.claude/rules/scoped/portal/page-conventions/rule.md` は生成物であり直接編集してはならない

## 触らない範囲

- 廃止した資料そのものを復活させない。1-246 の決定を覆さない
- `delivery-payload/` を変更しない（配布物であり、このリポジトリの起票の運用は配布対象ではない）
- 既存の指示書の本文を書き換えない。検査が不合格を返した場合は、その指示書を直すか一覧から語を外すかを判断し、記録に残す

## 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| 一覧ファイルの置き場 | `docs/references/retired-terms.json`。`docs/` はこのリポジトリ自身の説明と設計と台帳の置き場であり、配布対象ではない | `docs/` 直下に `references/` を作ることが配置の許可リストに反すると分かったとき。その場合は `docs/design/` の下へ置く |
| 既存2つの検査を直す範囲 | 4語のハードコードを一覧の読み取りへ置き換えるだけ。判定の中身（何件を要求するか）は変えない | 一覧の読み取りへ変えると判定の中身も変わると分かったとき |
| 走査の対象 | `docs/tasks/` の直下と `docs/tasks/design/` の指示書。`done/` と `work-records/` は対象外 | 片付いた指示書からも古い名前を消す方針へ変わったとき |
| 一覧に載せる語 | 上記4語から始める。以後、廃止のたびに足す | 他にも廃止済みの語が見つかったとき |

## 他の指示書との関係

`docs/tasks/一時ファイルの置き場を指定せず検査が動かない問題を直す指示書.md` と対象が重なる（どちらも `generation-engine/scripts/tests/` 配下の `.sh` を触る）。あちらを先に片付けてから着手すること。

## この指示書の位置づけ

起票の内容そのものではなく、起票する担当が古い前提を持ち込まない仕組みを扱う。1-246 の見落としは、起票の直前に既存の決定を確かめる手順が無かったために起きた。人が毎回思い出す運用では、次も見落とす。
