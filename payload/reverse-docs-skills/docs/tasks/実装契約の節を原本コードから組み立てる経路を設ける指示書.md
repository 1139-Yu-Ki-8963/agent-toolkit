## 1. この指示書は何か

接続窓口の詳細設計書が持つ「実装契約」の節（関数1本ごとの引数と戻り値の契約）を、原本コードから機械的に組み立てる経路を配布物へ新設する指示書である。現状はこの節を人手で書き起こしており、機械で導ける記述に人手を割いている。

## 2. なぜ必要か

接続窓口の詳細設計書の実装契約の節は、関数1本ごとの引数と戻り値の契約を並べる構造である。ある対象プロジェクトで様式のそろった1件を実測すると、当該の節は623行で小見出し19件を持ち、文書全体1179行の53%を占める。同じ対象の残り49件はこの節を持たない。この節を人手で書き起こすと1本あたり約950行・49件で約43500行になる。

ところが実測すると、この節の中身は原本コードから機械的に導ける。対象の実装配下48ファイル・関数776本を走査した結果は次のとおりである。引数の取り方が読めるのは703本（90%。`my (...) = @_` または `my $x = shift` の形）、戻り値が読めるのは760本（97%。`return` 文）である。関数の前のコメント（`param` と `return` の記載）に頼れるのは145本（18%）にとどまるが、コード自身からは9割以上読める。実際に1つのモジュール（13関数）に対して当該の節を組み立てたところ、様式のそろった1件と同じ形（サブルーチンの一覧と、関数ごとの引数・戻り値の表）で出力できた。型は命名の規約から導ける（参照を保持する変数の接頭辞が種類を表す規約が対象プロジェクトに実在する）。所在と関数名は接続窓口の宣言表から引ける（1-257 の source_ref がこれを指す）。

にもかかわらず、配布物にはこの節を組み立てる経路が無い。設計文書からマニフェストを組み立てる処理は存在するが、原本コードから実装契約を組み立てる処理は存在しない。結果として、機械で導ける記述を人手で書くことになる。

## 3. やること

1. 原本コードから実装契約の節を組み立てる経路を配布物へ設ける。入力は接続窓口の一覧の元データ（source_ref が指す実装のファイルと関数名）と原本コードとする
2. 抽出する項目は3つとする。第1にモジュールごとのサブルーチンの一覧（名前・公開の可否・引数の数・戻り値の要約）。第2に関数ごとの引数の表（位置・名前・型・NULL許容・初期値・導出）。第3に戻り値である
3. 型の導出は、命名の規約を宣言で受け取る形とする。接頭辞と型の対応を設定として渡し、規約を持たないプロジェクトでは型を「判定不能」とする
4. 引数の取り方が読めない関数（実測で1割）は、読めなかった旨を記録して欄を空にする。推測で埋めない
5. 抽出できた割合を実行結果へ報告し、閾値を下回る場合は警告する
6. 機械で埋まる節と埋まらない節を定義に明記する。実測では、構造を述べる節（実装契約・データアクセス・データ定義）は機械で埋まり、処理の意図を述べる節（処理フロー・ロジック・疑似コード・業務ルール）は埋まらない。どこまでを機械が担うかを定義が述べていないため、実行側が全節を人手で書く判断をしてしまう
7. 抽出処理の `--self-test` を用意し、引数の取り方が異なる複数の形（`my (...) = @_`・`my $x = shift`・どちらでもない形）を入力に含める

## 4. 完了の判定

1. `test -x generation-engine/scripts/extract/build-implementation-contract-section.sh` が終了コード0を返す
2. 同スクリプトの `--self-test` が終了コード0を返す
3. 自己テストの入力は `my (...) = @_` の形・`my $x = shift` の形・どちらでもない形の3種を含む。読めた関数は表が様式どおり出力され、読めない関数は欄が空になり「読めなかった」旨が記録される
4. 自己テストの入力に「命名の規約なし」のケースが含まれる。そのケースで型の値が「判定不能」になる
5. 自己テストの出力が抽出できた割合を含む
6. `test -f delivery-payload/references/doc-extraction.json` が終了コード0を返す。機械で埋まる節と機械で埋まらない節の一覧が定義ファイルに存在する

## 5. 触らない範囲

- 詳細設計書テンプレートの節構成そのもの（実装契約の節の位置・見出し名）
- 疑似コードの節の記入規則（`check-pseudocode-code-mixing.sh` の検査対象）
- 接続窓口の一覧の元データ（source_ref）の抽出処理（1-257 の対象）
- 命名の規約を持たないプロジェクトへの型推測の実装（判定不能のまま扱う）
