# 検査対象0件を合格としない指示書

## 1. この指示書は何か

`check-manifest-persistence.sh` が検査対象0件を合格として返す問題を直す。対象が無い実行結果を、合格・不合格とは別の判定不能として扱う。

## 2. なぜ必要か

見本の一覧フォルダを検査した実測で、対応表とHTML名の不一致により検査対象が0件だったにもかかわらず、検査は終了コード0を返した。このままでは一覧が全て消えても検査が通り、検査の目的であるマニフェスト永続化の確認を果たせない。

## 3. やること

1. 検査対象が0件なら、`[UNKNOWN]` を含む「実行できたが判定対象が無かった」と分かる文言を出し、終了コード2を返す。
2. 自己テストへ対象0件のケースを加え、`[UNKNOWN]` と終了コード2を確認する。
3. 自己テストで使う `mktemp` の失敗を、対象0件とは別の `[UNKNOWN]` 文言と終了コード2で扱う。
4. 構文、自己テスト、見本に対する実行、指示書形式を機械検査する。

## 4. 完了の判定

1. `bash -n generation-engine/scripts/unit-list/check-manifest-persistence.sh` が終了コード0を返す
2. `bash generation-engine/scripts/unit-list/check-manifest-persistence.sh --self-test` が終了コード0を返す
3. 見本に対する検査が `[UNKNOWN]` と対象0件の理由を出し、終了コード2で終わる
4. `TMPDIR=/dev/null` で自己テストを実行すると、`mktemp` が失敗した判定不能理由と `[UNKNOWN]` を出し、終了コード2で終わる
5. `bash .claude/rules/always/tasks/instruction-format/check-instruction-format.sh` が不合格0件で終了コード0を返す
6. `git diff --check` が終了コード0を返す

## 5. 触らない範囲

- `docs/tasks/` 直下の既存指示書
- `docs/tasks/work-records/` 配下の記録
- `generation-engine/scripts/verification/` 配下
- `generation-engine/scripts/skill-guide/` 配下
- `generation-engine/samples/` 配下の見本

## 6. 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| 検査対象が0件の扱い | `[UNKNOWN]` を出して終了コード2を返す | 正当に0件を合格とする呼び出し契約が追加され、その契約を別の機械検査で保証できる場合 |

## 7. 他の指示書との関係

`mktemp` 失敗を判定不能として区別する指示書と同じ終了コード2の規約に従う。ただし本件は実行環境の失敗ではなく、実行できたが判定対象が無かった状態を扱う。

## 8. この指示書の位置づけ

マニフェスト永続化検査の偽の合格を防ぎ、合格・不合格・判定不能を出力と終了コードで区別する限定的なバグ修正である。
