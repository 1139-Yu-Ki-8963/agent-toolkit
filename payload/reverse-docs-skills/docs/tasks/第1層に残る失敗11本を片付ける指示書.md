## やること

### 1. `generation-engine/scripts/scaffold-design-unit.sh` の `--backfill-basic` が `screen` 種別で落ちる

`delivery-payload/references/design-unit-layout.json` の `generationRules.basicFromExistingDetail.excludedKinds` が空配列であり、かつ `kinds.screen.phases.detail` が非空（`画面詳細設計書.md`・`DESIGN.md`）であるため、`--backfill-basic` の対象種別ループに `screen` が入る。ところが `scaffold-design-unit.sh` 内の `unit_root_key_for_kind()` は `api`・`table`・`batch`・`report`・`external`・`feature` の6種別しか扱わず、`screen` を渡すと `エラー: output-layout の物理配置キーが未定義の種別です: screen` を返して停止する。

`screen` は3階層構造（詳細設計・テスト設計・基本設計）を持ち `scaffold-screen.sh` が個別に扱う種別であり、`--backfill-basic` の対象にする設計だったかどうかを確認したうえで、`excludedKinds` に `screen` を加えるか、`unit_root_key_for_kind()` に `screen` の分岐を足すかを選ぶ（「決めていないこと」参照）。

### 11. 集約（`run-layer-machine-checks.sh`）が `test-confirmation-ledger.mjs` の合格を誤って「途中停止の疑い」と判定する

```
node generation-engine/scripts/tests/test-confirmation-ledger.mjs  # 5件すべて合格・終了コード0
[SUSPECT] generation-engine/scripts/tests/test-confirmation-ledger.mjs — 実行 0 件 / 終了コード 0  # 集約はこう判定する
```

このスクリプトは Node.js 標準の `node:test` が出すTAP形式の要約（`# tests 5` / `# pass 5` 等）で結果を報告するが、`run-layer-machine-checks.sh` の `count_cases()` 関数（9種類のパターンで実行件数を数える）は、このTAP要約の形式に対応するパターンを持たない。そのため実行件数が常に0件と判定され、`n -eq 0 && RUN_RC -eq 0` の条件に一致して「途中停止の疑い」（`SUSPECT`）へ分類される。この失敗は「失敗11本」には含まれないが（`SUSPECT`は別区分のため）、集約自身の欠陥であり実害があるため本指示書で扱う。

`count_cases()` へ `# (tests|pass) [0-9]+` のようなパターンを追加するか、`test-confirmation-ledger.mjs` 自身に集約が認識できる要約行（例: `実行 N 件` 形式）を追加出力させるかを選ぶ（「決めていないこと」参照）。
