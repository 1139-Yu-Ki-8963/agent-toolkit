## 1. この指示書は何か

顧客提示適合検査（`check-customer-facing-adequacy.sh`）が禁止する語のうち、配布物自身の様式・定義・生成物が使っている3語を言い換える指示書である。対象の語は「原本」「納品物」「抽出」である。

## 2. なぜ必要か

顧客提示適合検査は、定義が定める語を検出したら機械判定で不合格にする。この禁止語のうち3つが、配布物自身の様式・定義・生成物の側で使われている。

1つめは「原本」である。接続窓口の詳細設計書の様式の本文がこの語を含む表現を複数持つ。設計判断の節では、選ばなかった選択肢を読み取れない場合の値も、この語を含む固定値にしている。

2つめは「納品物」である。配置の定義が、納品物の一覧の置き場をこの語を含む名前で宣言する。生成されるページの表題・見出し・列の名前にも、この語が出る。

3つめは「抽出」である。一覧の様式の列の名前と、対応表の様式の文言が、この語を含む。

いずれも様式どおりに書いた文書、または生成器がそのまま出す生成物が不合格になる。配布物の根で顧客提示適合検査を見本の出力へ実行すると、終了コード1で不合格99件が出る。内訳は「対象コード」29件・「抽出」21件・「原本」21件・「顧客」20件・「納品物」6件・「調査範囲」1件・「ためである」1件である。配布物自身の見本の出力が、配布物自身の判定を通らない。

ある対象プロジェクトの納品物では、不合格1177件のうち1164件を私たちの側の言い換えで解消できた。残る13件はこの3語であり、私たちの側では解消できない。

## 3. やること

1. 様式・定義本文にある「原本」「納品物」「抽出」を、それぞれ「実装」「本資料」「取り出し」へ言い換える。対象は接続窓口相当の詳細設計書の様式である。配置の定義・一覧の様式・対応表の様式も、この3語を含む箇所を同様に直す。
2. `validate-api-design-decisions.mjs`が持つ固定値「不明（原本に記述なし）」を「不明（実装に記述なし）」へ変更する。API詳細設計書の様式本文にある同じ固定値の記述も、同じ文字列へ揃える。`generating-api-detail-design-for-reverse-docs`の`SKILL.md`が持つ同じ固定値への言及も、同じ文字列へ揃える。
3. テンプレートを改訂したら、`template-sample-sync`規約に従いサンプルを再生成する。対象は`generation-engine/samples/`配下の対応するファイルである。
4. `check-customer-facing-adequacy.sh`の自己テストへ、言い換え後の様式が不合格にならないケースを追加する。
5. `test-api-design-decisions.sh`が持つ固定文字列の照合を、言い換え後の固定値へ更新する。

## 4. 完了の判定

1. 見本の出力全体を検査すると不合格が0件になる
2. 様式どおりの詳細設計書を検査すると不合格にならない
3. 納品物の一覧のページを検査すると不合格にならない
4. 一覧と対応表の生成物を検査すると不合格にならない
5. 検査本体の自己テストが通る

## 5. 触らない範囲

- 顧客提示適合検査の走査対象の設計（`<project_root>`配下の生成物に限る仕組みそのもの）
- 第1・第2・第4・第5・第6カテゴリの語彙（「原本」「納品物」「抽出」以外の語）
- `FAIL`・`REVIEW`の判定ロジックそのもの
- 設計判断の記述区分（`観測（コードコメント）`等）の判定条件そのもの

## 6. 決めていないこと

| 何を決めるか | 既定（担当者はこの値を選ぶ） | 覆すときの条件 |
|---|---|---|
| 3つの方向のどれを採るか | 方向1（様式・定義の本文を言い換える）を採る。台帳は「1つめを採る場合、固定値の変更は設計判断の記述区分を見る検査と同時に行う必要がある」と方向1に限定した注意点を添えており、この方向を想定していると読める。方向2（禁止語一覧から外す）は、将来の対象プロジェクトで実際に問題のある使い方を見逃す恐れがある。方向3（配布物自身の資産を検査対象から外す）は、接続窓口の詳細設計書の本文に混入する事例（完了の判定2）を解消できない | 言い換えの範囲が広く既存の他の検査を壊すと判明した場合、または言い換え後も不合格が実測で残ると判明した場合は、方向2または方向3を併用する |
| 「原本」「納品物」「抽出」の言い換え後の語 | 台帳が挙げる「実装」「本資料」「取り出し」をそのまま使う | 言い換え後の語が既存の別の語と衝突すると判明した場合は、衝突しない語へ変更する |

## 8. この指示書の位置づけ

顧客提示適合検査の禁止語彙と、配布物自身が使う様式の語彙が衝突している箇所を洗い出し、言い換えで解消する指示書である。対象の語と衝突箇所は台帳の実測で特定済みのため、設計から始める必要はなく、そのまま言い換えに着手できる。優先度を高としたのは、この衝突が対象プロジェクトの納品物へ実際に持ち込まれ、私たちの側では解消できない不合格として残り続けるためである。
