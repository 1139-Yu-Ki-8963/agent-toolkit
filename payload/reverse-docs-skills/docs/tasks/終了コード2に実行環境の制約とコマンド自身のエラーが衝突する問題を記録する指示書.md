## この指示書は何か

`docs/scripts/judge-task-done.sh`は、終了コード2を判定不能として扱う。
対象は「確かめる手段」のコマンドである。

`grep`もファイルを開けないと終了コード2を返す。
このため、実行環境の制約とコマンド自身のエラーが同じ値で衝突している。

## なぜ必要か

当時の参照先は、
`docs/tasks/自己テストの所要時間が規約の件数に追いつかれる問題を片付ける指示書.md`
だった。

判定2の確かめる手段は、当時の参照先を `grep` していた。
このファイルは既に移動済みであり、当時の参照先は存在しない。

実在する移動先は、
`docs/tasks/done/自己テストの所要時間が規約の件数に追いつかれる問題を片付ける指示書.md`
である。

`grep`はファイルを開けないと終了コード2を返す。
判定器はこの終了コード2を環境制約による判定不能と扱ってしまった。

実際には、サンドボックスと無関係なファイル不在によるコマンド自身のエラーだった。

この調査では、2つの独立したセッションが別の誤った結論に至った。
結論はサンドボックス下の `mktemp` 失敗、`jq` 不在、公開状態だった。

どちらも終了コード2を実行環境の制約と決め打ちした。
このため、`grep` の参照先パスの誤りへたどり着けなかった。

`indeterminate-result`規約は、終了コード2を実行環境の制約として定めている。
規約のパスは `.claude/rules/always/verification/indeterminate-result/rule.md` である。

ただし、ファイル不在などでコマンド自身が終了コード2を返す場合との区別はない。
