# 調査書の検査が対象コードを丸ごと複製する問題を直す指示書

**状態**: 着手できる
**優先度**: 最高
**前提**: なし
**元の指摘**: 1-258

## 1. この指示書は何か

調査書の検査が非UTF-8ファイルへ検出手がかりを再実行するとき、対象リポジトリ全体を一時領域へ複製する処理を改める。
手がかりが読むパスだけを変換し、終了方法にかかわらず一時ミラーを片付け、規模超過時も他の検査結果を返せるようにする。

## 2. なぜ必要か

`.claude/skills/surveying-architecture-for-reverse-docs/scripts/check-architecture-survey.sh` の `prepare_utf8_mirror` は、`cp -R "$src/." "$mirror/"` のあとで全ファイルを1件ずつ判定・変換する。
3.9ギガバイト・96660ファイルの対象では9分半後も検査1しか終わらず、判定を返せなかった。
正常経路では呼び出し元が `rm -rf` するが、時間切れ・異常終了・割り込みではそこへ戻らず、実測時に `/tmp` へ5件・6.3ギガバイトの写しが残っていた。

手がかり6件の実行自体は合計168ミリ秒であり、時間を使っているのはリポジトリ全体の複製と変換である。
検査対象を手がかりの参照先へ限定し、限定できない場合の判定不能を局所化する必要がある。

## 3. やること

1. §6の検出手がかりから、`grep`・`rg`・`find` が読むリポジトリルート相対のファイルまたはディレクトリを抽出する関数を追加する。引用符、検索パターン、オプションと値、出力先はパスとして扱わない。`..` でリポジトリ外へ出る値と絶対パスは拒否する。
2. `prepare_utf8_mirror` は抽出したパスだけを相対配置を保って一時ミラーへ複製する。同じ親を指すパスは重複を除き、親ディレクトリを1回だけ複製する。変換対象の列挙も複製した範囲だけに限定する。
3. `find .` のように対象がリポジトリ全体になる手がかりは全体複製へ戻さない。複製前に対象パス集合の規模を測り、既定の上限を超えた場合は、その手がかりの再実行だけを飛ばす。
4. 既定の規模上限は合計1ギガバイトとする。
   上限は環境変数 `ARCHITECTURE_SURVEY_MIRROR_MAX_BYTES` で上書き可能にし、0以下や数値でない値は明示的なエラーにする。
   規模は重複を除いた通常ファイルの論理バイト数で測り、シンボリックリンクをたどらない。
   DarwinとLinuxの両方で疎ファイルの論理サイズを読める `stat` の分岐を持つ。
   飛ばした場合は、種別・対象パス・実測バイト数・上限・理由を `[SKIP]` 行へ出す。
5. 一時ミラーの作成と内容の複製・変換を別の関数へ分ける。
   親プロセスがミラーを作成した直後かつ複製開始前に、その実在パスを片付け対象へ登録する。
   コマンド置換の子プロセス内でミラーを作成してから親へ返す現行構造は使わない。
   `EXIT`・`INT`・`TERM` の終了経路で、登録済みミラーだけを削除する同じ関数を走らせる。
   `INT` は片付け後に終了コード130、`TERM` は143で終了し、通常処理を続けない。
   広い `/tmp`、未解決の変数、他プロセスが作成したミラーは削除対象にしない。
6. 規模超過で手がかりの再実行を飛ばしても、検査1および検査3以降を続ける。
   最終出力は合格・不合格・判定不能の件数を分け、飛ばした手がかりを判定不能として数える。
   不合格があれば終了コード1、判定不能だけがあれば2、全件を実行して合格した場合だけ0を返す。
   判定不能がある状態で「全7検査PASS」と表示しない。
7. 既存の `--self-test` へ、参照先限定、1ギガバイト超の無関係ファイルを持つリポジトリ、規模超過、`TERM`、`INT`、非UTF-8ファイルの再実行を追加する。
   シグナルのケースは複製・変換の途中で送信し、登録前の隙間が無いことを確かめる。
   一時ミラーが0件になること、所定の終了コードで制限時間内に終了すること、通常処理を続けないことを検査する。
   大容量ケースは疎ファイルを使い、論理サイズで閾値分岐を通したことも確かめる。

1. 一時ミラーへ複製されるファイルが、検出手がかりから抽出したパス配下だけである。確かめる手段: `bash .claude/skills/surveying-architecture-for-reverse-docs/scripts/check-architecture-survey.sh --self-test`

3. 複製・変換中の検査へ `TERM` を送り、一時ミラー0件・終了コード143・制限時間内の終了を確認する。確かめる手段: `bash .claude/skills/surveying-architecture-for-reverse-docs/scripts/check-architecture-survey.sh --self-test`
4. 複製・変換中の検査へ `INT` を送り、一時ミラー0件・終了コード130・制限時間内の終了を確認する。確かめる手段: `bash .claude/skills/surveying-architecture-for-reverse-docs/scripts/check-architecture-survey.sh --self-test`
5. 規模上限を超えるケースで他の検査結果を出し、判定不能を含む総括と終了コード2を返す。確かめる手段: `bash .claude/skills/surveying-architecture-for-reverse-docs/scripts/check-architecture-survey.sh --self-test`

## 5. 触らない範囲

- 実測時点で `/tmp` に残っている過去の写しを削除しない
- 調査書の必須節、6種別、判定語の契約を変更しない
- 検出手がかりとして許可するコマンドを `grep`・`rg`・`find` 以外へ広げない
- 対象プロジェクト側の調査書を変更しない
- 非UTF-8ファイルを判定・変換する `detect-encoding.sh` の契約を変更しない

## 6. 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| 複製対象の規模上限 | 合計1ギガバイトとし、`ARCHITECTURE_SURVEY_MIRROR_MAX_BYTES` で上書き可能にする | 実測で1ギガバイト未満でも実用時間を超える場合は、同じ環境変数を保ったまま既定値を下げる |
| 手がかりから安全にパスを抽出できない場合 | リポジトリ全体を複製せず、その手がかりだけを `[SKIP]` として理由付きで飛ばす | 安全な引数解析器を追加し、リポジトリ内の参照先を一意に抽出できるようになった場合 |
| `find .` が指す範囲 | リポジトリ全体として規模を測り、上限超過なら当該手がかりだけを飛ばす | `find` の後続引数から探索開始点をより狭く一意に抽出できる場合は、その開始点だけを測る |
| 規模超過時の全体終了コード | 他の検査結果を出したあと2を返し、判定不能件数を表示する | 上位の集約が判定不能を別の終了コードへ統一した場合 |

## 7. 他の指示書との関係

本指示書は調査書の検査2にある検出手がかり再実行の性能と後片付けだけを扱う。
調査書の節構成、検出手がかりの記述内容、非UTF-8判定そのものを扱う既存指示書とは重複しない。
既存の `check-architecture-survey.sh --self-test` を拡張し、別の検査器へ判定ロジックを複製しない。

## 8. この指示書の位置づけ

検査全体を高速化するのではなく、実測で支配的だった全体複製・全件変換と、異常終了時の残留を同じ一時ミラーの責務としてまとめた。
対象プロジェクト固有の調査書や過去の残留物まで含めると、検査器の再発防止と運用上の清掃が混ざるため含めない。

### 判断の記録

| 何を決めたか | 選んだもの | 選んだ理由 | 覆すと何が変わるか |
|---|---|---|---|
| 複製対象の規模上限 | 合計1ギガバイト | ユーザーの検収条件が1ギガバイト超の対象を明示し、実測3.9ギガバイトの全体複製を確実に避けられるため | 実測時間に合わせて既定値だけを調整し、環境変数の上書き契約は維持する |
| パス抽出不能時の扱い | 当該手がかりだけを理由付きで飛ばす | 安全性を保ちながら他の検査の判定を返し、全体が無結果になる状態を避けるため | 安全な解析が可能になれば再実行対象へ戻す |
| 一時ミラーの削除対象 | 現在のプロセスが登録した実在パスだけ | 異常終了時の残留を防ぎつつ、過去の写しや他プロセスの一時領域を誤削除しないため | プロセス間で所有権を証明できる別の仕組みを導入した場合だけ対象識別を置き換える |
| 規模の測り方 | 重複を除いた通常ファイルの論理バイト数 | 疎ファイルでも閾値分岐を検査し、同じ親パスの二重加算とリンク先の意図しない走査を避けるため | 配布対象の実転送量を別の指標で安全かつ移植可能に測れる場合 |
| 手がかり引数の解析 | 対応済みオプションだけを厳密に解釈し、未対応構文は判定不能とする | オプション値や検索パターンをパスと誤認すると無関係な複製へ戻るため | 安全な共通コマンド引数解析器を導入した場合 |
| コピーと変換の実行方法 | 外部処理を子プロセスとして起動し、親が割り込み可能なwaitで管理する | 同期実行では外部処理の終了までbashのtrapが遅延し、制限時間内に片付けられないため | 利用するシェルが同期子プロセス中もtrapを即時実行する契約になった場合 |
