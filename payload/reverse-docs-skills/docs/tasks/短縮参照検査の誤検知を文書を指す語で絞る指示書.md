## 1. この指示書は何か

他の文書への参照が宣言を伴わずに短縮形だけで使われていないかを見る検査（`check-shorthand-reference-declaration.sh`）の検出条件を絞る指示書である。ラベルが文書を指す語を含む場合だけ短縮参照とみなし、括弧の中で例や補足を述べる通常の書き方を誤って不合格にしないようにする。

## 2. なぜ必要か

他の文書への参照が宣言を伴わずに短縮形だけで使われていないかを見る検査を、ある対象プロジェクトの納品物へ実行したところ16件の不合格が出た。そのうち13件は私たちが書いた設計書であり、これは直した。残る3件は配布物自身が納品する資産である。内訳は配布するスキルの定義2本と、納品先の入口の文書である。検出された短縮の札は「例」「参照」、および開き括弧の直後にバッククォートが来る形である。いずれも他の文書への参照ではなく、丸括弧の中で例や補足を述べる通常の書き方である。検査は丸括弧・札・コロン・値・閉じ括弧という並びだけを見ており、その札が文書を指しているかを見ていない。検査の対象は納品先の出力の全文書であり、配布物が自分で納品した資産も含む。その結果、私たちが書いた文書をすべて直しても不合格が0にならない。

## 3. やること

1. `delivery-payload/references/shorthand-reference-document-words.json`を新設する。文書を指す語（設計書・一覧・規約・台帳を含む、拡張可能な配列）を`documentWords`キーに定義する
2. `_extract_shorthand_labels`が抽出したラベルのうち、`documentWords`のいずれかを含むものだけを短縮参照とみなす。`check_document`をこの判定に合わせて変更する。いずれの語も含まないラベルは対象から除外する。除外したラベルは不合格としない
3. 定義ファイルの読み込みに失敗した場合の扱いは「決めていないこと」の既定に従う
4. 台帳が報告した3件（配布するスキルの定義2本と納品先の入口の文書）を実際に検査し、不合格が0件になることを確認する
5. 括弧の中で「例」「参照」「理由」を使う文が不合格にならないことを確かめる自己テストケースを追加する
6. 文書を指す語を宣言なしで短縮形だけに使った文は従来どおり不合格になることを確かめる既存の自己テストケースが引き続き通ることを確認する
7. 検出の条件（文書を指す語の一覧）は、検査スクリプトの中ではなく定義ファイルの側に置く。スクリプト本体はハードコードした語彙リストを持たない形にする

## 4. 完了の判定

1. 文書を指す語の定義ファイルが実在する
2. 検査スクリプトが定義ファイルのパスを参照している
3. 検査スクリプトの自己テストが通る
4. 配布物が納品する資産だけを含む出力先（README.md・dev-flow/SKILL.md・importing-rule-proposals/SKILL.mdの3件）で本検査を実施する。不合格が0件になる

## 5. 触らない範囲

- `document-writing.md`「他文書への参照の短縮」節が定める記法そのもの（初出での宣言・以後は短縮形を使う規則）
- 文書を指す語を宣言なしで短縮形だけに使った場合に不合格とする既存の判定ロジック
- `docs/design/納品完了の条件.md`第3段の判定キー`docs-shorthand-reference`の定義
- `_has_declaration`関数（宣言文の判定ロジック）

## 6. 決めていないこと

| 何を決めるか | 既定（担当者はこの値を選ぶ） | 覆すときの条件 |
|---|---|---|
| 検出の条件を絞る方向を採るか、配布物の資産を検査対象から除外する方向を採るか | 検出の条件を絞る方向（文書を指す語をラベルが含む場合だけ短縮参照とみなす）を採る。この方向は配布物自身の3件だけでなく、今後どの対象プロジェクトでも起こりうる同種の誤検知（「例:」「参照:」等の一般的な補足表現）を一括で解消できる。資産を除外する方向は今回の3件にしか効かず、配布する資産が増えるたびに除外リストを追加し続ける対症療法になる | 条件を絞っても偽陽性・偽陰性が実測で許容できない件数残ると判明した場合は、配布物の資産を検査対象から除外する方向を併用する |
| 文書を指す語の一覧の初期値 | 台帳が言及する「設計書・一覧・規約・台帳」の4語を含む、拡張可能な配列とする | 実際の対象プロジェクトの短縮参照ラベルを実測し、この4語で捕捉できない正当な短縮参照が見つかった場合は語を追加する |
| 定義ファイルの読み込みに失敗した場合の扱い | 判定不能（`[UNKNOWN]`・終了コード2）として扱う。`.claude/rules/always/verification/indeterminate-result/rule.md`の規約に従う | 定義ファイルが常に存在することが別の仕組みで保証されるようになった場合は、全ラベルを対象とするフォールバックへ変更してよい |

## 8. この指示書の位置づけ

既存の短縮参照検査へ、文書を指す語による絞り込みを1つ追加するだけで完結する、単独の小さな指示書である。誤検知の原因（「例」「参照」「バッククォート直後の疑似コロン」）は既に実測で特定済みのため、設計から始める必要はなく、そのまま実装に着手できる。優先度を高としたのは、本検査が`docs/design/納品完了の条件.md`第3段の判定キーとして納品完了の可否に直結しており、誤検知が残ると納品完了の判定そのものが信頼できなくなるためである。
