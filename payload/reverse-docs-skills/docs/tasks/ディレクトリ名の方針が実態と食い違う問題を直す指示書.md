# ディレクトリ名の方針が実態と食い違う問題を直す指示書

**状態**: 着手できる
**優先度**: 中
**前提**: なし
**元の指摘**: なし

## この指示書は何か

配置の定義は「ディレクトリの名前は英数字とハイフンのみ」と定める。
実測の結果、方針（英字）を正とすることが決まった。
`project-portal/一覧` 等の直後5キーは、既に英字へ揃えられている。
ただし `project-portal/lists` と `project-portal/matrices` の
1段下（種別ごとのフォルダ名）には、まだ日本語が9件残っている。
この9件を英字へ揃える。

## なぜ必要か

実測（2026-08-24）。
`docs/tasks/work-records/2026-08-24-日本語のフォルダ名の実測.md` に、
3つの根拠それぞれを試した記録がある。

| 根拠 | 判定 |
|---|---|
| 経路の文字列での絞り込みが一致しない | 再現した |
| 場所の指定への埋め込みで変換が要る | 再現した |
| 文字の正規化で2通りに記録されうる | 再現しなかった（macOS APFS環境に限る） |

3根拠のうち2つが実際に再現した。
このため方針（英字）を正とし、実態を方針へ揃える判断をした。

`project-portal/一覧`・`project-portal/図`・`project-portal/対応表`・
`project-portal/基盤`・`project-portal/画面` の5キーは、
既に `lists`・`diagrams`・`matrices`・`foundation`・`screens` へ揃った。
`listRootException` という例外欄も削除済みである。

一方、次の実測を追加で行った。
`delivery-payload/references/portal-catalog.json` の `dir` 欄を確かめると、
`project-portal/lists` と `project-portal/matrices` の1段下に、
日本語のフォルダ名が9件残っている。

```
project-portal/lists/用語辞書
project-portal/lists/テスト観点表
project-portal/lists/メッセージ一覧
project-portal/lists/テストケース一覧
project-portal/matrices/CRUD図
project-portal/matrices/権限画面マトリクス
project-portal/matrices/権限機能マトリクス
project-portal/matrices/画面-API-テーブル対応表
project-portal/matrices/確認事項質問票
```

同じファイルの `discovery.glob` 欄も、同じ日本語の経路を持つ。
`delivery-payload/references/output-layout.json` の
`permissionFunctionMatrixHtml` にも、同じ日本語の経路が重複して書かれている。

既存の検査は、この9件を捕捉できない。
`docs/scripts/check-portal-dir-ascii.sh` は
`project-portal/` の直後だけを見る設計であり、
1段下は対象外だとコメントに明記している。
`docs/scripts/check-list-path-unified.sh` は
`project-portal/一覧` という文字列そのものだけを見る設計であり、
`project-portal/lists` 配下のフォルダ名は対象にしていない。

同じ定義ファイルには、各エントリの `kind` 値が既にある。
`kind` 値は英字であり、そのままフォルダ名として使える。

## やること

1. `delivery-payload/references/portal-catalog.json` の `dir` 欄と
   `discovery.glob` 欄を、次の対応で英字へ揃える。
   フォルダ名だけを変え、ファイル名（`.html` の前の部分）は変えない。

   | 現在のフォルダ名 | 揃える先（対応する `kind` 値） |
   |---|---|
   | `project-portal/lists/用語辞書` | `project-portal/lists/semantic-glossary` |
   | `project-portal/lists/テスト観点表` | `project-portal/lists/test-viewpoint-list` |
   | `project-portal/lists/メッセージ一覧` | `project-portal/lists/message-list` |
   | `project-portal/lists/テストケース一覧` | `project-portal/lists/test-case-list` |
   | `project-portal/matrices/CRUD図` | `project-portal/matrices/crud` |
   | `project-portal/matrices/権限画面マトリクス` | `project-portal/matrices/permission-screen` |
   | `project-portal/matrices/権限機能マトリクス` | `project-portal/matrices/permission-function` |
   | `project-portal/matrices/画面-API-テーブル対応表` | `project-portal/matrices/traceability` |
   | `project-portal/matrices/確認事項質問票` | `project-portal/matrices/confirmation-survey` |

2. `delivery-payload/references/output-layout.json` の
   `permissionFunctionMatrixHtml` を、同じ対応で
   `project-portal/matrices/permission-function/権限機能マトリクス.html` へ揃える。

3. 上記の変更に追従する生成スクリプト・見本（`generation-engine/samples/`）を
   再生成し、テンプレートと見本の同期規約
   （`.claude/rules/always/portal/template-sample-sync/rule.md`）に従う。

4. `docs/scripts/check-portal-dir-ascii.sh` のコメントが
   「1段下は `check-list-path-unified.sh` が検査する」と書いているが、
   実際には検査していない。このコメントを実態に合わせて書き直す。
   本指示書の完了の判定に新しい検査を追加するため、
   その検査名をコメントへ書く。

## 触らない範囲

- 一覧の置き場を日本語とした決定を覆さない。利用者が決めたことである
- 設計書の置き場（`docs/design/` 配下。英字である）を、この作業では扱わない
- `layout.unitTestDesignDir`（`テスト設計`）は対象外とする。
  1-208で対象キー外と決まっており、この指示書では扱わない

## 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| ファイル名（`.html` の前の部分）も英字にするか | しない。ディレクトリ名だけを英字にする。ファイル名の日本語は方針が許可しており、根拠1〜3のいずれにも該当しない | 見本の他のファイル名がすべて英字へ移った場合 |

## 他の指示書との関係

`docs/tasks/一覧の置き場が三者三様になっている問題を直す指示書.md` の
作業中に見つかった。あちらは一覧の置き場を日本語へ揃える作業であり、
既に片付いている。
`docs/tasks/一覧以外の置き場も定義と実態が食い違う問題を直す指示書.md` は
`project-portal/` 直後の4キーを英字へ揃える作業であり、既に片付いている。
本指示書は、その先に残った1段下のフォルダ名を扱う。

## この指示書の位置づけ

直後5キーの揃え直しは既に終わった。
残るのは、その1段下という狭い範囲である。
`kind` 値という既存の英字名をそのまま使えるため、
新しい名前を発明する必要はない。
