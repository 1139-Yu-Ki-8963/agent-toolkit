# 一時ファイルの置き場を指定せず検査が動かない問題を直す指示書

**状態**: 着手できる
**優先度**: 高
**前提**: なし
**元の指摘**: なし

## 1. この指示書は何か

検査スクリプトが一時ファイルを作るとき、置き場を指定せずに `mktemp` を呼んでいる。実行環境によっては既定の置き場へ書けず、検査が「判定できない」を返したまま一度も動かない。置き場を明示する形へ書き換える。

## 2. なぜ必要か

実測（2026-08-24）: 引数なしの `mktemp` は次の失敗を返した。

    mktemp: mkstemp failed on /var/folders/qb/_25w1xv13fs8lh1z_6cwmvbc0000gn/T/tmp.vWYn9QLb0g: Operation not permitted

同じ環境で置き場を明示すると成功する。

    mktemp "${TMPDIR:-/tmp}/chk.XXXXXX"   →  /tmp/claude-501/chk.xdPAWi

検査の判定不能規約（`.claude/rules/always/verification/indeterminate-result/rule.md`）は、`mktemp` の失敗を不合格と区別して `[UNKNOWN]`・終了コード2で返すことを求める。この扱い自体は正しい。ところが置き場を指定しないままだと、**その環境では常に判定不能になり、検査が一度も合否を返さない。** 実行できないことを正しく報告しながら、検査としては何も確かめていない状態が続く。

実際に、網羅の判定（`generation-engine/scripts/verification/check-coverage.sh`）の実行記録には次が残っていた。

    [UNKNOWN] 使い捨ての作業領域を作れないため判定できません（verification_env_setup が一時領域へ書き込めませんでした。実行環境の制約が原因である可能性があります）
    exit=2

実測した範囲: 引数なしで `mktemp` を呼ぶ箇所は276箇所、178ファイルにある（走査対象は `docs/scripts`・`generation-engine/scripts`・`delivery-payload/templates/rules/checkers`・`.claude/rules` の `*.sh`）。

## 3. やること

1. 走査対象の4つの置き場から、置き場を指定せずに `mktemp` を呼ぶ箇所を洗い出す
2. 各箇所を `mktemp "${TMPDIR:-/tmp}/<スクリプトの名前>.XXXXXX"` の形へ書き換える。ディレクトリを作る `mktemp -d` は `mktemp -d "${TMPDIR:-/tmp}/<スクリプトの名前>.XXXXXX"` とする
3. 既に `[UNKNOWN]`・終了コード2 で失敗を扱っている箇所は、その扱いを保つ。失敗の判定を消さない
4. まだ失敗を扱っていない箇所には、判定不能規約に沿って `[UNKNOWN]`・終了コード2 を返す扱いを足す
5. 書き換えの理由を、各スクリプトの該当箇所へコメントで残す。理由は「引数なしの `mktemp` は既定の置き場へ書こうとして失敗する環境がある（実測 2026-08-24）。素直な形へ戻してはならない」の趣旨を含める
6. 完了の判定1に使う `docs/scripts/check-mktemp-placement.sh` を新設する。判定の式に縦棒（`|`）が入るため、指示書の表へ直接書けない。判定不能規約（`.claude/rules/always/verification/indeterminate-result/rule.md`）に沿って `mktemp` を扱う

## 4. 完了の判定

1. `bash docs/scripts/check-mktemp-placement.sh` が終了コード0を返す（置き場を指定しない `mktemp` が0件であることを確かめる）
2. `bash generation-engine/scripts/tests/check-layer1-declarations.sh` が、着手前に測った成功本数を下回らない
3. `bash .claude/rules/always/tasks/instruction-format/check-instruction-format.sh` が終了コード0を返す
4. `bash generation-engine/scripts/verification/check-coverage.sh --output <生成物のディレクトリ>` が `[UNKNOWN]` を返さない（実行できる状態になる）

変更前の成功本数は、着手前に測って記録すること。

## 5. 触らない範囲

- 検査の判定内容（何を合格とするか）を変えない
- 判定不能（`[UNKNOWN]`・終了コード2）の扱いを消さない
- `LC_ALL` の指定を増減しない
- 走査対象の4つの置き場の外を変更しない

## 6. 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| 置き場の名前に何を使うか | スクリプト自身の名前（`$(basename "${BASH_SOURCE[0]}" .sh)`）を使う | 同じスクリプトが同時に複数の一時ファイルを作り、名前で見分けたい場合は用途を足す |
| 276箇所を一度に直すか分けるか | 一度に直す。置き換えの形が同じで、分けると途中の状態が混ざる | 1つのコミットが大きすぎて読めない場合は、走査対象の置き場ごとに分ける |
| 共通のヘルパー関数を作るか | 作らない。各スクリプトの中で完結させる | 同じファイルの中で3箇所以上使う場合はそのファイル内にヘルパーを置く |

## 7. 他の指示書との関係

`docs/tasks/mktemp失敗を判定不能として区別する指示書.md` が既にある場合、そちらは「失敗をどう扱うか」を定め、本指示書は「そもそも失敗しないようにする」を扱う。両者は重ならない。本指示書の作業を先に行うと、あちらの対象箇所で判定不能が起きなくなる。

## 8. この指示書の位置づけ

検査そのものの中身ではなく、検査が動く条件を扱う。動かない検査は、合格を返さないだけでなく、不合格も返さない。何も確かめていないことに気づけない状態を断つ。
