## この指示書は何か

スキルガイドのブロック要素が同じ行へ連結された状態を、検査で確実に検出し、規約どおり行ごとに分ける。
検査を先に直して既存違反による不合格を確認した後、全ガイドを自動整形する。

## なぜ必要か

2026-08-23 の実測では、`.claude/skills/` 配下の 52 件の `guide.html` にブロック要素の連結が 1,540 箇所あった。
一方、`apply-guide-style.sh --self-test` の検査8は終了コード 0 を返した。

現行の検出式は、対象タグの集合に `td` と `th` を含めていない。
そのため、`<tr><td>` や `</td><td>` のような表セルの連結を検出できない。
検査が偽陰性のままでは、整形処理を適用しても規約違反が残っていないことを機械で保証できない。

## やること

1. `generation-engine/scripts/skill-guide/apply-guide-style.sh` の検査8が偽陰性になる理由を特定する。
   ブロック要素の開きタグが同じ行へ連結された並びを検出できるようにする
2. ガイドを整形する前に `--self-test` を実行し、既存違反に対して終了コード 1 を返すことを確認する
3. 同スクリプトへ、`style` の外側にあるブロック要素の開きタグを行ごとに分け、入れ子の深さに応じて空白 2 個ずつを付ける整形処理を追加する
4. 52 件の `guide.html` へ整形処理を適用する
5. 機械検査と、1 件のガイドについて整形前後のタグの入れ子・本文を比較する
6. 変更ファイルを 1 件ずつ `git add` で列挙し、指定されたメッセージでコミットする

## 完了の判定

1. 自己テスト内の検査8回帰ケースが、同一行の違反例を検出する
2. 52 件のガイドにある `</p><p`・`</li><li`・`</td><td`・`</tr><tr` の出現が 0 件になる
3. 整形後の `bash generation-engine/scripts/skill-guide/apply-guide-style.sh --self-test` が終了コード 0 を返す
4. `bash generation-engine/scripts/skill-guide/check-guide-script-paths.sh` が終了コード 0 を返す
5. `bash .claude/rules/always/tasks/instruction-format/check-instruction-format.sh` が不合格 0 件で終了コード 0 を返す
6. 選んだ 1 件のガイドで、整形前後のタグの入れ子と本文が一致する
7. 指定メッセージのコミット後、`git status --short` の出力が 0 行になる
