# 機能の単体テスト設計書に後埋め手段が無い問題を直す指示書

**状態**: 着手できる
**優先度**: 中
**前提**: なし
**元の指摘**: 1-72

## この指示書は何か

`scaffold-design-unit.sh`へ後埋めの手段を追加する。対象はtestフェーズのファイル（`機能テスト設計書.md`・`機能単体テスト設計書.md`等）が欠けている既存の設計単位である。宣言済みファイルを後から補う手段を追加する。基本設計フェーズには既に`--backfill-basic`がある。これと対になる仕組みを、testフェーズにも用意する。

## なぜ必要か

1-72の当初の修正は、基本設計フェーズの後埋めだけを実装した。対象は`--backfill-basic`である。`scaffold-design-unit.sh --backfill-basic`の合成検証を確認した。詳細設計が存在する54ユニット全件に、基本設計フォルダの宣言2ファイルが実在する。`check-design-unit-file-completeness.sh --self-test`でも同じ結果を確認できる。

一方、testフェーズの生成は1つの手順だけに依存している。`generating-feature-design-for-reverse-docs/SKILL.md`のPhase 4である。同Phaseは`scaffold-design-unit.sh feature test`を呼ぶ。`grep`で確認した。`scaffold-design-unit.sh`は`--backfill-basic`しか持たない。testフェーズ相当の後埋めコマンドを持たない。

このため、既存の機能ユニットが取り残される場合がある。Phase 4を経ずに生成された場合や、Phase 4が実装される前のスキル版で生成された場合である。取り残されたユニットは単体テスト設計書を持たない。指摘の再検証（2026-08-25）は「機能9件が単体テスト設計書を持たない」と報告する。この後埋め手段の欠如が原因と考えられる。

この状態は、基本設計フェーズで一度発生した問題（一部のユニットにしか生成されない）と同じ構造を持つ。基本設計フェーズ側は後埋め機構で解消したが、testフェーズ側には同じ機構が用意されていない。

## やること

1. `design-unit-layout.json`の`generationRules`へ、testフェーズ向けの後埋めルールを追加する。`sourcePhase`は`detail`、`targetPhase`は`test`とする。`eligibility`は既存ルールを踏襲する。文言は「sourcePhaseに宣言されたファイルがすべて実在する設計単位を対象とする」である
2. `scaffold-design-unit.sh`へ`--backfill-test`モードを追加する。既存の`--backfill-basic`の実装を土台にする。あちらは`generationRules.basicFromExistingDetail`を読み、詳細設計が揃っている設計単位のtestフェーズファイルをテンプレートから複製する処理である。対象フェーズを`test`に差し替える
3. `--backfill-test`は全種別（screen・api・table・batch・report・external・feature）を対象にするか、feature限定にするかを検討する。screenのtestフェーズはscaffold-screen.sh側で別に管理されているため、対象種別の絞り込みが必要になる可能性がある
4. 修正後、`scaffold-design-unit.sh --backfill-test`の合成検証を`--self-test`へ追加する。詳細設計が存在するがtestフェーズのファイルが欠けている設計単位を合成し、後埋め後に宣言ファイルが実在することを確認する
5. `check-design-unit-file-completeness.sh`がtestフェーズの欠落も検出できることを確認する。既存の`--self-test`がこの検出能力を持つか確認する。無ければ追加する

## 完了の判定

1. `bash generation-engine/scripts/scaffold-design-unit.sh --backfill-test`（または相当のオプション）が終了コード0で実行できる
2. testフェーズのファイルが欠けた合成の機能ユニットに対して後埋めを実行し、`機能単体テスト設計書.md`が実在することを`test -f`で確認する
3. `bash generation-engine/scripts/scaffold-design-unit.sh --self-test`が全件PASSで終わる
4. `bash generation-engine/scripts/tests/check-design-unit-file-completeness.sh --self-test`が全件PASSで終わる

## 触らない範囲

- `--backfill-basic`の既存実装。testフェーズ向けの新規モードとして追加し、既存モードは変更しない
- `generating-feature-design-for-reverse-docs/SKILL.md`のPhase 4手順。新規生成の経路は変更しない
- feature以外の種別のtestフェーズ運用（screenは別経路のため対象を慎重に見極める。「決めていないこと」参照）

## 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| `--backfill-test`の対象種別をfeature限定にするか、全種別にするか | api・table・batch・report・externalも含めた全種別を対象にする。screenのみ`scaffold-screen.sh`側の管理下にあるため対象から除く | screen以外の種別でも既にtestフェーズの後埋め手段が別途存在することが判明した場合、featureとその種別だけに絞る |
| 後埋め対象の判定条件（どのユニットを「testフェーズ欠落」とみなすか） | `generationRules.basicFromExistingDetail`と同じ判定式（sourcePhaseの全ファイルが実在すること）をtestフェーズにも適用する | 種別によってtestフェーズの前提条件が異なることが判明した場合、種別ごとに判定式を分ける |

## 他の指示書との関係

## この指示書の位置づけ

1-72で確立済みの後埋めパターン（`--backfill-basic`）を、testフェーズへ拡張する作業である。対象種別の絞り込みは「決めていないこと」節の既定（screen以外の全種別を対象にする）に従って進められるため、そのまま着手できる。
