## この指示書は何か

波括弧なしの変数展開（`$変数名`）の直後に全角文字（日本語の括弧・句読点等）が続くコードを、リポジトリ全体の `.sh` ファイルから洗い出し、`${変数名}` の形へ修正する。bash が変数名の続きを誤読し、`set -u` 下で `unbound variable` エラーを起こす既存の潜在バグを解消する。

## なぜ必要か

2026-08-18〜19、独立した2つの作業でこのバグが顕在化した。

1. `generation-engine/scripts/build-portal.sh` で `$RULES_ROOT（` という形（波括弧なしの変数展開の直後に全角括弧）が、`set -u` 下で `unbound variable` を起こした。担当は `${RULES_ROOT}` へ直し、なぜ波括弧が要るのかをコードコメント・詳細設計書の実装判断・指示書の判断の記録の3箇所へ残した
2. `generation-engine/scripts/scaffold-design-unit.sh` で `$token）`・`$tmpl_token）`・`$heading）` という同じ形が3箇所見つかり、同様に `${変数}` へ修正した

いずれも既存コードに元からあり、新しい処理がたまたま踏んだことで発覚した。再現の最小例:

```bash
$ bash -c 'set -u; x=hello; echo "test（$x）: done"'
bash: line 1: x：unbound variable
```

同じ形はこのリポジトリの他の場所にも残っている可能性が高い。全角括弧を使う日本語のメッセージは `.sh` ファイル全体に多数あるため、放置すると次の作業で同じクラッシュが繰り返し発生する。この現象は2箇所で独立に顕在化しており、単発の偶然ではなく再発するパターンである。

## やること

1. リポジトリ全体（`.sh` ファイル）から、波括弧なしの変数展開の直後に全角文字が続く箇所を機械的に洗い出す（「決めていないこと」の検査パターンを使う）
2. 洗い出した箇所のうち、実際に問題を再現できるもの（「決めていないこと」の判定基準に従う）を `${変数名}` の形へ修正する
3. 修正箇所へ、なぜ波括弧が要るかを1行コメントで残す（`build-portal.sh` の `${RULES_ROOT}` 修正時の先例、および `scaffold-design-unit.sh` の3箇所の先例に倣う）
4. 修正した各ファイルに `--self-test` や対応する回帰テストがあれば実行し、退行がないことを確認する

## 完了の判定

1. `grep -rnP --include='*.sh' '\$[A-Za-z_][A-Za-z0-9_]*(?=[^\x00-\x7F])' generation-engine .claude delivery-payload 2>/dev/null | wc -l` が 0 を返す（誤検出として除外したものは、この指示書の「対応の記録」に除外理由を記載したうえで対象から外してよい）
2. 修正を加えた各 `.sh` ファイルについて、対応する `--self-test` またはテストスクリプトが存在する場合、それが終了コード0で終わる

## 触らない範囲

- 変数展開のロジック自体（値の計算方法）。波括弧で囲むこと自体は変数の値を変えない
- コメント文中・ヒアドキュメント内の `$記号` の地の文（実際にシェル変数として展開されない箇所）

## 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| 検査パターンの正規表現 | `grep -rnP --include='*.sh' '\$[A-Za-z_][A-Za-z0-9_]*(?=[^\x00-\x7F])' generation-engine .claude delivery-payload` で、波括弧なしの変数展開の直後に非ASCII文字（全角文字含む）が続く形をPCRE（`grep -P`）で検出する | 誤検出が多数出て別のパターンが必要だと分かった場合、対象拡張子・対象ディレクトリを見直す |
| 誤検出（コメント中の`$`記号や、シングルクォート内で展開されない`$変数`等）の扱い | 検出した各箇所について、実際にその変数が展開される文脈（ダブルクォート内・展開される行）かどうかを確認し、展開されない箇所（シングルクォート内・コメント行）は対象から除外し、除外理由を「対応の記録」の確かめた内容へ書く | 除外の判断が難しいケースが多数出て、除外リストの管理自体が不能になった場合はパターンを絞り込む方向で見直す |
| 修正の粒度 | 1ファイルずつ機械的に `${変数}` へ置換し、既存のテスト（`--self-test`等）があれば実行して確認する。テストが無いファイルは修正後に手動でスクリプトを実行し異常終了しないことを確認する | ファイル数が非常に多く、一括の自動置換とレビューが必要だと分かった場合 |

## この指示書の位置づけ

同一の潜在バグ（波括弧なし変数展開+全角文字隣接によるunbound variableクラッシュ）が、`build-portal.sh` と `scaffold-design-unit.sh` という無関係な2つの作業で独立に顕在化した。個別修正だけで終わらせると、リポジトリ内の他の同型箇所は未修正のまま残り、次に別の作業がまた同じクラッシュを踏む。横断的な洗い出しと修正が必要なため、個別修正とは別にこの指示書を新設して追跡する。
