## この指示書は何か

このリポジトリは配布先の対象プロジェクトへ「規約の定義（`docs/rules/`）から `.claude/rules/`・`.cursor/rules/`・`AGENTS.md` 索引・hooks 登録を生成し、生成物の直接編集を禁じる」仕組みを配っている。この仕組みを、リポジトリ自身の `.claude/rules/` には適用していない。この状態を是正する方針を定める指示書である。

## なぜ必要か

このリポジトリは `generation-engine/scripts/rules/build-derived-rules.sh`・`validate-rule-definitions.sh` により「`docs/rules/<親>/<子>/rule.md` の規約定義から `.claude/rules/`・`.cursor/rules/`・`AGENTS.md` 索引・3ツール（`.claude`/`.cursor`/`.codex`）の hooks 登録を生成し、定義から派生への一方向生成のみを行い、生成物の直接編集は前提としない」という仕組みを配布先へ提供している。この生成物の手書き編集を検知する専用の検査（`check-ai-config-derivative-manual-edit.sh`）まで用意し、`delivery-payload/references/rule-taxonomy.json` には配布先向けの規約分類（親7件・子27件）を持つ。

ところが、このリポジトリ自身には `docs/rules/` が存在しない（`ls -d docs/rules` で不在を確認済み）。`.claude/rules/` 配下の規約はすべて手書きで維持されており、配布先へ求める規律（定義から生成し、生成物を直接編集しない）を自分自身には適用していない。生成物であるべきものが手書きであるため、定義と派生の対応がそもそも存在せず、配る仕組み自体がこのリポジトリで検証されていないことにもなる。

## やること

本指示書は「設計から始める」ため、判断が必要な事項は次の「決めていないこと」節へ委ねる。着手する担当者は次の順で進める。

1. 「決めていないこと」節の各事項について、既定に従って判断するか、既定を覆す場合はその理由を「判断の記録」に残す
2. 判断が固まった対象規約について、`docs/rules/<親>/<子>/rule.md` の定義を新規に書き起こす（既存の `.claude/rules/<scope>/<親>/<子>/rule.md` の本文を移し、front matter 13鍵を補う）

5. `--apply` 実行後の生成結果と、既存の手書き `.claude/rules/*/rule.md` を突合する。一致しない場合は差分の内容と、生成物を正とするか手書きを正として定義側を直すかの判断を記録する

### 差分の説明（このコミット内での変更）

`build-derived-rules.sh --apply` は `.claude/rules/*/rule.md` 以外に `.cursor/rules/*.mdc`・`AGENTS.md`・`.claude/settings.json`・`.cursor/hooks.json`・`.codex/config.toml` も同時に書き換える設計である。今回はこのリポジトリ自身の既存の hooks 登録・AGENTS.md 索引への意図しない副作用を避けるため、`--apply` は一時ディレクトリへ向けて実行し、生成された `.claude/rules/*/rule.md` の2ファイルだけを本コミットで実リポジトリへコピーした（`.cursor/`・`.codex/`・`AGENTS.md`・`.claude/settings.json` は今回変更していない）。

置き換え前の手書き原本との差分は、いずれも「冒頭に生成物notice行が追加された」「末尾（または適切な位置）に新設必須の `## 規則` 節と任意の `## このプロジェクトの規則` 節が追加された」の2点のみで、既存の本文は1文字も変更していない（`diff` で確認済み。追加行のみで削除行は0件）。

上記の置き換え前差分は初回実装時の実測記録である。その後に履歴が初期化され、現在の履歴から置き換え前の手書き原本を再構成できないため、本セッションでは追試していない。本セッションで機械的に再確認した範囲は、現在の定義から再生成した結果と現在の生成物との一致である。
