# 高速化のあとに目視へ退いた判定を戻す指示書

**状態**: 着手できる
**優先度**: 中
**前提**: 自己テストの所要時間が規約の件数に追いつかれる問題を片付ける指示書
**元の指摘**: なし

## この指示書は何か

`docs/tasks/done/` の判定のうち、確かめる手段が時間の上限を超えるために `目視` へ退いた 10 行を、コマンドへ戻す。戻せるのは、先に所要時間の問題が片付いたあとである。

## なぜ必要か

片付き判定は確かめる手段のコマンドを実際に実行し、120 秒を上限として打ち切る。`generation-engine/scripts/rules/scaffold-rule-definitions.sh --self-test` は実測で 200 秒から 345 秒かかり、必ず上限を超える。

上限を超えた行は「未確認」となり、合格も不合格も返さない。**動かないコマンドを残すより目視のほうがよい**という判断で、10 行が `目視` へ退いた。

ところが目視の行は、その指示書を恒久的に移せなくする。作業が済んでも変わらない。**退いたままにすると、10 行を含む 6 件の指示書が永久に機械で確かめ直せない。**

実測（2026-08-18・コミット `ee9b683f` 時点）で、この自己テストを確かめる手段に持つ行は次のとおりである。

| 指示書 | 行数 |
|---|---|
| 対象プロジェクトの実態を反映させる指示書 | 2 |
| 検査を規則と対応させる指示書 | 2 |
| 規約の名前を中身が読める形へ改める指示書 | 2 |
| 人とAIの分担を定める指示書 | 2 |
| 規約定義生成の本文と禁止語検査を正す指示書 | 1 |
| 独自の言葉遣いをなくす指示書 | 1 |

同時点の `docs/tasks/done/` 全体は、判定の行 191 件・目視 51 件・コマンド 140 件である。

## やること

1. **前提の指示書が片付いていることを確かめる。** `time bash generation-engine/scripts/rules/scaffold-rule-definitions.sh --self-test` の所要時間を測り、120 秒を下回ることを確認する。下回らない場合はここで止まり、実測値を記録する

2. 上の表の 6 ファイルについて、確かめる手段が `目視` の行のうち、この自己テストで確かめられるものをコマンドへ戻す。**どの行が該当するかは、各ファイルの「確かめた内容」の欄に「時間の上限」または「目視へ変えた」旨の記述があるかで見分ける**

3. 戻したコマンドを **1 件ずつ実走し、120 秒以内に終わることと終了コードを確かめる**

4. **セル内のパイプは `\|` とエスケープする。** しないと表の列が増えて壊れる

## 触らない範囲

- `generation-engine/` 配下。所要時間の短縮は前提の指示書が担う
- 判定表の「判定」「状態」「コミット」「確かめた内容」の 4 列。戻すのは「確かめる手段」の欄だけである
- 文面の評価にあたる目視。時間の上限とは無関係であり、戻す対象ではない

## 他の指示書との関係

`自己テストの所要時間が規約の件数に追いつかれる問題を片付ける指示書` が所要時間を縮める。本指示書はそのあとに、退いた判定を戻す。**順序を逆にすると、戻した直後にまた上限を超えて目視へ退くことになる。**

`目視の判定を機械で確かめる形へ移す指示書` は、時間とは別の理由で目視になっていた行を扱う。本指示書は時間の上限が理由の行だけを扱う。

## この指示書の位置づけ

所要時間の短縮と、退いた判定の復帰は、片方だけでは意味を持たない。短縮しても戻さなければ目視のまま残り、戻しても短縮していなければまた退く。**依存の向きが一方向であるため、前提を持つ別の指示書として切った。**
