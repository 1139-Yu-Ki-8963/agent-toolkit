## 観点ごとの結果

### 1. mktemp失敗を判定不能として区別しているか

**結果: 見つからない。**

新規スクリプトは `generation-engine/scripts/check-portal-entry-freshness.sh` である。

self-test用の `mktemp -d` を144〜147行目で検査している。

通常実行用の `mktemp` は227〜230行目で検査している。

失敗時はどちらも `[UNKNOWN]` を出し、終了コード2を返した。

`generation-engine/scripts/tests/check-dev-flow-completion.sh` の165行目にも `mktemp` がある。

ただし、この行は今回のマージで新しく書かれた行ではない。

実行結果は「実行したコマンドと出力」の `mktemp失敗` を参照する。

### 2. 素直でない実装に理由のコメントがあるか

**結果: 見つかった。2件。**

#### 2-1. 環境変数による受け渡しの理由が無い

- 場所: `generation-engine/scripts/check-portal-entry-freshness.sh` 138行目
- 内容: `TARGET_REPO`、`OUTPUT_ROOT`、`REVERSE_DOCS_ENGINE` を環境変数として `sh -c` へ渡している
- 誤りの理由: 実装判断記録規約は、環境変数での受け渡しを「素直でない実装」としている。該当箇所の理由コメントと `docs/design/generation-engine/<群名>/詳細設計書.md` の実装判断の両方が必要である。138行目の前後に理由コメントは無い。`docs/design/` を `check-portal-entry-freshness` で横断検索しても該当は0件だった
- 実際に動かした結果: コード抽出では、138行目だけが環境変数で受け渡していた。設計書検索は `<no match>`・grep終了コード1だった

#### 2-2. 一時ファイル経由と引用済み trap の理由が無い

- 場所: `generation-engine/scripts/check-portal-entry-freshness.sh` 227〜232行目
- 内容: 影響を受ける成果物のIDを一時ファイルで関数間に受け渡し、`printf %q` で引用した削除コマンドを trap に登録している
- 誤りの理由: 一時ファイル経由と、単純な trap の書き方を避ける処理は実装判断記録規約の対象である。該当箇所に「なぜこの形か」のコメントが無く、対応する詳細設計書にも記録が無い
- 実際に動かした結果: 227〜232行目の抽出と、上記と同じ設計書横断検索で欠落を確認した

### 3. 新しい規約や検査が既存規約と食い違っていないか

**結果: 見つかった。2件。**

#### 3-1. 表示コミット取得の判定不能を STALE としている

- 場所: `generation-engine/scripts/check-portal-entry-freshness.sh` 73〜79行目
- 内容: `find_display_commit` は表示コミット元JSONを `jq` で読めないと終了コード2を返す。しかし呼び出し側は終了コード1と2を区別せず、どちらも `[STALE]`・終了コード0へ変換する
- 誤りの理由: 判定不能規約は、実行できなかった場合を合否と区別し、`[UNKNOWN]`・終了コード2にするよう定める。スクリプト自身の4行目も、実行環境や宣言の不備だけを `[UNKNOWN]`・終了コード2にすると宣言している
- 実際に動かした結果: 有効なGitリポジトリと入口ページを作った。表示コミット元の `code-metrics.json` だけを壊れたJSONにすると、`[STALE]`・終了コード0になった

#### 3-2. 設計判断と実装判断を混同している

- 場所: 定義は `docs/rules/portal/page-conventions/rule.md` 1555行目
- 場所: 派生物は `.claude/rules/scoped/portal/page-conventions/rule.md` 1540行目
- 内容: 規則名を「生成スクリプトの実装判断の維持」としながら、置き場を「設計判断」節とし、その根拠を「スクリプトが素直でない実装を採る理由」としている
- 誤りの理由: 実装判断記録規約の91〜94行目は、設計判断を「そのスクリプトが存在してよい理由」、実装判断を「そのコードの書き方が素直でない理由」と明確に分離し、混同を禁止する。新しい規則は両者を同じ行で混同している
- 実際に動かした結果: 上記3ファイルの該当行を同じコマンドで抽出し、文言の矛盾を確認した。定義から派生物を再生成した結果は一致したため、派生時の事故ではなく定義側にある誤りである
