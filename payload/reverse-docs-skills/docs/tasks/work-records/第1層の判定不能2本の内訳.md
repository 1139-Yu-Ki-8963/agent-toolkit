## 解消できない理由

`test-project-semantic-glossary-race.sh`は、YAML入力を解析し、用語辞書を検証した。
この検査は、`project-semantic-glossary.py`のTime of Check to Time of Use対策を確かめるものだった。
Time of Check to Time of Useは、検査した時点と使用する時点の間に対象が変わる問題を指す。
`project-semantic-glossary.py`はPyYAMLでYAMLを解析したため、PyYAMLの読み込みや検証処理を省けば検査を弱めることになった。
規定の依存を導入すれば、この判定不能は解消可能だった。
今回確認した範囲では、PyYAMLを使わずに同じ検査内容を保つ簡単な代替を確認できなかった。
同等のYAML解析を別実装する変更は、この2本の扱いを整理する範囲を超えたため行わなかった。

`test-validate-semantic-glossary.sh`は、Python 3.13、PyYAML、JSON Schema検証ライブラリのjsonschemaを前提とした。
この検査は、検証報告のスキーマと多数の正常ケース、異常ケースを確かめるものだった。
依存条件を満たさないシステムPythonへの単純な切り替えでは、指定された版数条件と依存を検証する前提を保てなかった。
Python 3.13の隔離環境へ規定の依存を導入すれば、この判定不能は解消可能だった。
規定の隔離環境か、同じ依存条件を満たす`GLOSSARY_PYTHON`指定の実行可能ファイルのパスが必要だったため、今回の実行環境では`[UNKNOWN]`として残した。
