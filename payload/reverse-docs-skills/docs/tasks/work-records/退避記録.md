# リバース検証の退避記録

実行を伴う検証を省略してよいのは、実行を試みたうえで実行できなかった場合だけである。「実行が要る」という理由だけでの退避を禁じる。

## 記録の形式

1 件の退避には、次の項目を含める。

| 項目 | 内容 |
|---|---|
| 退避した項目 | 実行できなかった検証の名称 |
| 退避した日時と版 | 退避を記録した日時と、対象のコミットハッシュを全長で |
| 何をどう試したか | 実際に実行したコマンド |
| 何がどう失敗したか | 出力の要点 |
| 再実行の条件 | 何が変われば試せるようになるか |

## 記録

### スキル実装計画.md の6判定（全体-judge到達／Stage1-2プロジェクト成立／Stage2-監査PASS／Stage3-2画面SEALED／Stage4-judgeとSKILL無改訂／Stage5-一気通貫）

| 項目 | 内容 |
|---|---|
| 退避した日時 | 2026-08-18T14:11:45+0900 |
| 版 | `ba6ddaaa640b8ca365ce3fa941ad584e375137c0` |
| 試したこと | 各判定の検証想定（Stage1: 38行目 / Stage3: 56行目 / Stage4: 65・69行目）が指す実行対象を本文から特定しようとした。あわせて generation-engine/scripts/verification/prepare-verification-input.sh --help を実行し、このリポジトリが持つ疑似入力生成ツールが代替になるかを確認した |
| 失敗の内容 | 検証想定の実行対象（<対象リポジトリA>・<異種スタックリポジトリ>・<画面A>〜<画面D>）はプレースホルダのまま本文に残っており、38・56・65・69行目のいずれも具体名を持たない。実行対象が特定できないため、どのコマンドを何に対して実行するかが定まらない。prepare-verification-input.sh は delivery-payload/templates/リバース検証/ の雛形から設計文書のプレースホルダを埋めて疑似入力を作るツールであり、Stage1が要求する『調査対象となる既存コードベース』・Stage3が要求する『事実抽出の元になる原本コード』のいずれも提供しない。目的が異なるツールであり代替にならない |
| 再実行の条件 | 本文の検証想定・パイロット・収束判定へ具体的な対象リポジトリ名・画面名が記入された時 |

この見出しの下へ、退避が発生するたびに新しい項目を追記する。
