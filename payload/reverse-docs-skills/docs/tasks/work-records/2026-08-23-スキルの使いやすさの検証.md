# スキルの使いやすさの検証

## 目的と判定基準

`.claude/skills/` 配下の配布対象について、スキルの説明が初見の読み手と AI に伝わるか、定義とガイドが対になっているか、ガイドの依存先と意匠がそろっているかを検証した。

判定は次のように区別した。

- 合格：検査を実行でき、定められた条件を満たした。
- 不合格：検査を実行でき、対象に条件を満たさない箇所があった。
- 判定不能：実行環境の制約などにより検査を完了できず、対象の合否を決められなかった。不合格には数えない。

照合した規約は次の3件であり、いずれも全文を読んだ。

- `.claude/rules/always/skill-guide/html/rule.md`
- `.claude/rules/always/docs/audience-split/rule.md`
- `.claude/rules/always/verification/indeterminate-result/rule.md`

## 件数

- スキル: 52件
- `SKILL.md`: 52件
- `guide.html`: 52件

## 観点1: SKILL.md と guide.html の対応

**判定: 合格**

52スキルすべてが `SKILL.md` と `references/guide.html` の両方を持つ。

指定されたコマンドは、走査起点の `.claude/skills` 自体も `-maxdepth 1 -type d` の結果に含めるため、次の2行を出力した。これはスキルディレクトリではない起点の混入であり、配布スキルの不整合ではない。

### 実行コマンドと出力

```console
$ find .claude/skills -maxdepth 1 -type d | while read d; do
>   [ -f "$d/SKILL.md" ] || echo "SKILL.mdなし: $d"
>   [ -f "$d/references/guide.html" ] || echo "guide.htmlなし: $d"
> done
SKILL.mdなし: .claude/skills
guide.htmlなし: .claude/skills
```

- 終了コード: 0
- 標準エラー: 出力なし

## 観点2: description が初見の読み手に伝わるか

**判定: 不合格（5件）**

descriptionだけで、核心となる入力、処理、成果、または隣接スキルとの役割境界を特定できないものを不合格とした。正確なファイル名や工程の全内訳まで説明することは要求しない。

全52件の `description` を読んだ結果、次の5件は、何を入力にして何を行い、何が完了するスキルなのかを初見の読み手が判別できない。

1. `maintaining-semantic-glossary`
   - 「用語の変更を検査し、影響を分析する。」だけでは、候補・変更提案・正式用語集のどれを入力にするのか分からない。
   - 正式用語集を直接変えず、変更要求を作るスキルだと分からない。
2. `managing-semantic-glossary`
   - 「確定した用語の変更と公開を管理する。」だけでは、照会・提案審査・承認済み変更の適用・公開のどこまで担うか分からない。
   - 二者承認を条件に正式用語集を更新するスキルだと分からず、`maintaining-semantic-glossary` との役割差も判別できない。
3. `orchestrating-ai-development-setup`
   - 「工程全体」が何を含むか分からない。
   - 調査・事実抽出・設計書作成・再構築・原本照合・基準確立のどこまで統括し、何が完了状態になるか分からない。
4. `unlocking-reverse-target-screens`
   - 「疑似の接続窓口」「開通」「起動モード」が未定義である。
   - データ取得の差し替え、サーバー起動、検証URL記録、基準確立のどれを行うか分からない。
5. `running-reverse-screen-batch`
   - 「画面ごとの検証」が何を検証するか分からない。
   - 画面一覧を入力に1画面ずつ無人のコマンドライン操作（CLI）で処理し、進捗・失敗を記録するスキルだと分からない。
