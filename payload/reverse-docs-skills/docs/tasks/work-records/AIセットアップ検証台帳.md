# AIセットアップ検証台帳

ある対象アプリに対して、リバース設計スキル群でAI駆動開発のセットアップが完遂できるかを検証した記録である。2026-08-11 に着手した。対象アプリ名とローカルの絶対パスは、このリポジトリが公開同期の対象であるため記載しない。以降 `<対象アプリ>` と `<worktrees>` と `<repos>` で表す。

## 検証の構図

入口モードの機械判定は 2026-08-11 の実測で `reverse-full` を返した（ソース 621 件・画面インジケータ 113 件）。`setup-only` 経路でしか呼ばれない規約定義の配布とAIツール設定の生成は、この判定では自動的に走らない。したがって検証は次の 2 系統に分ける。

| 系統 | 内容 | 完了条件 |
|---|---|---|
| セットアップ経路 | 規約定義一式とAIツール設定（`.claude`・`.cursor`・`.codex`・`AGENTS.md`）と `docs/rules/` の新規生成 | 2 本のスクリプトと索引生成スキルを直接起動し、生成物が検査を通る |
| リバース経路 | アーキテクチャ調査から静的設計書の完成まで | 統括スキルが `docs-only` で終端する |

### 実行順序の依存

`AGENTS.md` は派生生成スクリプトも索引生成スキルも作りうる。索引生成スキルが規約索引のマーカーを含むテンプレートを置き、派生生成スクリプトがその範囲を埋めるという順序であり、逆に動かすと索引が失われる。この順序はどの文書にも書かれていない。

### 実装フローのゲートによる停止

既存のAI環境を退避した状態では、リポジトリ直下への書き込みが実装フローのゲートに阻まれた。`.claude/rules/always/project-context/flow-values.yml` が存在しないためである。セットアップ経路はこのファイルを生成しないので、ツール群だけでAI環境をゼロから作ったリポジトリは、この停止を踏む状態で納品される。今回は定義 2 件を手で補って先へ進めた。

## 検証の総括

### AI セットアップは完遂できるか

条件付きで完遂できる。生成すべき成果物は揃い、機械ゲートの大半は合格した。ただし、そのままの手順では完遂しない箇所が複数ある。

完遂を妨げる要因は 3 系統に分かれる。

1 つ目は、経路が自動でつながっていない箇所である。入口モードの判定が `reverse-full` を返すと、規約定義の配布と各 AI ツール設定の生成は自動で走らない。`AGENTS.md` と `CLAUDE.md` を作るスキルは統括から呼ばれない。実装フローの定義 2 件はどのスキルも生成しない。利用者はこれらを自分で並べる必要があり、その順序はどの文書にも書かれていない。

2 つ目は、定義と実装の食い違いである。データ形式の定義とテンプレートの実装が異なる、定義が指す配列名が実データと違う、定義が指す出力先フォルダが存在しない、定義に書かれた探索コマンドが対象範囲を絞っていない、定義が持つ対応表の値域がページの要求と合わない。いずれも担当が実装側へ合わせるか自分で規則を作って埋めており、生成物は出来るが根拠が定義に残らない。

3 つ目は、抽出の精度である。テーブル一覧のマニフェストは列数が後続のマイグレーションを追えず、外部キーは実在するものを落とし実在しないものを記録する。その検証はマイグレーション履歴と突き合わせないため素通りし、下流の設計書の検査で初めて発覚する。アイコンは共通コンポーネントで包まれた参照を拾えない。操作の抽出は特定の命名規則に依存し、API を呼ぶ画面でもシーケンス図が作られない。事実抽出は業務と無関係な呼び出しを数える。

### 検証していない範囲

動的検証（画面開通・往復検証・環境同期・基準タグ確立）は実行モードの範囲外とした。API 135 件・テーブル 34 件の全量著述は通していない。画面は 35 件中 3 件のみを対象とし、二段階の著述へ切り替わる規模の境界は跨いでいない。無人バッチの経路も通していない。

機能設計書は 25 件中 3 件のみを著述した。用語辞書の公開と、承認済み用語の保守は、承認済みの用語が存在しないため実行しなかった。

事実の記録（facts.yml・facts.lock・独立再計数の報告）は当初セッションの一時領域へ出力した。検証の完了時に `<worktrees>/<対象アプリ>/ai-setup-verification-records/facts/` へ複製し、封印の検証が通ることを確かめた。

### 検証の過程で生じた逸脱

シーケンス図の生成で、委任側の制約が定義と食い違った。定義は操作が 0 件でも空の状態のページを生成すると定めるが、委任側は生成しないよう指示した。担当は委任側の制約を優先したため、3 画面中 2 画面が未生成である。これはツールの欠陥ではなく検証の進め方の誤りである。
