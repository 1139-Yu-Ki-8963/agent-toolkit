# セッション進捗台帳

PMが周ごとに更新する。状態は「未割り振り」「割り振り済み」「報告あり」「完了」「対象外」の5つだけを使う。「対象外」は、既定を選ぶと明らかに壊れると分かった項目に使う。理由を確かめた内容へ書く。

「報告あり」は担当が終わったと言った状態、「完了」はPMがコミットと判定を確かめた状態である。この2つを混ぜない。PMが突合した項目だけを「完了」とし、突合していない項目は担当の報告のまま「報告あり」に置く。

## PMの誤りの記録

PMは最初の割り振りで、`docs/tasks/` のファイル一覧だけを見て17件を主題で2分し、両担当へ渡した。この割り振りは次の3点で誤っていた。両担当の指摘を受けて全面撤回した。

1. 完了済み11件を含んでいた。そのまま着手すると同じ検証を二度行うことになった
2. main から新しいブランチを切らせる指示だった。reverse-docs-skills-b3 の24コミットと reverse-docs-skills-1b の3本の worktree を捨てることになった
3. 「main へマージするな」と指示した。両担当がユーザーとの間で決めた統合の順番を上書きするものだった

原因は、割り振る前に各指示書の「対応の記録」節と既存のブランチを確認しなかったことである。以後、割り振りの前に完了状況と既存の作業場所を確認する。

4件目の誤りとして、作業ディレクトリの取り違えがある。PMは確認のコマンドを docs/tasks の中から実行しており、相対パスの指定がその場所を起点に解釈された。そのため docs/ が存在しないという結果と、rules 配下の差分が空という結果を得て、台帳が消えたと誤って判断し、担当の境界の根拠にも誤った出力を記録した。リポジトリの root から取り直して両方を訂正した。以後、確認のコマンドは毎回 cd でリポジトリの root へ移ってから実行する。
