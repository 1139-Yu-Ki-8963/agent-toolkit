# ブラウザを使う検査が実行できないのに不合格を返す問題を直す指示書

**状態**: 着手できる
**優先度**: 最高
**前提**: なし
**元の指摘**: なし

## 1. この指示書は何か

ブラウザを使う検査が、実行環境の制約でブラウザを起動できないとき、
不合格（終了コード1）を返している。
実行できなかったことと不合格を区別する規約に反する。
判定不能（終了コード2）を返す形へ改める。

## 2. なぜ必要か

実測（2026-08-24）。第1層の集約を通しで走らせた結果は次のとおりだった。

    途中停止の疑い 0 本 / 総ケース数 4707 件

1本を実際に走らせて原因を確かめた。

    制限のある環境:
      Error: Chrome/Chromiumの起動に失敗しました（exit 21）
      bootstrap_check_in ...: Permission denied (1100)
      open .../Crashpad/settings.dat: Operation not permitted (1)
      Failed to create socket directory.
      → 終了コード1（不合格）

    制限を外した環境:
      INFO: dark配色 / サイドバー現在地項目の文字: コントラスト比11.34
      PASS: バッジ3種とサイドバーのナビ項目が、明るい配色・暗い配色の両方で
            コントラスト比4.5以上を満たす
      → 合格

成果物には問題が無い。ブラウザを起動できなかっただけである。

判定不能規約（`.claude/rules/always/verification/indeterminate-result/rule.md`）は次を定める。

- 実行環境の状態に依存して失敗しうる操作は、その戻り値を確認する
- 確認に失敗した場合、検査対象の合否を判定せず終了コード2で終了する
- 出力に `[UNKNOWN]` ラベルを付ける
- 既存の合格・不合格ラベルへ理由を書き添えるだけの表現を使わない

14本はこれに反している。

### なぜ重大か

第1層の合格本数を品質の指標として使えない。
失敗17本のうち14本が動かなかっただけであり、成果物の欠陥を1件も表していない。

同じ根の問題を、この周で既に2回直している。

| 直した問題 | 件数 |
|---|---|
| プロセス置換を外部コマンドへ渡す形 | 9箇所 |
| 一時ファイルの置き場を指定しない形 | 80箇所 |

これが3件目である。
いずれも実行環境によって答えが変わるという同じ性質を持つ。

### 影響の範囲

同じ形の検査を数えた。

    generation-engine/scripts/tests/ の .cjs と .mjs   20本
    うちブラウザを使うもの                            15本

15本が同じ問題を抱えうる。
実測で不合格を返したのは14本であり、残る1本は別の理由で通っている可能性がある。

## 3. やること

1. `generation-engine/scripts/tests/` 配下の `.cjs` と `.mjs` のうち、
   ブラウザを使う15本を洗い出す
2. 各本について、ブラウザの起動に失敗したときの扱いを調べる
3. 起動に失敗したとき、`[UNKNOWN]` と理由を出して終了コード2で終える形へ改める。
   理由には、ブラウザを起動できなかったこと・実行環境の制約が原因でありうることを含める
4. 起動に成功した後の判定は変えない。合格・不合格の判定はそのまま保つ
5. 共通の処理になる場合、1本のヘルパーへ集約してよい。
   集約する場合は置き場を `generation-engine/scripts/tests/` の下とする
6. 第1層の集約（`run-layer-machine-checks.sh`）が、終了コード2を
   「判定不能」として数えることを確かめる。数えていなければ集約の側も直す
7. 判定の式に縦棒（`|`）が入る場合はスクリプトへ切り出す。
   名前は `docs/scripts/check-browser-test-unknown.sh` とし、
   この指示書を実行する担当が作る

## 4. 完了の判定

1. `bash docs/scripts/check-browser-test-unknown.sh` が終了コード0を返す
2. `bash docs/scripts/check-browser-test-unknown.sh --self-test` が終了コード0を返す
3. 制限のある環境で第1層の集約を走らせたとき、失敗の本数が3本以下になる
   （14本が判定不能へ移るため）
4. 制限のある環境で第1層の集約を走らせたとき、判定不能の本数が16本以上になる
   （元の2本＋14本）
5. 制限を外した環境で第1層の集約を走らせたとき、成功の本数が着手前を下回らない
6. `bash .claude/rules/always/tasks/instruction-format/check-instruction-format.sh` が
   終了コード0を返す

条件3〜5の着手前の値は次である（2026-08-24 実測、main のコミット `d17d6b3`）。

    制限のある環境: 対象 186 本 / 成功 167 本 / 失敗 17 本 / 判定不能 2 本

## 5. 触らない範囲

- ブラウザの起動に成功した後の判定を変えない。合格・不合格の基準はそのまま
- ブラウザを使わない検査を変えない
- 第1層の集約の収集条件（どの検査を対象にするか）を変えない
- 他の指示書を変更しない

## 6. 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| 共通のヘルパーへ集約するか | 集約する。15本が同じ処理を持つため | 本ごとに起動の仕方が違い、共通化すると分岐が増えると分かったとき |
| ヘルパーの置き場 | `generation-engine/scripts/tests/` の下 | 集約の収集対象に入って誤って実行されると分かったとき |
| 判定不能の理由の文面 | 「ブラウザを起動できないため判定できません（実行環境の制約が原因である可能性があります）」 | 起動の失敗に複数の原因があり、区別する必要があると分かったとき |
| 15本すべてを一度に直すか | 一度に直す。同じ書き換えであり、分けると途中の状態が混ざる | 1本ずつ起動の仕方が違い、一括では直せないと分かったとき |

## 7. 他の指示書との関係

`docs/tasks/一時ファイルの置き場を指定せず検査が動かない問題を直す指示書.md` と同じ根を持つ。
あちらは一時ファイルの置き場、本指示書はブラウザの起動である。
どちらも実行環境によって答えが変わるという性質を扱う。
対象のファイルは重ならない。

## 8. この指示書の位置づけ

検査そのものの中身ではなく、検査が動く条件を扱う。
動かなかったことを不合格として数えると、成果物に問題が無いのに品質が低いと読める。
逆に、本当の不合格が14件の中に埋もれても気づけない。
