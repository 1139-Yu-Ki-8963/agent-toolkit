## この指示書は何か

3種別の詳細ページが、`build-detail-page.sh`の手順どおりに生成すると戻るリンクを解決できない問題を直す指示書である。対象は`design-system`・`component-inventory`・`icon-catalog`である。

## なぜ必要か

戻るリンクの決め方は共通エンジン（`generation-engine/scripts/detail-pages/build-detail-page.sh`、844〜852行目）にある。`--portal-dir`の有無で戻るリンクを決める。`--portal-dir`が無い場合、`release-notes`だけ`../index.html`を使う。他は`index.html`を使う。

詳細ページを作る10本のスキルのうち、`build-detail-page.sh`を直接呼ぶのは9本である。`generating-sequence-diagram-for-reverse-docs`はこの共通エンジンを使わないため対象に含めない。9本すべてのSKILL.mdを検査した。`--portal-dir`を渡す記述は0件だった。

9本のうち6本は`build-portal.sh`が自身の手順の中で`--portal-dir`付きに作り直す。対象は`entity-state`・`er`・`transition`・`techstack`・`env`・`release-notes`である。この6本はSKILL.mdの手順単体では壊れたリンクを生む。ただし`build-portal.sh`を通す最終の成果物では直る。

残る3本（`design-system`・`component-inventory`・`icon-catalog`）には、`build-portal.sh`側に対応する作り直しの手順が無い。見本HTMLからpage-dataを取り出した。`--portal-dir`を渡さずに`build-detail-page.sh --page design-system`を実行した。生成したHTMLの戻るリンクは`href="index.html"`のままだった。`project-portal/foundation`は`project-portal`の1階層下である。正しくは`../index.html`である。

`generation-engine/samples/`配下の同名ファイルはいずれも`href="../index.html"`を持つ。これは別の作り直しの経路による結果である。SKILL.mdの手順どおりに`build-detail-page.sh`を呼んだ結果ではない。

## やること

1. 次の3本の`SKILL.md`にある`build-detail-page.sh`の呼び出しへ`--portal-dir <output_dir>/project-portal`を追加する。
   - `.claude/skills/generating-design-system-for-reverse-docs/SKILL.md`
   - `.claude/skills/generating-component-inventory-for-reverse-docs/SKILL.md`
   - `.claude/skills/generating-icon-catalog-for-reverse-docs/SKILL.md`
2. 上記1で足りない場合に備え、`build-detail-page.sh`の既定値の決め方自体も直す。他の呼び出し元（未確認の経路）が残る場合の保険でもある。`--portal-dir`が未指定でも、出力先の深さを`OUTPUT_DIR`から判定する。正しい深さの相対パスを組み立てる。
3. `docs/scripts/check-detail-page-backlink.sh`（判定用に新設済み）を実行し、3種別すべてで`../index.html`になることを確認する。
