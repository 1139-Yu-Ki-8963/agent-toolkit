# 一覧以外の置き場も定義と実態が食い違う問題を直す指示書

**状態**: 着手できる
**優先度**: 高
**前提**: なし
**元の指摘**: なし

## 1. この指示書は何か

図・対応表・基盤・画面の置き場で、配置の定義と実際の見本が食い違っている。
定義は英字、見本は日本語である。
一覧で起きていた食い違いと同じ構造が残っている。
定義に合わせて見本を英字へ揃える。

## 2. なぜ必要か

実測（2026-08-24）。
配置の定義（`delivery-payload/references/output-layout.json`）を読むと、
次の値が入っている。

    diagramDir     = project-portal/diagrams
    foundationDir  = project-portal/foundation
    matrixDir      = project-portal/matrices
    screenViewRoot = project-portal/screens

一方、実際の見本（`generation-engine/samples/project-portal/`）の中身は次である。

    index.html
    一覧
    図
    基盤
    対応表
    画面

定義は英字、見本は日本語である。

日本語のフォルダを指す箇所を数えた。
走査対象は `generation-engine/`・`delivery-payload/`・`.claude/skills/` である。

| 置き場 | 行数 |
|---|---|
| project-portal/基盤 | 66 |
| project-portal/対応表 | 27 |
| project-portal/画面 | 22 |
| project-portal/図 | 16 |
| 合計 | 131行・14ファイル |

### 日本語のフォルダ名は2つの不具合を起こす

配置の定義が挙げる3つの根拠を実測した。
記録は `docs/tasks/work-records/2026-08-24-日本語のフォルダ名の実測.md` にある。
着手前に読むこと。

| 根拠 | 判定 |
|---|---|
| 経路の文字列での絞り込みが一致しない | 再現した |
| 場所の指定への埋め込みで変換が要る | 再現した |
| 文字の正規化で2通りに記録されうる | 再現しなかった（この実行環境に限る） |

この実測を受けて、一覧の置き場は英字へ揃え直すことが決まった。
同じ判断が、残る4つの置き場にも及ぶ。

配置の定義の `directoryNamePolicy.listRootException` は、
一覧系5キーだけを例外として日本語のまま残すと明記している。
その明記は同時に、matrixDir・diagramDir・foundationDir・screenViewRoot の4キーが
例外の対象外であり、英字化の対象のままであることも述べている。

### 一覧と同じ構造である

一覧では、定義・カタログ・生成器の3者が食い違い、
片側を直すともう片側が壊れる状態が続いた。
残る4つの置き場も、定義と見本が食い違ったままである。
放置すると同じ行き来が起きる。

## 3. やること

1. 配置の定義を確かめる。
   `diagramDir`・`foundationDir`・`matrixDir`・`screenViewRoot` 以外に、
   図・対応表・基盤・画面を指すキーがあるかを調べる
2. 定義が英字であることを確かめたうえで、見本を英字の配置へ作り直す。
   日本語側のフォルダを削除し、英字側を正とする
3. `generation-engine/scripts/` 配下の日本語への言及を英字へ直す
4. `.claude/skills/` 配下の日本語への言及を英字へ直す
5. `delivery-payload/` 配下の日本語への言及を英字へ直す
6. ポータルのカタログ（`portal-catalog.json`）を確かめる。
   日本語を指す箇所があれば英字へ直す
7. 英字への統一を確かめる検査を作る。
   名前は `docs/scripts/check-portal-dir-ascii.sh` とし、
   この指示書を実行する担当が作る

検査の要件は次とする。

- `generation-engine/`・`delivery-payload/`・`.claude/skills/` を走査し、
  `project-portal/` の直後に日本語が来る箇所を検出する
- 合格なら `[PASS]` と件数、不合格なら `[FAIL]` と該当箇所を出す
- 走査対象が存在しない場合は `[UNKNOWN]` と理由を出して終了コード2
- `--self-test` を実引数として処理する
- 一時ファイルを作る場合は置き場を明示する
  （`mktemp "${TMPDIR:-/tmp}/check-portal-dir-ascii.XXXXXX"`）
- `diff` や `comm` の引数へプロセス置換（`<(...)`）を渡さない
- このスクリプト自身を走査で不合格にしない
- 設計判断を `.claude/rules/always/tasks/instruction-format/rule.md` の
  設計判断の節へ追記する（`docs/scripts/*.sh` の先例に揃える）

## 4. 完了の判定

1. `grep -rnE 'project-portal/(図|対応表|基盤|画面)' generation-engine/ delivery-payload/ .claude/skills/ | wc -l` が0を返す
2. `bash docs/scripts/check-portal-dir-ascii.sh` が終了コード0を返す
3. `bash docs/scripts/check-portal-dir-ascii.sh --self-test` が終了コード0を返す
4. `bash generation-engine/scripts/tests/test-e2e-portal.sh` の不合格が0件
5. `bash generation-engine/scripts/tests/test-portal-conventions.sh` の不合格が0件
6. `bash generation-engine/scripts/tests/check-derived-drift-ledger.sh` が終了コード0を返す
7. `bash .claude/rules/always/tasks/instruction-format/check-instruction-format.sh` が終了コード0を返す

判定1で `docs/` を走査対象から外している。
実測の記録と本指示書が経緯として日本語の経路に言及するためである。

## 5. 触らない範囲

- ファイル名の日本語を変えない。
  配置の定義は「ファイル名は日本語を使ってよい」と定めている。
  変えるのはフォルダ名だけである
- ページの中身を変えない。置き場だけを扱う
- 設計書の置き場（`docs/design/` 配下。既に英字）を変えない
- 一覧の置き場を英字へ揃える作業と重ならないようにする。あちらが先に片付くのを待つこと
- `.claude/rules/scoped/portal/page-conventions/rule.md` を直接編集しない（生成物である）

## 6. 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| 英字の名前をどうするか | 配置の定義が既に持つ値を使う（`diagrams`・`foundation`・`matrices`・`screens`）。新しい名前を作らない | 定義に対応する値が無い置き場があったとき。その場合は既存の命名に倣って決め、判断の記録へ残す |
| 見本をどう作り直すか | 日本語側を削除し、英字側を新たに作る。生成器から作り直せるものは作り直す | 手で置いた見本があり、生成器から作れないと分かったとき |
| 4つを一度に直すか | 一度に直す。同じ書き換えであり、分けると途中の状態が混ざる | 置き場ごとに事情が違い、一括では直せないと分かったとき |
| 生成物のずれ台帳の扱い | 見本を作り直したのと同じコミットで台帳を更新する | なし |

## 8. この指示書の位置づけ

一覧だけを英字へ揃えても、残る4つが日本語のままなら、同じ食い違いが残る。
定義と実態が食い違ったままだと、新しく作る場所の名前をどう付けるかが決まらない。
