# 理由の無い目視を減らす指示書

**状態**: 着手できる
**優先度**: 中
**前提**: 高速化のあとに目視へ退いた判定を戻す指示書
**元の指摘**: なし

## この指示書は何か

`docs/tasks/done/` の判定表に、理由の書かれていない `目視` が 47 件ある。1 件ずつ判定文を読み、機械で確かめられるものはコマンドへ戻し、確かめられないものには理由を書く。

## なぜ必要か

判定表の「確かめる手段」の欄に `目視` と書くと、片付き判定はその指示書を**恒久的に移せなくする。** 作業が済んでも変わらない。

実測（2026-08-18・コミット `1524823d` 時点）:

```
docs/tasks/done/ の判定の行   191 件
うち目視                       51 件
うち理由らしき記述あり           4 件
うち理由なし                   47 件
```

理由を書く義務は規約へ追加済みだが、**形の検査は `docs/tasks/` の直下だけを走査し、`done/` を見ない**（検査 9）。そのため既存の 47 件は検知されない。

さらに、51 件の判定文を全件読んだところ、**機械で確かめられるものが多数混ざっていた。**

```
13. 規約の生成と整合の検査が通る                    → そのままコマンドで表せる
11. 第 1 層の機械検証を実行し、成功以外が 0 本になる  → そのままコマンドで表せる
3. 移動した 9 件への参照が切れていない               → 文字列の走査で足りる
1. 配色の是正                                       → 既存の検査スクリプトがある
祖先が別のリポジトリである場所へ置いて実行し、4 と同じ結果になる → 既存の検査スクリプトがある
```

**目視が本来の必要を超えて逃げ道として使われている。** 放置すると、`done/` の指示書は完了したことになっているのに、その裏付けを機械で取り直せない状態が残り続ける。

実際に 2026-08-18、`done/` にある完了扱いの指示書が、その後の変更で条件を満たさなくなっている退行を 1 件検出した。禁止語が 4 件戻っていた。**目視のままなら見つからなかった。**

## やること

1. **前提の指示書が片付いていることを確かめる。** その指示書が 16 件（時間の上限で退いた 10 件と、時間と無関係な 6 件）を戻す。戻ったあとの目視の件数を実測する

2. 残る目視について、1 件ずつ判定文を読み、次のどちらかに分ける

| 分け方 | 見分け | どうするか |
|---|---|---|
| 機械で確かめられる | 走査の対象と一致の条件が判定文から特定できる | コマンドへ戻す。**実走して終了コードを確かめてから書く** |
| 機械で確かめられない | 文面の評価を要する・複数の資料の突き合わせを要する・実行環境に依存する | 「確かめた内容」の欄へ理由を書く |

3. **「1 つのコマンドにまとめられない」を理由にしてはならない。** シェルは `&&` で連結できる。実際に、この理由で目視にされていた 4 件を 2026-08-18 に連結したコマンドへ戻した

4. 置き換えるときは次を守る
   - 「判定」「状態」「コミット」「確かめた内容」の 4 列のうち、理由を書く場合だけ「確かめた内容」を変える。コマンドへ戻す場合は 4 列とも変えない
   - **セル内のパイプは `\|` とエスケープする**

### 実走で確かめた 4 件

委任元が 2026-08-19（コミット `201e2a66`）に実走し、いずれも終了コード 0 を確認した。判定文が次に当たる目視は、このコマンドへ戻せる。

| 判定文の趣旨 | 置き換えるコマンド |
|---|---|
| 規約の生成と整合の検査が通る | `bash generation-engine/scripts/rules/scaffold-rule-definitions.sh --self-test` |
| 第 1 層の機械検証を実行し、成功以外が 0 本になる | `bash generation-engine/scripts/verification/run-layer-machine-checks.sh --self-test` |
| ポータルの規約に適合する | `bash generation-engine/scripts/tests/test-portal-conventions.sh generation-engine/samples/project-portal/index.html` |
| 独自の言葉遣いが残っていない | `bash generation-engine/scripts/check-internal-jargon.sh` |

**判定文の趣旨が合うかを 1 件ずつ確かめてから当てる。** 趣旨が違う目視へ当ててはならない。当てたあと実走し、終了コードを確かめる。

### 実走したが落ちた 1 件

```
node generation-engine/scripts/tests/test-badge-nav-contrast.cjs
```

これは**実在の未達である。** サイドバーの文字のコントラスト比が 2.88・2.57 で、基準の 4.5 を下回っている。コマンド自体は正しく動いており、直っていないことを正しく表している。

このコマンドを目視の置き換えに使う場合、その判定は「実測で満たさない」となり、指示書は移せないままになる。**それでも目視より良い。** 目視は作業が済んでも移せないが、落ちるコマンドは作業が済めば自動で通る。配色の是正は `サイドバーのナビ項目文字の配色を可読性基準まで上げる指示書` が扱う。

## 他の指示書との関係

`高速化のあとに目視へ退いた判定を戻す指示書` が 16 件を戻す。本指示書はその残りを扱う。**先にあちらを済ませないと、対象が重なって二重に手を入れることになる。**

`片付き判定に実測の段階を足す指示書` が判定表を 5 列にし、確かめる手段の欄を作った。本指示書はその欄の質を上げる。

## この指示書の位置づけ

目視を減らす作業は 2 段ある。1 段目は機械で確かめられるものをコマンドへ戻すことで、対応表が確定しているものは前提の指示書が扱う。2 段目は残りを 1 件ずつ読んで分けることで、判断を要するため件数だけ多い。**判断の要否で切り分けたほうが、引き受けた側が見積もりを立てられる。**
