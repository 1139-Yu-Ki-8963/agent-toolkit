# アーキテクチャ調査書の見出しへ助詞を補う指示書

**状態**: 着手できる
**優先度**: 低
**前提**: なし
**元の指摘**: なし

## この指示書は何か

`delivery-payload/templates/リバース検証/プロジェクト共通/アーキテクチャ調査書.md` の §6 の見出しと、その直下の表のヘッダが、助詞を欠いた複合語になっている。これを助詞のある形へ書き換える。

## なぜ必要か

このテンプレートは納品先のエンジニアと AI エージェントが読む。助詞を欠いた複合語は、語と語の関係が読み手の推測に委ねられる。「実在判定」は「実在するかどうかの判定」なのか「実在すると判定されたもの」なのか、書かれた形からは決まらない。

実測で確認した該当箇所は次の2つである。初期コミットから一貫してこの形であり、途中で言い換えられたものではない。

| 行 | 現在の記述 |
|---|---|
| 85 | `## §6 ユニット種別判定` |
| 87 | `| 種別 | 実在判定 | 検出手がかり | 根拠パス |` |

## やること

1. 85 行目の見出しを、助詞のある形へ書き換える
2. 87 行目の表ヘッダの3語（実在判定・検出手がかり・根拠パス）を、それぞれ助詞のある形へ書き換える
3. 書き換えた語を参照している箇所がこのテンプレート内の他の行、または他のファイルに無いかを確かめ、あれば追従させる

書き換え後の語は担当者が決めてよい。「決めていないこと」の既定を参照する。

## 完了の判定

1. `grep -c "ユニット種別判定" delivery-payload/templates/リバース検証/プロジェクト共通/アーキテクチャ調査書.md` が 0 を返す
2. `grep -c "実在判定" delivery-payload/templates/リバース検証/プロジェクト共通/アーキテクチャ調査書.md` が 0 を返す
3. `grep -c "検出手がかり" delivery-payload/templates/リバース検証/プロジェクト共通/アーキテクチャ調査書.md` が 0 を返す
4. `grep -c "根拠パス" delivery-payload/templates/リバース検証/プロジェクト共通/アーキテクチャ調査書.md` が 0 を返す
5. `grep -rn "ユニット種別判定\|実在判定\|検出手がかり\|根拠パス" --include="*.md" --include="*.sh" --include="*.json" --include="*.html" . ` が 1 件も返さない（旧い語への参照が残っていない）
6. `bash generation-engine/scripts/tests/test-portal-conventions.sh` の失敗件数が変更前を超えない

## 触らない範囲

- `## §6` という節番号そのもの。見出しの語だけを変える
- 表の行（各種別の行とその値）。ヘッダの語だけを変える
- このテンプレート以外のファイル。ただし完了の判定 5 で旧い語への参照が見つかった場合はその追従だけ行う

## 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| 見出しの書き換え後の語 | 「ユニットの種別の判定」 | 「ユニット」を平易な日本語へ置き換える判断を同時に行う場合 |
| 表ヘッダ3語の書き換え後の語 | 「実在の判定」「検出の手がかり」「根拠のパス」 | 表の幅が広がりすぎて読みにくくなる場合 |

## 他の指示書との関係

`docs/tasks/指摘改善一覧.md` の 1-30（テンプレートの語彙をユーザーの指摘に沿って直す）の作業中に見つかった所見である。1-30 は既に完了しており、この所見は 1-30 の範囲外だったため切り離した。当初は一覧へ番号を作って足したが、一覧の番号は画像に振られたものだけを使う決まりのため、独立した指示書へ移した。

## この指示書の位置づけ

対象が 1 ファイルの 2 行に限られ、他の作業と依存しないため単独で切った。反映先が `delivery-payload/templates/リバース検証/` 配下であり、`.claude/rules/always/portal/template-sample-sync/rule.md` の規約 4 により見本の再生成は不要である。
