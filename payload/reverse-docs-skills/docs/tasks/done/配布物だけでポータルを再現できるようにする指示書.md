# 配布物だけでポータルを再現できるようにする指示書

**状態**: 着手できる
**優先度**: 高
**前提**: なし
**元の指摘**: 1-26

**優先度: 高。同じ指摘が 6 回繰り返されている。**

## 1. この指示書は何か

配布物の生成器だけで、現在のポータル一式を作れるようにする。実行する側が独自に作ったスクリプトなしで再現できる状態にする。

あわせて、自己テストの取りこぼしと、納品物に残った記入者向けの記述を片付ける。

この指示書は指示であり、実装ではない。読んだ担当者が作業する。

## 2. なぜ必要か

### 2.1 配布物だけではポータルを作れない

現在のポータルは、配布物の生成器だけでは再現できない。実行する側が独自のスクリプトを作って補っている。

**実測では、独自のスクリプト 11 本のうち 9 本は配布物で担える。残る 2 本が担えない。**

| 残っているもの | 理由 |
|---|---|
| 規約のカードを作るもの | カタログの探索が単一の経路に固定されており、複数の経路を横断できない |
| 関連図の入力を組み立てるもの | 配布物の説明に「取り込まない」と書かれている |

**これらを失うと、ポータルは再生成できない。**

### 2.2 実ブラウザの検証が自己テストで走らない

実ブラウザを操作して描画と操作を検証するテストが 2 本ある。個別に実行すれば成功する。

**ところが自己テストから呼ばれていない。**

最新の実測では、自己テストは追加の指定なしで終了コード 0 になり、67 ケース中 1 件がスキップされる。**残るのはそのスキップ 1 件だけで、スキップの案内が事実と食い違う。**

導入の処理は、対象の設定ファイルが無ければ何も試さずに戻る実装になっている。**配布物の配下にその設定ファイルは 1 つも存在しない。** それなのに「試行して失敗した」と案内される。

### 2.3 納品物に記入者向けの記述が残る

記入者向けの作業の指示を納品物の本文から除く是正が、規約の雛形に対して行われた。

**同じ形の記述が、設計文書の雛形と対応する納品の見本に残っている。**

最新の実測では、指摘された 3 語は雛形・見本とも 0 件である。**残るのは起票時に数え漏らした別の 1 件で、`delivery-payload/templates/リバース検証/プロジェクト共通/アーキテクチャ調査書.md` の 87 行目に、助詞を欠いた言い換えがある。**

### 2.4 自己テストに失敗と実質未実行が混在する

第 1 層の機械検証を実行したところ、対象 100 本のうち**失敗が 4 本**ある。

| 失敗したもの | 内容 |
|---|---|
| `extract-ai-assets.sh` | 表示の分離の契約が一致しない |
| `check-argjson-unbounded-value.sh` | 許可リスト外の引数の指定を 5 件検出 |
| `validate-manifest.sh` | 配置・環境に依存する疑いがある |
| `test-semantic-glossary-page.cjs` | 同上 |

加えて、**対象 0 件のまま終了コード 0 を返すスクリプトがある。** 成功と区別できない。

「すべてのスクリプトの自己テストが成功すること」という条件は、この状態では満たせない。

## 3. やること

### 3.1 残る 2 本を配布物へ取り込む

2.1 で挙げた 2 本を、配布物側の生成器で担えるようにする。

| 対象 | やること |
|---|---|
| 規約のカードを作るもの | カタログの探索を、複数の経路を横断できる形にする |
| 関連図の入力を組み立てるもの | 配布物の説明にある「取り込まない」という記述を見直し、取り込むか、取り込まない理由を書き直す |

**設計文書から入力を組み立てる経路は、抽出元の形式を設定で指定できる形にする。** 特定の文書構成に依存させない。

**取り込みが難しい処理については、実行する側で補うことを前提とした受け口を用意する。** 生成の前後に任意の処理を差し込む仕組みとし、その存在を配布物の説明に明記する。

### 3.2 実ブラウザの検証を自己テストへ載せる

2 本のテストを自己テストの実行対象へ加える。

あわせて次を直す。

| 直すこと | 内容 |
|---|---|
| スキップの案内 | 実際の分岐に合わせる。試していないのに「試行して失敗した」と出さない |
| 導入の経路 | 対象の設定ファイルを前提としない形に改めるか、導入の処理が到達できるようにする |
| 実行基盤の指定 | 追加の指定が要る場合は、テスト自身が指定を補うか、必要な指定を実行時のエラーで案内する |

### 3.3 納品物から記入者向けの記述を除く

`delivery-payload/templates/リバース検証/プロジェクト共通/アーキテクチャ調査書.md` の 87 行目にある、助詞を欠いた言い換えを除く。

記入時の注意が必要なら、**納品物の本文ではなく生成する側の説明に置く。**

**他の種別の雛形にも同じ形の記述が無いかを走査すること。** 見つかった場合は、この作業の範囲で除くか、別途起票するかを判断して記録する。

### 3.4 自己テストの失敗と実質未実行を片付ける

**失敗の 4 本を個別に直す。**

| 対象 | 見るところ |
|---|---|
| `extract-ai-assets.sh` | 表示の分離の契約が何と一致していないか |
| `check-argjson-unbounded-value.sh` | 検出された 5 件が本当に違反か、許可リストへ足すべきか |
| `validate-manifest.sh` | 配置・環境に依存する疑いの中身 |
| `test-semantic-glossary-page.cjs` | 同上 |

**対象 0 件で終了する場合の扱いを決める。** 成功ではなく、0 件である旨を明示して区別できる終了の状態にする。

**時間の上限に収まらないものがある場合は、上限内に収めるか、上限を要件として明示する。**

## 4. 完了の判定

次のすべてを満たすこと。

1. 配布物の生成器だけを使って、実行する側の独自のスクリプトなしにポータル一式が生成できる
2. 生成されたポータルに、規約のページ・種別ごとの一覧・対応表・関連図がすべて含まれる
3. 差し込みの受け口を用意した場合、その使い方が配布物の説明に記載されている
4. 設計文書から入力を組み立てる経路が、抽出元の形式を設定で指定できる
5. 実ブラウザの検証 2 本が、自己テストを追加の指定なしで実行したときに走る
6. その自己テストが終了コード 0 になる
7. 実行されたケース数が、この作業の前より増えている
8. スキップの案内が実際の分岐と一致する（試していないのに試行したと出さない）
9. `アーキテクチャ調査書.md` から記入者向けの記述が除かれている
10. 他の種別の雛形についても走査し、結果が記録されている
11. 第 1 層の機械検証を実行し、成功以外が 0 本になる
12. 対象 0 件のスクリプトが、成功と区別できる形で報告される
13. 時間の上限に収まらないものが無い、または上限が要件として明示されている

## 5. 触らない範囲

- 実行する側に固有の表示の調整（取り込みの対象外）
- テストが検証する機能そのものの是正
- 個々のスクリプトが検証する機能そのものの是正
- `.claude/rules/` 配下（このリポジトリ自身の規約であり、配る資産とは別）

## 6. 決めていないこと

次は、作業する担当者が決める。

1. **残る 2 本を取り込むか、受け口で補うか**。取り込みの可否を個別に判断する
2. **差し込みの受け口の形**。生成の前後のどこへ差し込めるようにするか
3. **対象 0 件の終了の状態をどう表すか**。終了コードを分けるか、出力で示すか
4. **時間の上限を要件として明示する場合の値**
5. **他の種別の雛形に同じ記述があった場合、この作業で除くか別途起票するか**
