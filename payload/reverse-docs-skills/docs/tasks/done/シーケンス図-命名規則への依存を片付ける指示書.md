# シーケンス図-命名規則への依存を片付ける指示書

**状態**: 着手できる
**優先度**: 中
**前提**: なし
**元の指摘**: なし

## この指示書は何か

操作の抽出が特定の命名規則に依存し、API を呼ぶ画面でも操作が 0 件と判定されてシーケンス図が作られない問題を片付ける。`AIセットアップ検証の未決課題を片付ける指示書.md` の見送り5件の1件として起票する。

## なぜ必要か

対象画面が名前付き関数を持たず、すべて画面要素の属性へ直接書かれた無名関数である場合、`extracting-unit-facts-from-code` の⑤イベントハンドラ抽出はこれを対象に含めない（`.claude/skills/extracting-unit-facts-from-code/references/profile-screen.md` 15行目に「JSX属性そのもの・インラインアロー・Reactコンポーネント・通常ヘルパーは数えない」と既に明記されている）。この結果 `call_order` が空になり、`generating-sequence-diagram-for-reverse-docs` はシーケンス図を「操作 0 件」として生成する（`.claude/skills/generating-sequence-diagram-for-reverse-docs/SKILL.md` 120行目に既に実装済み）。

見送りとされた理由は「拾えるようにするには定義を変えて既存の検査を弱める必要がある」というものであり、実際に定義（profile-screen.md）と抽出側の緩和策（空状態の機械生成）はすでに存在する。ただし、シーケンス図生成側の定義には「なぜ0件になるか（無名関数を数えない設計に起因する）」という根本原因への言及と、「対象画面が名前付き関数を持つようになったら再検討できる」という条件が書かれていない。この記述が無いと、次にこの現象を見た担当者は「バグではないか」と誤認し、同じ調査をやり直すことになる。

## やること

### いま実装できる緩和策

緩和策（呼び出しが0件の区分を機械的に空状態で出力する）は `.claude/skills/generating-sequence-diagram-for-reverse-docs/SKILL.md` 120行目に既に実装済みである。新たな実装は不要。

### 限界を明示する記述の追加

`.claude/skills/generating-sequence-diagram-for-reverse-docs/SKILL.md` の該当箇所（120行目付近、「facts.yml が実在し、call_order を持つ handler が 1 件もない画面は」の文の直後）へ、次の趣旨の1文を追加する。

> 操作が0件になる主な原因は、対象画面のイベントハンドラがJSX属性への直接記述（インラインアロー関数等）のみで構成され、事実抽出の定義（`extracting-unit-facts-from-code` の⑤イベントハンドラ抽出）がこれを対象外とすることによる。バグではなく設計上の既知の限界である。

### 判断が変わる条件

同じ箇所、または直後に次の趣旨の1文を追加する。

> 対象画面が名前付き関数（`handle`/`on`命名の関数宣言、またはJSXイベント属性から参照される関数宣言）を持つように改修された場合、事実抽出は当該ハンドラを自動的に対象へ含めるようになり、この限界は解消する。

1. `.claude/skills/generating-sequence-diagram-for-reverse-docs/SKILL.md` に「無名関数」または「インラインアロー」を含む行が1件以上存在する（`grep -c '無名関数\|インラインアロー' .claude/skills/generating-sequence-diagram-for-reverse-docs/SKILL.md` が1以上を返す）

3. 追加した記述が「呼び出しが0件の区分」の記述と同じセクション（Phase 2 または隣接する完了条件の直前）に配置されている（目視確認。位置がずれていないことを diff で確認する）

## 触らない範囲

- `.claude/skills/extracting-unit-facts-from-code/references/profile-screen.md`（既に限界を明記済みであり、抽出の定義自体は変えない）
- 事実抽出の抽出パターン・検査ロジック（無名関数を拾えるようにする改修はしない。見送りの判断そのものは覆さない）
- `generating-sequence-diagram-for-reverse-docs` の空状態生成ロジック（Phase 2 の該当処理自体は変えず、説明文のみ追加する）
