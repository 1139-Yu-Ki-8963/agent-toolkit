# 統合先の枝の検査で作業用の枝を安定して通す指示書

**状態**: 着手できる
**優先度**: 高
**前提**: なし
**元の指摘**: 1-266

## 1. この指示書は何か

実際の書き方の検査で、作業用の枝を表す入力が検査実行元の現在の枝に依存しないようにする指示書である。統合先の枝への直接コミットを終了コード2で止める検査本体の判定は維持する。

## 2. なぜ必要か

修正前の入力集では、「作業用の枝の上でコミット」と「作業用の枝でコミット」のいずれも `cwd: REPO_ROOT` と `git commit -m x` を検査へ渡していた。修正前の `check-real-world-cases.sh` は `REPO_ROOT` を実行中のリポジトリへ置き換えたため、実際に検査する枝は入力のラベルではなく通し検査を実行した場所の現在の枝になった。

現在の `fix/branch-check` へ2入力を直接流すと、どちらも終了コード0になった。検査本体も `main`、`master`、`develop`、`trunk` だけを終了コード2にし、それ以外を終了コード0にする。一方、進行担当が実行した93件の通し検査ではこの2件が終了コード2だった。この差は、入力集が作業用の枝を用意せず実行環境の枝へ依存した場合の挙動と整合する。ただし、修正前と同じ統合先環境での直接再現は互換フックに止められたため未確認である。検査本体を緩めると、本来止めるべき統合先の枝も通るため、入力側の実行条件を固定する必要がある。

## 3. やること

1. `checker-real-world-cases.json` の作業用の枝を表す2件で、`cwd` を実行元の `REPO_ROOT` ではなく作業用ブランチ専用の印へ変える。
2. `check-real-world-cases.sh` が専用の印を検出した場合だけ、置き場を指定した一時ディレクトリへ小さなGitリポジトリを作る。
3. 一時Gitリポジトリに初期コミットと作業用の枝を用意し、専用の印をその実在パスへ置き換えて検査へ流す。各ケースの直前にリポジトリの実在と枝名を再確認し、欠落時はcleanではなく判定不能にする。
4. 一時ディレクトリを正常終了と異常終了のどちらでも残さない。削除に失敗した場合は成功として扱わず、終了コード2と対象パスを返す。
5. `check-real-world-cases.sh --self-test` に、実行元の枝に依存せず専用の作業用ブランチ入力が通るケース、削除失敗を検出するケース、準備後のリポジトリ消失を検出するケースを追加する。
6. 検査本体が持つ統合先4枝の拒否、作業用の枝の許可を変更せず、指定された完了の判定を実行する。

## 5. 触らない範囲

- `main`、`master`、`develop`、`trunk` を統合先の枝とする固定リスト
- 統合先の枝への直接コミットを終了コード2で止める判定
- `git commit` 以外のコマンドを対象外にする判定
- 検査登録の有無を通知だけにする判定
- 他のcheckerの入力と期待値
- 統合先の枝の追加指定やリポジトリごとの設定機能

## 6. 決めていないこと

| 事項 | 担当者がそのまま選べる具体的な既定 | 覆す条件 |
|---|---|---|
| 作業用ブランチ専用の印 | `WORK_BRANCH_REPO` を使う | 入力集で同名の文字列が別用途に使われている場合 |
| 一時リポジトリの作業用ブランチ名 | `fix/real-world-case` を使う | ブランチ命名規約の正本が別の固定名を要求する場合 |
| 一時領域の置き場 | `${TMPDIR:-/tmp}` の配下へ名前付きテンプレートを渡して `mktemp -d` で作る | 実行環境がその一時領域への書き込みを許可しない場合 |
| 一時リポジトリの初期履歴 | 空の初期コミットを1件作る | unborn branchを検査本体が作業用の枝として判定できる実装へ変わった場合 |
| 検査本体の修正 | 判定本体は変更せず、実際の書き方の検査の入力準備だけを直す | 作業用の枝を実在させても終了コード2になることを再現した場合 |
| 重複する2件のcleanケース | 規則の実例として両方を残し、同じ専用リポジトリへ向ける | 入力集の重複排除を別課題で行う場合 |

## 7. 他の指示書との関係

終了コード2を判定不能とコマンドエラーに分ける指示書とは独立している。進行担当が実測した終了コード2は、検査本体のコード経路と照合すると、実行元が統合先の枝だった場合の拒否と整合する。ただし、同じ統合先環境を一時複製して行う直接再現は互換フックに停止され、修正前には未確認だった。終了コードの意味の分類は変えず、入力の枝を固定して環境依存を解消する。

## 8. この指示書の位置づけ

配る検査の強さを維持したまま、実際の書き方の回帰検査を実行環境から独立させる修正である。作業用の枝を通す期待値と、統合先の枝を止める期待値を、それぞれ実在する枝で確かめられる状態にする。
