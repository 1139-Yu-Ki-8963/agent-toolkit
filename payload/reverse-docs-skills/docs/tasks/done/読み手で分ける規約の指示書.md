# 読み手で分ける規約の指示書

**状態**: 着手できる
**優先度**: 中
**前提**: なし
**元の指摘**: なし

## 1. この指示書は何か

公開する文書を、外部の読み手に向けたものと、内部の作業のためのものに分ける。分け方を置き場で決め、外部に向けたものには書いてよい内容の制限を設け、その制限を機械で検査する。

この指示書は指示であり、実装ではない。読んだ担当者が作業する。

## 2. なぜ必要か

### 2.1 実際に起きたこと

`docs/スキルの変遷.html` は、このリポジトリを知らない人が読む資料として公開された。ところが中身に次のものが混じっていた。

| 混じっていたもの | 実際の中身 |
|---|---|
| 内部の識別子 | 「節目」という章がコミット番号 8 件で構成されていた |
| 書き手の読み取り | 「変遷から読み取れること」という章が、書き手の解釈を述べていた |
| 調べ方の断り書き | 「この記録の限界」という章が、調べ方の不足を断っていた |
| 内部の確認手順 | 本文に `ls .claude/skills | wc -l` という確認のコマンドが書かれていた |
| 報告の言い回し | 「〜と読める」「〜と考えられる」「実測値」といった語 |

いずれも、作業の報告としては正しい書き方である。しかし外部の読み手にとっては、意味が取れないか、読む必要のないものである。コミット番号は外部へ出してよい情報ではない。

指摘を受けて 3 章を落とし、残る章から報告の言い回しを外した。

### 2.2 なぜ起きたか

原因は 2 つある。

1 つは、**外部に向けた文書と内部の文書を分ける線が無かったこと**である。`docs/` の直下に両方が並んでいる。

```
docs/
├── reverse-docs-overview.html     外部（全体の案内）
├── 納品物ガイド.html               外部（納品物の読み方）
├── スキルの変遷.html               外部（経緯の説明）
├── スキル一覧.html                 外部（スキルの一覧）
├── 用語集.md                       外部（言葉の説明）
├── 規約フォルダの案内.md            外部（規約の読み方）
├── 納品完了の条件.md               内部（作業の判定基準）
├── AI駆動開発セットアップ構想.md     内部（設計の構想）
├── design/                        内部（設計の記録）
├── ledgers/                       内部（作業の台帳）
└── plans/                         内部（作業の指示）
```

置き場が同じなので、書くときに読み手を意識する契機が無い。

2 つは、**書いてよい内容の制限が無かったこと**である。何を書いてはいけないかが定まっていないため、書き手ごとに判断が分かれる。機械で検査する手段も無い。

### 2.3 いま残っている同種の状態

外部に向けた資料に、報告の言い回しが残っている。

| ファイル | 件数 |
|---|---|
| `docs/スキル一覧.html` | 3 |

内部の文書にも同じ語があるが、そちらは内部の文書なので問題ではない。分ける線が無いため、この区別が機械でできない。

## 3. やること

### 3.1 置き場で分ける

`docs/` の下に、読み手ごとの置き場を作る。

| 置き場 | 読み手 | 入れるもの |
|---|---|---|
| `docs/guides/` | このリポジトリを知らない人 | 全体の案内、納品物の読み方、経緯の説明、スキルの一覧、言葉の説明、規約の読み方 |
| `docs/design/` | このリポジトリを保守する人 | 設計の記録・構想 |
| `docs/tasks/` | このリポジトリを保守する人 | 作業の指示 |
| `docs/tasks/work-records/` | このリポジトリを保守する人 | 作業の記録 |
| `docs/session-prompts/` | このリポジトリを保守する人 | 別のセッションへ渡す指示のプロンプト |

移す対象は次のとおりである。

| 現在 | 移す先 |
|---|---|
| `docs/reverse-docs-overview.html` | `docs/guides/` |
| `docs/納品物ガイド.html` | `docs/guides/` |
| `docs/スキルの変遷.html` | `docs/guides/` |
| `docs/スキルの変遷.md` | `docs/guides/` |
| `docs/スキル一覧.html` | `docs/guides/` |
| `docs/用語集.md` | `docs/guides/` |
| `docs/規約フォルダの案内.md` | `docs/guides/` |
| `docs/納品完了の条件.md` | `docs/design/` |
| `docs/AI駆動開発セットアップ構想.md` | `docs/design/` |

移したあと、`docs/` の直下にファイルを置かない。フォルダだけが並ぶ状態にする。

**移動は参照の追従を伴う。** 移す前に、各ファイルへの参照を全部洗い出すこと。`README.md`・`CLAUDE.md`・各スキルの定義・生成スクリプトが参照している可能性がある。

### 3.2 外部に向けた文書へ制限を設ける

`docs/guides/` の下に置く文書には、次を書いてはならない。

| 禁じるもの | 具体 |
|---|---|
| 内部の識別子 | コミット番号、変更依頼の番号、作業の識別子 |
| 内部の場所 | このマシンのホーム配下のパス、作業用の一時的な場所 |
| 内部の確認手順 | 数を数えるコマンド、検査を走らせるコマンド |
| 書き手の読み取り | 「〜と読める」「〜と考えられる」「〜と判断した」「〜と推測される」 |
| 調べ方の断り書き | 「実測値」「サンプリング」「未検証」「判断不能」「証拠なし」「この記録の限界」 |
| 作業の経過 | 「今回の作業で」「前回は」「差し戻し」「再実行」 |

これらは作業の報告としては正しい。**外部の読み手に向けた文書に混ぜてはならない**という制限である。

書いてよいのは、読み手がその資料を使うために要る事実だけである。

### 3.3 機械で検査する

`docs/guides/` の下のファイルを書き込む直前に、3.2 の制限へ照らして止める検査を作る。

検査の置き場は `.claude/rules/always/docs/audience-split/` とする。同じ場所に規約の本文（`rule.md`）と検査（`check-*.sh`）と回帰のテスト（`*.test.sh`）を置く。

**この置き場の作り方は、既にある規約に揃えること。** 参考にするのは次の 2 つである。

- `.claude/rules/always/skill-guide/html/rule.md`（同じ「文書の書き方」を扱う規約）
- `.claude/rules/always/portal/template-sample-sync/rule.md`（検査を持ち、フックで止める規約）

規約の本文には、既にある規約と同じ節を持たせる。背景・規約・機械強制・違反検知時の手順・プロジェクト上書き・設計判断・関連である。

検査は次の入力を受け取る形にする。フックは標準入力から書き込みの内容を渡す。

```
{"tool_name":"Write","tool_input":{"file_path":"...","content":"..."}}
```

書き込み先が `docs/guides/` の下でなければ、何もせず通す。

### 3.4 逃げ道を用意する

制限に一致するが正しい場合がある。たとえば言葉の説明の中で「実測値」という語そのものを説明する場合である。

環境変数による通過の口を1つ用意する。名前は既にある規約に揃えて `AUDIENCE_SPLIT_SKIP_REASON` とする。理由を書かなければ通らない形にする。

## 4. 完了の判定

次のすべてを満たすこと。

1. `docs/` の直下にファイルが 0 件で、フォルダだけが並んでいる
2. `docs/guides/` に外部へ向けた 7 件が入っている
3. 移動した 9 件への参照が、リポジトリ内のどこからも切れていない
4. `.claude/rules/always/docs/audience-split/rule.md` が存在し、既にある規約と同じ節を持つ
5. 検査が `docs/guides/` の下への書き込みだけを対象にする
6. 検査が 3.2 の 6 つの分類すべてを見る
7. 検査の回帰テストがあり、止まる場合と通る場合の両方を確かめている
8. `docs/guides/` の既存 7 件が、その検査を通る
9. 検査がフックとして登録され、実際に書き込みを止める
10. 逃げ道が理由なしでは通らない

## 5. 触らない範囲

- `delivery-payload/` と `generation-engine/`（納品先へ配るものであり、読み手が異なる）
- `.claude/skills/` の各定義とガイド（別の規約 `skill-guide/html` が担当する）
- 内部の文書の中身（`docs/design/`・`docs/tasks/`・`docs/tasks/work-records/`）
- 公開の同期の定義（読み手で分けても、公開する範囲は変えない）

## 8. この指示書の位置づけ

外部に向けた資料に内部の記述が混じった実例が 1 件あり、同種の状態が別の 1 件に残っている。個別に直しても、書く人が変わればまた起きる。置き場と制限と検査の 3 つで、起きない形にする。
