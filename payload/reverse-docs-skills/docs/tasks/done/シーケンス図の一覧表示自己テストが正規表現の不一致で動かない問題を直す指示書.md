# シーケンス図の一覧表示自己テストが正規表現の不一致で動かない問題を直す指示書

**状態**: 着手できる
**優先度**: 中
**前提**: なし
**元の指摘**: 1-73

## この指示書は何か

自己テスト`test-sequence-kind-policy.mjs`を直す。
このテストは`unit-list-template.html`からコードを抽出する。
抽出に使う正規表現が古いコメント文言に依存している。
現在のテンプレートのコメント文言に合わせて修正する。

## なぜ必要か

対象スキルは`generating-sequence-diagram-for-reverse-docs`である。
自己テストの実体は同スキルの`scripts/test-sequence-kind-policy.mjs`である。
`node`でこれを実行すると異常終了する。
エラーは`AssertionError`である。
文言は「一覧テンプレートの関連資料表示処理を抽出できること」である。

原因を`grep`で確認した。
テストの`runActualListRelatedDocs`関数は正規表現でコードブロックを抽出する。
正規表現は`/* 1-65:`という文字列に直後続けて一致することを前提にする。

一方、`unit-list-template.html`の該当コメントは変わっている。
別の改善課題（1-250）による編集を経た。
現在の文言は`/* 1-65, 1-250: 読者向け成果物を...`である。
`1-65`の直後に`, 1-250`が挿入された。
正規表現の`1-65:`という完全一致部分が、テンプレート側の`1-65,`と一致しなくなった。
その結果、抽出が失敗する。

この自己テストは1-73の完了根拠として使われていた。
台帳には「終了コード0」という記録が残っている。
現在はこの自己テストが実行できない。
1-73が主張する内容を機械的に再確認できない状態にある。
主張の内容は2点ある。
画面以外の種別へシーケンス図生成を広げたこと。
一覧の関連資料列が非対象種別で正しく省かれること。

なお、`sequencePath`フィールドを扱うコード自体は残っている。
`unit-list-template.html`に`pathField: 'sequencePath', kind: 'sequence'`という定義がある。
`grep`で確認した。
テンプレートの機能自体は失われていない。
それを検証する自己テストの抽出条件だけが、古いコメント文言に依存したまま追従していない。

## やること

1. `test-sequence-kind-policy.mjs`の正規表現を直す。対象は`runActualListRelatedDocs`関数内の抽出処理である。コメント文言の変化に耐える形へ修正する。`1-65`の直後に任意の追記が入っても一致する形にする
2. 修正後、自己テストが正常終了することを確認する。実体パスは「なぜ必要か」節に記した`test-sequence-kind-policy.mjs`である
3. 抽出条件を安定させることを検討する。コメント文言よりも安定した目印を使う案である。候補は関数名や一意なコードパターンである
4. 同じ抽出パターンに依存する他のテストが無いか確認する。`grep -rn "1-65:"`で確認する。あれば同様に修正する

## 完了の判定

1. 自己テストの終了コードが0になる
2. 自己テストの出力にAssertionErrorという文字列が含まれない
3. `grep -rn "1-65"`の結果が、現在のテンプレートのコメント文言と一致する形になっている

## 触らない範囲

- `unit-list-template.html`のコメント文言そのもの（`/* 1-65, 1-250: ...`）。テンプレート側を書き換えるのではなく、テスト側の抽出条件を追従させる
- `sequence-kind-policy.json`の種別ごとのgenerate設定。1-73の当初の修正内容（screen・api・featureをgenerate:trueにする等）は変更しない
- `generation-engine/scripts/tests/sequence-diagram/`配下の別のシーケンス図テスト（test-sequence-diagram-lanes.mjs等）。これらは今回のPASS確認で正常動作を確認済みであり対象としない

## 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| 正規表現をコメント文言に緩く一致させるか、コメントに依存しない抽出方式へ変えるか | まずコメント文言への緩い一致で最小修正する。同じ問題が再発しやすいと判断できる根拠が無い限り、大掛かりな変更はしない | 今後もコメント文言の追記で抽出が繰り返し壊れる場合、コメント非依存の抽出方式へ切り替える |
