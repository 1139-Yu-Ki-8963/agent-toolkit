# サイドバーのナビ項目文字の配色を可読性基準まで上げる指示書

**状態**: 着手できる
**優先度**: 中
**前提**: なし
**元の指摘**: なし

## この指示書は何か

共通シェルのサイドバーで、ナビ項目のカテゴリ名（`.pt-nav-item` の文字色）が明るい配色でコントラスト比の基準（4.5対1）を下回っている。文字色の定義を、通常項目・現在地項目の両方で基準を満たす値へ改める。
### 着手の前に確かめること（2026-08-19 実測）

**配色そのものは基準を満たしている可能性が高い。** 着手の前に、この節の実測を確かめる。

明るい配色の色の値は次のとおりである（`delivery-payload/templates/tokens.css`）。

```
--sub:   #4B5A70   通常項目の文字
--navon: #102A43   現在地項目の文字
--panel3: #F7F9FC  サイドバーの背景
--accent-soft: rgba(2,132,199,0.10)  現在地項目に重ねる半透明
```

この組み合わせのコントラスト比を計算した。

| 組み合わせ | 比 | 基準 4.5 |
|---|---|---|
| `#4B5A70` と `#F7F9FC` | 6.65 | 満たす |
| `#102A43` と `#dfedf7`（半透明を重ねた実効の背景） | 12.27 | 満たす |

**どちらも基準を大きく上回る。** ところが検査（`test-badge-nav-contrast.cjs`）は 1.90 と 1.07 を報告して落ちる。

暗い配色の背景（`#161C23`）と混ぜた場合の比も計算した。

| 組み合わせ | 比 | 検査の報告 |
|---|---|---|
| `#4B5A70` と `#161C23` | 2.45 | 1.90 |
| `#102A43` と `#161C23` | 1.17 | 1.07 |

**検査の報告は、暗い背景と混ざった値に近いが一致しない。** 切り替えの途中の値を拾っていると考えると説明がつく。

なお検査の側には、切り替えの途中の値を避ける対策が 2026-08-19 に入っている（遷移の完了を待つ購読と、祖先をたどる走査）。**対策が入ってなお落ちている。** 対策が足りないか、別の原因がある。

これは別の指示書（`test-badge-nav-contrast.cjs` の切り替え直後の読み取りが途中の値を拾う問題）が扱う内容と一致する。

#### まだ確かめていないこと

検査が実際にどの背景の値を読んでいるかは、検査のコードを読んで確かめていない。上の一致は数値の近さから導いた推測である。

**着手の前に次の順で確かめる。**

1. 別の指示書（切り替え直後の読み取り）を先に片付ける
2. そのうえで `test-badge-nav-contrast.cjs` を再実行する
3. それでも落ちる場合にだけ、本指示書の配色の変更へ進む

配色を変えるとテンプレートと全サンプルの作り直しが要る（`.claude/rules/always/portal/template-sample-sync/rule.md`）。**原因が検査の側にあるなら、その作り直しは無駄になるうえ、基準を満たしている配色を壊す。**



## なぜ必要か

`generation-engine/scripts/tests/test-badge-nav-contrast.cjs`（2026-08-18新設）による実測で、`generation-engine/samples/project-portal/一覧/画面一覧/画面一覧.html`（1-49対応済みの最新サンプル）を対象に、明るい配色・暗い配色それぞれでコントラスト比を計測した。

```
通常項目の文字（.pt-nav-item:not(.is-active)、色: var(--sub)）:  明るい配色 2.88 / 暗い配色 8.06
現在地項目の文字（.pt-nav-item.is-active、色: var(--navon)）:    明るい配色 2.57 / 暗い配色 9.84
```

明るい配色で両方とも基準（4.5対1）を大きく下回る。暗い配色は基準を満たす。

基準値4.5の採用根拠: WCAG 2.1 レベルAAの通常文字に対する最小コントラスト比（SC 1.4.3）。このリポジトリでは`generation-engine/scripts/tests/test-matrix-header-compact-layout.cjs`の`CONTRAST_MIN`が既にこの値を採用しており、本件の検証も同じ基準に揃える。`docs/tasks/指摘改善一覧.md`の1-49にも反映先の指示書にも、なぜ4.5を採ったかの根拠説明は明記されていなかった（2026-08-18実測時点）。

改善課題1-49（`docs/tasks/指摘改善一覧.md`）は「バッジと補助文字」を対象とし、現在地ナビ項目の番号・件数（`.pt-nav-num`・`.pt-nav-count`）は既にコミット`94539c09`で個別に是正済みである。本件のナビ項目の文字（カテゴリ名テキスト自体）は、ナビゲーションの主たる文言でありバッジや補助文字とは性質が異なるため、1-49とは別の指示書として切り出す。

## やること

1. `.pt-nav-item` の文字色（`color: var(--sub)`）と、`.pt-nav-item.is-active` の文字色（`color: var(--navon)`）について、明るい配色時の実効コントラスト比を4.5対1以上に引き上げる値を検討する
2. 変更は `--sub`・`--navon` トークン本体（`delivery-payload/templates/tokens.css`）を変えるか、サイドバー専用の新しいトークンを`delivery-payload/templates/partials/shell.css`へ追加するかのいずれかを選ぶ。既定は後者（`--muted`/`--faint`と同様、他の使用箇所への影響を避けるため専用トークンを追加する）
3. 変更後、`generation-engine/scripts/tests/test-badge-nav-contrast.cjs` を再実行し、通常項目・現在地項目の文字がいずれの配色でも基準を満たすことを確認する
4. `.claude/rules/always/portal/template-sample-sync/rule.md` の規約に従い、テンプレート変更と同じコミットで `generation-engine/samples/` 配下の関連サンプル一式を再生成し、`bash generation-engine/scripts/check-derived-drift.sh record generation-engine/samples` を実行して台帳を更新する

## 完了の判定

1. `node generation-engine/scripts/tests/test-badge-nav-contrast.cjs` を実行し、`サイドバー通常項目の文字`・`サイドバー現在地項目の文字` の両方が明るい配色・暗い配色でコントラスト比4.5以上になり、終了コード0を返す
2. `bash generation-engine/scripts/tests/test-portal-conventions.sh` の不合格件数が変更前を超えない
3. `bash generation-engine/scripts/check-derived-drift.sh status generation-engine/samples` が台帳とのずれ0件を返す

## 触らない範囲

- `--muted`・`--faint`トークン本体（他の9箇所・4箇所で共用のため、直接変更すると影響範囲が広がる）
- バッジ（`.badge.high`/`.badge.medium`/`.badge.low`）の配色（既に基準を満たしている。1-49の対象）
- 現在地ナビ項目の番号・件数（`--nav-current-num`・`--nav-current-count`。既にコミット`94539c09`で対応済み）

## 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| `--sub`・`--navon`本体を変えるか専用トークンを新設するか | 専用トークンを新設する（`--nav-current-num`と同じパターンに揃える） | `--sub`・`--navon`の他の使用箇所を全数調査し、本体変更で影響が出ないと確認できた場合 |
| 具体的な色の値 | 決めない。実測（現在値2.88・2.57）から基準4.5をわずかに超える最小の変更幅で決める | なし |

## 他の指示書との関係

- `docs/tasks/指摘改善一覧.md` の1-49（バッジと補助文字の配色）から切り出した。1-49側は現在地項目の番号・件数の対応記録の食い違い（2026-08-18実測）を別途扱っており、本指示書はその対応と独立している

## この指示書の位置づけ

1-49は「バッジと補助文字」を対象とする課題であり、サイドバーのナビ項目の文字（カテゴリ名というナビゲーションの主たる文言）はその範囲に含まれない。対象読み手（ナビゲーションを操作する利用者全般）と修正対象（トークン定義の追加）が独立して完結するため、単独の指示書として切り出した。
