## 1. この指示書は何か

文章の検査を起動する4箇所へ子プロセスの時間上限を設け、親を失った textlint が残留しないようにする指示書である。配備側 `agent-home` へ入れた暫定対処を、受け渡し側の定義へ反映できる形で記録する。

## 2. なぜ必要か

フック登録には10秒の上限があるが、起動された textlint の子プロセスには上限が無い。2026-08-25早朝には6件が最長6時間51分、CPU約90%で残留し、負荷が22.82まで上昇した。再現時にも親を失った3件が33分48秒残ったため、親だけに依存しない停止手段が必要である。

## 3. やること

1. `dispatch-pre-bash-checks.sh` の textlint 起動4箇所を、共通の時間上限関数から起動する。
2. `set -m` で専用プロセスグループを作り、0.2秒ごとに生存を確認する。
3. 子プロセス1回を5秒、フック内の textlint 合計を8秒で打ち切り、最後の1秒を後始末用に予約してSIGTERMの0.3秒後にSIGKILLを送る。
4. docs と HTML の textlint 出力を grep、perl、sed へ流す既存のパイプを維持する。
5. 打ち切りを判定不能として通知し、commit と PR・issue 作成は止める。通知専用のコメントは従来どおり止めない。
6. わざと30秒待つ子プロセスを使う回帰テストを追加し、時間内の打ち切りと子の消滅を確かめる。
7. 設計ノートへ上限値、選定理由、判定不能時の扱いを記録する。

## 5. 触らない範囲

- textlint の文章ルールと辞書
- 追加行だけを検査する行番号の抽出
- grep、perl、sed をつなぐ既存の絞り込み
- フック登録側の10秒上限
- コメント検査を通知専用とする既存方針
- `timeout` または `gtimeout` の導入

## 6. 決めていないこと

| 何を決めるか | 既定（担当者はこの値を選ぶ） | 覆すときの条件 |
|---|---|---|
| 子プロセス1回の上限 | 5秒 | 通常入力が5秒を超える再現可能な実測を得た場合 |
| フック内の textlint 合計上限 | 8秒。最後の1秒は停止と後始末に予約する | フック登録側の10秒上限が変更され、停止と後始末に2秒を確保できなくなった場合 |
| 打ち切り時の判定 | 判定不能。commit と PR・issue 作成は止める | 判定不能結果を通してよいとする規約変更が入った場合 |
| コメント打ち切り時の扱い | 判定不能を通知し、通知専用なので通す | コメント検査を block へ変える別の指示が承認された場合 |
| 停止方法 | プロセスグループへ SIGTERM を送り、0.3秒後に SIGKILL を送る | 子孫を同時に回収できる標準機構が対象環境へ導入された場合 |
