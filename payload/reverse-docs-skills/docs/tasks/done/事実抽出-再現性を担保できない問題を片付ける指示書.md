# 事実抽出-再現性を担保できない問題を片付ける指示書

**状態**: 着手できる
**優先度**: 高
**前提**: なし
**元の指摘**: なし

## この指示書は何か

画面の事実抽出は決定的な抽出器ではなくモデルの読解で行うため、同じ入力から同じ事実が得られることの検証（再現性検証）が担当の裁量に委ねられ、3画面のうち1画面では実施できなかった問題を片付ける。`AIセットアップ検証の未決課題を片付ける指示書.md` の見送り5件の1件として起票する。

## なぜ必要か

`.claude/skills/extracting-unit-facts-from-code/SKILL.md` は Phase 5 で再現性検証（同一argsでの2回目の独立抽出とdiff比較）を既に定義している（56行目・103〜137行目）。この機構自体は実装済みだが、見送りの元記録が指摘するのは「検証の実施が担当の裁量に委ねられ、3画面中1画面で実施できなかった」という運用面の問題である。仕組みが定義されているだけでは、実行を省略しても機械的に検知できない限り、同じ省略が繰り返される。

## やること

### いま実装できる緩和策

Phase 5 の再現性検証は既に `.claude/skills/extracting-unit-facts-from-code/SKILL.md` に実装済みである（56行目「再現性の担保」・103〜137行目「Phase 5: 再現性検証」）。新たな検証ロジックの実装は不要。

行うのは「実施の有無を記録に残す」ことである。Phase 5 の完了条件に、再現性検証を実施した場合はその結果（diff空・diff有り・実施省略）を `<verification_dir>/screen-<画面ID>/facts/<run_id>/recount-report.txt` 等の既存の出力に加えて、`status` フィールドとして明示的に記録する運用を追記する。実施を省略した場合は「実施省略」とその理由を必ず書く（省略の余地自体は残すが、無言の省略を禁じる）。

### 限界を明示する記述の追加

`.claude/skills/extracting-unit-facts-from-code/SKILL.md` の Phase 5 の記述末尾へ、次の趣旨の1文を追加する。

> Phase 5 の実施は担当者の裁量に委ねられており、時間制約等により省略される場合がある。省略する場合は「なぜ省略したか」を最終報告に明記する。無言での省略を禁じる。

### 判断が変わる条件

再現性検証を無条件で必須化する（省略を一切許さない）べきかどうかは判断が要る。「決めていないこと」参照。

## 完了の判定

1. `.claude/skills/extracting-unit-facts-from-code/SKILL.md` の Phase 5 に「省略」を含む行が1件以上存在する（`grep -c '省略' .claude/skills/extracting-unit-facts-from-code/SKILL.md` が1以上）
2. 追加した記述が既存の Phase 5 セクション（103〜137行目付近）の範囲内に配置されている（diffで確認）
3. Phase 3・Phase 5 の既存の合否判定ロジック（`recount-facts.sh`・`seal-facts.sh` の呼び出し・diff比較そのもの）が変更されていない（変更前後で該当スクリプトのdiffが空であることを確認する）

## 触らない範囲

- `generation-engine/scripts/`（または対応するスクリプト群）にある `recount-facts.sh`・`seal-facts.sh` の実装ロジックそのもの
- 事実抽出の方式（モデルの読解によるものからの変更。`AIセットアップ検証の未決課題を片付ける指示書.md` の触らない範囲を継承する）
- 独立再計数の乖離許容5%等、既存の閾値

## 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| 再現性検証（Phase 5）を無条件必須にするか、省略可能なまま理由記録のみ求めるか | 省略可能なまま理由記録のみ求める。無条件必須にすると、時間制約が厳しい実行環境で工程全体が止まるリスクがある | 省略の理由記録を運用した結果、無言省略と同程度に理由が形骸化する（「時間が無いため」のような無内容な記録が繰り返される）と分かった場合、無条件必須化を検討する |
