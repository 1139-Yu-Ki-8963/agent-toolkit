# 検証スクリプト群の自己テストと配布物再現を正す指示書

**状態**: 着手できる
**優先度**: 中
**前提**: なし
**元の指摘**: 1-26, 1-52

## この指示書は何か

第1層の機械検証（`generation-engine/scripts/verification/run-layer-machine-checks.sh` が集約する自己テスト群）の失敗・実質未実行の混在（対象: `docs/ledgers/改善課題タスク一覧.md` の 1-52）と、配布物の生成器だけでポータルを再現できるかどうかの完了条件（対象: 同 1-26）を追跡する。いずれも台帳の記録では「解消」と報告済みだが、台帳の廃止に伴い本指示書へ引き継ぐ。

## なぜ必要か

新設された第1層の機械検証を実行したところ、78本のうち成功67・失敗6・実質未実行4・時間切れ1という結果だった。横断検収条件が求める「全てのスクリプトの自己テストが成功すること」は、この状態では満たせない。配布物の生成器だけでは実行側の独自スクリプトなしにポータルを再現できず、種別別の一覧・対応表・関連図が欠けていた。いずれも検証の信頼性と配布物の自立性に関わる。

## やること

### 1-52. 検証スクリプト群の自己テストに、失敗と実質未実行が混在する

**現象（実測事実）**: 新設された第1層の機械検証を実行したところ、78本のうち成功67・失敗6・実質未実行4・時間切れ1だった。失敗6本は抽出・派生生成・一覧の検証に関わるもので、実質未実行の4本は対象0件のまま終了コード0を返すため、成功と区別できない。時間切れの1本は上限90秒に収まらなかった。横断検収条件が求める「全てのスクリプトの自己テストが成功すること」は、この状態では満たせない。

**修正内容**: 失敗6本を個別に是正する。対象0件で終了する場合は、成功ではなく0件である旨を明示して区別できる終了状態にする。時間切れの1本は上限内に収めるか、上限を要件として明示する。

**検収方法**: 第1層の機械検証を実行し、成功以外が0本であること。対象0件のスクリプトが成功と区別できる形で報告されること。

**完了条件**: 失敗6本の是正と、0件時の扱いの明示までを本項目の範囲とする。個々のスクリプトが検証する機能そのものの是正は範囲外。

### 1-26. 配布物の生成器では現在のポータルを再現できず、実行側の独自スクリプトに依存している（6回目の指摘）

**現象（実測事実）**: 現在のポータルは配布物の生成器だけでは再現できず、実行側の独自スクリプトが補っている。前回は種別別の一覧・対応表・関連図のいずれも生成されなかった。

**修正内容**: 実行側の処理を配布物側の生成器へ取り込む。設計文書から入力データを組み立てる経路は、抽出元の形式を設定で指定できる形にし、特定の文書構成に依存しないようにする。

**検収方法**: 配布物の生成器だけを使って実行側の独自スクリプトなしにポータル一式が生成できること。生成されたポータルに規約ページ・種別別一覧・対応表・関連図がすべて含まれること。

**完了条件**: 配布物の生成器だけでポータル一式が再現できること。実行側が独自に作った個々のスクリプトの取り込み可否の判断までを含む。実行側固有の表示調整の取り込みは本項目の対象外。

## 完了の判定

1. `run-layer-machine-checks.sh` を実行し、成功以外（失敗・実質未実行・時間切れ）が0本になる
2. 対象0件で終了するスクリプトは、成功と区別できる終了状態（0件である旨の明示）で報告される
3. `run-layer-full-pipeline.sh`（配布物の生成器だけを使う一気通貫）を実行し、実行側の独自スクリプトなしにポータル一式（規約ページ・種別別一覧・対応表・関連図を含む）が生成される

## 触らない範囲

- 実行側固有の表示調整の取り込み
