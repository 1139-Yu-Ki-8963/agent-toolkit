## この指示書は何か

共通文書のパス実在検査（`is_path_candidate`・`check_paths_exist`。両者とも `check-common-docs.sh` にある）に印を実装する。

印は「文書が意図的に不在を記録しているパス」を表す。印付きパスが実在した場合を不合格にする逆検査もあわせて実装する。

## なぜ必要か

リバース解析の成果物には、対象リポジトリに何が無いかを記録する必要がある。版管理の除外設定によって受領物から外れた資料、開発元にはあるが引き渡されなかった資料などである。何が外れたかを記録するには、そのパスの名前を書く以外に方法がないが、現行の検査は書いた時点でそのパスを不在として不合格にする。

加えて、`is_path_candidate` はバッククォートで囲まれた文字列のうち斜線を含むものを一律にパス候補として扱うため、応答文言のように斜線を含むだけでパスではない文字列も誤って候補になる。実際に検収済みの機能である `不在: ` 印は、この2つの問題（意図的な不在の記録・パスでない文言の誤認識）を同時に解消できる。

## やること

1. `is_path_candidate`・`check_paths_exist` へ、`不在: <相対パスまたは文言>` の形の印を判定する処理を追加する。印の書式は `check-agent-config-index.sh` が既に持つ実装（86〜116行付近）を踏襲してよい
2. 印の付いたトークンは通常のパス候補判定から外し、代わりに「実在してはいけないもの」として扱う。印付きパスが実在した場合は不合格（記録と実態の食い違い）とする
3. 印の無いパスの判定は現行と変えない（1-79の修正内容と両立させる）
4. `delivery-payload/references/common-document-definitions.json` またはテンプレート（`共通設計書.md`等の雛形）に、印の書き方の説明を追記する
5. 出力に、印を付けたパスの件数（不在記録）と、逆検査で実在を確認できた件数（不在確認）を残す。`不在記録 N 件 / 不在確認 M 件` の形式を推奨する（`check-agent-config-index.sh` の出力形式と揃える）
6. `--self-test` へ、下記「完了の判定」1〜4項目に対応する合成フィクスチャのケースを追加する。各ケースの出力メッセージは `[PASS] 1-80-<連番>: <内容>` の形式に統一する

## 完了の判定

1. 不在を表す印を付けた、実在しないパスの記述を1件含む入力で `check_paths_exist` を実行し、不合格にならない
2. 不在を表す印を付けた、実在するパスの記述を1件含む入力で `check_paths_exist` を実行し、記録と実態の食い違いとして不合格になる
3. 印の無い、実在しないパスの記述を1件含む入力で `check_paths_exist` を実行し、現行どおり不合格になる
4. 印の無い、実在するパスの記述を1件含む入力で `check_paths_exist` を実行し、現行どおり合格になる
5. `delivery-payload/references/common-document-definitions.json` またはテンプレートに印の書き方の説明があることを `grep` で確認できる
6. 印を付けたパスの件数が出力へ残る
7. self-testが終了コード0で終わる（コマンド）

## 他の指示書との関係

`共通文書パス実在検査の行範囲注記を除去する指示書`（元の指摘1-79）は別の修正である。対象は同じ `is_path_candidate`・`check_paths_exist` の2関数。

両方を同時に実装する場合は、印の判定（本項目）を行番号の除去処理（1-79）より先に評価する実装にすることを推奨する。`不在: pm/.gitignore:36-42` のような印付きかつ行番号付きの記述を、誤って行番号除去の対象にしないためである。順序の強制はしない。

## この指示書の位置づけ

`is_path_candidate`・`check_paths_exist` の欠陥のうち「意図的な不在を記録する手段が無い」という欠陥だけを対象とする。「行範囲注記の誤検出」という別の欠陥（1-79）は別指示書で扱う。両方とも同じ2関数を触るが、変更内容が独立しているため指示書を分けた。
