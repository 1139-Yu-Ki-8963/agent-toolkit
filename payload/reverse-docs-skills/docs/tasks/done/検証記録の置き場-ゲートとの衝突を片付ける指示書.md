## この指示書は何か

実行環境の実装フローのゲートは `~/Projects/` 配下のすべてを管轄するため、構想が定める「プロジェクトの外」という指定では足りず、`~/Projects/` の外まで出さないと書き込みが拒否される問題を片付ける。`AIセットアップ検証の未決課題を片付ける指示書.md` の見送り5件の1件として起票する。

## なぜ必要か

実行環境のグローバル規約（`~/.claude/rules/scoped/dev-flow/gate/rule.md` 等、実行環境側の実装フローゲート）は `~/Projects/` 配下の書き込みを一律に監視し、`flow-values.yml` が無いと書き込みを拒否する。このリポジトリの検証出力を「プロジェクトの外」という曖昧な指定で `~/Projects/` 配下の別ディレクトリに置くと、このゲートに再び捕まる。この問題自体は既に対応済みだが、なぜ `~/Projects/` の外という具体的な指定が必要なのかという理由が記録に残っていないと、次に検証出力の置き場を設計する担当者が同じ曖昧な指定（「プロジェクトの外」）へ後退させてしまう可能性がある。

## やること

### いま実装できる緩和策（実装済みの確認）

`.claude/skills/orchestrating-ai-development-setup/SKILL.md` の `verification_dir` 定義（32行目・103行目）は既に「既定値なし。`target_repo_path` の外にある絶対パスを必須とする」と定めており、`generation-engine/scripts/verification/verification-env.sh` は作業領域を `${TMPDIR:-/tmp}/reverse-verification/` 配下に固定して発番する（6行目のヘッダコメントで確認済み）。いずれも実装済みであり、新たな実装は不要である。

### 限界を明示する記述の追加

`.claude/skills/orchestrating-ai-development-setup/SKILL.md` の `verification_dir` の説明（32行目付近）に、次の趣旨の1文が無ければ追加する。

> 「プロジェクトの外」という指定だけでは、実行環境のグローバルな実装フローゲート（`~/Projects/` 配下全体を監視する）を回避できない。`~/Projects/` の外にある絶対パスを明示的に必須とすることで、このゲートとの衝突を構造的に避けている。

### 判断が変わる条件

実行環境側のグローバル規約（実装フローゲート）が `~/Projects/` 配下の対象を絞り込む方向に変更された場合、この制約は緩和されうる。ただし、これは実行環境側の変更であり、このリポジトリ側からは制御できない。
