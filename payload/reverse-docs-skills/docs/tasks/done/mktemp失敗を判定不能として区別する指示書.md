# mktemp失敗を判定不能として区別する指示書

**状態**: 設計から始める
**優先度**: 高
**前提**: なし
**元の指摘**: なし

## この指示書は何か

検査スクリプトが `mktemp` で一時ファイルを作れなかった場合、検査結果を「不合格」ではなく「判定不能」として区別できる形にする。実行環境のサンドボックス制約により `mktemp` が `Operation not permitted` で失敗する場合があり、この失敗を検査ロジックが吸収せずに素通りさせると、対象の中身に関わらず全項目が「欠落」判定になり、環境の制約が成果物の欠陥として誤読される。

## なぜ必要か

`check-instruction-format.sh` は、`STRIPPED_TMP="$(mktemp)"`（51〜58行目）でコマンド置換の戻り値をそのまま代入し、失敗時の空文字列チェックを行わない。`mktemp` が失敗すると `STRIPPED_TMP` は空文字列のままになり、`strip_fences "$file" > "$STRIPPED_TMP"`（237行目付近）は空パスへのリダイレクトとして失敗するか、意図しない挙動になる。以降の各検査（`grep` 等）は空またはリダイレクト失敗した対象を読むため、対象ファイルの実際の中身に関わらず全項目が「欠落」と判定される。

この現象は、別セッション（reverse-docs-skills-df、サンドボックスにより `/var/folders` への書き込みが拒否される環境）で実際に3回発生している（`check-portal-catalog.sh --self-test`・`check-instruction-format.sh`・今回）。同セッションはこの現象を「9件すべて不合格」という検査結果として受け取り、実際にはサンドボックスの制約だけが原因で、対象ファイルの中身は全て合格水準だった（サンドボックス制約を外した再実行では9件中9件合格）。同種の読み違いが起きるたび、環境差によるノイズと実際の不合格を切り分ける追加の手間が生じる。

## やること

対象範囲・実装方式は判断が要るため「決めていないこと」に委ねる。着手する担当者は次の順で進める。

1. 「決めていないこと」節の各事項について、既定に従って判断するか、既定を覆す場合はその理由を「判断の記録」に残す
2. 判断が固まった対象スクリプトについて、`mktemp` 呼び出し箇所へ失敗チェックを追加する。失敗時は検査全体を「不合格」として終了せず、判定不能である旨を明示する専用の終了コードまたは出力ラベルで終了する（値は「決めていないこと」で確定する）
3. 追加した失敗チェックが実際に機能するかを検証する。`mktemp` を意図的に失敗させる手段（例: `TMPDIR` を書き込み不可のパスへ一時的に向ける、または `mktemp` をラップした偽関数で失敗を強制する）で再現し、判定不能の扱いになることを確認する

### 実測（起票時点の実測。推測ではなく実際にコマンドを実行して確認した）

- `mktemp` を使うスクリプト（`.sh` ファイルのみ、`generation-engine/scripts/` と `.claude/rules/` 配下）: **120件**（`grep -rl 'mktemp' generation-engine/scripts/ .claude/rules/ | grep '\.sh$' | wc -l` で確認）
- そのうち `mktemp` 呼び出し直後に `||` による明示的な失敗チェックを持つもの: **24件**（`grep -rlE 'mktemp[^|]*\|\|' ... | grep '\.sh$' | wc -l` で確認。この24件が「失敗を判定不能として区別している」ことまでは確認していない。単に `|| exit` 等でスクリプトを止めるだけの場合も含まれる可能性があり、区別しているかどうかは個別に読む必要がある）
- 「判定不能」「測定不能」「UNKNOWN」「indeterminate」のいずれかの語を持つもの: **10件**（`grep -rlE '判定不能|測定不能|UNKNOWN|indeterminate' ... | grep '\.sh$' | wc -l` で確認。既に判定不能の概念を持つ先行例が存在する可能性を示す）
- `check-instruction-format.sh` 自体は `mktemp` の戻り値チェックを一切持たない（51〜58行目・584行目付近を実測して確認）。今回の実例（PMのセッションでの3回の誤読）はこの欠如が直接の原因である

## 完了の判定

1. `check-instruction-format.sh` の `mktemp` 呼び出し（`ensure_stripped_tmp` 関数内・584行目付近）が、失敗時に空文字列のまま処理を続行しない（`mktemp` を失敗させた状態で実行し、出力に「判定不能」に相当する語（値は「決めていないこと」で確定）が現れ、かつ既存の「不合格」ラベルが現れないことを確認する）
2. 「決めていないこと」で対象に追加したスクリプトについても、同様に `mktemp` 失敗時の判定不能扱いが機能することを確認する
3. 既存の正常系（`mktemp` が成功する通常実行）の挙動が変更されていない（変更前後で通常実行時の出力・終了コードのdiffが空であることを確認する）

## 触らない範囲

- `mktemp` 自体の呼び出し方（`-d` オプション・生成先ディレクトリ等）は変えない。失敗時の扱いのみを追加する
- 検査ロジックそのもの（節の必須判定・状態語の判定等）の中身は変えない
- サンドボックスの制約自体（実行環境側の設定）は変えない。このリポジトリ側からは制御できない

## この指示書の位置づけ

検査スクリプトが「実行できなかったこと」と「検査に不合格だったこと」を区別しない設計上の欠如を、実際に3回誤読された実例をもとに起票する。対象範囲・実装方式は担当者が決める設計判断を含むため「設計から始める」とする。
