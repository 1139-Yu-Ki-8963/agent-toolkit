# 文書テンプレートの本文表示を正す指示書

**状態**: 着手できる
**優先度**: 高
**前提**: なし
**元の指摘**: 1-30, 1-47, 1-51

## この指示書は何か

文書系テンプレート（`common-doc-template.html`・`screen-doc-template.html`・`リバース検証/` 配下のテンプレートと納品サンプル）と、それらが共通で通る描画処理（`render-template.sh`）が抱える3件の欠陥（対象: `docs/ledgers/改善課題タスク一覧.md` の 1-47・1-51・1-30）を追跡する。いずれも台帳の記録では「解消」と報告済みだが、台帳の廃止に伴い本指示書へ引き継ぐ。

## なぜ必要か

生成物の先頭に生成の内部情報（スクリプト名・内部の関数名・置換前後の値）が残るページが14ページ実測された。本文が空の資料は、単体で開いたときに未記入と分からず、読み手は「情報が欠けている」のか「調査した結果として空」なのかを区別できない。記入者向けの作業指示が本文にそのまま置かれ、納品先の読み手に向けた内容になっていない箇所が実測された。いずれも読み手が生成物の性質を誤認する原因になる。

## やること

### 1-47. 生成の内部情報を書いた注記が、一部の様式でのみ除去されず納品物に残る

**現象（実測事実）**: 生成物の先頭に、生成スクリプト名・内部の関数名・内部フィールド名・置換前後の値を列挙した注記が残るページがある。実測では14ページに残存し、内訳は一覧系・関連図・対応表・トップページである。一方で、文書の様式から生成されるページ（規約27枚など）では同じ注記が正しく除去されている。除去する仕組みは存在するが、一部の様式でのみ効いていない。トップページはさらに状態が悪く、置換前の説明文と置換後の実値が混在している。読み手には、生成の途中経過がそのまま見える。

**修正内容**: 注記の除去を、様式の種類によらず生成の共通経路で行う。除去が効いている様式の実装に揃える。トップページについては、置換前の説明文が残らないことを併せて確認する。

**検収方法**: 全ての様式から1ページずつ生成し、生成物に対して生成スクリプト名・内部の関数名・内部フィールド名の機械検索が0件であること。置換前の説明文が残っていないこと。

**完了条件**: 除去の共通経路への統合までを本項目の範囲とする。注記そのものを様式から削る対応（生成時に除去する方針を変える）は範囲外。

### 1-51. 未記入の資料が、単体で開いたときに未記入であると分からない

**現象（実測事実）**: ある資料は見出しだけがあり本文が空で、3つの表もすべて行が0件だった。トップページのカードには「雛形」と表示されるが、そのページを直接開くとその注記は見えない。読み手は「情報が欠けている」のか「調査した結果として空」なのかを区別できない。

**修正内容**: 本文が空の資料には、生成時にその旨を示す表示を入れる。空であることの判定は、見出し以外の本文と表の行が無いことで行う。

**検収方法**: 本文が空の資料を生成し、ページ内に未記入である旨の表示が現れること。本文のある資料には現れないこと。

**完了条件**: 未記入である旨の表示の追加までを本項目の範囲とする。未記入の資料そのものを埋める作業は範囲外。

### 1-30. 規約以外のテンプレートと納品サンプルに記入者向けの作業指示が残る（4回目の指摘）

**現象（実測事実）**: 記入者向けの作業指示を納品物の本文から除く是正が規約テンプレートに対して行われた。同じ形の記述が、設計文書のテンプレートと対応する納品サンプルに残っている。記入時の注意を述べる一文が本文中にそのまま置かれており、納品先の読み手に向けた内容になっていない。

**修正内容**: 規約テンプレートと同じ方針で、設計文書のテンプレートと納品サンプルからも記入者向けの指示を除く。記入時の注意が必要なら、納品物の本文ではなく生成側の説明に置く。

**検収方法**: 設計文書のテンプレートと納品サンプルに対し、記入者向けの指示にあたる定型句の機械検索が0件であること。除去後もサンプルが文書として妥当で、見出し構成が変わらないこと。

**完了条件**: 設計文書のテンプレートと対応する納品サンプルからの除去までを本項目の範囲とする。

## 完了の判定

1. 全ての文書様式から1ページずつ生成し、生成物に対して生成スクリプト名・内部の関数名・内部フィールド名の機械検索が0件になる
2. トップページに置換前の説明文が残っていない
3. 本文が空の資料を生成した際、未記入である旨の表示が現れ、本文のある資料には現れない
4. 設計文書のテンプレートと納品サンプルに対し、記入者向けの指示にあたる定型句の機械検索が0件になる
5. 除去後もサンプルの見出し構成が変わらない

## 触らない範囲

- 注記そのものを様式から削る対応（生成時に除去する方針の変更）
- 未記入の資料そのものを埋める作業
- 文書としての見出し構成の変更

## 決めていないこと

なし。

## この指示書の位置づけ

3件はいずれも「生成物の本文に納品先の読み手へ向けない情報が混入する、または情報の欠落が伝わらない」という同一系統の欠陥であり、`common-doc-template.html`・`screen-doc-template.html`・`render-template.sh`・`リバース検証/` 配下のテンプレートという重なる資産を触る。1つの指示書にまとめ、並行着手による衝突を避ける。
