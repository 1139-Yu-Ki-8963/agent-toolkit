## この指示書は何か

`docs/design/納品完了の条件.md`の「4. 判定の手順」節を直す。
第3段の判定項目のうち、手順から抜けている6項目のコマンドを追記する。
6項目は次のとおりである。
docs-required-items・docs-code-consistency・docs-cross-referenceの3件。
docs-customer-facing・docs-shorthand-reference・docs-style-registerの3件。
合わせて6件である。

## なぜ必要か

1-75の当初の修正は2点を解消した。
1点目は「対象外種別の記録」（reverse-excluded-kinds）という1項目の欠落である。
2点目は実行主体の区別が不明瞭な点である。
この2点は現在も解消されたままであることを確認した。

- `reverse-excluded-kinds`は§2の判定表にも§4の手順にも存在する。`grep`で確認した
- 実行主体の区別は2つの記法で行われている。1つは§4冒頭のブロック見出しである。もう1つは納品先向けコマンド群の直前の見出しと注記である

しかし、その後の改善課題で第3段へ6つの判定項目が追加された。
対象は1-230・1-232・1-233・1-235・1-237・1-246である。
§2の判定表には反映されたが、§4の判定の手順にはコマンドが追記されないまま残っている。

判定表とコマンドの対応を数えた。
`grep -c "| <キー> |" docs/design/納品完了の条件.md`と、§4該当範囲の`grep -c "# <キー>:"`で数えた。

| 判定キー | 判定表 | 手順のコマンド |

判定表の項目数は24件である。
§4でコマンドを持つのは18件である。
6件の差がある。
1-75が完了条件とした「条件の表の判定項目と判定の手順のコマンドが1対1で対応している」を満たしていない。

各項目に対応するコマンドは既に存在する。
§2の判定表の「判定コマンド・代替確認」列に記されている。
使うコマンドは6本ある。
実行ファイル名は「やること」節の表に一覧する。
§4への転記が漏れているだけであり、コマンド自体は既に実行可能である。

## やること

1. `docs/design/納品完了の条件.md`の「4. 判定の手順」節へ、6項目のコマンドを追記する。差し込む位置は、docs-inventoryのコマンドブロックとrules-scaffoldのコマンドブロックの間である
2. 6項目それぞれへ、見出しコメントとコマンドを1行ずつ追記する。見出しの形は`# <キー>: <判定項目名>`とする。キーと判定項目名の対応は下表のとおりである

| 判定キー | 判定項目名 | 追記するコマンド |
|---|---|---|
| docs-required-items | 詳細設計書の必須6項目 | `check-design-doc-required-items.sh <project_root>` |
| docs-code-consistency | 設計書間の記述の一致 | `check-design-code-consistency.sh <output_dir>` |
| docs-cross-reference | 文書間の節番号相互参照 | `check-doc-cross-reference.sh <output_dir>` |
| docs-customer-facing | 顧客提示文書としての適合 | `check-customer-facing-adequacy.sh <output_dir>` |
| docs-shorthand-reference | 他文書参照の短縮記法 | `check-shorthand-reference-declaration.sh <output_dir>` |
| docs-style-register | 顧客提示文書の文体 | `check-document-style-register.sh <output_dir>` |

上表のコマンド列は実行ファイル名だけを示す。
実際の呼び出しは`bash <実行ファイルの相対パス> <引数>`の形にする。
実行ファイルの置き場は§2判定表の該当行を見る。
3. 追記したコマンドが§2の判定表の「判定コマンド・代替確認」列と一致することを確認する
4. 追記後、§2の判定項目数と§4のコマンド数を再度数える。差が0になることを確認する

## 完了の判定

1. §2の判定キー行数と、§4該当範囲のコマンド見出し行数の差が0である
2. 6キーすべてが、§4の該当範囲に`# <キー>:`という見出しで存在する
3. 追記した6コマンドが、§2の判定表の該当行の「判定コマンド・代替確認」列と一致する

## 触らない範囲

- §2「5段の条件」の判定表の内容そのもの。今回は§4への転記漏れを直すだけで、判定項目・確認先・判定コマンドの定義は変更しない
- 実行主体の区別の記法（ブロック見出し・注記）。この点は既に解消されているため変更しない
- `reverse-excluded-kinds`を含む既存18項目のコマンド。追加の6項目だけを対象にする
