# 規約定義生成の本文と禁止語検査を正す指示書

**状態**: 着手できる
**優先度**: 高
**前提**: なし
**元の指摘**: 1-42, 1-48

## この指示書は何か

規約定義の生成器（`generation-engine/scripts/rules/scaffold-rule-definitions.sh`）が出す規約本文の 2 つの欠陥（対象: `docs/ledgers/改善課題タスク一覧.md` の 1-48・1-42）を追跡する。いずれも `docs/ledgers/改善課題タスク一覧.md` の記録では「解消」と報告済みだが、台帳の廃止に伴い本指示書へ引き継ぎ、対応の記録として保存する。

## なぜ必要か

宣言で「ツールが本文を定める」とされた規約が、別経路の本文で上書きされたり、納品先向けでない記述（生成の内部情報・検査できない理由の重複・設計外の節）を含んだまま出荷される欠陥が実測された。ツール側が定めたはずの内容が納品物に届かない、または納品物の本文に納品する側の都合が漏れ出すと、読み手が誤った情報を受け取る。

## やること

### 1-48. ツールが本文を定める指定を持つ規約の一部が、別経路の本文で上書きされる

**現象（実測事実）**: タクソノミの宣言で「ツールが本文を定める」とされた規約が4件ある。そのうち2件は宣言どおりツール側の本文が使われるが、残る2件は別の経路の本文で上書きされる。一方は空の雛形として、他方は規約提案からの取り込み文として本文が入る。その結果、宣言と実際の本文の出どころが一致しない。ツール側が定めたはずの内容が納品物に届かず、宣言を見て判断すると誤る。

**修正内容**: 宣言が「ツールが本文を定める」となっている規約は、ツール側の本文を唯一の出どころとする。他の経路が同じ規約へ本文を書き込む場合は、宣言を確認して書き込みを行わない。

**検収方法**: 宣言が「ツールが本文を定める」の規約4件すべてについて、生成された本文がツール側の様式と一致すること。他の経路を実行しても本文が変わらないこと。

**完了条件**: 宣言に基づく出どころの一本化までを本項目の範囲とする。宣言の値そのものの見直しは範囲外。

### 1-42. ツールが本文を定める規約の生成物に、納品先向けでない記述が残る（4回目の指摘）

**現象（実測事実）**: ツールが本文を定める規約が4件ある。その雛形4本すべての本文に、納品する側の都合を述べた記述が2種類含まれており、生成物と納品サンプルにそのまま焼き込まれる。1. 納品と上書きの運用を述べたコメント（4本の3行目）。納品する側の事情であり、規約を読んで実装する人には無関係な情報が本文の先頭に置かれる。2. 検査できない理由を述べたコメント（4本の4行目）。同じ内容は宣言部の項目として既に持っており、本文への重複である。3. 設計が定めていない5番目の節。3件と2件でそれぞれ文言が一字一句一致し、定型文として差し込まれたものと確認できる。片方には生成の内部データファイル名と生成の経緯が含まれる。この3つは原因が同じである。納品先の読み手に向けた内容でない記述が、納品物の本文に置かれている。

**修正内容**: 雛形4本から上記3種類の記述を除く。除いた内容のうち運用として必要なものは、納品物の本文ではなく payload の説明書へ移す。検査できない理由は宣言部の項目に集約する。設計が定める節以外を本文へ差し込まない。修正後、納品サンプルを再生成して焼き直す。

**検収方法**: 次の3つをいずれも満たすこと。1. ツールが本文を定める規約を生成し、生成物に対して納品する側の都合を表す語（納品・再納品・本文入り・上書きされる・機械生成・雛形であり、および内部データファイル名）の機械検索が0件であること 2. 生成物に、設計が定める節以外の見出しが現れないこと 3. 納品サンプルに対して同じ検索を行い0件であること

**再発を防ぐ仕組み（本項目の範囲に含める）**: 4. 上記1の禁止語の一覧を定義として持ち、生成の最後に生成物を走査して、該当があれば報告すること 5. 上記1〜3を雛形生成スクリプトの自己テストのケースとして追加し、以後の変更で自動的に検査されること

**完了条件**: 雛形4本の是正、納品サンプルの焼き直し、禁止語の検査と自己テストへの組み込みまでを本項目の範囲とする。空の雛形を配る経路の再点検、および設計側の節構成の変更は範囲外。

## 完了の判定

1. `rule-taxonomy.json` で `toolDefined: true` の規約すべてについて、生成された本文の出どころがツール側の様式と一致し、他の経路（規約提案の取り込み等）を実行しても本文が変わらない
2. 規約の生成物および納品サンプルに対して、納品する側の都合を表す語（納品・再納品・本文入り・上書きされる・機械生成・雛形であり、および内部データファイル名）の機械検索が0件になる
3. 生成物に、設計が定める節以外の見出しが現れない
4. 禁止語の一覧が定義として存在し、生成の最後に生成物を走査して該当を報告する処理が `scaffold-rule-definitions.sh` に組み込まれている
5. `scaffold-rule-definitions.sh --self-test` が全ケースPASSで終了コード0になる

## 触らない範囲

- 規約タクソノミ（`rule-taxonomy.json`）の宣言の値そのものの見直し
- 設計が定める節構成の変更

## この指示書の位置づけ

1-48・1-42 はいずれも `generation-engine/scripts/rules/scaffold-rule-definitions.sh` と `delivery-payload/templates/rules/tool-defined/` の同じファイル群を触り、原因も「本文の出どころ管理が甘い」という同一系統である。1 つの指示書にまとめることで、同じファイルへの並行着手による衝突を避ける。
