# 検証で見つかった4件を直す指示書

## この指示書は何か

2026-08-23の取り込み後検証で見つかった、入口ページ鮮度検査と規約定義の誤り4件を直す。
判定不能の区別、実装判断の記録、設計判断への用語統一、派生物と台帳の同期までを同じ変更として扱う。

## なぜ必要か

`generation-engine/scripts/check-portal-entry-freshness.sh` は、表示コミット元のJSONを読めない。
この場合を `[STALE]`・終了コード0へ誤分類することが実測された。
同じスクリプトには環境変数、一時ファイル、引用済みtrapを使う理由の記録が無く、`page-conventions` の規則は設計判断と実装判断を混同している。放置すると、判定不能を不合格相当として扱い、理由のある実装が次の書き換えで失われ、規約の役割分担も曖昧なまま残る。

## やること

1. `find_display_commit` の終了コード1と2を呼び出し側で区別し、終了コード2は `[UNKNOWN]`・終了コード2として返す。
2. 壊れた表示コミット元JSONが `[UNKNOWN]`・終了コード2になる自己テストを追加する。
3. 環境変数での受け渡し、一時ファイルでの成果物ID受け渡し、`printf %q` 済みの削除コマンドをtrapへ渡す理由を、スクリプトの該当箇所へコメントする。
4. 同じ実装判断を `docs/design/generation-engine/ルート直下/詳細設計書.md` へ記録する。
5. `docs/rules/portal/page-conventions/rule.md` の規則名と根拠を設計判断へ統一する。
6. `bash generation-engine/scripts/rules/build-derived-rules.sh --apply` で派生物を再生成し、手で直さない。
7. `bash generation-engine/scripts/check-derived-drift.sh record` で台帳を更新し、派生物と同じコミットへ含める。
8. 指定された3件を検査し、壊れたJSONの挙動を再現する。変更ファイルを明示して同じコミットへ入れる。

## 完了の判定

1. `bash generation-engine/scripts/check-portal-entry-freshness.sh --self-test` が終了コード0を返す。
2. 壊れた表示コミット元JSONを使う再現で、出力が `[UNKNOWN]` から始まり終了コード2になる。
3. `bash generation-engine/scripts/tests/check-derived-drift-ledger.sh` が終了コード0を返す。
4. `bash .claude/rules/always/tasks/instruction-format/check-instruction-format.sh` が終了コード0を返す。
5. 環境変数、一時ファイル、引用済みtrapの理由がスクリプトのコメントと詳細設計書の両方にある。
6. 規則名・内容・根拠が設計判断へ統一され、定義から再生成した派生物と作業ツリーの派生物が一致する。
7. `git status --short` の出力が0行である。
