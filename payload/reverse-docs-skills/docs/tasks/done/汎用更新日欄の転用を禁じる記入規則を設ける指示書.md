## 1. この指示書は何か

共通シェルが持つ汎用の更新日表示欄（`{{GENERATED_DATE}}`・`{{GENERATED_AT}}`）が何の時点を示す設計であるかを明文化する指示書である。あわせて、設計書の本文が個別の事実の時点を示す必要がある場合に、この汎用欄を根拠に転用しないよう記入規則を定める。

## 2. なぜ必要か

ある対象プロジェクトの単体テスト設計書で、テストコードを調査した時点を示す目的で、版面が持つ汎用的な更新日表示欄を参照する記述を書いた。この欄はヘッダー・フッターに表示される日付である。この日付欄は当該文書の中の個別の事実であるテストコード調査日と連動する仕組みを持たず、他の理由で内容が更新されれば、その事実と無関係に日付だけが変わりうる。時点を主張する記述と、それを裏付けるべき表示欄が別の仕組みで動いている状態だった。

## 3. やること

1. `page-conventions/rule.md`へ、共通シェルの更新日表示欄（`{{GENERATED_DATE}}`・`{{GENERATED_AT}}`）が示す時点の定義を追記する。「更新日表示欄はビルド時点を示す。」の一文を含める。記述は`build-portal.sh`の実装と整合させる。実装は`date +%Y-%m-%d`によるビルド時点算出と、`page-data.json`の`generatedAt`の由来を指す
2. `delivery-payload/templates/rules/tool-defined/document-writing.md`の`## 規則`テーブルへ、新しい規則行を1行追加する。規則名は「汎用の更新日欄を個別の事実の時点主張へ転用しない」とする
3. 内容欄には、設計書の本文が特定の事実の時点を示す必要がある場合は、汎用の更新日表示欄を参照せず、その事実専用の記録を持つ旨を書く。事実専用の記録とは、固定の日付記載、または当該事実に連動した専用の欄のいずれかであると明記する。汎用の更新日欄を他の事実の時点主張の根拠に転用しない旨を明記し、「転用しない」という語を含める
4. 根拠欄には、汎用の更新日欄と個別の事実が別の仕組みで動いており、内容が他の理由で更新されると事実と無関係に日付だけが変わりうる旨を書く
5. 検査欄には、汎用欄への転用の有無は自然文の意味を読む必要があり静的解析では判定できない旨（判定不能）を書く

## 4. 完了の判定

1. `page-conventions/rule.md`に、更新日表示欄がビルド時点を示す旨の定義が追記されている
2. `document-writing.md`に、汎用の更新日欄を他の事実の時点主張へ転用しない旨の記入規則が追加されている
3. `document-writing.md`の追加行に、事実専用の記録を持つべき旨が明記されている

## 5. 触らない範囲

- 共通シェルの`{{GENERATED_DATE}}`・`{{GENERATED_AT}}`の算出ロジックそのもの（`build-portal.sh`・`shell-injection.sh`の実装）
- `document-writing.md`の既存の規則行
- 設計書テンプレートの章構成そのもの

## 7. 他の指示書との関係

- `docs/tasks/指摘改善一覧.md`の1-263から本指示書へ追跡できる
- 他の指示書には依存せず、本指示書だけで着手できる
- 1-262（継続実施の宣言と裏付けの区別）とは対象の規則行が異なり独立しているが、どちらも`document-writing.md`の`## 規則`テーブルへ行を追加する点で同種の作業である

## 8. この指示書の位置づけ

共通シェルの設計判断の明文化と、`document-writing.md`への記入規則の追加という2つの文書修正だけで完結する、単独の小さな指示書である。GENERATED_DATE/GENERATED_ATの算出方法は既存の実装コード（`build-portal.sh`）から確認済みのため、設計から始める必要はなく、そのまま文書の追記に着手できる。優先度を中としたのは、既に発生した個別の誤記述を是正するものではなく、今後の記述の書き方を規定する予防的な追記であり、緊急性は高くないためである。
