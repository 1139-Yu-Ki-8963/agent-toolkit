# スキル五件の伝わらない説明を書き直す指示書

## この指示書は何か

初見では役割を判別できなかった五件のスキル説明を、各本文が定める入力・処理・成果に合わせて書き直す。特に用語集の変更要求を作る役割と、役割別の二件の承認がある変更を適用して公開する役割を説明だけで選べる状態にする。

## なぜ必要か

五十二件のスキル説明を検証した結果、五件は入力、処理範囲又は完了状態が説明から読み取れなかった。このままでは初見の利用者が隣接するスキルを使い分けられず、本文を読む前の選択を誤る。

## やること

1. 作業記録の「観点2」節と対象五件の本文を全文読む。
2. 各説明を、入力・処理・完了状態が一文で分かり、動詞で終わる日本語へ書き直す。
3. 用語集を保守するスキルは正式用語集を直接変えず変更要求を作り、用語集を管理するスキルは照会・審査・役割別の二件の承認がある変更の適用・公開を担うと区別する。
4. 説明の形式検査と内部用語検査を実行する。
5. 対象ファイルだけを列挙してステージし、指定メッセージでコミットする。

## 完了の判定

1. 対象五件の説明が指定された文面と一致する。
2. スキル説明の形式検査が終了コード0を返す。
3. 内部用語検査が終了コード0を返す。
4. 指示書形式検査が不合格0件を報告して終了コード0を返す。
5. 指定メッセージのコミットが存在し、未コミットの変更が0件である。

## 触らない範囲

- docs/tasks/ 直下に既にある指示書
- docs/tasks/work-records/ 配下
- .claude/skills/*/references/guide.html
- 対象五件の SKILL.md の本文
- generation-engine/scripts/skill-guide/ 配下

## 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| 説明の語順 | 入力、処理、完了状態の順に書く | 機械検査の条件を満たせない場合だけ、意味を保って語順を変える |

## 他の指示書との関係

既存の指示書には依存せず、検証記録の観点2で見つかった五件だけを対象にする。他の担当が変更する記録、ガイド及び検査スクリプトとは重複しない。

## この指示書の位置づけ

五十二件全体の再検証ではなく、初見で役割が伝わらないと実測された五件の説明修正だけを一つの作業単位にまとめる。
