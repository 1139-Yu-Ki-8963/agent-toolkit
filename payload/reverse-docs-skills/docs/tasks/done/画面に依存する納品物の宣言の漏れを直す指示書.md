# 画面に依存する納品物の宣言の漏れを直す指示書

**状態**: 着手できる
**優先度**: 最高
**前提**: なし
**元の指摘**: 1-253

## 1. この指示書は何か

納品物の状態を判定する宣言（deliverable-inventory.json）は、画面に依存する納品物へdependsOnKindを持たせる仕組みを備える。実測すると8件が宣言済みだが、design-system・component-inventory・icon-catalogの3件はこの宣言を持たない。3件は画面が無ければ作れない納品物である。宣言を追加し、宣言の網羅を確かめる検査を新設する。

## 2. なぜ必要か

指摘の詳細は台帳の1-253を見よ。ここでは実装に必要な点だけを補う。

design-system・component-inventory・icon-catalogの3件の生成元スキルを実測すると、いずれもscreenのマニフェストや一覧を直接には要求しない。共通設計文書・画面部品のファイル・アイコン参照という、UIが存在することを前提にした証拠に依存している。dependsOnKindの語彙は6種別（screen/api/table/batch/report/external/feature）のいずれかにしか依存を宣言できない。「UIが存在する」を表す種別は無い。画面がゼロ件と記録された対象は、UIそのものを持たない可能性が高く、この3件の証拠も存在しないと見込まれる。そのため、現行の語彙の中で最も近い代理としてscreenを採用する。この判断は、生成元スキルの入力そのものではなく、画面ゼロ件という状況からの推定であることに留意する。

## 3. やること

1. deliverable-inventory.jsonの3件へdependsOnKind=screenを追加する。対象はdesign-system・component-inventory・icon-catalogである。
2. docs/scripts/check-depends-on-kind.shを新設する。画面に依存する納品物11件を固定の一覧として持ち、全件が宣言済みかを確かめる。
3. 同スクリプトへ--check-resolutionを持たせる。画面ゼロ件の入力・画面ありの入力それぞれで実際に生成を行い、結果が想定どおりかを確かめる。
4. generation-engine/scripts/tests/配下へラッパーを置き、第1層の機械検証から拾えるようにする。docs/scripts/配下は第1層の走査対象に入らないため、この手当てが要る。
5. 触った資産の設計判断を、.claude/rules/always/tasks/instruction-format/rule.mdの「設計判断」節へ追記する。
6. 回帰を確認する。画面を持つ対象で3件が従来どおり判定されることを、上記--check-resolutionで確かめる。

## 4. 完了の判定

1. 3件がdependsOnKindを持ち、値がscreenであること。確かめる手段: `bash docs/scripts/check-depends-on-kind.sh`
2. 検査が画面ゼロ件の試験用入力で3件を「対象なし」と判定すること。確かめる手段: `bash docs/scripts/check-depends-on-kind.sh --check-resolution`
3. 網羅を確かめる検査が存在すること。確かめる手段: `test -f docs/scripts/check-depends-on-kind.sh`
4. その検査が、dependsOnKindを意図的に外した入力に対して不合格を出すこと。確かめる手段: `bash docs/scripts/check-depends-on-kind.sh --self-test`
5. 検査が画面ありの入力で3件を従来どおり判定すること。確かめる手段: `bash docs/scripts/check-depends-on-kind.sh --check-resolution`

## 5. 触らない範囲

- 既に宣言を持つ8件を変更しない
- generation-engine/samples/配下の見本を書き換えない
- 生成済みの対象プロジェクトの一覧を是正しない
- 他の指示書を変更しない
- .claude/rules/scoped/portal/page-conventions/rule.mdを直接編集しない（生成物である）

## 7. 他の指示書との関係

台帳（docs/tasks/指摘改善一覧.md）の1-252は、統括スキルへ調査結果の提示・承認段を設ける指示であり、対象種別の宣言ずれ全般を扱う。本項目は、その中の1事例（dependsOnKindの宣言漏れ）に絞って先に直す。1-252とは対象が重ならず、依存関係も持たない。

## 8. この指示書の位置づけ

台帳1-253が指摘する事象（画面に依存する納品物の一部が宣言を持たない）は、宣言を追加するだけでは再発しうる。宣言の網羅を機械で確かめる検査を伴わせることで、次に画面依存の納品物が増えたときも同じ漏れを検知できるようにする。この指示書は、その宣言の追加と検査の新設という1事例に絞った粒度で切る。
