# 確定していない事項の台帳を納品物から外す指示書

**状態**: 着手できる
**優先度**: 最高
**前提**: なし
**元の指摘**: 1-256

## 1. この指示書は何か

納品物の一覧（`portal-catalog.json`・`deliverable-inventory.json`）は、設計単位ごとの確定していない事項の台帳（`要確認事項台帳.json`）を`confirmation-item-ledger`という納品物として数える。この台帳を指す出力（`docs/design/**/要確認事項台帳.html`）を生成する処理は1本も存在せず、台帳が書き戻す先の設計書の節も1-223で全テンプレートから既に外れている。台帳を納品物の一覧から外し、確定していない事項そのものを失わない受け皿を明記する。

## 2. なぜ必要か

指摘の詳細は台帳の1-256を見よ。ここでは実装に必要な点だけを補う。

台帳は`resolving-confirmation-items`が回答を書き戻す作業記録であり、書き戻す先の設計書の節（要確認事項一覧）は1-223で削除済みである。書き戻す先を失った台帳を、それでも納品物の一覧が「未生成」として求め続けるため、この一覧は永久に完成しない状態になっている。一方で実測すると、確認事項質問票（`confirmation-survey`）が`build-confirmation-survey-data.sh`の`--confirmation-ledger`引数を通じて設計単位ごとの台帳を既に横断集約しており、納品物の一覧にも既に含まれ、生成元（`generating-cross-views-for-reverse-docs`）も実在する。新規の受け皿を起こすと、`confirmation-item-ledger`と同じ「生成元を持たない納品物」を複製しかねない。既存の`confirmation-survey`を正式な受け皿と位置づけ、置き場をリポジトリ既存の慣例（`matrixDir`）に紐づけて明記する。

## 3. やること

1. `delivery-payload/references/portal-catalog.json`から`confirmation-item-ledger`のblueprintを削除する。
2. `delivery-payload/references/deliverable-inventory.json`から`confirmation-item-ledger`の項目を削除する。
3. `delivery-payload/references/output-layout.json`の`directoryNamePolicy`へ、台帳を作業記録として持つ旨と、確定していない事項が`confirmation-survey`（`matrixDir`配下）へ集約されて失われない旨を1つのノートとして明記する。
4. `docs/scripts/check-confirmation-doc-handover.sh`を新設し、上記1〜3が揃っているかを機械で確かめる。
5. `generation-engine/scripts/tests/check-confirmation-doc-handover.sh`へ、本体の`--self-test`を呼ぶだけのラッパーを置き、第1層の機械検証から拾えるようにする。
6. 触った資産の設計判断を、`.claude/rules/always/tasks/instruction-format/rule.md`の「設計判断」節へ追記する。
7. `generation-engine/scripts/build-deliverable-inventory.sh --self-test`と`generation-engine/scripts/tests/test-portal-conventions.sh`で回帰が無いことを確かめる。

## 4. 完了の判定

1. `confirmation-item-ledger`が`portal-catalog.json`・`deliverable-inventory.json`の両方から外れ、`confirmation-survey`が両方に存在し置き場が`matrixDir`へ解決できること。確かめる手段: `bash docs/scripts/check-confirmation-doc-handover.sh`
2. 上記の検査が、台帳の復元・受け皿の削除・明記の削除それぞれで不合格を検出すること。確かめる手段: `bash docs/scripts/check-confirmation-doc-handover.sh --self-test`
3. 第1層の機械検証から本検査が拾われること。確かめる手段: `bash generation-engine/scripts/tests/check-confirmation-doc-handover.sh --self-test`
4. `deliverable-inventory.json`の生成が回帰無く成功すること（カタログとの被覆検査を含む）。確かめる手段: `bash generation-engine/scripts/build-deliverable-inventory.sh --self-test`
5. ポータル規約検査に新規の不合格が無いこと。確かめる手段: `bash generation-engine/scripts/tests/test-portal-conventions.sh generation-engine/samples`
6. 指示書の形式検査が合格すること。確かめる手段: `bash .claude/rules/always/tasks/instruction-format/check-instruction-format.sh`

## 5. 触らない範囲

- 設計書から確定していない事項の節を外す変更（1-223で実施済み）を行わない
- `confirmation-survey`（確認事項質問票）そのものの生成ロジック・テンプレートを変更しない
- 生成済みの対象プロジェクトの成果物を是正しない
- 他の指示書を変更しない
- `.claude/rules/scoped/portal/page-conventions/rule.md`を直接編集しない（生成物である）

## 6. 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| `confirmation-survey`専用の新規`output-layout.json`キー（`confirmationSurveyHtml`等）を新設するか | 新設しない。既存の`matrixDir`（全マトリクス系ページ共通の起点）を検査対象にする | マトリクス系ページ全体の出力先を個別キー方式へ移行する別の指示書が完了した場合 |
| `resolving-confirmation-items`のSKILL.mdが1-223で削除済みの節（設計書の要確認事項一覧）へ言及したまま残っている記述の是正 | 直さない。本項目とは別の指摘として扱う（本項目は納品物の一覧からの除去と受け皿の明記に限る） | 別の指示書として起票され、対応が完了した場合 |

## 7. 他の指示書との関係

台帳（`docs/tasks/指摘改善一覧.md`）の1-223は、設計書のテンプレートから確定していない事項の節を外す指示であり、既に完了している。本項目はその結果として書き戻す先を失った台帳を、納品物の一覧という別の資産から整理する後続作業であり、1-223の範囲は再度触らない。1-207は`confirmation-survey`とは別に、台帳と回答反映の仕組み自体（`resolving-confirmation-items`）を新設した指示であり、こちらも完了済みで本項目の対象外である。

## 8. この指示書の位置づけ

台帳を納品物の一覧から外すだけでは、確定していない事項という情報そのものが失われたかのように見える。実際には既存の`confirmation-survey`が同じ情報を既に集約しているため、この事実を検査可能な形で固定し、次に同種の「書き戻す先を失った台帳」が生じたときに同じ轍を踏まないよう、除去と受け皿の明記を1つの変更として切る。
