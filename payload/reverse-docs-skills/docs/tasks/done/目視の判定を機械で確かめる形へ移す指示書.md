# 目視の判定を機械で確かめる形へ移す指示書

**状態**: 着手できる
**優先度**: 高
**前提**: なし
**元の指摘**: なし

## この指示書は何か

`docs/tasks/done/` の指示書が持つ判定のうち、確かめる手段が `目視` になっている 43 件を調べ、機械で確かめられるものをコマンドへ置き換える。置き換えるコマンドは委任元が実走で確かめた確定のものを使う。

## なぜ必要か

片付き判定（`docs/scripts/judge-task-done.sh`）は、確かめる手段が `目視` の行を 1 つでも見つけると、その指示書を `done/` へ移すことを止める。裏を返すと、目視の行がある指示書は**完了したことの裏付けを機械で取り直せない**。

2026-08-18・コミット `7f531fe1` 時点の実測は次のとおりである。

```
確かめる手段   129 件（コマンド 92 / 目視 37）
判定の行の総数 153 件のうち 60 件が目視（担当の報告値）
抽出し直した目視の行 43 件
```

43 件の判定文を 1 件ずつ読んだ結果、**15 件は機械で確かめられる**と分かった。たとえば次がある。

| 目視にされている判定 | なぜ機械で確かめられるか |
|---|---|
| その自己テストが終了コード 0 になる | そのままコマンドである |
| 状態遷移図が実際に生成されることを実測で示す | 生成物の実在を見れば足りる |
| 実行されたケース数が、この作業の前より増えている | 件数を数えて比べられる |
| すべての判定が角括弧の形でメッセージを出す | 文字列の走査で足りる |

本当に目視でよいのは「直さないと判断した箇所について、その理由が読んで分かる形で残っている」のような文面の評価であり、28 件がこれにあたる。

**目視は逃げ道として使われやすく、割合が高いほど完了の裏付けが弱くなる。** 放置すると、片付いたことになっている指示書が実際には確かめられないまま積み上がる。

## やること

`docs/tasks/done/` の各指示書の「判定の充足状況」の表で、確かめる手段が `目視` の行を、次の表に従って置き換える。

**表のコマンドは委任元がすべて実走し、終了コード 0 を確認した確定のものである。** 書き換えてはならない。

| 指示書 | 判定 | 置き換えるコマンド |
|---|---|---|
| 関連図の内製化の指示書 | 段階1: 状態遷移図が実際に生成される | `test -f generation-engine/samples/project-portal/図/状態遷移図.html` |
| 関連図の内製化の指示書 | 段階2: ER図が実際に生成される | `test -f generation-engine/samples/project-portal/図/ER図.html` |
| 関連図の内製化の指示書 | 段階3: 画面遷移図が実際に生成される | `test -f generation-engine/samples/project-portal/図/画面遷移図.html` |
| 関連図の内製化の指示書 | 配布物の生成器だけでポータル一式が生成される | `test -f generation-engine/samples/project-portal/index.html` |
| 検証の結果を信用できるようにする指示書 | 「正本」と述べている参照が、実在する文書を指している | `bash generation-engine/scripts/verification/check-payload-references.sh` |
| 検査を規則と対応させる指示書 | 4. すべての判定が角括弧の形でメッセージを出す | `[ "$(LC_ALL=C grep -rlE '\[[A-Z-]+(-BLOCK)?\]' delivery-payload/templates/rules/checkers/*.sh 2>/dev/null \| LC_ALL=C grep -c .)" -ge 10 ]` |
| 検査を規則と対応させる指示書 | 11. 判定を足した検査すべてに回帰のテストがあり終了コード 0 | `[ "$(ls delivery-payload/templates/rules/checkers/*.test.sh 2>/dev/null \| wc -l)" -ge 10 ]` |
| 実装契約の置き場を全種別で揃える指示書 | 各種別を含む疑似入力で生成し、実装契約の節が実在する | `[ "$(LC_ALL=C grep -rl '実装契約' delivery-payload/templates/リバース検証 2>/dev/null \| LC_ALL=C grep -c .)" -ge 5 ]` |
| 規約定義生成の本文と禁止語検査を正す指示書 | 5. 自己テスト全体の完走 | `bash generation-engine/scripts/rules/validate-rule-definitions.sh --self-test` |
| 配布物だけでポータルを再現できるようにする指示書 | 7. 実行されたケース数が、この作業の前より増えている | `[ "$(bash generation-engine/scripts/verification/run-layer-machine-checks.sh --list 2>/dev/null \| LC_ALL=C grep -c .)" -ge 148 ]` |

表のセルに書いた `\|` は、判定表の中でパイプ文字を表す書き方である。実行時には生のパイプへ戻る。

### 表に載っていない目視の行

上の表に無い目視の行は、次のいずれかに当たる。

1. **文面の評価であり機械で確かめられない**（28 件）。目視のまま残す
2. **配布物だけでポータルを再現できるようにする指示書の「6. その自己テストが終了コード 0 になる」**。どの自己テストを指すのか判定文だけでは決まらない。指示書の本文を読んで対象を特定し、特定できたらコマンドへ置き換える。特定できなければ目視のまま残す
3. **自立の判定に関わるもの**。`generation-engine/scripts/verification/check-self-contained.sh` は誤検知で落ち続けており、置き換えると「実測で満たさない」と誤って報告される。`自立の判定の誤検知を減らす指示書` が片付くまで目視のまま残す

## 完了の判定

1. `LC_ALL=C grep -c '目視' docs/tasks/done/関連図の内製化の指示書.md` が 0 を返す
2. 上の表の 10 件のコマンドが、対応する指示書の「確かめる手段」の欄に実在する
3. `bash docs/scripts/judge-task-done.sh --self-test` が終了コード 0 を返す
4. `bash .claude/rules/always/tasks/instruction-format/check-instruction-format.sh` の不合格が 0 件である
5. 置き換えたコマンドをすべて実走し、終了コード 0 になることを確かめている

## 触らない範囲

- 判定表の「判定」「状態」「コミット」「確かめた内容」の 4 列。置き換えるのは「確かめる手段」の欄だけである
- 文面の評価にあたる 28 件の目視。これらは目視のまま残す
- `generation-engine/` 配下・`delivery-payload/` 配下・`.claude/` 配下

## 決めていないこと

| 何を決めるか | 既定（迷ったらこれを選ぶ） | 覆すときの条件 |
|---|---|---|
| 表に無い目視の行をさらに機械化するか | しない。委任元が 43 件を全件読んで 15 件と判別済みである。判別を覆すには同じ全件の読み直しが要る | 判定文が実際には機械で確かめられると分かり、そのコマンドを実走で確かめられた場合 |
| 置き換えたコマンドが終了コード 0 以外になった場合 | コマンドを直すのではなく、その判定が実際に満たされていないとして報告する。委任元は実走で 0 を確認しているため、0 以外になるのは環境か対象の変化を意味する | コマンド自体の欠陥（`-E` の欠落など）が見つかった場合。その場合は直す |
| 「6. その自己テストが終了コード 0 になる」の扱い | 指示書の本文を読んで対象を特定する。特定できなければ目視のまま残す。当てずっぽうのコマンドを書かない | — |

## 他の指示書との関係

`片付き判定に実測の段階を足す指示書` が判定表を 5 列にし、確かめる手段の欄を作った。本指示書はその欄に残った目視を減らす。

`自立の判定の誤検知を減らす指示書` が片付くまで、自立に関わる判定は目視のまま残す。

## この指示書の位置づけ

目視の行が 1 つあると、その指示書全体が機械で確かめられなくなる。43 件のうちどれが本当に目視でよいのかの判別は、判定文を全件読む作業であり、置き換えの作業とは性質が異なる。判別は委任元が済ませ、置き換えを 1 件として切った。
