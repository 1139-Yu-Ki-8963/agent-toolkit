## この指示書は何か

共通文書のパス実在検査を直す。対象は `is_path_candidate`・`check_paths_exist` の2関数（`check-common-docs.sh` にある）。

## なぜ必要か

パスの候補を判定する `is_path_candidate` は、斜線を含み特定の記号（URL・glob・空白・括弧等）を含まない文字列を一律にパス候補として扱う。コロンは除外対象に含まれていない。このため `pm/.gitignore:36-42` のような「実在するファイルの特定の行を指す書き方」が、末尾の `:36-42` を含んだまま実在確認にかけられ、実在しないパスとして不合格になる。

2026-08-25、実際に合成入力で再現した。共通設計書に `` `pm/.gitignore:36-42` `` を記載する。対象リポジトリに `pm/.gitignore` を実在させる。この状態で `check-common-docs.sh` を実行すると、次のとおり検査3が不合格になった。

```

検査3失敗: 記載パス 1 件中 1 件が target_repo_path 配下に実在しません
```
