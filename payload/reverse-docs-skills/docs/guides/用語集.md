# 用語集

語は減らすことが先。平易な言い換えで説明不要にできる語は載せない。キーは連番禁止。

| 語 | 種別 | 1 行定義 |
|---|---|---|
| facts | ドメイン用語（このツール固有） | 原本コードから抽出した宣言的契約の事実表。設計書執筆の唯一の情報源で、執筆スキルは原本を直接読まない |
| 往復検証 | ドメイン用語（このツール固有） | 設計書だけからコードを再生成し、原本と一致するまで再実装・比較・判定を繰り返す検証 |
| 基準タグ / 基準コミット | ドメイン用語（このツール固有） | 2 環境の完全一致を証明できた時点のコミットに打つ git タグ reverse-baseline/<scope>。表示値はずれ検知の対象 |
| 定義 | ドメイン用語（このツール固有） | AI が読む唯一の生成元（docs/ の Markdown と根拠画像）。直すべき対象は常にここ |
| 派生物 / 派生アダプター | ドメイン用語（このツール固有） | すべて定義から生成する（逆向きの生成はしない）。各 AI ツールが定義へ到達する層（.claude/ .cursor/ .codex/ 等）が派生アダプター |
| 空雛形 | ドメイン用語（このツール固有） | 型と定義だけを納品する規約テンプレート。コードから観測した実装慣行は本文へ書かない |
| 規約提案 | ドメイン用語（このツール固有） | コードから観測した実装慣行の提案。リポジトリ外へ出力し、取り込みの判断は現場のエンジニアが行う |
| ポータル | ドメイン用語（このツール固有） | project-portal/ 配下の人間向け HTML 群。スキルを実行するたびにカードが増える。docs/ 配下には置かない |
| 縮退 | ドメイン用語（このツール固有） | 画面なしプロジェクトで画面依存の工程を飛ばし、画面カードを選択できない状態で表示するモード |
| 統括スキル | ドメイン用語（このツール固有） | orchestrating-ai-development-setup。全工程の入口となる指揮役。成果物の実在と契約に基づく依存順で自動実行する |
| 台帳 | ドメイン用語（このツール固有） | 適用（record）のたびに派生物のハッシュを記録するフィンガープリント台帳。検査（status）が現在値と突合する |
| manifest / マニフェスト | ドメイン用語（このツール固有） | 原本コードや設計書から抽出した内容を構造化した JSON。派生の元となる一次データで、一覧や資産の表示名・件数はこの JSON から導出する |
| symlink | 技術用語（一般 IT） | 同じ形式で読める AI ツール同士で定義を共有する仕組み。形式が異なるツールへは変換して用意する |
| worktree | 技術用語（一般 IT） | 往復検証で使う、リバース元と設計書再現の 2 環境の作業ツリー。ポート管理と実描画比較を行う |
| 孤児参照 / 孤児関連 | ドメイン用語（このツール固有） | 参照先が存在しない状態を指す語。孤児 edge も同系の概念で、validate-page-data.sh 等が機械検査・機械検証する |
| 孤児 edge | ドメイン用語（このツール固有） | nodes の unitKey に一致しない edges 要素。0 件であることを機械検証する対象 |
| 責任の分界点 | ドメイン用語（このツール固有） | 対象（API・外部連携等）がどこまでを担い、どこから先を他へ委ねるかという境界。原本コードから抽出する対象の一つ |
| 要確認事項 | ドメイン用語（このツール固有） | 原本コードから確定できない事項を推測で埋めず、確認事項として記録したもの。設計書に集約し、キーは連番を禁じ内容を要約した意味語で付ける |
| 拡張マニフェスト | ドメイン用語（このツール固有） | 一覧スキルが出力する JSON に、メソッド・認証要否・入出力の要約など詳細設計向けの項目を付け足したもの |
| 拡張マニフェスト記載事項の一致 | ドメイン用語（このツール固有） | マニフェストの schedule・targetTables・downstreamJobs・execMethod のうち値を持つフィールドが本文に反映されていることの確認 |
| 原本を見ない検証 | ドメイン用語（このツール固有） | 設計書の執筆役が原本コードを読まず、確定済みの事実表だけを情報源にする進め方（盲検の言い換え）。前半で読んだ原本コードの情報を後半に持ち込まないための分離にも使う |
| 検出の方針の宣言 | ドメイン用語（このツール固有） | Phase 1 の調査結果をまとめ、approvedByUser: true のユーザー承認を得た抽出方針の JSON。以後の抽出と検証はこの宣言に沿って行う |
| 個別に組み立てる抽出 | ドメイン用語（このツール固有） | 組み込み検出器を使わず、Claude 自身が戦略宣言に沿って専用の抽出手順を設計・実行する経路 |
| 根拠 | ドメイン用語（このツール固有） | 原本コードの file:line 形式での記録を裏付けとして示すこと。詳細設計では本文に書いてよい |
| 根拠不足 | ドメイン用語（このツール固有） | 分析で確認できなかった項目に与える扱い。推測で埋めない |
| マニフェストとの整合確認 | ドメイン用語（このツール固有） | マニフェストの記載項目と原本から読み取った内容が食い違わないかを確認すること。食い違いは要確認事項一覧へ記録する |
| 交差ビュー | ドメイン用語（このツール固有） | 複数の一覧を突き合わせて、単独の一覧では答えられない関係を示すページ |
| 状態遷移表 | ドメイン用語（このツール固有） | データ設計.md の表。列はエンティティ／状態／遷移前／契機／遷移後／根拠パス |
| 集約設計書 | ドメイン用語（このツール固有） | 構成要素の個別設計書から値を再掲せず、パスで参照する設計書。構成要素をまたいで初めて意味を持つ事項だけを正として持つ |
| 派生一覧 | ドメイン用語（このツール固有） | ソースコードを直接走査せず、既存の一覧やマニフェストを組み立て直して作る一覧 |
| 未承認の提案 | ドメイン用語（このツール固有） | 人の承認を経ていない候補・提案。承認済みとして扱ってはならない |
| 確定検証 | ドメイン用語（このツール固有） | seal-facts.sh verify によって、facts.yml が確定時からの改変なしであることを確認する検証 |
| 機械ゲート | ドメイン用語（このツール固有） | check-*.sh による決定的スクリプト検証。合否判定は exit code のみで行い、自然文の自己申告では判定しない |
| L1〜L5 | ドメイン用語（このツール固有） | 動的検証を 5 段階に分けた検証レベル（L1 起動確認・L2 構造スナップショット・L3 画素比較・L4 コンソールエラー・L5 操作シーケンス突合） |
| オリジナルコード環境 | ドメイン用語（このツール固有） | リバース対象のオリジナルコードを保持する worktree。設計書 frontmatter の source_repo / source_ref から用意する読み取り専用コピー |
| リバースコード環境 | ドメイン用語（このツール固有） | 設計書だけを見て再構築したコードを置く worktree（reverse-code-<scope>）。中身のコードは呼び出し元が書く |
| drvfs | 技術用語（一般 IT） | WSL2 環境で Windows 側のドライブが /mnt/* としてマウントされる特殊なファイル領域。ネイティブ Linux ファイルシステムより低速なため、worktree の配置先として非推奨 |
| エンドポイント | 技術用語（一般 IT） | HTTP メソッドとパスの組で識別される API の 1 単位（例: GET /users/:id） |
| コンポーネント | 技術用語（一般 IT） | UI の部品として検出されるファイル単位（.tsx・.jsx・.vue 等）。1 ファイルを 1 件として数える |
| CSS トークン | 技術用語（一般 IT） | 色・余白・文字サイズ・角丸といった見た目の値に名前を付けたもの。CSS カスタムプロパティとして書かれることが多い |

この md は説明 HTML 群の用語の単一情報源であり、ガイドのパネルとの同期はずれ検知の対象に加える。同期機構は後続の実装である。

## 一般語彙

文脈によって対象が変わりうる一般語や、他文書で使われる語のうち説明を要するものを載せる。

| 語 | 種別 | 1 行定義 |
|---|---|---|
| 正本 | 一般語彙 | 複数の場所に存在しうる中で「唯一の正しい情報源」を指す。文脈により対象が変わる（定義ファイル・規約文書・確定版など）ため、使われている場所ごとに何を指すかを確認すること |
| 派生 | 一般語彙 | 正本から生成・導出された値やファイルを指す。正本を直接書き換えるのではなく、正本から作り直すことで更新する |
| 台帳 | 一般語彙 | 状態や履歴を時系列で記録し続けるファイルを指す。対象は複数存在し、実際のファイル名は「台帳」という語とは異なる場合がある（例: task-ledger.md） |
| 差し戻し | 一般語彙 | レビュー等で前工程へ差し戻すこと |
| 委任 | 一般語彙 | 作業を他の担当者・スキルへ任せること |
| 束ねる | 一般語彙 | 複数のものを 1 つにまとめること |
| 突合 | 一般語彙 | 複数の値・記録を照らし合わせて一致を確かめること |
| 著述 | 一般語彙 | 文章を書き著すこと |
| 業務語彙 | 一般語彙 | 業務で使われる用語 |
| 仲介 | 一般語彙 | 間に立って取り次ぐこと |
| 目録 | 一般語彙 | 項目の一覧・カタログ |
| 巻き戻し | 一般語彙 | 元の状態へ戻すこと |
| 退避 | 一般語彙 | 一時的に別の場所へ移し保存すること |
| 再計数 | 一般語彙 | 件数を数え直すこと |
| 退役 | 一般語彙 | 番号・機能等が使われなくなること |
| オーケストレーター | 技術用語（一般 IT） | 複数の処理を統括する役割 |
| パラメタライズドテスト | 技術用語（一般 IT） | パラメータを変えて繰り返し実行するテスト |
| メッセージキューコンシューマ | 技術用語（一般 IT） | メッセージキューからメッセージを取り出して処理する側 |
| 整合検証 | 一般語彙 | validate-manifest.sh 等による、抽出方法に依らない同一基準でのマニフェスト・データの機械検査 |
| 周回 | 一般語彙 | 繰り返しの1回分・軌道を回ること（「地球を周回する」と同じ用法） |
| 開通 | 一般語彙 | 画面・機能等が利用できる状態になること（道路・回線が使えるようになることと同じ用法） |
