29 本の検査

決まりは書いただけでは守られません。コードを書こうとした瞬間に手を止める検査を同梱しました。

検査が実際に止めるもの。以下はこの環境で実際に走らせて確かめた結果です
書こうとしたもの結果守らせる決まり
const k = "AKIA…"（認証の鍵をコードへ直書き） 止める 認証と入力と秘密の値
double price = 100.5（金額を小数で持つ） 止める 金額と数量の計算
繰り返しの中で問い合わせを発行する 止める 応答の速さと処理の量
一時ファイルを版管理へ入れる 止める どこに何を置くか
統合先の枝へ直接コミットする 通した 実装から統合までの順序（取りこぼし）
const k = process.env.KEY（正しい書き方） 通す —

これが納品先にとって何を意味するか

認証の鍵をコードへ書くと、版管理の履歴に残り、後から消せません。 金額を小数で持つと、計算のたびに誤差が積もります。 繰り返しの中で問い合わせを出すと、件数が増えたときに動かなくなります。

いずれも、書いてしまってから気づくと直すのに手間がかかる種類の誤りです。 書こうとした瞬間に止まれば、その手間は発生しません。

ただし、代表 6 件を個別に試すと 2 件が取りこぼした

上の 29 / 29 は、各検査に用意された試験を走らせた結果です。 これとは別に、実際に書きそうなコードを 6 通り与えて試したところ、2 件が素通りしました。

  • 繰り返しを見る検査が for (const x of xs) の形だけ通す。ほかの書き方では止まる
  • 統合先の枝への直接コミットを止める検査が、統合先の上で実行しても通す

いずれも未修正で、来週へ送ります。 用意された試験に通ることと、実際の書き方で止まることは別だと分かりました。

05手戻りとして記録するもの

週の後半に、自分たちが作った検査の側に欠陥が 5 件見つかり、その是正に時間を使いました。 いずれも差し引きの成果はゼロで、手戻りにあたります。

内容は「調べる対象が 0 件のとき合格を返す」という同じ形の誤りです。 検査が何も見ずに合格を返していました。

この時間を減らすために、次を来週の作り方へ入れます。

  • 検査を作るとき、違反を与えて止まることを確かめてから完成とする
  • 対象が 0 件の場合の振る舞いを、作る時点で決めて書く

この報告に載せた数は、いずれも実際に走らせるか、版管理の履歴を数えて得たものです。 推定した値・見込みの値は含みません。検査の結果は、違反を含む入力を実際に与えて確かめました。
