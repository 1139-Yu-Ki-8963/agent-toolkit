# 部品の分け方と依存の決まり

## 概要

画面と処理を構成する部品の分け方・責務の持たせ方・部品どうしの依存の取り決め。

部品の境界は後から動かすほど手数が増えるため、分け方の基準を先に決める。再利用のために分けるのではなく、変更の理由が違うものを分ける。

## 規則

| 規則 | 内容 | 検査 |
|---|---|---|
| 表示と判断と取得を混ぜない | 見た目を組み立てる部品・業務の判断を行う部品・データを取り出す部品を分ける | 静的解析: 表示の部品からデータ取得の呼び出しが直接行われていないかを走査する ／ レビュー: 業務の判断が表示の部品へ混入していないかを確認する |
| 部品の受け渡しを入口に集める | 部品が外から受け取る値を入口の宣言へ集め、外側の状態を直接読まない | 判定不能: 正当な取り込みと外側の状態の直接の参照を区別するにはデータの流れの解析を要し、書き込みの内容の走査では判定できない |
| 部品の大きさに上限を置く | 1つの部品の行数に上限を置き、超えたら分ける。既定の上限は150行とする | 静的解析: 150 行を超えていないかを走査する。値はこのプロジェクトの規則の表で上書きできる |
| 循環する依存を作らない | 部品どうしが互いを参照する形を作らない | 静的解析: 取り込みの関係に循環が無いかを走査する |

## このプロジェクトの規則

上限と形式の具体的な値は、リバース解析が対象リポジトリを観測してこの表の行として起こす。

| 規則 | 内容 | 検査 |
|---|---|---|
| 未解析 | この規約に対応する実装の慣行は、まだ観測していない。リバース解析を実行して対象コードを分析すると、その結果からこの節へ規則が起こされる。解析を待たずに規則を決めたい場合は、この節へ直接書き足してよい | 未解析: リバース解析が未実行であり、対象コードの観測結果がない | 不可: 観測の有無は解析の実行結果に依存し、静的解析で判定できない |

## 違反時の手順

書き込みが止められた場合、互いを参照している2つの部品の間から共通の処理を切り出し、双方がその切り出し先だけを参照する形に直す。
