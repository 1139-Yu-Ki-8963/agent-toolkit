# 検証の進め方

## 見張り方

3時間ごとに、公開リポジトリの更新を確かめます。
次の形で、見張りを始めます。

```
/loop 3h 公開リポジトリの更新を取得し、改善された内容を実プロジェクトへ適用して確かめる
```

## 各回の手順

| 手順 | 内容 |
|---|---|
| 手順1 | 公開リポジトリの最新を取得します |
| 手順2 | 前回からの差分を見ます |
| 手順3 | 改善された項目を特定します |
| 手順4 | 実プロジェクトへ適用します |
| 手順5 | 出来上がったものを見て確かめます |
| 手順6 | 問題があれば書き出します |

### 手順2について

差分が無ければ、そこで終えてください。
前回の未解決を、深掘りする必要はありません。
無駄な実行を避けるためです。

### 手順3について

何が変わったかを、課題の一覧と突き合わせてください。
突き合わせることで、どの指摘への対応かが分かります。

### 手順4について

改善された項目を、実際のプロジェクトへ適用してください。
検査を走らせるだけで、終えないでください。

### 手順5について

出来上がった設計書を、実際に読んでください。
検査が通ったことをもって、使えるとはしないでください。

## 確かめる観点

| 観点 | 何を見るか |
|---|---|
| 読めるか | 設計書を初めて読む人が、意味を取れるかです |
| 足りているか | 実装に必要な事項が、書かれているかです |
| 余計なものが無いか | 作り手の事情や途中経過が、混ざっていないかです |
| 一貫しているか | 同じ種別の設計書どうしで、章立てが揃っているかです |
| 辿れるか | 一覧から設計書へ、設計書から関連資料へ移動できるかです |

## 記録の残し方

各回の結果を、手元に残してください。
何を確かめ、何が動き、何が動かなかったかを書いてください。
