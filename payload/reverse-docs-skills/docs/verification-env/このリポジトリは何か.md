# このリポジトリは何か

## 何をする仕組みか

既存のコードから、設計書を起こす仕組みです。
起こした設計書だけをもとに、コードを作り直します。
作り直した結果を、元のコードと突き合わせます。
設計書が元のコードを言い表せているかを、この突き合わせで確かめます。

## 何が配られるか

| 配られるもの | 何をするか |
|---|---|
| スキル | 設計書を起こす手順です。種別ごとに分かれています |
| 規約 | 設計書の書き方・命名・配置の決まりです |
| テンプレート | 設計書の様式です |
| 生成器 | 一覧・ポータル・対応表を作る道具です |
| 検査 | 決まりを守れているかを機械で調べる道具です |

## どう改善しているか

実際のプロジェクトへ適用して、問題を見つけます。
見つけた問題は、課題の一覧へ書き出します。
課題の一覧から指示書を起こし、仕組みを直します。
直したものが実際に使えるかを、また別の環境で確かめます。
あなたは、その確かめる側です。

課題の一覧は、2つあります。

| 一覧 | 何が載るか |
|---|---|
| `docs/tasks/指摘改善一覧.md` | 実際の成果物を見て見つかった指摘です |
| `docs/tasks/作業課題一覧.md` | 仕組みを作る中で見つかった課題です |

## 何を確かめてほしいか

直したものが、実際のプロジェクトで使えるかどうかです。
見るべきは、検査が通ることではありません。
出来上がった設計書が、読めるか、使えるかを見てください。
