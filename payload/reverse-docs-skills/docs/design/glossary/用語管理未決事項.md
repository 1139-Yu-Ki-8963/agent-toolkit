# 用語管理未決事項

正式schema、validator、用語管理Skill、用語保守Skill、ポータル投影は現行v0.1で実装済みである。
この文書では、本番導入時の運用選択と将来拡張の判断だけを管理する。

## 1. 決定が必要な事項

| 論点 | 推奨初期値 | 選択肢 | 決定者 | 決定期限 |
|---|---|---|---|---|
| 定義の物理配置 | 対象アプリでは `docs/rules/business-domain/glossary/` を標準とし、中央索引が論理registryを構成する | 専用registry repoへ集約 | 基盤責任者 | 本番registry導入前 |
| ファイル分割単位 | domain別YAMLと全体索引 | 1ファイル、1用語1ファイル、application別 | maintainer | 本番registry導入前 |
| 承認人数 | 現行契約どおり業務1名と技術1名 | 1名承認、risk別可変 | ガバナンス責任者 | 承認方式の変更前 |
| definitionの権威順 | 業務文書、契約schema、実装の順 | プロジェクト別設定 | business approver | adapter実装前 |
| 類義語検出方式 | 決定的特徴量を先に使い、埋め込みは候補提示だけに使う | 文字列のみ、LLMのみ、hybrid | AI基盤責任者 | 検出器実装前 |
| confidenceの算出 | 分野別規則を明示し、単一の共通式に固定しない | 共通重み式、LLM自己評価 | 解析Skill責任者 | adapter実装前 |
| 未使用判定期間 | 四半期監査で12か月未観測を候補化する | 6か月、24か月、期間なし | 運用責任者 | 監査開始前 |
| 提案保管基盤 | 対象repo外の明示パスを必須にする | 専用review repo、artifact storage | セキュリティ責任者 | 分野別adapter導入前 |
| ポータル権限 | 承認済み一覧は通常閲覧、候補審査は限定権限 | 全公開、全限定 | portal責任者 | 候補審査UI実装前 |
| 多言語対応 | keyは共通、labelとaliasを言語別に持つ | 日本語のみ、用語レコード分割 | product責任者 | schema major確定前 |
| 外部標準との対応 | relationで外部concept URIを任意保持する | 外部標準を定義にする、非対応 | architecture approver | 初回導入後でも可 |
| 個人情報と機密語 | security classificationを用語へ持たせる | 別データカタログへ完全分離 | security approver | 本番導入前 |

## 2. 現行版の対象外

- 本番registryの配置と権限管理
- API、DB、画面、コード、文書ごとの候補adapter
- 旧5項目データから正式用語への自動移行
- AI利用向け索引。現行版の`ai_index`要求は`review_required/not_implemented`で停止する。
- versionずれgate、候補審査UI、用語ライフサイクルのE2E検証

## 3. 初期版で見送る候補

- 自動翻訳の承認workflow
- ontology推論と自動relation補完
- 用語変更からのコード自動改名
- graph databaseへの常時同期
- LLMによる自動承認
- 組織directoryとの双方向同期

これらはschemaの拡張余地を残すが、初期実装の完了条件には含めない。

## 4. 現行資産との整合で確認が必要な事項

- 既存 `docs/guides/用語集.md` と新しい複数アプリ用registryの責務分担。

## 5. 解決済み

- `generating-glossary-for-reverse-docs` は互換名を維持した候補生成専用Skillへ変更した。対象repo外の明示的な絶対パスへ `detected` proposalとdiagnosticsだけを出力し、ヘッドレスでも `NEEDS_REVIEW` で停止する。
- リポジトリ外提案出力は `proposal_output_ref` を呼び出し元が明示し、対象repo内・相対パス・symlink経由のrepo内パスを生成前に拒否する方式で統合した。
- `generation-engine/scripts/detail-pages/page-data-schema.md` のT2 glossaryは、定義schemaではなくポータル投影schema v0.1として再定義した。承認済み用語YAMLから必要項目だけを決定的に投影する。
- `generation-engine/samples/一覧/用語辞書/用語辞書.html` は日本語見出しの指定14列一覧と詳細ドロワーへ移行した。旧5フィールドとprojection v0.1のpage-dataは当面読み取り専用で受理し、不明値を捏造しない。互換入力の廃止は次回majorで判断する。

## 6. 本番導入前の意思決定

本番導入前に、次の3点はユーザーまたは基盤責任者が確定する必要がある。

1. 各アプリに置く定義を中央索引へ集約する方式を選ぶか、専用registry repoへ集約するか。
2. 業務承認者と技術承認者を誰またはどの役割にするか。
3. 提案ファイルをどの外部領域へ保存するか。
