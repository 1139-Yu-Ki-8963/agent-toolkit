現行実装は、実行に使う言語処理系の版数を完全一致で検査します（3.13系のみ許可）。範囲比較にすると、想定外の版数でも通過してしまい、単一の実行環境に固定するという設計の前提が崩れます。実体一致の確認は、場所の一致比較だけでなく、同一の実体を指すかどうかの比較も併用します。場所の一致比較だけでは、2つの異なる別名が同じ実体を指す場合を見逃し、出力先が入力の内容を書き換えてしまう恐れがあります。呼び出し口（シェルの薄いラッパー）は、検証エンジン本体の標準エラー出力を一時ファイルへいったん退避してから読みます。標準エラー出力は「呼び出し元へそのまま伝える」用途と「実行環境の版数不一致かどうかを判定する」用途の2箇所で必要であり、一度しか読めない経路を2回使うために一時ファイルを経由します。
