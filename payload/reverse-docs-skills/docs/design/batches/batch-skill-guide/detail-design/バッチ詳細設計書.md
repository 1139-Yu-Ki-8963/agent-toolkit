## 実装判断

本節は、今の実装が素直に見えない書き方を採っている箇所について、なぜその書き方を採ったかを記録します。

### 見た目の書き換えを一時ファイル経由で行う

`apply-guide-style.sh` は書き換え結果を直接ファイルへ上書きせず、一時ファイルへ組み立ててから置き換えます。処理の途中で中断した場合に、元ファイルの内容を失わないためです。直接上書きすると、書き込み先を先に空にしてから書き込むため、中断時に元の内容が失われます。

### 旧い参照パスの検査に版管理の仕組みを使う

`apply-guide-style.sh` の自己確認は、旧い名前を指すパス参照が残っていないかを、リポジトリ全体の無差別な走査ではなく、版管理の仕組み（追跡対象だけを見る）で検査します。生成物・依存先ディレクトリ等、意図的に走査から除きたい対象を自動的に除外できるためです。追跡されていない（まだ登録されていない）ファイルは走査対象に含まれないという既知の限界を持ちます。

### 順序をロケールの既定値に委ねない

`check-guide-script-paths.sh` の走査・整列は、実行環境の既定の並び順ではなく、明示した並び順に固定します。実行環境の設定によって並び順が変わると、走査順・報告順が環境ごとに変わってしまうためです。

### 一時領域が作れない場合の扱い

`check-guide-script-paths.sh` の自己確認は、一時領域の作成に失敗しうることを想定し、失敗時は例外で止めるのではなく「不合格1件」として報告してから終えます。書き込みが許可されていない実行環境でも、判定可能な形で終えるための設計です。**手元の書き込み制限が無い環境で単純な作成結果をそのまま使っても動くことを理由に、この二重の確認を外してはなりません。**
