## 実装判断

本節は、今の実装が素直に見えない書き方を採っている箇所について、なぜその書き方を採ったかを記録します。

### build-manifests-from-docs.sh: 遷移先パス算出にpython3を使う

一覧HTMLの行から個別の設計書ページへ遷移するための相対パスの算出に、bash単体の文字列操作ではなく `python3 -c 'import os,sys; ...'` を使います。bash自体には相対パス計算の標準機能が無く、2つの絶対パスから相対パスを機械的に導く処理をbashの文字列操作だけで実装するのは非現実的なためです。python3が存在しない環境への備えとして `command -v python3` の判定を持ち、不在時はフィールド自体を付けません（捏造しません）。**手元の開発機に常にpython3が入っていることを理由に、この判定を外してはなりません。**外すとpython3不在の環境で処理自体が失敗します。

### build-manifests-from-docs.sh: 可変長の値をファイル経由で渡す

種別1件分の全ユニットを蓄積した配列や、対象テーブル一覧、集約文書から作る要素は、コマンドライン引数への直接展開を避け、一時ファイルまたは標準入力を経由して渡します。対象リポジトリの設計文書数が多い場合に引数長の上限を超える恐れがあるためです。実測では、900列のテーブルで実際に引数長の上限（Linuxで131,071バイト）を超えて失敗した記録があります。**手元の少ない件数での動作確認を理由に、この経由を外してはなりません。**

### extract-er-page-data.sh: 参照先テーブルの解決を2種類の書き方に対応させる

参照先テーブルを指す書き方（内部識別子か日本語の表示名か）がこのリポジトリ内で統一されていなかったため、両方の書き方を解決できるようにしています。解決できない参照は関連として組み立てず、未解決の一覧へ理由付きで記録します。生成後の検証（孤児参照の検査）が、実在しない参照先を持つ関連をすべて不合格とするため、この対応は必須の設計です。

### extract-transition-page-data.sh: 出典参照・確信度の値を新設せず固定値で扱う

参照元の文書に行ごとの証跡列が無いため、出典参照は文書全体を指す固定の参照文字列とし、確信度は文書からは確からしさを判定できないため常に空文字とします。列を新設せず、値を捏造しない既存の方針を保ったまま矢印を組み立てられることを確認しています。
