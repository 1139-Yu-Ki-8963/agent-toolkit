## 実装判断

本節は、今の実装が素直に見えない書き方を採っている箇所について、なぜその書き方を採ったかを記録します。対象は `build-rule-proposal.sh` 1本です。

### 実行環境の外（`$HOME/agent-home`）にある静的検査への依存

1. **なぜ素直な形を採らなかったか** 静的検査の道具（禁止色・box-shadow・未解決プレースホルダ等を検査する）を、この一式へは同梱していない。実行環境固有の場所（`$HOME/agent-home/skills/reviewing-explanatory-html/scripts/verify-html-static.mjs`）を指す。理由は、この検査観点が他のHTML生成処理が検査する観点と重複するため、同梱して二重に保守するより、既存の検査器を再利用する設計とした。
2. **道具が無い環境での扱い** 道具または実行系（node）が見つからない場合、生成そのものを失敗させず、警告のみでスキップして処理を続ける（fail-open）。この検査はこの一式の開発時の追加チェックであり、決定的なHTML生成という本来の契約に必須の依存ではないため、不在を理由に生成そのものを止めない。
3. **環境に依存するかどうか** 依存する。実行環境に検査の道具一式が存在するかどうかに依存し、存在しない環境（他マシン・納品先での再生成等）では静的検査が常にスキップされる。**手元の開発環境（道具ありの環境）で検査が実行され不合格を検出できることを理由に、この依存を「常に検査を強制する」方向へ書き換えてはならない。他の環境で生成そのものが失敗するようになる。**
4. **過去に消えて再発した経緯** 記録なし。

### 属性値の区切り文字の選び方

組み立てたHTMLの一部の属性だけ、他の属性と異なり区切り文字をダブルクォートではなくシングルクォート（`\x27`で表す）にしています。値がJSON配列文字列であり要素ごとにダブルクォートを大量に含むため、生成後の生HTMLを人が読む・検索する際の判別をしやすくする目的の選択です。実行結果には影響しません。
