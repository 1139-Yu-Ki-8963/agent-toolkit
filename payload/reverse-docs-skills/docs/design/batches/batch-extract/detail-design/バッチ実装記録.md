現行実装には次の素直でない作りが含まれます。列名や検出結果を渡す先が可変長で伸びるとき、実行環境の引数の長さの上限に達して失敗することがあります。これを避けるため、可変長の値は一時ファイル経由で渡します。テーブルの抽出では、実測でこの上限が131,071バイトで打ち切られることを確認しています。この対策は2026-07-29に一度導入されましたが、2026-08-11の大規模な書き換えで直接展開の形へ戻ってしまい対策が失われ、2026-08-16に再度対策を入れ直した経緯があります。手元の環境で件数が少なく問題が再現しないことを理由に、一時ファイル経由の受け渡しを外してはいけません。画面の抽出では、共通クライアント経由の呼び出しを解決する際、対応表の件数が多いと呼び出しのたびに検索を起動します。この形では実行時間が大きく劣化することを実測しています（画面35件×対応表159件で20秒から2分超）。これを避けるため、検索文字列を1回だけ事前に切り出し、まとめて1回で走査します。一時ディレクトリを作る箇所は、既定の一時領域ではなく明示した場所を使います。既定のままだと、書き込みを制限する実行環境で失敗することがあります。原本の文字の符号化が不明な場合の走査には、環境のロケール設定に左右されない形を使います。左右される形のままだと、想定と異なる符号化の原本で不正な文字列という警告が出ることがあります。
