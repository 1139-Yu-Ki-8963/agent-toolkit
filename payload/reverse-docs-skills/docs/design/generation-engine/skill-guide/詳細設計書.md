# generation-engine/scripts/skill-guide 群 詳細設計書

対象は `docs/tasks/自己設計書整備の指示書.md` 4.5節の手順で洗い出した第1優先（素直でない実装を持つ）2本。群全体の役割・呼び出し関係・共通する背景は `基本設計書.md` を参照する。ここでは各スクリプトの実装契約と、なぜその実装を採ったかという実装判断を書く。

各節の「実装判断」は指示書4.2節の4点（1: なぜ素直な形を採らなかったか、2: 実測値、3: 環境依存かどうか、4: 過去に消えて再発した経緯）に沿って記載する。

## apply-guide-style.sh

### 実装契約

- 引数: 省略時（一覧表示のみ）、または `--apply`（実書き込み）、または `--self-test`（統一適用の妥当性検査）
- 環境変数: `TMPDIR`
- 出力: 標準出力へ対象・未適用件数の集計（既定モード）、または適用件数（`--apply`）、または9項目のPASS/FAIL（`--self-test`）
- 終了コード: 統一定義（`guide-style.css`）不在・対象ガイド0件で `exit 1`。`--self-test` は1項目でも不合格なら `exit 1`。既定モード・`--apply` は正常終了で `exit 0`
- 副作用: `--apply` 時、未統一のガイドHTMLの `<style>` 中身を書き換える。書き換えは `mktemp` で作った一時ファイルへ組み立ててから `mv` で置き換える（中断時に元ファイルを壊さない）

### 実装判断

1. **なぜ素直な形を採らなかったか**: 3点ある。
   (a) `<style>〜</style>` の中身の置き換えに `sed` を使わず `awk` で行単位に組み立てる。理由は本体コメント（48〜49行目）に既に記載済み: 「sed 置換は CSS 中の `/` や `()` でエスケープ事故を起こしやすいため使わない」。
   (b) 書き換え結果を直接ファイルへ上書きせず、明示テンプレート付きの `mktemp` で一時ファイルを作ってから `mv` で置き換える。素直な形（`awk ... > "$f"` の直接リダイレクト）は、途中でスクリプトが中断した場合に元ファイルの内容を失う（リダイレクトは書き込み先を先に空にするため）。一時ファイル経由＋`mv`（同一ファイルシステム内なら原子的な置き換え）にすることで、中断時も元ファイルが壊れない。
   (c) 旧名（`-guide.html`）を指すパス参照の検査（`--self-test` 項目7）に、素直な形（`grep -rn` での全ディレクトリ走査）ではなく `git grep` を使う。gitignore対象（生成物・依存ディレクトリ等）を自動的に除外できるため。既知の限界として、追跡されていない（gitに未addの）ファイルは走査されない（`.claude/rules/always/skill-guide/html/rule.md` の検査7節に同旨の記載あり）。
2. **実測値**: 実測値なし（(a)(b)(c)いずれも定性的な理由のみで、具体的な失敗事例の再現・計測は行っていない）。
3. **環境に依存するかどうか**: (a) は環境非依存（`sed`のエスケープ規則はシェル実装に依らず一般的な注意点）。(b) はサンドボックス実行環境かどうかに依存する（基本設計書5.1節参照）。**手元の書き込み制限が無い環境で裸のmktempや直接リダイレクトに戻しても動くことを理由に、一時ファイル経由の置き換えを外すな。**(c) は環境非依存（git grepの挙動はリポジトリの追跡状態に依るが、OS差は無い）。
4. **過去に消えて再発した経緯**: 記録なし。(a)(c) は本体・関連rule.mdに既存の理由記載があったが、(b) の一時ファイル経由の理由（サンドボックス実行環境での裸mktemp失敗）と(c) の理由（gitignore対象の自動除外）はコメントが無かったため、本作業で追記した。

## check-guide-script-paths.sh

### 実装契約

- 引数: 省略時（全ガイドを走査）、または `--self-test`（判定の妥当性検査）
- 環境変数: `TMPDIR`
- 出力: 標準出力へ `[FAIL] <guide> -> <path>` の一覧と「走査 N 件 / 不在 N 件」の集計
- 終了コード: 不在パスが0件で `exit 0`。1件以上あれば `exit 1`（`set -uo pipefail` を使用。`-e` は指定していない）。`--self-test` は3ケースいずれか不合格で `exit 1`
- 副作用: なし（読み取り専用）。`--self-test` のみ一時ディレクトリを作り削除する

### 実装判断

1. **なぜ素直な形を採らなかったか**: 2点ある。
   (a) `find`・`grep` の出力を素直な形（ロケール指定なしの `sort`）ではなく `LC_ALL=C sort` へ通す。理由は基本設計書5.2節のとおり、実行環境の照合順序に依存しない決定的な順序（走査順・報告順）を保証するため。
   (b) `--self-test` の一時ディレクトリ作成で、明示テンプレート付き `mktemp -d` に加え、`2>/dev/null` でエラー出力を抑え `|| tmp=""` でコマンド自体の失敗も明示的に捕捉し、続けて `[ -z "$tmp" ] || [ ! -d "$tmp" ]` で二重に存在確認する。素直な形（`mktemp -d` の結果をそのまま使い、失敗時はスクリプトの異常終了に任せる）ではなく、失敗を検知して「実行1件 / 合格0件 / 不合格1件」という自己検査の集計形式に沿った形で報告してから明示的に `return 1` する。
2. **実測値**: 実測値なし。
3. **環境に依存するかどうか**: (a) は環境（実行環境の照合順序）に依存する。**手元の環境で走査順の違いが体感できないことを理由に `LC_ALL=C` を外すな。**(b) はサンドボックス実行環境（書き込み自体を拒む環境）に依存する。**手元の書き込み制限が無い環境で単純な `mktemp -d` の結果をそのまま使っても動くことを理由に、二重の存在確認を外すな。**
4. **過去に消えて再発した経緯**: 記録なし。いずれの箇所にも理由コメントが無かったため、本作業で追記した。
