# generation-engine/scripts/rule-proposal 群 基本設計書

## 1. この文書の位置づけ

このリポジトリ自身の `generation-engine/scripts/` は、対象リポジトリへ設計書を生成する道具である。その道具自身には、これまで設計書が無かった（`docs/tasks/自己設計書整備の指示書.md` 2.1〜2.2 節）。本文書は `rule-proposal/` 1 群について、納品物と同じ二層構造（基本設計書・詳細設計書）を適用する。

対象は `generation-engine/scripts/rule-proposal/` 配下のスクリプト1本（実測。`.sh` 1本のみ。`rule.md` は本スクリプト新規作成時に既存の hook（`check-sh-design-decision.sh`）が求めるADR記載場所であり、スクリプトではない）。

`rule.md` は本群のスクリプト（`build-rule-proposal.sh`）について、既に「必要性・代替案不採用理由・保守責任者・廃棄条件」形式のADR（設計判断）を持つ。これは「このスクリプトがなぜ存在するか」を扱うものであり、本文書とは重複しない。本文書は「存在する前提で、なぜその内部実装（個々の行）がそうなっているか」を扱う。

## 2. この群が何をするか

規約提案HTML（対象リポジトリのコード調査から起こした規約の叩き台。現場エンジニアが採用・保留・却下を判定するための文書）を、入力JSON（章・カテゴリ・観測事項・提案文などを持つ）から決定的に生成する単一のビルダーである。`.claude/rules/scoped/portal/page-conventions/rule.md` が定める「適用対象から外す」ページの1つであり（意匠・生成方式が独立している）、共通シェル（サイドバー等）を使わず単一HTMLとして出力する。

| スクリプト | 役割 |
|---|---|
| `build-rule-proposal.sh` | 入力JSONから規約提案HTML（判定ボタン・進捗バー・TOC・章節構造・図・横断的所見を含む）を組み立て、書き出し後に外部の静的検査（`reviewing-explanatory-html` skill）を任意で実行する |

## 3. 群内スクリプトの呼び出し関係

本群はスクリプト1本のみであり、群内での呼び出し関係は無い。

## 4. 他の群との依存関係

- `../render-template.sh`（`generation-engine/scripts/` ルート直下、この群の外）を `source` する（451行目）
- `delivery-payload/templates/rule-proposal/rule-proposal-template.html`（テンプレート本体）を土台にする
- `$HOME/agent-home/skills/reviewing-explanatory-html/scripts/verify-html-static.mjs`（このリポジトリの外、実行マシン固有の設定資産置き場）にある静的検査器を任意で呼ぶ（5.1節参照）。このパスは `generation-engine/scripts/` の中で唯一、リポジトリ外のホームディレクトリ配下へ依存する箇所である
- `generation-engine/scripts/rules/build-derived-rules.sh` とは入力・出力・関心が異なり（本群は「取り込み前の提案文書生成」、あちらは「取り込み後の派生物変換」）、呼び出し関係を持たない（`rule.md`「代替案を採用しなかった理由」節に既存の記載あり）

## 5. 共通する実装上の判断

本群はスクリプト1本のみのため、共通判断ではなく本スクリプト固有の実装判断として扱う。詳細は `詳細設計書.md` を参照。

### 5.1 リポジトリ外（`$HOME/agent-home`）への依存

`VERIFY_SCRIPT`（89行目）は `$HOME/agent-home/skills/reviewing-explanatory-html/scripts/verify-html-static.mjs` を指す。`generation-engine/scripts/` は本来「このリポジトリと同梱スクリプトだけで動く」ことを目指す（`verification/check-self-contained.sh` が走査する自立性の判定基準）が、本群はその例外であり、実行マシンに `agent-home` が存在しない環境では静的検査自体が実行されない（警告のみでスキップ。5.2節参照）。**このパスを他の環境（agent-homeを持たない実行環境・納品先）でも動くように「同梱する」方向へ書き換える場合は、静的検査の内容自体（禁止色・box-shadow・未解決`{{`等）を重複実装することになる点に注意する。**
