# generation-engine/scripts/matrix 群 詳細設計書

対象は `docs/tasks/自己設計書整備の指示書.md` 4.5節の手順で洗い出した第1優先（素直でない実装を持つ）1本。群全体の役割・呼び出し関係は `基本設計書.md` を参照する。ここでは実装契約と、なぜその実装を採ったかという実装判断を書く。

「実装判断」は指示書4.2節の4点（1: なぜ素直な形を採らなかったか、2: 実測値、3: 環境依存かどうか、4: 過去に消えて再発した経緯）に沿って記載する。

## build-matrix-pages.sh

### 実装契約

- 引数: `<page-type> <data.json> <output-html-path> [--portal-dir <path>] [--project-name <name>] [--generated-at <iso8601>] [--catalog <file>]`、または `--self-test`
- `page-type`: `permission-screen` | `permission-function` | `crud` | `traceability` | `confirmation-survey` | `ai-assets`
- 環境変数: 明示的な参照なし（`TMPDIR` は `--self-test` の一時ディレクトリ生成でのみ使用）
- 出力: `<output-html-path>`（単一ファイル自己完結のHTML。`data.json` の内容は `<script type="application/json" id="matrix-manifest">` にそのまま埋め込む。埋め込みJSONは原本と完全一致させる契約）
- 終了コード: `jq` 不在・`data.json` 不在・`--generated-at` 不一致・テンプレート/`tokens.css` 不在・`data.json` がJSONオブジェクトでない・必須トップレベルキー欠落・未知の`page-type` のいずれかで `exit 1`。必須成分がすべて0件（`confirmation-survey` を除く）の場合は `exit 0`（ページを生成しない。既存の旧ページがあれば削除する）。正常終了は `exit 0`
- 副作用: `mkdir -p "$(dirname "$OUTPUT_HTML")"`。既存の`$OUTPUT_HTML`は、必須成分が全0件かつ`ALWAYS_GENERATE`でない場合にのみ削除される

### 実装判断

1. **なぜ素直な形を採らなかったか**: テンプレートへのマーカー置換（`render_template`。`../render-template.sh` へ委譲）を、マーカーごとに独立して `sed`/`grep` を呼ぶ素直な多重パス置換ではなく、単一パス（document-order）走査で行う。理由は、JSON埋め込みマーカー（`<!--MATRIX_JSON-->`/`<!--ASSETS_JSON-->`）をテンプレート内で物理的に最後に出現させ、単一パス走査が自動的にこれを最後に処理する構成にすることで、埋め込むJSON内容（画面名・機能名等の自由記述値）が偶然他のマーカー文字列（`{{GENERATED_AT}}`・`<!--MATRIX_JSON-->`等）と一致した場合の誤爆（二重置換・意図しない再置換）を避けるためである（本体該当箇所のコメント）。素直な形（マーカーごとに独立した多重パス置換）は、JSON内容にマーカー文字列が偶然含まれた場合、その内容自体がさらに置換対象として拾われてしまう可能性がある。
2. **実測値**: 実測値なし。ただし `--self-test` がこの誤爆を検出できるフィクスチャを持つ。`permission-function` ケースはマーカー文字列衝突を意図的に含む値（`ユーザー編集{{GENERATED_AT}}<!--MATRIX_JSON--><!--ASSETS_JSON-->{{DATA_SOURCE}}`）を `functionName` に埋め込み、`ai-assets` ケースは正規表現風のバックスラッシュ（`\d+`）を含む値で誤爆検証する（本体該当箇所・該当箇所）。いずれも埋め込みJSONが原本フィクスチャと完全一致することを `diff` で検証する。
3. **環境に依存するかどうか**: 依存しない。この判断はOS・実行環境ではなく、埋め込むデータの内容（対象リポジトリの画面名・機能名等に偶然マーカー文字列と一致する値が含まれるかどうか）に依存する。データ内容依存であるため、**特定の対象リポジトリで誤爆が再現しないことを理由に、単一パス方式を多重パス置換へ戻すな。**
4. **過去に消えて再発した経緯**: 記録なし。単一パス方式は `git log -p --follow` で辿れる本ファイルの履歴19件のうち、コミット `c23b92d`「ポータルトップと一覧・マトリクスを設計台帳デザインへ刷新」で導入された記載が最初で、以降の履歴でこの方式が外れて多重パス置換へ戻された形跡は見当たらない。
