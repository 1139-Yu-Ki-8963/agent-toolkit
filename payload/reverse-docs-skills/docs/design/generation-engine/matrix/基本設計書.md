# generation-engine/scripts/matrix 群 基本設計書

## 1. この文書の位置づけ

このリポジトリ自身の `generation-engine/scripts/` は、対象リポジトリへ設計書を生成する道具である。その道具自身には、これまで設計書が無かった（`docs/tasks/自己設計書整備の指示書.md` 2.1〜2.2 節）。本文書は `matrix/` 群について、納品物と同じ二層構造（基本設計書・詳細設計書）を適用する3群目である（1群目は `docs/design/generation-engine/extract/`、2群目は `docs/design/generation-engine/unit-list/` を参照）。

対象は `generation-engine/scripts/matrix/` 配下の `.sh` 1本（実測。`find generation-engine/scripts/matrix -name '*.sh' | wc -l`）。この群は他の群と異なり単一スクリプトで構成される。

## 2. この群が何をするか

`extract/` 群が導出したマトリクス・対応表データ（`permission-matrix.json`・`crud-matrix.json`・`traceability.json`・`confirmation-survey.json`）と、AI設定資産データを、page-type ごとに対応するテンプレートへ流し込み、単一ファイル自己完結の HTML 5種を決定的に生成する。行 HTML の組み立ては行わず、埋め込んだ JSON をテンプレート内 JS が実行時に描画する方式を取る（本体コメント該当箇所）。

| page-type | 入力データ | テンプレート | 必須トップレベルキー |
|---|---|---|---|
| `permission-screen` | `permission-matrix.json` | `delivery-payload/templates/matrix/permission-screen-matrix-template.html` | `roles`, `screens` |
| `permission-function` | `permission-function-matrix.json`（`build-permission-function-data.sh` の出力） | `delivery-payload/templates/matrix/permission-function-matrix-template.html` | `roles`, `functions` |
| `crud` | `crud-matrix.json` | `delivery-payload/templates/matrix/crud-matrix-template.html` | `tables`, `features` |
| `traceability` | `traceability.json` | `delivery-payload/templates/matrix/traceability-template.html` | `screens`, `apis`, `tables` |
| `confirmation-survey` | `confirmation-survey.json`（`build-confirmation-survey-data.sh` の出力） | `delivery-payload/templates/matrix/confirmation-survey-template.html` | `questions`（0件でも常に生成する唯一の例外。改善課題1-169） |
| `ai-assets` | AI設定資産抽出データ（`extract-ai-assets.sh` の出力） | `delivery-payload/templates/ai-assets/ai-assets-template.html` | `rules`, `skills`, `subagents`, `hooks` |

必須キーが揃っていても、その値（配列）がすべて0件ならページ生成をスキップする（既存の旧ページがあれば削除する）。`confirmation-survey` のみ `ALWAYS_GENERATE` により0件でも生成する。

## 3. 群内スクリプトの呼び出し関係

群内に呼び出し関係は存在しない（実測: スクリプトが1本のみ）。`build-matrix-pages.sh` 自身は `<page-type> <data.json> <output-html-path>` を受け取る単発 CLI として独立して呼べる。

## 4. 他の群との依存関係

- `../render-template.sh`（`generation-engine/scripts/` ルート直下）を `source` し、テンプレートへのマーカー置換を行う
- `../shell-injection.sh`（同ルート直下）が存在すれば `source` し、共通シェル（サイドバー等）の注入を行う
- `extract/build-matrix-data.sh`・`extract/build-permission-function-data.sh`・`extract/build-confirmation-survey-data.sh`・`extract/extract-ai-assets.sh` が生成したデータをこの群は入力として受け取る（この群はデータの「導出」ではなく「HTML化」を担う）。`--self-test` の連結ケースは `extract/build-matrix-data.sh` を実際に呼び、両スクリプト間のスキーマドリフトを検証する（本体該当箇所）
- `tests/test-matrix-header-compact-layout.cjs`（`generation-engine/scripts/tests/` 配下）を `--self-test` から呼び、ヘッダ行の高さ比率とコントラスト比を実描画で検証する（改善課題1-105）
- `build-portal.sh`（ルート）・`verification/run-layer-full-pipeline.sh`・`unit-list/rebuild-screen-derived-pages.sh` がこの群のスクリプトを呼ぶ側である（実測: `grep -rln "matrix/build-matrix-pages.sh" generation-engine/scripts/`）

## 5. 共通する実装上の判断

この群は単一スクリプトのため、複数スクリプトへ横断する共通の背景は無い。実装判断は個別スクリプトの節（`詳細設計書.md`）にまとめて記載する。

## 6. 詳細設計を個別に持つスクリプト（第1優先: 素直でない実装を持つもの）

`詳細設計書.md` を参照。`build-matrix-pages.sh` 1本について、実装契約と実装判断の節を持つ。

## 7. 詳細設計を個別に持たないスクリプト

無し（群の唯一のスクリプトを第1優先として選定したため）。
