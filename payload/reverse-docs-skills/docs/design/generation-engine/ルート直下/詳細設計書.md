## check-derived-drift.sh

### 実装契約

- 引数: `record <root> [--ledger <path>]` / `status <root> [--ledger <path>]` / `--self-test`
- 環境変数: `TMPDIR`（一時ファイルの既定親。未設定時は `/tmp`）
- 出力: `record` は `<root>/derived-fingerprints.json`（既定。`--ledger` で変更可）へハッシュ台帳を書く。`status` は標準出力へ `CLEAN`/`MODIFIED`/`DELETED`/`ADDED`/`DRIFT` を出力する
- 終了コード: `status` はずれなし0 / ずれあり1 / 台帳なし等の前提不足2。`record` は正常0、一時ファイル作成失敗で1
- 副作用: `record` は一時ファイルへ`jq`のパッチを1件ずつ適用してから台帳へ書き出す。異常終了時のクリーンアップは持たない（`--self-test` のみ `trap` で一時ディレクトリを削除する）

### 実装判断

1. **なぜ素直な形を採らなかったか**: 2点ある。(a) `cmd_record` の一時ファイルを `mktemp "${TMPDIR:-/tmp}/derived-drift.XXXXXX"` という明示テンプレート付きの形で作る。素直な形（テンプレートを省略した裸の `mktemp`）は `$TMPDIR` を無視し、書き込み許可の外にある既定の一時領域を使うため、サンドボックス実行環境では失敗する。(b) `list_targets`（HTML一覧の列挙）が `find | sed | LC_ALL=C sort` という形でロケールを明示指定する。素直な形（ロケール指定なしの `sort`）は、既定ロケールでの照合順序がロケールデータに依存するため、環境や実行タイミングによって列挙順序が変わりうる。
2. **実測値**: 実測値なし（いずれも失敗の再現は環境依存のため、この作業では未実施）。
3. **環境に依存するかどうか**: 両方とも依存する。(a) は書き込み制限のあるサンドボックス実行環境でのみ問題が顕在化する。(b) はシステムの既定ロケール設定に依存する。**手元の環境でいずれも問題が起きないことを理由に、明示テンプレートや `LC_ALL=C` を外すな。**
4. **過去に消えて再発した経緯**: (a) は本ファイル自身が実際に裸の `mktemp` によって失敗した実績を持つ。コミット `803d84cdaad314cf21f8b1dadb9e2119524e0d15`「台帳の道具が一時領域を作れず止まる」（コミットメッセージ: 「引数なしのmktempはTMPDIRを無視し、書き込みを拒まれる場所を使う」）で明示テンプレート付きへ修正された。同種の対策は `extract/` 群の複数スクリプト（`extract/基本設計書.md` 5.1節）にも存在する。(b) は再発記録なし。

## check-portal-entry-freshness.sh

### 実装契約

- 引数: `[--regenerate] <target_repo> <output_root> [dependency_file]`、または `--self-test`
- 環境変数: `TMPDIR`（一時ファイルの作成先）、`REVERSE_DOCS_ENGINE`（再生成コマンドへ渡すエンジンルート）、`TARGET_REPO`・`OUTPUT_ROOT`（再生成コマンドの子シェルへ渡すパス）。`REVERSE_DOCS_ENGINE` の未設定時は本リポジトリのルートを使う
- 出力: 通常検査は `[FRESH|STALE|SKIP]`、判定不能は標準エラーへ `[UNKNOWN]`。`--regenerate` は影響を受ける成果物ごとに `[REBUILD]` または `[REBUILD-SKIP]` を追加する
- 終了コード: 通常の鮮度判定は0、引数・宣言・実行環境・表示コミット元の不備による判定不能は2。`--regenerate` は再生成コマンドの失敗を伝播する
- 副作用: 通常検査は成果物ID一覧の一時ファイルを作りEXIT時に削除する。`--regenerate` は宣言JSONの `rebuildCommand` を子シェルで実行する。`--self-test` は一時Gitリポジトリと出力を作り終了時に削除する

### 実装判断

1. **なぜ素直な形を採らなかったか**: 3点ある。
   (a) 宣言JSONの `rebuildCommand` を実行する際、3種類のパスをコマンド文字列へ直接連結しない。`TARGET_REPO`・`OUTPUT_ROOT`・`REVERSE_DOCS_ENGINE` という環境変数で子シェルへ明示的に渡す。再生成コマンドは成果物ごとに異なり、宣言側がこの3変数名を契約として参照する。位置引数へ変えると既存の宣言コマンドをすべて書き換える必要がある。文字列へパスを埋め込む方法では引用境界も崩れる。
   (b) 影響を受ける成果物ID一覧は、シェル変数や標準出力ではなく一時ファイルで関数間共有する。`detect_freshness` の標準出力は利用者向け判定メッセージであり、ID一覧を混ぜられない。コマンド置換は関数をサブシェルで動かし、変数の更新を失う。Bash 3.2では `mapfile` も使えない。一時ファイルなら検出時の重複除去と再生成時の逐次読み取りを同じ形式で扱える。
   (c) 一時ファイルの削除は、`printf %q` でパスを引用したtrap文字列として登録する。EXIT trapは文字列を再評価する。`affected_file` は `main` のローカル変数であり、関数復帰後の終了処理では参照できない。登録時に値を固定すれば、空白やシェルのメタ文字を含むパスでも単一引数として削除できる。
2. **実測値**: (a)〜(c)の上限値・所要時間・件数の実測値はない。壊れた `code-metrics.json` を表示コミット元にした再現では、修正前は `[STALE]`・終了コード0、修正後は `[UNKNOWN]`・終了コード2になることを自己テストと個別再現で測る。
3. **環境に依存するかどうか**: (a)(b)は環境非依存で、宣言JSONの契約、判定出力との分離、Bash 3.2互換性に基づく。(c)もtrapの再評価とシェルの有効範囲に基づくため環境非依存である。`mktemp` の作成先だけは実行環境に依存し、失敗時は `[UNKNOWN]`・終了コード2とする。
4. **過去に消えて再発した経緯**: 記録なし。3点ともコミット `3054f07` で本スクリプトが導入された時点から存在したが、本体コメントと詳細設計書の実装判断が欠けていたため、2026-08-23の取り込み後検証で記録不足として見つかった。

## audit-consistency.sh

### 実装契約

- 引数: `<画面ディレクトリ>` / `--list-contract-files <画面ディレクトリ>` / `--self-test`
- 環境変数: `AUDIT_STRICT_P16`（`1` で §16 要確認事項一覧の未解消をWARNから違反へ昇格）
- 出力: 通常モードは標準出力へ検査結果（PASS/WARN/違反）を出す。`--list-contract-files` は実装契約章のファイル一覧を1行1パスで標準出力へ出す
- 終了コード: 通常モードは違反あり1 / WARNのみ・正常は0。`--list-contract-files` は取得成功0 / 取得不可1
- 副作用: `output-layout.sh` を `source` する。`--self-test` は `mktemp -d` でフィクスチャ用の一時ディレクトリを作り `trap` で削除する

### 実装判断

1. **なぜ素直な形を採らなかったか**: 重複除去・集合比較のコマンド（`sort -u`・`comm -23`・`comm -13`）へ `LC_ALL=C` を明示している。素直な形（ロケール指定なしの呼び出し）は、既定ロケールで多バイト文字（画面詳細設計書.md が含む日本語の意味語キー等）の判定を誤り、異なる意味語キーを同一と判定して集合比較の結果を縮退させうる。本ファイルはこの対策自体の退行を検知する自己テスト（ケース29「整合検査-文字環境依存の回帰防止」、1074〜1094行目）を既に持つ。全 `sort -u`/`comm -23`/`comm -13` 呼び出しへの `LC_ALL=C` の付与を静的に検査し、検査文自身が自己マッチしないよう探索語を変数で組み立てる工夫を伴う。
2. **実測値**: 実測値なし（意味語キーの縮退を実際に再現させた実測は無い。ロケールデータの違いによる潜在リスクとして対策済み）。
3. **環境に依存するかどうか**: 依存する。システムの既定ロケール設定に依存する。**手元の環境で意味語キーの縮退が再現しないことを理由に `LC_ALL=C` を外すな。**
4. **過去に消えて再発した経緯**: 記録なし。ケース29自体が最初から退行検知の自己テストとして導入されており（`git log -S'ケース29'` で該当コミットは1件のみ）、消えて再発した実績は見当たらない。
5. **なぜ素直な形を採らなかったか（検査 l）**: 検査 l（非該当記述の根拠併記チェック）の章単位集約行を検出する awk 呼び出しに `LC_ALL=en_US.UTF-8` を明示している。負の文字クラス（`[^[:space:]）)]`）で全角文字（`）`）を除外して根拠の有無を判定するが、`LC_ALL=C` の下ではこの負の文字クラスが全角文字を正しく除外できず、根拠が正しく記入された行（例:「本領域は全項目非該当（根拠: 対象機能なし）」）まで誤って未記入と判定する偽陽性を生む。この点は本節1〜4の `LC_ALL=C` 明示（完全一致比較・重複除去用）とは逆に、UTF-8 ロケールを明示する必要がある。使い分けの一般原則は `.claude/rules/always/design-record/implementation-decision/rule.md`「ロケールの使い分け」節を参照する。
6. **実測値**: 「本領域は全項目非該当（根拠: 対象機能なし）」という正しく記入された行に対し、`LC_ALL=C` 下では誤って検出（偽陽性）、`LC_ALL=en_US.UTF-8` 明示後は誤検出なしを実測した（改善課題1-241、bash 5.3.15 / macOS 標準 awk 20200816）。
7. **環境に依存するかどうか**: 依存する。呼び出し元シェルの環境変数に `LC_ALL=C` が設定されているかどうかに依存する。ファイル冒頭の `export` では呼び出し元の前置き代入に上書きされるため、awk 呼び出し自体へ都度明示する必要がある。**手元の環境で偽陽性が再現しないことを理由に `LC_ALL=en_US.UTF-8` の明示を外すな。**
8. **過去に消えて再発した経緯**: 記録なし。改善課題1-241で新規に発見・是正した。

## prefill-design-from-facts.sh

### 実装契約

- 引数: `<封印済みfacts.yml> <画面詳細設計書.md>`、または `--self-test`
- 環境変数: `TMPDIR`
- 出力: `<画面詳細設計書.md>` を直接書き換える（Pass1: facts.ymlの各アイテムを対応表へ挿入、Pass2: 残るプレースホルダを章番号付きマーカーへ一括置換）。標準出力へ転記サマリJSONを出す
- 終了コード: 引数不足・入力ファイル不在で `exit 2`。転記中の異常（アンカー不明・区切り線不明）は `awk` 側が2または3で終了し呼び出し元へ伝播する

### 実装判断

1. **なぜ素直な形を採らなかったか**: 3点ある。(a) `main`・`append_multiline_literal_blocks` の一時ファイル・一時ディレクトリを、明示テンプレート付きの `mktemp`/`mktemp -d` で作る。素直な形（裸の `mktemp`）は書き込みを拒む環境で失敗する。(b) `insert_table_rows`・`insert_list_rows`・自己テスト内の `extract_section` の3関数が、Markdownを走査する `awk` へ `LC_ALL=C` を明示する。転記先の画面詳細設計書.mdは日本語（多バイト文字）を含み、既定ロケール下のawkが「不正なマルチバイト列」の警告を出したり正規表現の走査結果が乱れたりすることを避けるため、バイト単位の走査に固定している。(c) `check_no_replacement_char`（改善課題1-160）は、転記後の出力に置換文字（U+FFFD）が含まれていないかを検査する防御的チェックを持つ。根本原因（転記処理のどこが複数バイト文字を破損させるか）は `LC_ALL=C`・標準ロケール双方での再検証でも特定できなかったため、原因不明のまま無警告混入だけを防ぐ形で残されている。
2. **実測値**: (a)(b) は実測値なし。(c) も実測値なし（根本原因が未特定のため、混入率等の定量値は取得していない）。
3. **環境に依存するかどうか**: (a) はサンドボックス実行環境かどうかに依存する。(b) はシステムの既定ロケール設定に依存する。(c) は環境依存の有無自体が未確定（`LC_ALL=C`・標準ロケール双方で検証済みだが原因を特定できていないため、特定のロケール設定に依存するとは言い切れない）。**(a)(b) について、手元の環境で問題が起きないことを理由に明示テンプレートや `LC_ALL=C` を外すな。(c) については、原因が未特定のまま防御的検査を外すな。**
4. **過去に消えて再発した経緯**: (a)(b) は本ファイル自身での消失・再発の記録なし（今回の作業で本体コメントへ理由を追記した）。同種の対策は `check-derived-drift.sh`・`extract/` 群に存在する。(c) は改善課題1-160として最初から防御的検査として追加されており、消えて再発した記録はない。

## build-portal.sh

### 実装契約

- 引数: `<対象リポジトリ> <docsルート> <ポータル出力先>`、または `--self-test` / `--self-test-related-material-links`
- 環境変数: `TMPDIR`
- 入力: 通常の設計書・マニフェストに加え、
  `<docsルート>/<manifestsRoot>/detail-pages/`配下の`techstack-page-data.json`・
  `env-page-data.json`・`glossary-page-data.json`。3ファイルは各生成スキルで検証済みの
  page-dataを永続化したものとする
- 出力: ポータルHTMLの束（`<ポータル出力先>`配下）。準備済みpage-dataがある場合は
  技術スタック・環境構築手順・用語辞書を再生成する。対象リポジトリの`.claude`配下に
  rules・skills・agentsのディレクトリ、または`settings.json`があればAI設定資産も抽出する。
  抽出結果は`<docsルート>/<manifestsRoot>/ai-assets.json`とAI設定資産ページへ再生成する
- 終了コード: 引数不足・`output-layout.sh`の解決失敗・詳細ページ生成失敗・AI設定資産の
  抽出または生成失敗で`exit 1`。準備済みpage-dataが無い種別は`SKIP`を記録する。
  対応する既存HTMLが残っている場合は古い版を成功扱いにせず`exit 1`。
  AI設定資産の抽出結果が0件の場合も`SKIP`を記録し、既存ページが残っていれば`exit 1`。
  `--self-test`系はケース不合格があれば`exit 1`、一時ディレクトリを作れず判定できないケース49は`exit 2`
- 副作用: `render-template.sh`・`output-layout.sh` を `source` する。`portal-catalog.mjs` を `node` 経由で呼ぶ。ビルド実行中だけ使う複数の一時ファイル（`OUTPUT_LAYOUT_RESOLVED_FILE`・`PORTAL_MD_MAP_FILE`・`PORTAL_IMPL_MAP_FILE` 等）を作り、新しい正本ファイルは作らない。Markdown対応表にあるHTMLと、解決済みcatalog exact outputのうち別生成器に属するHTMLは保持する。対応表外では、共通文書生成器の解決済みcatalog exact output、またはbuild-portal固有の`footer.pt-footer`内に固定スタンプと生成元要素を持つHTMLだけを共通文書変換後と`--post-build`直後に警告して削除する。コメント、コード例、フッター外にある同じ文字列は証拠にせず、それ以外の未知HTMLも警告して保持する

### 実装判断

1. **なぜ素直な形を採らなかったか**: 4点ある。(a) `create_physical_tmpdir` は `mktemp -d` の戻り値をそのまま使わず、`(cd "$d" && pwd -P)` で物理パスへ解決してから返す。素直な形（`mktemp -d` の戻り値をそのまま使う）は、macOSでは `/var` が `/private/var` へのシンボリックリンクであるため、埋め込みNode検証（`assertNoLexicalSymlink`、57・78〜79行目）が書き込み先をレキシカルシンボリックリンクとして拒否してしまう。この関数は self-test 群（15箇所以上）から広く再利用される。(b) 本スクリプトの `--self-test` は、機能がテンプレート由来の決定的生成であるにもかかわらず実測815秒かかる。素直な形（他の自己テストと同じ既定のタイムアウト内で完走を期待する）を採らず、`verification/run-layer-machine-checks.sh` 側に「宣言済み長時間（DECLARED-LONG）」として明示登録することで、TIMEOUTや途中停止の疑いとしてではなく既知の事実として扱われる。(c) `RULES_ROOT` が存在しない場合の警告分岐（3693行目付近）で、変数展開を `$RULES_ROOT` のまま全角括弧「（」を直後に続ける素直な書き方を採らず、`${RULES_ROOT}` と波括弧で囲む。`set -u` の環境で `$RULES_ROOT（...）` と書くと、bashの変数名解釈が全角文字を変数名の一部として誤読し `unbound variable` エラーになることを実装時に手動再現で発見した。(d) 孤立HTMLは`docs`配下の全HTMLを素直に削除すると別生成器のページや手作業で置いた未知HTMLまで消すため、Markdown対応表にあるHTMLと別生成器の解決済みcatalog exact outputを保持する。残りは、共通文書生成器の解決済みcatalog exact output、またはbuild-portal固有のフッター要素があるHTMLだけを警告して削除するOR条件とし、どちらにも該当しない未知HTMLは警告して保持する。
