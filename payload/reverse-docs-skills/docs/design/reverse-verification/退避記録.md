# リバース検証の退避記録

実行を伴う検証を省略してよいのは、実行を試みたうえで実行できなかった場合だけである。`docs/design/reverse-verification/設計.md`「退避の条件」が定めるとおり、「実行が要る」という理由だけでの退避を禁じる。退避の記録には、何をどう試して何がどう失敗したかを書く。

追記は `generation-engine/scripts/verification/record-deferral.sh` が行う。`--item`・`--version`・`--tried`・`--failed`・`--condition` のいずれか 1 つでも欠けると、終了コード 1 で拒否され記録できない。`## 記録` の見出し直後へ新しい節を差し込むため、新しい記録ほど上に来る。

## 記録の形式

1 件の退避には、次の項目を含める。

| 項目 | 内容 |
|---|---|
| 退避した項目 | 実行できなかった検証の名称 |
| 退避した日時 | 退避を記録した日時 |
| 版 | 対象のコミットハッシュを全長で記す。短縮形は使わない |
| 試したこと | 実際に実行したコマンド |
| 失敗の内容 | 出力の要点 |
| 再実行の条件 | 何が変われば試せるようになるか |
