## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | 機能設計書 | 機能単体テスト設計書 |
| 内部結合 | 1つの機能の中で関数・メソッドが結合した状態（外部の振る舞い） | 機能設計書 | 機能結合テスト設計書（本書） |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## テスト対象

| 対象 | 確認する内容 | 根拠となる機能設計書の章 |
|---|---|---|
| 横断集約 | 4系統（推定名称・要手動確認・権限未設定・要確認事項）の質問行が正しく導出されること | §3 業務フロー、§5 データ |
| 回答の記入から反映まで | 回答済みの行が本文セルへ反映され、台帳の状態が反映済みへ変わること | §3 業務フロー、§4.2 状態と遷移の制約 |
| 未回答行の保持 | 未確認・確認中の行が推測で変更されず台帳に残ること | §3.2 分岐と例外フロー |
| 反映後の整合検査 | 反映済みセルの値と台帳のanswerが一致し、キー重複が無いこと | §8.1 業務エラー一覧 |
| 承認済み設計書の未解消行検査 | statusがapprovedの設計書に未解消行が残っていないこと | §8.1 業務エラー一覧 |

機能設計書で確定した範囲だけを記入する。対象外の構成要素は「本書が扱わない範囲」に記録する。

## §1 テスト観点

**この節の位置づけ: 仕様**

§1は正常・異常・境界を含む全観点の一覧です。
§5と§6は、§1のうち異常と境界の観点を列ごとに詳しく述べる部分集合です。
§5と§6では新しい観点キーを作らず、§1と同じ観点キーを使います。
実行する全ケースは§2だけに記載し、§1の全観点へ1件以上のケースを対応させます。
実行するテストの件数は§2のデータ行数だけで数えます。

観点は機能設計書の業務フロー・業務ルール・エラーと業務メッセージの各章から起こす。

| キー | 観点 | 由来する機能設計書の章 |
|---|---|---|
| aggregate-4systems | 4系統の質問行が横断集約データへ正しく導出される | §3.1 正常系フロー |
| answer-recorded | 回答者がanswer・answeredDateを記入し、statusを回答済みへ変える | §3.1 正常系フロー |
| unanswered-kept | 未確認・確認中の行に回答が無いとき台帳に残り、実行結果に理由が表示される | §3.2 分岐と例外フロー |
| not-applicable | 設計対象外と合意した行だけをstatusが対象外へ変わる | §3.2 分岐と例外フロー |
| reflect-success | 回答済みの行が指定セルへ反映され、statusが反映済みへ変わる | §3.1 正常系フロー |
| reflect-target-missing | 反映先が見つからないとき設計書と台帳を変更せず異常終了する | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |
| check-only-consistent | 反映後の`--check-only`が整合を確認して終了コード0を返す | §8.1 業務エラー一覧 |
| duplicate-key | 台帳内でkeyが重複しているとき不合格になる | §8.1 業務エラー一覧 |
| approved-unresolved | 承認済み設計書に未解消行が残っているとき不合格になる | §8.1 業務エラー一覧 |

## §4 期待結果

**この節の位置づけ: 仕様**

| ケースのキー | 期待する結果 | 確認の方法 |
|---|---|---|
| aggregate-4systems | questions配列に4系統それぞれ1件以上が含まれる | confirmation-survey.jsonのquestions配列を確認する |
| answer-recorded | 台帳の該当行のstatusが回答済みになる | 台帳ファイルを確認する |
| unanswered-kept | 未確認・確認中の行が変更されず、実行結果に「未回答のため残す」とキー・状態が出る | apply-confirmation-answers.mjsの出力を確認する |
| not-applicable | 対象外にした行が推測で変更されていない | 台帳のstatus・answerを確認する |
| reflect-success | 設計書の指定セルがanswerの値に、台帳のstatusが反映済みになる | 反映後の設計書と台帳を確認する |
| reflect-target-missing | 設計書・台帳が変更されず異常終了する | 終了コードと、設計書・台帳の内容が変更前と一致することを確認する |
| check-only-consistent | `PASS: 設計書と要確認事項台帳は整合しています`が出て終了コード0を返す | `apply-confirmation-answers.mjs --check-only`を実行する |
| duplicate-key | 「台帳でキーが重複」を含む不合格を返す | check-confirmation-ledger.mjsの出力を確認する |
| approved-unresolved | 「承認済み設計書に未解消行」を含む不合格を返す | check-confirmation-ledger.mjsの出力を確認する |

**この節の位置づけ: 仕様**

## §6 境界値

**この節の位置づけ: 仕様**

| 観点のキー | 対象の項目 | 境界の値 | 境界の直前と直後の扱い |
|---|---|---|---|
| answer-recorded | 台帳内の回答済み行数 | 1件（0件との境界） | 0件なら反映処理の対象が無く終了、1件以上あれば反映を試みる |
| approved-unresolved | 設計書frontmatterのstatus | approved（draft・その他値との境界） | approved以外なら未解消行があっても不合格にしない、approvedなら未解消行の有無を検査する |

## §7 網羅基準

**この節の位置づけ: 仕様**

| 観点 | 基準 |
|---|---|
| 条件の網羅 | §1の全観点キー（9件）に§2で1件以上のケースを対応させる |
| 分岐の網羅 | §3.2の分岐と例外フロー6行のうち、テスト対象とした5行（未回答保持・対象外・反映先不在・反映後不整合・キー重複）を網羅する |
| 境界の網羅 | 回答済み行数0件/1件、設計書statusのapproved/非方法の各境界を網羅する |
