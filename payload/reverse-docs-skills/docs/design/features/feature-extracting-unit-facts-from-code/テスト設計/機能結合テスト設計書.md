## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | 機能設計書 | 機能単体テスト設計書 |
| 内部結合 | 1つの機能の中で関数・メソッドが結合した状態（外部の振る舞い） | 機能設計書 | 機能結合テスト設計書（本書） |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## テスト対象

| 対象 | 確認する内容 | 根拠となる機能設計書の章 |
|---|---|---|
| facts抽出〜確定〜再現性検証の一連の流れ | Phase 1〜6が意図した順序で完走し、独立再計数・改ざん検知・再現性検証をすべて通過すること | §3 業務フロー |
| 再計数不合格時の差し戻し | recount-facts.shの不合格でPhase 2へ戻り、上限3回・発散2回連続で中断すること | §3 業務フロー、§8 エラーと業務メッセージ |
| 再現性検証のdiff分類 | 独立した2回目の抽出結果に差分がある場合、順序差異／キー命名揺れ／共通文書由来のいずれかに分類されること | §3 業務フロー、§4 業務判断ポイント |

## テストの粒度と自動化の方針

| 項目 | 方針 |
|---|---|
| テストの粒度 | 1ケースで確認する振る舞いを記入します。 |
| 自動化 | recount-facts.sh・seal-facts.shのexit codeによる自動判定が可能です。手動確認は不要です。 |

## §1 テスト観点

**この節の位置づけ: 仕様**

観点は機能設計書の業務フロー・業務ルール・エラーと業務メッセージの各章から起こします。

| キー | 観点 | 由来する機能設計書の章 |
|---|---|---|
| 正常抽出完了 | screen/pythonいずれかのプロファイルで抽出・再計数・確定・再現性検証まで完走する | §3.1 正常系フロー |
| 再計数差し戻し | recount-facts.shが不合格のときPhase 2へ差し戻し、上限3回で収束しなければ中断する | §3.2 分岐と例外フロー |
| 発散検知 | 同一NG理由が2回連続で再発したとき、上限回数消化前でも即中断する | §3.2 分岐と例外フロー |
| 版不一致 | facts.lockのNORMALIZE_VERSIONが現行と異なるとき、改ざんとは区別して再確定を促す | §4.2 状態と遷移の制約 |
| 非対応プロファイル | profileがscreen/python以外のとき、Phase 2以降を実行せずPhase 1で中断する | §3.2 分岐と例外フロー |
| 検知漏れの回避禁止 | recount-facts.shが構造的に検知できないパターンをreasonへ逃がすことは禁止され、パターン側を拡張する | §8.1 業務エラー一覧 |

## §3 入力条件

**この節の位置づけ: 仕様**

| ケースのキー | 入力の項目 | 値 |

## §4 期待結果

**この節の位置づけ: 仕様**

| ケースのキー | 期待する結果 | 確認の方法 |
|---|---|---|
| 正常抽出完了 | status=封印済みで返却され、facts.yml/facts.lock/recount-report.txtが揃う | 返却ブロックのstatusとartifactsを確認する |
| 再計数差し戻し | Phase 2へ戻り、再抽出後に再計数する | recount-facts.shの再実行結果とPhase遷移ログを確認する |
| 発散検知 | 上限回数消化前でもstatus=中断になる | 返却ブロックのhintに試行回数と違反内容が記録されることを確認する |
| 版不一致 | exit 3で報告され、改ざん検知（exit 1）とは異なるメッセージになる | seal-facts.sh verifyの終了コードを確認する |
| 非対応プロファイル | Phase 2以降を実行せずPhase 1でstatus=中断になる | 返却ブロックのhintを確認する |
| 検知漏れの回避禁止 | itemsをreasonへ逃がさず、profile-screen.mdのパターンとrecount-facts.shの対応関数が拡張される | 差分のコミット内容を確認する |

## §5 異常系

**この節の位置づけ: 仕様**

| 観点のキー | 発生させる条件 | 期待する振る舞い | 由来する機能設計書の章 |
|---|---|---|---|
| 再計数差し戻し | facts.ymlの記載件数を原本の実件数から意図的に5%超乖離させる | Phase 2へ差し戻し、上限3回で収束しなければ中断する | §3.2 分岐と例外フロー |
| 発散検知 | 同一の検査・同一の違反を2回連続で再現させる | 上限回数消化前でも即中断する | §3.2 分岐と例外フロー |
| 非対応プロファイル | profileにscreen/python以外を指定する | Phase 2以降を実行せずPhase 1で中断する | §3.2 分岐と例外フロー |

## §6 境界値

**この節の位置づけ: 仕様**

| 観点のキー | 対象の項目 | 境界の値 | 境界の直前と直後の扱い |
|---|---|---|---|
| 再計数差し戻し | 記載件数と実件数の乖離率 | 5% | 5%以下は合格、5%を超えると差し戻し |
| 再計数差し戻し | 反復回数 | 3回 | 3回以内で収束すれば継続、収束しなければ中断 |

## §7 網羅基準

**この節の位置づけ: 仕様**

| 観点 | 基準 |
|---|---|
| 条件の網羅 | screen/pythonの両プロファイル、再計数合格／不合格、版不一致の有無をそれぞれ1件以上のケースで確認します |
| 分岐の網羅 | 再計数差し戻し・発散検知・非対応プロファイルの3分岐を1件以上のケースで確認します |
| 境界の網羅 | 乖離率5%・反復回数3回の境界を確認します |
