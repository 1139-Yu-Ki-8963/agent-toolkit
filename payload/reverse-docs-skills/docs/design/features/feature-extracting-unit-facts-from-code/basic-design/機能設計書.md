## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | extracting-unit-facts-from-code |
| 機能ID | feat-extracting-unit-facts-from-code |
| 大分類 | 調査 |
| 業務対象 | 対象ユニットの原本コードから宣言的契約 facts を抽出し、独立再計数・確定・再現性検証まで一貫して行うこと |
| 確からしさ | high |
| 判定根拠 | 機能一覧マニフェストの sourceFile と `.claude/skills/extracting-unit-facts-from-code/SKILL.md` の記述が一致する |
| 境界の決定元 | build-target（Claude Code スキルのディレクトリ単位） |

### 1.2 業務上の位置づけ

後続の詳細設計執筆スキルが、対象リポジトリの原本コードを直接読まずに済む品質の `facts.yml` を用意します。原本の `file:line` 根拠を持つ宣言的契約として抽出し、独立した再計数・改ざん検知・再現性検証を通過させることで、執筆工程の入力品質を保証します。

### 1.3 利用者と権限

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|
| リバース設計フローの進行担当（AI エージェント） | 画面ユニットまたは Python コードユニットから facts.yml を抽出し、確定・再現性検証まで完走させる | .claude/skills/extracting-unit-facts-from-code/SKILL.md |

## §2 機能の範囲

**この節の位置づけ: 仕様**

### 2.1 構成要素一覧

| 構成要素キー | 種別 | 識別子 | 個別設計書 |
|---|---|---|---|
| seal-facts | バッチ（確定・検証・正規化） | generation-engine/scripts/seal-facts.sh | docs/design/batches/batch-root/detail-design/バッチ詳細設計書.md |

本機能自身が持つ `recount-facts.sh`・`extract-python-facts.py`・`recount-python-facts.py` は本機能専用の内部スクリプトです。置き場は `.claude/skills/extracting-unit-facts-from-code/scripts/` です。他の機能から共用されないため独立した構成要素としては扱いません。§7.1 で呼び出しを記録します。

### 2.2 参照テーブル一覧

| テーブル | 作成 | 参照 | 更新 | 削除 | 参照先 |
|---|---|---|---|---|---|
| 該当なし | — | — | — | — | 本機能はデータベーステーブルを持ちません。入出力は facts.yml・facts.lock・recount-report.txt のファイル群です |

### 2.3 範囲外

詳細設計書の執筆（generating-reverse-detailed-design）と共通文書の書き起こし（generating-reverse-common-docs）は本機能の範囲外です。API・テーブル・バッチ・帳票・外部連携の専用プロファイルは未対応であり、指定された場合は status=中断 を返します。

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | 進行担当 | 本機能（Phase 1） | target_repo_path・verification_dir・survey_doc_path の実在、target_file_paths 全件の実在、profile の妥当性を確認する | 確認済みなら Phase 2 へ |
| 2 | 進行担当 | 本機能（Phase 2） | profile=screen なら12分類、profile=python なら6分類の facts.yml を file:line 根拠付きで抽出する | Phase 3 へ |
| 3 | 進行担当 | recount-facts.sh | facts.yml の profile を読み、原本から独立に再計数して記載件数と突合する | exit 0 なら Phase 4、exit 1 なら Phase 2 へ差し戻し（上限3回） |
| 4 | 進行担当 | seal-facts.sh | facts.lock を生成し（seal）、直後に整合性を確認する（verify） | verify が exit 0 なら Phase 5 へ |
| 5 | 進行担当 | 本機能（Phase 5） | 同じ args で独立した2回目の抽出を行い、normalize 後の facts.yml を diff で比較する | diff が空なら Phase 6 へ、差分があれば診断分類する |
| 6 | 進行担当 | 本機能（Phase 6） | 返却ブロック（status・artifacts・facts_ref・pending_measurements）を出力する | status 確定で完了 |

### 3.2 分岐と例外フロー

| キー | 分岐条件 | 到達先 | 参照先 |
|---|---|---|---|
| 再計数不合格 | recount-facts.sh が exit 1 | Phase 2 へ差し戻し。上限3回、同一NG理由が2回連続で再発したら発散として即中断 | .claude/skills/extracting-unit-facts-from-code/SKILL.md ループ設計 |
| 版不一致 | facts.lock の NORMALIZE_VERSION が現行と異なる | 改ざんではなく規則変更として exit 3 で報告し、再確定を促す | .claude/skills/extracting-unit-facts-from-code/SKILL.md 予想を裏切る挙動 |
| diff差分の診断 | Phase 5 の diff に差分がある | 順序差異／キー命名揺れ／共通文書由来の解釈分岐のいずれかへ分類し、分類できなければ status=中断 | .claude/skills/extracting-unit-facts-from-code/SKILL.md Phase 5 |
| 非対応プロファイル | profile が screen/python 以外 | Phase 2 以降を実行せず Phase 1 で status=中断 | .claude/skills/extracting-unit-facts-from-code/SKILL.md 予想を裏切る挙動 |

### 3.3 前後の機能との関係

| 関係 | 相手の機能キー | 受け渡す情報 | 参照先 |
|---|---|---|---|
| 後続 | generating-reverse-detailed-design（本リポジトリの18本には含まれない） | facts.yml・facts.lock・facts_ref（sha256） | .claude/skills/generating-reverse-detailed-design/references/phase-details.md |
| 差し戻し元 | generating-reverse-common-docs（本リポジトリの18本には含まれない） | status=共通文書帰着 の hint（不足している共通文書の観点） | .claude/skills/extracting-unit-facts-from-code/SKILL.md Phase 5 |
