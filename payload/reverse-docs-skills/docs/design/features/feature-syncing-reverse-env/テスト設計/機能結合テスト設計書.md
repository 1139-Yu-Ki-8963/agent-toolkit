## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | 機能設計書 | 機能単体テスト設計書 |
| 内部結合 | 1つの機能の中で関数・メソッドが結合した状態（外部の振る舞い） | 機能設計書 | 機能結合テスト設計書（本書） |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## §1 テスト観点

**この節の位置づけ: 仕様**

観点は機能設計書の業務フロー・業務ルール・エラーと業務メッセージの各章から起こす。

| キー | 観点 | 由来する機能設計書の章 |
|---|---|---|
| 正常PASS確立 | 実差分0・env_check全通過・全scenario render-ready到達のとき、PASSが確定し基準タグが更新される | §3.1 正常系フロー |
| 共有前提不成立degrade | 4条件のいずれかが外れるとき、per-scope方式へ自動degradeする | §3.2 分岐と例外フロー、§4.1 業務判断ポイント |
| dry-run無変更 | dry-run指定時、git管理内容・基準タグに触れない | §3.2 分岐と例外フロー |
| FAIL差し戻し | Phase6でFAILのとき、Phase3へ戻り上限max_loopまで再試行する | §3.2 分岐と例外フロー、§9.1 件数と量の制限 |
| DESIGN-INCOMPLETE差し戻し | 両環境が同様にrender-ready未到達のとき、scenarios追加のhintを付けて差し戻す | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |
| teardown未確認拒否 | 明示依頼が確認できないとき、削除を実行せずERRORで差し戻す | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |

## §3 入力条件

**この節の位置づけ: 仕様**

| ケースのキー | 入力の項目 | 値 |
|---|---|---|
| 正常PASS確立 | design-doc・mode | mode=sync、両環境が完全一致 |
| 共有前提不成立degrade | 起動プロファイル | 画面ごとに異なるlaunchコマンド |
| dry-run無変更 | dry-run | true |
| FAIL差し戻し | 静的比較の結果 | 実差分1件以上 |
| DESIGN-INCOMPLETE差し戻し | scenariosのready | 未設定 |
| teardown未確認拒否 | user-approved | 未指定 |

## §4 期待結果

**この節の位置づけ: 仕様**

| ケースのキー | 期待する結果 | 確認の方法 |
|---|---|---|
| 正常PASS確立 | status=PASSで基準タグが新しいコミットを指す | git tagの参照先を確認する |
| 共有前提不成立degrade | worktree名がoriginal-code-<scope>形式になる | worktree一覧を確認する |
| dry-run無変更 | 基準タグ・git管理内容が変更されない | git statusとタグの参照先を確認する |
| FAIL差し戻し | Phase3へ戻り2回目で収束するか上限max_loopで確定する | 実行記録の反復回数を確認する |
| DESIGN-INCOMPLETE差し戻し | hintにquery/path_params/readyの追加案内が含まれる | 返却のhintを確認する |
| teardown未確認拒否 | status=ERRORで何も削除されない | worktreeが残存していることを確認する |
