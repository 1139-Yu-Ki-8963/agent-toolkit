## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | generating-screen-list-for-reverse-docs |
| 機能ID | feat-generating-screen-list-for-reverse-docs |
| 大分類 | 生成 |
| 業務対象 | 既存コードをスタック調査→検出戦略の宣言→戦略に基づく抽出→整合検証の順で調査し、画面単位にファイルをグルーピングして画面一覧.htmlを作ります。 |
| 確からしさ | high |
| 判定根拠 | 機能一覧マニフェスト（docs/manifests/feature-manifest.json）の sourceFile と .claude/skills/generating-screen-list-for-reverse-docs/SKILL.md の記述が一致する |
| 境界の決定元 | build-target（Claude Code スキルのディレクトリ単位） |

### 1.2 業務上の位置づけ

既存コードをスタック調査→検出戦略の宣言→戦略に基づく抽出→整合検証の順で調査し、画面単位にファイルをグルーピングして画面一覧.htmlを作ります。設計書の雛形展開・生成・記入は行いません。

### 1.3 利用者と権限

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|
| リバース設計フローの進行担当（AI エージェント） | 本機能を起動し、画面一覧.html・screen-manifest.json（unit_kind=screen固定） を得る | .claude/skills/generating-screen-list-for-reverse-docs/SKILL.md |

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | 進行担当 | 本機能（スタック・画面規約の特定） | 対象プロジェクト固有の画面規約を確認する | 次のPhaseへ進む |
| 2 | 進行担当 | 本機能（戦略に基づく抽出） | 抽出基準を明文化し画面境界を検出する | 次のPhaseへ進む |
| 3 | 進行担当 | 本機能（分類の実行と検証） | 分類結果を検証しraw定義とraw由来extを確定する | 次のPhaseへ進む |
| 4 | 進行担当 | 本機能（整合検証） | validate-manifest.shで整合を検証する | 次のPhaseへ進む |
| 5 | 進行担当 | 本機能（画面一覧.html生成） | build-screen-list.shでHTMLを生成する | 次のPhaseへ進む |
| 6 | 進行担当 | 本機能（任意の複雑度プロファイリング） | 必要に応じて複雑度を計測する | 完了 |

| 抽出0件 | 戦略に基づく抽出で画面が1件も見つからない | 0件時の分岐へ進む | .claude/skills/generating-screen-list-for-reverse-docs/SKILL.md |
