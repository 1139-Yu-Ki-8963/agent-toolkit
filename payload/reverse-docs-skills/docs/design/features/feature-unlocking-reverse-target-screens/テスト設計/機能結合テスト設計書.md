## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | 機能設計書 | 機能単体テスト設計書 |
| 内部結合 | 1つの機能の中で関数・メソッドが結合した状態（外部の振る舞い） | 機能設計書 | 機能結合テスト設計書（本書） |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## §1 テスト観点

**この節の位置づけ: 仕様**

観点は機能設計書の業務フロー・業務ルール・エラーと業務メッセージの各章から起こす。

| キー | 観点 | 由来する機能設計書の章 |
|---|---|---|
| standalone正常完走 | invocation_mode=standaloneのとき、前提ゲート〜Phase5が完走しstatus=BASELINE-ESTABLISHEDになる | §3.1 正常系フロー |
| dynamic-only正常完走 | invocation_mode=dynamic-onlyのとき、レジストリ登録とscenarios完全性ゲート通過でstatus=UNLOCKEDになる | §3.1 正常系フロー |
| manifest未整備停止 | manifest必須キーが未確定のとき、status=ERRORで停止する | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |
| 埋め込みビュー読み替え | 対象画面がルートを持たないとき、親経由URL＋操作手順で全手順が読み替えられる | §3.2 分岐と例外フロー |
| 開通競合検知 | 作業コピーが他プロセス使用中のとき、CONFLICT-SKIPPEDで即座に終了する | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |
| 検証ループ発散停止 | 同一差分が2連続で再発し3回目でも解消しないとき、status=BLOCKEDになる | §3.2 分岐と例外フロー、§9.1 件数と量の制限 |

## §4 期待結果

**この節の位置づけ: 仕様**

| ケースのキー | 期待する結果 | 確認の方法 |
|---|---|---|
| standalone正常完走 | status=BASELINE-ESTABLISHEDでbaseline_tagが返る | git tag -lの参照先を確認する |
| dynamic-only正常完走 | status=UNLOCKEDでレジストリがstatus=unlockedになる | 画面レジストリの記帳内容を確認する |
| manifest未整備停止 | status=ERRORでhintに不足キー一覧が記される | 返却のhintを確認する |
| 埋め込みビュー読み替え | 検証URLが親URL＋操作手順の組で表現される | 生成された検証記録の形式を確認する |
| 開通競合検知 | status=CONFLICT-SKIPPEDで他プロセスの環境に触れない | 実行記録に環境操作が無いことを確認する |
| 検証ループ発散停止 | status=BLOCKEDでhintに未解消差分・試行履歴・推定原因Phaseが記される | 返却のhintを確認する |
