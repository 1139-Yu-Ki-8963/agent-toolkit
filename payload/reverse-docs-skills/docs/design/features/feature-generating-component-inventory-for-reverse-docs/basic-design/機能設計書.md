## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | generating-component-inventory-for-reverse-docs |
| 機能ID | feat-generating-component-inventory-for-reverse-docs |
| 大分類 | 生成 |
| 業務対象 | 対象プロジェクトの画面部品ファイル（.tsx/.jsx/.vue）を調べ、コンポーネント棚卸し.htmlを作ること |
| 確からしさ | high |
| 判定根拠 | 機能一覧マニフェストの sourceFile と `.claude/skills/generating-component-inventory-for-reverse-docs/SKILL.md` の記述が一致する |
| 境界の決定元 | build-target（Claude Code スキルのディレクトリ単位） |

### 1.2 業務上の位置づけ

対象リポジトリ配下の画面部品ファイルを単一の事実源とし、export名・props有無・ディレクトリ由来の分類・被参照件数を決定的に抽出して棚卸しページを組み立てます。責務推定・意味的グルーピングといった自動分類は一切行わず、分類はディレクトリパスから機械的に導出するだけです。

### 1.3 利用者と権限

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|
| リバース設計フローの進行担当（AI エージェント） | 対象リポジトリの画面部品ファイルからコンポーネント棚卸し.htmlを作る | .claude/skills/generating-component-inventory-for-reverse-docs/SKILL.md |

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | 進行担当 | 本機能（Phase 1） | .tsx/.jsx/.vueファイルが1件以上存在するかfindで確認する | 存在すればPhase 2へ、不在なら停止する |
| 2 | 進行担当 | extract-component-inventory.sh | export名・props有無・分類・被参照件数を抽出しpage-data.jsonを作る | Phase 3 へ |
| 3 | 進行担当 | validate-page-data.sh | page-data.jsonの整合を検証する | 全項目PASSでPhase 4へ |
| 4 | 進行担当 | build-detail-page.sh／build-portal.sh | コンポーネント棚卸し.htmlを生成し、portal_output_dir指定時はポータルを再生成する | 完了 |

### 3.2 分岐と例外フロー

| キー | 分岐条件 | 到達先 | 参照先 |
|---|---|---|---|
| コンポーネントファイル不在 | .tsx/.jsx/.vueが1件も存在しない | status=STOPPEDでハード停止し、不在を報告する | .claude/skills/generating-component-inventory-for-reverse-docs/SKILL.md Phase 1 |
| 整合検証不合格 | validate-page-data.shがFAILを返す | 指摘に応じて修正し再実行。3回失敗でPhase 2へ差し戻し | .claude/skills/generating-component-inventory-for-reverse-docs/SKILL.md Phase 3 |
| portal_output_dir未指定 | ポータル再生成先が指定されない | 再生成を省略し完了報告に注記する | .claude/skills/generating-component-inventory-for-reverse-docs/SKILL.md Phase 4 |

### 3.3 前後の機能との関係

| 関係 | 相手の機能キー | 受け渡す情報 | 参照先 |
|---|---|---|---|
| 該当なし | — | 本機能は他の17機能と直接の入出力関係をSKILL.md本文に明記していません | — |
