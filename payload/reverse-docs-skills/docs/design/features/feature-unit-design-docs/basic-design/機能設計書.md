本書は集約設計書です。構成要素（画面・API・実行ファイル等）の個別仕様は各構成要素の設計書を正とし、本書は値を再掲せずパスで参照します。本書が正を持つのは、構成要素をまたいで初めて意味を持つ事項（業務フロー・業務ルール・状態のライフサイクル）だけです。

コードから確定できない事項は推測で埋めない。空欄のままとする。

本機能は対象アプリケーションの業務機能ではありません。reverse-docs-skills自身が持つ「設計単位ごとの基本設計書・詳細設計書・テスト設計書を書き起こす」という能力を、集約設計書のテンプレート形式を借りて自己記述したものです。構成要素は画面・API・テーブルではなく、その執筆を担う13件のスキル定義（`.claude/skills/<スキル名>/SKILL.md`）です。

### 1.2 業務上の位置づけ

主体はこのツール自身です。リバース設計フローの中で、事実抽出と確定（fact-extraction機能）が確定した事実の記録（facts.yml）を入力として受け取ります。加えて、一覧の製造（unit-lists機能）が生成した各設計単位のマニフェスト（`docs/manifests/`配下の各`<kind>-manifest.json`）も入力として受け取ります。これらを入力に、各設計単位の基本設計書・詳細設計書・単体テスト設計書・結合テスト設計書を出力します。詳細設計相のうち接続窓口・バッチ・帳票・外部連携・テーブルの5スキルは、facts.ymlに加えて対象リポジトリの原本コードも情報源とします。

入力→出力: 確定した事実の記録（facts.yml）・各設計単位のマニフェスト・プロジェクト共通文書 → 各設計単位の基本設計書・詳細設計書・単体テスト設計書・結合テスト設計書。

本機能を構成する13スキルは、基本・詳細・テストの3相からなる生成スキル群です。6種別（画面・接続窓口・バッチ・帳票・外部連携・テーブル）は、基本設計相と詳細設計相の2つの執筆スキルを持ちます。機能（複数の構成要素を束ねる集約設計書）は、これらの出力を束ねる1つの執筆スキルが担います。ただし機能の集約設計書は詳細設計相を持たず、基本設計相とテスト設計相の2相だけを持ちます（§2.1参照）。テーブルは基本設計相の代わりに論理データモデル、詳細設計相の代わりにテーブル定義書という名前を使いますが、位置づけは基本・詳細と同じです。

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|

### 2.2 参照テーブル一覧

| テーブル | 作成 | 参照 | 更新 | 削除 | 参照先 |
|---|---|---|---|---|---|

該当なし。本機能はデータベースのテーブルを直接作成・参照・更新・削除しません。テーブルに関する設計書（テーブル定義書・論理データモデル）を成果物として生成する機能であり、成果物の対象がテーブルであって、本機能自身がテーブルを使う構成要素を持つわけではありません。

### 2.3 範囲外

- 各設計単位の一覧（画面一覧・API一覧等）の生成は本機能の範囲外です（→ unit-lists機能が担当）。
- 対象コードからの事実抽出そのものは本機能の範囲外です（→ fact-extraction機能が担当）。事実抽出は既に確定・封印済みである前提で、本機能はその結果（facts.yml）を読むだけです。
- 共通設計書・要件定義書の生成は本機能の範囲外です（→ common-docs機能が担当）。
- 状態遷移図・ER図・デザイン系ページの生成は本機能の範囲外です（→ cross-views-and-design-assets機能が担当）。
- プロジェクト全体のテスト仕様書への集約は本機能の範囲外です（→ test-aggregation機能が担当）。各構成要素スキルが著述するのは設計単位1件ごとの単体/結合テスト設計書までです。
- 生成した設計書を一覧化するポータルHTMLの生成は本機能の範囲外です（→ portal機能が担当）。
- 生成した設計書と原本コードの往復検証は本機能の範囲外です（→ roundtrip-verification機能が担当。機能の集約設計書自体は対応する原本ファイルを持たないため往復検証の対象外です）。

| 出力先識別子・不確定 | 機能のunitId・unitKeyの両方が空 | 当該機能を生成せず生成を中断し、ヒントに「出力先の識別子が確定しない」と当該機能の名称推定を記録する | generating-feature-design-for-reverse-docsの出力に関する節 |
| 機械検査上限超過 | 検査フェーズの機械検査が3回差し戻しても合格しない | 生成を中断する | 各構成要素スキルの検査フェーズ |
| 章の完備検査不合格 | 生成した設計書に必須章のいずれかが欠落、またはchapter_mapが不在 | 当該執筆フェーズへ差し戻して書き直す | 機能設計書の章の完備検査 |

|---|---|---|---|
