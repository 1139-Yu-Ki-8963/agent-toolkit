## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | 機能設計書 | 機能単体テスト設計書 |
| 内部結合 | 1つの機能の中で関数・メソッドが結合した状態（外部の振る舞い） | 機能設計書 | 機能結合テスト設計書（本書） |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## テスト対象

| 対象 | 確認する内容 | 根拠となる機能設計書の章 |
|---|---|---|
| 確認〜抽出〜導出〜生成の一連の流れ | Phase 1〜4が意図した順序で完走し、生成可能な全ページが固定パスへ出力されること | §3 業務フロー |
| 任意データ源不在時の続行 | テーブル一覧・機能一覧が不在でも他の交差データが生成できること | §3.2 分岐と例外フロー |
| 必須データ不在時の停止 | 画面一覧・API一覧が不在のときstatus=STOPPEDで停止すること | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |

## §1 テスト観点

**この節の位置づけ: 仕様**

観点は機能設計書の業務フロー・業務ルール・エラーと業務メッセージの各章から起こします。

| キー | 観点 | 由来する機能設計書の章 |
|---|---|---|
| 正常生成完了 | Phase 1〜4が完走し、生成可能な全ページが固定パスへ出力される | §3.1 正常系フロー |
| 必須データ不在の停止 | 画面一覧・API一覧が不在のときSTOPPEDで停止する | §3.2 分岐と例外フロー |
| 任意データ源不在時の続行 | テーブル一覧・機能一覧不在でも続行する | §3.2 分岐と例外フロー |
| データ形状不揃いのスキップ | permission-functionのデータ形状が揃わないとき未生成として理由を記録する | §3.2 分岐と例外フロー |
| permission-function形状変換 | roles→{key,name}等の決定的な変換を行う | §4.3 計算規則 |

## §4 期待結果

**この節の位置づけ: 仕様**

| ケースのキー | 期待する結果 | 確認の方法 |
|---|---|---|
| 正常生成完了 | status=DONEで返却され、generated_pagesに5種のpage-typeが記録される | 返却ブロックのstatusとgenerated_pagesを確認する |
| 必須データ不在の停止 | status=STOPPEDで返却され、hintに先行実行の案内が記録される | 返却ブロックのhintを確認する |
| 任意データ源不在時の続行 | permission-screen・crud・追跡可能性・ai-assetsが生成される | 返却ブロックのgenerated_pagesを確認する |
| データ形状不揃いのスキップ | skipped_pagesにpermission-functionと理由が記録される | 返却ブロックのskipped_pagesを確認する |
| permission-function形状変換 | permission-function-matrix.jsonのrolesが{key,name}形式になる | 変換後のJSONを確認する |
