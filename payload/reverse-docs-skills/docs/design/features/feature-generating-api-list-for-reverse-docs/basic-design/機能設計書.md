## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | generating-api-list-for-reverse-docs |
| 機能ID | feat-generating-api-list-for-reverse-docs |
| 大分類 | 生成 |
| 業務対象 | 既存コードを調べ、接続窓口（API）ごとの一覧ページ（API一覧.html）を作ること |
| 確からしさ | high |
| 判定根拠 | 機能一覧マニフェストの sourceFile と `.claude/skills/generating-api-list-for-reverse-docs/SKILL.md` の記述が一致する |
| 境界の決定元 | build-target（Claude Code スキルのディレクトリ単位） |

### 1.2 業務上の位置づけ

対象コードベースをスタック調査→検出戦略の宣言→戦略に基づく抽出→整合検証の順で調べ、APIエンドポイント単位にファイルをグルーピングしてAPI一覧.htmlを作ります。マニフェストスキーマ・整合検証・HTML生成は決定的スクリプトに固定し、抽出（エンドポイント境界の検出）だけをプロジェクトごとに可変な手作業とすることで、抽出の柔軟性と検証の確実性を両立します。

### 1.3 利用者と権限

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|
| リバース設計フローの進行担当（AI エージェント） | 既存コードベースからAPI一覧.htmlと永続マニフェストを作る | .claude/skills/generating-api-list-for-reverse-docs/SKILL.md |

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | 進行担当 | 本機能（Phase 1） | 対象形態（HTTP系/非HTTP系）・呼び出し境界の所在・API規約・除外パターンを調査し、検出戦略宣言をAskUserQuestionで承認を得る | 承認後 Phase 2 へ |
| 2 | 進行担当 | 本機能（Phase 2）／extract-api-metadata.sh | 戦略に基づきカスタム抽出を実行し、マニフェストJSONを作成後、メタデータ（method・authRequired・ioSummary）を付与する | Phase 3 へ |
| 3 | 進行担当 | validate-manifest.sh | 拡張マニフェストの整合を検証する | 全項目PASSでPhase 4へ |
| 4 | 進行担当 | build-unit-list.sh | API一覧.htmlを生成する | 完了 |

### 3.2 分岐と例外フロー

| キー | 分岐条件 | 到達先 | 参照先 |
|---|---|---|---|
| API実在しない | 検出0件、かつ調査書がAPI不在と判定 | status=NONE。API一覧（該当なし）.mdを生成し正常終了する | .claude/skills/generating-api-list-for-reverse-docs/SKILL.md 0件時の分岐 |
| 検出失敗 | 検出0件、かつ調査書がAPI実在と判定 | 停止する。headlessならprogress.jsonlへ記録しstatus=ERROR | .claude/skills/generating-api-list-for-reverse-docs/SKILL.md 0件時の分岐 |
| 整合検証不合格 | validate-manifest.shがFAILを返す | 指摘に応じて修正し再実行。3回失敗でPhase 2 Step 2へ差し戻し | .claude/skills/generating-api-list-for-reverse-docs/SKILL.md Phase 3 |

### 3.3 前後の機能との関係

| 関係 | 相手の機能キー | 受け渡す情報 | 参照先 |
|---|---|---|---|
