## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | cross-views-and-design-assets |
| 機能ID | feat-cross-views-and-design-assets |
| 大分類 | リバース |
| 業務対象 | 対象リポジトリのソースコードそのものではなく、既に生成済みの画面・API・テーブルの一覧マニフェストと共通設計文書（DESIGN.md 等） |
| 確からしさ | high |
| 判定根拠 | 構成要素8件のSKILL.mdがいずれも「Phase 1 前提確認」で既存マニフェスト・既存設計文書の実在を検査してから処理を始める構成になっており、原本コードの直接解析を行わない一貫した境界を持つため |
| 境界の決定元 | build-target（横断ビュー・図・デザイン系ページという生成物の種別で束ねる） |

### 1.2 業務上の位置づけ

主体: このツール自身（reverse-docs-skillsのリバース設計フロー）です。対象リポジトリの利用者や業務担当者が主体ではありません。

入力→出力: 画面・API・テーブルの一覧、共通設計文書 → 対応表・図（ER図/状態遷移図/画面遷移図/シーケンス図）・デザイン系ページ（デザインシステム/部品棚卸し/アイコンカタログ）。

この機能は、単体の画面・API・テーブルの設計書がそれぞれ確定した後に使う機能です。対象読者は、対象範囲全体の整合性を確かめたい設計者・レビュー担当と、UIの実装規約を確認したい実装担当の両方です。個別設計書だけでは見えない関係性・全体像を、両者へ向けて提示します。

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | このツール | cross-views | 拡張済み画面・APIマニフェストと構成データから権限×画面・権限×機能・CRUD図・画面-API-テーブル対応表・AI設定資産一覧の5ページを生成する | 常に実行可能（画面・API双方の一覧マニフェストが未生成の場合は空データで生成する） |
| 2 | このツール | er-diagram | テーブル一覧マニフェストのエンティティとORM/マイグレーションコードから抽出した外部キー関係からER図を生成する | テーブル一覧マニフェストが実在する場合のみ実行する |
| 3 | このツール | entity-state | 各データ設計書の§6状態遷移表を集約して状態遷移図を生成する | 状態遷移表を持つデータ設計書が1件以上ある場合のみ実行する |
| 4 | このツール | screen-transition | 画面一覧マニフェスト（raw/ext双方）とルーティング定義から画面遷移図を生成する | 画面一覧マニフェストが実在する場合のみ実行する |
| 5 | このツール | sequence-diagram | 設計単位（画面・API・機能）ごとにシーケンス図を個別生成する | 対象の詳細設計書が存在する場合のみ実行する |
| 6 | このツール | design-system | 対象リポジトリのDESIGN.mdのfrontmatter（色・タイポグラフィ・余白・角丸・コンポーネント）からデザインシステムページを生成する | DESIGN.mdが実在する場合のみ実行する |
| 7 | このツール | component-inventory | 対象リポジトリの.tsx/.jsx/.vueファイルを走査し部品棚卸しページを生成する | 対象拡張子のファイルが1件以上ある場合のみ実行する |
| 8 | このツール | icon-catalog | 対象リポジトリのアイコン使用パターン（Material Icons/SVG import/Reactアイコンコンポーネント）を走査しアイコンカタログページを生成する | いずれかのパターンが1件以上検出された場合のみ実行する |

8件の構成要素は互いに強い実行順序を持たず、各構成要素が要求する入力（一覧マニフェスト・共通設計文書）が揃った時点でそれぞれ独立に実行できる。
