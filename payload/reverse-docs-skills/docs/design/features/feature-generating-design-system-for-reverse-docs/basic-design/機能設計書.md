本書は集約設計書です。構成要素の個別仕様は各構成要素の設計書を正とし、本書は値を再掲せずパスで参照します。

## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | generating-design-system-for-reverse-docs |
| 機能ID | feat-generating-design-system-for-reverse-docs |
| 大分類 | 生成 |
| 業務対象 | 共通の設計文書（DESIGN.md）から色・余白等の値を取り出し、見た目の決まりをまとめたページを作ること |
| 確からしさ | high |
| 判定根拠 | 機能一覧マニフェストの sourceFile と `.claude/skills/generating-design-system-for-reverse-docs/SKILL.md` の記述が一致する |
| 境界の決定元 | build-target（Claude Code スキルのディレクトリ単位） |

### 1.2 業務上の位置づけ

DESIGN.mdを単一の事実源とする。frontmatterのcolors/typography/spacing/rounded/componentsを抽出してデザインシステム.htmlを組み立てます。トークン値の妥当性（配色の良否・命名の是非）は判定せず、記載された事実の転記に徹します。

### 1.3 利用者と権限

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|
| リバース設計フローの進行担当（AI エージェント） | DESIGN.mdが確定済みの状態で、デザインシステム.htmlを作る | .claude/skills/generating-design-system-for-reverse-docs/SKILL.md |

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | 進行担当 | 本機能（Phase 1） | output_dir/commonRoot/DESIGN.mdの実在を確認する | 実在すればPhase 2へ、不在なら停止する |
| 2 | 進行担当 | extract-design-tokens-from-designmd.sh | frontmatterからトークンを抽出し、無ければCSS変数へフォールバックする | Phase 3 へ |
| 3 | 進行担当 | validate-page-data.sh | page-dataの整合を検証する | 全項目PASSでPhase 4へ |
| 4 | 進行担当 | build-detail-page.sh／build-portal.sh | デザインシステム.htmlを生成し、portal_output_dir指定時はポータルを再生成する | 完了 |

### 3.2 分岐と例外フロー

| キー | 分岐条件 | 到達先 | 参照先 |
|---|---|---|---|
| DESIGN.md不在 | output_dir/commonRoot/DESIGN.mdが実在しない | status=STOPPEDで停止する | .claude/skills/generating-design-system-for-reverse-docs/SKILL.md 完了条件 |
| frontmatter未検出 | frontmatterが存在しない | CSS変数への正規表現フォールバックを行う。componentsは常に[]になる | .claude/skills/generating-design-system-for-reverse-docs/SKILL.md 予想を裏切る挙動 |
| 整合検証不合格 | validate-page-data.shがFAILを返す | 修正して再実行。3回失敗で抽出手順へ差し戻し | .claude/skills/generating-design-system-for-reverse-docs/SKILL.md 完了条件 |

### 3.3 前後の機能との関係

| 関係 | 相手の機能キー | 受け渡す情報 | 参照先 |
|---|---|---|---|
