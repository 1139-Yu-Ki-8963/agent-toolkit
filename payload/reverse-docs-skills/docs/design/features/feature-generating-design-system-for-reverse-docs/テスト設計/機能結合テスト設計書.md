## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | 機能設計書 | 機能単体テスト設計書 |
| 内部結合 | 1つの機能の中で関数・メソッドが結合した状態（外部の振る舞い） | 機能設計書 | 機能結合テスト設計書（本書） |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## テスト対象

| 対象 | 確認する内容 | 根拠となる機能設計書の章 |
|---|---|---|
| 確認〜抽出〜検証〜生成の一連の流れ | Phase 1〜4が意図した順序で完走し、デザインシステム.htmlが生成されること | §3 業務フロー |
| DESIGN.md不在の停止 | DESIGN.mdが実在しないときstatus=STOPPEDで停止すること | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |
| frontmatter未検出時のフォールバック | frontmatter未検出時にCSS変数へフォールバックし、componentsが常に空になること | §3.2 分岐と例外フロー |

## テストの粒度と自動化の方針

| 項目 | 方針 |
|---|---|
| テストの粒度 | 1ケースで確認する振る舞いを記入します。 |
| 自動化 | validate-page-data.shのexit codeによる自動判定が可能です。 |

## §1 テスト観点

**この節の位置づけ: 仕様**

観点は機能設計書の業務フロー・業務ルール・エラーと業務メッセージの各章から起こします。

| キー | 観点 | 由来する機能設計書の章 |
|---|---|---|
| 正常生成完了 | Phase 1〜4が完走し、デザインシステム.htmlが生成される | §3.1 正常系フロー |
| DESIGN.md不在の停止 | DESIGN.mdが不在のときSTOPPEDで停止する | §3.2 分岐と例外フロー |
| frontmatter未検出時のフォールバック | frontmatter未検出時にCSS変数へフォールバックし、componentsが空になる | §3.2 分岐と例外フロー |
| roundedの合流 | roundedがspacingカテゴリへ合流する | §4.3 計算規則 |
| 整合検証差し戻し | validate-page-data.shがFAILのとき修正して再実行し3回で収束しなければ抽出手順へ差し戻す | §3.2 分岐と例外フロー |

## §3 入力条件

**この節の位置づけ: 仕様**

|---|---|---|

## §4 期待結果

**この節の位置づけ: 仕様**

| ケースのキー | 期待する結果 | 確認の方法 |
|---|---|---|
| 正常生成完了 | status=DONEで返却され、デザインシステム.htmlが実在する | 返却ブロックのstatusとartifactsを確認する |
| DESIGN.md不在の停止 | status=STOPPEDで返却され、hintに不在の旨が記録される | 返却ブロックのhintを確認する |
| frontmatter未検出時のフォールバック | page-data.jsonのcomponentsが空配列になる | page-data.jsonを確認する |
| roundedの合流 | 出力JSONのspacingカテゴリにroundedが含まれる | page-data.jsonのspacing配列を確認する |
| 整合検証差し戻し | 3回以内に修正されるか、3回目で抽出手順へ差し戻される | validate-page-data.shの再実行結果を確認する |

## §6 境界値

**この節の位置づけ: 仕様**
