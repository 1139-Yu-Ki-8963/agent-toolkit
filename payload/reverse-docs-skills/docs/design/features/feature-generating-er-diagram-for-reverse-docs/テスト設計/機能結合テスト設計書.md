## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | 機能設計書 | 機能単体テスト設計書 |
| 内部結合 | 1つの機能の中で関数・メソッドが結合した状態（外部の振る舞い） | 機能設計書 | 機能結合テスト設計書（本書） |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## §1 テスト観点

**この節の位置づけ: 仕様**

観点は機能設計書の業務フロー・業務ルール・エラーと業務メッセージの各章から起こします。

| キー | 観点 | 由来する機能設計書の章 |
|---|---|---|
| 正常生成完了 | Phase 1〜4が完走し、ER図.htmlが生成される | §3.1 正常系フロー |
| エンティティ0件の停止 | entities[]が0件のときSTOPPEDで停止する | §3.2 分岐と例外フロー |
| FK0件の俯瞰ページ生成 | FKが0件でもエンティティがあれば俯瞰ページを生成する | §3.2 分岐と例外フロー |
| manifest外参照の分離 | manifestに無い参照先をunresolved[]へ分離する | §3.2 分岐と例外フロー |
| 検査不合格時の差し戻し | 同一FAILの2回連続再発でFK走査へ即差し戻す | §9.1 件数と量の制限 |

## §3 入力条件

**この節の位置づけ: 仕様**

| ケースのキー | 入力の項目 | 値 |
|---|---|---|
| 正常生成完了 | target_repo_path・output_dir | テーブル一覧.htmlが確定済みのプロジェクト |
| エンティティ0件の停止 | テーブル一覧manifest | entities[]が0件 |
| FK0件の俯瞰ページ生成 | 対象リポジトリのマイグレーション/ORM定義 | FKを1件も含まない |
| manifest外参照の分離 | FK定義 | 参照先テーブルがmanifestのunits[]に存在しない |
| 検査不合格時の差し戻し | validate-page-data.shの検査結果 | 同一検査項目が2回連続でFAILする |

## §4 期待結果

**この節の位置づけ: 仕様**

| ケースのキー | 期待する結果 | 確認の方法 |
|---|---|---|
| 正常生成完了 | status=DONEで返却され、ER図.htmlが実在する | 返却ブロックのstatusとartifactsを確認する |
| エンティティ0件の停止 | status=STOPPEDで返却され、hintに0件の旨が記録される | 返却ブロックのhintを確認する |
| FK0件の俯瞰ページ生成 | status=DONEで返却され、relations[]が空でもエンティティ一覧のみの俯瞰ページが生成される | page-data.jsonとER図.htmlを確認する |
| manifest外参照の分離 | 当該参照がrelations[]に現れずunresolved[]に記録される | page-data.jsonを確認する |
| 検査不合格時の差し戻し | Phase 2 Step 2（FK走査）へ即差し戻される | Phase遷移ログを確認する |
