## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | roundtrip-verification |
| 機能ID | feat-roundtrip-verification |
| 大分類 | リバース |
| 業務対象 | 設計書だけから対象コードを再構築し、原本と突き合わせて欠落を見つけます。単一ファイル検証・機能全体の往復検証・環境同期・画面開通・無人一括バッチの5機能を束ねます。 |
| 確からしさ | high |
| 判定根拠 | 機能一覧マニフェスト（docs/manifests/feature-manifest.json）の sourceFile と .claude/skills/rebuilding-code-from-docs/SKILL.md の記述が一致する |
| 境界の決定元 | build-target（Claude Code スキルのディレクトリ単位） |

### 1.2 業務上の位置づけ

リバース設計書の品質を検証する往復検証系の機能です。orchestrating-ai-development-setup の Phase 6・Phase 7（global_step 40〜41）が、本機能の5構成要素を依存順に呼び出します。順序は、unlock（画面開通）→ setup（環境準備）→ file verify（ファイル単位検証）です。続いて baseline sync（基準確立）→ implement（機能全体の実装検証）→ compare（比較結果保持）→ judge（判定と確定）と進みます。対象画面が4件以上なら running-reverse-screen-batch が unlock・file verify・implement・judge を無人バッチとして引き継ぎます。3件以下は orchestrating-ai-development-setup 自身が逐次仲介します。コードを直すことは目的ではなく、差分は「設計書の記載不足」として当該設計書へフィードバックします。

### 1.3 利用者と権限

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|
| orchestrating-ai-development-setup（管理者） | Phase 6・Phase 7 で unlock・setup・file verify・baseline sync・implement・compare・judge を依存順に実行し、画面数に応じて逐次仲介するかバッチへ委譲するかを判断する | `.claude/skills/orchestrating-ai-development-setup/SKILL.md` |
| rebuilding-code-from-docs・rebuilding-screen-unit-from-docs・running-reverse-screen-batch・syncing-reverse-env・unlocking-reverse-target-screens（各構成要素） | それぞれの担当工程（機能全体の往復検証・ファイル単位検証・無人一括バッチ・環境同期・画面開通）を実行する | 各スキルの SKILL.md |

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | orchestrating-ai-development-setup | 本機能（Phase 6判定） | 対象画面が4件以上かを判定する | 4件以上ならrunning-reverse-screen-batchへ委譲、3件以下なら本機能自身が逐次仲介する |
| 2 | unlocking-reverse-target-screens | 本機能（unlock） | 実レンダリング確認済みURLが無ければ dynamic-only で起動し画面を開通する | 開通完了で次へ |

| 4 | rebuilding-screen-unit-from-docs | 本機能（file verify） | env_blockを渡してファイル単位検証を行う | 再現一致確定で次へ |
| 5 | syncing-reverse-env | 本機能（baseline sync） | mode=sync でbaseline_tagを確立する | 確立完了で次へ |
| 6 | rebuilding-code-from-docs | 本機能（implement） | mode=implement のcompare_requestを受領する | compare_request確定で次へ |
| 7 | syncing-reverse-env | 本機能（compare） | mode=sync,dry-run で比較結果全文を保持する | 比較結果全文取得で次へ |
| 8 | rebuilding-code-from-docs・syncing-reverse-env | 本機能（judge） | mode=judge へcompare_result全文とfreeze_commitを渡し判定する。PASS時は承認を求めずsyncing-reverse-env(mode=sync)で基準タグを本番更新する | 完了 |

### 4.1 業務判断ポイント

| キー | 判断内容 | 判断材料 | 参照先 |

### 4.2 状態と遷移の制約

| 状態 | 遷移先 | 遷移条件 | 参照先 |
|---|---|---|---|
| unlocked | baseline-established | standaloneでsyncing-reverse-envがstatus=PASSを返し基準タグ確立を確認する | unlocking-reverse-target-screens 機能設計書 §4.2 |
| authored | unlocked | dynamic-onlyでscenarios完全性ゲートを通過する | unlocking-reverse-target-screens 機能設計書 §4.2 |

### 4.3 計算規則
