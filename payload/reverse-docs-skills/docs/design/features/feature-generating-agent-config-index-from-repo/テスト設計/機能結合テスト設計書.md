## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | 機能設計書 | 機能単体テスト設計書 |
| 内部結合 | 1つの機能の中で関数・メソッドが結合した状態（外部の振る舞い） | 機能設計書 | 機能結合テスト設計書（本書） |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## §1 テスト観点

**この節の位置づけ: 仕様**

観点は機能設計書の業務フロー・業務ルール・エラーと業務メッセージの各章から起こします。

| キー | 観点 | 由来する機能設計書の章 |
|---|---|---|
| 正常生成完了 | Phase 1〜3が完走し、AGENTS.md・CLAUDE.md・検証報告が出力される | §3.1 正常系フロー |
| 根拠不足での中断 | Phase 1で根拠パスが揃わない場合、生成を確定しない | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |
| rules_root未指定時の扱い | rules_rootが未指定のとき、規約索引を不明事項として残す | §3.2 分岐と例外フロー |
| RULES-INDEXマーカー単一 | AGENTS.mdにRULES-INDEXマーカーが1組だけ存在する | §9.1 件数と量の制限 |
| CLAUDE.md非重複 | CLAUDE.mdに規約本文・未確認の規約パス・AI行動規範が含まれない | §2.3 範囲外 |

## §3 入力条件

## §4 期待結果

**この節の位置づけ: 仕様**

| ケースのキー | 期待する結果 | 確認の方法 |
|---|---|---|
| 正常生成完了 | status=生成完了で返却され、AGENTS.md・CLAUDE.md・検証報告が output_dir に存在する | 返却形式のstatusとartifactsを確認する |
| 根拠不足での中断 | status=根拠不足で返却され、生成を確定しない | 返却形式のhintに未確定事項が記録されることを確認する |
| rules_root未指定時の扱い | 規約索引が不明事項として残り、推測記入されない | 生成物の該当箇所を確認する |
| RULES-INDEXマーカー単一 | マーカーが1組だけ存在することが検査で確認される | Phase 3の検査結果を確認する |
| CLAUDE.md非重複 | CLAUDE.mdに規約本文・未確認の規約パス・AI行動規範が無いことが検査で確認される | Phase 3の検査結果を確認する |
