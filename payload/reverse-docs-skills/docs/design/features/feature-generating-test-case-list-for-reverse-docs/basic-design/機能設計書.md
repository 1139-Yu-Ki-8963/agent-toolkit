## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | generating-test-case-list-for-reverse-docs |
| 機能ID | feat-generating-test-case-list-for-reverse-docs |
| 大分類 | 生成 |
| 業務対象 | 各設計単位の2テスト設計書と画面固有の操作シナリオ仕様書を事実源として横断集約し、テストケース一覧.htmlを生成します。 |
| 確からしさ | high |
| 判定根拠 | 機能一覧マニフェスト（docs/manifests/feature-manifest.json）の sourceFile と .claude/skills/generating-test-case-list-for-reverse-docs/SKILL.md の記述が一致する |
| 境界の決定元 | build-target（Claude Code スキルのディレクトリ単位） |

### 1.2 業務上の位置づけ

リバース設計フローの生成担当（AIエージェント）が、各設計単位のテスト設計書が1件以上確定した段階で、ポータルにテストケース一覧カードを追加するために使う転記・集約系の機能です。テストケースの妥当性・網羅性は判定せず、記載された事実の転記に徹します。

### 1.3 利用者と権限

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|
| リバース設計フローの生成担当（AIエージェント） | 各設計単位のテスト設計書と操作シナリオ仕様書を横断集約し、テストケース一覧.htmlを生成する | `.claude/skills/generating-test-case-list-for-reverse-docs/SKILL.md` |

## §2 機能の範囲

**この節の位置づけ: 仕様**

### 2.1 構成要素一覧

| validate-test-case-manifest | バッチ（整合検証スクリプト） | generation-engine/scripts/unit-list/validate-test-case-manifest.sh | `docs/design/batches/batch-unit-list/detail-design/バッチ詳細設計書.md` |

本機能自体は `.claude/skills/generating-test-case-list-for-reverse-docs/SKILL.md` の手順として実行される。対象の Phase は Phase 1〜4 です。Phase 1のテスト設計書実在確認は生成担当が直接行う。

| テーブル | 作成 | 参照 | 更新 | 削除 | 参照先 |

観点の網羅状況の確認は本機能の範囲外であり、generating-test-viewpoint-list-for-reverse-docs が生成するテスト観点表一覧が担います。プロジェクト全体の結合テスト仕様書（複数単位をまたぐ結合テスト）も本機能の集約対象に含めません。

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | 生成担当 | 本機能（Phase 1） | output-layoutの各UnitRootを走査し、設計単位直下のテスト設計/にある2設計書（画面は新配置優先・旧配置fallback）の実在を確認する | 1件以上存在すればPhase 2へ。全種別0件ならハード停止 |
| 2 | 生成担当・aggregate-test-cases | 本機能（Phase 2） | manifest JSONを横断集約し、summaryの件数・種別内訳・画面内訳を確認する | 集約結果を確認できればPhase 3へ（0件でもエラーにしない） |
| 3 | validate-test-case-manifest | 本機能（Phase 3） | manifestの整合検証を行う | 全項目PASSならPhase 4へ。FAILなら修正し3回まで再実行、それでも失敗なら集約元の見直しへ |
| 4 | 生成担当・build-unit-list | 本機能（Phase 4） | build-unit-list.shでテストケース一覧.htmlを生成し、portal_output_dir指定時はbuild-portal.shでポータルへ反映する | HTML生成完了で終了 |

### 3.2 分岐と例外フロー

| キー | 分岐条件 | 到達先 | 参照先 |
|---|---|---|---|
| テスト設計書全種別不在 | 全種別で2テスト設計書が0件 | ハード停止し、status=STOPPEDで返却する | SKILL.md Phase 1、返却ブロック |
| 集約0件 | aggregate-test-casesの結果が0件 | エラーにせず0件である旨を完了報告の注記に残す（fail-safe設計） | SKILL.md Phase 2 Step 2 |
| 検証3回失敗 | validate-test-case-manifest.shが3回連続でFAIL | 集約スクリプトの入力の見直しへ差し戻す | SKILL.md Phase 3 |
| portal_output_dir未指定 | ポータル再生成先が指定されない | build-portal.shの実行を省略し完了報告に注記する | SKILL.md Phase 4 Step 2 |

### 3.3 前後の機能との関係

| 関係 | 相手の機能キー | 受け渡す情報 | 参照先 |
|---|---|---|---|
| 類似機能 | generating-test-viewpoint-list-for-reverse-docs | 同じ派生一覧エンジン（build-unit-list.sh）を使う姉妹機能。集約対象・観点は異なる | `docs/design/features/feature-generating-test-viewpoint-list-for-reverse-docs/basic-design/機能設計書.md` |
