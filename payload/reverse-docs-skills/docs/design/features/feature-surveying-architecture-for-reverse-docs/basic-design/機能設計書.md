# アーキテクチャ調査書の確定 機能設計書

**この文書の位置づけ**（別の言語で作り直す場合は、まず「仕様」から読む）

- 仕様: §1 機能概要、§2 機能の範囲、§3 業務フロー、§4 業務ルール、§5 データ、§6 構成要素間の状態受け渡し。§7 呼び出し仕様、§8 エラーと業務メッセージ、§9 非機能、§10 共通仕様への準拠、§11 関連資料
- 現行実装: 該当なし
- 仕様／現行実装（詳細は各節の太字1行を見る）: 該当なし

本書は集約設計書です。構成要素（画面・API・実行ファイル等）の個別仕様は各構成要素の設計書を正とし、本書は値を再掲せずパスで参照します。本書が正を持つのは、構成要素をまたいで初めて意味を持つ事項（業務フロー・業務ルール・状態のライフサイクル）だけです。

コードから確定できない事項は推測で埋めない。空欄のままとする。

## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | surveying-architecture-for-reverse-docs |
| 機能ID | feat-surveying-architecture-for-reverse-docs |
| 大分類 | 調査 |
| 業務対象 | 既存のリポジトリを決定的コマンドで調べ、機械ゲートによる検証を添えてアーキテクチャ調査書を確定します。 |
| 確からしさ | high |
| 判定根拠 | 機能一覧マニフェスト（docs/manifests/feature-manifest.json）の sourceFile と .claude/skills/surveying-architecture-for-reverse-docs/SKILL.md の記述が一致する |
| 境界の決定元 | build-target（Claude Code スキルのディレクトリ単位） |

### 1.2 業務上の位置づけ

リバース設計フロー全体の最初に実行される調査系の機能です。対象リポジトリの技術スタック・ディレクトリ責務・6種別（画面・API・テーブル・バッチ・帳票・外部連携）の実在有無を、すべて決定的コマンド（find/grep/ls）の実出力を根拠に確定します。対象リポジトリへは読み取り専用で動作し、出力はアーキテクチャ調査書.md1本のみです。

### 1.3 利用者と権限

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|
| orchestrating-ai-development-setup（管理者） | 対象リポジトリを調査しアーキテクチャ調査書を新規作成・改訂する | `.claude/skills/surveying-architecture-for-reverse-docs/SKILL.md` |

## §2 機能の範囲

**この節の位置づけ: 仕様**

### 2.1 構成要素一覧

| 構成要素キー | 種別 | 識別子 | 個別設計書 |
|---|---|---|---|
| check-architecture-survey | バッチ（機械ゲートスクリプト。本機能専有） | .claude/skills/surveying-architecture-for-reverse-docs/scripts/check-architecture-survey.sh | 該当なし（本機能専有） |
| detect-encoding | バッチ（エンコーディング判定スクリプト） | generation-engine/scripts/detect-encoding.sh | `docs/design/batches/batch-root/detail-design/バッチ詳細設計書.md` |

本機能自体は `.claude/skills/surveying-architecture-for-reverse-docs/SKILL.md` の手順として実行される。対象の Phase は Phase 1〜6 です。決定的走査（Phase 2〜3）と調査書執筆（Phase 4）は生成担当がBash/Grep/Read/Writeで直接行う。

### 2.2 参照テーブル一覧

| テーブル | 作成 | 参照 | 更新 | 削除 | 参照先 |
|---|---|---|---|---|---|
| 該当なし | — | — | — | — | 本機能はデータベーステーブルを持たない。入出力はいずれもファイル（アーキテクチャ調査書.mdの書き込み）である |

### 2.3 範囲外

種別別一覧の生成（generating-screen-list-for-reverse-docs等）、共通文書の書き起こしやfacts抽出、詳細設計の執筆は本機能の範囲外です。これらは後続工程が担います。

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | 本機能 | 本機能（Phase 1） | argsを解決し、target_repo_path・template_rootの実在を確認する | 確認済みならPhase 2へ |
| 2 | 本機能・detect-encoding | 本機能（Phase 2） | 決定的走査（技術スタック・ディレクトリ責務・テスト基盤・エンコーディング・プロジェクト形態）を行う | 走査完了でPhase 3へ |
| 3 | 本機能 | 本機能（Phase 3） | 画面・API・テーブル・バッチ・帳票・外部連携の6種別を判定する | 6種別すべて判定済みでPhase 4へ |
| 4 | 本機能 | 本機能（Phase 4） | テンプレの全節を実測値の転記で埋める | プレースホルダ残存0でPhase 5へ |
| 5 | 本機能・check-architecture-survey | 本機能（Phase 5） | 機械ゲート（7検査）を実行する | exit 0でPhase 6へ。FAILならPhase 4へ差し戻し（上限5回） |
| 6 | 本機能 | 本機能（Phase 6） | 返却ブロック（status・survey_doc_path・unit_kinds_present）を出力する | 完了 |

### 3.2 分岐と例外フロー

| キー | 分岐条件 | 到達先 | 参照先 |
|---|---|---|---|
| mode=revise | 既存調査書に検出手がかりの欠落がある | revise_findingsが指摘した節のみ改訂するが、機械ゲートは全項目を再実行する | SKILL.md 予想を裏切る挙動 |
| ゲートFAIL | check-architecture-survey.shがexit 1を返す | Phase 4へ戻り、未実在パス・未判定種別・推測語・テンプレ残存を修正して再実行する（上限5回） | SKILL.md Phase 5 |
| 発散検知 | 同一検査項目の同一違反が2回連続で再発する | 上限回数消化前でも即中断しstatus=中断とする | SKILL.md ループ設計 |
| テスト基盤0件 | 既定コマンド・言語別規約のいずれでも検出結果が0件 | §9へ「実在しない（理由: …）」と記録する | SKILL.md Phase 2 |

### 3.3 前後の機能との関係

| 関係 | 相手の機能キー | 受け渡す情報 | 参照先 |
|---|---|---|---|
| 後段（全般） | orchestrating-ai-development-setup経由の後続工程一式 | survey_doc_path・unit_kinds_present | `docs/design/features/feature-orchestrating-ai-development-setup/basic-design/機能設計書.md` |
| 後段 | generating-tech-stack-for-reverse-docs | アーキテクチャ調査書§2の技術スタック表 | `docs/design/features/feature-generating-tech-stack-for-reverse-docs/basic-design/機能設計書.md` |
