## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | 機能設計書 | 機能単体テスト設計書 |
| 内部結合 | 1つの機能の中で関数・メソッドが結合した状態（外部の振る舞い） | 機能設計書 | 機能結合テスト設計書（本書） |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## テスト対象

| 対象 | 確認する内容 | 根拠となる機能設計書の章 |
|---|---|---|
| 原本読解〜執筆〜機械検査の一連の流れ | Phase 1〜4が完走し、8検査すべてに合格すること | §3 業務フロー |
| コード位置の非記録 | 詳細設計書・実装記録・単体テスト設計書のいずれにも対象コードのファイル名・行番号が残らないこと | §4.4 権限別の可否、§8.1 業務エラー一覧 |

## §1 テスト観点

**この節の位置づけ: 仕様**

観点は機能設計書の業務フロー・業務ルール・エラーと業務メッセージの各章から起こします。

| キー | 観点 | 由来する機能設計書の章 |
|---|---|---|
| 正常執筆完了 | Phase 1〜4が完走し、8検査すべてに合格する | §3.1 正常系フロー |
| 該当プロファイルなし | filesの拡張子がpython/perlどちらにも該当しないとき中断する | §3.2 分岐と例外フロー |
| ディスパッチ表構成の継続 | filesが入口モジュール1本のみでconfidenceが全件lowのとき、中断せずディスパッチ表を解いて実装本体まで読む | §3.2 分岐と例外フロー |
| コード位置非記録 | 詳細設計書・実装記録・単体テスト設計書のいずれにも対象コードの位置が記録されない | §4.4 権限別の可否 |
| 検査不合格時の差し戻し | 8検査のいずれかが不合格のときPhase 3へ差し戻す | §3.2 分岐と例外フロー |

## §3 入力条件

**この節の位置づけ: 仕様**

| ケースのキー | 入力の項目 | 値 |

## §4 期待結果

**この節の位置づけ: 仕様**

| ケースのキー | 期待する結果 | 確認の方法 |
|---|---|---|
| 正常執筆完了 | status=DONEで返却され、API詳細設計書・API実装記録・API単体テスト設計書が揃う | 返却ブロックのstatusとartifactsを確認する |
| 該当プロファイルなし | status=ERRORで返却され、hintに拡張子の内訳が記録される | 返却ブロックのhintを確認する |
| ディスパッチ表構成の継続 | 中断せず実装本体まで読み、生成物が0件にならない | 生成された設計書の件数を確認する |
| コード位置非記録 | ファイル名・行番号・file:lineが検出0件になる | 検査2・検査5の結果を確認する |
| 検査不合格時の差し戻し | Phase 3へ戻り、上限3回で収束しなければstatus=ERRORになる | 返却ブロックのstatusと試行回数を確認する |
