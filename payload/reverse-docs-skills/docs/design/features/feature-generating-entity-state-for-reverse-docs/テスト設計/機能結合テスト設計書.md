## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | 機能設計書 | 機能単体テスト設計書 |
| 内部結合 | 1つの機能の中で関数・メソッドが結合した状態（外部の振る舞い） | 機能設計書 | 機能結合テスト設計書（本書） |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## §1 テスト観点

**この節の位置づけ: 仕様**

観点は機能設計書の業務フロー・業務ルール・エラーと業務メッセージの各章から起こします。

| キー | 観点 | 由来する機能設計書の章 |
|---|---|---|
| 正常生成完了 | Phase 1〜4が完走し、状態遷移図.htmlが生成される | §3.1 正常系フロー |
| 状態遷移表不在の停止 | 状態遷移表が未書き起こしのときSTOPPEDで停止する | §3.2 分岐と例外フロー |
| データ行0件の停止 | §6のデータ行が0件のときSTOPPEDで停止する | §3.2 分岐と例外フロー |
| 表外遷移の非捏造 | 表に記載のない状態遷移を推測・補完しない | §4.4 権限別の可否 |
| 検査不合格時の差し戻し | validate-page-data.shの同一FAILが2回連続再発でnodes組み立てへ即差し戻す | §9.1 件数と量の制限 |

## §3 入力条件

**この節の位置づけ: 仕様**

| ケースのキー | 入力の項目 | 値 |
|---|---|---|
| 正常生成完了 | target_repo_path・output_dir | データ設計.md §6が確定済みのプロジェクト |
| 状態遷移表不在の停止 | データ設計.md | §6状態遷移表を持たない |
| データ行0件の停止 | データ設計.md §6 | 見出しのみで行が0件 |
| 表外遷移の非捏造 | データ設計.md §6 | 特定の状態からの遷移が記載されていない |
| 検査不合格時の差し戻し | validate-page-data.shの検査結果 | 同一検査項目が2回連続でFAILする |

## §4 期待結果

**この節の位置づけ: 仕様**

| ケースのキー | 期待する結果 | 確認の方法 |
|---|---|---|
| 正常生成完了 | status=DONEで返却され、状態遷移図.htmlが実在する | 返却ブロックのstatusとartifactsを確認する |
| 状態遷移表不在の停止 | status=STOPPEDで返却され、hintに不在の旨が記録される | 返却ブロックのhintを確認する |
| データ行0件の停止 | status=STOPPEDで返却され、hintに0件の旨が記録される | 返却ブロックのhintを確認する |
| 表外遷移の非捏造 | nodes/edgesに記載外の状態・遷移が含まれない | page-data.jsonを確認する |
| 検査不合格時の差し戻し | Phase 2 Step 1（nodes組み立て）へ即差し戻される | Phase遷移ログを確認する |

## §6 境界値

**この節の位置づけ: 仕様**

## §7 網羅基準

**この節の位置づけ: 仕様**

| 観点 | 基準 |
|---|---|
| 条件の網羅 | 状態遷移表の有無、データ行の有無をそれぞれ1件以上のケースで確認します |
| 分岐の網羅 | DONE・STOPPEDの2分岐を1件以上のケースで確認します |
| 境界の網羅 | データ行数（0件境界）を確認します |
