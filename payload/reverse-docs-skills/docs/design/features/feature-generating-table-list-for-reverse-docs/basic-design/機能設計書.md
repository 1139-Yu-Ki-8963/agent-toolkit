## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | generating-table-list-for-reverse-docs |
| 機能ID | feat-generating-table-list-for-reverse-docs |
| 大分類 | 生成 |
| 業務対象 | 既存コードベースを調査してデータベースのテーブル（テーブル・ビュー・マイグレーション）の単位にファイルをグルーピングし、テーブル一覧.html を作成します。 |
| 確からしさ | high |
| 判定根拠 | 機能一覧マニフェスト（docs/manifests/feature-manifest.json）の sourceFile と .claude/skills/generating-table-list-for-reverse-docs/SKILL.md の記述が一致する |
| 境界の決定元 | build-target（Claude Code スキルのディレクトリ単位） |

### 1.2 業務上の位置づけ

リバース設計フローの生成担当（AIエージェント）が、対象プロジェクトのテーブル定義（マイグレーションファイル・ORMのモデル定義・SQLのDDL）を横断調査する調査・生成系の機能です。テーブル一覧という最初の成果物を確定するために使います。テーブル単位の詳細設計書やテーブルの業務上の意味付けは後続の機能に委ねます。

### 1.3 利用者と権限

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|
| リバース設計フローの生成担当（AIエージェント） | 対象プロジェクトのテーブル定義を調査し、テーブル一覧.htmlと永続マニフェスト（table-manifest.json・table-manifest.ext.json）を生成する | `.claude/skills/generating-table-list-for-reverse-docs/SKILL.md` |

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | 生成担当 | 本機能（Phase 1） | ORM・マイグレーションツールを特定し、テーブル定義の所在・識別パターン・除外パターンを調査して検出戦略宣言を承認する | 戦略宣言が承認されればPhase 2へ |
| 2 | 生成担当 | 本機能（Phase 2） | 承認済み戦略でテーブルを抽出し、extract-table-metadataで外部キー・カラム件数等を付与した拡張マニフェストを永続化する | 1件以上検出、または0件時の分岐に従い処理すればPhase 3へ |
| 3 | 生成担当・validate-manifest | 本機能（Phase 3） | validate-manifest.shで整合検証を行う | 全項目PASSならPhase 4へ。FAILなら修正し3回まで再実行、それでも失敗なら抽出のやり直しへ |
| 4 | 生成担当・build-unit-list | 本機能（Phase 4） | build-unit-list.shでテーブル一覧.htmlを生成する | HTML生成と永続マニフェストの実在を確認して完了 |

### 3.2 分岐と例外フロー

| キー | 分岐条件 | 到達先 | 参照先 |
|---|---|---|---|
| 検出0件・テーブル不在 | 検出0件で、アーキテクチャ調査書がテーブル不在と判定済み | テーブル一覧（該当なし）.mdを生成しstatus=NONEで正常終了する。呼び出し元がexcluded-kinds.jsonへtableを記録する | SKILL.md 0件時の分岐 |
| 検出0件・テーブル実在 | 検出0件だが、アーキテクチャ調査書がテーブル実在と判定 | 検出失敗として停止し、status=ERRORまたはAskUserQuestionで報告する | SKILL.md 0件時の分岐 |
| 調査書未指定 | survey_doc_pathが未指定で実在判定と突合できない | 実在判定を推測せず検出失敗として扱う（fail-closed） | SKILL.md 0件時の分岐 |
| 非UTF-8原本 | 通常の文字列検索でマッチ0件になる | detect-encoding.shでエンコーディングを確定し、UTF-8以外なら一時コピーへ変換してから走査し直す | SKILL.md 非UTF-8原本への対応 |
| 検証3回失敗 | validate-manifest.shが3回連続でFAIL | 抽出手順の再検討（Phase 2 Step 1）へ差し戻す | SKILL.md Phase 3 |

### 3.3 前後の機能との関係

| 関係 | 相手の機能キー | 受け渡す情報 | 参照先 |
|---|---|---|---|
| 後段 | generating-table-definition-for-reverse-docs | テーブル一覧の拡張マニフェスト（table-manifest.ext.json） | `docs/design/features/feature-generating-table-definition-for-reverse-docs/basic-design/機能設計書.md` |
