## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | 機能設計書 | 機能単体テスト設計書 |
| 内部結合 | 1つの機能の中で関数・メソッドが結合した状態（外部の振る舞い） | 機能設計書 | 機能結合テスト設計書（本書） |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## テスト対象

| 対象 | 確認する内容 | 根拠となる機能設計書の章 |
|---|---|---|
| Phase 1〜5の一連の流れ | モード確定→機械検証→承認・適用→派生物投影→結果確定が意図した順序で完走すること | §3 業務フロー |
| 二者承認の要求 | 業務承認者・技術承認者の両方が揃わないと適用されないこと | §3 業務フロー、§4 業務ルール |
| ai_index禁止 | publish targetがai_indexのとき成果物なしで停止すること | §3 業務フロー、§8 エラーと業務メッセージ |

## §1 テスト観点

**この節の位置づけ: 仕様**

観点は機能設計書の業務フロー・業務ルール・エラーと業務メッセージの各章から起こす。

| キー | 観点 | 由来する機能設計書の章 |
|---|---|---|
| 正常公開完了 | 二者承認済みかつdry_run=falseのとき、Phase1〜5が完走し用語辞書.htmlへ投影される | §3.1 正常系フロー |
| glossary直接更新拒否 | reverse解析の出力がglossary直接更新要求として渡されたとき拒否されproposal扱いになる | §3.2 分岐と例外フロー |
| review_required残存停止 | validate exit 0だがreview_requiredが残るとき適用を止める | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |
| 承認欠落停止 | 二者承認のいずれかが欠けるとき適用しない | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |
| ai_index禁止 | publish targetがai_indexのとき成果物なしで停止する | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |
| 反復未収束停止 | 5回検証しても収束しないとき適用せず停止する | §3.2 分岐と例外フロー |

## §3 入力条件

**この節の位置づけ: 仕様**

| ケースのキー | 入力の項目 | 値 |
|---|---|---|
| 正常公開完了 | 変更要求・approved_by | business_approver・technical_approverの2件が記録済み |
| glossary直接更新拒否 | 入力kind | glossary直接更新要求 |
| review_required残存停止 | validator report | exit 0、counts.review_required>0 |
| 承認欠落停止 | approved_by | technical_approverのみ記録 |
| ai_index禁止 | publish target | ai_index |
| 反復未収束停止 | Phase2〜3の反復 | 5回ともerror・承認不足が解消しない状態 |

## §4 期待結果

**この節の位置づけ: 仕様**

| ケースのキー | 期待する結果 | 確認の方法 |
|---|---|---|
| 正常公開完了 | 用語辞書.htmlが投影される | 返却のartifactsとstatusを確認する |
| glossary直接更新拒否 | proposalとしてのみ受け取られ直接更新は行われない | 返却のmodeを確認する |
| review_required残存停止 | 適用が止まる | 返却のstatusとvalidationを確認する |
| 承認欠落停止 | 適用されない | 返却のapprovalsとnext_actionを確認する |
| ai_index禁止 | status=review_required、reason=not_implementedで停止する | 返却のstatusとreasonを確認する |
| 反復未収束停止 | 適用されずに停止する | 返却のstatusと反復回数を確認する |

## §6 境界値

**この節の位置づけ: 仕様**

| 観点のキー | 対象の項目 | 境界の値 | 境界の直前と直後の扱い |
|---|---|---|---|
| 反復未収束停止 | Phase2〜3の反復回数 | 5回 | 4回目までは修正して再検証、5回目で収束しなければ適用せず停止 |

## §7 網羅基準

**この節の位置づけ: 仕様**

| 観点 | 基準 |
|---|---|
| 条件の網羅 | 二者承認の有無・review_requiredの有無をそれぞれ1件以上のケースで確認する |
| 分岐の網羅 | dry-run・適用の両方を1件以上のケースで確認する |
| 境界の網羅 | 反復回数の上限（5回）前後を確認する |

## §8 前提条件と終了条件

**この節の位置づけ: 仕様**

| 区分 | 内容 |
|---|---|
| 実行の前提条件 | 変更要求（proposals/changes）とregistryが実在すること |
| 終了の条件 | 適用時は二者承認済みのglossary・changeが同じ変更単位で更新され、判断根拠と次の行動を含む結果が返ること |
