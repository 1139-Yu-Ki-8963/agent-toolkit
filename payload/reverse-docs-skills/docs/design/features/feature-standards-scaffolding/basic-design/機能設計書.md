## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | standards-scaffolding |
| 機能ID | feat-standards-scaffolding |
| 大分類 | セットアップ |
| 業務対象 | 対象リポジトリへ規約定義一式（親7・子27）を配り、その定義から.claude/・.cursor/・.codex/向けの派生物を生成すること |
| 確からしさ | high |
| 判定根拠 | scaffold-rule-definitions.sh と build-derived-rules.sh の冒頭コメント（目的・使い方）が一致する |
| 境界の決定元 | build-target（generation-engine/scripts/rules/ 配下のスクリプト単位） |

### 1.2 業務上の位置づけ

主体はこのツール自身（対象リポジトリへ設置する側）です。入力から出力への向きは、対象リポジトリからAIが読む定義・AIツール設定・ポータルの器へと進みます。本機能はそのうちAIが読む定義（docs/rules/配下の規約定義一式）を担います。加えて、AIツール設定（.claude/rules/・.cursor/rules/・AGENTS.md索引・3ツールのhooks登録）も担います。まっさらな対象リポジトリに規約定義の親7フォルダ・子27フォルダを配り、その定義から一方向で派生物を生成します。定義から派生への一方向生成のみを行い、生成物の直接編集は前提としません。

### 1.3 利用者と権限

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|
| リバース設計フローの進行担当（AI エージェント） | 対象リポジトリへ規約定義一式を配り（既定は生成予定パスの列挙のみ、実際に適用するときだけ書き込みを行う）、定義から派生物を生成する | docs/design/batches/batch-rules/detail-design/バッチ詳細設計書.md |

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | 進行担当 | scaffold-rule-definitions | 出力先リポジトリルートを引数に受け取り、既定では生成予定パスを標準出力へ列挙するだけで書き込みをしない | 実際に適用する指定があれば書き込みへ進む |
| 2 | 進行担当 | scaffold-rule-definitions | 実際に適用する指定のとき、親7フォルダ・parent.yml、子27フォルダ・rule.md（ツール側が本文を定める子は本文入り）を配る。実装フローのゲートが必須とする2ファイルも上書き保護つきで配る | 配置完了後、build-derived-rules を呼ぶ段へ |
| 3 | 進行担当 | build-derived-rules | 実行の最初に定義の妥当性を確認する検証を呼び、不合格なら何も生成せず終了コード1で止まる | 合格すれば派生生成へ進む |
| 4 | 進行担当 | build-derived-rules | 既定では生成予定パスと内容の要約を標準出力へ出すだけで書き込みをしない。実際に適用する指定のとき、.claude/rules/・.cursor/rules/・AGENTS.md の規約索引・3ツールのhooks登録・（対象が実在すれば）mcp関連設定を生成する | 全生成完了で正常終了 |

### 3.2 分岐と例外フロー

| キー | 分岐条件 | 到達先 | 参照先 |
|---|---|---|---|
| 適用指定なし | 実際に適用する指定が無い | 生成予定パスの列挙のみで書き込みをしない | generation-engine/scripts/rules/scaffold-rule-definitions.sh 冒頭コメント |
| 検証不合格 | build-derived-rules 実行時に定義の妥当性確認が不合格を返す | 何も生成せず終了コード1で停止する | generation-engine/scripts/rules/build-derived-rules.sh 冒頭コメント |
| 未確定の規約 | 規約定義が未確定（作業中）を示す印を持つ | 生成対象から除外し、除外件数を報告する | generation-engine/scripts/rules/build-derived-rules.sh 冒頭コメント |
| mcp設定不在 | 対象リポジトリに mcp サーバー宣言が無い | mcp関連設定の生成をスキップする | generation-engine/scripts/rules/build-derived-rules.sh 冒頭コメント |

### 3.3 前後の機能との関係

| 関係 | 相手の機能キー | 受け渡す情報 | 参照先 |
|---|---|---|---|
| 前段との関係 | delivered-skills（配布スキルの設置） | 実装フローのゲートが必須とする2ファイル | generation-engine/scripts/rules/scaffold-rule-definitions.sh 冒頭コメント |

例外は、確認の結果が不合格だったとき生成しないという1点だけです。境界は「実際に適用する指定の有無」であり、指定が無い間は常に安全側（列挙のみ）に倒れます。

本機能が扱う対象（未確定の規約という印）は一方向の除外判定であり、遷移先を持つ状態機械ではありません。
