# 用語変更の検査と影響分析 機能単体テスト設計書

**この文書の位置づけ**（別の言語で作り直す場合は、まず「仕様」から読む）

- 仕様: §1 テスト観点、§2 テストケース一覧、§3 入力条件、§4 期待結果、§5 異常系、§6 境界値、§7 網羅基準、§8 前提条件と終了条件
- 現行実装: 該当なし
- 仕様／現行実装（詳細は各節の太字1行を見る）: 該当なし

本書は関数・メソッド単位の内部処理を検証します。観点と具体的なケースを分けず、1文書で管理します。対応する設計書は `機能設計書.md` です。

## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | 機能設計書 | 機能単体テスト設計書（本書） |
| 内部結合 | 1つの機能の中で関数・メソッドが結合した状態（外部の振る舞い） | 機能設計書 | 機能結合テスト設計書 |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## テスト対象

対象は関数・メソッド単位の内部処理とする。

## テストの粒度と自動化の方針

反復可能なケースは自動化し、実装後のテスト参照をケースに記録する。単位配下へ結合テスト文書を生成しない。

## 本書が扱わない範囲

複数の画面・機能・APIにまたがる結合テストはプロジェクト全体の `docs/test-cases/結合テスト仕様書.md` が担う。

### 根拠

定義ファイルは `.claude/skills/maintaining-semantic-glossary/SKILL.md` です。同ファイルは「本Skillは独立したCRUD runnerや用語保守CLIではない」と明記している。同ファイルは「AIがRead/Grep/Bashで定義YAML・候補・影響を調べ、Writeで変更要求を作る手順である」とも記す。独自定義の関数・メソッドを持たない。唯一の個別スクリプトは `generation-engine/scripts/glossary/validate-semantic-glossary.sh` です。その関数単位の検証は当該スクリプトの詳細設計書（`docs/design/batches/batch-glossary/detail-design/バッチ詳細設計書.md`）の単体テスト設計書が担う。
