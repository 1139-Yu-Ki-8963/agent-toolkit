## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | prioritizing-improvement-tasks-from-images |
| 機能ID | feat-prioritizing-improvement-tasks-from-images |
| 大分類 | 統括・管理 |
| 業務対象 | 改善課題を写した画像を書き起こし、このリポジトリの指摘改善一覧.mdへ項目として集約し、未解決項目を調査して優先順位を確定します。 |
| 確からしさ | high |
| 判定根拠 | 機能一覧マニフェスト（docs/manifests/feature-manifest.json）の sourceFile と .claude/skills/prioritizing-improvement-tasks-from-images/SKILL.md の記述が一致する |
| 境界の決定元 | build-target（Claude Code スキルのディレクトリ単位） |

### 1.2 業務上の位置づけ

このリポジトリ自身（reverse-docs-skills）の改善課題を管理する統括・管理系の機能です。画像で渡された指摘を書き起こし、`docs/tasks/指摘改善一覧.md` という単一の指示書へ集約し、未解決項目の事実調査を経て優先順位を確定します。台帳や優先順位表といった別ファイルは作らず、指示書1ファイルの構造内で完結させます。

### 1.3 利用者と権限

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|
| このリポジトリの保守担当（AIエージェント） | 改善課題の画像を書き起こし、指摘改善一覧.mdへ反映し、優先順位を確定する | `.claude/skills/prioritizing-improvement-tasks-from-images/SKILL.md` |

## §2 機能の範囲

**この節の位置づけ: 仕様**

### 2.1 構成要素一覧

本機能はこのリポジトリ自身の運用資産（`docs/tasks/指摘改善一覧.md`）を対象とする統括であり、対応するバッチ・テーブルの設計単位は持たない。画像の書き起こしは外部スキル（transcribing-images。このリポジトリの設計単位ではない）へ委任する。事実調査・反映は投影サブエージェント（investigator・report-reviewer・worker-sonnet）へ委任する。

| 構成要素キー | 種別 | 識別子 | 個別設計書 |
|---|---|---|---|
| check-instruction-format | バッチ（指示書形式検査スクリプト） | .claude/rules/always/tasks/instruction-format/check-instruction-format.sh | 該当なし（規約付属スクリプトのため設計単位を持たない） |

### 2.2 参照テーブル一覧

| テーブル | 作成 | 参照 | 更新 | 削除 | 参照先 |
|---|---|---|---|---|---|
| 該当なし | — | — | — | — | 本機能はデータベーステーブルを持たない。入出力はいずれもファイル（画像・指摘改善一覧.mdの読み書き）である |

### 2.3 範囲外

書き起こしだけを求められた場合、指示書に触れない調査だけを行う場合は本機能の範囲外です。資産ごとの新しい指示書ファイルを作ることも行いません。

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | 本機能・transcribing-images | 本機能（Phase 1） | 対象画像を書き起こす | 全件の書き起こし結果が得られればPhase 2へ |
| 2 | 本機能 | 本機能（Phase 2） | 改善課題かどうかを判定し、見出しキーを確定し、指示書群との突合で処理を決める | 全キーの状態と処理が確定すればPhase 3へ |
| 3 | 本機能 | 本機能（Phase 3） | 新規項目の挿入、再検証の追記と復活を指摘改善一覧.mdへ反映する | 反映完了しファイル構造が保たれればPhase 4へ |
| 4 | 本機能・investigator・report-reviewer | 本機能（Phase 4） | 未完了の全項目を事実調査し、報告判定でPASSを確認する | 収集6項目が証拠付きで揃えばPhase 5へ |
| 5 | 本機能 | 本機能（Phase 5） | 各項目に反映先資産を記録する | 全項目に反映先が記録されればPhase 6へ |
| 6 | 本機能 | 本機能（Phase 6） | 優先度を確定し、着手順の判定根拠を記録する | 優先度と根拠が確定すればPhase 7へ |
| 7 | 本機能・worker-sonnet | 本機能（Phase 7） | 優先度を反映し、check-instruction-format.shの検査に合格させてから提示する | 検査合格・提示完了で終了 |

### 3.2 分岐と例外フロー

| キー | 分岐条件 | 到達先 | 参照先 |
|---|---|---|---|
| 改善課題でない | 資産の欠陥・欠落を述べていない、または反映先を特定できない | 指示書には触れず、書き起こし結果をユーザーへ報告して停止する | SKILL.md Step 2-1 |
| 見出しキー読み取り不能 | 画像の採番形式（`<数字>-<数字>.`）が判読できない | 推測で振らず、AskUserQuestionでユーザーにキーを確認する | SKILL.md Step 2-2 |
| 未対応で残存 | grepで該当キーの見出しが既存指示書に見つかる | 何もせず重複して追記しない | SKILL.md Step 2-3 |
| 解消済みで削除・再検証記載あり | git logの履歴に登場し、画像に再検証の記載がある | 項目を復活させ再検証内容を追記する | SKILL.md Step 2-3、Step 3-2 |
| 解消済みで削除・再検証記載なし | git logの履歴に登場するが再検証の記載がない | 実在確認による調査のみを行い、欠陥が残っていれば復活の可否をユーザーに確認する | SKILL.md Step 2-3、Step 2-4 |
| 未完了0件 | 反映後の指摘改善一覧.mdに未完了項目が1件も無い | Phase 4〜6を実行せず、変更内容だけを報告して完了とする | SKILL.md Phase 4 |
| 循環依存検出 | 2項目以上が互いを先行と判定する | 順序を決めず、循環に含まれるキーと根拠を提示してユーザーに順序を求める | SKILL.md 循環依存を検出した場合 |
| 反復上限 | 報告判定FAILの再検証が5回に達する | 発散検知または収束停止のいずれかで停止する | SKILL.md ループ設計 |

### 3.3 前後の機能との関係
