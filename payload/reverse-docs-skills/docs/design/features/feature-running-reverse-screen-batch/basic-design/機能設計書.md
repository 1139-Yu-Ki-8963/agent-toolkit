## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | running-reverse-screen-batch |
| 機能ID | feat-running-reverse-screen-batch |
| 大分類 | 検証 |
| 業務対象 | 対象画面を1画面=1呼び出しの無人バッチループ（claude -p ヘッドレスモード）で検証し、指定工程まで設計書作成・再構築・実装照合を行い、進捗と失敗を記録します。 |
| 確からしさ | high |
| 判定根拠 | 機能一覧マニフェスト（docs/manifests/feature-manifest.json）の sourceFile と .claude/skills/running-reverse-screen-batch/SKILL.md の記述が一致する |
| 境界の決定元 | build-target（Claude Code スキルのディレクトリ単位） |

### 1.2 業務上の位置づけ

orchestrating-ai-development-setup から画面数4件以上のときに委譲される無人バッチ処理系の機能です。マーカー冪等性・limit耐性・残ゼロまで継続の3要件を満たし、対話ゼロ契約でAskUserQuestionを一切発行しません。1画面につき前半（静的リバース著述）と後半（ファイル単位検証・往復検証）の2回のclaude -p呼び出しに分離し、原本を見ない分離を担保します。

### 1.3 利用者と権限

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|
| orchestrating-ai-development-setup（管理者） | 画面数4件以上のとき本機能へ画面バッチ処理を委譲する | `.claude/skills/running-reverse-screen-batch/SKILL.md` |

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | 本機能 | 本機能（Phase 1） | 全必須引数を検証し、対象画面一覧を生成する | 検証完了でPhase 2へ |
| 2 | 本機能 | 本機能（Phase 2） | 先頭1画面で単発ドライラン（前半・docs-onlyは前半のみ）を実行する | 成功またはfailed確定でPhase 3へ |
| 3 | 本機能 | 本機能（Phase 3） | ループ雛形にパラメータを反映しバックグラウンド起動する | PID生存確認でPhase 4へ |
| 4 | 本機能 | 本機能（Phase 4） | 残件カウントと完了判定を行う | 全画面確定でPhase 5へ |
| 5 | 本機能 | 本機能（Phase 5） | 完了報告を提示する | 完了 |

### 3.2 分岐と例外フロー

| キー | 分岐条件 | 到達先 | 参照先 |
|---|---|---|---|
| docs-only終端 | verification_mode=docs-only | 前半のみ実行しSTATIC_COMPLETEで終端する。動的工程を起動しない | SKILL.md 画面1件の処理パイプライン |
| limit待機 | 出力にlimit文言パターンを検知 | wait_seconds秒sleepして再開する。当該画面は未完のまま次周回で再試行 | SKILL.md ループ設計 |
| スロット枯渇 | syncing-reverse-envがスロット不足ERRORを返す | headless_approved_opsに環境撤去が含まれれば最古の環境を軽量解放して再試行、無ければfailedリストへ退避する | SKILL.md ループ設計 |
| 開通競合 | unlocking-reverse-target-screensがCONFLICT-SKIPPEDを返す | 当該画面をconflict-skipリストへ記録し、failedとは別区分として次画面へ続行する | SKILL.md ループ設計 |
| 時限到達 | deadline指定時に現在時刻が超過する | 新規着手を停止しソフト停止する（実行中の呼び出しは中断しない） | SKILL.md ループ設計 |
| 連続失敗上限 | iterativeで同一画面がfail_limit_k回連続失敗する | failedリストへ退避する | SKILL.md ループ設計 |
