## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | portal |
| 機能ID | feat-portal |
| 大分類 | リバース |
| 業務対象 | ポータルの基盤ページ（技術スタック・環境構築手順・リリースノート）と納品物一覧を作り、成果物を1つの入口へまとめます。 |
| 確からしさ | high |
| 判定根拠 | 機能一覧マニフェスト（docs/manifests/feature-manifest.json）の sourceFile と .claude/skills/generating-tech-stack-for-reverse-docs/SKILL.md の記述が一致する |
| 境界の決定元 | build-target（Claude Code スキルのディレクトリ単位、および generation-engine/scripts 直下の生成器） |

### 1.2 業務上の位置づけ

リバース設計ポータルの入口そのものを作る機能です。3つの基盤ページ生成スキル（技術スタック・環境構築手順・リリースノート）は、アーキテクチャ調査書や `git log` を単一の事実源として個別に page-data.json を組み立てます。その後、整合検証を経てページを生成します。生成後に `portal_output_dir` が渡されていれば、共通のポータル組み立て本体（build-portal.sh）を再実行してカードへ反映します。orchestrating-ai-development-setup 自身も、共通設計書の確定後（Phase 4 Step 4-4）に build-portal.sh を直接起動します。起動すると、ポータル全体（`project-portal/index.html`）を組み立てます。対象範囲の承認前後（Phase 2 Step 2-7・Phase 7 Step 7-1）には build-deliverable-inventory.sh を実行します。実行すると、納品物一覧（HTML・Markdown）を作ります。3つの基盤ページスキルはいずれも判定・評価をせず、事実の転記に徹します。

### 1.3 利用者と権限

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|
| orchestrating-ai-development-setup（管理者） | Phase 4 Step 4-4 でポータル全体を組み立て、Phase 2 Step 2-7・Phase 7 Step 7-1 で納品物一覧を暫定生成・完成時再生成する | `.claude/skills/orchestrating-ai-development-setup/SKILL.md` |
| generating-tech-stack-for-reverse-docs・generating-env-guide-for-reverse-docs・generating-release-notes-for-reverse-docs（各基盤ページ生成担当） | 自身が生成した page-data.json から詳細ページ HTML を作り、`portal_output_dir` 指定時は build-portal.sh を再実行してカードへ反映する | `.claude/skills/generating-tech-stack-for-reverse-docs/SKILL.md` 等 |

## §2 機能の範囲

**この節の位置づけ: 仕様**

### 2.1 構成要素一覧

| 構成要素キー | 種別 | 識別子 | 個別設計書 |
|---|---|---|---|
| generating-tech-stack-for-reverse-docs | 機能 | 技術スタック.html の生成 | `.claude/skills/generating-tech-stack-for-reverse-docs/SKILL.md` |
| generating-env-guide-for-reverse-docs | 機能 | 環境構築手順.html の生成 | `.claude/skills/generating-env-guide-for-reverse-docs/SKILL.md` |
| generating-release-notes-for-reverse-docs | 機能 | リリースノート.html の生成 | `.claude/skills/generating-release-notes-for-reverse-docs/SKILL.md` |
| build_portal（ポータル組み立て本体） | バッチ（処理本体） | generation-engine/scripts/build-portal.sh | `docs/design/batches/batch-root/detail-design/バッチ詳細設計書.md` |
| build-deliverable-inventory.sh（納品物一覧の生成） | バッチ（処理本体） | generation-engine/scripts/build-deliverable-inventory.sh | `docs/design/batches/batch-root/detail-design/バッチ詳細設計書.md` |
| validate-page-data.sh・build-detail-page.sh（3スキル共有の整合検証・HTML生成エンジン） | バッチ（処理本体） | generation-engine/scripts/detail-pages/validate-page-data.sh・build-detail-page.sh | `docs/design/batches/batch-detail-pages/detail-design/バッチ詳細設計書.md` |

本機能自体は2つの部分に分かれる。1つは3つの基盤ページ生成スキルの手順として実行される部分です。もう1つは build-portal.sh・build-deliverable-inventory.sh の部分で、orchestrating-ai-development-setup が直接呼ぶ。3 スキルは `.claude/skills/<スキル名>/SKILL.md` の Phase 1〜4 の手順として実行される。抽出（調査書 §2/§3 の読取・git log 取得）は各スキル自身が Bash/Read/Grep で行う。整合検証と HTML 生成は決定的スクリプトへ固定する。

### 2.2 参照テーブル一覧

| テーブル | 作成 | 参照 | 更新 | 削除 | 参照先 |
|---|---|---|---|---|---|
| 該当なし | — | — | — | — | 本機能はデータベーステーブルを持たない。入出力はいずれもファイル（アーキテクチャ調査書・git log・page-data.json・生成 HTML・納品物一覧の読み書き）である |

### 2.3 範囲外

図ページ（画面遷移図・ER図等）やデザイン系ページ（デザインシステム・コンポーネント棚卸し・アイコンカタログ）の生成は本機能の範囲外です。それぞれ対応する生成スキル（generating-screen-transition-for-reverse-docs 等）が担います。技術スタック・環境構築手順・リリースノートを除く基盤ページ（アーキテクチャ調査書そのもの）の作成も範囲外です。詳細ページ生成の共通エンジン（validate-page-data.sh・build-detail-page.sh）自体の内部仕様は batch-detail-pages の個別設計書が正です。本書は利用の観点だけを扱います。

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | orchestrating-ai-development-setup | 本機能（Phase 2 Step 2-7） | unit_kinds_present から excluded-kinds.json を暫定生成し、build-deliverable-inventory.sh で暫定の納品物一覧（大半は「未生成」）を作りユーザーへ提示する | 対象範囲を確定してPhase 3以降へ進む |

| 3 | 各基盤ページ生成スキル | 本機能（各スキル Phase 1〜2） | アーキテクチャ調査書または git log を読み、page-data.json を組み立てる | 全項目一致（または種別判定確定）でPhase 3へ |

| 5 | 各基盤ページ生成スキル・build-detail-page.sh | 本機能（各スキル Phase 4） | HTML 生成スクリプトを実行し、`portal_output_dir` 指定時は build-portal.sh を再実行してカードへ反映する | 生成完了 |
| 6 | orchestrating-ai-development-setup | 本機能（Phase 7 Step 7-1） | build-deliverable-inventory.sh を再実行して完成時点の納品物一覧を作り、Step 2-7 で承認した暫定件数と突き合わせて差を報告する | 完了 |

### 3.2 分岐と例外フロー

| キー | 分岐条件 | 到達先 | 参照先 |
|---|---|---|---|
| 既存資産との衝突 | build-portal.sh 実行前に `index.html` が実在し `pt-nav-data` マーカーを含まない | build-portal.sh を実行せず中断し、別の出力先をユーザーへ確認する | orchestrating-ai-development-setup SKILL.md Step 4-4 |
| 出力先の誤り | `<output_dir>` に `docs` 自体が渡され、layout 解決先が二重の docs/docs 接頭辞を含む | `check_docs_root_misconfiguration` が検知し ERROR で異常終了する | build-portal.sh §14 エラーハンドリング |
| 調査書の記載不在 | 技術スタック・環境構築手順の各スキルで `アーキテクチャ調査書.md` が不在 | ハード停止し `surveying-architecture-for-reverse-docs` の先行実行を案内する | 各スキル SKILL.md Phase 1 |
| 実測値との乖離 | 技術スタックの「実在する」群で調査書記載値と定義ファイル実測値が食い違う | page-data を生成せず乖離内容を報告して停止する | generating-tech-stack-for-reverse-docs SKILL.md Phase 2 |
| env-config.json 不在 | 環境構築手順スキルで `env_config_path` が不在 | ハード停止せず、前提ツール表・実行環境表のみ空欄にして調査書 §3 だけで進める | generating-env-guide-for-reverse-docs SKILL.md Phase 1 |
| git 履歴不在 | リリースノートスキルで対象リポジトリに `.git` が無い | ハード停止し git 履歴不在を報告して終了する | generating-release-notes-for-reverse-docs SKILL.md Phase 1 |
| 整合検証 FAIL | validate-page-data.sh が FAIL を返す | 該当箇所を修正し再実行、3回失敗で page-data 組み立てへ差し戻す | 各スキル SKILL.md ループ設計 |

## §8 エラーと業務メッセージ

### 8.1 業務エラー一覧

| キー | 発生条件 | 利用者に見える結果 | 参照先 |
