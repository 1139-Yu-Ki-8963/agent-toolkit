## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | 機能設計書 | 機能単体テスト設計書 |
| 内部結合 | 1つの機能の中で関数・メソッドが結合した状態（外部の振る舞い） | 機能設計書 | 機能結合テスト設計書（本書） |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## §1 テスト観点

**この節の位置づけ: 仕様**

§1は正常・異常・境界を含む全観点の一覧です。
§5と§6は、§1のうち異常と境界の観点を列ごとに詳しく述べる部分集合です。
§5と§6では新しい観点キーを作らず、§1と同じ観点キーを使います。
実行する全ケースは§2だけに記載し、§1の全観点へ1件以上のケースを対応させます。
実行するテストの件数は§2のデータ行数だけで数えます。

観点は機能設計書の業務フロー・業務ルール・エラーと業務メッセージの各章から起こす。

| キー | 観点 | 由来する機能設計書の章 |
|---|---|---|
| 一巡フロー-CLEAN確認 | 定義変更から再生成、status呼び出し、recordの再実行までを行い、最終的に一致した状態へ戻ること | §3.1 |
| 台帳なし時の差し戻し | 台帳未作成の状態でstatusを実行するとNO-LEDGERとして終了コード2を返し、recordの先行実行を促すこと | §3.2、§8.1 |
| ハッシュ突合-DRIFT検出とrecordでの解消 | 生成物を編集・削除・追加した状態でstatusを実行するとDRIFTとなり、意図した変更としてrecordを再実行すると再度一致した状態へ戻ること | §3.1、§4.2 |
| 値突合-不一致検出 | 画面名または表示コミットの表示値が定義と食い違う状態でderived-valuesを実行すると不一致が報告されること | §3.1、§4.1 |
| 整合検査群-全件成功での前進 | consistency-checksとlayer1-aggregateを実行し、1件でも失敗・途中停止の疑い・打ち切りがあれば差し戻され、全件成功で次工程へ進むこと | §3.1、§4.3 |
| 判定不能の不算入 | 判定不能（[UNKNOWN]）の対象が失敗として集計されず、集計結果の内訳で区別して表示されること | §3.2、§4.1、§8.1 |
| 打ち切りと宣言済み長時間の区別 | 時間の上限に達した通常対象はTIMEOUTとして失敗に算入される一方、宣言済み長時間対象はDECLARED-LONGとして失敗にも途中停止の疑いにも算入されないこと | §3.2 |

## §3 入力条件

**この節の位置づけ: 仕様**

| ケースのキー | 入力の項目 | 値 |
|---|---|---|
| case-full-cycle-clean | 定義（テンプレート・マニフェスト）と、そこから再生成した派生物一式、台帳（derived-fingerprints.json） | 定義変更から再生成が完了した状態 |
| case-no-ledger-stop | 出力ディレクトリ配下のderived-fingerprints.json | 存在しない |
| case-drift-detect-and-resolve | 台帳記録後に編集・削除・追加した生成物一式 | MODIFIED／DELETED／ADDEDの各パターンを1件以上含む |
| case-value-mismatch | screen-manifest.jsonの画面名またはfrontmatterのsource_ref、対応するHTML埋め込み値 | 意図的に不一致にした値 |
| case-consistency-all-pass | consistency-checks・layer1-aggregateの対象スクリプト一式 | list_targetsで動的列挙される全対象 |
| case-indeterminate-excluded | mktempの失敗等で終了コード2・[UNKNOWN]ラベルを返す対象スクリプト | 操作名・想定原因を持つ[UNKNOWN]出力 |
| case-timeout-vs-declared-long | 時間の上限より長く動くダミースクリプトと、宣言済み長時間対象のリスト | 上限（既定120秒）を超えて動作するスクリプト二種（宣言なし・宣言あり） |

## §4 期待結果

**この節の位置づけ: 仕様**

| ケースのキー | 期待する結果 | 確認の方法 |
|---|---|---|
| case-full-cycle-clean | 再生成後のstatusが一致した状態を返し、recordで台帳を更新し直すと以後のstatusも一致した状態を維持する | statusの実行結果と終了コードを確認する |
| case-no-ledger-stop | NO-LEDGERとして終了コード2を返し、recordを先に実行するよう促すメッセージが出る | 標準出力とメッセージ文言を確認する |
| case-drift-detect-and-resolve | 編集・削除・追加それぞれについてMODIFIED／DELETED／ADDEDの行が出力され終了コード1になり、recordの再実行後は一致した状態へ戻る | statusとrecordの出力・終了コードを確認する |
| case-value-mismatch | 不一致が報告され終了コード1になる | derived-valuesの出力・終了コードを確認する |
| case-consistency-all-pass | 1件でも失敗・途中停止の疑い・打ち切りがあれば差し戻され、全件成功時は次工程（統合・公開）へ進める旨の集計行が出る | 集計行（対象／成功／失敗／判定不能／途中停止の疑い／打ち切り／宣言済み長時間／総ケース数）を確認する |
| case-indeterminate-excluded | 判定不能の件数として区別され、失敗の件数にも成功の件数にも算入されない | 集計行の判定不能の値と全体の終了コードを確認する |
| case-timeout-vs-declared-long | 通常対象はTIMEOUTとして失敗に算入され、宣言済み長時間対象はDECLARED-LONGとして失敗にも途中停止の疑いにも算入されない | 集計行の失敗・途中停止の疑い・宣言済み長時間の各値を確認する |

## §5 異常系

**この節の位置づけ: 仕様**

| 観点のキー | 発生させる条件 | 期待する振る舞い | 由来する機能設計書の章 |
|---|---|---|---|
| 台帳なし時の差し戻し | derived-fingerprints.jsonが存在しない状態でstatusを実行する | NO-LEDGERとして終了コード2を返す | §3.2、§8.1 |
| 値突合-不一致検出 | 画面名または表示コミットの表示値を定義と意図的に不一致にする | 不一致が報告され終了コード1になる | §3.1、§4.1 |

## §6 境界値

**この節の位置づけ: 仕様**

| 観点のキー | 対象の項目 | 境界の値 | 境界の直前と直後の扱い |
|---|---|---|---|
| 判定不能の不算入 | 判定不能の件数 | ゼロ／ゼロより多い | ゼロなら通常の成功・失敗の判定だけで完結する。ゼロより多くても不合格には数えず、内訳として区別して表示する |
| 打ち切りと宣言済み長時間の区別 | 対象が宣言済み長時間対象かどうか | 宣言なし／宣言あり | 宣言なしの対象が上限に達すればTIMEOUTとして失敗に算入する。宣言ありの対象が上限に達してもDECLARED-LONGとして失敗にも途中停止の疑いにも算入しない |

## §7 網羅基準

**この節の位置づけ: 仕様**

| 観点 | 基準 |
|---|---|
| 条件の網羅 | §3業務フローの分岐（台帳なし・判定不能・打ち切り・宣言済み長時間）をすべて1件以上のケースで確認する。 |
| 分岐の網羅 | derived-drift・derived-values・consistency-checks/layer1-aggregateそれぞれの正常系と差し戻し経路を1件以上のケースで確認する。 |
| 境界の網羅 | 判定不能の件数の有無と、宣言済み長時間対象の有無という2つの境界を確認する。 |

## §8 前提条件と終了条件

**この節の位置づけ: 仕様**

| 区分 | 内容 |
|---|---|
| 実行の前提条件 | 台帳（derived-fingerprints.json）の初回作成が済んでいること。jq・shasumが実行環境に存在すること。 |
| 終了の条件 | statusの終了コードが一致した状態（0）またはずれあり（1）のいずれかに確定していること。集計行の対象件数と、成功・失敗・判定不能・途中停止の疑い・打ち切り・宣言済み長時間の内訳の合計が一致していること。 |
