## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | unit-lists |
| 機能ID | feat-unit-lists |
| 大分類 | リバース |
| 業務対象 | 既存コードから画面・API・テーブル・バッチ・帳票・外部連携・機能・メッセージの8種別を検出し、各種別のマニフェストJSONと一覧ページ（HTML）を作ること |
| 確からしさ | high |
| 判定根拠 | 機能一覧マニフェスト（docs/manifests/feature-manifest.json）のsourceFile（generating-screen-list-for-reverse-docs/SKILL.md）が実在し、対応する8スキルのSKILL.mdがいずれも「既存コードから<種別>の一覧を作る」という一貫した目的を「いつ使うか」節に明記している |
| 境界の決定元 | build-target（Claude Code スキルのディレクトリ単位。8スキルが `.claude/skills/generating-<種別>-list-for-reverse-docs/` という共通の命名規則で並ぶ実行単位） |

### 1.2 業務上の位置づけ

主体: このツール自身（AIエージェントによるリバース設計フローの進行担当）です。

入力→出力: 既存コード（対象リポジトリの原本ファイル） → 7種別＋メッセージの一覧ページです。

本機能は8つの一覧生成スキルの集約です。画面・API・テーブル・バッチ・帳票・外部連携の6種別は互いに依存しません。対象種別（`unit_kinds_present`）に含まれるものだけを、対話モードでは並列、headlessモードでは逐次で起動します。機能一覧（generating-feature-list-for-reverse-docs）は画面一覧の定義（raw画面定義）が確定した後にだけ起動し、画面とAPIを業務機能ごとに束ね直します。メッセージ一覧（generating-message-list-for-reverse-docs）はメッセージ定義書.mdという既に確定した文書からの転記に限られ、原本コードを検出しません。8スキルはいずれも「抽出（検出）は種別ごとに可変、整合検証とHTML生成は決定的スクリプトへ固定する」という同じ設計原則（固定と可変の分離）に従います。

### 1.3 利用者と権限

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|
| リバース設計フローの進行担当（AIエージェント） | 対象種別ごとに一覧生成スキルを起動し、raw manifest・拡張manifest・一覧HTML（または該当なし文書）を確定させる | 各構成要素のSKILL.md |
| orchestrating-ai-development-setup（呼び出し元） | 対象種別の確定（excluded-kinds.json）に基づき、8スキルを起動して結果（statusの値）を回収する | `.claude/skills/orchestrating-ai-development-setup/SKILL.md` |

| report-list | スキル（帳票検出とHTML生成のオーケストレーション） | `.claude/skills/generating-report-list-for-reverse-docs/SKILL.md` | 該当なし（本機能の構成要素そのもの） |

| feature-list | スキル（画面・API等を業務機能へ束ね直すオーケストレーション） | `.claude/skills/generating-feature-list-for-reverse-docs/SKILL.md` | 該当なし（本機能の構成要素そのもの） |
| message-list | スキル（メッセージ定義書.mdからの転記オーケストレーション） | `.claude/skills/generating-message-list-for-reverse-docs/SKILL.md` | 該当なし（本機能の構成要素そのもの） |

種別はいずれも「スキル」です。8構成要素は `.claude/skills/generating-<種別>-list-for-reverse-docs/SKILL.md` という共通の命名規則を持ちます。識別子はリポジトリルートからの実在パスです。

8構成要素は、共通の内部ヘルパーとして2本のスクリプトを呼びます。1本は `generation-engine/scripts/unit-list/build-unit-list.sh`（HTML生成の共通ディスパッチャ）です。もう1本は `generation-engine/scripts/unit-list/validate-manifest.sh`（screen〜featureの7種別が使う整合検証）です。messageだけ `validate-message-manifest.sh` を個別に使います。この共通処理は §7.1 に1回だけ記述し、各構成要素の個別記述からは参照に留めます。

### 2.2 参照テーブル一覧

| テーブル | 作成 | 参照 | 更新 | 削除 | 参照先 |
|---|---|---|---|---|---|
| 該当なし | — | — | — | — | 本機能はデータベーステーブルを持たない。入出力はいずれもファイル（原本コード・メッセージ定義書.md・マニフェストJSON・一覧HTML）である |

### 2.3 範囲外

各構成要素が生成した一覧から、機能単位の集約設計書（機能設計書.md）を書き起こす工程は本機能の範囲外です。担当は generating-feature-design-for-reverse-docs です。各構成要素の詳細設計書の執筆（API・テーブル等の個別詳細設計）も範囲外です。一覧HTMLをポータルへ組み込んだ後の突合検証（ずれ検知）はdrift-detection機能が担い、本機能の範囲外です。テストケース一覧・テスト観点表一覧の生成は、種別ループの対象外の派生一覧です。担当は generating-test-viewpoint-list-for-reverse-docs・generating-test-case-list-for-reverse-docs です。本機能の8構成要素には含みません。

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | 呼び出し元（orchestrating-ai-development-setup） | 本機能の対象外（前工程） | 承認済みexcluded-kinds.json（presentKinds/excludedKinds）から対象種別（`unit_kinds_present`）を確定する | 対象種別が1件以上あれば次へ |
| 2 | 進行担当 | screen-list・api-list・table-list・batch-list・report-list・external-list（対象種別のみ） | 各スキルのPhase 1（スタック・規約の特定）からPhase 2（検出戦略に基づく抽出）を経てPhase 3（validate-manifest.shによる整合検証）へ進み、Phase 4（build-unit-list.shによるHTML生成）を実行する。対話モードはAgentで並列、headlessはSkillで逐次実行する | 各スキルがstatus=DONE（一覧HTML確定）またはstatus=NONE（該当なし文書確定）を返せば次へ、status=ERRORなら差し戻し |
| 3 | 進行担当 | feature-list | raw画面定義（`<output_dir>/<manifestsRoot>/screen-manifest.json`）が実在すれば、画面一覧と他種別一覧のraw manifestを入力に、Phase 1（入力収集）から順にPhase 6まで実行して業務機能へ束ね直す | raw画面定義が不在ならfeature-listをスキップし、画面一覧の定義確立後に再実行する |
| 4 | 進行担当 | message-list | メッセージ定義書.md（`<output_dir>/<commonRoot>/メッセージ定義書.md`）が実在すれば、Phase 1（存在確認）からPhase 4（HTML生成）までを実行してメッセージ定義書.mdの内容を一覧へ転記する | メッセージ定義書.mdが不在ならstatus=STOPPEDで終了し、本機能の範囲では一覧を生成しない |
| 5 | 呼び出し元 | 本機能の対象外（後工程） | 全構成要素のstatusを回収し、次工程（横断ビュー・ポータルの製造等）へ進む | 全対象種別がDONEまたはNONEであれば次工程へ、ERRORが残れば差し戻し |

### 3.2 分岐と例外フロー

| キー | 分岐条件 | 到達先 | 参照先 |
|---|---|---|---|
| 検出0件（対象外） | アーキテクチャ調査書の判定で当該種別が実在しないと分かる | `<種別>一覧（該当なし）.md`を判定理由の転記付きで生成し、status=`NONE`で正常終了する。呼び出し元はexcluded-kinds.jsonのexcludedKindsへ記録する | 各構成要素SKILL.md「0件時の分岐」 |
| 検出0件（検出失敗） | アーキテクチャ調査書が当該種別の実在を認めているのに0件しか検出できない | 停止する。headless=falseならAskUserQuestionで報告し、headless=trueなら`<verification_dir>/progress.jsonl`へ記録してstatus=`ERROR`を返す。手動リストは聞き出さない | 各構成要素SKILL.md「0件時の分岐」 |
| feature-list前提未充足 | raw画面定義（screen-manifest.json）が未確定 | feature-listの起動を見送り、画面一覧の定義確立後に本Stepを再実行する | `.claude/skills/orchestrating-ai-development-setup/SKILL.md` |
| message-list前提未充足 | メッセージ定義書.mdが不在 | message-listの起動そのものを見送る（「いつ使わないか」節が明記） | `.claude/skills/generating-message-list-for-reverse-docs/SKILL.md` |
| 整合検証不合格 | validate-manifest.sh／validate-message-manifest.shが1項目でも不合格を返す | HTML生成へ進まず、抽出（Phase 2）へ差し戻す | 各構成要素SKILL.md Phase 3 |
