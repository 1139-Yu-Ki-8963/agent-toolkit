## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | 機能設計書 | 機能単体テスト設計書 |
| 内部結合 | 1つの機能の中で関数・メソッドが結合した状態（外部の振る舞い） | 機能設計書 | 機能結合テスト設計書（本書） |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## テスト対象

| 対象 | 確認する内容 | 根拠となる機能設計書の章 |
|---|---|---|
| 抽出〜執筆〜検査の一連の流れ | Phase 1〜5が完走し、基本設計書・結合テスト設計書・単体テスト設計書が揃うこと | §3 業務フロー |

## §1 テスト観点

**この節の位置づけ: 仕様**

観点は機能設計書の業務フロー・業務ルール・エラーと業務メッセージの各章から起こします。

| キー | 観点 | 由来する機能設計書の章 |
|---|---|---|
| 正常執筆完了 | Phase 1〜5が完走し、基本設計書・結合テスト設計書・単体テスト設計書が揃う | §3.1 正常系フロー |
| プロファイル未確定時の確認 | 最多集計が同数で対象ユニット数でも決まらない場合にAskUserQuestionで確認する | §3.2 分岐と例外フロー |
| 該当プロファイルなしの中断 | どちらの拡張子にも該当しない場合status=ERRORで中断する | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |
| 記述の3区分判定 | 観測できる事実・観測から一意に導ける存在理由・判断基準と業務背景に分けて記入する | §4.1 業務判断ポイント |
| 検査不合格時の差し戻し | 機械検査のいずれかが不合格でPhase 3へ差し戻す | §3.2 分岐と例外フロー |

## §4 期待結果

**この節の位置づけ: 仕様**

| ケースのキー | 期待する結果 | 確認の方法 |

| 正常執筆完了 | status=DONEで返却され、API基本設計書・API結合テスト設計書が揃う | 返却ブロックのstatusとartifactsを確認する |
