## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | 機能設計書 | 機能単体テスト設計書 |
| 内部結合 | 1つの機能の中で関数・メソッドが結合した状態（外部の振る舞い） | 機能設計書 | 機能結合テスト設計書（本書） |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## §1 テスト観点

**この節の位置づけ: 仕様**

§1は正常・異常・境界を含む全観点の一覧です。
§5と§6は、§1のうち異常と境界の観点を列ごとに詳しく述べる部分集合です。
§5と§6では新しい観点キーを作らず、§1と同じ観点キーを使います。
実行する全ケースは§2だけに記載し、§1の全観点へ1件以上のケースを対応させます。
実行するテストの件数は§2のデータ行数だけで数えます。

観点は機能設計書の業務フロー・業務ルール・エラーと業務メッセージの各章から起こす。

| キー | 観点 | 由来する機能設計書の章 |
|---|---|---|
| 出力先・内側指定停止 | 候補生成でproposal_output_refが対象リポジトリ自身または配下・相対path・symlinkを含むとき何も書かず停止する | §8.1 業務エラー一覧 |
| detected固定 | 候補生成の出力はapproval.statusがdetected固定で、reviewers・reviewed_at・decision_reasonが未確定のまま人へ引き渡される | §3.2 分岐と例外フロー |
| 正常検査完了 | operationが許可一覧にあるとき、Phase1〜5が完走し変更要求または差し戻し理由が生成される | §3.1 正常系フロー |
| 物理削除拒否 | 公開済み用語への物理削除operationが拒否されdeprecate/retireを案内する | §3.2 分岐と例外フロー、§4.4 権限別の可否 |
| registry省略停止 | registryが省略されたときreview_requiredとして停止し変更要求を渡さない | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |
| 走査不能のhuman_check | 法令・契約・教育・運用のチャネルが走査不能のときhuman_check_requiredになる | §3.2 分岐と例外フロー |
| report不整合拒否 | root countsとfindingsの再集計件数が一致しないreportを拒否する | §8.1 業務エラー一覧 |
| 反復未収束停止-検査 | 検査と影響分析で5回検査しても収束しないときreview_requiredのまま停止する | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |
| 正常公開完了 | 二者承認済みかつdry_run=falseのとき、Phase1〜5が完走し用語辞書.htmlへ投影される | §3.1 正常系フロー |
| glossary直接更新拒否 | reverse解析の出力がglossary直接更新要求として渡されたとき拒否されproposal扱いになる | §3.2 分岐と例外フロー |
| review_required残存停止 | validate exit 0だがreview_requiredが残るとき適用を止める | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |
| 承認欠落停止 | 二者承認のいずれかが欠けるとき適用しない | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |
| ai_index禁止 | publish targetがai_indexのとき成果物なしで停止する | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |
| 反復未収束停止-適用 | 承認・適用・公開で5回検証しても収束しないとき適用せず停止する | §3.2 分岐と例外フロー |

## §4 期待結果

**この節の位置づけ: 仕様**

| ケースのキー | 期待する結果 | 確認の方法 |
|---|---|---|
| 出力先・内側指定停止 | 何も書かずSTOPPEDで終了する | 出力先にファイルが無いこと、終了ラベルを確認する |
| detected固定 | schema検証結果を保持したまま、needs_reviewとして人へ引き渡して停止する | 出力proposalのapproval.status・reviewersを確認する |
| 正常検査完了 | 変更要求または差し戻し理由が生成される | 返却のstatusとvalidationを確認する |
| 物理削除拒否 | 物理削除が拒否されdeprecate/retireの案内が返る | 返却のhintを確認する |
| registry省略停止 | review_requiredとして停止し変更要求が渡らない | 返却の変更要求保存先が空であることを確認する |
| 走査不能のhuman_check | human_check_requiredが記録され0件が削除許可へ変換されない | 影響分析結果のhuman_check_required欄を確認する |
| report不整合拒否 | 当該reportが拒否される | 返却のstatusを確認する |
| 反復未収束停止-検査 | review_requiredのまま停止する | 返却のstatusと反復回数を確認する |
| 正常公開完了 | 用語辞書.htmlが投影される | 返却のartifactsとstatusを確認する |
| glossary直接更新拒否 | proposalとしてのみ受け取られ直接更新は行われない | 返却のmodeを確認する |
| review_required残存停止 | 適用が止まる | 返却のstatusとvalidationを確認する |
| 承認欠落停止 | 適用されない | 返却のapprovalsとnext_actionを確認する |
| ai_index禁止 | status=review_required、reason=not_implementedで停止する | 返却のstatusとreasonを確認する |
| 反復未収束停止-適用 | 適用されずに停止する | 返却のstatusと反復回数を確認する |

## §6 境界値

**この節の位置づけ: 仕様**

## §7 網羅基準

**この節の位置づけ: 仕様**

| 観点 | 基準 |
|---|---|
| 条件の網羅 | 出力先の内外、registryの有無、走査可能・不能チャネル、二者承認の有無・review_requiredの有無をそれぞれ1件以上のケースで確認する |
| 分岐の網羅 | 検査合格・不合格、dry-run・適用の両方を1件以上のケースで確認する |
| 境界の網羅 | 反復回数の上限（検査・適用それぞれ5回）前後を確認する |

## §8 前提条件と終了条件

**この節の位置づけ: 仕様**

| 区分 | 内容 |
|---|---|
| 実行の前提条件 | 用語定義YAML・registryが実在し、正式validatorが実行可能であること。候補生成では出力先の絶対パスが対象リポジトリ外を指すこと |
| 終了の条件 | dry-run結果と次行動が記録され、正式用語集が変更されていないこと。適用時は二者承認済みのglossary・changeが同じ変更単位で更新され、判断根拠と次の行動を含む結果が返ること |
