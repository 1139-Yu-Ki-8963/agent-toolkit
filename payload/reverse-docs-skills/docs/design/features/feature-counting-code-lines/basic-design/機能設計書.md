## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | counting-code-lines |
| 機能ID | feat-counting-code-lines |
| 大分類 | 調査 |
| 業務対象 | 対象ディレクトリのコード行数・ファイル数を FE/BE 別の内訳つきで計測すること |
| 確からしさ | high |
| 判定根拠 | 機能一覧マニフェスト（docs/manifests/feature-manifest.json）の sourceFile と `.claude/skills/counting-code-lines/SKILL.md` の記述が一致する |
| 境界の決定元 | build-target（Claude Code スキルのディレクトリ単位） |

### 1.2 業務上の位置づけ

リバース設計フローの進行担当（AI エージェント）が、対象プロジェクトの規模を把握するために使う調査系の機能です。ポータル生成の解析サマリに表示する行数・ファイル数の元データを作ります。計測結果は `code-metrics.json` として保存し、他の生成処理から再利用できます。

### 1.3 利用者と権限

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|
| リバース設計フローの進行担当（AI エージェント） | 対象ディレクトリのコード行数・ファイル数を FE/BE 別・テスト別の内訳つきで計測し、`code-metrics.json` を得る | `.claude/skills/counting-code-lines/SKILL.md` |

## §2 機能の範囲

**この節の位置づけ: 仕様**

### 2.1 構成要素一覧

| 構成要素キー | 種別 | 識別子 | 個別設計書 |
|---|---|---|---|
| validate-code-metrics | バッチ（検証スクリプト） | generation-engine/scripts/validate-code-metrics.sh | docs/design/batches/batch-root/detail-design/バッチ詳細設計書.md |

本機能自体は `.claude/skills/counting-code-lines/SKILL.md` の手順として実行される。対象の Phase は Phase 1〜6 です。cloc または find + wc -l を直接呼び出す。これらは対象プロジェクトが持つ汎用コマンドであり、このリポジトリが保守する設計単位を持たない。

### 2.2 参照テーブル一覧

| テーブル | 作成 | 参照 | 更新 | 削除 | 参照先 |
|---|---|---|---|---|---|
| 該当なし | — | — | — | — | 本機能はデータベーステーブルを持たない。入出力はいずれもファイル（code-metrics.json・env-config.jsonの読み書き）である |

### 2.3 範囲外

計測結果（code-metrics.json）をポータルへ表示する処理は本機能の範囲外です。表示はポータル生成側（想定: generating-agent-config-index-from-repo）が担います。アーキテクチャ調査書からの技術スタック抽出そのものも本機能の範囲外であり、`survey_doc_path` を経由して受け取るだけです。

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | 進行担当 | 本機能（Phase 1） | target_dir の実在・env_config の有無・output_dir の書き込み可否を確認する | env_config が実在すれば cloc 方式の判定へ進む |
| 2 | 進行担当 | 本機能（Phase 2） | env_config の tools.cloc を読み、cloc 方式か wc -l 方式かを決定する | 決定した方式で Phase 3 へ進む |
| 3 | 進行担当 | 本機能（Phase 3） | 対象拡張子・除外ディレクトリを適用してコード行数の総計を計測する | 計測結果を Phase 4 へ渡す |
| 4 | 進行担当 | 本機能（Phase 4） | ファイルパスの判定パターンで FE/BE/未分類に分離する | 未分類率が 0.5 を超えれば警告フラグを立てて Phase 5 へ進む |
| 5 | 進行担当 | 本機能（Phase 5） | テストファイルを列挙し、アサーション出現数を計数する | Phase 6 へ進む |
| 6 | 進行担当 | 本機能（Phase 6） | 既存の code-metrics.json があれば previous として転記し、新しい計測結果を書き出す | validate-code-metrics.sh の終了コードが 0 であれば完了 |

### 3.2 分岐と例外フロー

| キー | 分岐条件 | 到達先 | 参照先 |
|---|---|---|---|
| env設定なし | env_config が存在しない | tools.cloc=false とみなし wc -l 方式で進める | .claude/skills/counting-code-lines/SKILL.md Phase 1 |
| 未分類率超過 | 未分類ファイル数 ÷ 列挙ファイル数 が 0.5 を超える | unclassified.warning=true を記録し、計測結果に警告を明示する | .claude/skills/counting-code-lines/SKILL.md Phase 4 |
| テスト検出失敗 | 既定パターンで列挙が 0 件、かつテストランナー設定・テストディレクトリも不在 | testDetectionFailed=false（テスト不在と判断） | .claude/skills/counting-code-lines/SKILL.md Phase 5 |

### 3.3 前後の機能との関係

| 関係 | 相手の機能キー | 受け渡す情報 | 参照先 |
|---|---|---|---|
| 後続 | generating-agent-config-index-from-repo（想定。ポータル生成側） | code-metrics.json（total・fe・be・tests 等） | docs/design/features/feature-generating-agent-config-index-from-repo/basic-design/機能設計書.md |
