## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | 機能設計書 | 機能単体テスト設計書 |
| 内部結合 | 1つの機能の中で関数・メソッドが結合した状態（外部の振る舞い） | 機能設計書 | 機能結合テスト設計書（本書） |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## テスト対象

| 対象 | 確認する内容 | 根拠となる機能設計書の章 |
|---|---|---|
| 調査〜抽出〜検証〜生成の一連の流れ | Phase 1〜4が完走し、バッチ一覧.htmlとマニフェストが揃うこと | §3 業務フロー |
| 0件時の分岐 | 検出0件のとき、調査書の判定によりNONEとERRORが正しく分かれること | §3.2 分岐と例外フロー |

## §1 テスト観点

**この節の位置づけ: 仕様**

観点は機能設計書の業務フロー・業務ルール・エラーと業務メッセージの各章から起こします。

| キー | 観点 | 由来する機能設計書の章 |
|---|---|---|
| 正常生成完了 | Phase 1〜4が完走し、バッチ一覧.htmlと永続マニフェストが揃う | §3.1 正常系フロー |
| バッチ不在の正常終了 | 検出0件かつ調査書がバッチ不在と判定するとき、NONEで正常終了する | §3.2 分岐と例外フロー |
| 検出失敗の停止 | 検出0件かつ調査書がバッチ実在と判定するとき、ERRORで停止する | §3.2 分岐と例外フロー |
| 定義のみで実装なしの除外 | 定義エントリに対応する実装が無いとき一覧本体に載せない | §3.2 分岐と例外フロー |
| 整合検証差し戻し | validate-manifest.shがFAILのとき、修正して再実行し3回で収束しなければ差し戻す | §9.1 件数と量の制限 |

## §3 入力条件

**この節の位置づけ: 仕様**

| ケースのキー | 入力の項目 | 値 |
|---|---|---|
| 正常生成完了 | source_dir・output_dir | 実在するバッチを持つコードベース |

## §4 期待結果

**この節の位置づけ: 仕様**

| ケースのキー | 期待する結果 | 確認の方法 |
|---|---|---|
| 正常生成完了 | status=DONEで返却され、バッチ一覧.html・batch-manifest.json・batch-manifest.ext.jsonが揃う | 返却ブロックのartifactsを確認する |
| バッチ不在の正常終了 | status=NONEで返却され、バッチ一覧（該当なし）.mdが生成される | 返却ブロックのstatusとartifactsを確認する |
| 検出失敗の停止 | status=ERRORで返却される | 返却ブロックのstatusを確認する |
| 定義のみで実装なしの除外 | 当該エントリがunitsに現れず、detectionSummary.diagnostics.definitionWithoutImplementationに記録される | 拡張マニフェストの該当フィールドを確認する |
| 整合検証差し戻し | 3回以内に修正されるか、3回目で抽出手順へ差し戻される | validate-manifest.shの再実行結果を確認する |

**この節の位置づけ: 仕様**

| 観点 | 基準 |

| 境界の網羅 | 整合検証の修正ループ回数（3回）の境界を確認します |
