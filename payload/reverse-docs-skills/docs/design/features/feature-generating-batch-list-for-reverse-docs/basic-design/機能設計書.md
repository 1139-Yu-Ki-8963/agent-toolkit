## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | generating-batch-list-for-reverse-docs |
| 機能ID | feat-generating-batch-list-for-reverse-docs |
| 大分類 | 生成 |
| 業務対象 | 既存コードを調べ、定期的に実行する処理（バッチ）ごとの一覧ページ（バッチ一覧.html）を作ること |
| 確からしさ | high |
| 判定根拠 | 機能一覧マニフェストの sourceFile と `.claude/skills/generating-batch-list-for-reverse-docs/SKILL.md` の記述が一致する |
| 境界の決定元 | build-target（Claude Code スキルのディレクトリ単位） |

### 1.2 業務上の位置づけ

対象コードベースをスタック調査→検出戦略の宣言→戦略に基づく抽出→整合検証の順で調べ、バッチ一覧.htmlを作ります。マニフェストスキーマ・整合検証・HTML生成は決定的スクリプトに固定し、抽出（バッチ境界の検出）だけをプロジェクトごとに可変な手作業とします。

### 1.3 利用者と権限

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|
| リバース設計フローの進行担当（AI エージェント） | 既存コードベースからバッチ一覧.htmlと永続マニフェストを作る | .claude/skills/generating-batch-list-for-reverse-docs/SKILL.md |

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | 進行担当 | 本機能（Phase 1） | スタック・バッチ規約を調査し、検出戦略宣言を作る | Phase 2 へ |
| 2 | 進行担当 | 本機能（Phase 2）／extract-batch-metadata.sh | 戦略に基づきカスタム抽出を実行し、マニフェストJSONを作成後、メタデータ（schedule・targetTables・downstreamJobs・execMethod）を付与する | Phase 3 へ |
| 3 | 進行担当 | validate-manifest.sh | 拡張マニフェストの整合を検証する | 全項目PASSでPhase 4へ |
| 4 | 進行担当 | build-unit-list.sh | バッチ一覧.htmlを生成する | 完了 |

### 3.2 分岐と例外フロー

| キー | 分岐条件 | 到達先 | 参照先 |
|---|---|---|---|
| バッチ実在しない | 検出0件、かつ調査書がバッチ不在と判定 | status=NONE。バッチ一覧（該当なし）.mdを生成し正常終了する | .claude/skills/generating-batch-list-for-reverse-docs/SKILL.md 0件時の分岐 |
| 検出失敗 | 検出0件、かつ調査書がバッチ実在と判定 | 停止する。status=ERROR | .claude/skills/generating-batch-list-for-reverse-docs/SKILL.md 0件時の分岐 |
| 定義のみで実装なし | cron設定等の定義エントリに対応する実装が無い | definitionWithoutImplementationへ記録し、一覧本体には載せない | .claude/skills/generating-batch-list-for-reverse-docs/SKILL.md Phase 2 |
| 整合検証不合格 | validate-manifest.shがFAILを返す | 修正して再実行。3回失敗で抽出手順へ差し戻し | .claude/skills/generating-batch-list-for-reverse-docs/SKILL.md Phase 3 |

### 3.3 前後の機能との関係

|---|---|---|---|
