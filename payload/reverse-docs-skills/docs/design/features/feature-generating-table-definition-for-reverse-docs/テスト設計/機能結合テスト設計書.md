## 本書が検証するもの

結合は2段に分けて定義します。1つの設計単位の中で構成要素が結合した状態を内部結合、複数の設計単位をまたぐ連携を外部結合と呼びます。単位ごとの文書は内部結合までを担い、プロジェクト全体の文書が外部結合を担います。

| 段 | 検証する状態 | 対応する設計書 | 文書 |
|---|---|---|---|
| 単体 | 1つの関数・メソッドの入出力 | 機能設計書 | 機能単体テスト設計書 |
| 内部結合 | 1つの機能の中で関数・メソッドが結合した状態（外部の振る舞い） | 機能設計書 | 機能結合テスト設計書（本書） |
| 外部結合 | 複数の画面・機能・APIをまたぐ連携 | 複数の設計書 | docs/test-cases/結合テスト仕様書.md |

## テスト対象

| 対象 | 確認する内容 | 根拠となる機能設計書の章 |
|---|---|---|
| Phase 1〜4の一連の流れ | 4引数確認→対象確定→原本読解→執筆→機械検査が意図した順序で完走すること | §3 業務フロー |

## §1 テスト観点

**この節の位置づけ: 仕様**

観点は機能設計書の業務フロー・業務ルール・エラーと業務メッセージの各章から起こす。

| キー | 観点 | 由来する機能設計書の章 |
|---|---|---|
| 正常生成完了 | 4引数が実在するとき、Phase1〜4が完走しテーブル定義書・テーブル実装記録が生成される | §3.1 正常系フロー |
| 識別子不確定エラー | unitId・unitKeyが両方空のとき、当該ユニットを生成せずstatus=ERRORで中断する | §3.2 分岐と例外フロー、§8.1 業務エラー一覧 |
| unitKey特殊文字置換 | unitKeyにパス区切りや制御文字を含むとき、ハイフンへ置換し置換前後を記録する | §3.2 分岐と例外フロー |
| 検査差し戻し | Phase4の5検査のいずれかが不合格のとき、Phase3へ差し戻して再実行する | §3.2 分岐と例外フロー、§4.1 業務判断ポイント |
| 検査未収束エラー | 差し戻しが上限3回に達しても収束しないとき、status=ERRORになる | §8.1 業務エラー一覧 |
| status遷移 | 記入完了に伴いstatusがdraftからauthoredへ更新される | §4.2 状態と遷移の制約 |

## §2 テストケース一覧

**この節の位置づけ: 仕様**

| キー | 番号 | ケースの名前 | 対応する観点のキー | 区分 |
|---|---|---|---|---|
| 正常生成完了 | 1 | 4引数実在時に一連の生成が完走する | 正常生成完了 | 正常系 |
| 識別子不確定エラー | 2 | unitId・unitKeyが両方空のとき生成せずエラー終了する | 識別子不確定エラー | 異常系 |
| unitKey特殊文字置換 | 3 | unitKeyの特殊文字がハイフンへ置換される | unitKey特殊文字置換 | 境界値 |
| 検査差し戻し | 4 | 検査不合格時にPhase3へ差し戻され再実行される | 検査差し戻し | 正常系 |
| 検査未収束エラー | 5 | 差し戻しが3回続いてもstatus=ERRORになる | 検査未収束エラー | 異常系 |
| status遷移 | 6 | 記入完了後にstatusがauthoredになる | status遷移 | 正常系 |

## §3 入力条件

**この節の位置づけ: 仕様**

| ケースのキー | 入力の項目 | 値 |
|---|---|---|
| 正常生成完了 | table_manifest_path・source_dir・output_dir・template_root | いずれも実在するパス |
| 識別子不確定エラー | 対象ユニットのunitId・unitKey | 両方null／空文字 |
| unitKey特殊文字置換 | 対象ユニットのunitKey | パス区切り（/）を含む値 |
| 検査差し戻し | Phase4の検査対象 | カラム件数がマニフェストと不一致な状態 |
| 検査未収束エラー | Phase3〜4の反復 | 3回連続で不合格になる状態 |
| status遷移 | 対象ユニットのfrontmatter | status=draftの初期状態 |

## §4 期待結果

**この節の位置づけ: 仕様**

| ケースのキー | 期待する結果 | 確認の方法 |
|---|---|---|
| 正常生成完了 | テーブル定義書.md・テーブル実装記録.md が生成される | `scaffold-design-unit.sh --verify table detail`の終了コードが0であることを確認する |
| 識別子不確定エラー | 当該ユニットが生成されずstatus=ERRORになる | 返却のhintに識別子不確定の旨が記録されることを確認する |
| unitKey特殊文字置換 | 出力先ディレクトリ名がハイフン置換後の値になる | 実行結果に置換前後が記録されることを確認する |
| 検査差し戻し | Phase3へ差し戻され再実行後に合格する | 2回目のPhase4検査が全件合格することを確認する |
| 検査未収束エラー | 3回目の差し戻し後もstatus=ERRORのままである | 返却のstatusを確認する |
| status遷移 | frontmatterのstatusがauthoredになる | 生成ファイルのstatus欄を確認する |

## §7 網羅基準

**この節の位置づけ: 仕様**

| 観点 | 基準 |
|---|---|
| 条件の網羅 | unitId・unitKeyの有無、unitKeyの特殊文字有無をそれぞれ1件以上のケースで確認する |
| 分岐の網羅 | 検査合格／不合格の両方を1件以上のケースで確認する |
| 境界の網羅 | 差し戻し回数の上限（3回）前後を確認する |
