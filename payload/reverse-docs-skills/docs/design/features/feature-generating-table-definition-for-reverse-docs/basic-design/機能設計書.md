# テーブル定義書の書き起こし 機能設計書

**この文書の位置づけ**（別の言語で作り直す場合は、まず「仕様」から読む）

- 仕様: §1 機能概要、§2 機能の範囲、§3 業務フロー、§4 業務ルール、§5 データ、§6 構成要素間の状態受け渡し。§7 呼び出し仕様、§8 エラーと業務メッセージ、§9 非機能、§10 共通仕様への準拠、§11 関連資料
- 現行実装: 該当なし
- 仕様／現行実装（詳細は各節の太字1行を見る）: 該当なし

本書は集約設計書です。構成要素（画面・API・実行ファイル等）の個別仕様は各構成要素の設計書を正とし、本書は値を再掲せずパスで参照します。本書が正を持つのは、構成要素をまたいで初めて意味を持つ事項（業務フロー・業務ルール・状態のライフサイクル）だけです。

コードから確定できない事項は推測で埋めない。空欄のままとする。

## §1 機能概要

**この節の位置づけ: 仕様**

### 1.1 基本情報

| 項目 | 値 |
|---|---|
| 機能キー | generating-table-definition-for-reverse-docs |
| 機能ID | feat-generating-table-definition-for-reverse-docs |
| 大分類 | 生成 |
| 業務対象 | テーブル一覧の拡張マニフェストと原本コード（マイグレーションファイル・ORMのモデル定義・SQLのDDLのいずれか）から、テーブルごとの定義書（カラムの名前・型・長さ・必須の別・既定値・制約・索引・外部キーの参照先）を書き起こします。 |
| 確からしさ | high |
| 判定根拠 | 機能一覧マニフェスト（docs/manifests/feature-manifest.json）の sourceFile と .claude/skills/generating-table-definition-for-reverse-docs/SKILL.md の記述が一致する |
| 境界の決定元 | build-target（Claude Code スキルのディレクトリ単位） |

### 1.2 業務上の位置づけ

リバース設計フローの生成担当（AIエージェント）が、テーブル一覧の生成後に、テーブル単位の詳細設計書を確定するために使う生成系の機能です。抽出する内容はカラム構造と制約に限り、テーブルが持つ業務上の意味は論理データモデルを作る機能が別に担います。

### 1.3 利用者と権限

| 利用者区分 | この機能でできること | 参照先 |
|---|---|---|
| リバース設計フローの生成担当（AIエージェント） | テーブル一覧の拡張マニフェストと原本コードから、テーブルごとのテーブル定義書・テーブル実装記録を生成する | `.claude/skills/generating-table-definition-for-reverse-docs/SKILL.md` |

## §2 機能の範囲

**この節の位置づけ: 仕様**

### 2.1 構成要素一覧

| 構成要素キー | 種別 | 識別子 | 個別設計書 |
|---|---|---|---|
| scaffold-design-unit | バッチ（テンプレート配置・検証スクリプト） | generation-engine/scripts/scaffold-design-unit.sh | `docs/design/batches/batch-root/detail-design/バッチ詳細設計書.md` |

本機能自体は `.claude/skills/generating-table-definition-for-reverse-docs/SKILL.md` の手順として実行されます。対象の Phase は Phase 1〜4 です。原本コードの読解と各章への記入は生成担当が直接行います。個別のスクリプトとして切り出されているのは配置・検証を担う scaffold-design-unit.sh のみです。

### 2.2 参照テーブル一覧

| テーブル | 作成 | 参照 | 更新 | 削除 | 参照先 |
|---|---|---|---|---|---|
| 該当なし | — | — | — | — | 本機能はデータベーステーブルを持たない。入出力はいずれもファイル（マニフェスト・設計書・HTMLの読み書き）である |

### 2.3 範囲外

テーブルが持つ業務上の意味（論理データモデル）を書く処理は本機能の範囲外であり、generating-table-logical-model-for-reverse-docs が担います。テーブル一覧そのものの生成も範囲外で、generating-table-list-for-reverse-docs が担います。

## §3 業務フロー

**この節の位置づけ: 仕様**

### 3.1 正常系フロー

| 順 | 実行主体 | 構成要素 | 処理 | 次の分岐条件 |
|---|---|---|---|---|
| 1 | 生成担当 | 本機能（Phase 1） | 4引数（table_manifest_path・source_dir・output_dir・template_root）の実在を確認し、マニフェストを読んで対象ユニットを確定する | 4引数が実在しマニフェストが確認済みなら Phase 2 へ |
| 2 | 生成担当 | 本機能（Phase 2） | 対象ユニット1件ごとに原本コードを読み、カラムの名前・型・長さ・必須の別・既定値・制約・索引・外部キーの参照先を抽出する | 全対象ユニットの材料が揃えば Phase 3 へ |
| 3 | 生成担当 | 本機能（Phase 3） | scaffold-design-unit でテンプレートを配置し、テーブル定義書・テーブル実装記録の各章へ記入して status を authored へ更新する | 記入完了後 Phase 4 へ |
| 4 | 生成担当 | 本機能（Phase 4） | 5検査（カラム件数一致・注記残存・frontmatter・章完備・配置）を実行する | 全検査合格で完了。不合格なら Phase 3 へ差し戻し（上限3回） |

### 3.2 分岐と例外フロー

| キー | 分岐条件 | 到達先 | 参照先 |
|---|---|---|---|
| 識別子不確定 | 対象ユニットの unitId・unitKey が両方空 | 当該ユニットを生成せず status=ERROR で中断し、hint に識別子不確定と unitNameGuess を記録する | SKILL.md 成果物 |
| unitKeyの特殊文字 | unitKey にパス区切り（/）または制御文字を含む | ハイフンへ置換し、置換前後を実行結果に記録する | SKILL.md 成果物 |
| 検査不合格 | Phase 4 の5検査のいずれかが1件でも不合格 | Phase 3 へ差し戻して再実行する。上限3回で収束しなければ status=ERROR | SKILL.md ループ設計 |

### 3.3 前後の機能との関係

| 関係 | 相手の機能キー | 受け渡す情報 | 参照先 |
|---|---|---|---|
| 前段 | generating-table-list-for-reverse-docs | テーブル一覧の拡張マニフェスト（table-manifest.ext.json） | `docs/design/features/feature-generating-table-list-for-reverse-docs/basic-design/機能設計書.md` |
| 後段 | generating-table-logical-model-for-reverse-docs | テーブル定義書のカラム構造（業務上の意味付けの土台） | `docs/design/features/feature-generating-table-logical-model-for-reverse-docs/basic-design/機能設計書.md` |
