## §1 外部仕様

**この節の位置づけ: 仕様**

本定義は利用者から直接見える対象ではありません。この JSON ファイルを読み込む規約生成スクリプト（scaffold-rule-definitions.sh）が外部仕様に相当します。規約索引生成スクリプト（build-rule-flow-map.sh）も同様です。規約整合検査スクリプト（validate-rule-definitions.sh）も同様です。

| 参照元の種別 | 参照元の識別子 | 参照する目的 |
|---|---|---|
| 生成スクリプト・検査スクリプト | delivery-payload/references/rule-taxonomy.json を読む各スクリプト | 対象プロジェクトへ配る27件の規約を親カテゴリ7件・子カテゴリ27件へ分類し、各規約の適用範囲・対応フェーズ・機械検査の有無・作業の単位を定めた定義です。 |

## §2 業務仕様

**この節の位置づけ: 仕様**

### 2.1 業務フロー

| 順 | 実行主体 | 処理 | 次の分岐条件 |
|---|---|---|---|
| 1 | 生成スクリプト・検査スクリプト | この定義を読み込む | 定義に該当項目が見つかるかどうか |
| 2 | 生成スクリプト・検査スクリプト | 定義に基づいて判定または生成を行う | 該当なし |

### 2.2 状態遷移

本定義自体は状態を持ちません。この定義を参照する生成物・検査結果の側が状態（合格・不合格・対象外等）を持ちます。

| 状態 | 遷移先 | 遷移条件 |
|---|---|---|

### 2.3 業務ルール

親カテゴリごとの子カテゴリ一覧、横断的な機械検査、規約が未解析または対象外のときの定型文を保持します。

| キー | 判定内容 | 判定材料 |
|---|---|---|
| rule-taxonomy-規則-1 | 親カテゴリの識別子 | parents[].key が一意であること |
| rule-taxonomy-規則-2 | 子カテゴリの識別子 | parents[].children[].key が全親を通じて一意であること |
| rule-taxonomy-規則-3 | 機械検査の宣言 | children[].toolDefined が true の場合、checker が空でないこと |
| rule-taxonomy-規則-4 | 適用範囲の指定 | children[].scope が always または scoped であること。scoped の場合 paths[] が1件以上であること |
| rule-taxonomy-規則-5 | 作業の単位 | children[].workUnit が file／process／artifact のいずれかであること |
| rule-taxonomy-規則-6 | 横断的な機械検査の識別子 | crossCuttingChecks[].key が一意であること |

### 2.4 例外条件

| キー | 発生条件 | 取り扱い |
|---|---|---|
| rule-taxonomy-未定義 | この定義に該当する項目が見つからない | 読み手側のスクリプトが既定の代替値または対象外として扱う |

### 2.5 取消と再実行と二重送信の取り扱い

本定義は読み取り専用の静的データであり、取消・再実行・二重送信の概念を持ちません。

| 事象 | 取り扱い |
|---|---|

## §3 方式設計

**この節の位置づけ: 仕様**

| 観点 | 方式 |
|---|---|
| 性能 | ファイル1件を都度読み込む方式であり、件数に比例する処理は発生しない |
| 可用性 | バージョン管理下の静的ファイルであり、可用性は版管理システムに準じる |
| セキュリティ | 機密情報を含まない設定データであり、公開資産として配布される |
| 監査ログ | git の変更履歴が監査の記録を兼ねる |
| 運用 | 変更時は本定義を読む全スクリプトへの影響を確認してから更新する |
| バックアップ | git リポジトリの複製がバックアップを兼ねる |
| 災害対策 | 該当なし |

## §4 データ仕様

**この節の位置づけ: 仕様**

### 4.1 扱うデータの論理定義

| 論理名 | 意味 | キー | 整合性の条件 |
|---|---|---|---|
| 親カテゴリ識別子 | 規約の大分類を表す識別子 | 主キー | parents 内で一意であること |
| 子カテゴリ識別子 | 規約1件を表す識別子 | 主キー | 全親を通じて一意であること |
| 機械検査の有無と検査名 | この規約が機械検査を持つかどうかとその検査スクリプト名 | なし | toolDefinedがtrueならcheckerが空でないこと |
| 適用範囲 | 常時適用（always）か特定パス限定（scoped）か | なし | always または scoped であること |
| 対応フェーズ | この規約が効くフロー上のフェーズの一覧 | なし | 定めたフェーズ語彙であること |
| 作業の単位 | ファイルの中身／進め方／成果物の形のいずれを規定するか | なし | file／process／artifactのいずれかであること |

### 4.2 データフローと更新責任

| データ | 読む | 書く | 更新の責任 |
|---|---|---|---|
| rule-taxonomy.json | 生成スクリプト・検査スクリプト | 人手（レビュー担当） | 本定義を変更する場合は、これを読む全スクリプトと本設計書を同時に更新する |

### 4.3 保存期間とマスキング

| データ | 保存期間 | マスキングの要否 |
|---|---|---|
| rule-taxonomy.json | 版管理下で永続的に保持する | 不要（機密情報を含まない） |

### 4.4 トランザクション境界と排他

本定義はファイル単位の読み取り専用データであり、トランザクション境界・排他制御の対象ではありません。

| 対象 | 境界 | 排他の方針 |
|---|---|---|
