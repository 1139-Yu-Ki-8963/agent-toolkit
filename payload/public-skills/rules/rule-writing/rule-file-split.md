# 規約をファイルに分ける仕方

## 適用する場面

規約の箱の中で、1 つの決まりをどのファイルに置くか決めるとき。新しいファイルを作るとき。

## 守ること

規則 1: 1 ファイルは 1 つの対象について書く
- 判定の仕方: 機械的
- 規約のファイルは、1 つの対象(phase、step の文、リファレンス、スクリプト)についての決まりだけを持つ。題名は、その対象の名前。

規則 2: 2 つ以上の対象に同じ形で掛かる決まりは、観点のファイルに集める
- 判定の仕方: AI の推論
- 同じ観点の決まりが 2 つ以上の対象に掛かるとき(数の上限、チャットへの表示、使う語)は、その観点で 1 ファイルを作り、すべての対象の分をそこに書く。対象のファイルには書かない。
- 1 つの対象にしか掛からない決まりは、その対象のファイルに書く。

規則 3: 対象のファイルから観点のファイルへの参照
- 判定の仕方: 機械的
- 対象のファイルが観点の決まりを使うときは、観点のファイルの名前と規則の番号で指す。文は写さない。

規則 4: 決まりをどのファイルに置くかの例
- 判定の仕方: 機械的

| 決まり | 置くファイル | 理由 |
|---|---|---|
| phase は 5 個まで | skill-limits(観点: 数の上限) | step、リファレンス、スクリプトにも上限がある |
| phase の見出しは「## phase 2 名前」 | skill-phase(対象: phase) | phase にしか掛からない |
| 各 phase の最初に phase の表示を出す | skill-input-output(観点: 表示) | 8 種類の表示の 1 つ |

## 理由

決まりの置き先が対象か観点かで決まっていれば、同じ決まりが 2 つのファイルに現れず、読む側はどちらを見ればよいかで迷わない。
