# 規約か雛形か雛形の書き方か

## 適用する場面

スキルに関する文書(規約、雛形、雛形の書き方、完成例)に文や形を足すとき、または既存の文をどの文書に置くかを決めるとき。

## 守ること

規則 1: 書くもの
- 規約に書くのは、できあがった成果物(`SKILL.md`、リファレンス)が満たしていること。主語は step、節、本文、表のような「もの」で、述語は「〜を持つ」「〜以内」「〜の形とする」「〜と書く」。
- 雛形に書くのは、成果物の形(節の並び、表の列、埋める場所の山かっこ)だけ。文は、山かっこの外にそのまま写す文だけ。
- 雛形の書き方に書くのは、雛形の山かっこをどう埋めるか。主語は埋める人で省略されることが多く、述語は「先に〜を下書きする」「〜から作る」「〜のときは〜を省く」。
- 完成例に書くのは、雛形を埋めてできあがった `SKILL.md` の全文。

規則 2: 使われ方
- 規約は、成果物と並べて見れば合格か違反かが決まる。作る側と照らす側の両方が読む。
- 雛形は、節と表の有無を照らすときに使う。作る側と照らす側の両方が読む。
- 雛形の書き方は、埋めるときに読む。読むのは作る側だけ。
- 完成例は、作る側が手本として、照らす側が合格の側の例として読む。

規則 3: 文書を置くフォルダ
- 規約は、規約のフォルダ(`rules/skill-writing/`)の `skill-or-rule.md`、`structure/`、`writing/`。
- 雛形は `template/skill-template/`。
- 雛形の書き方は `template/skill-template-writing/` に、対になる雛形と同じファイル名で置く。
- 完成例は `template/skill-template-completed-example/`。

規則 4: 規約と雛形の書き方の重なり
- 同じ定めは、規約と雛形の書き方の片方にだけある。雛形の書き方が規約の定めを使うときは、規約の名前で指す(「skill-limits の上限に収める」)。
- 規約の理由は、規約の「理由」の節にだけある。

規則 5: 例

| 文 | 置く文書 |
|---|---|
| 手順の 1 文は、1 つの動作と、その対象、方法、終わりの条件を含む | 規約 |
| `- 手順: <手順>` | 雛形 |
| phase と step の一覧を先に下書きしてから、前提ツールを埋める | 雛形の書き方 |
| summarizing-logs の `SKILL.md` の全文 | 完成例 |

## 理由

規約が「もの」について言う文だけなら、照らす側は成果物と規約を並べて見るだけで判定できる。雛形が形だけなら、埋める側は山かっこを埋めるだけで成果物の形がそろう。雛形の書き方が埋め方だけなら、埋める側はそれを順に実行するだけで書ける。完成例が 1 本の全文なら、手本と合格の例を同じものから読める。
