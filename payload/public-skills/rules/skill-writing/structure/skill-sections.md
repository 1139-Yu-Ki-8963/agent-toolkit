# 必ず持つ節と項目

## 適用する場面

`SKILL.md` を書くとき、または既存の `SKILL.md` を規約と照らすとき。

## 守ること

規則 1: 節の順
- `SKILL.md` は、全体像(目的、開始時の入力、最終出力、流れ)、前提ツール、使用するスクリプト、使用するリファレンス、phase と step の節を、この順に持つ。

規則 2: description
- フロントマターの description は、何をするスキルか、発動する場面、発動しない場面の 3 文とする。

規則 3: 0 件のとき
- 開始時の入力、前提ツール、使用するスクリプト、使用するリファレンスが 0 件のときは、表の代わりに「なし」と書く。

規則 4: 開始時の入力の項目
- 開始時の入力は、項目ごとに、種類(ユーザーの発言、既存のファイル、コマンドの結果)、必須か任意か、受け取り方、読み取れないときの動作(聞き取る、既定の値を使う、AI が案を作る、中止する、のどれかと、それを行う step)を持つ。ユーザーに聞くのは、依頼から読み取れず、機械的にも決まらない項目だけとし、入力を確定する質問は本作業の最初の phase の 1 つの step にまとめる。

規則 5: step の項目
- すべての step は、種別、入力、出力、手順を持つ。分岐の step では条件と 2 つの行き先が、ユーザー確認の step では質問と選択肢の表が、手順に当たる。

規則 6: 種別
- 種別は「固定の手順」か「AI による推論」のどちらかとする。数える、列挙する、形式を検証する、変換する、のように毎回同じ結果になる作業は固定の手順とし、結果の意味づけ、進む道の選択、失敗したときの対処は AI による推論とする。

規則 7: 種別ごとの項目
- 固定の手順の step は、使う機能の名前と渡す値を持つ。AI による推論の step は、判断の観点と合格の基準を持ち、境目が割れやすいときは合格の側と不合格の側の例を 1 つずつ持つ。

## 理由

節と項目が決まっていれば、読む AI は探す場所で迷わず、照らす側は有無を見るだけで判定できる。
