# 前提ツールとサブエージェント

## 適用する場面

スキルが OS に標準で入っていないコマンドを使うとき、またはサブエージェントに作業を委任するとき。

## 守ること

規則 1: 前提ツールの表に挙げるコマンド
- 前提ツールに挙げるのは、step が実行するコマンドのうち OS に標準で入っておらず、かつ使う場面の外にあるもの(コミットの直前に使うスキルの git は、使う場面の中にあるので挙げない)とする。

規則 2: 前提ツールがあるときに先頭に置く phase
- 前提ツールがあるときは、探す、不足を見る、インストールの意思を確認する、インストールする、の 4 step の phase を先頭に置く。

規則 3: サブエージェントに委任できる 3 つの場合
- サブエージェントへの委任は、独立した観点が複数あるとき、多くのファイルを読むがその中身が後で要らないとき、何も知らない実行者に検証させるとき、のどれかに限る。

規則 4: 委任の step が持つ項目
- 委任の step は、当てはまる条件、使うモデル、渡す入力(親が決めたパスの一覧)、返す出力の形、同時に起動する数を持つ。返り値は受け渡し値とし、統合は親が行う。

規則 5: 検証は毎回新しいサブエージェントで行う
- 検証は、実行のたびに新しいサブエージェントで行う。

## 理由

前提ツールの確認を先頭に置けば、本作業を最後まで進められる。委任を限るのは、文脈の分断が判定のぶれを生むためである。
