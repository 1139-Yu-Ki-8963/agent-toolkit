# 雛形: SKILL.md の形

## 適用する場面

`SKILL.md` を新しく書くとき。埋め方は `template/skill-template-writing/skill-template.md` にある。

## 形

```markdown
---
name: <name>
description: <description>
---

# <日本語名>

## 全体像

- 全体の決まり: <全体の決まり>

|---|---|---|---|---|
| <項目> | <種類> | <必須か任意か> | <受け取り方> | <読み取れないときの動作> |

## phase 1 前提ツールの確認

### step 1-1 ツールを探す
- 種別: 固定の手順
- 入力: なし(「前提ツール」の節の表を使う)
- 出力: 受け渡し値「不足しているツールの一覧」
- 表示: 開始の表示と、phase の表示と、前提ツールの表示。方法はチャットへの文の表示。文面は「<スキルの名前> を開始します。<何をするか>。最後に、<最終出力の名前の一覧>を出力します」「phase 1 前提ツールの確認」「<ツールの名前> を探しています」
- 手順: 「前提ツール」の節の表の 1 行ごとに、コマンドの実行の機能で「確認に使うコマンド」を実行する。終了コードが 0 でないツールの名前を、受け渡し値「不足しているツールの一覧」に入れる。表のすべての行を実行したら終わる。表の行は、この phase があるとき常に 1 行以上ある。

### step 1-2(分岐)不足があるかを見る
- 種別: 固定の手順
- 入力: 受け渡し値「不足しているツールの一覧」
- 出力: なし
- 条件: 一覧が 0 件である
- 当てはまる場合: step 2-1 へ
- 当てはまらない場合: step 1-3 へ

### step 1-3(ユーザー確認)インストールの意思を聞く
- 種別: 固定の手順
- 入力: 受け渡し値「不足しているツールの一覧」
- 出力: なし
- 表示: 前提ツールの表示。方法はチャットへの文の表示。文面は「<不足しているツールの名前の一覧> のインストールが必要です」
- 提示の方法: 選択の画面。その機能がない場合は、チャットへの文の表示で番号付きの選択肢を出し、回答を待つ
- 質問の文: 「<不足しているツールの名前の一覧> をインストールしますか」
- 選び方: 1 つだけ選ぶ

| 表示する名前 | 選ぶと何が起こるか | 行き先 |
|---|---|---|
| インストールする(推奨) | 不足しているツールをインストールして、作業を続ける。 | step 1-4 |
| インストールしない | 何も変更せずに、スキルを中止する。 | 中止 |

- 推奨する理由: このツールがないと、phase 2 を実行できないため。
- 選択肢にない回答のとき: 選択肢のどれかを選んでもらえるまで、同じ質問を表示する。
- 中止の表示の文面: 「<不足しているツールの名前の一覧> がないため、step 1-3 で中止しました。インストールしてから、もう一度実行してください」

### step 1-4 インストールする
- 種別: 固定の手順
- 入力: 受け渡し値「不足しているツールの一覧」
- 出力: なし
- 手順: リファレンス `references/インストールの方法.md`(種類: 分岐先の資料)を、ファイルを読む機能で全文読む。リファレンスの「OS の見分け方」に書かれたコマンドを、コマンドの実行の機能で実行して、その結果を作業中の値「実行している OS」にする。作業中の値「実行している OS」が、リファレンスの表にないときは、中止する。中止の表示の文面は「実行している OS が、インストールの方法の表にないため、step 1-4 で中止しました。<不足しているツールの名前の一覧> を自分でインストールしてから、もう一度実行してください」。表にあるときは、受け渡し値「不足しているツールの一覧」の 1 件ごとに、リファレンスの「OS ごとのインストールのコマンド」の表の、その OS の行のコマンドを、コマンドの実行の機能で実行する。一覧は、step 1-2 の分岐により常に 1 件以上ある。すべての件の終了コードが 0 なら step 2-1 へ進む。0 でない件が 1 つでもあれば中止する。中止の表示の文面は「<インストールできなかったツールの名前の一覧> をインストールできなかったため、step 1-4 で中止しました。自分でインストールしてから、もう一度実行してください」。文面の山かっこの値は、入力の受け渡し値「不足しているツールの一覧」から得る。

## phase 2 <本作業の名前>

### step 2-1 <step の名前>
- 種別: <種別>
- 入力: <入力>
- 出力: <出力>
- 表示: phase の表示。方法はチャットへの文の表示。文面は「phase 2 <本作業の名前>」
- 手順: <手順>

### step 2-<n> 読み取れなかった項目を聞き取る
- 種別: AI による推論
- 入力: <読み取りの step の受け渡し値>
- 出力: 受け渡し値「確定した入力」
- 表示: 聞き取り。方法はチャットへの文の表示。質問の文は、AI による推論で作る。「不明」の必須の項目を、1 回の発言にまとめて尋ねる。項目ごとに、答えの候補を 3 つ添え、推奨する候補を先頭に置いて、その候補を推奨する理由を書く。候補は、<候補の元>から作る。パスや ID のように固有の値しか答えようがない項目は、候補を添えず、質問の文だけでよい。形の例: 「次の点を教えてください。(1) <項目の名前>。候補 1(推奨): 〜。理由: 〜。候補 2: 〜。候補 3: 〜」
- 手順: 必須の項目のうち「不明」のものを数える。判断の観点は「不明」の数とし、0 件なら質問をしない。1 件以上なら、「表示」の項目の質問を 1 回だけ行い、回答を待ち、回答で項目を埋める。任意の項目と、読み取れた項目は、質問しない。すべての項目を、受け渡し値「確定した入力」にして終わる。

## phase 3 完了の確認

### step 3-1 最終出力を照らす
- 種別: 固定の手順
- 入力: <最終出力の名前の一覧>
- 出力: 受け渡し値「照合の結果」
- 表示: phase の表示。方法はチャットへの文の表示。文面は「phase 3 完了の確認」
- 手順(最終出力にファイルが 1 つ以上あるスキル): ファイル名の検索で、`<出力先のフォルダ>` のすべての階層のファイルを集める。全体像の「最終出力」の表の 1 行ごとに、集めたファイルがその行に当たるかを照らす(表には完了の報告の行が常にある)。表のどの行にも当たらないファイルが 1 つでもあれば「不合格」とする。表の「0 件でもよいか」が「いいえ」の行に、当たるファイルが 1 つもなければ「不合格」とする。どちらもなければ「合格」とする。結果と、照らしたファイルの数、表の行の数を、受け渡し値「照合の結果」にして終わる。
- 手順(最終出力にファイルが 1 つもないスキル): 全体像の「最終出力」の表の、完了の報告を除く 1 行ごとに、その成果物の表示を、この実行の中でチャットに出したかを照らす。照らす方法は、この実行の中で自分がチャットに出した文を、最初から順に読み返して、その行の名前を見出しに持つ文があるかを見ることとする(自分の出力を読み返す)。照らした行の数と、出した行の数を数える。すべての行を出していれば「合格」を、出していない行があれば「不合格」と、その行の名前を、照らした数と合わせて、受け渡し値「照合の結果」にして終わる。表の行が 0 件のときは「合格」とする。

### step 3-2 完了を報告する
- 種別: 固定の手順
- 入力: 受け渡し値「照合の結果」、<最終出力の名前の一覧>
- 出力: 最終出力「完了の報告」
- 表示: 完了の報告。方法はチャットへの文の表示。文面の型は「<スキルの名前> が完了しました。<最終出力の名前>: <最終出力のパスの一覧>。照合の結果: <照合の結果>」
- 手順: 「表示」の項目の文面の型の山かっこを埋めて、チャットへ表示する。表示したら終わる。
```
