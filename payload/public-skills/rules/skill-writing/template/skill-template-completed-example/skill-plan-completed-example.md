# 完成例: 最も短いスキルの構成の案

## 適用する場面

雛形 `template/skill-template/skill-plan-template.md` を書いてできあがった構成の案の全文。完成例 `skill-completed-example.md`(summarizing-logs の SKILL.md)は、この案から書いたもの。前提ツールなし、本作業の phase 1 つ、最終出力はチャットへの表示だけ。

## 完成例

```markdown
# 構成の案: summarizing-logs

## フロントマターと題名

- name: summarizing-logs
- 日本語名: ログの要約
- description: ログファイルを読み、エラーと警告を抜き出して、要約をチャットに表示する。発動する場面は、ログの調査をするとき。発動しない場面は、ログの継続的な監視、ログファイルの削除や保存、エラーの原因の修正。

## 出力先のフォルダ

~/.claude/skills/summarizing-logs

## 開始時の入力

| 項目 | 種類 | 必須か任意か | 受け取り方 | 読み取れないときの動作 |
|---|---|---|---|---|
| ログファイルのパス | ユーザーの発言 | 必須 | 依頼の文面 | 聞き取る(step 1-2) |

## 最終出力

| 名前 | 種類 | 特定の仕方 | 0 件でもよいか |
|---|---|---|---|
| ログの要約 | チャットへの表示(成果物の表示) | 見出し「ログの要約」と、エラーと警告の件数、代表的な内容 | いいえ |
| 完了の報告 | チャットへの表示(完了の報告) | 最終出力の一覧と、それぞれのパス | いいえ |

## 前提ツール

なし

## phase と step の一覧

| step | パターン | step の種別 | 内容 | 入力 | 出力 | 中止する条件 | 判断の観点 |
|---|---|---|---|---|---|---|---|
| phase 1 ログの要約 | | | | | | | |
| 1-1 | 直列 | AI による推論 | 依頼の文面からログファイルのパスを読み取る | 開始時の入力「ログファイルのパス」 | 受け渡し値「読み取ったパス」 | なし | 区切りの `/` を含むか拡張子を持つ語句が明示されているか。明示されていなければ「不明」 |
| 1-2 | 直列 | AI による推論 | 「不明」なら、パスを 1 回だけ聞き取る | 受け渡し値「読み取ったパス」 | 受け渡し値「確定したパス」 | なし | 「不明」かどうか |
| 1-3 | 直列 | 固定の手順 | ファイルを読む機能で、確定したパスのファイルを全文読む | 受け渡し値「確定したパス」 | 受け渡し値「ログの内容」 | ファイルが存在しない | なし |
| 1-4 | 直列 | AI による推論 | `ERROR` と `WARN` の行を数え、内容ごとにまとめて表示する | 受け渡し値「ログの内容」 | 最終出力「ログの要約」 | なし | 同じ原因の行を 1 つにまとめているか。合格の基準は、抜き出した行の合計と件数の合計が一致すること |
| phase 2 完了の確認 | | | | | | | |
| 2-1 | 直列 | 固定の手順 | 最終出力を照らす | 最終出力「ログの要約」 | 受け渡し値「照合の結果」 | なし | なし |
| 2-2 | 直列 | 固定の手順 | 完了を報告する | 受け渡し値「照合の結果」 | 最終出力「完了の報告」 | なし | なし |

## スクリプト

なし

## リファレンス

なし

## 数の上限との照合(上限は規約 skill-limits)

- phase の数: 2
- 1 つの phase の step の数の最大: 4
- スクリプトの数: 0
- リファレンスの数: 0
- 委任の step の数: 0

## AI が案を作った点

- 発動しない場面の 3 つ(継続的な監視、削除や保存、原因の修正)は、依頼になく、「ログの調査」に近い依頼で誤って発動するおそれがあるものとして AI が選んだ。
- step 1-4 の `ERROR` と `WARN` は、依頼の「エラーと警告」をログの一般的な表記として解釈した。
```
