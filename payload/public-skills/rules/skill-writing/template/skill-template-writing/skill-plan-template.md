# スキルの雛形の書き方: 構成の案

## 適用する場面

雛形 `template/skill-template/skill-plan-template.md` の山かっこを埋めるとき。雛形と同じ名前で対になっている。書くのは埋め方だけで、形は雛形に、成果物が満たすことは規約にある。

## 埋め方

- 埋める順序: 「phase と step の一覧」を先に下書きし、それを見て「前提ツール」「スクリプト」「リファレンス」「数の上限との照合」を埋め、残りを雛形の順に埋める。前提ツールは step が実行するコマンドから決まり、上限の数は一覧から数えるため。
- description は 3 文。何をするスキルか(目的から)、発動する場面(使う場面から)、発動しない場面(目的の近くにあって扱わない作業を 3 つ)。
- 日本語名は、何をするスキルかが分かる体言止めの短い名前。
- 任意の項目が「不明」なら AI が案を作り、「AI が案を作った点」に解釈を書く。案は依頼の目的を満たす最小の設計にとどめ、依頼にないツール、入力、step は、それなしでは最終出力を作れないときだけ足す。
- 種類が「コマンドの結果」の入力は、本作業の step の中でコマンドの実行の機能で読み取って受け渡し値にし、その step の入力に項目の名前を書く。
- 「毎回同じ結果になる作業」は、種別を固定の手順にした step として書く。
- 前提ツールに挙げるのは、step が実行するコマンドのうち OS に標準で入っていないもの(git、jq、gh、node、python3 など)で、使う場面の外にあるもの。ls、grep、cat、wc、test、find と、インストールに使うコマンドと、使う場面の中にあるツール(コミットの直前に使うスキルの git)は、表から外す。1 つもなければ「なし」。
- 一覧の「内容」には、直列以外のパターンの step では、そのパターンが必ず書く項目(分岐の条件と 2 つの行き先、やり直しの戻り先と終了の条件、ユーザー確認の質問と選択肢、委任の条件とモデルと入出力の形と上限)も書く。「中止する条件」はその step で中止する場合をすべて書き、1 つもなければ「なし」。「判断の観点」は AI による推論の step に書き、固定の手順は「なし」。
- 上限を超えるときは、step を減らすか、スクリプトを使わない形にして作り直す。作り直しても収まらないときは、スキルを分ける案を書いてユーザーに見せる。分けても収まらないときは中止する。
