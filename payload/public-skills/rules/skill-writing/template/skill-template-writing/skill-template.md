# スキルの雛形の書き方: SKILL.md

## 適用する場面

雛形 `template/skill-template/skill-template.md` の山かっこを埋めるとき。雛形と同じファイル名で対になっている。書くのは埋め方だけで、形は雛形に、できあがった SKILL.md が満たすことは規約にある。

## 埋め方

- 山かっこの部分を構成の案の内容で埋め、山かっこの外の文はそのまま写す。`<name>` `<description>` `<日本語名>` と各表は、構成の案の同じ名前の項目から写す。全体像の「全体の決まり」は、書くことがあるときだけ残す。フォルダのパスを山かっこに入れるときは、末尾の `/` を除いた形にそろえる(`<出力先のフォルダ>/SKILL.md` のように後ろに `/` を続けるため)。
- 文面の中の `<〜の一覧>` は、読点で区切って並べる。`<最終出力のパスの一覧>` は、最終出力の表の行ごとに「名前: パス」を並べ、パスのない最終出力は「チャットに表示」、0 件の最終出力は「0 件」と書く。
- 前提ツールが「なし」のときは、本作業の phase を phase 1 として番号を振り、phase「前提ツールの確認」の節と「流れ」の表の行は省く。step の番号、行き先、「流れ」の表は繰り上げた番号で書く。このとき、開始の表示は本作業の最初の step の「表示」の項目の先頭に置く。前提ツールがあるときは、インストールの方法を種類「分岐先の資料」のリファレンス `references/インストールの方法.md` に、「OS の見分け方」と OS ごとのコマンドの表の 2 節で書く。
- 本作業の phase と step は、構成の案の「phase と step の一覧」にある数だけ書く。聞き取りの step の型は、必須の入力を依頼から読み取れないことがあるスキルで使い、`<候補の元>` には依頼の語句か、その項目の一般的な値を書く。聞き取りは流れのパターンとは別なので、見出しはかっこなしで書く。
- 各 step の `<手順>` と表示の文面は、一覧の「内容」「中止する条件」「判断の観点」の 3 列から作る。中止する条件と判断の観点は、案にあるものを写す。表示の文面と境目の例は、案になくても足してよい。手順の文の形は規約 skill-step-sentence、step が持つ項目は skill-sections、0 件や多いときの動作は skill-input-output に従う。判断の観点は、終わりの状態が変わるごとに 1 項目に分ける。
- 直列以外のパターンの step は、見出しに「step 2-3(繰り返し)」のようにパターンの名前を書き、規約 skill-flow の規則 2 から 4 が定める項目を足す。
- コマンドを実行する step と、ファイルを読む step の `<手順>` には、失敗したときに中止することと、中止の表示の文面(起きたこと、止まった step、次にすること、残したファイルのパス)を書く(規約 skill-exception-handling の規則 1 から 3)。
- 最終出力をチャットに出す step は、「表示」の項目に種類を「成果物の表示」と書く。
- 完了の確認の step 3-1 は、最終出力の表の「種類」の列に「ファイル」の行があるかどうかで、2 つの手順のどちらか 1 つを写す。ファイルのないスキルでは、step 3-1 の入力を、成果物の表示の名前(例: 最終出力「コミットの文面」)に書き換える。
- 「使用するスクリプト」「使用するリファレンス」が 0 件のときの書き方は規約 skill-sections の規則 3。スクリプトの説明書は「使用するスクリプト」の「説明書のパス」の列にだけ書き、リファレンスの表には入れない。
