# 入出力と表示

## 適用する場面

step の入力と出力、ファイルの読み書き、チャットへの表示を書くとき。

## 守ること

1. step の入力は、開始時の入力、先行する step が出力した受け渡し値、先行する step が作った最終出力の 3 種類とする。出力は、最終出力と受け渡し値の 2 種類とする。受け渡し値は、後続の step の入力になる。
2. 対象の範囲(どのフォルダか、どの種類のファイルか、直下だけか全階層か、除外するもの)を書く。対象が複数件になり得る step は、対象が存在しないとき、結果が 0 件のとき、想定より多いときの動作を持つ。起こり得ないときは、その理由を書く。
3. 完了した時点で、新しく作られたファイルと変更されたファイルは、全体像に列挙した最終出力と完全に一致する。
4. 実行の途中でだけ要るファイル(検証で実行者に書かせる成果物など)は、OS の一時フォルダの中に置き、完了と中止の前に消す。その置き場と消す step を `SKILL.md` に書く。
5. チャットへの表示は、次の 8 種類とし、step に書いた表示を行う。中止するときの表示は、中止の表示だけとする。ユーザーから質問を受けたときの回答は、いつでも行う。

| 種類 | いつ | 必ず含める内容 |
|---|---|---|
| 開始の表示 | 最初の step | スキルの名前、何をするか、最後に何を出力するか |
| phase の表示 | 各 phase の最初 | phase の番号と名前 |
| 前提ツールの表示 | ツールを探すとき、不足が分かったとき | ツールの名前、インストールが必要であること |
| ユーザー確認 | ユーザー確認の step | 質問の文と選択肢 |
| 聞き取り | 自由な回答を求めるとき | 質問の文と、答えの候補 3 つ(推奨を先頭に、理由を添える)。パスや ID のように固有の値しか答えようがない項目は、質問の文だけ |
| 中止の表示 | 中止するとき | 理由、止まった step、次にすること |
| 成果物の表示 | 最終出力をチャットに出すとき | 最終出力の名前と中身 |
| 完了の報告 | 最後の step | 最終出力の一覧とパス(パスがなければ「チャットに表示」、0 件なら「0 件」) |

## 理由

読むもの、書くもの、表示するものが `SKILL.md` に列挙されていれば、実行の結果を列挙と突き合わせるだけで確かめられる。
