# 付属物

## 適用する場面

リファレンス、スクリプト、前提ツール、サブエージェントへの委任を設けるとき。

## 守ること

1. リファレンスは `references/` に置き、1 つの主題だけを扱う。毎回は使わない内容、1 つの step でだけ使う 10 行を超える内容、雛形や例や一覧のように見て使う資料をリファレンスに置き、全体像、入出力の列挙、phase と step、各 step の種別と入出力、スクリプトとリファレンスの一覧は `SKILL.md` に置く。
2. リファレンスは、この実行の開始後に、使う step に到達したときに全文読む。
3. スクリプトは `scripts/` に置き、固定の手順だけを扱う。処理は 1 つ、終了コードは 0 を正常、1 を指摘あり、2 を呼び出しの誤りとする。1 本ごとに、空行とコメント行を除く 1 行ずつの処理と理由を書いた説明書を `references/scripts/` に、テストを `scripts/tests/` に置く。`SKILL.md` に書くスクリプトのパスは、`SKILL.md` があるフォルダからの相対とする。
4. 実行中に使うスクリプトとコマンドは、同梱したものと 1 行のコマンドだけとする。
5. 前提ツールに挙げるのは、step が実行するコマンドのうち OS に標準で入っておらず、かつ使う場面の外にあるもの(コミットの直前に使うスキルの git は、使う場面の中にあるので挙げない)とする。前提ツールがあるときは、探す、不足を見る、インストールの意思を確認する、インストールする、の 4 step の phase を先頭に置く。
6. サブエージェントへの委任は、独立した観点が複数あるとき、多くのファイルを読むがその中身が後で要らないとき、何も知らない実行者に検証させるとき、のどれかに限る。返り値は受け渡し値とし、統合は親が行う。検証は、実行のたびに新しいサブエージェントで行う。

## 理由

リファレンスとスクリプトは `SKILL.md` の外に出した本体であり、置き場と読む時点が決まっていれば `SKILL.md` を短く保てる。委任を限るのは、文脈の分断が判定のぶれを生むためである。
