# 直し方の決まりと書く形

## 指摘の一覧の項目

この章は、対応表である。

| 項目 | 読むファイル | 使う step | 使い道 |
|---|---|---|---|
| number | json | 3-1、3-8 | 番号 |
| weight | json | 3-1 | 並べる順 |
| file | json | 3-2 | 直すファイルのパス。絶対パスでなければ `<プロジェクトのフォルダ>/<file>` |
| line | json | 3-2、3-8 | 行の手がかりと報告のファイル:行 |
| quote と occurrence | json | 3-2 | 直す箇所の特定 |
| rule_viewpoint | json | 3-2 | 直さないと決めた箇所の一覧の規則の観点 |
| fix_before | json | 3-2 | 前の文 |
| fix_after | json | 3-2 | 後の文。decision_needed が true のときは案の配列で、案 <k> は配列の 1 から数えて k 番目 |
| fix_reason | json | 3-2 | 変えたことの理由 |
| decision_needed | json | 3-2 | 決めてもらうことの指摘か |
| 勧める案 | `指摘の一覧.md` の見出し「決めてもらうこと」の「勧める案と理由: 案 <番号>」 | 3-2 | 選んでいないときの案 |

直す対象の json は、項目 number、weight、file、line、quote、occurrence、rule_viewpoint、fix_before、fix_after、fix_reason、decision_needed を持つ要素の配列とする。
項目の名前と意味は、checking-ui-with-rules の references/指摘の一覧の形.md の「指摘の一覧.json の形」と同じとし、このスキルが読まない項目(rule_file、rule_quote、problem、single、画面の指摘の url、width、selector、photo、file_guessed)があってもよい。
`調べ直しの結果.json` は、同じ項目に status(残っているか、新しく出た)を足した配列で、直った指摘を持たない。
checking-ui-with-rules の json は勧める案の項目を持たないので、勧める案は md から読む。

## 直し方の判定の基準

番号の指摘だけを直し、重さが「直す」のものから先に直す。
小さく狙って直し、関係しないコードを書き直さない。
部品の仕組み(ライブラリ)を入れ替えない。
HTML の要素で足りるときは、読み上げのための属性を足さない。
プロジェクトの今の書き方と、色や余白の決まった値に合わせて直す。
見た目のファイルを直すときは、ほかの指定を打ち消さないように、指定の強さ(セレクタの強さと `!important`)を変えない。
決めてもらうことの指摘は、ユーザーが選んだ案で直し、選んでいないときは勧める案で直す。
直し方の案と違う直し方を選んだときは、その理由を書く。
直す箇所は、quote の occurrence 番目の出現で決め、行の番号は手がかりとする。
1 つのファイルに 2 件以上の直しがあるときは、すべての直しを 1 つの全文にまとめる。
前の文がなく後の文があるファイルは、直し済みとして「変更なし」にする。
画面のファイルを新しく作らない。
ルールの文書を直さない。
直したファイルをコミットしない。

## 直さないと決めた箇所の一覧の雛形

この章は、雛形である。

直さないと決めた箇所の一覧のファイルは、「# 直さないと決めた箇所の一覧」の見出しと、列「引用」「規則の観点」「理由」の表(1 件 1 行)を持つ。
引用は、指摘の quote を `|` を `\|` にしてバッククォートで囲んだもの。

```markdown
# 直さないと決めた箇所の一覧

| 引用 | 規則の観点 | 理由 |
|---|---|---|
| `<引用>` | <規則の観点> | <理由> |
```

例の行:

```markdown
| `outline: none;` | フォーカスインジケーターを消さない | 独自のフォーカスの表示を box-shadow で持つため |
```
