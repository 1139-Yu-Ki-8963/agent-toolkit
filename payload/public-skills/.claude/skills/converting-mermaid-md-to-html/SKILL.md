# Mermaid の図を含む md を HTML に変換する

## 全体像

- 目的: Mermaid の図を含む md ファイル 1 本を、図を描画した 1 ページの HTML に変換する。HTML は、上のバー(目次ボタンと題名)と本文だけを持ち、ブラウザで直接開け、表示のときに外部と通信しない。
- 全体の決まり:
  - 使うツールと役割は次のとおり。Mermaid は、md の ` ```mermaid ` のブロックを SVG の図に描画する。Relearn に同梱されており、step 3-2 の取得で揃う。Relearn(9.1.0 で検証)は Hugo のテーマで、Mermaid を呼び出して図を描き、拡大・移動・リセットを付け、目次と見た目も担う。Hugo(extended、0.167.0 で検証)は、md を HTML に変換する。
  - 変換のためにスキルが行うのは、公式のコマンドの実行、検証済みの設定ファイルの配置、md のそのままのコピーの 3 つだけ。このほかに、ツールの有無の確認、入力の確定、出力先の有無の判定、完了の照合を行う。
  - 題名は、ブラウザのタブと上のバーに出る。本文の大見出しは md の最初の H1 がそのまま出る。題名を指定すると、両者は違う文字列になり得る。
  - md と、生成した HTML は、そのまま扱う。スキルの作業は、HTML を出力先に書いた時点で終わる。
  - 開くのは `public/index.html` 1 枚である。同じ `public/` の css、js、fonts を読むので、渡すときは `public/` ごと渡す。

## phase 2 入力の確定

### step 2-1 依頼を読み取る
- step の種別: AI による推論
- 入力: 開始時の入力の 3 項目
- 出力: 受け渡し値「読み取った入力」
- 表示: phase の表示。方法はチャットへの文の表示。文面は「phase 2 入力の確定」
- 手順: 依頼の文面から、md ファイルのパス、題名、出力先のフォルダの 3 項目を読み取る。判断の観点は、文面に明示されているかどうかとする。値は原文の語句のまま写し、明示されていない項目は「不明」とする。値の切り出し方は次のとおり。md ファイルのパスは、`/` か `~` を含み `.md` で終わる語句とする(「md」だけや、`sample.md` のようなファイル名だけは当たらない)。出力先のフォルダは、「出力先は」の後ろにある、`/` か `~` を含む語句とする。題名は、「題名は」か「タイトルは」の後ろから、その文の終わりまでとする。値の終わりは項目ごとに次のとおり。2 つのパスは、空白、句点、依頼の終わりのどれかで終わる。ただし引用符かかぎかっこで囲まれたパスは、囲みの中が値で、空白を含んでよい。題名は、句点か依頼の終わりで終わり、空白を含んでよい。どの項目も、末尾に続く「にして」「で」「に」「を」のような依頼の語は値に含めない。切り出した値は前後の空白を除き、値の全体を囲むかぎかっこか引用符が 1 組あるときは、その 1 組だけを除く。値の中にある引用符は値の一部として残す。例: 「題名は 注文 "フロー" 図」の題名は `注文 "フロー" 図`。3 項目を受け渡し値「読み取った入力」にして終わる。

### step 2-2 読み取れなかった項目を聞き取る
- step の種別: AI による推論
- 入力: 受け渡し値「読み取った入力」
- 出力: 受け渡し値「確定した入力」
- 表示: 聞き取り。方法はチャットへの文の表示。質問の文は「変換する md ファイルのパスを教えてください」とする。パスは固有の値なので、質問の文だけにする。
- 手順: 必須の項目である md ファイルのパスが「不明」かを見る。判断の観点は「不明」かどうかとし、「不明」でなければ質問をしない。「不明」なら、「表示」の項目の質問を 1 回だけ行い、回答を待ち、回答から step 2-1 と同じ切り出し方でパスを取り出して、その項目の値にする。取り出せないときは、回答の全文を値にし、step 2-3 の「読めないときの中止」に任せる。任意の項目(題名、出力先のフォルダ)は質問しない。3 項目を受け渡し値「確定した入力」にして終わる。

### step 2-3 md を読み、題名と出力先を決める
- step の種別: 固定の手順
- 入力: 受け渡し値「確定した入力」
- 出力: 受け渡し値「決まった値」
- 手順: 先に、md ファイルのパスと、出力先のフォルダ(「不明」でなければ)を絶対パスに整える。整え方は、`~` をホームのフォルダに展開し、末尾の `/` を除く。相対パスのときだけ、コマンドの実行の機能で `pwd` を実行し、その結果のフォルダを基準にする。次に、整えた md ファイルのパスのファイルを、ファイルを読む機能で全文読む。ファイルが存在しないか読めないときは中止する。中止の表示の文面は「<md ファイルのパス> を読めないため、step 2-3 で中止しました。パスを直して、もう一度実行してください。残したファイルはありません」。題名が「不明」なら、先頭から順に見て最初に `# ` で始まる行の、`# ` より後ろの文字列を題名にする。このとき、先頭の frontmatter(`---` で囲まれた部分)と、コードブロック(```` ``` ```` で囲まれた部分)の中の行は見ない。その行がなければ md のファイル名から末尾の `.md` を除いたものを題名にする。出力先のフォルダが「不明」なら、`<md のあるフォルダ>/<md のファイル名から末尾の `.md` を除いたもの>-html` を出力先のフォルダにする。md ファイルのパス、題名、出力先のフォルダを受け渡し値「決まった値」にして終わる。

### step 2-4(分岐)出力先のフォルダがすでにあるかを見る
- step の種別: 固定の手順
- 入力: 受け渡し値「決まった値」
- 出力: なし
- 手順: コマンドの実行の機能で `test -e "<出力先のフォルダ>"` を実行する。
- 条件: 終了コードが 0 である(そのパスに、フォルダかファイルが、空かどうかによらず、すでにある)
- 当てはまる場合: 中止する。空のフォルダでも中止する。中止の表示の文面は「<出力先のフォルダ> がすでにあるため、step 2-4 で中止しました。上書きはしません。別の出力先のフォルダを指定するか、そのパスの中身を確かめて要らなければ消してから、もう一度実行してください。残したファイルはありません」
- 当てはまらない場合: step 3-1 へ

## phase 3 HTML の生成

### step 3-1 Hugo の作業フォルダを作る
- step の種別: 固定の手順
- 入力: 受け渡し値「決まった値」
- 出力: 最終出力「変換のフォルダ一式」
- 表示: phase の表示。方法はチャットへの文の表示。文面は「phase 3 HTML の生成」
- 手順: コマンドの実行の機能で `H=$(command -v hugo || echo ~/.local/bin/hugo) && "$H" new site "<出力先のフォルダ>"` を実行する。終了コードが 0 でないときは中止する。中止の表示の文面は「hugo new site が失敗したため、step 3-1 で中止しました。<コマンドの出力の最後の行>。原因を取り除いてから、もう一度実行してください。残したファイル: <出力先のフォルダ>(あれば)」。<コマンドの出力の最後の行> は、この step で実行したコマンドの出力から得る。終了コードが 0 なら終わる。

### step 3-2 Relearn を取得して展開する
- step の種別: 固定の手順
- 入力: 受け渡し値「決まった値」
- 出力: 最終出力「変換のフォルダ一式」
- 手順: コマンドの実行の機能で、次の 1 行を実行する。`set -o pipefail; mkdir -p "<出力先のフォルダ>/themes/hugo-theme-relearn" && curl -fsSL https://github.com/McShelby/hugo-theme-relearn/archive/refs/tags/9.1.0.tar.gz | tar -xzf - -C "<出力先のフォルダ>/themes/hugo-theme-relearn" --strip-components=1 --exclude='*/.claude' --exclude='*/CLAUDE.md'`。終了コードが 0 でないときは中止する。中止の表示の文面は「Relearn の取得か展開が失敗したため、step 3-2 で中止しました。github.com と codeload.github.com に接続できるかを確かめ、<出力先のフォルダ> を消してから、もう一度実行してください。残したファイル: <出力先のフォルダ>」。終了コードが 0 なら終わる。

### step 3-3 設定ファイルを書く
- step の種別: 固定の手順
- 入力: 受け渡し値「決まった値」
- 出力: 最終出力「変換のフォルダ一式」
- 手順: リファレンス `references/サイトの設定一式.md`(種類: 雛形)を、ファイルを読む機能で、先頭から最後の行まで読む。この step に到達したときに、改めて先頭から最後の行まで読む。読めないときは中止する。中止の表示の文面は「リファレンスを読めないため、step 3-3 で中止しました。スキルのフォルダに references/サイトの設定一式.md があるかを確かめてください。残したファイル: <出力先のフォルダ>」。リファレンスの 5 本を、リファレンスの「書き方」に従い、`<出力先のフォルダ>` の中に、次の順で作る。まず、コマンドの実行の機能で `mkdir -p "<出力先のフォルダ>/assets/css" "<出力先のフォルダ>/layouts/partials/topbar/area"` を常に実行する。次に、`hugo.toml` と `assets/css/theme-sekkei.css` の 2 本を、ファイルを書く機能で書く。最後に、残りの 3 本をコマンドの実行の機能で作る。空の 2 本は `: > "<パス>"` で作る。`layouts/partials/topbar/area/start.html` は、2 行目の行頭のタブを確実に残すため、`printf` でリファレンスの 3 行を書く。`hugo.toml` は、ファイルを読む機能で一度読んでから、ファイルを書く機能で書き換える。書けないファイルが 1 つでもあれば中止する。中止の表示の文面は「<書けなかったファイルのパス> を書けないため、step 3-3 で中止しました。<出力先のフォルダ> を消してから、もう一度実行してください。残したファイル: <出力先のフォルダ>」。<書けなかったファイルのパス> は、この step で書こうとしたパスから得る。5 本を書いたら終わる。

### step 3-4 md をコピーする
- step の種別: 固定の手順
- 入力: 受け渡し値「決まった値」
- 出力: 最終出力「変換のフォルダ一式」
- 手順: コマンドの実行の機能で `cp "<md ファイルのパス>" "<出力先のフォルダ>/content/_index.md"` を実行する。終了コードが 0 でないときは中止する。中止の表示の文面は「md のコピーが失敗したため、step 3-4 で中止しました。<コマンドの出力>。原因を取り除き、<出力先のフォルダ> を消してから、もう一度実行してください。残したファイル: <出力先のフォルダ>」。<コマンドの出力> は、この step で実行したコマンドの出力から得る。終了コードが 0 なら終わる。

### step 3-5 HTML を生成する
- step の種別: 固定の手順
- 入力: 受け渡し値「決まった値」
- 出力: 最終出力「HTML」
- 手順: コマンドの実行の機能で `H=$(command -v hugo || echo ~/.local/bin/hugo) && "$H" --source "<出力先のフォルダ>" --cleanDestinationDir` を実行する。出力の `WARN` の行と、出力の表の言語の欄の表示(`EN` と出る)は、中止の理由にしない(`languageCode` の非推奨の警告は毎回出る)。中止するかは、次の 2 つだけで決める。終了コードが 0 でないとき、または `<出力先のフォルダ>/public/index.html` がないときは中止する。`public/index.html` の有無は、コマンドの実行の機能で `test -f "<出力先のフォルダ>/public/index.html"` を実行して見る。中止の表示の文面は「HTML の生成が失敗したため、step 3-5 で中止しました。<コマンドの出力の ERROR の行>。md 側を直し、<出力先のフォルダ> を消してから、もう一度実行してください。残したファイル: <出力先のフォルダ>」。<コマンドの出力の ERROR の行> は、この step で実行したコマンドの出力から得る。ERROR の行がないときは「public/index.html が作られませんでした」とする。どちらでもなければ終わる。

## phase 4 完了の確認

### step 4-1 最終出力を照らす
- step の種別: 固定の手順
- 入力: 受け渡し値「決まった値」、最終出力「変換のフォルダ一式」、最終出力「HTML」
- 出力: 受け渡し値「照合の結果」
- 表示: phase の表示。方法はチャットへの文の表示。文面は「phase 4 完了の確認」
- 手順: 全体像の「最終出力」の表のうち、種類が「ファイル」の 2 行だけを照らす。行ごとに「特定の仕方」に書いたパスを、コマンドの実行の機能で `test -f "<パス>"` を実行して見る。変換のフォルダ一式の行は代表の 3 本、HTML の行は `public/index.html` の 1 本とする。4 本すべての終了コードが 0 なら「合格」、1 本でも 0 でなければ「不合格」と、なかったパスを読点で区切って並べたものを、受け渡し値「照合の結果」にして終わる。

### step 4-2 完了を報告する
