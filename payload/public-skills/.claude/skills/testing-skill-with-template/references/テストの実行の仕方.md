# テストの実行の仕方

## インストールの方法

step 1-5 で、不足している前提ツールをインストールするときに読む。

### OS の見分け方

コマンドを実行するツールで `node -p process.platform` を実行する。出力が `darwin` なら macOS、`linux` なら Linux、`win32` なら Windows とする。実行できないときは、実行している OS が表にないものとする。

### OS ごとのインストールのコマンド

パッケージマネージャだけを使い、一般ユーザーの権限で実行できるコマンドだけを書く。

| OS | ツール | インストールのコマンド |
|---|---|---|
| macOS | node | `brew install node` |
| Linux | node | `brew install node` |
| Windows | node | `winget install OpenJS.NodeJS` |

## 実行者への指示文

step 4-2 で、実行者に渡す指示文を作るときに読む。「指示」のコードブロックの空欄を埋め、その後ろに「サブエージェントが返す書式」のコードブロックを続ける。

指示:

```text
あなたは、これから渡すスキルを初めて読む実行者です。次のとおりにスキルを最後まで実行し、何が起きたかを返してください。

1. 作業フォルダは <実行のフォルダ> です。ファイルを書くのは、このフォルダの中だけにしてください。
2. <写したスキルの SKILL.md のパス> を、ファイルを読むツールで全文読み、そのスキルの手順のとおりに動いてください。
3. 次の文を、ユーザーからの依頼として受けてください。
   <依頼の文>
4. スキルの手順が、ユーザーへの聞き取りかユーザー確認でユーザーに尋ねたときは、次の回答を、尋ねられた順に 1 つずつ、ユーザーの回答として使ってください。回答が足りなくなったら、そこで止まってください。
   <回答の一覧>
5. スキルの手順やテストの値に出る `~` で始まるパスは、`~` を <実行のフォルダ> に読み替えてください。
6. スキルが終わるか、中止するか、回答が足りなくなって止まったら、下の「サブエージェントが返す書式」のとおりに返してください。返すのは、その書式の文だけにしてください。パスのうち、ホームのフォルダの部分は `~` で書いてください。
```

サブエージェントが返す書式:

```text
## 通った step
<通った step の番号を、通った順に読点で区切って並べる>

## チャットへの表示
<スキルがチャットに出した表示の全文を、出した順に並べる。なければ「なし」>

## 書いたファイル
<書いたファイルと作ったフォルダのパスを、1 行に 1 つ並べる。なければ「なし」>

## 中止した step
<中止の表示の step の番号。回答が足りなくて止まったときは「回答が足りない(step <番号>)」。最後まで終わったときは「なし」>
```

## 判定者への指示文

step 5-2 で、判定者に渡す指示文を作るときに読む。「指示」のコードブロックの空欄を埋め、その後ろに「サブエージェントが返す書式」のコードブロックを続ける。

指示:

```text
あなたは、スキルのテストの判定者です。ファイルは読むだけにして、判定してください。

1. 次の一覧の 1 行が、判定するケースと実行の 1 組です。1 行は、ケースの番号、シナリオの番号、回目、期待、出どころ、実行の記録のパス、実行のフォルダのパスを持ちます。
   <判定するケースの一覧>
2. 1 行ごとに、実行の記録と、実行のフォルダの下のファイルを、ファイルを読むツールで読んでください。
3. 期待の文が言う状態が、読んだ中身で成り立つかを決めてください。成り立てば「合格」、成り立たなければ「不合格」とします。期待の言葉の意味が分からないときは、出どころの文を読んで決めてください。
4. 根拠には、期待のどの語を、実行の記録かファイルのどこ(見出しかパスと行)と照らしたかを、1 文で書いてください。
5. 下の「サブエージェントが返す書式」のとおりに返してください。返すのは、その書式の表だけにしてください。
```

サブエージェントが返す書式:

```text
| ケースの番号 | シナリオの番号 | 回目 | 合否 | 根拠 |
|---|---|---|---|---|
| <ケースの番号> | <シナリオの番号> | <回目> | <合格 / 不合格> | <根拠の 1 文> |
```

## 判定の記録の雛形

step 5-4 で、判定の記録.md の中身を作るときに写す雛形。山かっこを値で埋める。

````markdown
# 判定の記録: <テスト対象のスキルの名前>

## 対象

- テスト計画書のパス: <テスト計画書のパス>
- テスト対象のスキルのフォルダ: <テスト対象のスキルのフォルダ>
- 実行日時: <実行日時のフォルダの名前>

## ケースごとの判定

| ケースの番号 | 判定の仕方 | 実施したか | 実行ごとの合否 | 1 回目 | 2 回目 | 合否 | 根拠か未実施の理由 |
|---|---|---|---|---|---|---|---|
| <番号> | <機械的 / AI の推論> | <実施した / 未実施> | <シナリオの番号-回目: 合否 を読点で区切って並べる。未実施なら空ける> | <シナリオの番号-回目: 1 回目の合否 を読点で区切って並べる。機械的なら空ける> | <シナリオの番号-回目: 2 回目の合否 を読点で区切って並べる。機械的なら空ける> | <合格 / 不合格 / 判定できない。未実施なら空ける> | <根拠か未実施の理由> |

## 合計

| 合格 | 不合格 | 判定できない | 未実施 |
|---|---|---|---|
| <数> | <数> | <数> | <数> |

## 実行時の網羅の測定

- 合格のケースを持つ仕様の行: <持つ行の数> / <全行の数>

| 仕様の行 | 合格のケースの番号 | 合格のケースを持つか |
|---|---|---|
| <ID> | <ケースの番号の一覧か「なし」> | <持つ / 持たない> |

## 未実施の実行

| シナリオの番号 | 回目 | 理由 |
|---|---|---|
| <シナリオの番号> | <回目> | <理由> |
````

未実施の実行が 0 件なら、「未実施の実行」の章の表の代わりに「なし」と書く。
