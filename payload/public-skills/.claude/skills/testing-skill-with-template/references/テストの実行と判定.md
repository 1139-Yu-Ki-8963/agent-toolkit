# テストの実行と判定

このリファレンスは、スキル testing-skill-with-template が、実行者と判定者のサブエージェントに渡す指示文、実行の記録から実行結果を取る取り方、テストケースごとの判定の仕方、テスト結果の文書の雛形を、スキルで使う順に 5 つの章で持つ。各 step は、使う章だけを全文読む。

## 実行者の指示文

「サブエージェントへの指示」と「サブエージェントが返す書式」の節を、この順につなげて、対象のスキルを実行するサブエージェントに渡す。「サブエージェントへの指示」の中の空欄 `<対象のスキルの SKILL.md のパス>`、`<対象のスキルのフォルダのパス>`、`<そのシナリオの一時フォルダのパス>`、`<依頼の文>`、`<ユーザーへの聞き取りへの回答>`、`<選ぶ選択肢>`、`<委任の返事>` に、それぞれの値を書き込む。ほかの文はそのまま写す。

空欄の値:

| 空欄 | 値 |
|---|---|
| 対象のスキルの SKILL.md のパス | `<対象のスキルのフォルダ>/SKILL.md` |
| 対象のスキルのフォルダのパス | `<対象のスキルのフォルダ>` |
| そのシナリオの一時フォルダのパス | `<一時フォルダのパス>/<シナリオの番号>` |
| 依頼の文 | いま処理している実行の単位のシナリオの「依頼の文」の `<一時フォルダ>` の語を、そのシナリオの一時フォルダのパスに置き換えたもの |
| ユーザーへの聞き取りへの回答 | 同じシナリオの「ユーザーへの聞き取りへの回答」の `<一時フォルダ>` の語を、同じく置き換えたもの |
| 選ぶ選択肢 | 同じシナリオの「選ぶ選択肢」をそのまま |
| 委任の返事 | 同じシナリオの「委任の返事」が「なし」なら「なし」。あれば、step の番号ごとに、「#### 委任の返事 step <番号>」の見出しの下のコードブロックの中身を「step <番号>: 」に続けた全文(2 件以上は 1 件ずつ改行で区切る) |

### サブエージェントへの指示

```text
あなたは、これから渡すスキルについて何も知らない実行者です。スキルの文に書かれたとおりに実行し、文にないことに出会った点は、下の 3 の決まりのとおり記録してください。

1. 次のファイルを、ファイルを読むツールで全文読んでください。これがあなたが実行するスキルです。
   <対象のスキルの SKILL.md のパス>
   スキルのフォルダは <対象のスキルのフォルダのパス> です。スキルが「SKILL.md があるフォルダ」や「相対パス」と書いているときは、このフォルダを基準にしてください。
2. 次の依頼を受けたものとして、スキルの最初の step から順に実行してください。
   依頼の文: <依頼の文>
   ユーザーへの聞き取りへの回答: <ユーザーへの聞き取りへの回答>
   選ぶ選択肢: <選ぶ選択肢>
   委任の返事: <委任の返事>
3. 次の決まりを守ってください。
   - ファイルを書く先は <そのシナリオの一時フォルダのパス> の下だけです。ほかの場所に書く、消す、上書きする step に来たら、その step で止め、理由を記録してください。
   - ツールのインストールとネットワークへの送信をする step に来たら、その step で止めて理由を記録してください。委任の step では、下の「委任の返事」の step の番号に対応する文を返り値として、返り値の形を確かめる段落から進めてください。「委任の返事」が「なし」か、その step の番号の文がないときは、返り値を「未実行」として、返り値の形を確かめる段落を飛ばして次の step へ進んでください。
   - ユーザーへの聞き取りの step では、尋ねる質問の文を「表示の記録」に記録してから、上の「ユーザーへの聞き取りへの回答」を使ってください。回答がない項目は「分からなかった点」に記録し、その step で止めてください。
   - ユーザー確認の step では、質問の文と選択肢を「表示の記録」に記録してから、上の「選ぶ選択肢」を選んでください。該当する選択肢の指定がなければ「分からなかった点」に記録し、推奨の選択肢を選んでください。
   - スキルがチャットに出す表示は、そのすべてを、出した順に「表示の記録」に記録してください。対象は、スキルのフォルダの references/全スキル共通の決まり.md の「チャットへの表示の書式」の書式から作る表示(作業の開始をユーザーに伝える宣言、中止の表示、ユーザーへの完了の報告)と、step の「#### ユーザーに見せる文面」に書かれた表示(ユーザーへの聞き取り、ユーザー確認、成果物の表示)です。
   - 「チャットへの表示の書式」の書式から作る表示は、書式の山かっこに値を入れて、実際に出した文面をそのまま記録してください。作業の開始をユーザーに伝える宣言はそれを出した step の番号で、中止の表示は中止した step の番号で、ユーザーへの完了の報告は最後の step の番号で記録してください。
   - 文に書いていないことを決めた瞬間(値を補った、順番を変えた、文の意味を解釈した)は、そのすべてを「補った点」に記録してください。
   - スキルの文の意味が分からず進めなかった点は「分からなかった点」に記録してください。
4. 下の「サブエージェントが返す書式」の文だけを返してください。
```

### サブエージェントが返す書式

次の 7 つの見出しを、この順にすべて持つ。該当がない見出しの下は「なし」と書く。

```text
## 行動の記録
| step | 行動 |
|---|---|
| <step の番号> | <何をしたか> |

## 表示の記録
1. <step の番号>: <チャットに出した文面をそのまま>
2. <step の番号>: <チャットに出した文面をそのまま>

## 止めた step と理由
<step の番号と理由。なければ「なし」>

## 分からなかった点
- <step の番号>: <何が分からなかったか>

## 補った点
- <step の番号>: <何をどう補ったか>

## 書いたファイルのパス
- <パス>

## 最後の表示
<スキルが最後にチャットに出した文面をそのまま>
```

## 実行結果の取り方

step 3-7 が、いま処理している実行の単位の実行の記録から実行結果を取る取り方。「ケースの中身」の「期待結果の種類ごとの判定」の表の、そのケースの期待結果の種類と同じ行の「比べる記録」の値ごとに、次の表のとおりに取る。複数行の内容は、1 行ずつ「」で囲んで並べる。

| 比べる記録 | 実行結果の取り方 |
|---|---|
| 行動の記録 | 実行の記録の「行動の記録」の表の step の列を、上から読点でつなぐ。同じ番号が続くときは 1 つにする |
| 止めた step と理由 | 実行の記録の「止めた step と理由」の下の文をそのまま写す |
| 表示の記録 | 実行の記録の「表示の記録」の番号つきの行をすべて写す |
| 最後の表示 | 実行の記録の「最後の表示」の下の文をすべて写す |
| 書いたファイルのパス | 実行の記録の「書いたファイルのパス」の各パスのうち、そのシナリオの一時フォルダのパスで始まるものは、その部分を除いた相対パスにする。それ以外のパスはそのまま並べる |
| 見本のファイルのハッシュ | 「見本の控えの一覧」のそのシナリオの 1 件ごとに、コマンドを実行するツールで `shasum <一時フォルダのパス>/<シナリオの番号>/<見本のファイルの相対パス>` を実行し、得たハッシュが控えのハッシュと同じかどうか(一致 / 不一致)を相対パスごとに並べる。控えが「なし」なら、実行の記録の「書いたファイルのパス」が「なし」のとき「一致」、それ以外のとき「不一致」とする |
| 書いたファイルの中身(「書いたファイルの中身」で始まる値) | そのケースの機能と同じ名前を持つ、「ケースの中身」の最終出力の表の行を取る。出力の種類が「ファイル」なら、実行の記録の「書いたファイルのパス」のうち、その行の見分け方のパス(山かっこの部分を任意の文字列とする)に合う 1 つを、ファイルを読むツールで全文読み、中身を実行結果にする。出力の種類が「フォルダ」なら、実行の記録の「書いたファイルのパス」のうち、その行の見分け方のパスで始まるものの一覧を実行結果にする。出力の種類が「チャットへの表示」なら、実行の記録の「表示の記録」のうち、その行の名前の見出しを持つ記録を実行結果にする。合うパスか記録がないときは「なし」 |

## 判定の仕方

step 3-8 が、テストケースごとに「合格」「不合格」「判定できない」を決める判定の仕方と、ケースの結果の形。「判定の順」の 3 の項は、「ケースの中身」の「期待結果の種類ごとの判定」の表の、そのケースの期待結果の種類と同じ行の「判定の仕方」の列を使う。

### 期待する結果の山かっこの置き換え

比べる前に、そのケースの期待する結果の山かっこのうち、中の語がいまのシナリオの「依頼で渡した出力先」の「<項目の名前> = <相対パス>」の項目の名前と同じものを、その相対パスに置き換える。相対パスが `<一時フォルダ>/` で始まるときは、その部分を除く。「依頼で渡した出力先」が「なし」なら、期待する結果をそのまま使う。置き換えた後の期待する結果を、テスト結果の文書の「期待する結果」の値にする。

### 判定の順

いま処理している実行の単位のケースの 1 件ごとに、次の順に判定を決める。

1. 判定できない。「止めた step と理由」の理由が、「実行者の指示文」の章の決まりの語(「一時フォルダの外」「インストール」「ネットワーク」「回答がない」)のどれかを含み、かつ、実行結果が「なし」であるか、止めた step の番号が期待する結果に現れる step の番号のどれかより前なら、「判定できない」にし、理由に止めた step と理由を写す。期待する結果に step の番号がないケースは、実行結果が「なし」のときだけ「判定できない」にする。それ以外のケース(「止めた step と理由」が「なし」、対象のスキルの手順の「中止する。」の段落で止まった、を含む)は、2 へ進む。
2. 回で決まる判定。観点が「再現性」か「冪等性」のケースは、いま処理している実行の単位の回が 1 なら、そのケースを飛ばして次のケースへ進む。その回のケースの結果の一覧には、飛ばしたケースを除いたケースだけを載せる。回が 2 なら、次の 4 の項に従う。
3. 通常の判定。「判定の仕方」の列の文のとおりに、実行結果を置き換えた後の期待する結果と比べる。満たさない点が 1 つでもあれば「不合格」にし、理由に満たさなかった点を書く。すべて満たせば「合格」にする。置き換えられずに残った山かっこは、その位置に 1 語以上の値が入っていれば一致と見る。期待結果の種類が「表示の記録」「最後の表示」のケースは、期待する結果の行ごとに、対応する行が記録にあるときだけ満たす。期待結果の種類が「見本のファイルの状態」のケースは、実行結果がすべて「一致」のとき「変更なし」を満たす。期待結果の種類が「最終出力の中身」のケースは、期待する結果の「(機械的)」の項目だけを比べ、「(AI の推論)」の項目は step 4-2 の判定者に委ねる。「<件数> 件」の形の項目は、山かっこの位置に数が入った行があるときだけ「行がある」を満たす。
4. 2 回目だけの判定。観点が「再現性」のケースは、「ケースの結果の一覧」にある同じシナリオの 1 回目の実行の記録と、いまの実行の記録の、「行動の記録」の step の列(同じ番号が続くときは 1 つ)と「最後の表示」を比べる。step の列が一致し、最後の表示の山かっこに入る値(パス、step の番号、選択肢の名前、件数)が一致し、さらに、いまの実行結果を 3 の項のとおりに期待する結果と比べて満たすときだけ「合格」、どれかが違えば「不合格」にし、理由に違った点を書く。観点が「冪等性」のケースは、3 の項のとおりに 2 回目の実行結果を比べ、さらに「見本のファイルのハッシュ」の取り方で取った値がすべて一致するときだけ「合格」にする。
5. 期待との差。期待結果の種類が「表示の記録」「最後の表示」のケースと、4 の項の再現性のケースで、山かっこに入る値以外の語句の差は、判定にかかわらず「期待との差」に、期待する結果の語句と実行結果の語句の組で書く。差がなければ「なし」にする。ほかのケースの「期待との差」は「なし」にする。

ケースの結果の 1 件は、実行の単位(シナリオの番号、シナリオの名前、回)、ケースごとの判定の一覧(ID、確かめること、観点、期待結果の種類、判定、置き換えた後の期待する結果、実行結果、期待との差、理由。合格なら理由は「なし」)、実行の記録の全文の 3 つを持つ。

## 判定者の指示文

「サブエージェントへの指示」と「サブエージェントが返す書式」の節を、この順につなげて、最終出力の中身を判定するサブエージェントに渡す。「サブエージェントへの指示」の中の空欄 `<判定の対象の一覧>` に、テストケースと回の組ごとに次の「判定の対象の一覧の形」で書いた塊を、ID と回の順に並べて書き込む。ほかの文はそのまま写す。

判定の対象の一覧の形(テストケースと回の組 1 つにつき 1 つ。「中身」には実行結果の全文を、「項目」にはテストケースの期待結果のはい/いいえの列挙式の項目を、1 行に 1 つずつ番号を付けて書く):

```text
### <ID>(<回> 回目)
#### 中身
<実行結果の全文>
#### 項目
1. <項目の文>
2. <項目の文>
```

### サブエージェントへの指示

```text
あなたは、渡された中身を、渡された項目に照らして判定する判定者です。中身に書かれた行だけを根拠にして、項目ごとに「はい」か「いいえ」を決めてください。

1. 下の「判定の対象の一覧」の「### <ID>(<回> 回目)」の塊ごとに、「#### 中身」の下の文を全文読んでください。
2. その塊の「#### 項目」の 1 つごとに、中身がその項目を満たすかを「はい」か「いいえ」で決めてください。
   「はい」のときは、根拠にした中身の行を 1 行、そのまま引用してください。
   「いいえ」のときは、根拠の行の代わりに「該当する行がない」と書いてください。
3. 下の「サブエージェントが返す書式」の文だけを返してください。

判定の対象の一覧:
<判定の対象の一覧>
```

### サブエージェントが返す書式

「## 判定」の見出しと、その下の 5 列の表を持つ。渡した ID と回と項目の番号の組ごとに 1 行を、渡された順に書く。判定の列は「はい」か「いいえ」のどちらかとする。判定の対象の一覧が「なし」のときは、「## 判定」の見出しと、表の列の名前の行と区切りの行だけを書く。

```text
## 判定
| ID | 回 | 項目の番号 | 判定 | 根拠の行の引用 |
|---|---|---|---|---|
| <ID> | <回> | <項目の番号> | <はい / いいえ> | <中身の 1 行をそのまま。「いいえ」なら「該当する行がない」> |
```

## テスト結果の雛形

テスト結果の文書の雛形の本文と、山かっこの値をどこから取るかの表。ケースは、確かめることと ID で書き、実行の単位(シナリオの番号と回)ごとの塊に置く。

### 雛形の本文

```markdown
# テスト結果: <対象のスキルの名前>

- テストシナリオの文書: <テストシナリオの文書のパス>
- テストケースの文書: <テストケースの文書のパス>
- 実行日時: <実行日時>
- 受け入れ: <可 / 不可>

## 集計

| 判定 | 件数 |
|---|---|
| 合格 | <合格の数> |
| 不合格 | <不合格の数> |
| 判定できない | <判定できないの数> |

- 一時フォルダの外への書き込み: <一時フォルダの外への書き込みの件数> 件
- 期待との差(要件は満たす): <期待との差の件数> 件
- 実行者が補った点: <補った点の件数> 件

## 不合格と判定できないケース

### <シナリオの名前>(シナリオ <シナリオの番号>、<回> 回目)

**<確かめること>(<ID>)**
- 観点: <観点>
- 判定: <不合格 / 判定できない>
- 期待する結果: <期待する結果>
- 実行結果: <実行結果>
- 理由: <理由>

## 合格したケース

### <シナリオの名前>(シナリオ <シナリオの番号>、<回> 回目)

**<確かめること>(<ID>)**
- 観点: <観点>
- 期待との差: <期待との差>

## 実行者の記録

### <シナリオの名前>(シナリオ <シナリオの番号>、<回> 回目)

- 止めた step と理由: <止めた step と理由>
- 分からなかった点: <分からなかった点>
- 補った点: <補った点>
- 返り値の全文: 記録/<シナリオの番号>-<回>.md
- 書いたファイル: 成果物/<シナリオの番号>/
```

### 値の取り方

| 値 | 取る場所 |
|---|---|
| 対象のスキルの名前 | 「シナリオの中身」の対象のスキルの名前 |
| テストシナリオの文書のパス | 「聞き取り後の依頼」のテストシナリオの文書のパス |
| テストケースの文書のパス | 「シナリオの中身」のテストケースの文書のパス |
| 実行日時 | 「実行日時」 |
| 受け入れ | 不合格の数が 0 かつ判定できないの数が 0 なら「可」、それ以外は「不可」 |
| 合格の数、不合格の数、判定できないの数 | 「確定したケースの結果の一覧」のケースを ID ごとにまとめ、ID ごとに 1 件として数える。同じ ID のどれかの回が「不合格」なら不合格、それ以外でどれかの回が「判定できない」なら判定できない、すべての回が「合格」なら合格に数える |
| 一時フォルダの外への書き込みの件数 | 「確定したケースの結果の一覧」の各実行の単位の実行の記録の「書いたファイルのパス」のうち、「一時フォルダのパス」で始まらないパスの数(実行の単位をまたいで同じパスは 1 と数える)。「なし」の 1 行は 0 と数える |
| 期待との差の件数 | 「確定したケースの結果の一覧」のケースのうち、「期待との差」に語句の組がある件の数 |
| 補った点の件数 | 各実行の単位の実行の記録の「補った点」の行の数の合計(「なし」は 0) |
| 不合格と判定できないケースの章 | 「確定したケースの結果の一覧」の実行の単位ごとに、判定が「不合格」か「判定できない」のケースを持つ単位だけ、「### <シナリオの名前>(シナリオ <番号>、<回> 回目)」の見出しと、そのケースごとの塊を、文書に現れる順に置く。塊の 7 つの値は、そのケースの確かめること、ID、観点、判定、置き換えた後の期待する結果、実行結果、理由から写す。該当するケースが 0 件なら、章の見出しの下に「なし」の 1 行だけを置く |
| 合格したケースの章 | 同じ形で、判定が「合格」のケースだけを置く。塊の値は、確かめること、ID、観点、期待との差から写す。該当するケースが 0 件なら、章の見出しの下に「なし」の 1 行だけを置く |
| 実行者の記録の章 | 「確定したケースの結果の一覧」の実行の単位ごとに 1 つ。見出しの値は実行の単位から、止めた step と理由、分からなかった点、補った点は、その単位の実行の記録の同じ見出しの下の文から写す(複数のときは 1 件ずつ「」で囲んで並べる)。返り値の全文と書いたファイルは、シナリオの番号と回を入れた相対パス |
| 複数の値の書き方 | 1 つの行に入れる値が複数行のときは、1 行ずつ「」で囲んで並べる |
