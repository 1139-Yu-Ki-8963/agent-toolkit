# 雛形: テスト結果の文書

テスト結果の文書の形と、山かっこの値をどこから取るかの表。

## 形

```markdown
# テスト結果: <対象のスキルの名前>

- テスト設計の文書: <テスト設計の文書のパス>
- 実行日時: <実行日時>

## 結果の一覧

| ID | シナリオ | 観点 | 判定 | 実行結果 | 期待との差(要件は満たす) | 備考 |
|---|---|---|---|---|---|---|
| <ID> | <シナリオの番号> | <観点> | <合格 / 不合格 / 判定できない> | <実行結果> | <期待との差。なければ空> | <備考。なければ空> |

## 集計

- 受け入れ: <可 / 不可>
- 合格 <合格の数> / 不合格 <不合格の数> / 判定できない <判定できないの数>(全 <テストケースの数> 件)
- 一時フォルダの外への書き込み <一時フォルダの外への書き込みの件数> 件
- 期待との差 <期待との差の件数> 件
- 補った点 <補った点の件数> 件

## 実行者の記録

### シナリオ <シナリオの番号> <シナリオの名前>

- 止めた step と理由: <値。複数のときは 1 件ずつ「」で囲んで並べる>
- 分からなかった点: <値。複数のときは 1 件ずつ「」で囲んで並べる>
- 補った点: <値。複数のときは 1 件ずつ「」で囲んで並べる>
```

## 値の取り方

| 値 | 取る場所 |
|---|---|
| 対象のスキルの名前 | 「設計の中身」の対象のスキルの名前 |
| テスト設計の文書のパス | 「聞き取り後の依頼」のテスト設計の文書のパス |
| 実行日時 | 「実行日時」 |
| 結果の一覧の行 | 「確定したケースの結果の一覧」のテストケースごとに 1 行。シナリオと観点は、「設計の中身」のテストケースの一覧の同じ ID の行から写す |
| 判定 | 「確定したケースの結果の一覧」のそのケースの判定(合格、不合格、判定できないのどれか) |
| 期待との差(要件は満たす) | 「確定したケースの結果の一覧」のそのケースの「期待との差」と、そのシナリオの実行者の記録の「分からなかった点」「補った点」のうち、step の番号がそのケースの期待結果に現れる step の番号のどれかと同じもの。1 件ずつ「」で囲んで並べ、なければ空 |
| 備考 | 「確定したケースの結果の一覧」のそのケースの備考 |
| 受け入れ | 不合格の数が 0 かつ判定できないの数が 0 なら「可」、それ以外は「不可」 |
| 合格の数、不合格の数、判定できないの数、テストケースの数 | 結果の一覧の行の判定を数える |
| 一時フォルダの外への書き込みの件数 | 「確定したケースの結果の一覧」の各シナリオの実行者の記録の「書いたファイルのパス」のうち、「一時フォルダのパス」で始まらないパスの数(シナリオをまたいで同じパスは 1 と数える) |
| 期待との差の件数 | 結果の一覧の行のうち、「期待との差(要件は満たす)」が空でない行の数 |
| 補った点の件数 | 実行者の記録の各シナリオの「補った点」の件の数の合計(「なし」は 0) |
| 実行者の記録の節 | 「設計の中身」のシナリオごとに 1 つ。番号と名前はシナリオの一覧から、3 つの値は「確定したケースの結果の一覧」のそのシナリオの実行者の記録から写す |
