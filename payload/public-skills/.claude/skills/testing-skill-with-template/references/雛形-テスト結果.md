# 雛形: テスト結果の文書

テスト結果の文書の形と、山かっこの値をどこから取るかの表。

## 形

```markdown
# テスト結果: <対象のスキルの名前>

- テスト設計の文書: <テスト設計の文書のパス>
- 実行日時: <実行日時>

## 結果の一覧

| ID | シナリオ | 観点 | 判定 | 実行結果 | 備考 |
|---|---|---|---|---|---|
| <ID> | <シナリオの番号> | <観点> | <合格 / 不合格> | <実行結果> | <備考。なければ空> |

## 集計

- 合格 <合格の数> / 不合格 <不合格の数>(全 <テストケースの数> 件)

## 実行者の記録

### シナリオ <シナリオの番号> <シナリオの名前>

- 止めた step と理由: <値。複数のときは 1 件ずつ「」で囲んで並べる>
- 分からなかった点: <値。複数のときは 1 件ずつ「」で囲んで並べる>
- 補った点: <値。複数のときは 1 件ずつ「」で囲んで並べる>
```

## 値の取り方

| 値 | 取る場所 |
|---|---|
| 対象のスキルの名前 | 「設計の中身」の対象のスキルの名前 |
| テスト設計の文書のパス | 「聞き取り後の依頼」のテスト設計の文書のパス |
| 実行日時 | 「実行日時」 |
| 結果の一覧の行 | 「ケースの結果の一覧」のテストケースごとに 1 行。シナリオと観点は、「設計の中身」のテストケースの一覧の同じ ID の行から写す |
| 合格の数、不合格の数、テストケースの数 | 結果の一覧の行の判定を数える |
| 実行者の記録の節 | 「設計の中身」のシナリオごとに 1 つ。番号と名前はシナリオの一覧から、3 つの値は「ケースの結果の一覧」のそのシナリオの実行者の記録から写す |
