# テストの不合格によるスキルの修正

## 全体像

- 目的: 判定の記録の不合格と判定できないのケースの原因を 5 つの種類に仕分け、対象のスキルの誤りだけを直し、回帰のケースをもう一度テストする依頼の文を出す。テストの実行と判定は running-skill-tests に任せる。
- 全体の決まり: スキルが書き換えるファイルは、対象のスキルのフォルダの下のファイルだけとする。テストの計画、判定の記録、実行の記録、規約、雛形は、読むだけにする。対象のスキルの動きを変えてよいのは、承認を得たスキルの誤りの直しだけとする。判定の記録とテストの計画に書かれたパスが `~` で始まるときは、`~` をホームのフォルダの絶対パスに置き換えて読み、書き、コマンドに渡す。チャットに出す表示のパスは、ホームのフォルダの絶対パスを `~` に置き換えて書く。

## phase 2 入力の確定

- phase の入力: 判定の記録のパス、対象のスキルのフォルダ、判定の記録、テストの計画と対象のスキルのファイル、実行の記録、規約の一式
- phase の出力: 確定した入力、判定の記録の内容、テストの材料、規約の内容
- 合格の条件:
  - 確定した入力の必須の項目が、すべて値を持つ。
  - 判定の記録の内容が、テストの計画のパスと、対象のスキルのフォルダと、1 件以上のケースごとの判定を持つ。
  - テストの材料のテストケースの件数が、テストの計画の「## ケースの数」の章の「- 合計: 」の行の値と一致する。
  - テストの材料が、`<対象のスキルのフォルダ>/SKILL.md` の全文と、判定が「不合格」のケースごとに 1 件以上の実行の記録を持つ。
  - 規約の内容が、規約、雛形、完成例の 3 つの中身を持つ。
  - 作業の開始をユーザーに伝える宣言が、チャットに 1 回表示されている。
  - 中止で終わるときは、中止の表示の step の番号が、2-3、2-4、2-5 のどれかである。

### step 2-2 依頼から読み取れなかった開始時の入力をユーザーに聞く

#### ユーザーに見せる文面

ユーザーへの聞き取り。
「ユーザーのチャット入力にない」必須の項目を、1 回の質問にまとめて尋ねる。
項目ごとに、答えの候補を添え、推奨する候補を先頭に置いて、その候補を推奨する理由を書く。
既にあるファイルのパスや ID のように、答えがユーザーの手元にある固有の値に限られる項目は、質問の文だけにする。
次の文面のうち、尋ねる項目の行を表示する。

```text
running-skill-tests が書いた判定の記録(結果のフォルダの 判定の記録.md)のパスを教えてください。
直す対象のスキルのフォルダを教えてください。
```

#### 手順

必須の項目のうち「ユーザーのチャット入力にない」のものを数える。

0 件なら、「依頼の内容」をそのまま使い、「確定した入力」を作る段落へ進む。

1 件以上なら、「ユーザーに見せる文面」の質問を 1 回だけ行い、回答を待つ。
回答から、尋ねた項目ごとに、step 2-1 と同じ読み取り方で値を取り出し、その項目の値にする。

すべての項目を、「確定した入力」にする。

#### ── step 2-2 の情報 ──

- 種別: 固定の手順
- 入力: 依頼の内容を step 2-1 から受け取る
- 出力: 確定した入力を step 2-3、2-5、5-1、5-2 へ渡す

### step 2-3 判定の記録を読む

#### 手順

「確定した入力」の判定の記録のパスのファイルを、ファイルを読むツールで全文読む。

読めないときは、中止する。
理由: <判定の記録のパス> を読めない。
ユーザーが次にすること: 判定の記録のパスを確かめてから、もう一度実行する。
中止までの成果物: なし

「## ケースごとの判定」の章(見出しの行から、次の「## 」で始まる行の前まで)の「### 」で始まる見出しの行ごとに、見出しの「### 」の後ろの最初の空白までの語をケースの名前とし、その見出しから次の「### 」で始まる行の前までの「- 判定: 」「- 判定の仕方: 」「- 根拠: 」の行の値と、あれば「- 1 回目の判定: 」「- 2 回目の判定: 」の行の値を写す。

<合わなかったものの一覧> は、当たった条件ごとに「テストの計画のパスの行」「対象のスキルのフォルダの行」「ケースの見出し(0 件)」「ケース <ケースの名前> の判定の行」の語句を読点で区切って並べて作る。

理由: <判定の記録のパス> の <合わなかったものの一覧> が形と合わない。
ユーザーが次にすること: running-skill-tests でテストを実行し直して、新しい判定の記録のパスで、もう一度実行する。
中止までの成果物: なし

対象のスキルのフォルダの行の値が、「確定した入力」の対象のスキルのフォルダと一致しないときは、中止する。
理由: 判定の記録の対象のスキルのフォルダ <判定の記録の行の値> が、依頼の <確定した入力の対象のスキルのフォルダ> と違う。
ユーザーが次にすること: 依頼の対象のスキルのフォルダか、判定の記録のパスを確かめてから、もう一度実行する。
中止までの成果物: なし

テストの計画のパスと、対象のスキルのフォルダと、判定の記録があるフォルダ(結果のフォルダ)と、判定の数の行と、ケースごとに写した値を「判定の記録の内容」にして終わる。

### step 2-4 テストの計画と対象のスキルのファイルと実行の記録を読む

#### 手順

### step 2-5 規約の一式が文脈にあるかを見る

#### 手順

自分の文脈の中だけで、規約(「目次」と「守ること」の章)、雛形「スキルの雛形(phase と step)」(「省ける部分」「決まった値の一覧」「この雛形で作るスキルが守ること」「書き方の決まり」「全スキル共通の決まり」「雛形の本文」の章)、完成例の 3 つの中身がすべてあるかを見る。

3 つのうち 1 つでも文脈にないときは、中止する。
理由: 規約の一式(<文脈になかったものの一覧>)が読み込まれていない。
ユーザーが次にすること: 対象のスキルが skills フォルダの直下にあるか、規約の一式の `paths` がその場所に当たるかを確かめてから、もう一度実行する。
中止までの成果物: なし

3 つの中身を「規約の内容」にする。
