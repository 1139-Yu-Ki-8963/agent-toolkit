# テストの不合格によるスキルの修正

## 全体像

- 目的: 判定の記録の不合格と判定できないのケースの原因を 5 つの種類に仕分け、テスト対象のスキルの誤りだけを直し、回帰で流すテストケースの番号と次の依頼の文を出す。
- 全体の決まり: スキルが書き換えるファイルは、テスト対象のスキルのフォルダの下の `SKILL.md` と `references/` の下のファイルだけとする。パスは、判定の記録に書かれたとおりに使い、`~` だけをホームのフォルダの絶対パスに置き換えて読み、書き、コマンドに渡す。

### step 1-5 不足している前提ツールをインストールする

#### 手順

リファレンス `references/テストの不合格の修正の決まり.md` の「インストールの方法」の章(章の種類: 対応表)を、ファイルを読むツールで全文読む。

セッションの環境の情報の Platform の値を、「インストールの方法」の章の「OS の見分け方」の表で OS に対応させ、実行している OS とする。
Platform の値が表にないときと、セッションの環境の情報に Platform がないときは、実行している OS を「表にない OS」とする。

「不足しているツールの一覧」のうち、区分が「前提」の件が 1 件以上あり、実行している OS が「表にない OS」のときは、中止する。
理由: OS を見分けられない。
ユーザーが次にすること: <不足しているツールの名前の一覧> を自分でインストールしてから、もう一度実行する。
中止までの成果物: なし

「不足しているツールの一覧」のうち、区分が「前提」の 1 件ごとに、続く 2 つの段落のうち、当たるほうの段落を行う。

その行がなければ、実行している OS のパッケージマネージャで、そのツールを入れるコマンドを決めて、コマンドを実行するツールで実行する。

理由: <インストールできなかったツールの名前の一覧> をインストールできなかった。
ユーザーが次にすること: 自分でインストールしてから、もう一度実行する。
中止までの成果物: なし

## phase 2 入力の確定

- phase の入力: 判定の記録のパス、テスト対象のスキルのフォルダ、判定の記録、テスト計画書とテスト対象のスキルのファイル、実行の記録、規約の一式
- phase の出力: 判定の記録の内容、テストの材料、直す対象のケースごとの材料、規約の内容
- 合格の条件:
  - 確定した入力の判定の記録のパスが、依頼の文面か回答の語句と一字一句一致する。
  - 判定の記録の内容が、テスト計画書のパスと、テスト対象のスキルのフォルダと、1 行以上のケースごとの判定を持つ。
  - テストの材料が、テストケースの表の行を 1 行以上と、`SKILL.md` の全文と、最初に流すケースの番号を持つ。
  - 直す対象のケースごとの材料の件数が、判定の記録の内容のうち「実施したか」が「実施した」で「合否」が「不合格」か「判定できない」の行の数と一致する。
  - 直す対象のケースごとの材料のすべてのケースが、実行の記録を 1 件以上持つ。
  - 規約の内容が、規約、雛形、完成例の 3 つの中身を持つ。
  - 作業の開始をユーザーに伝える宣言が、チャットに 1 回表示されている。
  - 中止で終わるときは、中止の表示の step の番号が、2-3、2-4、2-5、2-6 のどれかである。

### step 2-2 依頼から読み取れなかった開始時の入力をユーザーに聞く

実行者は、「ユーザーのチャット入力にない」必須の項目を、1 回の質問にまとめて尋ねる。
実行者は、項目ごとに、答えの候補を添え、推奨する候補を先頭に置いて、その候補を推奨する理由を書く。
実行者は、既にあるファイルのパスや ID のように、答えがユーザーの手元にある固有の値に限られる項目を、質問の文だけで尋ねる。
実行者は、次の文面のうち、尋ねる項目の行を表示する。

```text
testing-skill-with-template が書いた判定の記録のパスを教えてください。
```

## phase 3 原因の仕分け

- phase の入力: 判定の記録の内容、直す対象のケースごとの材料、規約の内容
- phase の出力: 仕分けの結果、断ったケースの一覧、直しの記録、戻す直しの一覧、判定が割れた差分(後の 3 つは、step 3-1、3-6、3-7 から step 5-1 へ進むときだけの空の一覧)
- 合格の条件:
  - 仕分けの結果の件数が、直す対象のケースごとの材料の件数と一致する。
  - 仕分けの結果のケースが、すべて 5 つの種類のどれか 1 つを持つ。
  - 仕分けの結果のうち合否が「判定できない」のケースが、すべて「テストの期待の誤り」である。
  - 仕分けの結果のうち「スキルの誤り」のケースが、すべて筋書きを 1 つ持つ。
  - 仕分けの結果の承認の質問が、スキルの誤りが 1 件以上のときに、チャットに 1 回表示されている。
  - 断ったケースの一覧のケースが、すべて「スキルの誤り」のケースである。
  - 中止で終わるときは、中止の表示の step の番号が、3-3、3-7 のどれかである。

「やめる」なら、中止する。
理由: ユーザーが「やめる」を選んだ。
ユーザーが次にすること: 直すときは、もう一度依頼する。
中止までの成果物: なし

### step 4-4 直す前の写しとの差分を取る

#### 手順

### step 4-5 対に当たらない差分を戻す直しにし、戻す直しの判定の指示文を作る
