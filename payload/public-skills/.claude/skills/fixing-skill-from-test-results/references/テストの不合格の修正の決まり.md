# テストの不合格の修正の決まり

## 原因の仕分けの基準

不合格と判定できないのケースの 1 件ごとに、原因を次の 5 つの種類のどれか 1 つに仕分ける。上から順に当てはめ、最初に当たった種類にする。

| 種類 | 当てはまるケース | 直し方 |
|---|---|---|
| 判定の材料の不足 | 判定が「判定できない」で、理由が、実行の記録に判定の材料がないことである | 直さない。テストシナリオの文書の直し先として一覧に出す |
| テストの期待の誤り | 期待する結果が、対象のスキルの今の文(最終出力の表、ユーザーに見せる文面、リファレンスの雛形)と食い違い、スキルの今の文が規約と雛形に合っている | 直さない。テストケースの文書の直し先として一覧に出す |
| 規約か雛形が原因 | スキルが規約と雛形のとおりに書かれていて、そのとおりに動いた結果が期待と違う | 直さない。範囲の外として一覧に出す |
| 実行者の揺れ | 実行の記録で、実行者が手順の文と違う動作をしている。手順の文は 1 つの読み方しかできない | 直さない。もう一度実行して確かめる対象として一覧に出す |
| スキルの誤り | 上の 4 つに当たらない。スキルの手順か文面か表が、期待する結果と違う動作を引き起こしている。手順の文が 2 つ以上に読めて、実行者が補った結果が期待と違う場合も含む | 「直し方の決まり」の章のとおりに直す |

スキルの誤りには、「このケースで、この step の、この文(その step が読むリファレンスの文を含む)が、この動作を引き起こした」という筋書きを 1 つ書く。
筋書きを書けないケースは、スキルの誤りにしない。
迷うときは、スキルの誤りにせず、実行者の揺れにする。

## 直し方の決まり

- 直す場所は、筋書きが指す文(step の文か、その step が読むリファレンスの文)とし、引用した文で探す。
- 1 件の直しは、筋書きが指す文と、その直しで一致が崩れる参照(行き先の番号、流れの表、中間成果物の表、入力と出力の文、その直しで指す先がなくなった文)だけとする。ほかの箇所は、ついでに直さない。
- 直しは、期待する結果を出すのに要る最小の変更とする。期待する結果にない動作は足さない。
- スキルの中で、最終出力の表と、手順かリファレンスが食い違うときは、最終出力の表を正しいとみなし、手順かリファレンスを表に合わせる。
- step の数と番号は変えない。
- 直すと雛形の上限(雛形の規則「上限に収まること」の数)を超えるときは、承認の段で、超える上限と数を示す。承認されたら直す。収めるためにほかの文を削らない。
- 直すと規約か雛形の別の規則に違反するときは、直さずに「規約か雛形が原因」に移す。
- 直すたびに、ファイルのパスと、前の文と後の文の対を記録する。

## 動きの変更の基準

動きとは、次の 7 つである。

1. 実行する動作とツールとコマンド、その順序、それを行う step
2. 分岐、中止、繰り返しの条件と行き先
3. ユーザーに聞くこと、聞く回数、選択肢、候補
4. 作るファイルとフォルダ、その中身と置き場
5. チャットに出す表示の中身
6. step の種別
7. 判断の手がかりになる説明の文(消すと実行する AI の判断が変わる文)

戻す直しの決め方:

- 承認のときに示した変わる動きのほかに、変わった動きがあれば、その直しを戻す。承認のときに示した動きに伴って出る表示(足した中止の段落による中止の表示など)は、承認のときに示した動きに含める。
- 動きが変わるかどうか迷う直しは、変わるとして扱い、戻す。
- 直しの記録の対に当たらない差分は、戻す。

## 修正の結果の表示

見出し「修正の結果」の下に、次の並びで出す。名前が「一覧」で終わる値は、全スキル共通の決まりのとおりに書く。

**修正の結果**
- 直したもの: <直しの記録のうち戻していないものの、ファイルのパスと前の文と、直したケースの ID の一覧>
- 戻したもの: <戻す直しの一覧の、ファイルのパスと戻す理由の一覧>
- テストケースの文書の直し先: <テストの期待の誤りのケースの ID と、食い違う期待の一覧>
- テストシナリオの文書の直し先: <判定の材料の不足のケースの ID と、足りない材料の一覧>
- 範囲の外: <規約か雛形が原因のケースの ID と、原因の規則の一覧>
- もう一度実行して確かめるケース: <実行者の揺れのケースの ID の一覧>
- 保留(ユーザーが断った): <ユーザーが断ったケースの ID の一覧>
- 直す前の文を持つテストの文書の行: <直す前の文を持つテストの文書の行の、ファイルのパスと行の番号の一覧>
- 雛形の上限の見直しの相談: <上限を超える直しを示したときだけ、超えた上限、超えた数、その上限は 2026-09 に決めた経験則で実測の根拠がないこと。示していなければ「なし」>

最後に、次の 3 行を、山かっこを埋めて出す。

```text
次に、testing-skill-with-template に「<テストシナリオの文書のパス> を、出力先 <出力先のフォルダ> でテストして」と依頼してください。
直したケースが合格し、新しい不合格が 0 件なら、修正は終わりです。テストの文書の直し先か、直す前の文を持つテストの文書の行があるときは、先に designing-skill-test-cases か designing-skill-test-scenarios で直してください。
新しい不合格が出たときに、このスキルをもう一度使ってよいのは 2 回までです。3 回目も不合格が残るときは、設計を見直してください。
```
