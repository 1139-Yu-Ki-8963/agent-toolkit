# 雛形: テスト設計の文書の形

テスト設計の文書は、次の節をこの順に持つ。`<>` は設計者が埋める。

## 形

```markdown
# テスト設計: <対象のスキルの名前>

## 対象の説明

<何を受け取り、何をして、何を出すかの 3 文以内の説明>

## 仕様

### 開始時の入力

| 項目 | 種類 | 必須か任意か | 受け取り方 | 読み取れないときの動作 |
|---|---|---|---|---|
| <SKILL.md の表の写し> | | | | |

### 最終出力

| 名前 | 種類 | 特定の仕方 | 0 件でもよいか |
|---|---|---|---|
| <SKILL.md の表の写し> | | | |

### 要件の文

<要件の文。なければ「なし」>

## 機能の一覧

| 番号 | step | 種類 | 引用 | 模擬 |
|---|---|---|---|---|
| <F1> | <step の番号> | <通常 / 分岐 / ユーザー確認 / やり直し / 繰り返し / 委任> | <SKILL.md の文をそのまま写した 1 文> | <模擬 / 空> |

## シナリオ

### シナリオ <S1>

- 通す機能: <機能の番号の一覧>
- 依頼の文: <実行者に渡す 1 つの依頼>
- 聞き取りへの回答: <項目と回答。なければ「なし」>
- 選ぶ選択肢: <step と選択肢の名前。なければ「なし」>
- 見本のファイル: <一時フォルダからの相対パスと中身。なければ「なし」>
- 期待する結果: <仕様の最終出力と要件の文から作った結果。中止の経路なら中止の表示の文面>
- 通る step: <step の番号の並び>

## 経路の網羅の表

| 機能 | 通すシナリオ | 覆えない理由 |
|---|---|---|
| <F1> | <S1、S3> | <空 / 委任の中身 / インストール / 一時フォルダの外への副作用 / ネットワーク> |

- 設計時の網羅率: <覆える機能の数> / <全機能の数>(<百分率>)

## 既知の限界

- 委任の step の中身は実行しないため、見ていない。
- スキルを呼び出して発動したときの挙動(文脈への入り方、フォルダのパスの渡り方)は、実行者がファイルを読む機能で読む方法と異なるため、見ていない。
- 聞き取りとユーザー確認は、あらかじめ決めた回答と選択肢で模擬するため、質問の文の分かりやすさは見ていない。
```
