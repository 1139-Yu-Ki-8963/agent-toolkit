# 設計者の指示文

テスト設計を作るサブエージェントに、そのまま渡す文。`<>` の中は、親が step 2-1 の「渡す入力」で埋める。

## 渡す文

```text
あなたは、これから渡すスキルについて何も知らない設計者です。対象のファイルを変更せず、読むだけでテスト設計の文書を作ってください。

1. 次の対象のファイルを、ファイルを読む機能で 1 つずつ全文読んでください。
   <対象のファイルのパスの一覧(1 行に 1 つ)>
2. 要件の文: <要件の文。なければ「なし」>
3. 下の「雛形」の節と表の形で、文書を作ってください。節の見出しは雛形のとおりに、すべて持たせてください。
   - 対象の説明: 対象の SKILL.md の description と全体像から、何を受け取り、何をして、何を出すかを 3 文以内で書く。
   - 仕様: 全体像の「開始時の入力」と「最終出力」の表をそのまま写し、要件の文を添える。期待する結果はここから作る。
   - 機能の一覧: 機能は「step 1 つの手順が生む結果」と「分かれる点の 1 つの側」とする。step の見出しに「(分岐)」があれば当てはまる側と当てはまらない側で 2 つ、「(ユーザー確認)」があれば選択肢の表の行ごとに 1 つ、「(やり直し)」があれば「やり直す」と「進展がないとき」で 2 つ、「(繰り返し)」と「(委任)」は 1 つ、どれもない step は 1 つ。各行に、番号、step の番号、種類(通常、分岐、ユーザー確認、やり直し、繰り返し、委任)、SKILL.md の文をそのまま写した引用(1 文)、模擬の印(聞き取りとユーザー確認の機能は「模擬」、それ以外は空)を書く。
   - シナリオ: 機能ごとに 1 本以上。1 本に、番号、通す機能の番号、実行者に渡す依頼の文(開始時の入力の必須の項目の値をすべて含む 1 つの依頼。出力先を受け取る項目は一時フォルダの中のパス)、聞き取りへの回答、ユーザー確認で選ぶ選択肢、見本のファイル(パスと中身。踏ませる分かれる点の条件を満たすように逆算する)、期待する結果(仕様の最終出力の表の「特定の仕方」と要件の文から作る。中止の経路なら、その中止の表示の文面)、通る step の番号の並び(手順から作る)を書く。
   - 経路の網羅の表: 機能ごとに、通すシナリオの番号を書く。委任の中身、前提ツールのインストール、一時フォルダの外への書き込みや削除、ネットワークへの送信を要する機能は、シナリオを割り当てずに「覆えない」とし、理由を書く。設計時の網羅率は「覆える機能の数 ÷ 全機能の数」を分数と百分率で書く。
   - 既知の限界: 雛形の 3 項目をそのまま写す。
4. 文書の全文だけを返してください。
```

直したい点があるとき(親が差し戻すとき)は、上の文の末尾に次を添える。

```text
5. 前回の文書に対して、次の直したい点があります。この箇所だけを直して、文書の全文を返してください。
   <直したい点の一覧(1 行に 1 つ)>
```

## 返す出力の形

`references/雛形-テスト設計.md` の「形」の節の見出しをすべて持つ、1 つの文書の全文。
