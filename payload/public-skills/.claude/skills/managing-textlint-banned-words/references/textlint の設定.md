# textlint の設定

このリファレンスは、スキル managing-textlint-banned-words が使う資料を、前提ツールの入れ方、辞書の雛形、設定の雛形、hooks の雛形、一覧の書式の 5 つの章で持つ。各 step は、使う章だけを全文読む。

## インストールの方法

step 1-5 で、不足している前提ツールを入れるときに読む。

### OS の見分け方

```bash
uname -s
```

出力が `Darwin` なら macOS とする。

### OS ごとの入れ方

| OS | ツール | コマンド |
|---|---|---|
| macOS | node | `brew install node` |
| すべての OS | textlint | `npm install -g textlint` |
| すべての OS | textlint-rule-preset-ai-words-ja | `npm install -g textlint-rule-preset-ai-words-ja` |
| すべての OS | textlint-filter-rule-allowlist | `npm install -g textlint-filter-rule-allowlist` |
| すべての OS | textlint-filter-rule-comments | `npm install -g textlint-filter-rule-comments` |
| すべての OS | kuromojin | `npm install -g kuromojin` |

textlint とルール群とフィルタは、同じ場所に入れる。
textlint は、自分と同じ場所に入ったルール群とフィルタだけを読み込む。

node を textlint より先に入れる。
npm は node と一緒に入る。

## 辞書の雛形

step 3-3 で、辞書の案を作るときに読む。

### 責務の分担

語を見分けるロジックは、外部ライブラリ textlint-rule-preset-ai-words-ja が持つ。
このライブラリは、文を kuromoji で形態素に分け、辞書の項目の「tokens」に書いた形態素の条件の並びに当たる箇所を指摘する。
スキルは、使い方と例文から「tokens」の形態素の条件の並びを書くこと、例文で試して期待どおりかを確かめること、ファイルを書いて一覧を表示することだけを行う。

### 項目が持つ欄

辞書は、`entries` の配列を持つ JSON のオブジェクトとする。
配列の 1 要素が 1 項目で、1 つの語の 1 つの止める形を表す。
1 つの語に止める形が 2 つ以上あるときは、項目を分ける。

| 欄 | 中身 | textlint が使うか |
|---|---|---|
| word | 語 | 使わない(一覧の表示に使う) |
| usage | 使い方。どの形のときに止めるかを 1 文で | 使わない(一覧の表示に使う) |
| flagged | 当てる例文の配列。1 件以上 | 使わない(試験と一覧の表示に使う) |
| allowed | 当てない例文の配列。1 件以上 | 使わない(試験と一覧の表示に使う) |
| replacement | 言い換え | 使わない(一覧の表示に使う) |
| message | 指摘のときに出す文。言い換えを肯定の形で書く | 使う |
| tokens | 形態素の条件の並び | 使う |

textlint が使わない欄を足しても、検査の結果は変わらない。

### 辞書の項目の書き方

tokens は、形態素解析で分けた語の並びに、前から順に当てる形態素の条件の並びとする。
1 つの条件は、1 つの形態素に当てる。
並びの長さが文脈の範囲で、前後に条件を足すほど、当たる形が狭くなる。

| 書けるもの | 書き方 | 例 |
|---|---|---|
| 活用前の形 | `basic_form` | `{ "basic_form": "照らす" }` は「照らし」「照らす」「照らさ」に当たる |
| 文中に出るままの形 | `surface_form` | `{ "surface_form": "文" }` |
| 品詞 | `pos`、`pos_detail_1` | `{ "pos": "名詞", "pos_detail_1": "サ変接続" }` は「起動」「検索」に当たる |
| どれか 1 つに一致 | 値を配列にする | `{ "surface_form": ["に", "と", "を"] }` |
| あってもなくてもよい形態素 | `"_skippable": true` を足す | 読点を挟んでも当てたいとき |

使い方と例文から tokens を書く手順は、次のとおりとする。
当てる例文と当てない例文を、次のコマンドで形態素に分ける。
コマンドは、グローバルに入れた kuromojin を `NODE_PATH` で探す。

```bash
NODE_PATH=$(npm root -g) node -e "require('kuromojin').tokenize('<例文>').then(t=>console.log(t.map(x=>[x.surface_form,x.pos,x.pos_detail_1,x.basic_form].join('/')).join(' | ')))"
```

当てる例文のすべてにあり、当てない例文のどれにもない形態素の並びを探し、その並びを条件にする。
当てる例文で語の直前か直後にある形態素が、当てない例文では違う形態素であるとき、その形態素を条件に足す。

見分けられる範囲は、次のとおりとする。
見分けられるのは、品詞、活用、前後の形態素のように、形で決まる違いである。
見分けられないのは、前後の形が同じで、意味だけが違うものである。
例: 比喩の「仕様の穴」と物理の「壁の穴」は、どちらも「名詞 + の + 穴」の並びなので分けられない。
形で分けられない語は、辞書に入れず、文章の書き方の規約に違反の例として足す。

書けない条件は、次の 2 つである。
「後ろが一覧でないとき」のような否定の条件。
1 語にまとまった複合語の一部だけに当てる条件。
否定の条件が要るときは、止める並びを 1 つずつ項目に分けて書く。

### 初期の辞書の全文

辞書が未作成のときは、この全文を起点にする。
3 語は「機能」(ツールを指す使い方)、「照らす」(比べる動作)、「渡す文」である。
すべての例文が期待どおりに分かれることを、textlint 15.8.0 と textlint-rule-preset-ai-words-ja 1.2.1 で確かめてある。

      "allowed": ["新しい機能を追加した。", "機能一覧を作る。"],
      "replacement": "ファイルを読むツール(雛形のツールの呼び方)",
      "message": "ツールは、雛形の呼び方(ファイルを読むツール など)で書く。",

    },
    {
      "word": "機能",
      "usage": "「起動の」のようなサ変名詞と「の」の後に続けて、ツールを指す",
      "flagged": ["サブエージェントの起動の機能がないときは中止する。"],

      "replacement": "指すツールの名前",
      "message": "前に出たツールは、そのツールの名前で書く。",
      "tokens": [{ "surface_form": "その" }, { "basic_form": "機能" }]

      "usage": "「に」「と」「を」の後に続けて、比べる動作を書く",

「照らす」の項目は、「を照らす」も止めるので、「月が夜道を照らす。」のような照明の意味の文も止める。
「最終出力を照らす。」を止めるには「を」が要り、照らす対象の意味は形で分けられないためである。

## 設定の雛形

step 3-4 で、設定の案を作るときに読む。

### .textlintrc.json の全文

`ai-words-dict.json` の語だけで指摘する(`dictionaryMode` を `override` にする)。
短い主題の直後の読点の規則は切る。
フィルタは、行頭が「参考:」「例:」などの行と、`<!-- textlint-disable -->` から `<!-- textlint-enable -->` までの範囲を検査から外す。

```json
{
  "filters": {
    "comments": true,
    "allowlist": {
      "allow": ["/^(参考|題名|出典|引用|例|図[0-9]*|表[0-9]*|キャプション|注|注釈|備考|補足)[:：].*$/m"]
    }
  },
  "rules": {
    "preset-ai-words-ja": {
      "no-ai-words": { "dictionaryPath": "./ai-words-dict.json", "dictionaryMode": "override" },
      "no-short-topic-comma": false
    }
  }
}
```

`dictionaryPath` の相対パスは、設定のファイルがあるフォルダから解決される。

## hooks の雛形

step 3-1 で登録済みかを見るときと、step 3-4 で hooks の案を作るときに読む。

### hooks の項目の全文

settings.json の `hooks.PostToolUse` の配列に、次の項目を 1 つ足す。
山かっこには、設定のフォルダの絶対パスを入れる。

```json
{
  "matcher": "Write|Edit",
  "hooks": [
    {
      "type": "command",
      "command": "f=$(jq -r '.tool_input.file_path // empty'); case \"$f\" in *.md) textlint --config <設定のフォルダ>/.textlintrc.json \"$f\" >&2 || exit 2;; esac"
    }
  ]
}
```

### hooks の項目の動き

ファイルを書くツール(matcher の Write と Edit)が動いたあとに、書いたファイルのパスを受け取る。

パスが `.md` で終わるときだけ textlint で検査する。

指摘があると textlint は終了コード 1 を返し、この項目は指摘の文を標準エラーに出して終了コード 2 を返す。
終了コード 2 の標準エラーは、Claude に指摘として渡る。

この項目は、Claude Code を起動した環境の PATH から textlint を探し、書いたファイルのパスを jq で取り出す。
jq は macOS 15 以降に標準で入っている。

### 登録済みかの見分け方

`hooks.PostToolUse` のどれかの `command` が `<設定のフォルダ>/.textlintrc.json` を含めば、登録済みとする。

## 一覧の書式

step 4-2 で辞書を一覧で表示するときに読む。

### 登録内容を示すとき

見出しの行のあとに、表を 1 つ出す。

```text
禁止語の一覧(<語の数> 語、<項目の数> 項目)
```

| 語 | 止める形 | 当てる例文 | 当てない例文 | 言い換え |
|---|---|---|---|---|
| <word> | <usage> | <flagged を「 / 」で区切って並べる> | <allowed を「 / 」で区切って並べる> | <replacement> |

表の 1 行は、辞書の 1 項目とする。
同じ語の項目は、辞書の並びのまま続けて置く。
語の数は、word の重なりを除いた数とする。
辞書の項目が 0 件なら、表の代わりに「登録された語はありません。」と出す。

### 例

```text
禁止語の一覧(1 語、1 項目)
```

| 語 | 止める形 | 当てる例文 | 当てない例文 | 言い換え |
|---|---|---|---|---|
| 渡す文 | サブエージェントへの指示を「渡す文」と呼ぶ | そのまま渡す文を作る。 | サブエージェントに渡す引数を書く。 / サブエージェントへの指示を書く。 | サブエージェントへの指示 |
