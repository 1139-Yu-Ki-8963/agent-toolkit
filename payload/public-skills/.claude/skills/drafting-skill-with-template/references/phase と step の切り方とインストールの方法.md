# phase と step の切り方とインストールの方法

## phase と step の切り方

この章は、判定の基準である。

phase を切る目安:
- 1 つの phase の step は、すべてその phase の出力を作るための動作である。別々の終わりの状態へ向かう step の並びが 2 つ以上あるときは、その境目で phase を分ける。
- phase 1 は、固定の phase である。前提ツールがあるスキルの phase 1 は「全スキル共通の決まりの読み込みと前提ツールの準備」で、step 1-1 から 1-5 を持つ。前提ツールがないスキルの phase 1 は「全スキル共通の決まりの読み込み」で、step 1-1 だけを持つ。
- 最後の phase は、固定の phase「最終出力の確認とユーザーへの完了の報告」で、2 つの step を持つ。
- phase 2 は、step「依頼を読み取る」から、作業の開始をユーザーに伝える宣言を出す step までを持つとき、名前を「入力の確定」とする。
- phase の入力は、開始時の入力か、前の phase の出力から選ぶ。phase の出力は、後の phase が使う受け渡す値と、最終出力である。

step を切る目安:
- step を分ける境目は、2 種類だけである。1 つ目は、スキルの外に手を出す動作(ファイルを書く、ファイルを消す、ユーザーの回答を待つ、サブエージェントに任せる)の前後。2 つ目は、流れ(分岐、繰り返し、やり直し、ユーザー確認)の前後。
- 値を読んで決める動作は、1 つの step に収まる。
- ファイルを書く step の手順は、書く中身の名前と、ファイルを書くツールの呼び出しと、書けないときの中止の段落だけを持つ。
- ファイルの形(出力するファイルの中身の雛形)と、2 つ以上の step で使う文面は、リファレンスの章に出す。コマンドの組み立ては、スクリプトに出す。step の手順は、その章かスクリプトを指す。
- 1 つの step は、1 つの種別(固定の手順か AI による推論)と、1 つの流れのパターンを持つ。出力を持つ AI による推論の step は、決める結果の名前を持つ。
- step の中の中止は、その step の動作が失敗したときだけである。行き先の片方が中止だけの判定は、その動作の失敗の中止として同じ step に置く。
- 元に戻せない操作(インストール、上書き、削除)を行う step の前には、ユーザー確認の step を置く。

流れのパターンごとに step が持つ項目:

| パターン | 持つ項目 |
|---|---|
| 直列 | 動作と、次の step |
| 分岐 | 条件と、行き先 |
| 繰り返し | 範囲(この step か、同じ phase の中の続いた step)と、終了の条件 |
| やり直し | 戻り先(同じ phase の中の前の step か、前の phase の最初の step)と、やり直す条件と、終了の条件(達成すべき状態)と、進展がないときの動作と、進展がないときの質問と選択肢 |
| ユーザー確認 | 1 文の質問と、選択肢の表と、推奨する理由と、選択肢にない回答のときの動きと、回答ごとの行き先(後の step、同じ phase の中の前の step、中止のどれか)と中止の値と、選べる選択肢の数 |
| 委任 | 委任できる条件と、使うモデルと、同時に起動するサブエージェントの数と、委任の指示文の空欄と、サブエージェントが返す書式 |

## インストールの方法

### OS の見分け方

実行者は、セッションの環境の情報の Platform の値を、次の表で OS に対応させる。

| Platform の値 | OS |
|---|---|
| `darwin` | macOS |
| `linux` | Linux(WSL を含む) |
| `win32` | Windows |

### OS ごとのインストールのコマンド

次の表のコマンドは、パッケージマネージャのコマンドで、一般ユーザーの権限で実行できる。

| OS | ツール | インストールのコマンド | 先に書くファイル |
|---|---|---|---|
| macOS | node | `brew install node` | なし |
| Linux | node | `brew install node` | なし |
| Windows | node | `winget install OpenJS.NodeJS.LTS` | なし |
