# スキルの雛形(phase と step)

## 適用する場面

スキルのフォルダの `SKILL.md` と `references/全スキル共通の決まり.md` を新しく書くときと、既存の `SKILL.md` をこの雛形と比べるとき。

山かっこは、書き手が埋める欄と、実行のたびに変わる値の両方を表す。

## 省ける部分

【】で囲んだ行は、その下の部分を入れる条件を示す。条件に当たるときだけ、その下の部分を `SKILL.md` に写す。

| 条件の行 | 省いたときにすること |
|---|---|
| 全体の決まりがあるときだけ | 全体像の「全体の決まり」の行を省く |
| 1 行もなければ「なし」 | 表の代わりに「なし」と書く |
| 前提ツールがあるときだけ | step 1-2 から 1-5 を省く。流れの表の phase 1 を「1-1」だけにする。phase 1 の名前を、流れの表と見出しの両方で「全スキル共通の決まりの読み込み」にする |
| 分岐があるときだけ、繰り返しがあるときだけ、やり直しがあるときだけ、ユーザー確認があるときだけ、委任があるときだけ | その step を省く。繰り返しは、範囲の 2 つの step も省く |
| 繰り返す範囲がこの step のときだけ、別の step のときだけ | 繰り返しの step で、当たらない側の部分を省く。範囲がこの step のときは、範囲の 2 つの step も省く |
| 結果の一覧があるときだけ、ないときだけ | 繰り返しの step で、当たらない側の行を省く |
| ユーザーへの聞き取りがあるときだけ | step を省く。入れるときは、step「依頼を読み取る」の直後 |
| 候補を実行のたびに作る項目があるときだけ、ないときだけ | 聞き取りの step で、当たらない側の部分を省く。候補を実行のたびに作る項目とは、開始時の入力の項目のうち、答えの候補を依頼の文面や既存のファイルから作り、質問の文を AI による推論で作るもの。入力の値から決まった式で作る候補だけを持ち、質問の文を決まった文面にする項目は、ないときだけの側に入れ、その候補を文面の中に山かっこの値で書く |
| 候補をツールで集める項目があるときだけ | 聞き取りの step で、推奨する理由の行と、候補が 0 件のときの行と、候補を集める段落を省く |
| 候補が 2 つ以上ある項目があるときだけ | 聞き取りの step の形の例で、「候補 2: 〜。」の行を省く |
| この step が、作業の開始をユーザーに伝える宣言を出す step のときだけ | 宣言を出す段落を省く |
| 先へ進む選択肢で値を作るときだけ | ユーザー確認の step で、値を作って先へ進む段落を省く |
| 前の step へ戻る選択肢があるときだけ | ユーザー確認の step で、前の step へ戻る段落を省く |
| 中止する返り値の形があるときだけ、ないときだけ | 委任の step で、当たらない側の行を省く |
| 委任の step が委任の指示文だけを受け取るときだけ、ほかの入力も受け取るときだけ | 委任の step で、当たらない側の入力の行を省く |
| step「依頼を読み取る」で既定の値を入れるか案を作る項目があるときだけ | step「依頼を読み取る」で、既定の値を入れるか案を作る段落を省く。この項目とは、開始時の入力の表の「読み取れないときの動作」が、step「依頼を読み取る」の番号を添えた「既定の値を使う」か「AI が案を作る」の項目 |
| 読み取った値から作る値があるときだけ、ないときだけ | step「依頼を読み取る」と聞き取りの step で、当たらない側の部分を省く |
| 最終出力の確認の step が最終出力だけを受け取るときだけ、確定した入力も受け取るときだけ | step <最後の phase の番号>-1 で、当たらない側の入力の行を省く |

## 決まった値の一覧

| 項目 | 値 |
|---|---|
| 開始時の入力の種類 | ユーザーのチャット入力、既存のファイル、コマンドの結果 |
| 読み取れないときの動作 | 聞き取る、既定の値を使う、AI が案を作る、中止する(それを行う step を「(step <番号>)」の形で添え、step が 2 つ以上なら読点で区切る。既定の値を使うは「既定の値を使う(値: <値>、step <番号>)」の形) |
| 出力の種類 | ファイル、フォルダ、チャットへの表示(下の表の種類を括弧で添える) |
| 選択肢にない回答のときの動き | 同じ質問をもう一度表示する、回答を直したい点にして step <番号> へ戻る |
| 使うモデル | 親と同じモデル、軽いモデル(読んで一覧にするだけの委任のとき) |
| step の種別 | 固定の手順、AI による推論 |
| 流れのパターン | 直列、分岐、繰り返し、やり直し、ユーザー確認、委任 |
| リファレンスの章の種類 | 雛形、判定の基準、完成例、対応表、委任の指示文、スクリプトの説明書(使用するリファレンスの表の `references/全スキル共通の決まり.md` の行は、「章の種類」の列に、ファイルの種類「全スキル共通の決まり」を書く) |
| スクリプトの終了コード | 0 正常、1 指摘あり、2 呼び出しの誤り |
| 置き場 | 全スキル共通の決まり `references/全スキル共通の決まり.md`、リファレンス `references/<主題の名前>.md`(インストールの方法とスクリプトの説明書は、このファイルの章)、スクリプト `scripts/`、テスト `scripts/tests/` |

チャットへの表示の種類:

| 種類 | いつ | 必ず含める内容 |
|---|---|---|
| 作業の開始をユーザーに伝える宣言 | 全スキル共通の決まりの「チャットへの表示の書式」のとおり | 目的、確定した入力の値、最終出力とその場所 |
| ユーザー確認 | ユーザー確認の step | 質問の文と選択肢 |
| ユーザーへの聞き取り | 自由な回答を求めるとき | 質問の文と、答えの候補(推奨を先頭に、理由を添える)。既にあるファイルのパスや ID のように、答えがユーザーの手元にある固有の値に限られる項目は、質問の文だけ |
| 中止の表示 | 中止するとき | 起きたこと、止まった step、ユーザーが次にすること、中止までの成果物のパス |
| 成果物の表示 | 最終出力をチャットに出すとき | 最終出力の名前と中身 |
| ユーザーへの完了の報告 | 最終出力の確認とユーザーへの完了の報告の phase の最後の step | 完了したことと、ファイルとフォルダの最終出力のパス |

## この雛形で作るスキルが守ること

この雛形で書いた `SKILL.md` とリファレンスが守ること。規約 skill-writing-rule の規則「「この雛形で作るスキルが守ること」の章が持つ形」に従い、節と「規則 <番号>: <観点>」で書く。

### 表で決まる値

この雛形の「決まった値の一覧」の章が決める値を使うとき。

規則 1: 決まった値の一覧で決まる値
- 判定の仕方: 機械的
- この雛形の「決まった値の一覧」の章の表にある値は、`SKILL.md` とリファレンスの中で、表のとおりにする。

### 数の上限

数を数えるとき、数を上限と比べるとき。

規則 1: 数の数え方
- 判定の仕方: 機械的
- 上限と同じ数は、上限に収まる側とする。手順の文字数は、すべての「#### 手順」の見出しの下の行(次の見出しまで)の、行の中の文字の数を足した数とする。本作業の phase の数は、phase 2 から最後の phase の 1 つ前までを数える。step の数の上限は、固定の phase にも当てはめる。スクリプトの行数は空行とコメント行を除いて数える。リファレンスの章の数と行数は、`references/全スキル共通の決まり.md` を除き、章の種類が「スクリプトの説明書」以外の章で数える。

規則 2: 上限に収まること
- 判定の仕方: 機械的
- `SKILL.md`、リファレンス、スクリプトは、次の表の上限に収まる。上限と同じ数は、上限に収まる側とする。

| 対象 | 上限 | 数え方 |
|---|---|---|
| 本作業の phase | 3 つまで | phase 2 から最後の phase の 1 つ前までを数える |
| 1 つの phase の step | 8 つまで | 固定の phase にも当てはめる |
| リファレンスの章 | 5 つまで | `references/全スキル共通の決まり.md` を除き、章の種類が「スクリプトの説明書」以外の章を数える |
| リファレンスの 1 つの章の行 | 200 行まで | リファレンスの章と同じ章で数える |
| スクリプト | 3 本まで | なし |
| スクリプト 1 本の行 | 50 行まで | 空行とコメント行を除いて数える |
| スクリプトの引数 | 3 つまで | なし |
| 委任 | 1 つの phase に 1 つまで、1 つのスキルに 3 つまで | なし |
| 同時に起動するサブエージェント | 委任の step に書いた数まで | なし |
| ユーザー確認の選択肢 | 2 つから 4 つ | なし |

### description と step の中身

`SKILL.md` を書くとき、または既存の `SKILL.md` をこの雛形と比べるとき。

規則 1: SKILL.md の description に書くこと
- 判定の仕方: AI の推論
- `SKILL.md` の description は、何をするスキルか(全体像の「目的」の語句から)と、発動する場面(依頼の文の語句から)を持つ。発動しない場面は、近い依頼で誤って発動するおそれがあるときだけ、その依頼を持つ。

規則 2: 手順に当たるもの
- 判定の仕方: 機械的
- その step を実行するのに要る動作と行き先が、手順に当たる。分岐の条件と 2 つの行き先、繰り返しの範囲と終了の条件、やり直しの戻り先と終了の条件と進展がないときの動作、ユーザー確認の回答ごとの行き先も、手順に当たる。
- 「#### 手順」は手順だけを持つ。step の種別、入力と出力、判断の観点、合格の基準は「#### ── step <番号> の情報 ──」にある。

規則 3: step の種別の決め方と、種別ごとに step が持つ項目
- 判定の仕方: AI の推論
- step の種別は「固定の手順」か「AI による推論」のどちらかとする。数える、列挙する、形式を検証する、変換する、のように毎回同じ結果になる作業は固定の手順とし、結果の意味づけ、進む道の選択、失敗したときの対処は AI による推論とする。
- 固定の手順の step は、「#### 手順」に、使うツールの呼び方と、そのツールで扱う値(パスやコマンド)を持つ。AI による推論の step は、「#### ── step <番号> の情報 ──」に、判断の観点と合格の基準を持つ。
- すべての step は、「#### ── step <番号> の情報 ──」に、種別、入力、出力を持つ。

規則 4: 1 つの step が持つ作業
- 判定の仕方: AI の推論
- 1 つの step は、1 つの作業だけを持つ。作業とは、1 つの種別(固定の手順か AI による推論)で、1 つの流れのパターン(直列、分岐、繰り返し、やり直し、ユーザー確認、委任)に当たる、ひとまとまりの動作をいう。
- 読む、作る、渡す、待つ、のように性質の違う動作は、別の step にある。

規則 5: 開始時の入力を確定する質問は、本作業の最初の phase の 1 つの step にまとまっている
- 判定の仕方: AI の推論
- 開始時の入力の項目を尋ねる質問は、すべて、本作業の最初の phase の step「依頼から読み取れなかった開始時の入力をユーザーに聞く」にある。

### phase

スキルの流れを phase に分けるとき。

規則 1: phase の番号
- 判定の仕方: 機械的
- phase の番号は、1 から始まる整数。
- 合格の例: phase 1。違反の例: phase 0、phase 1.5。

規則 2: 先頭と最後に置く固定の phase
- 判定の仕方: 機械的
- 前提ツールが 1 つ以上あるスキルは、phase 1 を「全スキル共通の決まりの読み込みと前提ツールの準備」とし、step 1-1 で全スキル共通の決まりを読み、step 1-2 から 1-5 で前提ツールを確かめる。
- 前提ツールがないスキルは、phase 1 を「全スキル共通の決まりの読み込み」とし、phase 1 に step 1-1 だけを持つ。
- phase 1 の step は、この雛形の「雛形の本文」の phase 1 の文と一致する。
- この雛形で書くスキルは、最後の phase を「最終出力の確認とユーザーへの完了の報告」とし、その step は、この雛形の「雛形の本文」の同じ名前の phase の文と一致する。

規則 3: 本作業の phase の分け方
- 判定の仕方: AI の推論
- 本作業は、終わりの状態が変わるところで phase が分かれる。1 つの phase は、1 つ以上の step を持つ。

### 流れ

step の並びと、分岐、繰り返し、やり直し、ユーザー確認、中止、委任を書くとき。

規則 1: 流れのパターン
- 判定の仕方: 機械的
- 分岐、繰り返し、やり直し、ユーザー確認、委任の step は、どのパターンかを、見出しの末尾に角括弧で書いたパターンの名前で示す。1 つの step に 2 つのパターンが重なるときは、主たるほうを示す。

規則 2: 分岐、繰り返しの step が持つ項目
- 判定の仕方: 機械的
- 分岐の step は、この雛形の「雛形の本文」の [分岐] の step にある項目を持つ。分岐は 2 方向まで、深さは 1 とする。上限を超えて分かれるときは、分岐の step が直列に並ぶ。
- 繰り返しの step は、この雛形の「雛形の本文」の [繰り返し] の step にある項目を持つ。範囲は「この step」か、「step 2-2 から 2-3」のように同じ phase の中の続いた step。範囲が複数の step のときは、範囲の中の step は「いま処理している<1 件の名前>」を繰り返しの step から受け取る。繰り返しの深さは 1 とする。

規則 3: やり直しの step が持つ項目
- 判定の仕方: 機械的
- やり直しの step は、この雛形の「雛形の本文」の [やり直し] の step にある項目(戻り先、やり直す条件、終了の条件、進展がないときの動作、進展がないときの質問と選択肢)を持つ。
- 戻り先は、その step より前の step とする。戻り先の step は、戻ってきたときだけ使う入力(レビューの指摘など)を入力に持ち、手順に「戻ったときは〜だけを直す」を持つ。
- 終了の条件は、達成すべき状態で書かれている。
- 進展がないとき(同じ問題が 2 回続けて残る、または問題の数が 2 回続けて減らない)は、残っている問題と原因を表示し、方法を変えて続けるか中止するかをユーザー確認で選ばせる。

規則 4: ユーザー確認の step が持つ項目
- 判定の仕方: 機械的
- ユーザー確認の step は、この雛形の「雛形の本文」の [ユーザー確認] の step にある項目(1 文の質問、選択肢の表、推奨する理由、選択肢にない回答のときの動き、回答ごとの行き先と中止の値、選べる選択肢の数)を持つ。
- 選択肢の行き先は、後の step、前の step、中止のどれか。推奨があれば先頭にあり、理由がある。

規則 5: 元に戻せない操作の前に置くもの
- 判定の仕方: 機械的
- 元に戻せない操作(インストール、上書き、削除)を行う step の前には、ユーザー確認の step がある。規約 skill-writing-rule の規則「スキルが消すファイルとフォルダ」が求める一時フォルダの削除は除く。

規則 6: step の中に置く中止と、分かれる処理の書き方
- 判定の仕方: 機械的
- step の中にある中止は、その step の作業が失敗したときだけとし、条件と中止の値がその step にある。作業の結果を確かめて、合わなければ中止する処理も、その作業の失敗として同じ step にある。確かめることそのものが 1 つの作業(判断する、ファイルを探す、など)のときは、それが独立した step になっていて、合わなければその step で中止する。
- ユーザー確認と、行き先が 2 つの step に分かれる処理は、それぞれ独立した [ユーザー確認] と [分岐] の step になっている。行き先の片方が中止だけのときは、この規則の 1 つ目の箇条書きにある、作業が失敗したときの中止になっている。
- 繰り返しの中で 1 件ごとに処理が分かれるときは、繰り返しの step の手順に、分かれる条件とそれぞれの処理がある。繰り返しの範囲の中の step は、直列か委任の step とする。

規則 7: 委任の step
- 判定の仕方: AI の推論
- step がサブエージェントに委任できるのは、次の 4 つのどれかに当たるときだけ。独立した観点が複数あり、別々に見るほうがよいとき。多くのファイルを読むが、その中身は後の step で要らないとき。そのスキルを初めて読む実行者に検証させるとき。前の step までに作った成果物を、それを作った文脈と別の文脈で判定させるとき。
- 委任の step は、この雛形の「雛形の本文」の [委任] の step にある項目(委任の指示文の空欄、サブエージェントが返す書式、委任できる条件、使うモデル、同時に起動するサブエージェントの数)を持つ。サブエージェントの返り値は中間成果物になり、返り値をまとめる作業は、委任の step の次の step が行う。

### 番号の並び

phase と step の番号を並べるとき。

規則 1: 番号は空きなく並び、参照と一致する
- 判定の仕方: 機械的
- phase は 1 から、各 phase の step は 1 から空きなく並ぶ。この雛形の省ける部分を省いた場合も同じ。流れの表、行き先、中止の文面の中の番号は、見出しの番号と一致する。

### step の文

step の見出し、手順、ユーザーに見せる文面を書くとき。

規則 1: step の番号の書き方
- 判定の仕方: 機械的
- step の番号は、1 から始まる整数。「step 2-1」の形(phase の番号、ハイフン、step の番号)で呼ぶ。
- 合格の例: step 2-1。違反の例: step 2-0、step 2.1、step 2-1-1。

規則 2: step の見出しと項目の並び
- 判定の仕方: 機械的
- step は、この雛形の「雛形の本文」のとおりの見出しと項目を、同じ順に持つ。

規則 3: 手順とユーザーに見せる文面が満たすこと
- 判定の仕方: AI の推論
- 手順と、ユーザーに見せる文面の 1 つの段落は、1 つの動作だけを持つ。
- 手順の 1 文は、1 つの動作と、その動作の対象、方法、終わりの条件を含む。
- 中止の段落は、「理由」「ユーザーが次にすること」「中止までの成果物」の 3 つの値を持つ。

規則 4: 対象と方法を添えたときだけ使える語
- 判定の仕方: AI の推論
- 「確認する」「調査する」「整理する」「適切に」「必要に応じて」「など」は、何を、どうやって、が同じ文にあるときだけ使える。

規則 5: 実行のたびに変わる値の書き方
- 判定の仕方: 機械的
- 文面や手順の中で、実行のたびに変わる値は、`<ツールの名前>` のように山かっこで書かれている。
- 山かっこの値は、その step の入力のどれから来るかがたどれる。複数になり得る値は、件数と区切り方を持つ。

規則 6: ツールの呼び方
- 判定の仕方: 機械的
- ツールは、全スキル共通の決まりの「ツールの呼び方」の表にある、何をするツールかを表す呼び方だけで書かれている。
- 実行する環境にそのツールがないときは、同じ表の「ないときの動作」をとる。

### step の入力と出力

step の入力と出力を書くとき。

規則 1: step の入力と出力になるもの
- 判定の仕方: 機械的
- step の入力になるのは、次の 3 つのどれか。開始時の入力。前の step から受け取る中間成果物。前の step が書いた最終出力。
- step の出力になるのは、次の 2 つのどれか。後の step へ渡す中間成果物。最終出力(全体像の最終出力の表の行のうち、この step が書くか表示するもの)。
- 「#### ── step <番号> の情報 ──」の入力と出力の文に含まれる名前と step の番号は、中間成果物の表の「名前」「出す step」「使う step」と、最終出力の表の「名前」と一致する。

規則 2: 対象の件数が実行のたびに変わる step が書くこと
- 判定の仕方: AI の推論
- ファイルを探す、件数を数える、見つかったものを 1 件ずつ処理する、のように対象の件数が実行のたびに変わる step は、対象の範囲を持つ。範囲とは、どのフォルダか、どの種類のファイルか、直下だけか全階層か、何を除くか。
- その step は、上限があるときだけ、その上限と、超えたときの動きを持つ。0 件が起こり得るときは、0 件のときの動きを持つ。前の step が 0 件のときに中止するので 0 件が起こり得ないときは、その中止をする step の番号を持つ。

### step の中止

step の途中で、手順に書いていないことが起きたときの動きを書くとき。

規則 1: 想定外が起こり得る step が手順に書くこと
- 判定の仕方: AI の推論
- コマンドを実行する step と、ファイルを読む step は、失敗したときに中止することを手順に持つ。中止の段落の値は規則「手順とユーザーに見せる文面が満たすこと」のとおり。リファレンスを読めないときの中止は、全スキル共通の決まりに従う。

## 書き方の決まり

- ユーザーに見せる文面と手順は、それぞれ見出し「#### ユーザーに見せる文面」「#### 手順」の下に、段落で書く。1 つの段落は 1 つの動作で、段落の間は空行にする。段落の中は 1 文ごとに改行する。段落は地の文で書く。
- 「── step <番号> の情報 ──」の「判断の観点」は、観点を読点で区切った 1 文、「合格の基準」は、数か有無で判定できる 1 文で書く。観点が 3 つを超えるときは、リファレンスの「判定の基準」の章に出し、「── step <番号> の情報 ──」にはその章の名前を書く。step「依頼から読み取れなかった開始時の入力をユーザーに聞く」の判断の観点と合格の基準は、完成例 `skill-template-completed-example/skill-completed-example.md` の同じ step の文をそのまま写す。
- 「── step <番号> の情報 ──」の「入力」の値は、何を、どの step から受け取るかを 1 文で書く(例: 「依頼の中のログファイルのパスを step 2-1 から受け取る」)。「出力」の値は、何を、どの step へ渡すかを 1 文で書き、最終出力なら、何を書くか、何をチャットに表示するかを書く(例: 「確定した依頼を step 2-3 と 2-4 へ渡す」「ログの要約をチャットに表示する」)。文の中の名前は、中間成果物の表と最終出力の表の「名前」をそのまま使う。入力か出力がないときは「なし」と書く。
- どの step でも使う決まり(ツールの呼び方、チャットへの表示の書式、中止の決まり)と、最終出力の確認とユーザーへの完了の報告の手順は、`references/全スキル共通の決まり.md` に置く。中身は下の「全スキル共通の決まり」の章を一字一句そのまま写す。`SKILL.md` は step 1-1 でこれを読み、各 step から呼び出す。
- 中止は、手順の段落に「〜ときは、中止する。」と書き、続く 3 行に「理由: 」「ユーザーが次にすること: 」「中止までの成果物: 」の値を、1 行に 1 つずつ書く。中止の表示は、全スキル共通の決まりの「チャットへの表示の書式」から作る。
- スキルごとに中身が違う文面(ユーザーへの聞き取りの質問、ユーザー確認の質問、成果物の表示)は、その step の「#### ユーザーに見せる文面」に、`text` のコードブロックで 1 文 1 行で書く。出力するファイルの中身の雛形、10 行を超える文面、2 つ以上の step で使う文面は、リファレンスの章に出す。
- スキルが作るフォルダは、最終出力の表の 1 行とし、出力の種類を「フォルダ」、見分け方をそのパスにする。そのフォルダの下に書くファイルの行の見分け方は、フォルダの行のパスから始める。既にあるファイルと同じフォルダに書くときは、フォルダの行の見分け方のパスの後ろに「(既にあるファイルと並べて書く)」と書く。
- 山かっこの値は、段落の先頭に「<値> は、〜から得る。」の 1 文で定義する。同じ段落の動作の結果から名前で分かる値は、この 1 文を省く。
- 山かっこを埋める語句(step の名前、中間成果物と最終出力の名前、判断の観点)は、次の順に確かめて書く。語句の中心の動詞を決め、その動詞が要る「誰が」「何を」「誰に」「いつ」を語句に含める。語が、実際に起きることをそのまま言っているかを見る。物の名前が「〜した〜」の形なら、それが何かと、いつの、どの範囲のものかで呼び直す。同じ分類を文と表の 2 か所に書いていたら、1 か所にする。合否の基準は規約 text-writing-rule(文章の書き方の規約)にある。

## 全スキル共通の決まり

各スキルの `references/全スキル共通の決まり.md` に、次の全文を一字一句そのまま写す。

````markdown
# 全スキル共通の決まり

このスキルのどの step でも使う決まり。step 1-1 で全文読む。

## 1. ツールの呼び方

| 呼び方 | ないときの動作 |
|---|---|
| ファイルを読むツール | 中止する |
| ファイルを書くツール | 中止する |
| ファイルを名前で探すツール | コマンドを実行するツールで代わりに探す |
| ファイルの中身を検索するツール | コマンドを実行するツールで代わりに探す |
| コマンドを実行するツール | 中止する |
| 選択肢を提示するツール | チャットに番号付きの選択肢を出し、回答を待つ |
| サブエージェントを起動するツール | 委任の step の「委任できる条件」が「そのスキルを初めて読む実行者に検証させるとき」か「前の step までに作った成果物を、それを作った文脈と別の文脈で判定させるとき」なら中止する。それ以外は自分で順に行う |

## 2. チャットへの表示の書式

作業の開始をユーザーに伝える宣言、中止の表示、ユーザーへの完了の報告の 3 つは、次の形の Markdown のまま出す。1 行目は太字の見出し、2 行目以降は「- <名前>: <値>」の箇条書き。

作業の開始をユーザーに伝える宣言。開始時の入力の表の「読み取れないときの動作」に書かれた step のうち、番号が最も後ろの step の最後に 1 回出す。
入力の行は開始時の入力の項目ごとに、成果物の行は最終出力の表の、ユーザーへの完了の報告を除く行ごとに 1 行ずつ出す。

**次の内容で始めます**
- 目的: <SKILL.md の目的の 1 文目>
- <入力の項目>: <値>
- 成果物: <最終出力の名前>(<パス。チャットへの表示なら「チャットに表示」>)

中止の表示。手順の「中止する。」の段落で出す。
値は、その段落の「理由」「ユーザーが次にすること」「中止までの成果物」の行から取る。

**step <番号> で中止しました**
- 理由: <理由>
- ユーザーが次にすること: <ユーザーが次にすること>
- 中止までの成果物: <パスの一覧。なければ「なし」>

ユーザーへの完了の報告。最終出力の確認とユーザーへの完了の報告の phase の最後の step で出す。
2 行目以降は、最終出力の表の、出力の種類が「ファイル」と「フォルダ」の行ごとに 1 行ずつ出す。その行がなければ 1 行目だけを出す。

**<SKILL.md の題名の日本語名> が完了しました**
- <ファイルかフォルダの最終出力の名前>: <パスの一覧>

ユーザーに見せる文面の山かっこのうち、名前が「一覧」で終わる値は 0 件以上で、読点で区切って書き、0 件のときは「なし」と書く。
一覧は全件を扱う。上限を持つ step は、その手順に、上限と、超えたときの動きを持つ。

## 3. 中止の決まり

手順にないことが起きたら、その場で中止する。
一時フォルダの中間成果物を消してから、中止の表示を出す。
中止の表示を出したら止まる。

リファレンスを読めないときは、中止する。
理由: <パス> を読めない。
ユーザーが次にすること: スキルのフォルダに <パス> があるかを確かめ、なければスキルを入れ直してから、もう一度実行する。
中止までの成果物: それまでに書いた最終出力のファイル。なければ「なし」。

## 4. 最終出力の確認とユーザーへの完了の報告

最終出力の確認とユーザーへの完了の報告の phase の最初の step で使う。

最終出力にファイルかフォルダがあるとき:
最終出力の表の、出力の種類が「ファイル」と「フォルダ」の行ごとに、見分け方のパスがあるかを、ファイルを名前で探すツールで確かめる。
「フォルダ」の行は、その直下のファイルが表の行に当たるかも確かめる。
フォルダの行の見分け方に直下のファイル名が書かれているときは、そのファイルを表にあるファイルとして扱う。
次の 2 つのどちらかに当たるときは、中止する。
- 「0 件でもよいか」が「いいえ」の行に当たるものがない。
- 「フォルダ」の直下に、表にないファイルがある(見分け方に「(既にあるファイルと並べて書く)」とあるフォルダは除く)。
理由: 最終出力が最終出力の表と合わない(<合わなかったパスか行の名前の一覧>)。
ユーザーが次にすること: 最終出力のパスとフォルダの中身を確かめてから、もう一度実行する。
中止までの成果物: <表の行に当たるファイルとフォルダのパスの一覧>

最終出力がチャットへの表示だけのとき:
最終出力の表の、ユーザーへの完了の報告を除く各行について、その名前の見出しを持つ表示を出したかを、自分の出力を読み返して調べる。
出していない行があれば、中止する。
理由: 最終出力の表示を出していない(<出していない行の名前の一覧>)。
ユーザーが次にすること: もう一度実行する。
中止までの成果物: なし
````
