## 列ごとの規約とスキル

この章は、列の順とその理由と、検査の列ごとの、丸が示すこと、突き合わせる規約、突き合わせるスキル、直すスキルを持つ。スキルの表と規約の表の検査の列の名前は、規約との照合の列では突き合わせる規約の名前とし、ピンクの象の除去とシナリオテストの列では検査の名前とする。「丸を付けるときに使うか」の列は、丸を付ける条件がそのスキルの出力で決まるかを示す。

スキルの表と規約の表の検査の列は、左から、作者が検査を通す順に並ぶ。「丸を消す条件」の章のとおり、どの検査の直しでも、その行のファイルを変えると、変えたコミットより前の hash の丸は空になる。このため、作者は、スキルと規約の書き方を決める規約の列(skill-writing-rule と rule-writing-rule)を検査の列の左端に置き、その直しで変わった文を見る text-writing-rule とピンクの象の除去の列をその右に置き、スキルの表では、通すのに最も手間がかかるシナリオテストの列を右端に置いた。text-writing-rule とピンクの象の除去の 2 列は、どちらも文の言い回しを直す検査で、2 列の間の順は決めていない。作者が左から通すと、シナリオテストを、ほかの検査の直しが終わったあとに通せる。

## 値の書き方

- 丸の値は、`○ <検査した日付> <その行のファイルを最後に変えた作業用リポジトリのコミットの短い hash>`、`対象外`、空の 3 つのどれかです。
- 「最後に変えたコミット」の値は、スキルの行では `git log -1 --format=%h -- skills/<スキルの名前>` の出力、規約の行では `git log -1 --format=%h -- <規約のファイルのパス>` の出力です。検査の丸を書くときと、publishing-skills-to-public-repo が写す前に、書き換えます。

## 丸を消す条件

publishing-skills-to-public-repo は、写す前に、丸の hash より後にその行のファイル(スキルの行は `skills/<スキルの名前>/`、規約の行は規約のファイル)を変えたコミットがあるかを列ごとに確かめ、あればその丸を空にし、「最後に変えたコミット」を今の値に書き換える。コミットしていない変更がスキルのフォルダか規約のファイルにあるときは、publishing を中止する。
