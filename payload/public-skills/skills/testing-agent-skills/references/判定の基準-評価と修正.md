# 判定の基準(評価と修正)

実行者の報告を評価するときと、対象のスキルを直すときの、判断の観点と基準。

## 評価の基準

| 項目 | 決め方 |
|---|---|
| 成否 | 必須の要件が、すべて ○ のときだけ成功とする。1 個でも × または部分なら、失敗とする。 |
| 達成率 | ○ を 1、部分を 0.5、× を 0 として合計し、要件の数で割る。百分率で書く。 |
| 新しい不明瞭な点 | 実行者の報告の「不明瞭な点」のうち、受け渡し値「評価の結果」の前の回に、同じ事象がないもの。 |
| 残っている不明瞭な点 | 実行者の報告の「不明瞭な点」のうち、前の回にも同じ事象があるもの。 |
| 独自の判断で補った点 | 実行者の報告から、そのまま写す。スキルに書かれていない前提を示すものとして扱う。 |
| 不明瞭な点の区分 | 1 件ごとに、「結果を変える点」か「結果を変えない点」かを、親が決める。実行者の申告では決めない。 |

- 失敗のときは、どの必須の要件が落ちたのかを、1 行で書く。
- 重視するのは、達成率の数値ではなく、不明瞭な点と、独自の判断で補った点とする。
- 実行者の成果物(検証の出力のフォルダの中のファイル)を、ファイルを読む機能で読み、実行者が付けた ○、×、部分が、成果物と合っているかを照らす。合っていない要件は、親が付け直して、その理由を書く。

## 不明瞭な点の区分

- 結果を変える点: 次のどれかに当たるもの。(1) 実行者によって、要件の達成(○、×、部分)か、成果物のファイルの内容が変わった、または変わり得る。進む step や経路の違いで、同じ成果物と同じ要件の達成に至るものは、結果を変えない点とする。(2) 要件を落とした、または落とし得る。(3) 対象のスキル、その雛形、その規程が、規程の規則に違反している。(4) 指示された作業を、実行者が行わなかった、または行わなくても誰にも分からない。
- 結果を変えない点: 上のどれにも当たらないもの。文面の好み、説明の追加の要望、実行者が迷ったが、どの実行者も同じ結論に達した点。
- 区分の根拠は、複数の実行者の成果物と報告が食い違ったかどうか、および成果物を読んで確かめた事実とする。迷うときは、結果を変える点とする。
- 終了の条件に数えるのは、結果を変える点だけとする。結果を変えない点も、記録して直すが、終了の条件には数えない。

## 不明瞭な点の書き方

1 件ごとに、次の 3 行で書く。

- 事象: 何が起きたか。対象のスキルのどの step のどの文か。
- 原因: 指示のどこが、なぜ不明瞭だったか。
- 一般的なルール: 同じ種類の失敗を防ぐために、指示の書き方をどう変えるべきか。その場かぎりの直しではなく、同じ種類の失敗すべてに当てはまる形で書く。

## 直し方の決まり

1. 1 回に直すのは、1 つの失敗の型に属する不明瞭な点とし、同じ型のものはまとめて直す。直すときは、実行者が挙げた箇所だけでなく、対象のスキルのすべてのファイルから、同じ型に当たるほかの箇所を探して、一緒に直す。結果を変える点が複数の型にまたがるときは、結果を変える点のある型を、すべて 1 回で直してよい。ただし、1 回目の実行で見つかった不明瞭な点は、すべての型を 1 回でまとめて直してから、2 回目の実行に進む。初回は数が多く、型ごとに実行をやり直すと、終わるまでの実行の回数が多くなりすぎるためである。2 回目からは、残った点と新しく出た点を、型ごとに直す。
2. 主題は、次の順で選ぶ。必須の要件を落とした原因、残っている不明瞭な点、新しい不明瞭な点、説明と本文のずれ、独自の判断で補った点。
3. 直す前に、その直しが、どの要件、または評価の結果のどの不明瞭な点を解消するためのものかを書く。要件とも、評価の結果の不明瞭な点とも結び付かない直しは、行わない。要件がすべて ○ でも、不明瞭な点が残っていれば直す。
4. 直しは、不明瞭な点を解消する最小限の量とする。関係のない文を書き換えない。
5. 前の回に同じ型の不明瞭な点があった場合は、前の直しで防げなかった理由を先に決め、前と違う直し方を選ぶ。
6. シナリオと要件を、直しに合わせて変えてはならない。
7. 直した後の対象のスキルが、スキル運用規程の数の上限(`SKILL.md` の本文は 200 行以内、1 つのリファレンスは 200 行以内)を超えないこと。超える場合は、直しを行わず、残っている不明瞭な点として扱う。
8. 直しで、判定に使う語(「案にない」「一致」「読み直す」のような語)を足すときは、その語について「何の単位で見るか」と「何と何を比べるか」を、同じ文の中に書く。単位と比較の相手を書かずに足した語は、次の回に新しい穴になる。

## 失敗の型のまとめ方

- 不明瞭な点の「一般的なルール」が同じものを、1 つの型としてまとめる。
- 型ごとに、名前、代表的な事象、一般的なルールを、評価の結果の「直した内容」に書く。
