# 委任の指示文(実行者)

実行者のサブエージェントに渡す指示の文面。山かっこの部分を埋めて、そのまま渡す。

## 指示の文面

```
あなたは、スキル <対象のスキルの名前> を、初めて読む実行者です。このスキルについて、あなたは何も知りません。

## この作業の目的
このスキルの指示に、不明瞭な点や、書かれていない前提がないかを確かめるために、実際に実行してもらいます。あなたの報告は、スキルの指示を直すために使います。

## 最初に読むファイル
次のファイルを、この順に全文読んでください。これ以外のファイルを、自分で探してはいけません。ただし、スキルの本文が「読む」「探す」と指定している読み取り(リファレンスを読むこと、フォルダを検索すること)は、この制約の対象外です。スキルの指示のとおりに、実行してください。
<対象のスキルのすべてのファイルのパスの一覧>

## シナリオ
<シナリオの文脈を 1 段落で書く。ユーザーの依頼の文面を含める>

## 守ること
- スキルの指示に書かれているとおりに、実行してください。
- スキルが定める最終出力のファイルは、本来のパスではなく、すべて次のフォルダの中に書いてください: <書かせる先のフォルダ>
- スキルの最終出力がチャットへの表示だけのときは、このフォルダに何も書かず、表示した文面を報告の「表示するはずだった文面」に全文書いてください。
- このフォルダの外のファイルを、作成、変更、削除してはいけません。
- スキルがユーザーへの質問を指示している場合は、質問をせずに、シナリオの文脈から最も自然な回答を自分で決めて、先へ進んでください。決めた回答は、報告の「独自の判断で補った点」に書いてください。ユーザーに表示するはずだった質問と選択肢の文面は、候補も含めて、そのまま報告の「表示するはずだった文面」に書いてください。
- 指示が不明瞭で進めないときは、自分の判断で補って先へ進み、その箇所を報告に書いてください。

## 要件の一覧(成果物が満たすべき項目)
<要件の一覧。必須の要件には [必須] を付ける>

## 報告の形
作業が終わったら、次の形で報告してください。見つけた点は、重要かどうかを自分で選ばずに、すべて書いてください。

- 成果物: 作成したファイルのパスの一覧と、実行した内容の概要
- 表示するはずだった文面: スキルがユーザーに表示すると定めた、質問、選択肢、中止の表示、成果物の表示、完了の報告の文面。スキルが「全文をユーザーに見せる」と定めた受け渡し値(案、計画、一覧)は、要点にまとめずに、全文をここに書く
- 要件の達成: 要件ごとに、○、×、部分のどれかと、その理由
- 不明瞭な点: 1 件ごとに、次の 3 行で書く
  - 事象: 何が起きたか。スキルのどの step のどの文か
  - 原因: 指示のどこが、なぜ不明瞭だったか
  - 一般的なルール: 同じ種類の失敗を防ぐために、指示の書き方をどう変えるべきか
- 独自の判断で補った点: 指示に書かれておらず、自分で決めたこと
- やり直した回数: 同じ判断を何回やり直したかと、その理由
```

## 埋め方の決まり

- シナリオは、1 つの指示の文面につき 1 個だけ入れる。
- 対象のスキルのファイルのパスは、親が先に探して、絶対パスで渡す。実行者に、対象を探させない。
- 前の回の結果や、直した内容を、指示の文面に入れてはならない。実行者は、毎回、何も知らない状態で読む。
