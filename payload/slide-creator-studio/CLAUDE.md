# slide-creator-studio

このプロジェクトは、Claude Code で、説明用のスライドを作るための一式です。この文書は、一式を作るものの責務と、置き場を定義します。AI は、この一式のファイルを足すとき、直すときに、この文書の責務に合う置き場と形にします。

## この一式が満たすこと

- 作ったスライドは、規約の原則に合う。原則への適合は、テンプレートを足すときの確かめと、機械のチェックツールと、AI が原則に照らす 1 回の読みで保つ。
- 人が、スライドのどの部品について、値、位置、色、言葉の理由を聞いても、AI は答えられる。見た目の理由は、デザインシステムの部品の意図が持ち、言葉と数字の理由は、スライドの中身のデータの出どころが持つ。
- 新しいスライドを数枚作る時間は、テンプレートにある型だけなら 5 分以内、テンプレートにない型を含むなら 10 分以内とする。
- 機械で確かめられることは、機械のチェックツールが確かめる。AI が読んで確かめるのは、機械で決まらないことだけとする。

## 責務の定義

AI は、新しく作るファイルを、この節の置き場に置きます。

### CLAUDE.md(この文書)

- 持つもの: この一式の責務の定義と、置き場の地図。
- 持たないもの: 原則の本文、値、手順、直す所の一覧。
- 読まれるとき: このプロジェクトの会話の最初に、毎回。
- 置き場: プロジェクトの直下。

### 規約

- 持つもの: 抽象の原則と、その理由。原則は、デザインの原則(見た目が満たすこと)と、中身の原則(話の組み立て、結論の一文、言葉、数字が満たすこと)の 2 種類とする。規約は、原則ごとに、値の名前の一覧を、機械が読める形で持つ。値の名前は、規約が決め、値は、デザインシステムが与える。
- 持たないもの: 数値(px、pt、比、字数、行数、個数)、色コード、部品の作り、手順、確かめ方、成果物のファイルの名前の決まり。
- 読まれるとき: デザインの原則は、デザインシステムを作るとき、直すとき、テンプレートにない型を作るとき。中身の原則は、スライドの言葉と数字を書くとき。読み込む場面は、規約のファイルの冒頭の `paths`(読み込みの設定)で絞る。
- 置き場: `.claude/rules/`。

### デザインシステム

- 持つもの: 具体の全部。デザインシステムは、規約の原則を、1 つの見た目として実装したものである。
  - 見た目の値(色、文字の大きさ、間隔)と、部品と部品の関係の値(どの部品とどの部品の間か、何にそろえるか、どう積むか)。値は、1 つずつ、理由を持つ
  - 中身の形の値(字数、行数、個数の上限、文末の形)
  - 部品と、部品ごとの意図(1 つの部品に 1 回だけ書く)
  - 型ごとのテンプレート(中身のデータを受けて描く HTML と CSS。テンプレートは、部品を名前で指す)
  - 型ごとの、使う場面の条件(中身から、どの型を選ぶか)
  - 素材(イラストなど)
  - テンプレートに見本のデータを入れた例と、NG の例
- 持たないもの: 原則の文、手順、スライドごとの中身。
- 読まれるとき: AI は、使うテンプレートと値だけを、スライドを作るときに読む。機械のチェックツールは、値を読む。
- 置き場: `design-systems/<デザインシステムの名前>/`。どのデザインシステムにも共通の NG の例は、`design-systems/ng-examples/`。

### 機械のチェックツール

- 持つもの: 確かめ方(スクリプト)。チェックツールは、次の 7 つを確かめ、合否を、毎回同じ答えで返す。
  - スライドが、デザインシステムの値に合うこと
  - スライドの数字が、中身のデータの出どころが指す、元の資料の箇所にあること
  - デザインシステムが、規約の値の名前の一覧のすべてに、値を定義していること
  - デザインシステムのすべての部品が、意図を持つこと
  - デザインシステムのコード(`base.css`、`*.js`、`templates/*.js`)の見た目の数が、値の名前で引いた値か、値の名前の式で計算した値であること
  - 部品の意図の文が言う px の数と色コードが、デザインシステムの値にあること
  - デザインシステムのすべての部品が、コードに実装を持つか、テンプレートを持たない部品であることを示す項目を持つこと
- 持たないもの: 値、原則、AI の読みが要る判断。
- 走るとき: スライドを書いた直後と、デザインシステムを足したとき、直したとき。スキルの手順が呼ぶ。
- 置き場: `tools/`。

### スキル

- 持つもの: 手順だけ。スキルは、次の 2 本とする。
  - スライドを作るスキル: テンプレートを選ぶ、中身のデータを書く、描く、チェックツールを走らせる、AI が原則に照らす、Claude デザイン(Artifact の型「Design」)に出す、の順と、ユーザーを待つ所。テンプレートにない型を、テンプレートとしてデザインシステムに足し、チェックツールを走らせる手順。
  - 全ページを 1 つの HTML にまとめるスキル。
- 持たないもの: 原則、値、判断の基準、確かめ方の中身。
- 読まれるとき: ユーザーが頼んだとき。
- 置き場: `.claude/skills/`。

### スライドの中身と、作ったスライド

- 持つもの: 元の資料(ユーザーが渡す)。スライドごとの中身のデータ(型の名前、結論の一文、ラベル、数字、数字と言葉の出どころ)。スライドの並びと題(`canvas.json`)。描いたスライドと画像。
- 持たないもの: 値、部品の作り、部品の意図。
- 置き場: `output-slides/<作る日>_<資料の名前>/`。

### AI が読んで確かめること

このまとまりは、ファイルでなく、スキルの手順の 1 つです。

- 持つもの: 機械で決まらないことへの照らし合わせ。
  - スライドを書いたあとに、中身の原則と、デザインの原則のうち中身で決まるもの(強調を置く所、改行の位置など)に、1 回照らす。
  - テンプレートを足すとき、直すときに、テンプレートをデザインの原則に 1 回照らし、部品の意図の文を読む。
  - テンプレートを足すとき、直すときに、書いた AI とは別の点検者 2 人が、描いた見本のすべての部品と、隣り合う部品の間、そろえ方、積み方に、「なぜこの値か、なぜこの形か」の問いを立て、デザインシステムの値の理由と部品の意図だけで答えられるかを確かめる。
- 持たないもの: 機械で確かめられること。スライドごとの、部品の理由の書き直し。

### そのほかの置き場

- `README.md`: 人が読む、この一式の使い方の説明。責務の定義は、持たない。
- `docs/`: 経緯の記録、確かめの記録。
- `payload/`: ユーザーが公開すると選んだ成果物への symlink。

## 依存の向き

- 規約は、デザインシステムを知らない。デザインシステムが、規約の原則と値の名前を、名前で指す。
- 機械のチェックツールは、デザインシステムの値と、規約の値の名前の一覧と、スライドと、中身のデータと、元の資料を読む。規約の本文は読まない。
- スキルは、テンプレートと機械のチェックツールを呼ぶ。値と原則は、スキルの外にある。スキルの手順の中の AI の読みは、規約の原則を、名前で指す。
- 部品の意図は、デザインシステムの部品が持つ。スライドごとの記録が持つのは、使ったテンプレートの名前と、中身のデータの出どころである。
- この一式は、hook を持たない。機械のチェックツールは、スキルの手順が呼ぶ。

## 置き場の地図

| 置き場 | 中身 |
|---|---|
| `.claude/rules/slide-writing/design-principles.md` | 規約。デザインの原則 |
| `.claude/rules/slide-writing/content-principles.md` | 規約。中身の原則 |
| `.claude/rules/slide-writing/value-names.json` | 規約。値の名前の一覧 |
| `design-systems/blue-and-gray/`、`design-systems/ink-and-red/` | デザインシステム「青と灰」と「墨と赤」。値(`tokens.json`)、部品と意図(`parts.json`)、骨組みと部品のコード(`base.css`、`frame.js`、`parts.js`)、テンプレート(`templates/`)、見本のデータ(`examples/`)、NG の例(`ng-examples/`)、素材 |
| `design-systems/ng-examples/` | どのデザインシステムにも共通の NG の例 |
| `tools/` | 機械のチェックツールと、描く道具。使い方は `tools/README.md` |
| `.claude/skills/creating-claude-design-slides/` | スライドを作るスキル |
| `.claude/skills/exporting-slides-to-html/` | 全ページを 1 つの HTML にまとめるスキル |
| `output-slides/` | スライドの中身と、作ったスライド。資料ごとのフォルダ |
| `payload/` | ユーザーが公開すると選んだ成果物への symlink。資料ごとのフォルダ |
| `docs/` | 経緯の記録、確かめの記録 |
| `README.md` | 人が読む、この一式の使い方の説明 |
