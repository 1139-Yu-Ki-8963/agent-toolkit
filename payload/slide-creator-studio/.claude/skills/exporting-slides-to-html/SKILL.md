# スライドを、全ページを 1 つにまとめた HTML にする

## 全体像

- 目的: できたスライドを、ブラウザだけで開いて、1 ページずつ切り替えて見られる 1 つの HTML のファイルにする。
- 入力: 資料のフォルダ `output-slides/<作る日>_<資料の名前>/` の、`canvas.json` と、`canvas.json` の `order` の `.dc.html`。
- 出力: 資料のフォルダの直下の、`<資料の名前>スライド.html` 1 つ。資料の名前は、`canvas.json` の `title` とする。
- まとめた HTML に入れるスライド: `order` のスライドのうち、ファイルの名前が `-alt<数字>.dc.html` で終わる案のスライドと、`canvas.json` の題が「使わなかったスライド 」で始まるスライドを除いたもの。順は `order` の順とする。
- まとめた HTML の作り: スクリプトは、1 枚のスライドを、1 つの iframe の中の 1 ページにする。表示しているページだけを見せ、画面の下のボタンと、キー(→、←、PageDown、PageUp、空白、Home、End)で切り替え、ページの大きさを、ウィンドウに合わせて縮める。ページの大きさは、`canvas.json` のスライドの幅と高さとする。本文に差し込みの印(`{{名前}}`)を持つ、動きのあるスライドだけは、スクリプトが、`<script type="text/x-dc">` の Component と、印を Component の値で埋める処理を、iframe に入れる。
- AI がこのスキルで資料のフォルダに作るファイルは、まとめた HTML の 1 つだけとする。スライドの中身は、スキル creating-claude-design-slides の手順(データを直して描く)で直す。`payload/` に置く作業は、ユーザーが公開すると選んだときだけ行う別の作業とする。

## 入力

| 項目 | 必須か任意か | 依頼にないときの動作 |
|---|---|---|
| まとめるスライド(資料のフォルダか、Claude デザインの URL) | 必須 | ユーザーに聞く |
| 資料の名前 | 任意 | `canvas.json` の `title` とする |
| まとめるスライドのファイルの名前 | 任意 | 上の「まとめた HTML に入れるスライド」の全部とする |

## 手順

### step 1 スライドと `canvas.json` をそろえる

1. 資料のフォルダが手元にあるときは、AI は、そのフォルダを使う。フォルダがないときは、AI は、名前が `Artifact` のツールがあるかを、ツールの一覧と ToolSearch で確かめ、ツール `Artifact` で、Claude デザインの `project/canvas.json` と、すべての `.dc.html` を得て、`output-slides/<作る日>_<資料の名前>/` に、元のままで置く。ツールがないときは、AI は、スライドを得られないことをユーザーに伝えて止まる。
2. AI は、`canvas.json` を読み、`order` のすべての `.dc.html` がフォルダにあることを、`ls` で確かめる。
3. AI は、`order` のスライドを、上の規則で、ページのスライドと、まとめた HTML の外のスライドに分け、ページのスライドの数と順を控える。

### step 2 まとめた HTML を作る

AI は、次のコマンドを実行する。資料の名前を `title` と違う名前にするときだけ `--name` を付け、まとめるスライドを絞るときだけ、スライドのファイルの名前を後ろに並べる。

```bash
node .claude/skills/exporting-slides-to-html/scripts/build-slides-html.js '<資料のフォルダ>' [--name '<資料の名前>'] [<スライドのファイルの名前> ...]
```

スクリプトは、ページのスライドだけを入れたまとめた HTML を、資料のフォルダに `<資料の名前>スライド.html` で書き、書いたファイルのパス(`out`)、ページの数(`pages`)、ページの大きさ(`width`、`height`)、ページごとのスライドの題(`titles`)、まとめた HTML の外としたスライドのファイルの名前(`excluded`)を返す。

AI は、返った値の `pages` が、step 1 で控えたページのスライドの数(絞ったときは、絞ったスライドの数)と同じであること、`titles` の順が、控えた順と同じであること、`excluded` が、まとめた HTML の外としたスライドと同じであることを確かめる。スクリプトがエラーで止まったときは、AI は、エラーの文が言うスライドか `canvas.json` を、スキル creating-claude-design-slides の手順で直してから、この step をもう一度行う。

### step 3 ブラウザで開いて、全ページが見えることを確かめる

1. AI は、名前が `browser_run_code_unsafe` の Playwright の MCP のツールがあるかを、ツールの一覧と ToolSearch で確かめる。ないときは、AI は、入れるコマンド `claude mcp add playwright npx @playwright/mcp@latest` をユーザーに示し、入れてよいかを聞く。ツールが使えないままのときは、AI は、この step を飛ばし、ブラウザで確かめていないことを報告に書く。
2. AI は、スクリプト `scripts/check-slides-html.js` を、`cp` で、`$TMPDIR` の下に写し、写したファイルの「AI が書き換える値」の 2 行(まとめた HTML の絶対パスの `src` と、ページごとの画像を置く一時のフォルダの絶対パスの `outDir`)だけを書き換える。`outDir` は、AI が、`$TMPDIR` の下に作ったフォルダとする。AI は、写したファイルの絶対パスを、ツール `browser_run_code_unsafe` の `filename` に渡して、1 回呼ぶ。`filename` が許可された場所の外で拒まれたときは、写したファイルの全文を、同じツールの `code` に渡して、1 回呼ぶ。スクリプトは、まとめた HTML を開き、→ のキーで最後のページまで 1 ページずつ進み、ページごとに画像を作る。
3. AI は、返った値を確かめる。確かめる値は、次の 5 つとする。
   - `pages` が、step 2 の `pages` と同じである。
   - `stage` が、step 2 の `width`、`height` と同じである。
   - ページごとの `visible` が 1 で、`counter` が「<そのページの番号> / <ページの数>」である。
   - ページごとの `title` が、step 2 の `titles` と同じ順である。
   - ページごとの `brokenImages` と `marks` が 0 で、`fonts` が 1 以上で、`root` が `stage` と同じである。
4. AI は、ページごとの画像を 1 枚ずつ見て、スライドの中身が欠けずに見えることを確かめる。
5. 値か画像が合わないときは、AI は、原因がスライドにあるときに、スキル creating-claude-design-slides の手順でデータを直して描き直し、step 2 からもう一度行う。

### step 4 報告する

AI は、次の項目を、この順に報告する。

- まとめた HTML のファイルのパス
- ページの数と、ページごとのスライドの題
- まとめた HTML の外としたスライドのファイルの名前。ないときは、「なし」
- step 3 で確かめた値と、見た画像のパス。確かめていないときは、そのことと、理由
- ユーザーが確かめる項目(ユーザーのブラウザでファイルを開いたときの見え方)
