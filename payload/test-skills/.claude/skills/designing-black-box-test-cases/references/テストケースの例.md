# テストケースの例

このファイルは、工程ごとのテストケースの md の見本を持つ。
3 つの見本は、次の内容のテストベース `docs/会員登録の仕様.md`(AI が作った例)から作った md である。

- 節 1 画面定義書: 会員登録の入力画面の項目「年齢」は、必須の整数で、18 以上 120 以下とする。範囲の外の値には、「年齢は 18〜120 で入力してください」を出す。項目「メールアドレス」は、必須で、254 文字以下とする。
- 節 2 登録 API のインターフェースの仕様: 入力画面は、登録のボタンを押すと、会員情報を登録 API に渡す。登録 API は、入力チェックが不合格なら入力エラーを返し、メールアドレスの重複を調べない。入力チェックが合格でメールアドレスが登録済みなら重複エラーを返し、入力画面は「登録済みです」を出す。入力チェックが合格でメールアドレスが登録済みでないなら会員番号を返し、入力画面は登録完了の画面に移る。
- 節 3 要件定義書: 会員が入力画面で登録すると、会員の状態は仮登録になり、確認メールが届く。確認メールのリンクを 24 時間以内に押すと、会員の状態は本登録になる。24 時間が過ぎると、会員の状態は期限切れになり、期限切れのリンクを押すと「期限が切れました」を出す。

見本のセルの「仮-<番号>」は、テストベースにない値を仮に決めた点の番号を指す。

## 単体のテストケースの md の例

この章は、完成例である。

## 結合のテストケースの md の例

この章は、完成例である。

登録 API の重複。テスト対象「規模: サブシステム。テストアーキテクチャ: オンライン。→ 入力画面と登録 API」、観点「観点1: 入力する、観点1': 登録する。観点2: なし。観点3: 連結・連動中に」、組み合わせ構造「入力画面に会員情報を入力させることと、登録 API に会員情報を登録させることを、連結して実施する」、技法「デシジョンテーブルテスト。条件: 入力チェックの合否、メールアドレスの重複の有無。入力が不合格なら重複を調べないので、列は 3 つ」、期待結果「入力が不合格 → 入力エラーの表示。合格で重複あり → 重複エラーの表示(「登録済みです」)。合格で重複なし → 登録完了の表示」。3 つの節にも 1 行以上

この見本のデシジョンテーブルは、条件を入力チェックの合否とメールアドレスの重複の有無とし、列 1(不合格)、列 2(合格で重複あり)、列 3(合格で重複なし)の 3 つを持つ。

## 総合のテストケースの md の例

この章は、完成例である。

仮登録から本登録。テスト対象「規模: システム。テストアーキテクチャ: オンライン。→ 会員登録の業務全体」、観点「観点1: 仮登録する、観点1': 本登録する。観点2: なし。観点3: エンド・ツー・エンド型で」、組み合わせ構造「仮登録させることと、本登録させることを、エンド・ツー・エンド型で実施する」、技法「状態遷移テスト(有効遷移カバレッジ)。初期状態: 仮登録。確認メールのリンクを押す → 本登録。期限が過ぎる → 期限切れ」、期待結果は手順ごとに「仮登録 → リンクを押す → 本登録。仮登録 → 期限が過ぎる → 期限切れ(「期限が切れました」)」。3 つの節にも 1 行以上

この見本の状態遷移は、状態を仮登録、本登録、期限切れとし、有効な遷移を、仮登録 → 本登録(確認メールのリンクを押す)と、仮登録 → 期限切れ(24 時間が過ぎる)の 2 つとする。
