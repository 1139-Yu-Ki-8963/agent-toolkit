# QA の問題の分類

## 重大度

| 重大度 | 定義 | 例 |
|----------|------------|----------|
| **critical** | 中心の作業の流れを止めるか、データを失わせるか、アプリを落とす | フォームを送るとエラーのページになる、購入の流れが壊れている、確かめずにデータが消える |
| **high** | 大きな機能が壊れているか使えず、回避の方法がない | 検索が間違った結果を返す、ファイルのアップロードが黙って失敗する、認証のリダイレクトがループする |
| **medium** | 機能は動くが、目に付く問題があり、回避の方法がある | ページの読み込みが遅い(5 秒より長い)、フォームの検証がないが送信はできる、モバイルでだけレイアウトが崩れる |
| **low** | 見た目か仕上げの小さな問題 | フッターの誤字、1px の位置のずれ、ホバーの状態の不揃い |

## 分類

### 1. Visual/UI
- レイアウトの崩れ(要素の重なり、切れた文字、横のスクロールバー)
- 壊れた画像か、ない画像
- 誤った z-index(要素がほかの要素の後ろに出る)
- 書体か色の不揃い
- アニメーションの乱れ(カクつき、途中で終わる遷移)
- 揃えの問題(グリッドからのずれ、不揃いな間隔)
- ダークモードかテーマの問題

### 2. Functional
- 壊れたリンク(404、誤った行き先)
- 効かないボタン(押しても何も起きない)
- フォームの検証(ない、誤っている、すり抜けられる)
- 誤ったリダイレクト
- 状態が残らない(再読み込みや戻るボタンでデータが消える)
- 競合の状態(二重の送信、古いデータ)
- 検索が誤った結果を返すか、結果を返さない

### 3. UX
- 分かりにくいナビゲーション(パンくずがない、行き止まり)
- 読み込み中の表示がない(何かが起きていることがユーザーに分からない)
- 遅い操作(500ms より長く、反応がない)
- 分かりにくいエラーのメッセージ(詳しさのない "Something went wrong")
- データを壊す、消す操作の前に確認がない
- ページごとに操作の形が揃っていない
- 行き止まり(戻る道も、次の操作もない)

### 4. Content
- 誤字と文法の誤り
- 古いか誤った文
- 仮の文か lorem ipsum の文が残っている
- 途切れた文(省略記号や "more" なしで切れている)
- ボタンかフォームの欄の誤ったラベル
- 空の状態の表示がないか、役に立たない

### 5. Performance
- 遅いページの読み込み(3 秒より長い)
- カクつくスクロール(フレームの落ち)
- レイアウトのずれ(読み込みのあとに中身が動く)
- 多すぎるネットワークのリクエスト(1 ページで 50 より多い)
- 最適化していない大きな画像
- 読み込みを止める JavaScript(読み込みの間、ページが反応しない)

### 6. Console/Errors
- JavaScript の例外(捕まえていないエラー)
- 失敗したネットワークのリクエスト(4xx、5xx)
- 非推奨の警告(これから壊れるもの)
- CORS のエラー
- 混在するコンテンツの警告(HTTPS の上の HTTP のリソース)
- CSP の違反

### 7. Accessibility
- 画像の代替テキストがない
- ラベルのないフォームの入力
- キーボードの操作が壊れている(Tab で要素に移れない)
- フォーカスの閉じ込め(モーダルかドロップダウンから出られない)
- ARIA の属性がないか、誤っている
- 色のコントラストが足りない
- スクリーンリーダーで届かない中身

## ページごとの探索の点検表

QA のセッションで訪れたページの 1 つごとに、次を行う:

1. **見た目の点検** — 画像を撮る(qa-patterns の「読み取りと流れ」の手順。欠陥の要素を示すときは、Phase 5 の印を付けた画像の手順)。レイアウトの問題、壊れた画像、揃えを探す。
2. **操作できる要素** — すべてのボタン、リンク、操作の部品を押す。それぞれが、書いてあるとおりに動くかを確かめる。
3. **フォーム** — 入力して送る(手元でない対象では、先に同意を得る。ブラウザの準備の節の、ブラウザを動かす決まりの 3)。空の送信、不正なデータ、境目の場合(長い文、特殊な文字)を試す。
4. **ナビゲーション** — 入る道と出る道をすべて確かめる。パンくず、戻るボタン、ディープリンク、モバイルのメニュー。
5. **状態** — 空の状態、読み込み中の状態、エラーの状態、いっぱいかあふれた状態を確かめる。
6. **コンソール** — 操作のあとに `mcp__playwright__browser_console_messages`(`level: "error"`)でエラーを取り、`CONSOLE_ERRORS=` として書く。新しい JS のエラーか、失敗したリクエストがないかを確かめる。
7. **画面の幅への対応** — 関係があるときは、モバイルとタブレットのビューポートを確かめる。
8. **認証の境目** — ユーザーをサインアウトさせたり、アカウントを切り替えたりを、AI 自身で決してしない。サインアウトした画面かほかの役割の画面が関わるときは、ユーザーに Playwright のブラウザでサインアウトか切り替えを頼み、ページの確かめを走らせ直す。
