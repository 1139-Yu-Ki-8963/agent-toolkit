# 直したあとのブラウザの確かめ

AI は、この節を、ブラウザの欠陥にだけ使う。機能の直しでは、この節を読まない。

AI は、元の操作と、隣の正常な流れを、もう一度行う。直す前の証拠は Phase 5 のもの(操作の欠陥は `issue-NNN-result.jpg`、静的な欠陥は印を付けた `issue-NNN.png`)とし、直したあとの証拠を、ここで撮る。

- **操作の欠陥:** AI は、qa-patterns の Phase 3 の「読み取りと流れ」の手順を、操作ありで行い、操作と待ちを元の再現と同じにする。
- **静的な欠陥:** AI は、同じ手順を、操作なしで行う。

AI は、操作の前と後の snapshot、コンソールのエラー(`mcp__playwright__browser_console_messages`、`level: "error"`)、失敗したリクエスト(`mcp__playwright__browser_network_requests`)を、同じように取る。AI は、流れごとに、影響を受けた URL を開くところから続けて行う。直したファイルをブラウザがキャッシュから読まないように、AI は、開く URL に `?v=<時刻>`(`date -u +%Y%m%d%H%M%S` の値。URL がすでに問い合わせの文字列を持つときは `&v=<時刻>`)を付け、確かめ直しのたびに新しい時刻を使う。AI は、報告と、直す前の証拠との比べでは、`v` を除いた URL を使う。

AI は、新しい画像の名前を使い、結果の画像は `issue-NNN-after.jpg` とする(同じ名前があるときは、後ろに番号を足す)。AI は、撮った画像を Read で開く。AI は、snapshot の木、操作の前と後の違い、コンソールのエラーを、直す前の証拠と比べる。
