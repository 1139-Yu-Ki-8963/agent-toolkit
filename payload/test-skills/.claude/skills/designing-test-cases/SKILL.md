# テストケースの設計

この skill は、仕様、要件、画面や API の説明を入力にして、テスト技法を選び、テストケースの一覧を作る手順です。土台は、ISTQB CTFL v4.0 のテスト技法です。この skill は、v4.0 の技法に加えて、ペアワイズ(組み合わせテスト。ISTQB では Advanced の Test Analyst の範囲)と、ユースケースやシナリオからのテスト(v3.1 にあり、v4.0 で外れた技法)も使います。技法ごとの説明は `references/techniques.md` にあります。

## 入力

- テストの対象の説明: 仕様書、要件、ユーザーストーリー、画面の説明、API の説明のどれか。ファイルのパスか、会話の文。
- 任意: テストの範囲、優先度の付け方、出力の形の指定。

## 守ること

- AI は、仕様にない値、メッセージ、上限、エラーコードを、作り話で埋めない。仕様から読めない値は、「仮に決めた点」の一覧に置き、テストケースの中では、その一覧の番号(例: `仮-1`)で指す。
- AI は、期待結果を、仕様の文から確かめられる結果で書く。仕様から期待結果が決まらないときは、期待結果に「仕様で確かめる(仮-n)」と書く。
- AI は、すべてのテストケースに、使った技法の名前を 1 つ以上書く。
- AI は、組み合わせの数を数え、ペアワイズの組み合わせは `scripts/pairwise.py` で作る。AI は、組み合わせを手で並べない。

## 手順

1. AI は、入力の説明を読み、テストの対象(画面、API、機能)と、入力の項目、出力、状態、業務の規則を書き出す。
2. AI は、書き出した項目ごとに、仕様から読める値の範囲、型、必須かどうか、規則の条件を集め、仕様から読めない点を「仮に決めた点」の一覧に置く。
3. AI は、次の表に従い、項目ごとに技法を選ぶ。1 つの項目に、2 つ以上の技法を当ててよい。

   | 仕様の特徴 | 選ぶ技法 | 技法の分け方 |
   |---|---|---|
   | 入力や出力の値が、同じ扱いを受ける範囲に分かれる | 同値分割 | v4.0 のブラックボックステスト技法 |
   | 値の範囲に、上限、下限、桁数のような端がある | 境界値分析 | v4.0 のブラックボックステスト技法 |
   | 2 つ以上の条件の組で、結果が変わる | デシジョンテーブル | v4.0 のブラックボックステスト技法 |
   | 対象が状態を持ち、出来事で状態が移る | 状態遷移テスト | v4.0 のブラックボックステスト技法 |
   | 過去の不具合や、起こりやすい誤りの型がある | エラー推測 | v4.0 の経験ベースのテスト技法 |
   | 仕様が少ないか、時間が限られ、動かしながら調べる必要がある | 探索的テスト | v4.0 の経験ベースのテスト技法 |
   | 確かめる項目の一覧(チェックリスト)がある | チェックリストベースのテスト | v4.0 の経験ベースのテスト技法 |
   | ユーザーストーリーに受け入れ基準がある | 受け入れ基準、ATDD | v4.0 の協働ベースのテストのアプローチ |
   | 互いに独立したパラメータが 3 つ以上あり、すべての組み合わせが多すぎる | ペアワイズ | v4.0 の技法に加えて使う技法 |
   | 利用者の操作の流れ(ユースケース、シナリオ)がある | ユースケースやシナリオからのテスト | v4.0 の技法に加えて使う技法 |

4. AI は、選んだ技法を、`references/techniques.md` の手順に従って当て、テスト条件(同値クラス、境界値、ルール、遷移、誤りの型、探索のテストチャーター、チェックリストの項目、受け入れ基準、組み合わせ、流れ)を出す。
5. ペアワイズを使うときは、AI は、パラメータと値を JSON にして、次のコマンドで組み合わせの表を出す。

   ```bash
   <Python> <この SKILL.md があるフォルダの絶対パス>/scripts/pairwise.py --input '{"parameters": {"os": ["mac","win"], "browser": ["chrome","safari","firefox"], "lang": ["ja","en"]}}'
   ```

   - AI は、スクリプトを、この SKILL.md があるフォルダの `scripts/pairwise.py` の絶対パスで呼ぶ。Claude Code の作業のフォルダは、プロジェクトの直下で、skill のフォルダではないので、相対パスでは見つからない。
   - `<Python>` は、プロジェクトの直下に `.venv/bin/python3` があるときは、その絶対パスとし、ないときは `python3` とする。Claude Code のシェルでは、仮想環境が有効にならないので、`python3` では仮想環境の allpairspy が読み込まれない。
   - パラメータが多いときは、`--input-file <JSON のファイル>` で渡す。
   - 同じパラメータの中に同じ値が 2 つあるときは、スクリプトは、入力の誤りとして終了コード 2 で止まる。AI は、値を 1 回ずつにして、もう一度呼ぶ。
   - スクリプトが終了コード 1 で止まり、allpairspy の入れ方を出したときは、AI は、スクリプトが出したコマンドを実行してよいかを、ユーザーに聞く。
   - スクリプトが終了コード 1 で止まり、「覆えていない 2 つの組」の件数を出したときは、AI は、その表を使わず、件数をユーザーに伝える。
   - 組み合わせの中に、仕様で起こり得ない組があるときは、AI は、その行を消さず、「起こり得ない組」として印を付け、消すかどうかの判断を「仮に決めた点」に置く。
6. AI は、テスト条件の 1 つごとに、テストケースを 1 件以上作り、次の列を持つ表にする。

   | ID | 前提 | 入力 | 手順 | 期待結果 | 使った技法 | 優先度 |
   |---|---|---|---|---|---|---|

   - ID は、`TC-001` の形の通し番号とする。
   - 手順は、セルの中で `1.`、`2.` の番号を付ける。
   - 優先度は、「高」「中」「低」の 3 段とし、業務への影響と、不具合の起こりやすさで決める。ユーザーが優先度の付け方を決めたときは、その付け方に従う。
7. AI は、表のあとに、次の 3 つの節を書く。
   - 「使った技法と理由」: 技法ごとに、当てた項目と、その技法を選んだ理由(手順 3 の表のどの特徴に当たったか)。
   - 「仮に決めた点」: `仮-1` から始まる番号、仕様のどこが読めなかったか、仮に決めた中身、確かめる相手。
   - 「テストしない範囲」: 入力から外したもの、または手が届かなかったものと、その理由。
8. AI は、表のすべての行が、前提、入力、手順、期待結果、使った技法、優先度を持つかを確かめ、空の欄を埋めてから出す。

## 出力

- テストケースの一覧の表(Markdown)。
- 節「使った技法と理由」「仮に決めた点」「テストしない範囲」。
- ユーザーがファイルへの保存を頼んだときは、頼まれたパスに Markdown のファイルとして保存する。

## ファイル

- `scripts/pairwise.py`: パラメータと値の JSON を受け、すべての 2 つの組を少なくとも 1 回覆う組み合わせを、Markdown の表で出す。allpairspy(MIT)を使う。終了コードは、すべての 2 つの組を覆った表を出したときは 0、allpairspy が入っていないときと、覆えていない 2 つの組があるときは 1、入力の誤り(入力がない、JSON の形の誤り、同じパラメータの中の同じ値)のときは 2。
- `references/techniques.md`: 技法ごとの、使う場面、当て方、出すテスト条件、注意点。
