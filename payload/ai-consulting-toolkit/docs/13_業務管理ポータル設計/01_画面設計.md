# 業務管理ポータル 画面設計

## 1. 概要

ポータルは次の4点を目的として画面を構成する。

1. 散在情報の集約: Slack・会議・メールなどに散らばる情報を、AIが1画面に集める。手動の追加ボタンは置かない。
2. 事実と判断の分離: 出典つきの事実と、人の見解である判断・仮説を、必ず別枠で表示する。
3. 次アクションの明確化: どの画面でも、直近の対応事項を最初に目に入る位置へ置く。
4. AI解読状態の可視化: 情報ごとにAIの取込状況を示すタグを付け、人が取込状況を監査できるようにする。

## 2. 画面一覧

キーは連番を使わず、内容を要約した意味語で付ける。

| 画面キー | 名称 | 役割 | 表示方針 |
|---|---|---|---|
| issue-portfolio | 課題管理(一覧) | 課題を優先度別に一覧し対応状況を把握する | 全件表示 |
| issue-workspace | 課題ワークスペース | 個別課題のゴール・計画・記録をまとめる | 段階的開示(次アクションは直近3件のみ) |
| issue-goal | ゴール詳細 | 課題のゴールと達成条件・成果物を確認する | 全件表示 |
| portfolio-map | 全体マップ | 課題の構造と優先順位を1画面で把握する | 段階的開示(重要課題のみ展開) |
| task-board | 計画・タスク | 全課題のタスクを横断して確認する | 全件表示(中目標でグループ化) |
| doc-list | 受領資料一覧 | 資料の確認状況とAI解読状況を確認する | 全件表示 |
| people-list | 登場人物 | 関係者の役割・スタンスを確認する | 全件表示 |
| access-matrix | アクセス・環境準備 | メンバー別の環境準備状況を確認する | 例外優先(要対応・申請中を優先表示) |
| meeting-log | 会議メモ・議事録 | 会議の内容とAI取込状況を確認する | 全件表示 |
| decision-log | 決定事項ログ | 確定した決定事項を履歴として確認する | 全件表示 |
| project-switcher | プロジェクト切替 | 案件を切り替え要対応件数を確認する | 全件表示 |
| global-search | 横断検索 | 課題・資料・人物・会議・決定を横断検索する | 段階的開示(上位10件のみ) |

## 3. 各画面のレイアウト

プロトタイプ(`コンサル業務管理 プロトタイプ.dc.html`)の構造を正とする。

### issue-portfolio(課題管理一覧)

```
+----------------+----------------------------------------------+
| サイドバー      | ヘッダー: 優先度フィルタ + 件数バッジ           |
| (236px固定)     +----------------------------------------------+
|                | 課題行一覧: 優先度グループ見出し + 進捗バー      |
|                | (全20件、内部スクロール)                       |
+----------------+----------------------------------------------+
```

優先度(高・中・低)ごとに見出しを出し、行内に進捗バーを表示する。

### issue-workspace(課題ワークスペース)

```
+----------------+----------------------------+------------------+
| サイドバー      | パンくず/優先度/タイトル/⚑ゴール(一等地)         |
|                +----------------------------+------------------+
|                | 次のアクション(直近3件)      | 参照レール(300px) |
|                | 計画(中目標→タスク)         | ステータス/AIタグ  |
|                | 記録(箇条書きエントリ)       | 関連                |
+----------------+----------------------------+------------------+
```

左は読む列(次のアクション → 計画 → 記録)、右は参照レール。ゴールは課題に1つだけ持ち、必ず最初に見える位置へ置く。

### issue-goal(ゴール詳細)

```
+----------------+----------------------------------------------+
| サイドバー      | パンくず: 課題管理 / ISS-xx / ゴール詳細         |
|                +----------------------------------------------+
|                | ゴール全文 → 達成条件一覧 → 成果物一覧          |
+----------------+----------------------------------------------+
```

達成条件・成果物は省略せず全件表示する。

### portfolio-map(全体マップ)

```
+----------------+----------------------------------------------+
| サイドバー      | ズーム(65/80/100%) + 粒度切替(中目標まで/タスクまで) |
|                +----------------------------------------------+
|                | 重要課題のみ展開したツリー + 「+他N課題」ノード  |
+----------------+----------------------------------------------+
```

既定は重要課題のみ展開し、「+他N課題」ノードはマップ内でその場展開・折りたたみする。一覧画面へは飛ばさない。

### task-board(計画・タスク)

```
+----------------+----------------------------------------------+
| サイドバー      | 当社/先方の絞り込みタブ                       |
|                +----------------------------------------------+
|                | 課題別・中目標別にグループ化したタスク一覧       |
+----------------+----------------------------------------------+
```

### doc-list(受領資料一覧)

```
+----------------+----------------------------------------------+
| サイドバー      | 確認状況・AI解読の絞り込みチップ + 母数表示      |
|                +----------------------------------------------+
|                | 受領週見出し + 資料行(種別/提供者/確認/AI解読)   |
+----------------+----------------------------------------------+
```

### people-list(登場人物)

```
+----------------+----------------------------------------------+
| サイドバー      | 当社/先方/重要人物の絞り込みチップ              |
|                +----------------------------------------------+
|                | 部門見出し + 人物カード(役割/スタンス/最終接触)  |
+----------------+----------------------------------------------+
```

### access-matrix(アクセス・環境準備)

```
+----------------+----------------------------------------------+
| サイドバー      | 「要対応・申請中のみ」列フィルタ                |
|                +----------------------------------------------+
|                | メンバー列(sticky)+状況サマリー列(sticky)      |
|                | + 項目列(横スクロール)                        |
+----------------+----------------------------------------------+
```

メンバー列と状況サマリー列は左に固定し、項目列だけを横スクロールする。列が多い場合の代替として、完了を「✓完了 n件」に畳み未完了だけをチップ表示する「メンバー別カード」表示も持つ。

### meeting-log(会議メモ・議事録)

```
+----------------+----------------------------------------------+
| サイドバー      | 定例/個別/経営層の絞り込みチップ                |
|                +----------------------------------------------+
|                | 時期見出し + 会議カード(概要/取込状況/反映先)    |
+----------------+----------------------------------------------+
```

### decision-log(決定事項ログ)

```
+----------------+----------------------------------------------+
| サイドバー      | 月次グループ見出し                            |
|                +----------------------------------------------+
|                | 決定事項一覧(合意者/場/関連課題)               |
+----------------+----------------------------------------------+
```

## 4. 遷移表

遷移はすべて状態(page, issueId, hl)の組で表す。ブラウザ実装ではURLのハッシュに載せ、戻る操作と共有を可能にする。

| 遷移元 | 操作 | 遷移先 | 引き渡す状態 |
|---|---|---|---|
| サイドバー | 各カテゴリ行をクリック | 対応する一覧画面 | page=対象画面 |
| issue-portfolio | 課題行をクリック | issue-workspace | page=issue, issueId |
| issue-workspace | ⚑ゴールをクリック | issue-goal | page=goal, issueId(維持) |
| issue-goal | パンくずの課題名をクリック | issue-workspace | page=issue, issueId(維持) |
| issue-workspace | 関連リンク(rels)をクリック | 対象種別の画面 | page=対象種別, hl=対象名 |
| 各一覧画面 | 検索結果行をクリック | 対象種別の画面 | page=対象種別, hl=対象名 |
| サイドバー最上部 | プロジェクト行をクリック | 現在画面を維持 | projKeyを変更しデータ全体を入れ替える |

ハイライト遷移(関連リンク・検索経由)は、遷移先のフィルタを「すべて」にリセットしてから該当行を黄色でハイライトする。

## 5. レイアウト不変条件

| 条件キー | 内容 |
|---|---|
| 高さ固定 | ページ全体を100vhに固定し、ルート要素には最小高さを付けない |
| ワイド表 | 幅が広い表は行にmin-widthを設定し、外側コンテナをoverflow:autoにする |
| 折返し制御 | ラベル・チップ・タブにはnowrapを付け、行コンテナ側にflex-wrapを付ける |
| 2要素行 | 左右2要素の行(タスク行など)は右側をflex:none、左側テキストにmin-width:0を設定する |
| 局所スクロール | 縦スクロールは各一覧領域の内部だけに閉じ、ページ全体はスクロールしない |

## 6. 状態網羅表

| 状態カテゴリ | 取りうる値 | 表示ルール |
|---|---|---|
| 確認状況(資料) | 未確認・確認済・差戻し | AI解読とは別カラムで表示し、統合しない |
| AI解読状況(資料) | 解読済・解読中・旧版 | 「✦」を先頭に付ける |
| AI取込状況(会議) | 取込済・取込待ち | 真偽値から文言へ変換して「✦」を先頭に付ける |
| 件数バッジの色 | 赤地白字・黄・グレー・淡グレー | 期限超過あり=赤地白字、今週期限あり=黄、通常=グレー、残0=淡グレー |
| 今週期限の強調 | 赤太字 | 今日から1週間以内の期限を赤太字にする。今日日付は運用時に動的計算する |
| 先方滞留の表示 | ワークスペース警告カード + 一覧行バッジ | 先方担当の未完了タスクが期限超過の場合、両方に表示する |
| フィルタ母数の明示 | 「N件を表示 / 全M件」 | フィルタ適用時は表示件数と全体件数を必ず併記する |
| 空状態文言 | 「該当する項目がありません」等 | フィルタで0件になった場合に用意する |
| ハイライト遷移のフィルタ | 「すべて」にリセット | 遷移直後にフィルタを解除し、対象行が見える状態を保つ |

## 7. 色語彙トークン表

本節の値は、画面の見た目を統一するための変数名(トークン名)として定義する。命名には、見た目の定義に使う記法であるCSS(Cascading Style Sheets)のカスタムプロパティ記法を用いる。トークン名は`--c-`で始める。

| トークン名 | 色 | 用途 |
|---|---|---|
| --c-bg | #fbfbfa | ページ全体の背景(温白) |
| --c-sidebar-bg | #f6f5f2 | サイドバーの背景 |
| --c-text | #26251f | 基本文字色 |
| --c-text-sub | #7b786f | 補助文字色 |
| --c-text-faint | #9b988f | 淡い文字色 |
| --c-danger | #a03d2e | 優先度高・要対応の文字色 |
| --c-danger-bg | #f6e7e3 | 優先度高・要対応の地色 |
| --c-warning | #8a6d1f | 中優先度・申請中の文字色 |
| --c-warning-accent | #c9a227 | 中優先度のドット・強調線の色 |
| --c-warning-bg | #f4ecd8 | 中優先度・申請中の地色 |
| --c-success | #4a7042 | 完了・協力的の文字色 |
| --c-success-bg | #e8f0e6 | 完了・協力的の地色 |
| --c-link | #3b6ea5 | リンク・資料・先方関連の文字色 |
| --c-link-bg | #eef0f4 | リンク・資料・先方関連の地色 |
| --c-neutral | #57544b | 中立・当社関連の文字色 |
| --c-neutral-bg | #eceae4 | 中立・当社関連の地色 |
| --c-cat-account | #3b6ea5 | アクセス分類「アカウント」のドット色 |
| --c-cat-network | #7b9971 | アクセス分類「ネットワーク」のドット色 |
| --c-cat-devenv | #b0813e | アクセス分類「開発環境」のドット色 |
| --c-cat-data-bi | #8a5e9e | アクセス分類「データ/BI」のドット色 |
| --c-cat-admin | #8a877e | アクセス分類「手続き・研修」のドット色 |

AI関連の表示は「✦」を接頭辞として付け、色は上記の成功・警告・淡色トークンを状態に応じて使い分ける。専用トークンは追加しない。優先度のドット凡例は、高=--c-danger、中=--c-warning-accent、低=--c-success を用いる。
