# 機能要件

この文書は、AI 駆動開発の支援の業務フローで、支援する人が案件ごとに使うスキルを、機能要件として並べる文書です。チームの運用規約のような決まりの種類は、納品する `.claude/` の雛形の中身なので、[04_テンプレートの中身.md](04_テンプレートの中身.md) に並べます。項目「作業」は [02_業務フロー.md](02_業務フロー.md) の作業の番号で、項目「区分」は [01_必須とあると便利の基準.md](01_必須とあると便利の基準.md) の基準で決めます。

## 1. 機能要件の一覧

| 機能要件 | 作業 | 区分 |
|---|---|---|
| 機能要件 1: 顧客のリポジトリと資料の取得 | 1-1 から 1-4 | 必須 |
| 機能要件 2: コードからの設計書の書き起こし | 2-1 | 必須 |
| 機能要件 3: リポジトリの履歴と設定からの、チームの運用の慣習の読み取り | 2-2 | 必須 |
| 機能要件 4: 資料による設計書の肉付けと、足りない情報の一覧 | 2-3、2-4 | 必須 |
| 機能要件 5: 設計書の章と雛形の空欄の照合 | 2-5 | 必須 |
| 機能要件 6: 雛形から対象プロジェクトの `.claude/` を作る | 3-1 から 3-4 | 必須 |
| 機能要件 7: 開発フローの接続の照合 | 3-5、4-4 | 必須 |
| 機能要件 8: 納品のフォルダの準備 | 4-1 から 4-4 | 必須(作業 4-1 と、あると便利な納品物を入れる部分だけ、あると便利) |

## 2. あると便利な機能

**コードを分かりやすい HTML にする**
- 作業: なし
- 区分: あると便利
- 理由: 人が理解するためのもので、AI に渡す情報は Markdown の設計書が持つ

**照合の表と指標の割合を、顧客に見せる報告書にする**
- 作業: なし
- 区分: あると便利
- 理由: 顧客に説明するためのもの

## 3. 決まっていないこと

**コードを分かりやすい HTML にする機能を、誰が使うものにするか**
- 候補 1(推奨): 対象プロジェクトの人。`.claude/` の雛形のスキルに入れる。定義の章 2 は、人が判定する手間が開発の速さを決めるとしており、人がコードを理解しやすいほど判定が速くなる
- 候補 2: 支援する人。この文書の機能要件に入れる。フェーズ 2 で、支援する人が顧客のコードを理解するために使う
