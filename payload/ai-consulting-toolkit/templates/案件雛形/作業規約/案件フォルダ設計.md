# 案件フォルダ設計

AI 支援案件で、コンサル側が持つ案件フォルダの共通の構成と運用の決まりである。新しい案件は道具箱の `templates/案件雛形/` を `clients/<案件名>/`(git 管理外)へ複製して始める。特定の案件の資料・名前・事情は本文書にも雛形にも書かない。例は `<課題名>` のような置き換え用の名前で書く。

## 業務の流れとファイルの対応

工程の順は、相談受付 → 確認ヒアリング → 提案 → 環境準備 → 課題別の取り組み → 完了報告 → 運用・フォロー。道具箱の 7 フェーズ(`../01_コンサル業務フロー/コンサル業務フロー.md`)との対応を併記する。

| 工程 | 道具箱のフェーズ | その工程で起きること | 書く・更新するファイル |
|---|---|---|---|
| 10_相談受付 | 1. 課題の受付・事例照合 | 先方から相談が来る。課題を自由文で受け付ける | `案件管理/課題整理/<YYYYMMDD>_初回受付/課題一覧.md` を作る |
| 20_確認ヒアリング | 2. 現場ヒアリング、3. 業務の棚卸し、4. AI化レベル判定 | 誰が何に困っているかを聞く。資料を受け取る | `受領資料/README.md` の台帳に 1 行。課題整理の新しい版(担当・現状のやり方・現在レベル) |
| 30_提案 | 5. 施策設計・WBS化 | 課題をグループに分け、目標レベルと取り組みを提案する。提案書を先方へ出す | `50_` と `受領資料/` に `課題<N>_<グループ名>/<NN_課題名>/` を新設し `課題.md` を作る。`送付台帳.md` に 1 行 |
| 40_環境準備 | 5. 施策設計・WBS化(着手前提) | 着手前提 5 分類(権限・データの実物・現状手順・実行環境・体制と時間)を揃える | `課題.md` の「関連する受領資料」。`受領資料/README.md` |
| 50_課題別の取り組み | 6. 実行・稼働管理 | 取り組みごとに 1_設計 → 2_検証用 → 3_納品用 → 4_提示 → 5_納品済み | `<取り組み名>/やること.md` を作る。4_提示 と 5_納品済み に置くたび `送付台帳.md` に 1 行 |
| 60_完了報告 | 6. 実行・稼働管理 | 全課題の結果をまとめて報告する | `課題.md` の状態を「完了」に。`送付台帳.md` に 1 行 |
| 70_運用・フォロー | 7. 効果測定・定着化 | 効果測定と昇格判定 | `課題.md` のレベルを更新。課題整理の新しい版 |

## フォルダ構成

```
<案件>/
├── 10_相談受付/                    全課題に共通する、相談の資料
├── 20_確認ヒアリング/              全課題に共通する、ヒアリングの資料
├── 30_提案/                        全課題に共通する、提案の資料
├── 40_環境準備/                    全課題に共通する、環境準備の資料
├── 50_課題別の取り組み/
│   ├── 共通基盤/                   全課題で使う道具(任意)
│   ├── 課題<N>_<グループ名>/       課題をグループで扱う案件だけ作る(任意)
│   │   ├── 共通基盤/               グループ内の複数課題で使う道具(任意)
│   │   └── <NN_課題名>/
│   │       ├── 課題.md
│   │       └── <取り組み名>/
│   │           ├── やること.md     相手・やること・完了の判定・状態
│   │           ├── 1_設計/
│   │           ├── 2_検証用/       大容量の原本は置かない(受領資料を参照する)
│   │           ├── 3_納品用/       納品物の元(最新の確定版)
│   │           ├── 4_提示/         先方へ出す物。送った物は 送付済み/<YYYYMMDD>/
│   │           └── 5_納品済み/     先方へ渡した版。<YYYYMMDD>_<名前>/ で凍結
│   └── 社内向け/<取り組み名>/      課題に属さない取り組み(同じ形)
├── 60_完了報告/                    中身ができた時点で作る
├── 70_運用・フォロー/              中身ができた時点で作る
├── 受領資料/
│   ├── README.md                   台帳(受領日・出所・課題・置き場)
│   ├── 共通/<資料の種類>/
│   └── [課題<N>_<グループ名>/]<NN_課題名>/<資料の種類>/    50_ と同じ階層
├── 案件管理/
│   ├── 課題整理/<YYYYMMDD>_<名前>/  課題一覧の版の並び
│   ├── 送付台帳.md                 何をいつ誰に渡したか(全送付)
│   └── 進行管理/                   (任意)
├── 作業規約/                       私たちの規約の正本
├── アーカイブ/                     使わなくなった物
├── .claude/
└── .gitignore
```

## 置き場の判定

上から順に当てはめ、最初に当たった場所に置く。

1. 先方から受け取った原本 → `受領資料/`。1 つの課題の物は課題の下、同じグループの複数課題で使う物はグループの下、それ以外は `共通/`
2. 1 つの課題の成果物 → その課題の取り組みの、該当する工程
3. 複数の課題で使う道具 → 使う範囲で最も小さい共通階層の `共通基盤/`
4. 全課題に共通し、1 つの工程に属する物 → 工程フォルダ(`10_` 〜 `70_`)
5. 工程も課題もまたぐ物(状況・送付・進行) → `案件管理/`
6. どれにも当たらない物 → 置かずに、決まりを見直す

## 番号・名前

- ルートの工程は 10 刻みの 2 桁。差し込みは間の番号(例: `35_<工程名>`)。振り直さない。0 から始めない
- グループは「課題の種類」を表す。名前は `課題<N>_<グループ名>`(例: `課題1_AI駆動開発`)。N は 1 から始まる 1 桁以上の番号で、提案で分けた順に付ける
- 課題は 2 桁(`01_` 〜)。課題整理の正本の番号に合わせる。番号は案件全体で通しで、グループをまたいでも重複しない。追加のみ、欠番は再利用しない
- 取り組みの中の工程は `1_` 〜 `5_` に固定。取り組み名に番号を付けない
- 番号付きのフォルダが先に、番号なしのフォルダが後に並ぶ
- 日付は `YYYYMMDD`、版は `<YYYYMMDD>_<名前>`。名前は内容を表す日本語

## 完了・送付・大容量

- 完了した取り組みは動かさず、`やること.md` の状態を「完了」にする。使わなくなった物だけ `アーカイブ/` へ
- 先方へ送った物は、提示物は `4_提示/送付済み/<YYYYMMDD>/`、納品物は `5_納品済み/<YYYYMMDD>_<名前>/` に置き、`送付台帳.md` に 1 行記録する。置いた後は内容を変えない
- 先方から受領した原本は `受領資料/` にだけ置き、台帳(`受領資料/README.md`)以外は git 管理外にする。`2_検証用/` などに写しを置かず、台帳の置き場を参照する

## 雛形ファイルの項目

| ファイル | 項目 | 書く工程 |
|---|---|---|
| `課題.md` | 課題名・グループ・先方の担当・状態・困っていること(先方の言葉のまま)・現状のやり方・現在レベル・目標レベル・関連する受領資料・取り組みの一覧 | 30_提案で作る。40 以降は関連資料・取り組み・状態・レベルだけ動く |
| `やること.md` | 取り組み名・課題・相手・状態・やること・完了の判定・工程の記録 | 取り組みを足すとき |
| `受領資料/README.md` | 受領日・出所・課題・置き場・備考(1 行 1 件) | 資料を受け取るたび |
| `案件管理/送付台帳.md` | 送付日・宛先・何を・種別(提示/納品/報告/その他)・置き場・手段(1 行 1 件) | 先方へ送るたび |
| `案件管理/課題整理/<YYYYMMDD>_<名前>/課題一覧.md` | 課題番号・課題名・グループ・先方の担当・課題原文・出所・現在レベル・目標レベル・状態 | 相談受付で初版。以後は変わるたびに新しい版 |

状態の値は 4 つ: 未着手・進行中・完了・保留。レベルは `../02_AI化レベル基準/AI化レベル基準.md` のレベル 1〜5。

## 運用

| 場面 | やること |
|---|---|
| 新しい案件 | `templates/案件雛形/` を `clients/<案件名>/` へ複製し、工程フォルダと `案件管理/` から始める |
| 工程を足す | 間の番号で新設 |
| 課題を足す | 次の課題番号で、`50_` と `受領資料/` に同じ階層で作る |
| 取り組みを足す | `やること.md` と `1_` 〜 `5_` を雛形から複製 |
| 資料を受け取る | 判定 1 で置き、`受領資料/README.md` の台帳に 1 行 |
| 先方へ送る | 決まりどおり置き、`送付台帳.md` に 1 行 |
| 工程の順序を変える | この場合だけ番号を付け替え、参照を直す |

`templates/案件雛形/` の中の `課題雛形/` と `取り組み雛形/` は複製元であり、案件の中では使わない。複製したら名前を付け替える。
