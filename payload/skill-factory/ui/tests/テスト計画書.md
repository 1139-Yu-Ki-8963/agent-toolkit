# スキル作成の確認と承認の画面のテスト計画書

この文書は、画面(`ui/index.html`)と中継サーバー(`ui/server.mjs`)のテスト計画書である。スキルのテスト計画書(規約 skill-test-design-rule)がスキルの振る舞いを確かめるのに対して、この計画書は、画面と中継サーバーのプログラムを確かめる。要件の出どころは、`docs/スキル作成の確認と承認の画面/` の要件定義書.md(この文書では「要件」と呼ぶ)、設計書.html の章 9、設計漏れの一覧.md である。

## 1. テストの分け方

テストは、AI の扱いと流す時点の 2 つの軸で分ける。

- AI の扱い: モックのテストは、`claude` の代わりに決まった応答を返すスクリプトを使う。本物のテストは、本物の `claude` を使う。
- 流す時点: 毎回自動のテストは、git の hook がコミットの前に流す。指示したときだけのテストは、時間がかかり、claude の使用量を使うので、ユーザーの指示で流す。節目のテストは、利用料はかからないが時間がかかるか手動なので、章 2 の時点に流す。

| 層 | 確かめること | AI の扱い | ブラウザ | 流す時点 | プログラム |
|---|---|---|---|---|---|
| 静的な検査 | 構文、ファイルの形、計画書とプログラムの同期 | 使わない | 使わない | 毎回自動 | `ui/tests/test-static.mjs` |
| 中継サーバーのテスト | API の答え、`claude` に渡す引数と文、保存するファイル | モック | 使わない | 毎回自動 | `ui/tests/test-relay.sh`、`ui/tests/test-relay-edge.mjs` |
| 画面のテスト | 画面の表示と操作、画面が送るもの | モック | 使う | 毎回自動 | `ui/tests/test-screen.mjs` |
| 契約のテスト | 本物の `claude` の引数と出力の形がモックと同じこと | 本物 | 使わない | 指示したときだけ | `ui/tests/test-real.mjs` の `contract` |
| 会話のテスト | 本物の AI との対話で、画面の操作が段階を進めること | 本物 | 使う | 指示したときだけ | `ui/tests/test-real.mjs` の `hearing-screens`、`hearing-to-written`、`until-stage-3`、`until-stage-8`、`check-skill`、`session-lost` |
| テスト自体の検証 | 入れた不具合をテストが見つけること | モック | 使う | 節目 | `ui/tests/test-mutants.mjs` |
| 手動の確認 | ブラウザの見た目と普段の環境 | 本物 | 使う | 節目 | 章 8 |

- `ui/server.mjs` と `ui/index.html` は関数を公開しないので、この計画書は、プロセスとブラウザを外から動かすテストの層だけを置く。
- モックの層の合格は、受け渡しの形が本物と同じ間だけ意味を持つ。契約のテストは、`ui/tests/test-real.mjs` が決めた形を本物が返すことを確かめる。モックの出力との比較は章 9 の 「モックの 1 本化」 である。
- 会話のテストの合否は、ファイルと画面の状態と、テストが決めた目印の文字列で決める。

## 2. 流す時点の決まり

| コマンド | 流すテスト | 合否 |
|---|---|---|
| `bash ui/tests/run-auto.sh` | 毎回自動の 4 本を順に流し、判定の記録を書く | 終了コード 0 は、すべての項目が合格か既知の不合格であることを指す。2 は時間の上限を超えて判定できないことを指す |
| `ui/tests/git-hooks/pre-commit` | `ui/`、`.claude/rules/`、`.claude/skills/`、`output/updating-skill-factory-ui-state/`、`README.md` のファイルが変わったコミットの前に `ui/tests/run-auto.sh` を流す | 終了コード 0 でコミットを通す。ステージしていない変更があると止める |
| `node ui/tests/test-real.mjs contract --yes` | 契約のテストを流す | 終了コード 0 は、すべての項目が合格か既知の不合格であることを指す |
| `node ui/tests/test-real.mjs until-stage-3 --yes` | 会話のテストの 1 件を流す(`hearing-screens`、`hearing-to-written`、`until-stage-3`、`until-stage-8`、`check-skill`、`session-lost` のどれか) | 終了コード 0 は、すべての項目が合格か既知の不合格であることを指す |
| `node ui/tests/test-mutants.mjs` | テスト自体が不具合を見つけられることを確かめる | 終了コード 0 は、入れたすべての不具合で指定のケースが不合格になったことを指す |

変えたものと時点ごとに流すものは、次の表のとおりとする。

| 変えたものか時点 | 流すもの |
|---|---|
| `ui/` のプログラム | 毎回自動の 4 本 |
| `server.mjs` の `claude` の引数か stream-json の読み取り | 毎回自動の 4 本、契約のテスト、依頼から段階 3 までの会話のテスト |
| `claude` の版(`ui/tests/run-auto.sh` が、同じフォルダの `contract-baseline.json` の版との違いを知らせる) | 契約のテスト。違いがあれば依頼から段階 3 までの会話のテスト |
| スキル updating-skill-factory-ui-state のリファレンス | 毎回自動の 4 本、依頼から段階 3 までの会話のテスト |
| 規約 skill-making-flow か段階のスキル | 毎回自動の 4 本。段階 1 から 3 は `until-stage-3`、段階 5 は `check-skill`、段階 4 から 8 は `until-stage-8` |
| `ui/tests/package.json` か Node の版 | 毎回自動の 4 本 |
| `ui/tests/` のプログラム | 毎回自動の 4 本、`ui/tests/test-mutants.mjs` |
| `ui/index.html` の配置 | 毎回自動の 4 本、章 8 の手動の確認 |
| 受け入れの前 | 毎回自動の 4 本、契約のテスト、会話のテストの 4 つ、章 8 の手動の確認、`ui/tests/test-mutants.mjs` |

## 6. 合否の基準

- コミットの基準: 毎回自動の 4 本のすべての項目が、合格か既知の不合格である。
- 受け入れの基準: 章 2 の「受け入れの前」のすべてのテストが合格し、既知の不合格だったすべての項目が合格し、章 9 の「受け入れに要る」のすべてのテストが実装されている。
- 判定の結果は、合格、不合格、判定できないの 3 つとする。`ui/tests/run-auto.sh` と `ui/tests/test-real.mjs` は、時間の上限を超えたときに終了コード 2 の「判定できない」を返す。ログイン切れとレート制限の判定は章 9 の 「ログイン切れとレート制限」 で足す。
- `ui/tests/known-failures.json` にある項目は、合否に数えない。その項目が合格したら、テストは、一覧の消し忘れとして不合格にする。
- `ui/tests/run-auto.sh` は、静的な検査が不合格なら、そこで終わる。AI は、直したあとに静的な検査から流し直す。

| 計画書との同期 | ケース「計画書とプログラムの同期」が、計画書とプログラムのケースの名前とパスと状態の一致と、章 5 の対応を確かめる。コードの網羅の値は参考の値とし、受け入れの基準に使わない |

## 8. 受け入れの前にユーザーが手で確かめること

ブラウザの見た目と普段の環境はプログラムで確かめられないので、画面の配置が変わったときと受け入れの前に、ユーザーが次の項目を確かめる。ユーザーは、項目ごとの合否を、受け入れの回の判定の記録の章「手動の確認」に書く。

- 普段のブラウザで、`PORT` を付けない `node ui/server.mjs` の画面を `http://localhost:4173/` で開く。
- 日本語を入力して、変換の確定の Enter で送られないことを確かめる。
- 図と文書の配置と色が、`docs/スキル作成の確認と承認の画面/画面のイメージ.html` と同じことを確かめる。
- 段階 1 から 3 を、画面だけで進める。
- `Ctrl+C` で止め、起動し直して「続きから」で続ける。
- skill-factory のリポジトリを新しく複製したフォルダで、章 7 の準備と README の手順だけで `bash ui/tests/run-auto.sh` が流れることを確かめる。

## 10. ユーザーが決めること

次の 3 つは、ユーザーが決める。

- `--resume` が「No conversation found」以外の 0 でない終了コードで終わったときに、新しい会話に替えるか、同じ会話を保つか(要件の章 6 と実装が違う)。
- F5 の表示の文を、要件の「作っている」にするか、実装の「書いています」にするか。
- 設計漏れの L15(段階の名前の正本)、L18(削除と名前の変更)、L19(文の長さと選択肢の検証)を直すか、受け入れたリスクに足すか。
