# 画面の状態のファイルの形

## キーの名前と型の対応表

この章は、対応表である。state.json は、次の表の 16 のキーを、表の順に持ち、そのあとに章「段階 2 から 8 で足すキー」の表のキーを、表の順に持つ。キー `summary` から `draftReview` までの 5 つは、段階 1 の聞き取りの画面を出すキーで、段階 1 のほかの時点と段階 2 から 8 では `null` とする。キー `screen` は、段階 1 では聞き取りの画面の値を、段階 2 から 8 では章「段階 2 から 8 で足すキー」の画面の値を持つ。表の「パス」は、作業のフォルダからの相対パスで、区切りを `/` とする。作業のフォルダは、規約 skill-making-flow の規則「作業のフォルダとスキルのフォルダのパスと作る時期」の `output/<開始日時>/` で、出力先のフォルダ `<作業のフォルダ>/ui/` の親のフォルダである。

| 値 | キー | 型 | 値の決まり |
|---|---|---|---|
| 作業の名前 | `workName` | 文字列 | 1 文字以上 |
| いまのスキルの名前と作る順 | `currentSkill` | オブジェクト `{"name": 文字列, "order": 整数, "total": 整数, "done": 整数か null}` か `null` | `order` は 1 以上 `total` 以下。`done` は、段階 8 まで終えたスキルの数で、`total` と同じなら作業は完了。`done` は、分割設計書の承認の前は `null` |
| いまの段階の番号 | `stage` | 整数 | 1 から 8 |
| 成果物の状態 | `artifacts` | オブジェクト `{"stage": 整数, "name": 文字列, "status": 文字列}` の配列 | 8 件。`stage` は 1 から 8 の順。`status` は「未着手」「下書き」「承認待ち」「済み」のどれか。段階 5 の間に AI が段階 6 のテスト計画書を作っているときは、段階 6 の要素の `status` を「下書き」にする(画面は、帯の段階 6 の名前の下に「作っている」を出す。2026-11-12) |
| 図のタブの一覧 | `figures` | オブジェクト `{"tab": 文字列, "path": 文字列}` の配列 | 0 件でもよい。`path` は `ui/figures/` で始まり、`.svg` で終わる。drawing-skill-factory-figure が書く図のファイルのパスは、`ui/figures/<段階の番号>-<作る順の番号>-<図の種類>.svg` である |
| 文書のパス | `documentPath` | 文字列 | `.md` で終わるパス |
| 決めてもらうこと | `decision` | オブジェクト `{"question": 文字列, "choices": 配列, "replies": 配列}` か `null`。`choices` の要素は行 `decision.choices[]`、`replies` の要素は行 `decision.replies[]` の形 | 聞き返しのときだけ、`replies` の後ろに、値が true の欄 askBack を足す。聞き返しは、`screen` が段階 1 の聞き取りの画面の値のときだけ使う。`choices` は 0 件でもよい。0 件のときは、自由に答える問いとする。`replies` は、自由に答える問いの答えの候補で、0 件から 4 件とし、`choices` が 1 件以上のときは空の配列とする。段階 2 から 8 の画面では、行 `decision.notice`、`decision.detail`、`decision.files`、`decision.prompt`、`decision.freeText` の欄を、その行の使う画面のときだけ足す。決めてもらうことがないときは `null` |
| 選択肢 | `decision.choices[]` | 文字列か、オブジェクト `{"label": 文字列, "result": 文字列, "recommend": 真偽値, "recommendReason": 文字列か null, "confirm": 真偽値}` | `label` は表示する名前で、画面はこの文のまま送る。文字列の要素は、`label` だけを持つものとして扱い、末尾の「(推奨)」を持つ要素を推奨とする。`result` は「選ぶと何が起こるか」の文で、オブジェクトの要素では必須。`confirm` が true の選択肢(「やめる」)は、押すと「スキルを中止しますか？」を出す。「直す点を伝える」のように、スキルが同じ step で文を受ける選択肢だけは、欄 `input`(オブジェクト `{"placeholder": 文字列, "sendLabel": 文字列}`)を持ってよい。「却下する」は `input` を持たず(却下の理由は 2 回で送る)、画面は「却下する」の `input` を無視する |
| 返答の候補 | `decision.replies[]` | 文字列か、オブジェクト `{"text": 文字列, "recommend": 真偽値, "reason": 文字列か null}` | `text` は候補の文。文字列の要素は、`text` だけを持つものとして扱う。使う画面は、依頼のファイルがない、依頼の形を聞く、前の会話を続けられない(E2)、却下の理由(候補があるとき)。開始時の入力の質問と分割で生まれた値の質問は、`questions.items[].choices` を候補に使う |
| 見出しの下の 1 行 | `decision.notice` | 文字列か `null` | 上書きで消えるもの、管理者の権限、ファイルがなかった場所。使う画面は、上書きの確認、インストールの確認、依頼のファイルがない |
| 問いの材料 | `decision.detail` | オブジェクト `{"name": 文字列, "value": 文字列}` の配列か `null` | インストールの確認では 4 行(足りないツール、確かめたコマンド、実行するコマンド、管理者の権限)。進展がないときの確認では、1 行目が残っている問題、2 行目以降が前と違う直し方。AI から決めてもらうことでは、どちらを選ぶ場合も知っておくこと。使う画面は、インストールの確認、進展がないときの確認、AI から決めてもらうこと |
| 上書きするファイルの一覧 | `decision.files` | 配列か `null`。要素は、文字列か、オブジェクト `{"path": 文字列, "writtenAt": 文字列か null, "diff": 文字列か null}` | `path` はパス、`writtenAt` は最後に書いた日時、`diff` は中身の違い(画面「上書きの確認」の「既にあるファイル」の 3 行)。文字列の要素は、`path` だけを持つものとして扱う。使う画面は、上書きの確認 |
| 問いの塊の文 | `decision.prompt` | 文字列か `null` | 問いの塊に出す文(例: 「指摘 6 件の扱いを選んでください。」)。ないときは、問いの塊に文を出さない。使う画面は、AI から決めてもらうこと |
| 下の 1 行に書いた文の扱い | `decision.freeText` | 文字列か `null` | 折りたたみ「選ぶと何が起こるか」の最後の段落「下の 1 行に書いた文: <扱い>」の文。使う画面は、承認と確認の画面 |
| 質問の一覧 | `questions` | オブジェクト `{"title": 文字列, "added": 整数, "removed": 整数, "notice": 文字列か null, "items": 配列}` か `null`。`items` の要素は、オブジェクト `{"number": 整数, "text": 文字列, "choices": 文字列の配列, "answer": 文字列か null, "reason": 文字列か null, "example": 文字列か null, "results": 文字列の配列, "previousAnswer": 文字列か null, "category": 文字列か null, "multiple": 真偽値, "parts": 配列, "files": 配列}` | 段階のスキルが 2 問以上をまとめて聞くときの一覧と、画面「調べるための問い」と画面 4 の問いとし、聞く質問がないときは `null`。`title` は一覧の見出しで、画面 4 ではカテゴリーの名前。`added` と `removed` は、前の答えで増えた問数と減った問数で、1 回目は 0。`notice` は、次の問いの上の知らせの行で、ないときは `null`。`items` は、段階のスキルがチャットに出した質問の番号と質問の文を、番号の小さい順に持つ。要素の `choices` は答えの候補で、0 件から 4 件。`answer` は答えた問いの答えで、まだ答えていない問いは `null`。`reason` は聞く理由の文、`example` は回答例、`results` は選択肢ごとの結果の文で、選択肢の順に持つ。この 3 つは、画面 4 の問いのほかでは `null` か空の配列。`previousAnswer` は、「戻る」で未回答に戻した問いの前の回答で、ほかの問いでは `null` とする。`category` は、画面 4 の問いのカテゴリーの名前で、ほかの画面の問いでは `null` とする。2 つ以上のカテゴリーの問いを持つときは、`items` をカテゴリーの順に並べ、`title` を 1 つ目のカテゴリーの名前とする。`multiple` は、問いの雛形の列「数」が「複数」の問いで true、ほかの問いで false とする。`parts` の要素は `{"name", "source", "selected"}`、`files` の要素は `{"name", "source", "mainParts", "selected"}` で、項目 7-1、7-10 の問いのほかでは空の配列とする。`source` は出典か「AI の案」、`mainParts` は主な部分の文字列、`selected` は初めに選ぶかの真偽値とする |
| 回の一覧 | `rounds` | 配列か `null`。要素は、オブジェクト `{"kind": 文字列, "items": 配列}`。`items` の要素は、`questions.items` の要素と同じ欄に、`"replaced": 真偽値` を足したもの | 聞き取りの画面の、問いの回のすべて。`kind` は「調べるための問い」「既にあるものとの関係の問い」「1 段目」「2 段目」「追加の回」「聞き直しの回」のどれか。`answer` は送った答えで、まだ送っていない問いは `null`。`replaced` は、直した答えで次の回に置き換えた問いで true とする。実行者は、回を後ろに足すだけとし、前の回を消さない。実行者は、会話の要約のあとも、今の `state.json` の `rounds` を読んで持ち越す。聞き取りの画面の問いの回がまだないときは `null` |
| ダウンロードできるファイルの一覧 | `downloads` | 文字列の配列 | 0 件でもよい。1 件ずつがパス |
| いまの聞き取りの画面 | `screen` | 文字列か `null` | 段階 1 では、「AI が読む」「画面 2」「調べるための問い」「調査」「画面 3」「画面 4」「AI の案」「画面 5」「画面 6」のどれか。聞き取りの画面を出さないときは `null`。段階 2 から 8 では、「始める段階の知らせ」「直す内容の一覧」「依頼のファイルがない」「依頼の形を聞く」「上書きの確認」「インストールの確認」「進展がないときの確認」「開始時の入力の質問」「中止」「AI から決めてもらうこと」「分割で生まれた値の質問」「成果物の承認」「却下の理由」「指摘の一覧」「直しの承認」「修正の結果」「テストの実行」「テストの結果」「不合格の仕分けの結果」「規約か雛形が原因」「テスト計画書の直しの承認」「文書の照合の結果」「スキルができた」のどれか。AI が作業している間は `null` |
| 画面 2 のまとめ | `summary` | オブジェクト `{"lines": 文字列の配列, "readings": 文字列の配列}` か `null` | `lines` は、3 つの部分の境目で改行した `<まとめた文>` の行で、1 件以上。`readings` は、2 通り以上に読めるときの読みの候補で、0 件でもよい。`screen` が「画面 2」のほかでは `null` |
| 調査の状態 | `research` | オブジェクト `{"rows": 配列}` か `null`。`rows` の要素は、オブジェクト `{"name": 文字列, "status": 文字列, "result": 文字列か null}` | `name` は調査の行の名前。`status` は「調べています」「調べました」「調べられませんでした」のどれか。`result` は結果の文で、調べている間は `null`。調べられなかった行の `result` は、調べられなかった理由と、場所が分かったら調べることを持つ。`screen` が「調査」のほかでは `null` |
| 画面 3 の事実確認 | `factCheck` | オブジェクト `{"heading": 文字列, "note": 文字列, "facts": 配列, "items": 配列}` か `null`。`facts` の要素は、オブジェクト `{"text": 文字列, "source": 文字列}`。`items` の要素は、オブジェクト `{"name": 文字列, "value": 文字列, "label": 文字列か null}` | `heading` は画面 3 の見出しの文。`note` は残りの数とこのあとの量の文。`facts` は AI が調べて分かった事実と出どころ。`items` は確かめる項目の名前と値で、0 件のときは画面 3 を出さない。`label` は「追加」「修正しました」のどちらかか `null`。`screen` が「画面 3」のほかでは `null` |
| 承認の 1 枚 | `approvalSheet` | オブジェクト `{"heading": 文字列, "rows": 配列}` か `null`。`rows` の要素は、オブジェクト `{"section": 文字列, "name": 文字列, "label": 文字列か null, "cells": 配列}`。`cells` の要素は、オブジェクト `{"name": 文字列, "value": 文字列, "source": 文字列, "choices": 文字列の配列}` | `heading` は見出しの文。`section` は行の見出し、`name` は行の名前。`label` は「追加」「変更」のどちらかか `null`。`cells` は小さな行で、`source` は「あなたの文章」、AI が調べたファイルと行か URL、「AI の案」のどれか。`choices` は直すときの選べる値で、0 件のときは値を書いて直す。`screen` が「AI の案」のほかでは `null` |
| 画面 5 の下書き | `draftReview` | オブジェクト `{"checkFirst": 配列, "checks": 配列, "sections": 配列}` か `null`。`checkFirst` の要素は、オブジェクト `{"name": 文字列, "value": 文字列}`。`sections` の要素は、オブジェクト `{"title": 文字列, "items": 配列}` で、`items` の要素は `checkFirst` の要素と同じ形 | `checkFirst` は、承認の前に見る行で、確かめる点を持たない。`checks` の要素は `{"name": "確かめる点: <語>(<項目>)", "candidates": 読みの候補の文の配列}` で、確かめる点がないときは空の配列とする。`candidates` は、読みの候補を読点で連ねず、1 つずつ要素に持つ。`sections` の `title` は「あなたの文章から決まった内容」「質問で答えた内容」「AI の案で決まった内容」「AI が調べた内容」のどれか。`screen` が「画面 5」のほかでは `null` |

## 段階 2 から 8 で足すキー

この章は、対応表である。次の表のキーは、段階 2 から 8 の画面(規約 skill-making-flow の規則「スキルだけで動く 8 段階の流れ」の表の段階)を出すキーで、state.json は、「キーの名前と型の対応表」の 16 のキーの後ろに、表の順に持つ。使わない画面では `null`(配列のキーは `null` か空の配列)とする。画面は、欠けたキーを `null` として扱う。`figures` と `documentPath` は残し、`panels` があるときは、画面は `panels` を使い、ないときは `figures`(図のタブ)と `documentPath`(文書のタブ。初め畳む)から同じ形を作る。8-1 のシナリオごとの進み具合は、state.json のキーではなく、中継サーバーの答えから画面が作る。

| 値 | キー | 型 | 値の決まり |
|---|---|---|---|
| 開始の宣言と完了の報告 | `report` | オブジェクト `{"start": オブジェクト か null, "done": オブジェクト か null}` か `null`。`start` は `{"stage": 整数, "skill": 文字列, "purpose": 文字列, "inputs": 配列, "outputs": 文字列の配列, "request": 文字列か null, "form": 文字列か null, "folder": 文字列か null, "next": 文字列か null, "rewrite": 真偽値}` で、`inputs` の要素は `{"name": 文字列, "value": 文字列, "kind": 文字列}`。`done` は `{"title": 文字列, "outputs": 配列}` で、`outputs` の要素は `{"path": 文字列, "unchanged": 真偽値}` | 段階のスキルの「次の内容で始めます」の宣言(`start`)と、「<題名> が完了しました」の報告(`done`)。`inputs` の `kind` は、開始時の入力の表の入力の種類。`request` は依頼の文、`form` は当たった依頼の形、`folder` はスキルのフォルダで、画面「始める段階の知らせ」はこの 3 行と、`inputs` の表(列は「項目」「値」「入力の種類」)を出し、`inputs` に `value` が「ユーザーに聞く」の要素を持つ。`next` は、AI が作業している間の知らせの行「AI は、<成果物>ができたら、<次の画面>を出します。」。`rewrite` は、却下のあとの書き直しなら true で、画面はこれが true のときだけ「書き直しています」を出す。使う画面は、AI が作業している間(`screen` が `null`)、始める段階の知らせ、テストの実行 |
| 図と文書のタブ | `panels` | オブジェクト `{"kind": 文字列, "name": 文字列, "path": 文字列か null, "section": 文字列か文字列の配列か null, "key": 文字列か null, "open": 真偽値, "isNew": 真偽値}` の配列か `null` | `kind` は「図」か「文書」。`path` は、ファイルの全文を出すときのパス(図は `.svg`、文書は `.md`)。`section` は、`path` の `.md` のうち章だけを出すときの、その章の見出しの文(`## ` を除く。「テスト観点の一覧」「テストケースの一覧」「網羅の証明」「シナリオテストの表」「ケースごとの判定」「実行時の網羅の証明」「未実施の実行」など)で、文字列の配列のときは、画面はその章を配列の順に続けて出す。全文を出すときと `key` で出すときは null で、欠けてよい。`key` は、state.json のキーの値を出すときのキーの名前(`aiValues`、`findings`、`fixRecord`、`docCheck` など)。`open` は初めに開くか。`isNew` は新しくできた図か(ラベル「新しい」)。図と文書の欄を持つすべての画面で使う。`section` を使う画面は、段階 6 と 7 の成果物の承認と、段階 8 のテストの結果 |
| 照合と修正の組の回 | `checkRound` | オブジェクト `{"round": 整数, "limit": 整数}` か `null` | いまの回と上限(「1 回目(3 回まで)」)。段階 5 の画面で使う |
| 依頼の文の形の一覧 | `forms` | オブジェクト `{"form": 文字列, "stage": 整数, "skill": 文字列}` の配列か `null` | 規約 skill-making-flow の規則「最初の依頼から始める段階を決める」の表の全行。使う画面は、依頼の形を聞く |
| 中止の表示 | `abort` | オブジェクト `{"skill": 文字列, "step": 文字列, "reason": 文字列, "next": 文字列, "artifacts": 文字列の配列}` か `null` | 中止の表示の step の番号、理由、ユーザーが次にすること、中止までの成果物。使う画面は、中止 |
| 承認の前の要約 | `summaryCard` | オブジェクト `{"name": 文字列, "value": 文字列}` の配列か `null` | 承認の前に本文に出す要約の行。段階 2 は選んだ切り方、段階 3 は designing-skill-phases の step 9-4 の 5 行、段階 6 は designing-skill-test-cases の step 4-7 の 3 行(1. テスト観点、2. テストケース、3. 網羅の証明)、段階 7 は実施する範囲の案。使う画面は、成果物の承認 |
