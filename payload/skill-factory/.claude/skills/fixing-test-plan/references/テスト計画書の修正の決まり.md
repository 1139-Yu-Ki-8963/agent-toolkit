# テスト計画書の修正の決まり

## 判定の記録とテスト計画書から読む章と列

この章は、実行者が step 2-3 で判定の記録を、step 2-4 でテスト計画書を、step 2-5 で実行の記録を読むときに読む判定の基準である。

章と見出しの読み方:
- 実行者は、コードブロックの外にある「## 」で始まる行で、章を区切る。章の範囲は、見出しの行から、次の「## 」で始まる行の前までとし、「## 」で始まる行がその後ろになければ、ファイルの終わりまでとする。
- 実行者は、コードブロックの外にある「### 」で始まる行だけを、章の中の見出しとして読む。
- コードブロックは、3 つ以上の逆引用符で始まる行で開き、開いた行の逆引用符の数以上の逆引用符だけの行で閉じる。閉じる行がないときは、ファイルの終わりまでをブロックの中とする。
- 実行者は、表の値を、セルのとおりに一字一句写す。

判定の記録から読むもの(判定の記録は、testing-skill-with-template が書いた `判定の記録.md`):

| 読む章 | 取り出すもの |
|---|---|
| `## 対象` | 「- テスト計画書のパス:」と「- テスト対象のスキルのフォルダ:」の行の値 |
| `## ケースごとの判定` | 直すケースの番号の行の「ケースの番号」「実施したか」「合否」「根拠か未実施の理由」の値 |

- 「- テスト計画書のパス:」と「- テスト対象のスキルのフォルダ:」の行の値が `/` でも `~` でも始まらないときは、実行者は、作業フォルダを起点にした相対パスとして読む。
- 判定の記録があるフォルダは、判定の記録のパスの 1 つ上のフォルダとする。

テスト計画書から読むもの(テスト計画書は、designing-skill-test-cases が書き、designing-skill-test-scenarios が章を足した `テスト計画書.md`):

| 読む章 | 取り出すもの |
|---|---|
| `## テストケースの一覧` | 直すケースの番号の行の、「番号」「確かめ方」「対象の番号」「前提の状況」「依頼の文」「回答」「実行の回数」「期待する結果」「期待の根拠」「判定」の値 |
| `## 前提の状況として置くファイルとコマンド` | 「### 」の見出しごとの、見出しの名前と、見出しの下の全文 |
| `## シナリオテストの表` | 表のすべての行の「シナリオの番号」「含むケース」「実行の回数」の値 |

- 実行者は、テストケースの一覧の表のすべての行の「前提の状況」の値から、「### 」の見出しの名前ごとに、その名前を前提の状況に持つケースの番号の一覧を作る。

実行の記録(判定の記録があるフォルダの `<シナリオの番号>-<何回目か>-実行の記録.md`)の形:
- 見出し「## 通った step」「## チャットへの表示」「## 書いたファイル」「## 中止した step」「## step ごとの記述」の 5 つを、この順に持つ。
- 直すケースの実行の記録は、そのケースを「含むケース」に持つシナリオの、実行の回数の分のファイルとする。何回目かは、1 から実行の回数までの整数とする。
- 実行者は、「## 中止した step」が「なし」でないとき、「## チャットへの表示」の「**step <番号> で中止しました**」の塊の「- 理由:」の行を、中止の理由として取り出す。

## 期待する結果の直し方の決まり

この章は、実行者が step 3-2 で、直すケースの期待する結果を作り直すときに読む判定の基準である。

実行者は、直すケースの 1 件ごとに、次の順で新しい期待する結果を作る。

1. 期待の根拠の文を取り出す。行の「期待の根拠」の値が指す文を、次の表の指し先から取り出す。

| 期待の根拠の値 | 期待の根拠の文を取る場所 |
|---|---|
| phase の合格の条件の行 | テスト対象のスキルの SKILL.md の、その phase の「合格の条件」の下の箇条書きの行 |
| 最終出力の表の行 | テスト対象のスキルの SKILL.md の全体像の「最終出力」の表の、その行 |
| 中止の段落 | テスト対象のスキルの SKILL.md か `references/全スキル共通の決まり.md` の、その中止の段落の「理由」「中止までの成果物」の行と、step の番号 |
| 規約 skill-test-design-rule の「種別」の表の行 | 規約 skill-test-design-rule の「種別」の表の、その性質の行の「スキルでの期待」の列 |

2. 記号を埋める。期待の根拠の文の `<値>` の形の記号を、そのケースの前提の状況として置くファイルとコマンドの中身と、依頼の文と、回答から導いた値に置き換える。
3. 期待する結果の文を作る。designing-skill-test-cases のリファレンスの章「テストケースごとの項目の決め方」の「期待する結果:」の段の決まりのすべてを、同じに使って、置き換えた文を期待する結果の文にする。

- 実行者は、置き換えた期待する結果の文を、期待の根拠の文にある語と、前提の状況と依頼の文と回答にある値だけで書く。
- 実行者は、期待の根拠の文の記号を導けるだけの値が、前提の状況と依頼の文と回答にないときは、そのケースの期待する結果を直さず、ユーザーに見せる一覧に「期待する結果」と「記号を導く値がない」を置く。
- 新しい期待する結果が行の今の期待する結果と一字一句同じときは、実行者は、そのケースの期待する結果を直す箇所にしない。
- 行の「確かめ方」が「スクリプトで確かめる」のケースの期待する結果は、直さない。実行者は、ユーザーに見せる一覧に「期待する結果」と「スクリプトで確かめるケースの期待する結果は、このスキルの範囲の外」を置く。
- 新しい期待する結果に対して、章「テストケースごとの項目の決め方」の「判定:」の段が選ぶ判定が、行の「判定」の値と違うときは、実行者は、行の「判定」を変えず、ユーザーに見せる一覧に「判定」と「期待する結果に対する判定が <章が選ぶ判定> と違う」を置く。

## 前提の状況の直し方の決まり

この章は、実行者が step 3-2 で、直すケースの前提の状況に足すファイルを決めるときに読む判定の基準である。

実行者は、直すケースの 1 件ごとに、次の順で前提の状況に足すものを決める。

1. 足す対象のケースかを決める。ケースの実行の記録のうち、「## 中止した step」が「なし」でないものが 1 件以上あり、ケースの新しい期待する結果が中止の表示を求めていないケースだけを、足す対象とする。行の「対象の番号」が `AB-` で始まる ID を持つケースは、期待する結果が中止を求めるケースとする。
2. 中止の理由からパスを取り出す。足す対象のケースの、実行の記録の中止の理由の文が書くファイルとフォルダのパスを、すべて取り出す。パスの先頭の実行のフォルダのパスか `~` は、外して、実行のフォルダからの相対パスにする。
3. 足すパスを決める。取り出したパスのうち、ケースの前提の状況の見出しに、パスの行がないものを、足すパスにする。
4. 中身を決める。足すパスのファイルが、テスト対象のスキルのファイルか、テスト対象のスキルが読む別のスキルのファイルとして既にあるときは、元のファイルのパスを持たせ、変えて置くときだけ、変える箇所ごとの変える前の文と変えた後の文の組を、ケースの期待する結果、依頼の文、回答、期待の根拠の文に書かれた値だけで作る。足すパスのファイルが既にないときは、そのファイルにそのまま書く全文を、同じ文に書かれた値だけで作る。足すパスがフォルダのときは、そのフォルダの下に置くファイルのパスと、ファイルごとの中身を、この段落の 2 つの形のどちらかで、同じ文に書かれた値だけで作る。

- 実行者は、中止の理由の文がファイルとフォルダのパスを 1 つも書いていないケースを、ユーザーに見せる一覧に「前提の状況」と「中止の理由にファイルかフォルダのパスがない」を置く。
- 実行者は、中身を、期待する結果、依頼の文、回答、期待の根拠の文に書かれた値だけでは作れないパスを、ユーザーに見せる一覧に「前提の状況」と「<パス> の中身を決める値がない」を置く。
- ケースの前提の状況の見出しを、前提の状況にその見出しの名前を持つケースが、そのケースだけのとき、実行者は、その見出しの下に、足すファイルのパスと中身の行を足す。
- 前提の状況にその見出しの名前を持つケースが 2 件以上あるとき、実行者は、新しい見出しを作る。見出しの名前は、「<元の見出しの名前>に <足すファイルのパスの最後の名前の一覧> を足したもの」とする。新しい見出しは、元の見出しの下の行(環境の条件、パスと中身の行)のすべてと、足すファイルの行を持つ。ケースの「前提の状況」の値は、新しい見出しの名前にする。
- ケースの「前提の状況」が「なし」のとき、実行者は、新しい見出しを作る。見出しの名前は、「ケース <番号> の前提の状況」とする。ケースの「前提の状況」の値は、新しい見出しの名前にする。
- 足すファイルの行は、章「前提の状況として置くファイルとコマンド」の書き方のとおり、規約 skill-test-design-rule の規則「入力の欄の項目がファイルのとき、操作はそのファイルを前提の状況として置くファイルとコマンドに持つ」の 3 つの形のどれかとする。新しく作るファイルは、「- パス: <実行のフォルダからの相対パス>」と、「- 中身:」と、中身の全文を逆引用符の行で囲んだコードブロックの 3 つとする。既にあるファイルは、「- パス:」と「- 元のファイル: <元のファイルのパス。`~` から始める>」の行と、変えるときだけ変える箇所ごとの「- 変える前の文:」と「- 変えた後の文:」の組とする。

## 直しの案の表示

この章は、実行者が step 3-3 で、直す箇所をユーザーに見せるときに写す雛形である。ケースの 1 件ごとに、直す箇所を持つ項目だけを出す。名前が「一覧」で終わる値は、全スキル共通の決まりのとおりに書く。

**ケース <ケースの番号>**
- 期待する結果の前: <行の今の期待する結果。直さないときは「直さない」>
- 期待する結果の後: <新しい期待する結果。直さないときは「直さない」>
- 前提の状況: <ケースの「前提の状況」の値の前と後。直さないときは「直さない」>
- 足すファイル: <足すファイルのパスの一覧と、パスごとの足すファイルの行の全文。足さないときは「なし」>

直す箇所が 0 件のときは、上の塊の代わりに「直す箇所はありません。」の 1 行を出す。

続けて、ユーザーに見せる一覧を、次の塊で出す。一覧が 0 件のときは、「ユーザーに見せる一覧: なし」の 1 行を出す。

**ユーザーに見せる一覧: ケース <ケースの番号>**
- 直せない項目: <期待する結果 / 前提の状況 / 判定>
- 理由: <理由>

## 修正の結果の表示

この章は、実行者が step 5-1 で、修正の結果を表示するときに写す雛形である。名前が「一覧」で終わる値は、全スキル共通の決まりのとおりに書く。

**修正の結果**
- 直したケースの番号: <直しの案の、期待する結果か前提の状況を直すケースの番号を、小さい順に読点で区切ったもの。0 件のときは「なし」>

続けて、ユーザーに見せる一覧を、次の塊で出す。一覧が 0 件のときは、「ユーザーに見せる一覧: なし」の 1 行を出す。

**ユーザーに見せる一覧: ケース <ケースの番号>**
- 直せない項目: <期待する結果 / 前提の状況 / 判定>
- 理由: <理由>

直したケースの番号が「なし」のときは、続けて次の 1 行だけを出す。

```text
直したケースがないので、シナリオテストの表の作り直しとテストは依頼しません。
```

直したケースの番号が「なし」でないときは、続けて次の 3 行を出す。<テスト計画書のパス> は、判定の記録の内容のテスト計画書のパスとする。<出力先のフォルダ> は、判定の記録があるフォルダの 1 つ上のフォルダとする。

```text
次に、designing-skill-test-scenarios に「<テスト計画書のパス> にシナリオテストの表を足して。実施するケースの番号は <直したケースの番号>」と依頼してください。
できたら、testing-skill-with-template に「<テスト計画書のパス> を <出力先のフォルダ> にテストして」と依頼してください。
直したケースがすべて合格するなら、修正は終わりです。
```
