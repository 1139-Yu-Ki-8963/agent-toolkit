確認と承認の画面の設計書

作成日: 2026-10-26。この設計書は、要件定義書(同じフォルダの 要件定義書.md)の画面、中継サーバー、スキル 2 本を、どの利用の流れでも正しく状態遷移させるための設計を持つ。章 8 の実測の結果を前提にする。

1. 前提と、この設計書で使う語

語意味
作業のフォルダ1 回の作業の成果物と画面のファイルを置くフォルダ。決まり方は章 4。画面のファイルは、作業のフォルダの ui/ に置く
会話の ID中継サーバーを 1 回起動するごとに 1 つ作る ID。画面からのすべての送信は、この ID の 1 つの claude の会話になる
仮の会話作業のフォルダが決まる前の会話。ui/.pending/<会話の ID>.md(skill-factory の ui/ の下)に置く
画面のファイル作業のフォルダの ui/state.json、ui/figures/、ui/conversation.md

2. 利用の流れ

起動は、どの流れでも node ui/server.mjs の 1 つである。流れは、ユーザーが画面から最初に送る依頼の文の形で決まる。依頼の形と始める段階は、規約 skill-making-flow の規則 2 の表と docs/操作の流れ.md のとおりである。

流れ(最初の依頼の文の形)起動した時点の作業のフォルダ始める段階AI が state.json を最初に書く時点画面に最初に出る文書と決めてもらうこと
「<作業>をするスキルを作って」ない。AI がスキルの名前を提案し、段階 1 の step 3-2 で作る1段階 1 の最初の質問の前要件定義書.md(まだない)と、質問 1
要件定義書のパスある2段階 2 の切り方の案の選択の前要件定義書.md と、案の選択
分割設計書のパスある3段階 3 の最初の質問の前分割設計書.md と、質問 1
構成の案のパスある4段階 4 の出力先の質問の前構成の案.md と、出力先の質問
「<スキルの名前> を照合して」ある5(照合だけ)照合の指摘の一覧を見せる前SKILL.md と、「直してよいか」
「<スキルの名前> の <直す内容> を直して」ある5(fixing-skill から)依頼の一覧.md を書いたあと、承認の前依頼の一覧.md と、直しの承認
スキルのフォルダのパスと「テストを作って」ある5 から 6段階 5 の照合の前SKILL.md と、なし
テスト計画書のパスと実施する範囲ある7段階 7 を始める前tests/テスト計画書.md と、なし
テスト計画書のパスと「テストを流して」ある8段階 8 を始める前tests/テスト計画書.md と、なし
判定の記録のパスある5(fixing-skill から)直しの承認の前判定の記録.md と、直しの承認
どの形にも当たらない依頼(挨拶、質問)決まらないなし書かないなし。AI の返事に依頼の形の一覧が出る

段階 2 以降から始める流れでは、AI は、始める段階より前の段階の成果物の状態を「済み」にして書く。

3. 主体ごとの状態

3.1 中継サーバーと画面

stateDiagram-v2
  [*] --> 作業なし_待ち: 起動(会話の ID を作る)
  作業なし_待ち --> 作業なし_AI実行中: 送る(1 回目は --session-id)
  作業なし_AI実行中 --> 作業あり_AI実行中: AI が state.json を書く(作業のフォルダを決め、仮の会話を移す)
  作業なし_AI実行中 --> 作業なし_待ち: AI が state.json を書かずに終わる
  作業あり_AI実行中 --> 作業あり_決めてもらう: AI が決めてもらうことを持つ state.json を書いて終わる
  作業あり_AI実行中 --> 作業あり_待ち: AI が決めてもらうことなしで終わる
  作業あり_決めてもらう --> 作業あり_AI実行中: 承認のボタンか入力欄から送る(--resume)
  作業あり_待ち --> 作業あり_AI実行中: 入力欄から送る(--resume)

AI が実行中の間の送信は、中継サーバーが断る(同時に動かす claude は 1 つ)。作業のフォルダは、一度決まったら、中継サーバーを止めるまで変えない。別の作業に移るときは、ユーザーが中継サーバーを起動し直す。

3.2 段階ごとの成果物

stateDiagram-v2
  [*] --> 未着手
  未着手 --> 下書き: その段階のスキルを始める
  下書き --> 承認待ち: 成果物を書き、承認か答えを求める
  承認待ち --> 下書き: 直す
  承認待ち --> 済み: 承認する(段階 4、6 は完了の報告)
  済み --> 下書き: 段階 8 の不合格で段階 5 に戻る(段階 5 から 8)

4. 作業のフォルダの決まり方

流れ作業のフォルダ
新しくスキルを作る流れoutput/<作る順 1 のスキルの名前>/。分割設計書の 2 本目以降のスキルの段階 3 から 8 でも変えない。2 本目以降のスキルの成果物は output/<そのスキルの名前>/ に置き、state.json の「いまのスキルの名前と作る順」で見分ける
既にあるスキルへの流れ依頼の文が指すスキルのフォルダ output/<スキルの名前>/
中継サーバーの見つけ方起動したあとに output/*/ui/state.json が書かれた最初のフォルダ。起動の前からある state.json は見ない

5. 会話の扱い

sequenceDiagram
  actor U as ユーザー(画面)
  participant S as 中継サーバー
  participant C as claude
  participant F as 作業のフォルダ
  Note over S: 起動。会話の ID を作る
  U->>S: 1 回目の送信
  S->>S: 仮の会話に「ユーザー:」を書く
  S->>C: claude -p --session-id ID --output-format stream-json --verbose --permission-mode acceptEdits
  C-->>S: 途中の返事(1 つずつ)
  S->>S: 返事ごとに「Claude Code:」を書く
  C->>F: 段階 1 の step 3-2 でフォルダを作り、最初の質問の前に ui/state.json を書く
  S->>F: state.json を見つけ、仮の会話を ui/conversation.md の後ろに移す
  C-->>S: 質問 1 で終わる
  U->>S: 2 回目の送信(答えか承認のボタンの文)
  S->>F: ui/conversation.md に「ユーザー:」を書く
  S->>C: claude -p --resume ID ...
  • conversation.md の 1 件は、「ユーザー:」か「Claude Code:」で始まる行から、次の同じ形の行の前までとする。
  • 前の作業の conversation.md が作業のフォルダにあるときは、中継サーバーは、その後ろに新しい会話を足す。
  • claude が 0 でない終了コードで終わったときは、中継サーバーは、「Claude Code: (終了コード <番号>) <標準エラーの文>」を書く。
  • 仮の会話は、作業のフォルダに移したら消す。作業のフォルダが決まらないまま中継サーバーを止めたときは、ui/.pending/ に残す。

6. ファイルを書く時点と書く役

時点書くもの書く役
中継サーバーの起動なし(会話の ID は中継サーバーの中に持つ)中継サーバー
作業のフォルダが決まる前の送信と返事ui/.pending/<会話の ID>.md中継サーバー
段階のスキルがユーザーに質問か承認を出す前作業のフォルダの ui/state.json(決めてもらうことと文書のパス)updating-skill-factory-ui-state(AI が呼ぶ)
段階のスキルが成果物を書いたあと、承認を求める前作業のフォルダの ui/figures/<段階の番号>-<図の種類>.svg(規約 skill-making-flow の規則「確認と承認の画面を使うときに AI が足す動作」の表「描く図」にある段階だけ)drawing-skill-factory-figure(AI が呼ぶ)
段階の完了の報告のあと作業のフォルダの ui/state.json(次の段階と成果物の状態)updating-skill-factory-ui-state(AI が呼ぶ)
作業のフォルダが決まったあとの送信と返事作業のフォルダの ui/conversation.md中継サーバー

自由回答の質問(段階 1 の質問など)では、決めてもらうことの選択肢は 0 件とし、画面は問いの文だけを出す。そのため、updating-skill-factory-ui-state のキーの名前と型の対応表の choices を「0 件でもよい」に変える。

8. 実測の結果(2026-10-26、skill-factory の写しで本物の claude を動かした)

確かめたこと結果設計で決めたこと
--session-id で始め、--resume で続けると、前の会話を覚えているか覚えている(「7 を覚えて」のあとに「7」が返った)中継サーバーは、1 回目に --session-id、2 回目から --resume を使う
claude -p の標準出力は何か最後の返事だけ中継サーバーは、--output-format stream-json --verbose で途中の返事を 1 つずつ取る(「始めます」と「おわり」の 2 つが取れた)
--permission-mode acceptEdits で、Bash の node とファイルの書き込みが通るか通った(42 が返り、memo.txt ができた)中継サーバーは、--permission-mode acceptEdits を付ける

9. 受け入れの確認の計画

確かめること方法
新しくスキルを作る流れで、段階 1 の最初の質問の前に state.json ができ、仮の会話が作業のフォルダに移り、2 回目の送信が同じ会話の続きになり、承認のボタンの文で段階 2 に進むskill-factory の写しで、本物の claude を、中継サーバーの要求の処理を直接呼ぶテストで動かす
「<スキルの名前> を照合して」の流れで、前の ui/ を画面に出さず、段階 5 の照合のスクリプトが権限で止まらない同じ方法
画面の 9 機能画面を表示しないブラウザで、段階 1 から 8 を開く(前と同じ方法)
本物の中継サーバーとブラウザでの通しユーザーが /sandbox でローカルの待ち受けを許したあとに 1 回通す。許さないときは、ユーザーの PC で確かめてもらう

10. 画面のイメージの部品と、部品が読むもの(2026-10-28)

部品読むもの決まり
開いた直後の画面の見出しと文ui/はじめに.md(/api/start)作業のフォルダが決まる前だけ、会話の欄の上に出す
実行中のスキル/api/status の skillCalls(Skill のツールで呼んだスキルの名前を呼んだ順に並べたもの)と subagents(結果が返っていない Agent か Task のツールの呼び出しの数)と busy名前は、最後に呼んだ段階のスキルとする。そのあとに補助のスキルを呼んだときは「+ 補助のスキルの名前」を、AI が返事を書いている間にサブエージェントがいるときは「サブエージェント N 体」を添える。AI が返事を書いている間だけ回る印を付ける。スキルをまだ呼んでいないときは出さない
段階で使うスキルと規約の一覧ui/段階ごとのスキルと規約.json(/api/stages)と skillCalls実行中のスキルを押すと開く。表は、このファイルの 1 か所だけに持つ。スキルの状態は「実行中」(最後に呼んだ段階のスキル)、「呼んだ(N 番目)」(初めて呼んだ順)、「まだ呼んでいない」とする
右の欄の 4 つの状態state.json の documentPath のファイルがあるかと busyファイルがなく AI が返事を書いている: 作っている。ファイルがあり AI が返事を書いている: 書き直している。ファイルがあり AI が答えを待っている: 出している。ファイルがなく AI も返事を書いていない: まだない
文書のパスの表示/api/status の workDir(skill-factory からの作業のフォルダの相対パス)と documentPath<workDir>/<documentPath> の形で出す
質問の一覧state.json の questions(title、added、removed、items の番号と文と選択肢と答え)答えが null の問いがあり、AI が返事を書いていないときに、文書の代わりに右の欄に出す。答えが null の問いだけを並べ、見出しの横に「全 N 問(回答済み A 問、残り R 問)」を出す。added か removed が 1 以上なら「前の答えで、質問が X 問増え、Y 問減りました。」を出す。送る文は、答えた問いだけを「質問の番号: 答え」の形で 1 行に 1 問ずつ並べたものとする。送ったあとは、questions が変わるまで出さない
返答の候補state.json の decision.replieschoices が 0 件で replies が 1 件以上のときに、問いの吹き出しの下に出す。押すと候補の文を入力欄に入れ、送らない。送ったあとと、AI が返事を書いている間は出さない

サブエージェントの数は、stream-json の Agent か Task の tool_use の id を、同じ id の tool_result が来るまで数える。バックグラウンドで動かすサブエージェントの数え方は、本物の claude の stream-json でまだ確かめていない。
