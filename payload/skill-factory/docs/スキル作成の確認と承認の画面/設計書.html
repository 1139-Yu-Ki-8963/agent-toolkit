2. 利用の流れ

起動は、どの流れでも node ui/server.mjs の 1 つである。流れは、ユーザーが画面から最初に送る依頼の文の形か、「続きから」で決まる。依頼の形と始める段階は、規約 skill-making-flow の規則 3 の表と docs/操作の流れ.md のとおりである。

「<作業>をするスキルを作って」ない。AI が output/<開始日時>/ を段階 1 の前に作る1段階 1 のスキルを始める前要件定義書.md(まだない)と、質問 1
開いた直後の画面の「続きから」ユーザーが押した行の作業のフォルダ離れたときの段階書かない(離れたときの state.json のまま)離れたときの文書と決めてもらうこと
要件定義書のパスある2段階 2 の切り方の案の選択の前要件定義書.md と、案の選択
分割設計書のパスある3段階 3 の最初の質問の前分割設計書.md と、質問 1
構成の案のパスある4段階 4 の出力先の質問の前構成の案.md と、出力先の質問

スキルのフォルダのパスと「テストを作って」ある5 から 6段階 5 の照合の前SKILL.md と、なし
テスト計画書のパスと実施する範囲ある7段階 7 を始める前tests/テスト計画書.md と、なし

段階 2 以降から始める流れでは、AI は、始める段階より前の段階の成果物の状態を「済み」にして書く。既にある作業のフォルダの下の成果物のパスから始める流れでは、AI は、そのパスの作業のフォルダを使う。

5. 会話の扱い

sequenceDiagram
  actor U as ユーザー(画面)
  participant S as 中継サーバー
  participant C as claude
  participant F as 作業のフォルダ
  Note over S: 起動。会話の ID を作る
  U->>S: 1 回目の送信
  S->>S: 仮の会話に「ユーザー:」を書く
  S->>C: claude -p --session-id ID --output-format stream-json --verbose --permission-mode acceptEdits --model <CLAUDE_MODEL>(文は標準入力。1 行目は「画面: 新規」)
  C-->>S: 途中の返事(1 つずつ)
  S->>S: 返事ごとに「Claude Code:」を書く
  C->>F: 段階 1 の前に output/<開始日時>/ を作り、段階 1 のスキルを始める前に ui/state.json を書く
  S->>F: state.json を見つけ、仮の会話を ui/conversation.md の後ろに移し、ui/session.json を書く
  C-->>S: 質問 1 で終わる
  U->>S: 2 回目の送信(答えか承認のボタンの文)
  S->>F: ui/conversation.md に「ユーザー:」を書く
  S->>C: claude -p --resume ID ...(1 行目は「画面: output/<開始日時>/」)

続きからの流れ(章 11)

sequenceDiagram
  actor U as ユーザー(画面)
  participant S as 中継サーバー
  participant C as claude
  participant F as 作業のフォルダ
  U->>S: GET /api/works
  S->>F: output/*/ui/state.json を読む
  S-->>U: 途中の作業の一覧
  U->>S: POST /api/resume(作業のフォルダ)
  S->>F: ui/session.json の会話の ID を読む
  S-->>U: 作業のフォルダと会話の ID
  U->>S: 送信(答えか承認のボタンの文)
  S->>C: claude -p --resume ID ...(1 行目は「画面: output/<開始日時>/」)
  alt --resume が 0 でない終了コードで終わる
    S->>S: 新しい会話の ID を作る
    S->>F: ui/session.json を書き直す
    S-->>U: 「前の会話を続けられないので、新しい会話で始めます。成果物のパスを送ってください」
    U->>S: 成果物のパスの送信
    S->>C: claude -p --session-id 新しい ID ...
  end
  • conversation.md の 1 件は、「ユーザー:」か「Claude Code:」で始まる行から、次の同じ形の行の前までとする。
  • 中継サーバーは、送る文を claude の標準入力で渡し、1 行目に「画面: <作業のフォルダ>」(作業のフォルダが決まる前は「画面: 新規」)を置く。AI は、この 1 行目で規約 skill-making-flow の規則「確認と承認の画面を使うときに AI が足す動作」を当てる。
  • 前の作業の conversation.md が作業のフォルダにあるときは、中継サーバーは、その後ろに新しい会話を足す。
  • claude が 0 でない終了コードで終わったときは、中継サーバーは、「Claude Code: (終了コード <番号>) <標準エラーの文>」を書く。
  • 仮の会話は、作業のフォルダに移したら消す。作業のフォルダが決まらないまま中継サーバーを止めたときは、ui/.pending/ に残す。
  • 中継サーバーは、Ctrl+C を受けると、動いている claude の子プロセスに SIGTERM を送り、5 秒以内に終わらなければ SIGKILL を送ってから終わる。書いている途中の返事は conversation.md に残らず、直前の保存までが残る(要件定義書の章 5)。
