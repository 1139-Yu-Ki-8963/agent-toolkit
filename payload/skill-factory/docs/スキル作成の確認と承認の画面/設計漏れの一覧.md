## 4. 担当の分け方

担当は、画面の要件定義書の章 2「責務境界」の役(画面、中継サーバー、スキル、AI)とする。文書(要件定義書、設計書、規約)は、担当の責務を書き留める場所であり、担当ではない。スキルは、画面なしで単独で動く 13 本と、画面のためだけに使う 2 本に分け、単独で動く 13 本の手順は画面の都合で変えない。

| 担当 | 責務 | 受け持つ漏れ |
|---|---|---|
| 画面(`ui/index.html`) | 状態のファイルを読んで表示し、入力を中継サーバーに送る | L2、L3 の再開の入口の表示、L6、L12、L15、L16、L23、L24 |
| 中継サーバー(`ui/server.mjs`) | 画面の入力を Claude Code に渡し、返事を記録する | L1、L3 の会話の ID の保存、L4、L6、L7、L8、L9、L12、L17、L19、L20、L21、L22、L25 |
| 画面のスキル(updating-skill-factory-ui-state) | `state.json` を書く | L13、L14 の作業の名前の持ち方、L15、L16 |
| AI(規約 skill-making-flow に従う) | 段階を進め、スキルを呼ぶ | L3 の再開の流れ、L14 の名前でフォルダを作らないこと、L18 |

- L5 は、単独で動くスキル defining-skill-requirements 自身の再開の設計であり、画面の漏れから外す。
- L10 と L11 は、文書同士の食い違いであり、どちらにそろえるかを決めてから文書を直す。

直す順は、要件定義書、設計書、規約、画面のスキル、中継サーバー、画面の順とし、担当は、直した設計に従って実装を直す。
