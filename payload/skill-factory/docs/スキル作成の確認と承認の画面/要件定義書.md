# スキル作成の確認と承認の画面の要件定義書

この文書は、skill-factory(規約 skill-making-flow の「適用する場面」が決める、AI が 8 段階でスキルを作るフォルダ)の、スキル作成の確認と承認の画面の要件定義書である。

作成日: 2026-10-26。依頼の文: 画面の HTML の責務を、裏で実行したスキルが作ったものの表示と、プロンプトの入力と、ダウンロードに限る。図を作る機能は持たせない。その前提で、業務要件、責務境界、機能要件、新しく足すスキルを設計する。

## 1. 業務要件

- この画面は、skill-factory で Claude Code がスキルを作る 8 段階(規約 skill-making-flow の表)を、ユーザーがブラウザで追い、段階ごとの図と文書を見て、承認か直す指示を返すための画面である。
- ユーザーは、この画面だけで段階 1 から 8 を終えられる。
- 画面に出る図と文書は、すべてスキルが書いたファイルである。

## 2. 責務境界

この設計は、次の 4 つの役を分ける。

| 役 | 持つ責務 | 持たない責務 |
|---|---|---|
| 画面(HTML 1 枚) | 画面の状態のファイルを読む。図のファイルと文書のファイルを表示する。ユーザーの入力(プロンプト、承認の選択)を中継に送る。ファイルをダウンロードさせる。 | 図を描く。文書を変える。段階を決める。スキルを呼ぶ。ファイルを書く。成果物の中身を計算する(件数の集計、網羅の判定を含む)。 |
| 中継(ローカルの小さな HTTP サーバー) | `output/<スキルの名前>/ui/` のファイルを画面に返す。画面からの入力を、中継の起動ごとに 1 つの会話として、1 回目は `claude -p --session-id <会話の ID>`、2 回目からは `claude -p --resume <会話の ID>` の形で Claude Code に渡す。Claude Code の返事を `conversation.md` に追記する。 | 図を描く。段階を決める。 |
| スキル(skill-factory の 13 本と、新しく足す 2 本) | 成果物(要件定義書から判定の記録まで)を書く。成果物から図のファイルを描く。画面の状態のファイルを書く。 | 画面の表示の形を決める。 |
| Claude Code(AI) | 規約 skill-making-flow に従って段階を進め、スキルを呼ぶ。 | 図のファイルを自分で描く(新しく足すスキルを呼んで描く)。 |

### 2.1 画面が読むファイル

`state.json`、`figures/`、`conversation.md` の置き場は、`output/<スキルの名前>/ui/` とする。成果物の md の置き場は、規約 skill-making-flow の表のとおりとする。

| ファイル | 書く役 | 中身 |
|---|---|---|
| `state.json` | スキル updating-skill-factory-ui-state | 表の下の一覧のとおり |
| `figures/<段階の番号>-<図の名前>.svg` | スキル drawing-skill-factory-figure | 段階の図 1 つ |
| `conversation.md` | 中継 | ユーザーの入力と Claude Code の返事を、上から順に追記した記録 |
| 成果物の md(要件定義書、分割設計書、構成の案、SKILL.md、テスト計画書、判定の記録) | 既存のスキル | 段階の文書。画面は `state.json` の文書のパスで読む |
| `ui/段階ごとのスキルと規約.json`(skill-factory の `ui/` の下) | skill-factory を直す人が書く | 段階ごとに、使うスキルの名前と種類(段階か補助)と役目、使う規約の名前と読み込む条件。中身は、規約 skill-making-flow の表と、各スキルの SKILL.md から作る |

`state.json` は、次の 9 つを持つ。

- 作業の名前
- いまのスキルの名前と作る順
- いまの段階の番号
- 成果物の状態
- 図のタブの一覧(タブの名前と図のファイルのパス)
- 文書のパス
- 決めてもらうこと(問いの文と、選択肢の文の一覧と、返答の候補の文の一覧)
- ダウンロードできるファイルの一覧
- 質問の一覧(見出しと、前の答えで増えた問数と減った問数と、問いごとの番号と文と選択肢と答え)

### 2.2 画面から中継に送るもの

| 送るもの | 中継がすること |
|---|---|
| プロンプトの文 | `conversation.md` に「ユーザー:」の行で追記し、Claude Code に同じ文を渡す |
| 承認の選択(押した選択肢の文) | 選択肢の文を、送るもの「プロンプトの文」と同じに扱う |
| ダウンロードの要求(ファイルのパス) | そのファイルを返す |
| 質問の一覧の答え(答えた問いだけを「問いの番号: 答え」の形で 1 行に 1 つずつ並べた文) | 送るもの「プロンプトの文」と同じに扱う |
| 状態の問い合わせ | AI が返事を書いているか、中継の起動のときに `claude --version` が終了コード 0 を返したか、Skill のツールで呼んだスキルの名前の一覧(呼んだ順)、結果が返っていない Agent のツールの呼び出しの数、作業のフォルダのパスを返す |

## 3. 機能要件

画面は、次の 13 の機能だけを持つ。

| 番号 | 機能 | 入力 | 出力 |
|---|---|---|---|
| F1 | 画面の状態を読む | `state.json` | 画面の各部の表示 |
| F2 | 段階の帯を出す | `state.json` の段階の番号と成果物の状態 | 8 段階の帯。画面は、済んだ段階にチェックの記号を付け、いまの段階を青で塗る |
| F3 | 会話を出す | `conversation.md` | 左の会話。画面は、「ユーザー:」の行を右寄せにし、Claude Code の行を左寄せにする |
| F4 | 図を出す | `state.json` の図のタブの一覧と SVG のファイル | 右上の図。ユーザーは、タブで図を切り替える |
| F5 | 文書を出す | `state.json` の文書のパスと md のファイルと、AI が返事を書いているか | 右下の文書。画面は、md を見出し、表、箇条書きの形で表示する。画面は、ファイルがないときは「作っている」か「まだない」を、ファイルがあり AI が返事を書いているときは「書き直している」を出す |
| F6 | プロンプトを送る | 入力欄の文 | 中継への送信。画面は、送ったあと入力欄を空にする |
| F7 | 承認の選択を送る | `state.json` の決めてもらうことの選択肢の文の一覧 | 画面は、選択肢の数だけボタンを出し、ユーザーが押した選択肢の文を F6 と同じ形で送る |
| F8 | ファイルをダウンロードする | `state.json` のダウンロードできるファイルの一覧 | ブラウザのダウンロード |
| F9 | 画面の更新を受ける | 中継からの更新の知らせ、または前の読み込みから 2 秒の経過 | F1 の読み直し |
| F10 | 接続の状態を出す | 状態の問い合わせの答え | ヘッダーの右端の状態。画面は、中継につながらないときと、中継の起動のときに `claude --version` が終了コード 0 を返さなかったときは、ヘッダーの下に直し方を出す |
| F11 | 実行中のスキルと、段階で使うスキルと規約の一覧を出す | 状態の問い合わせの答えと `ui/段階ごとのスキルと規約.json` | ヘッダーの実行中のスキルの名前(サブエージェントの数か、あとに呼んだ補助のスキルを添える)。ユーザーが実行中のスキルの名前を押すと、画面は、いまの段階のスキルごとの状態(まだ呼んでいない、実行中、呼んだ)と、呼んだスキルの呼んだ順と、規約の一覧を開く |
| F12 | 質問の一覧に答える | `state.json` の質問の一覧 | 右の欄の質問の一覧。全体の問数と回答済みの問数と残りの問数を出し、答えた問いだけを F6 と同じ形で送る |
| F13 | 返答の候補を出す | `state.json` の決めてもらうことの返答の候補 | 選択肢がない問いの下の候補のボタン。ユーザーが押すと、画面は、候補の文を入力欄に入れる |

### 3.1 画面と中継と図のファイルの作りの要件

- 画面は、HTML 1 枚とし、外部のライブラリは md の表示用の 1 本だけとする。
- ユーザーは、`skill-factory/` で 1 つのコマンドで中継を起動する。
- 図のファイルは SVG とし、画面はそのまま埋め込む。

## 4. 新しく足すスキルと、直す規約

### 4.1 スキル

| スキルの名前 | 使う場面 | 目的 | 最終出力 | 入力 |
|---|---|---|---|---|
| drawing-skill-factory-figure | 段階の成果物ができたあと、その段階の図を描くとき | 成果物の md から、図の種類ごとに決まった形の SVG を 1 つ描く | `ui/figures/<段階の番号>-<図の名前>.svg` | 図の種類(17 種類のどれか)、元の成果物のパス、出力先のフォルダ |
| updating-skill-factory-ui-state | 段階のスキルがユーザーへの完了の報告を出したあと、または決めてもらうことが変わったとき | 画面の状態のファイルを、いまの段階と成果物に合わせて書く | `ui/state.json` | 2.1 の `state.json` が持つ 9 つの値 |

drawing-skill-factory-figure のリファレンスは、17 種類の図と、元の成果物の章の対応を、種類ごとの章で持つ。17 種類は、全体の流れ図、作業の流れ図、値の出どころの図、分割の比較図、入出力の契約の図、phase と step の流れ図、シーケンス図、受け渡す値と中間成果物の寿命の図、中止の一覧、階層の図、照合と修正の輪と指摘の色分け、網羅の図、シナリオの経路の図、判定の結果の図、配置図、成果物の対応の図、成果物の状態の図である。

### 4.2 スキルを 1 本にするか、成果物ごとに分けるか

- 候補 A(推奨): drawing-skill-factory-figure 1 本で、図の種類を入力にする。根拠: 使う場面(成果物から図を描く)と目的が 1 つで、規約 skill-writing-rule の規則「1 つのスキルが扱う場面と目的は 1 つ」に合う。
- 候補 B: 成果物ごとに 7 本(要件定義書の図、分割設計書の図、構成の案の図、SKILL.md の図、照合の図、テスト計画書の図、判定の記録の図)。根拠: 元の成果物ごとに読む章が違う。採らない理由: 7 本の SKILL.md が同じ手順を持ち、手順を直す人は、7 か所を直す。

### 4.3 画面と Claude Code をつなぐ形

- 候補 A(推奨): 中継(ローカルの HTTP サーバー)を置き、画面はファイルの読みと入力の送信を中継に頼む。根拠: ファイルの監視と Claude Code の起動は、ブラウザの外で動くプログラムだけができる。画面の責務を表示と入力に限ったまま、承認のボタンを 1 回押すと Claude Code が動く。
- 候補 B: 中継を置かず、ユーザーが画面でフォルダを選び、画面はそのフォルダのファイルを読み、ユーザーはプロンプトをクリップボードに写して端末に貼る。根拠: 足すものが HTML 1 枚で済む。採らない理由: 承認のたびにユーザーが端末に戻るので、業務要件「この画面だけで段階 1 から 8 を終えられる」を満たさない。

### 4.4 直す規約

- AI は、規約 skill-making-flow の規則「ユーザーへの完了の報告のあとに次の段階を始める」に、次の 1 文を足す。「AI は、段階 n のスキルがユーザーへの完了の報告を出したら、次の段階を始める前に、drawing-skill-factory-figure でその段階の図を描き、updating-skill-factory-ui-state で画面の状態を書く。」
- AI は、規約 skill-making-flow の規則「段階と、段階が使うスキルと、段階の入力と最終出力」の表に列「描く図」を足し、段階ごとに描く図の種類をその列に書く。

## 5. スキルと画面と中継を作り、規約を直す順

1. updating-skill-factory-ui-state(画面の状態のファイルの形が決まる)
2. 画面の HTML(作る人は、状態のファイルと手で置いた SVG で表示を確かめる)
3. 中継
4. drawing-skill-factory-figure(作る人は、図の種類を、全体の流れ図、分割の比較図、phase と step の流れ図の 3 つから作り始め、残りの 14 種類をあとで足す)
5. 規約 skill-making-flow に 4.4 の 1 文と列を足す

## 6. ユーザーに決めてもらうこと

- 4.2 の候補 A(スキル 1 本)でよいか。
- 4.3 の候補 A(中継を置く)でよいか。
- 作る順は 5 のとおりでよいか。
