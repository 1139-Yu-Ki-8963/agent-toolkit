# スキル作成の確認と承認の画面の要件定義書

この文書は、skill-factory(規約 skill-making-flow の「適用する場面」が決める、AI が 8 段階でスキルを作るフォルダ)の、スキル作成の確認と承認の画面の要件定義書である。

作成日: 2026-10-26。改訂日: 2026-10-28(設計漏れの一覧.md の L1、L3、L4、L8、L9、L10、L11、L14、L21、L22 を直し、受け入れたリスクの一覧を足した)。依頼の文: 画面の HTML の責務を、裏で実行したスキルが作ったものの表示と、プロンプトの入力と、ダウンロードに限る。図を作る機能は持たせない。その前提で、業務要件、責務境界、機能要件、新しく足すスキルを設計する。

## 1. 業務要件

- この画面は、skill-factory で Claude Code がスキルを作る 8 段階(規約 skill-making-flow の規則「スキルだけで動く 8 段階の流れ」の表)を、ユーザーがブラウザで追い、段階ごとの図と文書を見て、承認か直す指示を返すための画面である。
- ユーザーは、この画面だけで段階 1 から 8 を終えられる。
- ユーザーは、中継サーバーを止めたあとに起動し直し、途中の作業の続きを同じ画面で進められる。
- 画面に出る図と文書は、すべてスキルが書いたファイルである。

## 2. 責務境界

この設計は、次の 5 つの役を分ける。表の「依存する形」は、その役が読むものの形のうち、形が変わるとその役を直すことになるものである。

| 役 | 読むもの | 書くもの | 持たない責務 | 依存する形 |
|---|---|---|---|---|
| 画面(`ui/index.html` 1 枚) | `state.json`、`conversation.md`、`figures/` の SVG、成果物の md、`ui/段階ごとのスキルと規約.json`、中継サーバーの答え | なし(ユーザーの入力を中継サーバーに送る) | 図を描く。文書を変える。段階を決める。スキルを呼ぶ。ファイルを書く。成果物の中身を計算する(件数の集計、網羅の判定を含む)。画面は、表示のための数(質問の回答済みの数と残りの数)だけは数える | `state.json` のキーと型、`conversation.md` の 1 件の区切り、中継サーバーの API の名前と答えの形 |
| 中継サーバー(`ui/server.mjs`) | 画面からの送信、`output/*/ui/state.json`、`ui/session.json`、`claude` の標準出力(stream-json) | `conversation.md`、`session.json`、仮の会話のファイル | 図を描く。段階を決める。`state.json` を書く | `claude` のコマンドの引数と stream-json の形、`state.json` のキー `stage`、`artifacts`、`decision`、`questions`、`workName` |
| 画面のスキル updating-skill-factory-ui-state | AI が渡す 9 つの値 | `ui/state.json` | 段階のスキルの表示を読む。値を決める | 値の決まり(自分のリファレンス「画面の状態のファイルの形」が正本) |
| 画面のスキル drawing-skill-factory-figure | 段階の成果物の md | `ui/figures/<段階の番号>-<図の名前>.svg` | 画面の表示の形を決める | 成果物の md の章の名前(自分のリファレンスの図の種類ごとの章が持つ) |
| AI(Claude Code) | 規約 skill-making-flow、段階のスキルの表示(質問、承認の要求、完了の報告) | 段階のスキルの成果物(段階のスキルの手順で) | 図のファイルを自分で描く。`state.json` を自分で書く | 規約 skill-making-flow の規則「確認と承認の画面を使うときに AI が足す動作」 |

- 段階のスキルの表示(質問の文、選択肢、完了の報告)を `state.json` の値(決めてもらうこと、質問の一覧、成果物の状態)に変換する役は、AI である。その対応表は、updating-skill-factory-ui-state のリファレンス「画面の状態のファイルの形」が持つ。段階のスキル 10 本と補助のスキル 3 本の手順は、画面を使うときも同じとする。

### 2.1 画面が読むファイル

`state.json`、`session.json`、`figures/`、`conversation.md` と成果物の md の置き場は、章 4 の表のとおりとする。

| ファイル | 書く役 | 中身 |
|---|---|---|
| `ui/state.json` | スキル updating-skill-factory-ui-state | 表の下の一覧のとおり |
| `ui/session.json` | 中継サーバー | 会話の ID、作業のフォルダのパス、書いた日時 |
| `ui/figures/<段階の番号>-<図の名前>.svg` | スキル drawing-skill-factory-figure | 段階の図 1 つ |
| `ui/conversation.md` | 中継サーバー | ユーザーの入力と Claude Code の返事を、上から順に追記した記録 |
| 成果物の md(要件定義書、分割設計書、構成の案、SKILL.md、テスト計画書、判定の記録) | 段階のスキル | 段階の文書。画面は `state.json` の文書のパスで読む |
| `ui/はじめに.md`(skill-factory の `ui/` の下) | skill-factory を直す人が書く | 開いた直後の画面の見出しと文 |
| `ui/段階ごとのスキルと規約.json`(skill-factory の `ui/` の下) | skill-factory を直す人が書く | 段階ごとに、使うスキルの名前と種類(段階か補助)と役目、使う規約の名前と読み込む条件。中身は、規約 skill-making-flow の表と、各スキルの SKILL.md から作る |

`state.json` は、次の 9 つを持つ。

- 作業の名前
- いまのスキルの名前と作る順
- いまの段階の番号
- 成果物の状態
- 図のタブの一覧(タブの名前と図のファイルのパス)
- 文書のパス
- 決めてもらうこと(問いの文と、選択肢の文の一覧と、返答の候補の文の一覧)
- ダウンロードできるファイルの一覧
- 質問の一覧(見出しと、前の答えで増えた問数と減った問数と、問いごとの番号と文と選択肢と答え)

### 2.2 画面から中継サーバーに送るもの

| 送るもの | 中継サーバーがすること |
|---|---|
| プロンプトの文 | `conversation.md` に「ユーザー:」の行で追記し、章 7 の形で Claude Code に渡す |
| 承認の選択(押した選択肢の文) | 選択肢の文を、送るもの「プロンプトの文」と同じに扱う |
| ダウンロードの要求(ファイルのパス) | そのファイルを返す |
| 質問の一覧の答え(答えた問いだけを「問いの番号: 答え」の形で 1 行に 1 つずつ並べた文) | 送るもの「プロンプトの文」と同じに扱う |
| 状態の問い合わせ | AI が返事を書いているか、中継サーバーの起動のときに `claude --version` が終了コード 0 を返したか、Skill のツールで呼んだスキルの名前の一覧(呼んだ順)、結果が返っていない Agent のツールの呼び出しの数、作業のフォルダのパスを返す |
| 途中の作業の問い合わせ | `output/*/ui/state.json` から作った途中の作業の一覧(章 6)を返す |
| 続きからの要求(作業のフォルダのパス) | 章 6 のとおりに会話を続ける |

## 3. 機能要件

画面は、次の 15 の機能だけを持つ。

| 番号 | 機能 | 入力 | 出力 |
|---|---|---|---|
| F1 | 画面の状態を読む | `state.json` | 画面の各部の表示 |
| F2 | 段階の帯を出す | `state.json` の段階の番号と成果物の状態 | 8 段階の帯。画面は、済んだ段階にチェックの記号を付け、いまの段階を青で塗る |
| F3 | 会話を出す | `conversation.md` | 左の会話。画面は、「ユーザー:」の行を右寄せにし、Claude Code の行を左寄せにする |
| F4 | 図を出す | `state.json` の図のタブの一覧と SVG のファイル | 右上の図。ユーザーは、タブで図を切り替える |
| F5 | 文書を出す | `state.json` の文書のパスと md のファイルと、AI が返事を書いているか | 右下の文書。画面は、md を見出し、表、箇条書きの形で表示する。画面は、ファイルがなく AI が返事を書いているときは「作っている」を、ファイルがなく AI が返事を書いていないときは「まだない」を、ファイルがあり AI が返事を書いているときは「書き直している」を出す |
| F6 | プロンプトを送る | 入力欄の文 | 中継サーバーへの送信。画面は、送ったあと入力欄を空にする |
| F7 | 承認の選択を送る | `state.json` の決めてもらうことの選択肢の文の一覧 | 画面は、選択肢の数だけボタンを出し、ユーザーが押した選択肢の文を F6 と同じ形で送る |
| F8 | ファイルをダウンロードする | `state.json` のダウンロードできるファイルの一覧 | ブラウザのダウンロード |
| F9 | 画面を読み直す | 前の読み込みから 2 秒の経過 | F1 の読み直し |
| F10 | 接続の状態を出す | 状態の問い合わせの答え | ヘッダーの右端の状態。画面は、中継サーバーにつながらないときと、中継サーバーの起動のときに `claude --version` が終了コード 0 を返さなかったときは、ヘッダーの下に直し方を出す |
| F11 | 実行中のスキルと、段階で使うスキルと規約の一覧を出す | 状態の問い合わせの答えと `ui/段階ごとのスキルと規約.json` | ヘッダーの実行中のスキルの名前(サブエージェントの数か、あとに呼んだ補助のスキルを添える)。ユーザーが実行中のスキルの名前を押すと、画面は、いまの段階のスキルごとの状態(まだ呼んでいない、実行中、呼んだ)と、呼んだスキルの呼んだ順と、規約の一覧を開く |
| F12 | 質問の一覧に答える | `state.json` の質問の一覧 | 右の欄の質問の一覧。画面は、全体の問数と回答済みの問数と残りの問数を出し、答えた問いだけを F6 と同じ形で送る |
| F13 | 返答の候補を出す | `state.json` の決めてもらうことの返答の候補 | 選択肢がない問いの下の候補のボタン。ユーザーが押すと、画面は、候補の文を入力欄に入れる |
| F14 | 途中の作業の一覧を出す | 途中の作業の問い合わせの答え | 開いた直後の画面の、入力欄の下の一覧(章 6)。画面は、作業のフォルダが決まる前で、途中の作業が 1 件以上あるときに出す |
| F15 | 続きから始める | ユーザーが押した行の作業のフォルダのパス | 続きからの要求の送信。画面は、答えを受けたら、その作業のフォルダの `state.json` で F1 を行う |

### 3.1 画面と中継サーバーと図のファイルの作りの要件

- 画面は、HTML 1 枚とし、外部のライブラリは md の表示用の 1 本だけとする。
- ユーザーは、`skill-factory/` で 1 つのコマンドで中継サーバーを起動する。
- 図のファイルは SVG とし、画面はそのまま埋め込む。

## 4. フォルダの設計

フォルダは、規約 skill-making-flow の規則「作業のフォルダとスキルのフォルダ」のとおりとする。

| フォルダ | パス | 作る役と時点 |
|---|---|---|
| 作業のフォルダ | `output/<開始日時>/`(`<開始日時>` は `YYYY-MM-DD-HHMM`) | AI が、段階 1 を始める前に作る |
| スキルのフォルダ | `output/<開始日時>/skills/<スキルの名前>/` | AI が、段階 3 を始める前に作る |
| 画面のファイルのフォルダ | `output/<開始日時>/ui/`(`state.json`、`session.json`、`conversation.md`、`figures/`) | updating-skill-factory-ui-state が、最初に `state.json` を書くときに作る |

- 1 つの作業の成果物と画面のファイルは、すべて作業のフォルダの下にある。そのため、中継サーバーは、作業のフォルダの下のファイルだけを画面に返せばよく、2 本目以降のスキルの成果物も画面に出る。
- 作業の名前(ユーザーに見せる日本語の名前)は、`state.json` の作業の名前が持つ。ユーザーが作業の名前を変えても、フォルダの名前は開始日時のままとする。

## 5. 保存

次の表の書く役(2.1 の表の「書く役」)が、表の書く時点に自動で保存する。

| ファイル | 書く時点 |
|---|---|
| `ui/state.json` | 規約 skill-making-flow の規則「確認と承認の画面を使うときに AI が足す動作」の 3 つの時点(段階のスキルを始める前、段階のスキルがユーザーに質問か承認を出す前、段階の完了の報告のあと) |
| `ui/conversation.md` | 画面からの送信のたびと、Claude Code の返事を受けるたび |
| `ui/session.json` | 作業のフォルダが決まったとき(新しい作業では AI が最初に `state.json` を書いたとき、続きからでは会話の ID が変わったとき) |

ユーザーが画面から離れたときに残るものは、離れ方で決まる。

| 離れ方 | 残るもの |
|---|---|
| ブラウザのタブを閉じる | すべて残る。中継サーバーと Claude Code は動き続け、AI の返事は `conversation.md` と `state.json` に書かれる |
| 中継サーバーを止める(AI が返事を書いていないとき) | 直前の保存まで残る |
| 中継サーバーを止める(AI が返事を書いている途中) | 直前の保存まで残り、書いている途中の返事だけが残らない。中継サーバーは、Claude Code の子プロセスを止めてから終わる(章 7) |

## 6. 再開

- 途中の作業の一覧(F14)の 1 行は、次の 5 つを持つ。
  - 作業の名前(`state.json` の `workName`)
  - 段階の番号と成果物の名前(`stage` と `artifacts`)
  - 状態(`artifacts` の 8 件目が「済み」なら「完了」、`decision` があれば「承認待ち」、`questions` に答えのない問いがあれば「質問中(N 問のうち A 問に回答)」、それ以外は「作業中」)
  - 最後の保存(`state.json` のファイルの更新日時)
  - 作業のフォルダのパス
- 画面は、「完了」の作業を、「終わった作業 N 件」の折りたたみの中に出す。
- ユーザーが行の「続きから」を押すと、中継サーバーは、その作業のフォルダの `ui/session.json` の会話の ID で、次の送信から `claude -p --resume <会話の ID>` を使う。
- 会話の ID が使えないとき(`session.json` がない、または `--resume` が 0 でない終了コードで終わった)は、中継サーバーは、新しい会話の ID で会話を始め、`session.json` を書き直し、画面に「前の会話を続けられないので、新しい会話で始めます。成果物のパスを送ってください」を出す。ユーザーは、成果物のパス(要件定義書、分割設計書、構成の案、テスト計画書、判定の記録のどれか)を送り、AI は、規約 skill-making-flow の規則「最初の依頼から始める段階を決める」で段階を決める。

## 7. 中継サーバーの仕様

| 項目 | 仕様 |
|---|---|
| 起動 | `skill-factory/` で `node ui/server.mjs`。起動時の引数はない。待ち受けのポートは環境変数 `PORT`(既定は 4173)とする |
| ポートが使用中のとき | 中継サーバーは、「ポート <番号> は使用中です。PORT=<別の番号> node ui/server.mjs で起動してください」を標準エラーに出し、終了コード 1 で終わる |
| モデル | 中継サーバーは、環境変数 `CLAUDE_MODEL`(既定は `sonnet`)を、毎回 `--model` で渡す |
| Claude Code の呼び方 | 1 回目は `claude -p --session-id <会話の ID>`、2 回目からは `claude -p --resume <会話の ID>`。共通の引数は `--output-format stream-json --verbose --permission-mode acceptEdits --model <モデル>` |
| 文の渡し方 | 中継サーバーは、送る文を Claude Code の標準入力で渡す |
| 送る文の 1 行目 | 中継サーバーは、送る文の 1 行目に「画面: <作業のフォルダ>」を置く。作業のフォルダが決まる前は「画面: 新規」とする。2 行目から、ユーザーの文を置く |
| Origin の確認 | 中継サーバーは、POST の要求の `Origin` ヘッダーが `http://localhost:<ポート>` か `http://127.0.0.1:<ポート>` のときだけ受け、それ以外は 403 を返す |
| 同時の送信 | 中継サーバーは、AI が返事を書いている間の送信を 409 で断る |
| 子プロセスの停止 | 中継サーバーは、`Ctrl+C`(SIGINT)を受けると、動いている Claude Code の子プロセスに SIGTERM を送り、5 秒以内に終わらなければ SIGKILL を送ってから終わる |
| `GET /api/status` | 状態の問い合わせの答え(2.2) |
| `GET /api/stages` | `ui/段階ごとのスキルと規約.json` |
| `GET /api/start` | `ui/はじめに.md` |
| `GET /api/works` | 途中の作業の一覧(章 6) |
| `POST /api/resume` | 本文は作業のフォルダのパス。中継サーバーは、章 6 のとおりに会話を続け、作業のフォルダと会話の ID を返す |
| `POST /api/prompt` | 本文は送る文。中継サーバーは、`conversation.md` に追記し、Claude Code に渡す |
| `GET /files/<パス>` | 作業のフォルダの下のファイル。作業のフォルダの外は 403 |
| 作業のフォルダの決まり方 | 続きからでは、ユーザーが押した行の作業のフォルダ。新しい作業では、送信の前になかった `output/*/ui/state.json` が送信のあとに現れた最初のフォルダ。一度決まった作業のフォルダは、中継サーバーを止めるまで同じとする |

## 8. 運用

| 作業 | 手順 |
|---|---|
| 起動 | ユーザーは、章 7 の起動のとおりに中継サーバーを起動し、ブラウザで `http://localhost:4173/` を開く |
| 停止 | ユーザーは、中継サーバーの端末で `Ctrl+C` を押す(章 7) |
| 更新(画面か中継サーバーを直したあと) | ユーザーは、中継サーバーを止め、起動し直し、ブラウザの画面を読み直す。続きは、開いた直後の画面の「続きから」で始める |

## 9. 受け入れたリスクの一覧

次の表は、設計漏れの一覧.md で「設計漏れ」とされた項目のうち、この設計で直さないと決めたものである。

| 番号 | 引用(設計漏れの一覧.md の「決まっていないこと」) | 観点(設計漏れの一覧.md の「観点」) | 直さない理由 |
|---|---|---|---|
| L2 | 画面が、AI が書いた md と SVG を `innerHTML` でそのまま出すので、返事に混ざった HTML が画面で動く | セキュリティ | 画面は、ユーザーの PC の中継サーバーだけにつながり、出す内容は、ユーザー自身が頼んだ AI の成果物である。中継サーバーは、章 7 の Origin の確認を持つ |
| L7 | `claude` が返事を返さないときのタイムアウトがなく、送信が永久に 409 になる | エラー処理 | 段階 8 のテストは 1 回の返事が数十分かかることがあり、上限の時刻を決めると正しい作業を止める。ユーザーは、`Ctrl+C` で中継サーバーを止めて子プロセスを止められる |
| L8 | 要件 F9「中継サーバーからの更新の知らせ」が実装にない(ポーリングだけ) | 責務の境界と整合 | 画面は 2 秒ごとに読み直す(F9)。2 秒の遅れは、承認の作業に影響しない |

## 10. 新しく足すスキルと、規約が持つ決まり

### 10.1 スキル

| スキルの名前 | 使う場面 | 目的 | 最終出力 | 入力 |
|---|---|---|---|---|
| drawing-skill-factory-figure | 段階の成果物ができたあと、その段階の図を描くとき | 成果物の md から、図の種類ごとに決まった形の SVG を 1 つ描く | `ui/figures/<段階の番号>-<図の名前>.svg` | 図の種類(16 種類のどれか)、元の成果物のパス、出力先のフォルダ |
| updating-skill-factory-ui-state | 規約 skill-making-flow の規則「確認と承認の画面を使うときに AI が足す動作」の 3 つの時点 | 画面の状態のファイルを、いまの段階と成果物に合わせて書く | `ui/state.json` | 2.1 の `state.json` が持つ 9 つの値 |

drawing-skill-factory-figure のリファレンスは、16 種類の図と、元の成果物の章の対応を、種類ごとの章で持つ。16 種類は、作業の流れ図、値の出どころの図、分割の比較図、入出力の契約の図、phase と step の流れ図、シーケンス図、受け渡す値と中間成果物の寿命の図、中止の一覧、階層の図、照合と修正の輪と指摘の色分け、網羅の図、シナリオの経路の図、判定の結果の図、配置図、成果物の対応の図、成果物の状態の図である。

### 10.2 スキルを 1 本にするか、成果物ごとに分けるか

- 候補 A(採用): drawing-skill-factory-figure 1 本で、図の種類を入力にする。根拠: 使う場面(成果物から図を描く)と目的が 1 つで、規約 skill-writing-rule の規則「1 つのスキルが扱う場面と目的は 1 つ」に合う。
- 候補 B: 成果物ごとに 7 本(要件定義書の図、分割設計書の図、構成の案の図、SKILL.md の図、照合の図、テスト計画書の図、判定の記録の図)。根拠: 元の成果物ごとに読む章が違う。採らない理由: 7 本の SKILL.md が同じ手順を持ち、手順を直す人は、7 か所を直す。

### 10.3 画面と Claude Code をつなぐ形

- 候補 A(採用): 中継サーバー(ローカルの HTTP サーバー)を置き、画面はファイルの読みと入力の送信を中継サーバーに頼む。根拠: ファイルの監視と Claude Code の起動は、ブラウザの外で動くプログラムだけができる。画面の責務を表示と入力に限ったまま、承認のボタンを 1 回押すと Claude Code が動く。
- 候補 B: 中継サーバーを置かず、ユーザーが画面でフォルダを選び、画面はそのフォルダのファイルを読み、ユーザーはプロンプトをクリップボードに写して端末に貼る。根拠: 足すものが HTML 1 枚で済む。採らない理由: 承認のたびにユーザーが端末に戻るので、業務要件「この画面だけで段階 1 から 8 を終えられる」を満たさない。

### 10.4 規約 skill-making-flow が持つ決まり

この画面のために規約 skill-making-flow が持つ決まりは、次の 3 つである。

- 規則「作業のフォルダとスキルのフォルダ」: 章 4 のフォルダ。
- 規則「最初の依頼から始める段階を決める」: 続きからで会話の ID が使えないときに、ユーザーが送る成果物のパスから段階を決める表。
- 規則「確認と承認の画面を使うときに AI が足す動作」: 依頼の文の 1 行目が「画面: <作業のフォルダ>」か「画面: 新規」のときだけ、AI が `state.json` を書く 3 つの時点と、段階ごとに描く図。
