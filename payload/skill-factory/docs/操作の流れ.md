# 操作の流れ

この文書は、skill-factory でユーザーが claude を起動してから、作ったスキルを使うプロジェクトにリンクするまでの操作の流れを、1 つの図で持つ文書です。README の「使い方」の表が依頼の文の形と始める段階を持つのに対して、この文書は、段階の順と、ユーザーが承認か答えを出す点と、AI が止まる点を持ちます。依頼の文の形の全件は、規約 skill-making-flow の規則「最初の依頼から始める段階を決める」の表にあります。

## 図の読み方

- 角の丸い四角は、ユーザーの操作です。
- 四角は、AI が段階のスキルを流す作業です。段階の番号は、規約 skill-making-flow の規則「段階と、段階が使うスキルと、段階の入力と最終出力」の表の番号です。
- ひし形は、分岐です。
- 二重線の四角は、AI が止まり、ユーザーの次の操作を待つ点です。

## 図

```mermaid
flowchart TD
  U1([ユーザーが skill-factory で claude を起動し、README の表の形で依頼する])
  U1 --> Q{依頼の文の形}
  Q -->|「<作業>をするスキルを作って」| S1[段階 1 defining-skill-requirements<br>要件定義書を書く]
  Q -->|要件定義書のパス| S2
  Q -->|分割設計書のパス| S3
  Q -->|構成の案のパス| S4
  Q -->|「<スキルの名前> を照合して」| S5c
  Q -->|「<スキルの名前> の <直す内容> を直して」| S5f[段階 5 fixing-skill<br>依頼の一覧で直す]
  Q -->|スキルのフォルダのパスと「テストを作って」| S5c
  Q -->|テスト計画書のパスと実施する範囲| S7
  Q -->|テスト計画書のパスと「テストを流して」| S8
  Q -->|判定の記録のパス| S5r[段階 5 fixing-skill<br>判定の記録で直す]
  S1 --> A1([ユーザーが要件定義書を承認]) --> S2[段階 2 designing-skill-structure<br>分割設計書を書く]
  S2 --> A2([ユーザーが分割設計書を承認]) --> S3[段階 3 designing-skill-phases<br>構成の案を書く]
  S3 --> A3([ユーザーが構成の案を承認]) --> A4([ユーザーが段階 4 の出力先を答える]) --> S4[段階 4 drafting-skill-with-template<br>SKILL.md とリファレンスを書く]
  S4 --> S5c[段階 5 checking-skill-with-template<br>雛形と規約に照らす]
  S5f --> S5c
  S5r --> S5c
  S5c --> J5{指摘の一覧}
  J5 -->|指摘なし| J5b{依頼は照合だけか}
  J5 -->|指摘あり、3 回目まで| S5x[段階 5 fixing-skill<br>指摘の一覧で直す] --> S5c
  J5 -->|3 回目でも指摘あり| STOP1[[AI が止まり、指摘の一覧を見せる]]
  J5b -->|照合だけ| STOP2[[AI が止まる]]
  J5b -->|それ以外| J6{テスト計画書があるか}
  J6 -->|ない| S6[段階 6 designing-skill-test-cases<br>テスト計画書を書く]
  J6 -->|ある| S8
  S6 --> A7([ユーザーが実施する範囲を答える]) --> S7[段階 7 designing-skill-test-scenarios<br>シナリオテストの表を足す]
  S7 --> S8[段階 8 testing-skill-with-template<br>判定の記録を書く]
  S8 --> J8{判定の記録}
  J8 -->|全ケース合格| END[[AI がスキルのパスとリンクのコマンドを示す]]
  J8 -->|「不合格」か「判定できない」のケースがある| S5r
  END --> U2([ユーザーが、使うプロジェクトでリンクのコマンドを実行する])
  S3 -.->|分割設計書のスキルの本数だけ繰り返す| S3
```

## 確認と承認の画面で進めるとき

ユーザーは、ターミナルで claude を起動する代わりに、skill-factory で `node ui/server.mjs` を実行し、ブラウザで http://127.0.0.1:4173/ を開いて、同じ依頼の文を画面の入力欄から送れます。図の段階の順と止まる点は、画面で進めるときも同じです。AI は、段階のスキルが質問か承認を出す前と、段階の完了の報告のあとに、作業のフォルダの `ui/state.json` を書き、画面は、その state.json の文書と決めてもらうことを出します。依頼の形ごとの開き方は、`docs/スキル作成の確認と承認の画面/設計書.html` の章 2 にあります。

## 図にある成果物の置き場

作ったスキルと、要件定義書、分割設計書、構成の案、依頼の一覧は、`output/<スキルの名前>/` に置かれます。テスト計画書と判定の記録は、`output/<スキルの名前>/tests/` に置かれます。
