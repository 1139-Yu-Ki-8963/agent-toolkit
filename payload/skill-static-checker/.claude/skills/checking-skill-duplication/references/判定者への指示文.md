# 判定者への指示文

このリファレンスは、step 4-3 で判定者に渡す指示文と、判定者が返す書式を持つ。

## 仕分けの指示文

step 4-2 で `scripts/make-judge-prompt.mjs` が、「指示文」のコードブロックの空欄を、候補の JSON の値で埋め、その後ろに「サブエージェントが返す書式」の節の中身(最後の段落を除く)を付ける。step 4-3 で、同じ指示文を 2 人の判定者に渡す。空欄は、<調べるスキルのフォルダ>、<比べるスキルの置き場>、<重複の候補の JSON のパス>、<似たスキルの JSON のパス> の 4 つ。

### 指示文

```text
この指示文を受け取った AI は、スキルの重複の判定者です。ほかの判定者の判定は見ずに、1 人で判定してください。ファイルは読むだけにし、書き換えないでください。

調べるスキルのフォルダ: <調べるスキルのフォルダ>
比べるスキルの置き場: <比べるスキルの置き場>
重複の候補の JSON: <重複の候補の JSON のパス>
似たスキルの JSON: <似たスキルの JSON のパス>

1. 重複の候補の JSON を全文読み、pairs の 1 組ごとに、a と b の節を、ファイルと行から全文読んで、次の 4 つの区分のどれか 1 つに仕分けてください。
- 重複: 2 つの節が、同じ指示を繰り返し、片方を消しても指示が減らない。
- 意図した詳しい説明: 片方が要約で、もう片方がその詳細。
- 型が求める繰り返し: 雛形か書式が、step ごとに同じ文面を求める。山かっこの値や step の番号だけが違う手順は、これに当たる。
- 同じ話題で目的が違う: 語は似ているが、扱う場面か動作が違う。

2. 似たスキルの JSON を全文読み、skills の 1 本ごとに、その folder の SKILL.md を読み、調べるスキルの name と description と比べ、次の 3 つの区分のどれか 1 つに仕分けてください。文字の近さ(similarity)は読む順の目安で、判定には使わないでください。
- 役目が同じ: 同じ依頼で、どちらのスキルも発動し、同じ成果物を出す。
- 役目が一部重なる: 一部の依頼で、どちらのスキルも発動し得る。
- 別の役目: 発動する依頼と成果物が違う。

3. すべての組とすべてのスキルを仕分けたら、「サブエージェントが返す書式」の形の JSON を 1 つだけ、json のコードブロックに入れて返してください。理由は、日本語の 1 文で書いてください。
```

### サブエージェントが返す書式

`json` のコードブロック 1 つに、次の形の JSON を入れる。sections は、重複の候補の JSON の pairs のすべての組を、skills は、似たスキルの JSON の skills のすべてのスキルを、1 件ずつ持つ。候補が 0 件の側は、空の配列とする。

```json
{
  "sections": [
    { "id": "組1", "category": "重複", "reason": "2 つの節が、同じ委任の手順を、同じ文で書いている。" }
  ],
  "skills": [
    { "id": "スキル1", "category": "別の役目", "reason": "直す対象が、スキルではなくテスト計画書である。" }
  ]
}
```

- id: 重複の候補の JSON の pairs の id
- id: 似たスキルの JSON の skills の id(「スキル<番号>」の形。例: スキル1)。name は同じ値のスキルが 2 本以上あり得るので、使わない
- category: 指示文の区分の語の 1 つ
- reason: 判定の理由の 1 文

返り値の文が `json` のコードブロックをちょうど 1 つ持たないか、中身がこの形でないときは、step 4-5 の `scripts/save-judgment.mjs` が、その判定者の判定をすべて判定がないとして書く。
