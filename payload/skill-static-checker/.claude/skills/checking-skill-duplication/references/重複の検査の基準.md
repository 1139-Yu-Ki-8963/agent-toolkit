# 重複の検査の基準

このリファレンスは、重複の候補の抜き出し方と、判定者の仕分けから合否を決める基準を持つ。このスキルは、規約 skill-writing-rule の規則「AI を乗っ取る書き方」の「スキルが外部へ送るものは、最終出力として挙がるものだけ」に合わせて、埋め込みの提供元に本文を送らず、手元の文字の近さで候補を挙げる。意味の判定は、スキルを動かしている AI の実行環境の中の、別の文脈の判定者 2 人に任せる。判定者が読む本文は、AI の実行環境がすでに使っている AI の提供元に届き、それより外には送らない。

## 節の分け方と文字の近さ

step 3-2 で、`scripts/find-duplicate-sections.mjs` が候補を抜き出すときの基準。

### 比べるファイルと節

- 比べるファイル: 調べるスキルのフォルダの `SKILL.md` と、`references/` の直下の `.md` のファイル。
- 除くファイル: `references/全スキル共通の決まり.md`。雛形の章を一字一句そのまま写す決まりのファイルなので、写しが正しい形である。
- 節: 「##」から「######」の見出しの行から、次の見出しの行の前までの本文。コードブロックの中の「#」の行は、見出しにしない。
- 節の見出し: 上の見出しを「 > 」でつないだもの(例: `phase 3 指摘の仕分け > step 3-5 判定者 2 体に仕分けさせる [委任] > 手順`)。
- 見出しの段は、「#」の数とする。上の見出しは、その節より段の小さい見出しのうち、最も近いものを段ごとに 1 つずつたどる。
- 除く節: 見出しが「── step <番号> の情報 ──」の節(雛形が全 step に求める形の欄)と、空白と記号を除いた本文が 60 字より短い節。

### 文字の近さの測り方

- スクリプトは、節の本文を NFKC で正規化し、空白と記号を除き、続いた 3 字の組の数を数える。
- 3 字の組の重みは、TF-IDF(多くの節に出る組ほど軽くする重み)とし、2 つの節の近さは、重みの並びのなす角の余弦(0 から 1)とする。
- 丸める前の近さが 0.60 以上の組を、候補とする。重複の候補の JSON と報告に書く近さは、小数 3 桁に丸めた値とする。候補は近さの大きい順に並べ、上の 30 組までを判定者に渡す。30 組を超えた分は判定せず、状態を「調べきれなかった」にする。
- 候補に入れる本文は、1 つの節につき、先頭の 2,000 字までとする。判定者は、ファイルと行から全文を読める。

### 線を決めた測りの値

2026-11-19 に、雛形に従って書いたスキル 1 本に 4 種類の節を足して、写した節との近さを測った。

| 足した節 | 近さ |
|---|---|
| 1 つの節をそのまま写した節 | 1.000 |
| 写して 4 か所の語を変えた節 | 0.941 |
| 同じ指示を別の言葉で書き直した節 | 0.192 |
| 別の話題の節 | 0.014 |

同じ日に、雛形に従って書いたスキル 4 本で測った近さの上位は、除く節を除く前は、「── step の情報 ──」の節の組(最大 1.000)と手順の組だった。除く節を除いた後の上位は、0.60 から 0.83 の、[委任] の step の手順のような、雛形の文面を多く持つ手順の組だった。0.60 の線は、写した節と語を少し変えた節を必ず拾い、雛形の文面を多く持つ組も拾って、判定者の「型が求める繰り返し」で落とす線である。言い換えた節(0.192)は、この線で拾えない。長い節の一部の段落だけを写した節は、節の全体で比べるので、近さが下がり、拾えないことがある。

## 比べるスキルの選び方

step 3-3 で、`scripts/find-similar-skills.mjs` が比べるスキルを並べるときの基準。

- 比べるスキルの置き場: 依頼の文面にあれば、その置き場を `--catalog` でスクリプトに渡す。なければ、`--catalog` を渡さず、スクリプトの既定の値の、調べるスキルのフォルダの親のフォルダと比べる。
- 比べるスキル: 置き場の直下のフォルダのうち、`SKILL.md` を持ち、調べるスキル自身(シンボリックリンクの先で比べる)でないもの。
- 比べる項目: フロントマターの name と description。`>` か `|` の複数行の形の description と、次の行に字下げして続く description は、続く字下げした行をつないで読む。閉じていない引用符で始まる値と、読めない形の `>` か `|` の値は、読めない description とする。
- 番号: 比べるスキルに、近さの順に「スキル<番号>」(例: スキル1)を付け、判定者の判定と結ぶ。name が同じスキルが 2 本以上あっても、別々に判定するためである。
- 並べ方: name と description の文字の近さ(「節の分け方と文字の近さ」の章と同じ測り方)の大きい順。文字の近さは、判定者が読む順の目安で、合否には使わない。判定者は、並べたすべてのスキルの name と description を読み、意味で仕分ける。
- 上限: 60 本。60 本を超えた分は判定せず、状態を「調べきれなかった」にする。
- 調べるスキルの description を読めないときは、比べるスキルが 0 本でも、状態を「調べきれなかった」にする。name か description を読めない比べるスキルがあるときも、状態を「調べきれなかった」にする。
- 調べるスキルの description を読め、比べるスキルが 0 本のときは、状態を「対象なし」にする。「対象なし」は、合否を変えない。

## 合否の決め方

step 5-1 で、`scripts/merge-judgments.mjs` が判定をまとめるときの基準。判定者は 2 人で、候補を 1 件ずつ、互いの判定を見ずに仕分ける。

### 1 本の中の重複の区分と重さ

| 区分 | 意味 | 2 人とも | 1 人だけ |
|---|---|---|---|
| 重複 | 2 つの節が、同じ指示を繰り返し、片方を消しても指示が減らない | 重大 | 注意 |
| 意図した詳しい説明 | 片方が要約で、もう片方がその詳細 | 指摘にしない | 指摘にしない |
| 型が求める繰り返し | 雛形か書式が、step ごとに同じ文面を求める | 指摘にしない | 指摘にしない |
| 同じ話題で目的が違う | 語は似ているが、扱う場面か動作が違う | 指摘にしない | 指摘にしない |

### スキルどうしの重なりの区分と重さ

| 区分 | 意味 | 重さ |
|---|---|---|
| 役目が同じ | 同じ依頼で、どちらのスキルも発動し、同じ成果物を出す | 2 人とも「役目が同じ」なら重大 |
| 役目が一部重なる | 一部の依頼で、どちらのスキルも発動し得る | 重大に当たらず、1 人以上が「役目が同じ」か「役目が一部重なる」なら注意 |
| 別の役目 | 発動する依頼と成果物が違う | 2 人とも「別の役目」なら指摘にしない |

### 合否

- 不合格: 重さ「重大」の指摘が 1 件以上ある。
- 調べきれなかった: 重大の指摘がなく、次のどれかに当たる。調べきれなかったことは、重複がない証拠にならない。
  - 候補が上限を超えた検査か、name か description を読めない比べるスキルを持つ検査か、調べるスキルの description を読めない検査がある。
  - 判定者の 1 人が、同じ候補に 2 件以上の判定を返した。
  - 判定者のどちらかの判定がないか、区分の表にない判定の候補がある(判定がない候補)。
  - 判定者の返り値の文が形と違い、その判定者の判定がすべてない。形のとおりの返り値は、`json` のコードブロックをちょうど 1 つ持ち、その中身が、id、category、reason の文字列を持つ項目の配列 sections と skills を持つ JSON である。形を見るのは step 4-5 の `scripts/save-judgment.mjs` で、形と違う返り値の判定は、判定がないとして扱う。
- 合格: 重大の指摘がなく、2 つの検査の状態が「済み」か「対象なし」である。注意の指摘は、合否を変えない。
- 終了コード: 合格なら 0、不合格か調べきれなかったなら 1。
