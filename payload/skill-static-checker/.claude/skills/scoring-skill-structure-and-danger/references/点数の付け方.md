# 点数の付け方

このリファレンスは、指摘の重さの段階と、構造の点数の出し方と、危険の合否の決め方と、指摘の JSON の形と、AI が書く判定の JSON の形を持つ。

## 重さの段階

細かい重さ(CRITICAL、HIGH、MEDIUM、LOW、INFO の 5 つ)を、3 つの段階に当てる。指摘の JSON は、細かい重さも持つ。

| 段階 | 細かい重さ | 意味 |
|---|---|---|
| 重大 | CRITICAL、HIGH | 配る前と使う前に直す |
| 注意 | MEDIUM、LOW | 直すほうがよい |
| 参考 | INFO | 点数と合否に入れず、知らせるだけ |

## 構造の点数

step 5-1 で、`scripts/score.mjs` が出す。

1. 区分「構造」の指摘を、4 つの分野(正しさ、見つけやすさ、信頼性、効率)に分ける。
2. 分野ごとに、100 点から、その分野の指摘の減点の合計を引く。0 点より下にはしない。
3. 分野の点数に、次の表の重みをかけて足したものを、丸める前の構造の点数とする。報告とチャットに出す構造の点数は、丸める前の点数を小数点以下 1 桁に丸めたものとする。ちょうど半分のときは、偶数の側へ丸める(96.25 点は 96.2 点)。
4. 丸める前の構造の点数が 70 点以上で、重さ「重大」の構造の指摘が 1 件もないときに、構造を合格とする。丸めた点数が 70.0 点でも、丸める前の点数が 70 点より低ければ不合格とし、点数が 70 点以上でも、重さ「重大」の構造の指摘が 1 件でもあれば不合格とする。

| 分野 | 重み |
|---|---|
| 正しさ | 0.35 |
| 見つけやすさ | 0.25 |
| 信頼性 | 0.25 |
| 効率 | 0.15 |

項目ごとの減点は、リファレンス `references/構造の静的チェックの項目.md` にある。

## 危険の合否

step 5-1 で、`scripts/score.mjs` が決める。危険は点数にしない。区分「危険」の指摘のうち、重さ「重大」が 1 件でもあれば、危険を不合格とし、1 件もなければ、合格とする。重さ「注意」と「参考」の危険の指摘は、数えて報告に載せるが、合否に入れない。

## 道具ごとの読み込みの助言

step 5-1 で、`scripts/score.mjs` が数える。区分「助言」の指摘は、道具ごとの読み込みの違いを知らせるだけのものなので、点数と合否に入れず、報告に載せるだけとする。

## 指摘の JSON の形

step 3-2 から 3-4、3-7、4-1 から 4-5、4-8 で、スクリプトが `<一時フォルダのパス>/findings/` に書く JSON の形。実行者は、この形の JSON を書かない。step 5-1 の `scripts/score.mjs` は、検査の名前、状態、区分、重さ、細かい重さ、分野、減点の値が次の決まりのとおりかを確かめ、違えば終了コード 2 で終わる。

```json
{
  "script": "<検査の名前>",
  "target": "<調べるスキルのフォルダの絶対パス>",
  "status": "済み",
  "findings": [
    {
      "check": "<検査の名前>",
      "item": "<項目>",
      "kind": "<構造、危険、助言のどれか>",
      "severity": "<重大、注意、参考のどれか>",
      "source_severity": "<CRITICAL、HIGH、MEDIUM、LOW、INFO のどれか>",
      "dimension": "<正しさ、見つけやすさ、信頼性、効率のどれか。危険と助言は null>",
      "deduction": 0,
      "file": "<調べるスキルのフォルダからの相対パス>",
      "line": 0,
      "message": "<見つけたこと>",
      "fix": "<直し方>"
    }
  ]
}
```

- status は、「済み」「対象なし」「調べられなかった」のどれかとする。
- deduction は、区分「構造」の指摘だけが 0 より大きい数を持つ。
- line は、行がない指摘(フォルダやファイルの全体の指摘)では 0 とする。
- 重さと細かい重さの組は、「重さの段階」の章の表のとおりとする。
- 検査の名前は、check-schema、check-structure、check-harness、ai-structure、check-secrets、check-unicode、check-code-risk、check-license、check-dependencies、ai-danger のどれかとし、すべての JSON の target は同じとする。
- step 3-7 で `scripts/save-ai-findings.mjs` が書くファイルは `ai-structure.json`、検査の名前は「ai-structure」とする。step 4-8 で書くファイルは `ai-danger.json`、検査の名前は「ai-danger」とする。指摘が 0 件のときも、findings を空の配列にして書く。
- check-structure の JSON は、参考の数の値の配列 metrics も持つ。check-dependencies の JSON は、調べた部品の配列 packages も持つ。check-license の JSON は、見分けたライセンス license も持つ。

## AI が書く判定の JSON の形

step 3-6 と 4-7 で、実行者が `<一時フォルダのパス>/ai-input/` に書く JSON の形。実行者は、判定の結果として、項目、ファイル、行、中身、直し方だけを書く。重さ、細かい重さ、分野、減点、検査の名前、調べるスキルのフォルダは、step 3-7 と 4-8 の `scripts/save-ai-findings.mjs` が付ける。

```json
[
  {
    "item": "<項目>",
    "file": "<調べるスキルのフォルダからの相対パス>",
    "line": 0,
    "message": "<見つけたこと>",
    "fix": "<直し方>"
  }
]
```

- 1 件の指摘は、item、file、line、message、fix の 5 つだけを持つ。
- item は、step 3-6 ではリファレンス `references/構造の静的チェックの項目.md` の「日本語の章の中身を見る基準」の章の表の項目、step 4-7 ではリファレンス `references/危険の静的チェックの型.md` の「AI を乗っ取る書き方を見る基準」の章の表の項目の名前を、一字一句そのまま書く。
- file は、調べるスキルのフォルダの中にあるファイルの相対パスとする。line は、0 以上の整数とし、行がない指摘では 0 とする。message と fix は、空でない文とする。
- 指摘が 0 件のときは、`[]` を書く。
- step 3-6 で書くファイルは `ai-structure.json`、step 4-7 で書くファイルは `ai-danger.json` とする。
