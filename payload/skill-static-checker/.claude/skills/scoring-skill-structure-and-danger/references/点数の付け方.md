# 点数の付け方

このリファレンスは、指摘の重さの段階と、構造の点数の出し方と、危険の合否の決め方と、指摘の JSON の形を持つ。点数の出し方は、SkillEvaluator の `models/quality.py` と `constants.py` の値を写したものである。

## 重さの段階

SkillEvaluator の 5 つの重さを、3 つの段階に当てる。指摘の JSON は、元の重さも持つ。

| 段階 | SkillEvaluator の重さ | 意味 |
|---|---|---|
| 重大 | CRITICAL、HIGH | 配る前と使う前に直す |
| 注意 | MEDIUM、LOW | 直すほうがよい |
| 参考 | INFO | 点数と合否に入れず、知らせるだけ |

SkillEvaluator の品質の検査の error、warning、info は、`validators/quality_score.py` の 445 行目のとおり、HIGH、MEDIUM、LOW に当てる。

## 構造の点数

step 5-1 で、`scripts/score.mjs` が出す。

1. 区分「構造」の指摘を、4 つの分野(正しさ、見つけやすさ、信頼性、効率)に分ける。
2. 分野ごとに、100 点から、その分野の指摘の減点の合計を引く。0 点より下にはしない。
3. 分野の点数に、次の表の重みをかけて足し、小数点以下 1 桁に丸めたものを、構造の点数とする。
4. 構造の点数が 70 点以上なら、構造を合格とする。

| 分野 | 重み | SkillEvaluator の分野 |
|---|---|---|
| 正しさ | 0.35 | correctness |
| 見つけやすさ | 0.25 | discoverability |
| 信頼性 | 0.25 | reliability |
| 効率 | 0.15 | efficiency |

合格ラインの 70 点は、SkillEvaluator の QUALITY_DEFAULT_MIN_SCORE である。項目ごとの減点は、リファレンス `references/構造の静的チェックの項目.md` にある。

## 危険の合否

step 5-1 で、`scripts/score.mjs` が決める。危険は点数にしない。区分「危険」の指摘のうち、重さ「重大」が 1 件でもあれば、危険を不合格とし、1 件もなければ、合格とする。重さ「注意」と「参考」の危険の指摘は、数えて報告に載せるが、合否に入れない。

## 道具ごとの読み込みの助言

step 5-1 で、`scripts/score.mjs` が数える。区分「助言」の指摘は、点数と合否に入れず、報告に載せるだけとする。SkillEvaluator の `validators/harness.py` が、自分を助言だけの検査としているためである。

## 指摘の JSON の形

step 3-2 から 3-4、3-6、4-1 から 4-5、4-7 で、`<一時フォルダのパス>/findings/` に書く JSON の形。step 3-6 と 4-7 で実行者が書く JSON も、この形とする。

```json
{
  "script": "<検査の名前>",
  "target": "<調べるスキルのフォルダの絶対パス>",
  "status": "済み",
  "findings": [
    {
      "check": "<検査の名前>",
      "item": "<項目>",
      "kind": "<構造、危険、助言のどれか>",
      "severity": "<重大、注意、参考のどれか>",
      "source_severity": "<CRITICAL、HIGH、MEDIUM、LOW、INFO のどれか>",
      "dimension": "<正しさ、見つけやすさ、信頼性、効率のどれか。危険と助言は null>",
      "deduction": 0,
      "file": "<調べるスキルのフォルダからの相対パス>",
      "line": 0,
      "message": "<見つけたこと>",
      "fix": "<直し方>"
    }
  ]
}
```

- status は、「済み」「対象なし」「調べられなかった」のどれかとする。
- deduction は、区分「構造」の指摘だけが 0 より大きい数を持つ。
- line は、行がない指摘(フォルダやファイルの全体の指摘)では 0 とする。
- step 3-6 で書くファイルは `ai-structure.json`、検査の名前は「日本語の章の中身(AI の推論)」とする。step 4-7 で書くファイルは `ai-danger.json`、検査の名前は「AI を乗っ取る書き方(AI の推論)」とする。指摘が 0 件のときも、findings を空の配列にして書く。
- check-structure の JSON は、参考の数の値の配列 metrics も持つ。check-dependencies の JSON は、調べた部品の配列 packages も持つ。check-license の JSON は、見分けたライセンス license も持つ。
